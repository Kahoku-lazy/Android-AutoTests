# 平台相关专有术语约定

> 用途：全平台统一模块称呼。文档、代码注释、提交说明、界面文案谈到某个模块时，一律用下表的名字，不再另造别名。
>
> 命名口径：后端 12 个 Django App 以 `apps.py` 的 `verbose_name` 与前端侧栏文案为来源，两者冲突时按代码实际功能定名；6 个引擎包取 `engines/AGENTS.md` 的一级子包定义；前端 10 个页面模块取 `frontend/src/modules/` 的目录名与该目录 `routes.ts` 覆盖的页面。

## 业务模块（backend/apps）

1. accounts 是 账号与登录会话模块
2. ai_assistant 是 AI助手模块
3. knowledge_search 是 知识库模块
4. bug_manager 是 BUG单管理模块
5. case_manager 是 用例管理模块
6. dashboard 是 仪表盘模块
7. device_pool 是 设备管理模块
8. ops_console 是 运营后台模块
9. report_generator 是 测试报告模块
10. serial_log 是 串口日志模块
11. task_list 是 任务清单模块
12. usage_ledger 是 模型用量账本模块

## 引擎包（engines）

13. engines.ae_harness 是 Agent 原语层
14. engines.backend_bridge 是 平台侧智能体角色装配层
15. engines.device 是 设备控制引擎
16. engines.uart_log 是 串口日志采集引擎
17. engines.vision 是 页面文本识别引擎
18. engines.utils 是 引擎内文件读写辅助

## 前端模块（frontend/src/modules）

19. frontend.ai-assistant 是 AI助手页
20. frontend.bug-manager 是 BUG单管理页
21. frontend.case-manager 是 用例管理页
22. frontend.dashboard 是 仪表盘页
23. frontend.device-pool 是 设备管理页
24. frontend.knowledge-search 是 知识库页
25. frontend.ops-console 是 运营后台页
26. frontend.report-generator 是 测试报告页
27. frontend.serial-log 是 串口日志页
28. frontend.task-list 是 任务清单页

## 易混项

| 容易混用 | 正确口径 |
|---|---|
| accounts 与「用户管理」 | accounts 是账号与登录会话模块（注册、登录、令牌吊销、账号启停）。侧栏「用户管理」是 ops_console 的 `/ops/users` 页面，不是 accounts。 |
| ai_assistant 与「Agent配置」 | ai_assistant 是 AI助手模块（助手名片、Agent 配置、对话）。侧栏「平台助手」指的就是它；ops_console 的 `/ops/agents` 只是同一批配置的另一个入口。 |
| knowledge_search 与引擎检索 | knowledge_search 是知识库模块（知识模块、检索面、评测面、设置）。`engines.ae_harness` 内的只读检索是引擎实现，不是平台模块。 |
| accounts 的前端在哪 | 前端没有 `accounts` 目录；登录与注册在同一个页面 `frontend/src/views/LoginView.vue`（路由 `/login`，页内切换「登录 / 注册」）。`me` 与 `logout` 由 `frontend/src/shared/api/auth.ts` 调用，没有独立页面。 |
| usage_ledger 的前端在哪 | 前端没有独立账本页；费用在仪表盘页（当天 / 总费用、Token 与费用趋势）和任务清单页（「平台费用」列）里展示，不单开入口。 |
