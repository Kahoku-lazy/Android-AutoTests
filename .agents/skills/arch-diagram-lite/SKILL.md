# 分层架构图（arch-diagram-lite）

一句话：**把 archify 的架构图「语言」抽出来，用平台自己的令牌和一次自绘 SVG 画出来**——不搬它的 viewer。

语法与取舍的拆解过程见 [references/decomposition.md](references/decomposition.md)。

## 什么时候用 / 不用

| 用 | 不用（仍走 archify） |
| --- | --- |
| 页面里嵌一张架构图，跟着看板一起滚动 | 要导出 PNG / SVG / WebM 交付 |
| 只需要一种主题（平台纸面风） | 要深/浅主题、4 套视觉风格 |
| 节点 4~12 个、层 2~4 层 | 要引导故事、路径探测、语义雷达、分享卡 |
| 数据已经在页面的快照里 | 图本身就是最终交付物、要独立分发 |
| 文件体积敏感（不能多 800 KB） | 需要被非技术人员反复改图中内容 |

**分工口径**：archify 出「对外的一次性大图」，本 skill 出「页面里的长期图」。同一份系统可以两者都有，但要各自维护各自的数据源。

## 六条语法（全部来自 ARCH 图，去掉包装）

1. **分层行**：从上到下 = 依赖/流向的顺序。层数 2~4，行距恒定，节点等高。**层的名字写在左侧槽里**（`入口层`/`服务层`/`底座`），不画背景色带——层是读者要建立的第一个心智模型。
2. **三行节点卡**：`目录名 / 组成事实 / 量化事实`。主标 16px 粗、副标 12px、量化 12px 次要色（同字号靠颜色分层，**不写 11px**）；左对齐；左缘一条 8px 色条 = 该节点的模块色（与饼图、卡片同源）。不写散文式职责，**每一行都必须是可查的数**。
3. **角色图例**：图下方一行 chips——「层名 + 节点数」+ 线型说明（实/虚、颜色含义）。ARCH 的图例是「语义类型 + 计数」，我们换成「层 + 计数」，因为节点色已经承载了模块身份。
4. **区域边界**：一个虚线圆角框 + 左上角挂一个 mono 标签，用来表达**纪律**而不是分组（例：`engines/ · 零 django / apps.* 依赖`）。全图最多一个，多了就是噪声。
5. **正交布线**：端口只从节点边中点出入；跨行先出竖线到行间「走廊」（行距的中线），再横走，再落回目标点；拐角 8px 圆角（`orthPath()`）。**坐标写死在一个 `LAYOUT` 表里**，不引布局算法。
6. **边标签**：只写 `数量 + 量词`（`110 次`、`95 处`）；**关系类型由线型 + 图例编码**（紫虚 = import、橙虚 = HTTP），不把 `import` 重复写进 7 个标签。标签贴自己那段线、带 paper 色描边（`paint-order: stroke`）保证压线可读；强调边加粗一档，不做发光/动效。

## 落地规格（照抄，不要重新发明）

| 项 | 值 |
| --- | --- |
| 画布 | 静态属性 `viewBox="0 0 1180 540"` + CSS `aspect-ratio: 1180 / 540`；**不要**用 `:viewBox`（in-DOM 模板会被小写成 `viewbox`，图会跑飞） |
| 节点 | `240 × 88`，行 y = 50 / 210 / 370，列 x = 200 / 760；阴影 = 同形 rect 偏移 `5,5`、`opacity .12` |
| 色条 | 节点内左侧 8px，`x+12`，`y+14 → y+h-14`，fill = 模块色，`rx 2` |
| 文本基线 | 主标 `y+34`、副标 `y+56`、量化 `y+74`；`x+34` 起，左对齐 |
| 层名槽 | `x=40`，宽 140，垂直居中于行 cy；下方一条 1px 弱分隔线（`x=40 → 150`），12px 次要色 |
| 边界框 | 包住目标节点，`pad 22`，`stroke-dasharray 8 4`；标签在**框内左上**（`x+10, y+16`） |
| 线 | 默认 `2px` 虚线 `--c-element`；HTTP/跨系统 `2.2px` `--c-tool`；选中 `3px` 实线 `--c-device` |
| 字号 | 全部取 `--app-size-*` 档（16 / 12）；SVG 内显式写 `font-size` 时**必须**确认没被 CSS 类覆盖（字号冲突过一次） |
| 颜色 | 只取 `var(--…)`；节点 fill 用 `color-mix(in srgb, var(--node-color) 58%, var(--app-bg-card))` |
| 主题 | **单主题**。不写 `prefers-color-scheme`、不写 `data-theme` 分支、不做切换按钮 |

## 流程（七步，别跳）

1. **定视角**：这张图回答什么？「谁依赖谁」还是「一次请求怎么走」？两种图不能混在一张里。
2. **定节点与层**：节点边界必须是**已有口径**（目录 / app / 运行时组件），并在页面或 README 里一句话声明；层是**人工划分**，必须同句声明「层按依赖方向人工划分」。
3. **定边语义**：先写清边的方向与量词（import 次数 / HTTP 处数 / 调用），再动坐标。**边不许手写**——两端与数字都必须来自快照或生成器。
4. **排坐标**：把层和列写成 `LAYOUT` 表；同一列上下对齐，跨层边走行间走廊；长跨度的边单独给一条侧向走廊，别从节点上穿过去。
5. **画**：`<rect>` 节点 + 三条 `<text>` + 色条 + 虚线边界 + `<path>` 正交线 + `<text>` 标签。边在节点之前渲染（z 序）。
6. **量**：`node --check` + HTTP 打开 + Playwright 截图；**再量一次文字宽度**（`getBBox` / `getComputedStyle`），确认三行都不出框、标签不压线不压节点。
7. **回写**：页面说明、README 口径表、目录 `AGENTS.md` 的坑同步；新增分层口径要在三处都写。

## 红线

1. **不编数字**：三行节点里每一行都要能追到生成器或快照；追不到的删掉这行，不填「约」。
2. **不编边**：图上每条线都要有数据来源；人工语义图（如有）必须在图上写明「人工语义，非静态解析」。
3. **层要声明**：分层是设计判断，不是数据。页面必须写清「层按依赖方向人工划分」，否则读者会以为层是算出来的。
4. **只取令牌**：色值/字号/间距/圆角/阴影一律 `var(--…)`；`:root` 之外不写色值字面量。
5. **单主题、无 viewer**：不引 archify，不引 CDN，不加主题切换/导出/缩放平移——这些是 viewer 的能力，不是图的。
6. **标签让路**：标签与节点、标签与标签禁止重叠；宁可移动标签位置，也不缩小字号到 11px 以下。

## 踩过的（本项目实测）

- **边界框标签与跨层竖线打架**：框内顶部放全句标签，会被从上方进框的竖线（`tests→engines`）穿过 → 框上只写半句，完整口径放图例；或者把标签右对齐到框左边缘外侧。
- **偏移量要相对节点中心算**：端点写成 `from.cx + dx`、`to.left`，不要写死绝对坐标。第一次就把 4 条边的 `dx/tx` 符号写反，线全落到节点外面。
- **旋转的节点里量文字**：`getBBox()` 返回旋转前的局部坐标，判断"出没出框"要按同一个局部坐标系比。
- **共享类改字号会连坐**：`.dep-node__title` 之类被 27 个页面共用，改一次要逐页截图（本项目把 15px 收到 16px 刻度后，`knowledge_search` 这种长名仍在 200px 节点内）。
- **标签 11px 不是刻度**：平台字号最小 12px，宁可改颜色/位置，也不要为了塞进去降到 11px。

## 自检

```
[ ] viewBox 是静态属性 + aspect-ratio 同比例；缩窗口图不变形、不裁剪
[ ] 三行文字都在节点内（用 getBBox 量，不靠眼）；最长一行留 ≥8px 余量
[ ] 边全部来自数据；方向与快照一致（不要为了好看反转）
[ ] 边界框标签没有被任何跨层竖线穿过；框上写不全的句子在下方图例里补齐
[ ] 图例的层名与左侧槽一致；计数 = 该层节点数
[ ] 点节点只高亮相关边，默认态零变化；键盘 Enter / Tab 可达
[ ] 没有 prefers-color-scheme / data-theme / 导出按钮
[ ] 色值全 var()；字号取刻度（16 / 12，不写 11）；`node --check` 通过
```
