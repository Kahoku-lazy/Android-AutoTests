# Feature Analysis — 功能三视角深度分析

**目的**: 从业务、技术、治理三个维度对模块功能进行完整剖析，生成普通人能读懂、技术人员能实现、AI 能遵从的 HTML 报告。

**三部分结构**:
```
第一部分：业务视角 — 这个功能是什么、谁在用、解决了什么痛点
第二部分：技术视角 — 数据从哪来、经过哪些层、渲染成什么（逐层展开+通俗解释）
第三部分：AI 编码治理 — 依赖边界、命名规则、错误处理、数据规则、测试标准、专属提示词
```

## 工作流

### Phase 1: 需求理解（必须询问用户）

在开始分析前，先和用户确认：
- 分析哪个模块的哪个功能？
- 报告输出到什么位置？（默认 `tests/functional/{module}/reports/`）
- 有没有特别关注的维度？

如果用户只说了模块名没指定功能点，先列出该模块的功能列表让用户选择。

### Phase 2: 代码探索

按以下路径追踪完整链路：

```
1. 前端入口 → index.vue 找到对应模板区块
2. 前端 API → api.js 找到调用的端点
3. 前端子组件 → components/ 找到渲染组件及其 Props
4. 后端路由 → config/urls.py 找到 URL → view 映射
5. 后端视图 → views.py 找到数据生产逻辑
6. 数据库表 → models.py 找到涉及的表和字段
```

使用 Explore agent 或直接 Read/Bash 读取代码。每次读完后确认理解再继续。

### Phase 3: 报告生成

**强制要求**：
- 必须加载 `html-report` skill 获取 design token
- 输出自包含 HTML，配色/字体/圆角/阴影严格遵循 PROMPT.md 规范
- 报告输出到 `tests/functional/{module}/reports/` 目录

**报告模板结构**：

#### 第一部分：业务视角

```
1. 功能定位 — 一句话说清楚这个功能做什么、回答什么问题
   配 3 个图标卡片展示核心指标

2. 用户故事 — 3 个场景：
   - 谁在什么场景下使用
   - 他想达到什么目的
   - 他怎么做（操作路径）

3. 解决的痛点 — 左右对照表：
   左侧：没有这个功能之前（痛点）
   右侧：有了这个功能之后（收益）

4. 界面信息架构 — 表格：
   面板/组件/展示内容/回答的问题
```

#### 第二部分：技术视角

```
5. 数据流全景 — 7 层逐层展开（每层独立卡片+颜色）：
   🟡 第 1 层：数据库（含完整表说明 — 通俗含义+用途）
   🟤 第 2 层：ORM 聚合查询（ORM是什么/聚合查询/性能问题）
   🔵 第 3 层：后端函数（每个函数的角色+通俗解释）
   🟢 第 4 层：JSON 响应字段（字段→存储内容→前端变量→显示位置）
   🔴 第 5 层：HTTP 传输（请求地址/鉴权/api封装）
   🟣 第 6 层：前端数据层（变量→来源→去向）
   🟠 第 7 层：渲染组件 + 视觉主题（组件/渲染技术/效果 + animal-island-vue 6维度）
   
   🔑 每两层之间的箭头中必须加灰色流转说明卡片，
      解释这一跳做了什么、数据以什么形式传递。

6. 前端实现 — 每个文件前加交互感知说明：
   "从交互上你能感知到什么？" + 通俗解释 + 代码片段

7. 后端实现 — 每个函数前加大白话解释：
   "后端数据流转 — 用大白话讲" + 叙事步骤 + 代码片段

8. 涉及文件清单 — 表前加"这些文件的关系"说明
```

#### 第三部分：AI 编码治理

```
9.  模块边界与依赖注入 — 允许依赖白名单 + 输入输出契约（接口签名不可改）
10. 命名规则 — 9 层变量命名 + 数据库表前缀 + 代码风格 6 条
11. 错误处理与日志规范 — 禁止 vs 必须对照表 + INFO/WARN/ERROR 三级日志
12. 数据流转与持久化规则 — ORM 规范 + DTO 转换规则
13. 单元测试与验收标准 — 覆盖率红线 + AI 生成代码时同步输出的测试模板
14. 模块专属 AI 提示词 — 5 张规则卡片整合（角色/红线/代码要求/数据铁律/接口契约）

三部分总结表 — 视角/回答问题/受众
```

#### 逐层通俗解释的关键原则

**每一层必须回答三个问题**：
1. 这一层是什么？（一句话）
2. 输入是什么？输出是什么？（数据形态变化）
3. 为什么需要这一层？（不能跳过的原因）

**技术术语必须有比喻**：
- 数据库表 → 银行流水、分数单、工单、目录
- ORM → 翻译官（Python ↔ SQL）
- JSON → 标准化装箱单
- HTTP → 快递配送
- Props → 部门交接单

### Phase 4: 输出

1. 生成 HTML 文件到指定位置
2. `open` 命令在浏览器中打开
3. 告知用户文件路径
