## 一、完整性检查（14 项）

### 1.1 结构完整

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 是否包含 10 个标准章节 + 附录 A？ | 功能定位 → 功能详细规格 → 布局与视觉设计 → 后端功能逻辑 → API 接口功能 → 数据来源表 → 非功能需求 → 非目标 → 关键约束速查 → 相关文件索引 → 附录 A 功能边界 |
| 2 | 文档头部是否有元信息？ | 关联模块路径、关联 `需求大纲.md`、版本号、状态、日期；有上下游时链到 PRD-XX |
| 3 | 是否有版本号和修订记录？ | 版本 + 日期 + 变更摘要 |

### 1.2 功能规格完整

| # | 检查项 | 说明 |
|---|--------|------|
| 4 | 每个 F 是否有业务叙述 + 验收标准？ | 验收须可验证（「输入 X → 期望 Y」），禁止「功能正常」 |

### 1.3 边界与异常

| # | 检查项 | 说明 |

| 13 | 外部依赖失败是否有拦截或降级？ | adb/设备占用/WS 等（§4 降级规则或 F 边界） |

### 1.4 数据与 API

| # | 检查项 | 说明 |
|---|--------|------|

## 评分规则

### 维度得分

| 维度 | 满分 | 计算方式 |
|------|:--:|------|
| 完整性 | 100 | (✅ + ⚠️×0.5) ÷ 适用项数 × 100 |
| 准确性 | 100 | 同上 |
| 可落地性 | 100 | 同上 |
| 规范性 | 100 | 同上 |
| 一致性 | 100 | 同上 |
| 异常与边界 | 100 | 同上 |

### 总体结论判定

| 条件 | 结论 |
|------|------|
| 无 P0 + 6 维度全部 ≥80 | ✅ 通过 |
| 无 P0 + 有维度 <80 | ⚠️ 有条件通过（P1 限期修复） |
| 有 P0 | ❌ 不通过（修复后重评） |

### 问题分级

| 级别 | 判定 | 示例 |
|:--:|------|------|
| **P0** 🔴 | 阻塞开发 | 缺核心 F 规格、跨 PRD 状态/字段矛盾、无验收标准、安全越权未定义 |
| **P1** 🟠 | 影响质量 | 边界状态缺失、非功能未量化、信封差异未登记、API 字段不完整 |
| **P2** 🟡 | 改进建议 | 格式不统一、可迁 ARCH 的实现细节过多、缺契约变更行 |

### 明确不再检查（已废弃的旧模板项）

以下内容**不作为**不通过理由（避免误杀 PRD-02 系列）：

- 独立「功能清单 + P0/P1/P2」章
- 强制用户故事表 / 模块边界 ASCII 图
- 「前端架构」路由树 / Props·Emits 图
- 完整数据库字段书（索引/FK 级联长表）
- 独立「里程碑」章
- 每功能强制 6 子节模板
- animal-island 组件名（现用 Doodle Craft）
