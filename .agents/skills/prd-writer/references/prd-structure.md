## §1 功能定位

- 解决什么问题、在平台哪一层
- 核心职责：粗体动词开头（发现/连接/锁定/推送/校验…）
- 一句模块性质：管理有写 / 只读聚合 / 瞬态无表
- ❌ 不强制用户故事、不强制边界 ASCII（用附录 A）

## §2 功能详细规格

编号 `F-{组}-{序}`。每 F：

1. 业务叙述  
2. 字段/规则表（有表单或枚举时）  
3. 组件（`.vue` / composable）  
4. 边界状态（场景 → 行为；权限可加触发方式）  
5. 验收标准（禁止「功能正常」）

边界按相关性写：网络失败、空态、权限显隐、写冲突(409)、外部依赖不可用。  
复杂操作可加权限矩阵（参考 PRD-02 §2.5）。  
❌ 禁止每功能 6 子节；❌ 接口细节不进 §2（进 §5）。

## §3 布局与视觉

- ASCII 布局 + 分栏/响应式
- Doodle Craft：`frontend/DESIGN_SYSTEM.md`；有则链 `设计-{模块}前端UI规范与checklist.md`
- 卡片/状态色/关键交互表
- ❌ 路由表、组件树、Props/Emits 图 → ARCH

## §4 后端功能逻辑

- 状态枚举 + 流转 + 进入条件
- 业务口径（锁、去重、心跳、占用前缀…）
- 降级表
- ❌ 类成员、私有方法逐步伪代码 → ARCH

## §5 API

- 鉴权；默认 `{status, data}` / `{status, message}`，snake_case
- 信封不一致 → 章首警告块（原因 + 前端是否已适配）
- 总览：# / 方法 / 路径 / 功能 / 前端消费 ✅❌
- 逐端点：请求/响应字段表、错误码、JSON 示例
- 契约变更表（至少一行初始契约）
- 跨模块端点：引用对端 PRD，不重复写满字段

## §6 数据来源表

| 表 | 前缀 | 说明 |
无表写「无自有表」；只读/写入他模块时标明主权 PRD。完整字段在 models/ARCH/database.md。

## §7–10 + 附录 A

| 章 | 表格列 |
|----|--------|
| §7 | 类别 / 指标 / 目标值（数字） |
| §8 | 不做的功能 / 原因 |
| §9 | C-xx / 约束 / 实施位置 |
| §10 | 层 / 路径 / 说明 |
| 附A | 能做 / 不能做 / 越界 / 数据可见性 |
