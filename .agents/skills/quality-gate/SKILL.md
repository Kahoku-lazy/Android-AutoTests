# Quality Gate — 四齿轮代码质量关卡

**目的**: 整合写法、输入输出、白盒、灰黑盒四个维度的审查能力，一次性输出完整的代码质量矩阵报告。

**核心理念**: 写法检查告诉你怎么写对，契约检查告诉你逻辑对不对，白盒告诉你路径覆盖全不全，灰黑盒告诉你用户能不能用。四个齿轮咬合——任何一个空的都是盲区。

## 四齿轮模型

```
  ┌─────────────────────────────────────────────────────┐
  │                    Quality Gate                       │
  ├─────────┬─────────┬─────────┬─────────────────────────┤
  │ 齿轮 1  │ 齿轮 2  │ 齿轮 3  │ 齿轮 4                  │
  │ 写法层  │ 契约层  │ 白盒层  │ 灰黑盒层                │
  ├─────────┼─────────┼─────────┼─────────────────────────┤
  │ 能发现: │ 能发现: │ 能发现: │ 能发现:                 │
  │ 魔法值  │ 参数未  │ 分支未  │ 接口返回格式            │
  │ 吞异常  │ 消费    │ 覆盖    │ 不一致                  │
  │ 类型缺  │ 返回值  │ 异常路  │ 鉴权缺失               │
  │ 重复码  │ 形态不  │ 径遗漏  │ 端到端数据              │
  │         │ 一致    │ 边界值  │ 完整性                  │
  └─────────┴─────────┴─────────┴─────────────────────────┘
```

四个齿轮覆盖 30 项检查，互相补充，无盲区。

## 工作流

### Phase 0: 确定目标

必须确认：
- 目标文件/模块/函数
- 关注维度（默认四个齿轮全开）
- 输出位置（默认 `tests/functional/quality-gate/reports/`）

### Phase 1: 齿轮 1 — 写法层 (工具 + AI 语义)

执行 `code-health-check` 的引擎 1 + 引擎 2：

**引擎 1: ruff 工具扫描**
```bash
ruff check --select PL,B,SIM,N,B,C90,RUF,ANN <target>
```

**引擎 2: AI 语义审查 (12 项)**
检查返回类型一致性、魔法字符串、热路径冗余、静默吞错、字段语义过载、重复逻辑、封装破坏、字段名滥用、枚举同步、硬编码散落、日志规范、异常吞噬。

### Phase 2: 齿轮 2 — 契约层 (输入输出 + 数据协议)

这是 code-health-check 没有的新维度。针对目标函数的调用方与被调用方之间的"合同"逐条校验。

**A 组: 输入契约 (4 项)**

```
A1. 参数消费
  搜索: 列出所有函数参数 → 在函数体中搜索是否被引用
  命中: 参数声明了但从未在函数体中出现 → 要么是死参数，要么漏了校验逻辑

A2. 隐含非空假设
  搜索: 参数使用处（如 db_agent.api_key、s.xpath）→ 是否有 if not xxx 的守卫
  命中: 参数被直接传给子函数/ORM/外部库而无空值检查 → 调用方不知道这个隐含约定

A3. 外部依赖防御
  搜索: ORM 调用（.get()/.filter()）、文件操作、网络请求 → 是否有 try/except
  命中: 外部依赖调用无异常保护 → 一个 DB 断连整个请求链崩掉

A4. 环境变量/配置依赖
  搜索: os.environ / settings.XXX / django.conf → 是否有默认值？默认值是否合法？
  命中: os.environ.get("KEY", "") 返回空字符串 → 传给需要有效值的下游
```

**B 组: 输出契约 (3 项)**

```
B1. 返回形态完整性
  搜索: 所有 return 语句 → 对比类型注解
  命中: 声明返回 Agent 但可能抛异常 / 声明返回 str 但可能返回 None

B2. 异常路径输出
  搜索: except 块中的 return → 返回了什么？调用方能区分"正常空结果"和"异常"吗？
  命中: return None 既表示"没找到"又表示"出错了" → 调用方无法区分

B3. 对象状态完整性
  搜索: 构造函数/工厂函数返回的对象 → 所有必要属性是否已设置？
  命中: 返回的对象某些属性依赖外部后续调用设置 → 使用时可能拿到半初始化对象
```

**C 组: 数据协议 (3 项)**

```
C1. 跨层字段名一致性
  操作: 追踪数据从 DB → ORM → JSON → 前端 → props 的字段名变化
  命中: 同一数据在相邻两层名字不同 → 数据溯源困难

C2. 默认值来源统一
  操作: 搜索同一含义的默认值在配置/代码/环境变量中是否一致
  命中: 模型名默认值在 agent_factory 中写死是 "qwen-max"，在 settings 中可能是另一个值

C3. 枚举/映射完整性
  操作: 搜索 dict 映射 → 检查是否覆盖了枚举的全部取值
  命中: _MODEL_CLASS 有 4 个 key，但 ModelProvider 枚举如果有 5 个值 → 缺覆盖
```

### Phase 3: 齿轮 3 — 白盒层 (路径 + 边界)

基于代码内部结构，逐函数分析所有可能的执行路径。不需要实际运行代码。

**D 组: 路径覆盖 (4 项)**

```
D1. 分支枚举
  操作: 对目标函数的每个 if/else/for/while → 列出所有分支
  输出: 路径图 + 每条路径的触发条件

D2. 分支可达性
  操作: 每条分支 → 判断是否可能被实际执行
  命中: 某个条件永远为 True（如 provider 在 dict 中取值后有默认值，外层 if provider in (...) 永远成立）

D3. 异常路径
  操作: 搜索函数中所有可能抛异常的调用 → 是否有对应的 try/except
  输出: 每条异常路径的触发条件 + 当前行为（崩/吞/降级）

D4. 时序依赖
  操作: 搜索对象的方法调用顺序 → 是否隐含时序假设
  命中: toolkit=None 注释说"injected later" → 在使用 Agent 前必须调用工厂，但代码不强制
```

**E 组: 边界值 (3 项)**

```
E1. 空值边界
  操作: 每个参数 → 如果传 None / 空字符串 / 空列表 / 0 会怎样
  命中: 无守卫的参数直接传给 .get() 或 .encrypt() → 异常

E2. 极值边界
  操作: 数值参数 → 如果传极大值/极小值/负数会怎样
  命中: max_tokens=0 或负数 → API 调用行为未知

E3. 类型边界
  操作: 参数如果传了"意料之外但合法"的类型会怎样
  命中: agent_id 声称为 int 但 DB 的 id 是字符串 → int("abc") ValueError
```

### Phase 4: 齿轮 4 — 灰黑盒层 (接口 + 端到端)

不看代码，只看接口。从"外部视角"验证。

**F 组: 灰盒 (3 项) — 知道接口签名，不知道实现**

```
F1. 接口契约断言
  操作: 对每个公开函数的签名 → 生成输入→输出断言
  输出: 正常输入 → 期望输出 / 异常输入 → 期望行为

F2. 状态变化验证
  操作: 写操作函数 → 调用前查状态 → 调用后查状态
  输出: save_message() 后 AIMessage.objects.count() 应 +1

F3. 权限边界
  操作: 带 user_id 的函数 → 用不同 user_id 调用
  输出: 能否访问/操作其他用户的数据
```

**G 组: 黑盒 (3 项) — 只知道 HTTP 端点**

```
G1. 响应格式校验
  操作: curl 端点 → 检查 {ok, data/error} 格式是否一致
  命中: 正常返回和错误返回的 JSON 结构不同 → 前端解析出错

G2. 鉴权完整性
  操作: curl 无 token / 过期 token / 错误 token → 检查响应
  命中: 应返回 401 但返回了 200 → 安全漏洞

G3. 端到端数据完整性
  操作: 从前端能接触到的最高层端点调用 → 追踪响应中的每个字段
  输出: 是否有字段缺少值、值为 null 但前端没处理、字段名和文档不一致
```

### Phase 5: 输出报告

生成 HTML 报告，结构：

```
1. 四齿轮覆盖矩阵 (核心)
   - 30 项检查 × 目标文件 → 命中/未命中/N/A
   - 颜色热力图：绿(通过) 黄(命中) 红(严重) 灰(N/A)
   - 一眼看出哪个齿轮覆盖了什么

2. 齿轮 1: 写法层结果
   - ruff 命中详情 + 语义审查命中详情

3. 齿轮 2: 契约层结果
   - A组(输入) / B组(输出) / C组(数据协议) 逐项详情

4. 齿轮 3: 白盒层结果
   - 每条函数的路径图 + 边界值触发条件
   - 自动生成的测试用例骨架

5. 齿轮 4: 灰黑盒层结果
   - 接口契约断言表 + curl 验证命令

6. 问题汇总 + 优先级
   P0-P3 分级，跨齿轮对比
```

## 与现有技能的关系

```
code-health-check ← 本技能的内置引擎 1+2
feature-analysis  ← 互补: feature-analysis 做业务视角分析, quality-gate 做技术质量审查
functional-testing ← 互补: functional-testing 做实际运行验证, quality-gate 做静态质量审查
html-report       ← 报告输出: 生成 HTML 矩阵报告时加载 design token
```

## 齿轮选择

用户可以根据需求选择齿轮组合：

```
/quality-gate <target> --gears=1,2,3,4  # 全量
/quality-gate <target> --gears=1,2      # 只要写法+契约（功能开发完成后）
/quality-gate <target> --gears=3,4      # 只要白盒+灰黑盒（测试阶段）
/quality-gate <target> --gears=2,3      # 只要契约+白盒（重构前审查）
```
