# 仓库可视化看板（repo-viz-board）

把「一个目录/一个仓库」变成一张能离线双击打开的看板：**模块关系图 → 模块依赖 → 分层代码量 → 逐单元三次对比**。

按本技能产出时**不要照抄任何现成看板的模块名**——模块边界永远由当前仓库的目录结构决定。

## 什么时候用

- 用户说「把 X 模块/仓库可视化」「画出模块关系」「统计各模块代码量」「哪个模块依赖谁」
- 要给某个目录做一张架构图 + 统计图，且希望**不装 Node、不启动服务**就能看
- 已有看板需要改口径（换模块划分、换统计深度）

不适用：需要实时数据（接 API/数据库）、需要登录权限、需要交互式编辑器。

## 先定三件事，再动手（不问清就别写代码）

这三件事决定了后面所有数字，返工成本极高：

| 要素 | 问法 | 例子 |
|---|---|---|
| **模块边界** | 模块 = 哪一层目录？ | 「`engines/` 下的 7 个顶层目录就是 7 个模块」 |
| **统计单位** | 一个「格子」是什么？往下追几层？ | 「只看模块下一层：一个直接子目录算一个（整目录汇总），一个直接 `.py` 各算一个，不往里拆」 |
| **关系含义** | 箭头是 import 还是运行期调用？ | 「箭头 = 静态 import 次数，不证明运行期谁调谁」 |

如果用户只给了模糊描述（"梳理一下关系"），**先用一句话复述你的理解并请他确认**，不要自己发明模块。

## 工作流

### 1. 先探数据，再画图

用脚本列出候选模块与它们的下一层结构，把真实数字读出来再设计页面：

```python
from pathlib import Path

root = Path("engines")  # 换成用户指的目录
for item in sorted(root.iterdir()):
    if item.is_dir() and item.name != "__pycache__":
        dirs = [d.name for d in sorted(item.iterdir()) if d.is_dir()]
        files = [f.name for f in sorted(item.iterdir()) if f.suffix == ".py"]
        print(item.name, len(dirs), dirs, len(files), files)
```

这一步同时暴露三类陷阱：`__init__.py`（通常不计）、`logs/` `__pycache__/`（必须跳过）、只有 `__init__.py` 的空壳目录（计 0 个单元）。

### 2. 写生成器，不手填数字

所有数字由 `tools/gen_xxx_data.py` 生成，页面只读快照：

- 用 `ast` 解析 import，不要正则匹配（`from a.b import c` 与 `import a.b` 都要覆盖）
- 同时产出 `data.json`（机器读）与 `data.js`（`window.__DATA__ = …`，页面读）
- **历史快照 append-only**：每次跑追加一条 `{at, 各项行数}`，数值没变就不追加；页面取最近三条做「本次 / 最近一次 / 最近两次」
- 缺记录的位写 `null`，**绝不补 0、绝不倒推**——页面显示「待记录」

判定「变了没有」时，要比较**所有**口径字段（新增一个统计维度时最容易漏，导致历史永远不增长）。

### 3. 页面骨架：三节

```
1. 模块架构：模块关系        ← 自绘 SVG，点节点高亮相关线
2. 依赖关系 × 模块代码量      ← 左：**依赖图 + import 表两个 tab**；右：**模块代码量饼图**
3. 各模块代码量（可选：三次对比） ← 每模块一张图，两列网格，单元多的独占一行
```

- 第 1 节**只有标题 + 图**，标题与图之间不放说明文字（用户通常明确要"干净"）
- 三节标题都带序号 `1.` `2.` `3.`，跨页保持一致
- 第 2 节右栏是**饼图**（`modulePie`：legend 带行数、tooltip 带百分比），不再用卡片；左侧 import 关系用**表格**（`.sheet-table`，三列：引用方 / 被引用 / 次数），不用卡片
- 第 3 节：单元 ≤ 10 个用两列；> 10 个加 `.cmp--wide` 独占一行，否则 X 轴标签挤成一团

### 4. 画图：共享底层 + 纯函数 option

- 一个 `<viz-chart :option="…" height="…">` 组件管生命周期（init / update / dispose / resize），**页面里永远不直接 `echarts.init`**
- option 全部是**纯函数**：`(数据, 令牌, 颜色) => option`，不碰 DOM
- 颜色只从 CSS 令牌读（`getComputedStyle(document.documentElement)`），canvas 读不到 `var(--x)`
- 关系图用正交折线：一条主路径优先、端口从节点边中点出、拐角 8px 圆角、实在避不开的交叉画跳桥
- 数字渐变用 `background-clip: text` + **两个 hex 停点**（HSL 保色相：深端 L36%、浅端 L78%）

### 5. 验证：HTTP + 量 DOM，不要只看"没报错"

```bash
python -m http.server 8899 --directory <看板目录>
```

- **必须用 HTTP 打开**：`file://` 下 `<link>` 的 CSS 会被缓存，改完样式仍看到旧渲染
- 用 Playwright 量关键元素的 `getComputedStyle`（字号 / grid 列 / fill / 高度），**"元素存在"不等于"渲染正确"**
- 每个页面截一张图自己看：有没有黑块、文字被压、图高度塌成 0
- 长元素（>1500px）的整块截图可能出现渲染错位，**换成单卡截图复核**

### 6. 回写文档

把这次踩的坑写进该目录的 `AGENTS.md`（口径 + 陷阱 + 禁止事项）。看板本身是文档，但它记录的"为什么这么统计"才是长期价值。

## 红线


1. **不得编造关系**：图上的每条边都要能追到代码（AST 结果或人工写的因果说明）。曾经手写一条数据里不存在的边，图上看着合理、实际是假的。
2. **不得编造数字**：没数据就写「待定 / 待记录」，不填 0、不填示例值。
3. **口径写进页面**：每个数字旁边或节标题下要能看到「数什么、从哪来、不证明什么」。
4. **统计深度要么只到一层，要么明确声明**：用户说"不深入"就真的不深入——`agents/assistant/` 整体算 1 个单元，不列里面的文件。
5. **第 2 节的「模块依赖图」不许删**：那一节必须是「图 / 表」两个 tab，图在左、表是它的另一半。第 1 节的图看的是**结构**（谁连谁），第 2 节的图看的是**次数**（可缩放、可拖拽、带 import 计数），不是重复。觉得"第 1 节已经有图了"就删掉第 2 节的图，是**同一个错误犯两次**（agents 页、backend 页各踩过一遍）。
6. **第 2 节的左栏用表格，不要用卡片**：`from → to | N 次` 这种两列数据，表格的列对齐比卡片更好扫；卡片会把 6 张以后的信息压成一条条横带，密度低、难比较。右栏的模块代码量用**饼图**，不要再用卡片。
7. **颜色/字号/间距只走令牌**，不写色值字面量。
8. **单页离线**：不引 CDN、不写网络字体、不多开构建步骤。

## 技术约束（踩过的）

完整清单见 `references/pitfalls.md`。最容易致命的四条：

- **`file://` 不能 `fetch` 本地 JSON** → 生成器要额外写一份 `window.__DATA__ = …` 的 `.js`
- **in-DOM 模板里 `:viewBox` 会被小写成 `viewbox`** → 写静态 `viewBox="0 0 W H"` + CSS `aspect-ratio` 同比例
- **一个元素链上只能有一个 `v-else`** → 多个兄弟块共享条件时用容器包起来，否则 Vue `compiler-30` 整页白屏
- **SVG 文字是替换元素**，`align-items: baseline` 对不齐 → 数字用 HTML 文本，不要用 `<text>` 画

## 交付前自检

```
[ ] 第 2 节有且只有两个 tab：「模块依赖图」+「import 次数表」，且默认停在图上
[ ] 生成器 --check 通过（快照与代码一致）
[ ] 所有数字能追到生成器某段口径；关系能追到 AST 或人工说明
[ ] HTTP 打开六个页面：0 pageerror / 0 console error
[ ] 量过关键元素：字号、grid 列、图高度、节点 fill 都符合预期
[ ] 截图自查：无黑块、无文字压叠、无高度塌陷
[ ] 缺数据处显示「待记录」，没有 0 和假值
[ ] AGENTS.md 已记录口径与本次新增的坑
```

## 需求 → 落点对照

| 用户说 | 落在哪 |
|---|---|
| 「梳理这几个模块的关系」 | 第 1 节 SVG 图（边来自 import，或人工因果表） |
| 「谁依赖谁 / 引用了几次」 | 第 2 节左栏：**依赖图（默认）+ import 次数表**，两个都要有 |
| 「每个模块多少代码」 | 第 2 节右栏**环形饼图**（占比 + 图例带行数） |
| 「每个子模块/文件多少代码」 | 第 3 节每模块一张图 |
| 「和上次比呢」 | 第 3 节三系列柱 + 三张总量卡（本次/最近一次/最近两次） |
| 「点开看这个模块的文档」 | 节点上的 `AGENTS` 入口 → 弹层渲染 markdown（生成器把 md 读进快照，页面不 fetch） |
