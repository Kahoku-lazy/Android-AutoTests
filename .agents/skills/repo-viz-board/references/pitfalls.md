# 踩过的坑（repo-viz-board）

按「改哪儿出错」分类。每条都给出**症状 → 根因 → 正确做法**，方便直接对照。

## 一、数据与口径

### 1. 历史永远不增长
**症状**：`--check` 一直说"最新"，但代码明明改过；页面的「最近一次」永远是「待记录」。
**根因**：追加历史时用 `{k: v for k, v in row.items() if k != "at"}` 比较，新增的统计维度没加进比较的 key 列表。
**做法**：新增口径字段时，同步加进变更检测的 tuple（例如 `for cat in (*CATEGORY_KEYS, "ae_harness", "engine_modules")`）。

### 2. 新增模块后数字对不上
**症状**：页面显示 5 个模块，实际目录已有 6 个。
**根因**：模块清单是**写死在生成器常量里**的（`AE_HARNESS_GROUPS` / `ENGINE_MODULES`），新增目录不会自动出现。
**做法**：加模块要**五处同步**：生成器常量 → 因果说明 → 页面 `MODULE_ORDER` → 令牌颜色 → 架构图坐标与边。少一处就是半成品。

### 3. `__init__.py` 让「文件数」多 1
**症状**：`agents/` 明明 4 个 `.py`，页面显示 3。
**根因**：`__init__.py` 是包标记，不含业务代码。
**做法**：统一排除 `__init__.py`；同理排除 `__pycache__/`、`logs/`、只有 `__init__.py` 的空壳目录（自然就计 0 个单元）。

### 4. 非确定性：同一份代码两次跑出不同结果
**症状**：`--check` 反复报"数据已过期"，重跑一次又好了。
**根因**：遍历 `set` 决定输出顺序，Python 的字符串哈希每进程随机。
**做法**：所有聚合输出前 `sorted()`；涉及排序的再加二级 key（`-loc, name`）保证稳定。

### 5. 关系图里出现了数据里没有的边
**症状**：图上 `A → B` 看起来很合理，但 AST 结果里没有。
**根因**：手写边列表时"凭语义补了一条"。
**做法**：图的边要么**全部来自数据**，要么在数据里明确标注 `source: "manual"` 并在图注声明。两者不能混着不标。

## 二、Vue（in-DOM 模板）

### 6. 整页白屏 + `compiler-30`
**症状**：控制台只有一条 `vuejs.org/error-reference/#compiler-30`，页面全空。
**根因**（两个都踩过）：
- 三个兄弟块都写了 `v-else`（一个元素链只允许一个 `v-else`）
- `<viz-chart … />` 自闭合，把后面的 `v-else` 吞掉
**做法**：多个兄弟共享条件时用容器包一层 `<div v-if/v-else>`；组件一律写成对标签。

### 7. `:viewBox` 不生效，图跑出容器
**症状**：SVG 里的节点画到了容器外面，`getAttribute('viewBox')` 返回 `null` 或字面量。
**根因**：HTML 解析器把带前缀的属性名小写化成 `:viewbox`，Vue 拿不到。
**做法**：`viewBox` 写成**静态属性**（`viewBox="0 0 1180 520"`），尺寸固定就用 CSS `aspect-ratio` 同比例。真要动态就用 JS 设属性。

### 8. 节点上的按钮不显示
**症状**：给节点加的小标签在节点外侧能看见，挪进节点内部就消失了。
**根因**：SVG 按文档顺序绘制，按钮写在节点 `<g>` 之前，被节点的 `rect` 盖住。
**做法**：覆盖在节点上的元素必须放在节点 `<g>` **之后**。

### 9. 共享组件"没渲染"，但没有任何报错
**症状**：`<viz-chart>` 位置只有空 div，canvas 数量 0。
**根因**：调用了不存在的导出（`VizCharts.VizChart`），实际 API 是 `VizCharts.register(app)`。
**做法**：注册组件后**数一下 canvas 数量**，别只看"页面上没报错"。

### 10. `v-if` 切换后图表尺寸算错
**症状**：从「表」切回「图」，图被压成一条线。
**根因**：`v-show` 隐藏在 0 宽容器里 init，ECharts 算出错误宽高。
**做法**：用 `v-if` 让它重新挂载；或者隐藏时 `dispose`、显示时 `init`。

## 三、ECharts

### 11. 空系列在图例里"有名字没数据"
**症状**：图例显示「最近两次」，但图上一根柱都没有。
**根因**：整列都是 `null` 的系列仍然被渲染。
**做法**：构造 option 前先过滤掉全 `null` 的系列。

### 12. 图例/标签被挤到看不见
**症状**：窄容器里节点标签压在圆点上；17 个类目的柱顶数字互相叠。
**做法**：标签位置提供可选参数（`labelPosition`），窄容器用 `bottom`；类目 > 10 时 `label.show = false`，只留 tooltip。

### 13. 数字渐变绘制不出来
**症状**：`background-clip: text` + `color-mix()` 渐变，计算值正确、实际渲染成一片浅色。
**根因**：Chromium 在 `background-clip:text` 下对 `color-mix()` 作为渐变停点绘制失败。
**做法**：渐变停点用**两个具体 hex**（`shadePair()` 按 HSL 算：保色相，深端 L36% / 浅端 L78%）。

## 四、CSS

### 14. 改样式不生效，但 CSS 文件里明明改了
**症状**：改完刷新还是旧样式，`getComputedStyle` 却返回新值。
**根因**：`file://` 下 `<link>` 的 CSS 被缓存。
**做法**：**一律用 HTTP 验证**（`python -m http.server`）。

### 15. 同一个 class 有多份规则，旧值覆盖新值
**症状**：新写的 `width: 110px` 不生效，元素宽 100%。
**根因**：样式文件里同一个 selector 有多份（多轮追加累积），CSS 级联合并、后者覆盖同名属性。
**做法**：加规则前先 `Select-String` 查重；积累多了按 selector 合并去重一次（后者覆盖同名属性、保留最后位置，语义等价）。

### 16. 清死样式把活样式一起删了
**症状**：页面变黑块 + 竖排文字。
**根因**：用「从 A 注释删到 B 注释」的区间删除，区间里混着仍在用的规则。
**做法**：只按**类名**精确删；删完用 Playwright 量一遍关键元素的 `getComputedStyle`（display / grid 列 / fill），别只看 DOM 存在。

### 17. 卡片三块内容基线不齐
**症状**：模块名比数字"偏下"。
**根因**：数字用 SVG `<text>` 画，SVG 是替换元素，`align-items: baseline` 对不齐。
**做法**：三块都用 HTML 文本，容器 `grid` + `align-items: baseline`，每块内部 `flex` + `align-items: baseline`，主体元素 `flex: 0 0 auto`（否则被挤成省略号）。

## 五、工具链

### 18. 一次 `str.replace` 改坏两个函数
**症状**：某个页面白屏，报 `ReferenceError: opts is not defined`。
**根因**：`str.replace` **替换所有匹配**，两个函数里有相同的代码片段，其中一个没有 `opts` 参数。
**做法**：改共享文件里的重复片段时，按行号改或加足够上下文；改完 `node --check`。

### 19. 长元素截图"图被切了"
**症状**：整块 section 截图里后面几张卡片只露出顶部。
**根因**：Playwright 对超长元素截图的渲染问题（DOM 尺寸其实是好的）。
**做法**：先量 `getBoundingClientRect()`；确认 DOM 正常后，用**单卡截图**复核，不要据此改样式。

### 20. 中文在传输中被写坏
**症状**：CSS/JS 注释变成 `浠ｇ爜閲忓崱鐗囷` 这类乱码。
**根因**：脚本经 shell 传参时编码不一致。
**做法**：写文件的脚本统一 `PYTHONUTF8=1` + `encoding="utf-8"`；写完 `read_text` 抽查一眼。

## 六、模板本身

### 21. 复制别的页面当骨架，带入一堆无用绑定
**症状**：新页一渲染就 `TypeError: isNodeActive is not a function` / `Cannot read properties of undefined (reading 'length')`。
**根因**：从现成页面（如 `agents.html`）复制骨架，把它的 AGENTS 弹层、`depRows`、`toggleModule` 一起带了过来，而新页的 JS 没实现这些。
**做法**：**用 `assets/template/` 里的模板起手**，不要复制某个已完成的页面。模板里的每个绑定都在 `app.template.js` 里有对应实现；复制现成页面则要逐条核对。

### 22. 模板 HTML 与 JS 的方法对不上
**症状**：`:class="{ 'is-selected': isNodeActive(node) }"` 报未定义。
**根因**：模板 HTML 用了 `isNodeActive`，但 `app.template.js` 初版只写了 `isEdgeActive`。
**做法**：模板改动后，用脚本交叉检查「HTML 里出现的标识符」是否都在 JS 的 data/computed/methods 里；或者至少把三个节各渲染一次看有没有 TypeError。

### 23. 长模块名压住后面的数字
**症状**：`knowledge_assistant` 和「6 个单元」重叠。
**根因**：卡片第一列宽度固定，模块名一长就挤掉后面的内容。
**做法**：名字超过 14 字符时**不显示中文名**（`shortLabel`），不要试图靠加宽列解决——加宽会把「文件数 / 行数」推远，三块就散了。

### 24. 把「第 2 节的依赖图」当成与第 1 节重复删掉（犯过两次）
**症状**：第 2 节只剩一张 import 表，用户问"依赖图怎么没了"。
**根因**：第 1 节已经有一张更精致的关系图，于是觉得第 2 节的 ECharts 图多余，顺手删了。
**为什么不能删**：两张图解决不同问题——第 1 节是**人工布置的结构图**（固定坐标、可点选高亮、看层次）；第 2 节是**数据驱动的依赖图**（可缩放拖拽、边上带 import 次数、与表格互切）。删掉第 2 节的图，等于把"按次数看依赖"的入口拿走了。
**做法**：第 2 节固定为「图 / 表」两个 tab，默认停在图上；12 个以上节点时给 `depGraph` 传 `positions`（复用第 1 节分层坐标），否则 circular 布局会挤成一团。

### 25. 把两列数据做成卡片，反而不如表格
**症状**：`from → to · N 次` 做成一行一张卡后，用户反馈"效果不行"。
**根因**：这类数据只有三个字段、且需要**逐行横向比较**（谁引用谁最多）。卡片为了排版加粗边、内边距、渐变，一屏只能放 8~10 条，列不对齐，扫读成本反而更高。
**做法**：
- 两列/三列的**明细数据** → `.sheet-table`（列对齐，能一屏看 15+ 条）
- 需要强调数值时，用表格里的 `num` 列 + 令牌色，不要为了"好看"改成卡片
- 只有「一张图 + 一句话」的概览项才用卡片（`.code-card`）
