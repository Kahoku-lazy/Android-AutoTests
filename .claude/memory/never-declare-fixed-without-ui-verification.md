## 铁律：宣布修复前必须完成浏览器UI端到端验证

之前的记忆 `full-stack-verification-workflow.md` 说了"必须浏览器验证"，但我仍然反复犯同一个错误：

### 我的错误模式

```
发现一个后端问题 → 修复代码 → curl/API测试通过 → "修好了" ❌
```

用户一打开浏览器 → 根本不能用 → 白修了。

### 正确流程

```
发现任何问题
  ↓
修复代码 + 重启
  ↓
浏览器UI完整走一遍（不止一次！）
  ↓
发现新问题 → 继续修复 → 继续测试
  ↓
重复直到完整流程不中断
  ↓
确认每一个Tab/按钮/状态/日志都正确
  ↓
才能说"修好了"
```

### 具体规则
1. **永远从用户视角测试**：打开浏览器，模拟用户点击，不要只调API
2. **不满足于单个修复**：一个修复往往暴露下一个问题，持续测试直到完整链路跑通
3. **测试至少2次**：一次可能是巧合，两次确认稳定
4. **发现卡住不要停下来分析**：继续修，继续测，直到能用
5. **修复≠完成**：只有用户在浏览器里看到正确结果才算完成

**Why:** 多次声称修复完成但用户打开浏览器发现完全不能用。API测试通过不代表UI能用。每次只修一个问题就停下来，用户永远用不到完整功能。

**How to apply:** 
- 不管遇到几个bug，一直修到浏览器UI完整流程跑通为止
- 在说"修好了"之前，至少完整走通2次创建→执行→查看结果
- 把浏览器测试作为唯一验收标准，不是API/CLI
