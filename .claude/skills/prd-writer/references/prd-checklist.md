# PRD 验收检查清单

> 用于 Mode 3「校验 PRD」的逐项检查依据。按 6 个维度组织，每项标记 ✅ 通过 / ❌ 不通过 / ⚠️ 部分通过 / ➖ 不适用。

---

## 一、完整性检查（15 项）

### 1.1 结构完整

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 是否包含 12 个标准章节？ | 功能目标 → 功能清单 → 详细规格 → 前端架构 → 数据模型 → API → 状态 → 非功能需求 → 约束速查 → Non-goals → 里程碑 → 文件索引 |
| 2 | 文档头部是否有元信息？ | 关联模块、关联全局PRD、上下游子PRD、版本号、状态、日期 |
| 3 | 是否有版本号和修订记录？ | 每次变更应有版本号 + 日期 + 变更类型 + 变更摘要 |

### 1.2 功能规格完整

| # | 检查项 | 说明 |
|---|--------|------|
| 4 | 每个功能是否有完整字段表？ | 字段名/类型/必填/默认值/说明 五列齐备 |
| 5 | 每个功能是否有触发条件？ | 用户在什么状态/操作下触发该功能 |
| 6 | 每个功能是否有需求目标？ | 可量化的衡量方式 + 目标值 |
| 7 | 功能清单表是否标注优先级？ | P0/P1/P2，P0 为核心流程必须 |
| 8 | 是否有用户故事？ | 覆盖全部目标角色，每个故事有验收标准 |

### 1.3 异常场景覆盖

| # | 检查项 | 说明 |
|---|--------|------|
| 9 | 是否覆盖网络断连场景？ | 每个涉及网络请求的功能至少描述断连时的行为 |
| 10 | 是否覆盖数据为空场景？ | 列表/搜索结果/详情页 无数据时的展示 |
| 11 | 是否覆盖权限不足场景？ | 未登录/无权限时的跳转或提示 |
| 12 | 是否覆盖重复提交/并发冲突？ | 创建/保存操作的幂等性和去重 |
| 13 | 是否覆盖输入校验失败？ | 前端+后端双层校验 + 错误提示文案 |
| 14 | 是否覆盖超时场景？ | 长时间操作（如 AI 对话/测试执行）的超时处理 |

### 1.4 数据模型完整

| # | 检查项 | 说明 |
|---|--------|------|
| 15 | 是否包含所有表的完整字段定义？ | 类型/约束/默认值/说明 + 索引/唯一约束 + 外键级联策略 |

## 二、准确性检查（8 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 16 | 术语是否全文统一？ | 搜索关键术语，确认无同义词混用（如"设备"与"手机"、"用例"与"案例"） |
| 17 | 术语是否与全局 PRD 一致？ | 与 `实际需求文档.md` 中的术语保持统一 |
| 18 | 术语是否与代码命名一致？ | URL 路径/表名/组件名/API 字段名 是否与 PRD 中的术语对应 |
| 19 | 是否有模糊词汇？ | 搜索"大概/可能/差不多/尽量/或许/一般/通常"等主观词汇 |
| 20 | 功能描述是否有歧义？ | 每句话应该只有一种理解方式，不能有多种解读 |
| 21 | 同一个概念是否全文描述一致？ | 同一功能在不同章节（概述/详细规格/API）中的描述不矛盾 |
| 22 | 优先级标注是否合理？ | P0 是"没有它系统不可用"，P1 是"重要但可分期"，P2 是"锦上添花" |
| 23 | 是否符合行业法规与合规要求？ | 数据加密/隐私/权限控制是否达标 |

## 三、可落地性检查（8 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 24 | 每个用户故事是否有可验证的验收标准？ | "输入 X，期望得到 Y"格式，非"功能正常" |
| 25 | 验收标准是否量化？ | 含具体数值（如"响应时间 ≤500ms"），非"足够快" |
| 26 | 非功能需求是否量化？ | 性能/容量/安全/兼容性 必须有数字指标 |
| 27 | 是否明确技术可行性？ | 不与现有架构冲突，不依赖未实现的基础能力 |
| 28 | 是否明确功能优先级？ | P0/P1/P2 标注，开发可按优先级排期 |
| 29 | API 端点定义是否完整？ | 方法/路径/请求体/响应格式/状态码/认证要求 |
| 30 | 数据模型是否与 API 响应字段一致？ | API 示例中的字段名必须在数据模型中能找到来源 |
| 31 | 前端交互要求是否具体到组件级别？ | 不是"展示列表"，而是"用 animal-island-vue Table 组件展示，列包含 X/Y/Z" |

## 四、规范性检查（5 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 32 | 章节编号是否统一？ | 全文档使用一致的编号体系（如 `1.` `2.1` `3.1.2`） |
| 33 | 表格格式是否统一？ | 所有表格使用一致的列对齐和表头风格 |
| 34 | JSON/代码块格式是否正确？ | 代码块标注语言类型，JSON 有效可解析 |
| 35 | 是否有错别字或冗余内容？ | 全文通读，修正拼写错误和重复段落 |
| 36 | 链接和引用是否有效？ | 文档内交叉引用、关联 PRD 路径是否正确 |

---

## 五、一致性检查（5 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 37 | 与全局 PRD 的定位/用户/目标是否一致？ | 不出现与全局 PRD 矛盾的定位描述 |
| 38 | 与上游子 PRD 的数据契约是否匹配？ | 上游模块输出的数据格式/字段名与本模块输入一致 |
| 39 | 与下游子 PRD 的数据契约是否匹配？ | 本模块输出的数据格式/字段名与下游模块期望一致 |
| 40 | 字段名是否与后端命名规范一致？ | snake_case：`test_case_id`，非驼峰或混用 |
| 41 | API 路径是否与项目路由规范一致？ | kebab-case：`/api/case-manager/`，非驼峰或下划线 |

---

## 六、异常与边界检查（6 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 42 | 每个 API 端点是否定义了错误响应格式？ | 包括 400/401/404/409/500 的响应体和提示文案 |
| 43 | 所有状态是否定义了流转规则？ | 包括初始态→中间态→终态的完整路径 |
| 44 | 是否有边界值校验？ | 字符串最大长度/数值范围/文件大小上限/超时限制 |
| 45 | 是否考虑了并发场景？ | 多用户同时操作同一资源的冲突处理 |
| 46 | 删除/禁用操作的级联影响是否明确？ | 删 A 会不会影响 B，FK 是 CASCADE 还是 SET_NULL |
| 47 | 是否有降级/兜底策略？ | 依赖的外部服务不可用时的备用方案 |

## 评分规则

### 维度得分

| 维度 | 满分 | 计算方式 |
|------|:--:|------|
| 完整性 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |
| 准确性 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |
| 可落地性 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |
| 规范性 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |
| 一致性 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |
| 异常与边界 | 100 | (✅项数 + ⚠️×0.5) ÷ 总适用项数 × 100 |

### 总体结论判定

| 条件 | 结论 |
|------|------|
| 无 P0 问题 + 6 维度全部 ≥80 | ✅ 通过 |
| 无 P0 问题 + 有维度 <80 | ⚠️ 有条件通过（P1 问题限期修复） |
| 有 P0 问题 | ❌ 不通过（P0 必须修复后重新评审） |

### 问题分级

| 级别 | 判定 | 示例 |
|:--:|------|------|
| **P0** 🔴 | 阻塞开发：缺核心功能规格/数据契约矛盾/安全合规问题/无验收标准 | 缺 API 端点定义、字段表不完整、安全需求缺失 |
| **P1** 🟠 | 影响质量：异常场景缺失/术语不统一/边界条件未覆盖 | 网络断连处理缺失、非功能需求未量化 |
| **P2** 🟡 | 改进建议：格式不规范/描述可优化/缺少关联文件索引 | 章节编号不统一、表格格式不一致 |
