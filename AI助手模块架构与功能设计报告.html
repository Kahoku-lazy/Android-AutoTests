一、架构定位与三层分离

1.1 AI 助手的平台角色

AI 助手是平台的 自然语言交互中枢，是三条操作通道之一（通道 B）：

🖐️ 通道 A：手动操作

各模块页面点击按钮、填表单 → 精细化控制每一步，逐条执行。

🤖 通道 B：AI 对话 本模块

ChatView 输入自然语言 → AI 自动搜索元素、编排步骤、锁定设备、执行测试、返回结果。

🧩 通道 C：可视化编排

Blockly 拖拽积木 + VueFlow 画图 → 图形化编排后同步到用例库执行。

1.2 三层架构中的位置

AI 助手跨 后端层 (Django) 和 AI 引擎层 (AgentScope) 两层，是唯一跨越两个后端子系统的模块：

层AI 助手模块的职责
🖥️ 前端层 (:5173)Vue 3 组件：智能体列表、5 步配置向导、SSE 流式对话界面、HITL 确认弹窗
⚙️ 后端层 — Django (:8765)管理智能体配置（加密存储 API Key）、对话记录持久化、37 REST 端点
🤖 AI 引擎层 — AgentScope (:8000)ReAct 推理循环、24 Tool 编排调用、SSE 流式输出、Agent Team 并行协作、ChromaDB 知识库检索

1.3 核心交互链路

用户自然语言 → ChatView (SSE Client) → AgentScope ReAct 推理
    → 24 个 Tool → 同进程 import Django ORM/API → 6 个业务模块
    → 结果返回 → SSE 流式逐 token 输出 → 前端渲染

四、SSE 流式对话事件系统

4.1 事件类型与前端渲染映射

SSE 事件前端渲染说明
REPLY_START消息气泡出现开始新回复
TEXT_BLOCK_DELTA打字机效果 逐 token 追加文本AI 正文输出
THINKING_BLOCK_START/DELTA/END折叠面板 (默认折叠)ReAct 推理过程
TOOL_CALL_START工具调用卡片 (loading 状态)工具名 + 参数
TOOL_CALL_DELTA追加工具参数 JSONJSON 增量流
TOOL_RESULT_START/DELTA/END结果面板 (折叠)成功/失败状态
HINT_BLOCKSOP 状态卡片 / 任务卡片UI 结构化提示
REQUIRE_USER_CONFIRMElMessageBox 确认弹窗HITL 人机协同
REPLY_END触发 save-message API持久化到 ai_messages 表

4.2 消息持久化流程

SSE 流结束 (REPLY_END)
  → 前端调用 POST /api/ai/conversations/{id}/save-message
  → 请求体: { role:"assistant", blocks:"[{type:'text',...},...]",
              reason:"normal", tokens:1234, input_tokens:567,
              model_name:"qwen-max" }
  → Django INSERT ai_messages (blocks 存储完整 ContentBlock JSON)
  → 对话恢复时可从 DB 重建完整消息历史

8.3 Tool 基类设计模板

class MyNewTool(ToolBase):
    name = "my_new_tool"              # LLM Function Calling 三要素
    description = "工具功能描述"        # LLM 据此选择工具
    input_schema = {                  # JSON Schema 参数定义
        "type": "object",
        "properties": {
            "param1": {"type": "string", "description": "..."},
        },
        "required": ["param1"],
    }
    is_concurrency_safe = False       # 写操作设为 False
    is_read_only = False              # 有副作用设为 False

    async def check_permissions(self, tool_input, context):
        # 权限决策：ALLOW / DENY / REQUIRE_USER_CONFIRM
        return PermissionDecision(
            behavior=PermissionBehavior.ALLOW,
            reason="所有用户可调用"
        )

    async def call(self, params: dict) -> ToolChunk:
        # 核心：调用 Django API → 返回 ToolChunk
        result = await run_sync(some_django_operation, params)
        return ToolChunk(
            content=[TextBlock(type="text", text=json.dumps(result))]
        )

# Tool 开发七大约束
# 1. 必须继承 ToolBase
# 2. 必须有 name/description/input_schema
# 3. 读 Tool 设 is_read_only=True
# 4. 写 Tool 必须走 Django api.py（禁止 Tool 内直接 ORM 写入）
# 5. 返回值用 ToolChunk 包装 TextBlock 或 HintBlock
# 6. 异步桥接 run_sync() — 封装 sync_to_async，8s 超时
# 7. 新增后在 factory.py 的 _ALL_BUSINESS_TOOLS 注册

十四、安全设计

14.1 API Key 全生命周期保护

阶段安全措施
🔐 写入用户输入 → encrypt_key() Fernet 对称加密 → 写入 DB（不以 sk- 开头）
👁️ 展示列表接口不返回 api_key；详情接口返回 mask_key() 脱敏值 sk-***xxxx
🔓 查看独立 reveal-key 端点，完整 Key 仅返回一次，5 秒后不可再获取
🔄 更新检测 "***" 掩码 → 跳过更新，保留原值
🔧 使用decrypt_key() 仅在后端 agent_factory.py 调用；解密后不写入日志、不返回前端、不出现在错误消息中
🚫 导出禁止任何 API 返回解密后的完整 api_key；数据迁移/备份只导出加密值

14.2 HITL 人机协同安全

高风险操作（如执行测试）需要用户确认后才执行：

Agent → REQUIRE_USER_CONFIRM 事件 (tool_call_id, tool_call_name, tool_call_input)
前端 → 显示确认弹窗（设备、用例列表、循环次数）
用户 → 点击「确认」或「取消」
前端 → POST /confirm-result {tool_call_id, decision: "ALLOW/DENY"}
AgentScope → 收到确认结果 → 继续或跳过工具调用

十五、关键设计决策

决策理由
AgentScope 同进程调用 DjangoTool 直接 import ORM/API，不走 HTTP，零网络开销，零序列化损耗
Django + AgentScope 共享 JWT 密钥统一认证体系，避免双系统 Token 同步复杂度
24 Tool 全部继承 ToolBase框架通过基类发现和注册；统一的输入校验、权限检查、异步桥接
SSE + 阻塞 POST 双模式AgentScope 不可用时自动降级为同步模式，保证可用性
两层工具体系 (Plan + SOP)Plan 工具管理阶段内子任务（内存态），SOP 工具管理跨阶段状态（持久化），职责清晰
裸 Django View 而非 DRF37 端点稳定运行，JSON 格式统一 {ok, data|error}，AI Tool 同进程调用无帮助
Fernet 对称加密 API KeySECRET_KEY 为密钥，DB 泄露不会直接暴露 Key；前端脱敏 + 5 秒限时查看
ChromaDB 本地持久化32 篇文档向量化存储在本地，无需外部向量数据库，查询延迟低
animal-island-vue 独立主题AI 助手模块使用动森暖木色主题，与其他业务模块的 Element Plus 蓝白风格隔离，提升 AI 对话的亲和力
消息完整持久化为 ContentBlock JSONblocks 字段存储 AgentScope 完整事件结构，对话恢复可重建完整消息历史
