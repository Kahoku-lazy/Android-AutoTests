# 报错诊断手册

> 常见错误快速诊断与修复指引。Agent 和人工均可使用。
> 版本：v1.1 · 日期：2026-06-30

---

## 使用方式

### 人工查阅

直接看 §七「诊断速查表」→ 按关键词跳转到对应章节。

### Agent 自动诊断（Code-Debug 工作流）

```
Step 0: 查本手册 — 用报错关键词匹配 §七 速查表
  ├── 命中 → 返回标准方案 (原因 + 排查 + 修复)
  └── 未命中 ↓
Step 1: 分析错误 — 提取错误类型/消息/堆栈/文件路径
Step 2: 分类 — 编译 / 运行时 / 配置 / 网络 / 权限
Step 3: 搜索知识库 — 检索飞书/项目文档中的已知问题
  ├── 已知 → 返回解决方案
  └── 未知 ↓
Step 4: 搜索代码仓库 — 定位相关代码 → 理解调用链 → 生成修复建议
Step 5: 输出诊断 — 🔎 根因 + 相关代码 + 修复建议 + 预防措施
Step 6: 归档 — 未知问题解决后补充到本手册 §二~§六
```

> 此工作流参考 PM-Project `code-debug` Agent 方法论（`analyze → classify → search KB → branch response`），增加 Step 0 优先查本手册作为快速路径。

## 一、ADB / 设备错误

### 1.1 `adb: no devices/emulators found`

| 属性 | 内容 |
|------|------|
| **症状** | 执行 `adb devices` 返回空列表 |
| **原因** | USB 断开 / 设备 USB 调试未授权 / adb server 异常 |
| **排查** | 1. `adb kill-server && adb start-server`<br>2. 检查 USB 线 + 重新插拔<br>3. 手机上确认"允许 USB 调试"弹窗 |
| **Agent 提示** | 这是硬件问题，Agent 无法修复。提示用户检查连接。 |

### 1.2 `uiautomator2.exceptions.ConnectError`

| 属性 | 内容 |
|------|------|
| **症状** | `d = u2.connect(serial)` 抛异常 |
| **原因** | uiautomator2 服务未启动 / 设备 ATX agent 未安装 |
| **修复** | `python -m uiautomator2 init` 安装 ATX agent 到设备 |
| **预防** | 新设备连接后自动执行 `init` |

### 1.3 `BrokenPipeError` / `ConnectionResetError`

| 属性 | 内容 |
|------|------|
| **症状** | WebSocket 连接断开，日志刷屏 |
| **原因** | 设备 USB 中途断开 / adb forward 端口冲突 |
| **修复** | 1. 自动重连逻辑<br>2. 超过 3 次 → 设备标记 OFFLINE |
| **预防** | 设备心跳检测，5s 无响应 → 自动清理 |

### 1.4 截图全黑 / 空白

| 属性 | 内容 |
|------|------|
| **症状** | `d.screenshot()` 返回纯黑/纯白图片 |
| **原因** | 设备锁屏 / 权限不足 / minicap 不兼容 |
| **排查** | 1. 检查设备是否锁屏 → 提示解锁<br>2. `adb shell screencap` 手动测试<br>3. 回退到 `uiautomator2` 自带的截图方法 |

## 二、Django 启动错误

### 2.1 `django.core.exceptions.ImproperlyConfigured`

| 属性 | 内容 |
|------|------|
| **症状** | Daphne 启动失败，Settings 加载异常 |
| **常见原因** | `INSTALLED_APPS` 引用了不存在的模块 / 路径错误 / .env 缺失 |
| **修复** | 1. `python manage.py check` 定位<br>2. 检查 `config/settings.py` → `INSTALLED_APPS` 模块名正确<br>3. 确认 `.env` 文件存在 |

### 2.2 `ModuleNotFoundError: No module named 'xxx'`

| 属性 | 内容 |
|------|------|
| **症状** | import 失败 |
| **原因** | 包未安装 / venv 未激活 / 模块目录缺 `__init__.py` |
| **修复** | `pip install xxx` 或 `pip install -r requirements.txt`<br>检查目标模块是否有 `__init__.py` |

### 2.3 `Port 8765 already in use`

| 属性 | 内容 |
|------|------|
| **症状** | Daphne 启动报端口冲突 |
| **原因** | 上次进程未正常退出（残留）或 `action_server.py` 同时在跑 |
| **修复** | 1. `lsof -i :8765` / `netstat -ano | findstr 8765` 找到 PID<br>2. `kill {PID}` 或 `taskkill /PID {PID} /F`<br>3. 或改变端口 `daphne -p 8766`

### 2.4 `SECRET_KEY 未设置`

| 属性 | 内容 |
|------|------|
| **症状** | Django 启动警告 / 部分功能不可用 |
| **原因** | `.env` 文件中未设置 `DJANGO_SECRET_KEY` |
| **修复** | 复制 `.env.example` → `.env`，或 `export DJANGO_SECRET_KEY=xxx` |

## 三、API 错误

### 3.1 全部 `/api/*` 返回 503

| 属性 | 内容 |
|------|------|
| **症状** | 所有 API 返回 `{"error": "无可用设备"}` |
| **原因** | ADB 未连接任何设备 |
| **预防** | 服务正常启动但不崩溃，前端显示"请连接设备" |

### 3.2 单个 API 返回 500

| 属性 | 内容 |
|------|------|
| **排查** | 1. 查看 Django 日志 `logs/`<br>2. 设 `DEBUG=True` → 看详细错误栈<br>3. 重点查：uiautomator2 操作异常 / DB 写入失败 / JSON 解析失败 |
| **常见** | dump 时 XML 解析失败（大页面或特殊字符）→ 加 try/except + 降级 |

### 3.3 `404 Not Found`

| 属性 | 内容 |
|------|------|
| **排查** | 1. 检查 URL 前缀 `/api/{module}/` 是否正确<br>2. `python manage.py show_urls` 确认路由已注册<br>3. 检查 `gateway/server.py` 是否漏了 `include_router` |

### 3.4 WebSocket 连不上

| 属性 | 内容 |
|------|------|
| **症状** | `ws://localhost:8765/ws/screenshot` 握手失败；元素定位页「正在连接截图流…」 |
| **原因** | ① Daphne 未以 ASGI 模式启动 ② Channels layer 配置错误 ③ **channels-redis msgpack 序列化器不兼容 → HTTP 500**（复发，见专档） |
| **修复** | 1. 确认启动：`daphne ... config.asgi:application` 非 `wsgi`<br>2. `config/settings.py` → `serializer_format: 'json'`<br>3. `python run.py restart` 后按专档 §三 诊断 |
| **专档** | → [元素定位截图流故障手册.md](./元素定位截图流故障手册.md) |

## 四、数据库错误

### 4.1 SQLite `database is locked`

| 属性 | 内容 |
|------|------|
| **症状** | 并发写入时 SQLite 报锁 |
| **解决** | 1. 启用 WAL 模式：`PRAGMA journal_mode=WAL;`<br>2. 降低 `timeout` 参数<br>3. 长期方案：迁 MySQL |

### 4.2 `OperationalError: no such table`

| 属性 | 内容 |
|------|------|
| **症状** | 访问新模块 API 报"表不存在" |
| **原因** | 未执行 `makemigrations` / `migrate` |
| **修复** | `python manage.py makemigrations {模块名} && python manage.py migrate` |

### 4.3 app.db 体积膨胀过快

| 属性 | 内容 |
|------|------|
| **原因** | 截图 base64 存入 DB / 大量测试结果未清理 |
| **修复** | 1. 截图存文件不存 DB<br>2. 执行 `VACUUM` 压缩<br>3. 设置结果自动清理策略（保留最近 N 天） |

## 五、前端错误

### 5.1 页面白屏

| 属性 | 内容 |
|------|------|
| **排查** | 1. F12 → Console 看 JS 错误<br>2. Network 面板看 API 请求状态<br>3. 检查 CDN 资源是否加载成功（Vue/Element Plus） |
| **修复** | 如果是 CORS 问题 → `config/settings.py` 加 `CORS_ALLOW_ALL_ORIGINS` |

### 5.2 WebSocket 实时截图不更新

| 属性 | 内容 |
|------|------|
| **症状** | 元素定位左侧手机框空白 / 「正在连接截图流…」 |
| **排查** | 1. `logs/backend.log` 搜 `MsgPackSerializer`（HTTP 500）<br>2. 浏览器 Network → WS `/ws/screenshot` 是否 101<br>3. `adb devices` + `GET /api/devices` 确认 `current` 非空<br>4. `GET /api/elements/screenshot` 是否返回 `ok:true` |
| **常见** | 设备未连接 → 显示「未选择设备」；WS 500 → 改 Channel 序列化为 json 并重启 |
| **专档** | → [元素定位截图流故障手册.md](./元素定位截图流故障手册.md)（复发问题完整手册） |

### 5.3 XPath 候选面板为空

| 属性 | 内容 |
|------|------|
| **排查** | 1. 点击的元素是否在 dump 数据中<br>2. XPath 生成逻辑是否抛异常<br>3. 检查 API `/api/elements/dump` 返回的 JSON |
| **修复** | 元素不存在 → 面板显示"未找到可定位元素"而非空白 |

## 六、Agent 专用错误

### 6.1 Agent 跨模块改了代码

| 属性 | 内容 |
|------|------|
| **症状** | Review 时发现改动文件超出任务声明的模块范围 |
| **修复** | `git checkout --` 回滚 → 重新约束 Agent 范围 → 执行 |
| **预防** | 任务描述中明确"只改 `modules/{X}/` + `frontend/.../{X}/`" |

### 6.2 Agent 改了其他模块的 import

| 属性 | 内容 |
|------|------|
| **症状** | 重构了一个模块，但修改了其他模块的 import 语句 |
| **造成** | 模块 A 的函数签名变了，模块 B 的 import 自动跟着变 |
| **修复** | B 模块的 import 应通过 A 的 api.py 而非直接调内部函数 |
| **检查** | `grep -r "from modules.{A}" modules/` → 只应在 A 内部出现 |

### 6.3 Agent 漏了文档同步

| 属性 | 内容 |
|------|------|
| **症状** | 代码改了但 `技术代码结构.md` 模块状态还是旧版本 |
| **修复** | 手动补充文档更新 |
| **预防** | 代码 Review 规则 #23~26 强制检查 |
