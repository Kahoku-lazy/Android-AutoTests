## 代码设计规范

> 本节是通用可复用原则，不绑定具体类名/表名；新增或重构代码时按此执行。

### 1. 数据契约

- 用 `dataclass` 定义**数据契约类**，字段与 ORM 模型（数据库表）**一一对应**、顺序一致，作为数据阶段的类型边界。
- 契约类的每个字段必须有**行内注释**说明变量定义：`field: type = default  # 变量定义说明`。
- 状态/类型等离散取值用 **str Enum** 定义，消除魔法字符串；对外序列化用 `.value`（仍是字符串，不破坏既有契约）。
- 契约只承载「数据本身」；展示层派生的计算字段（合成串、布尔标记、当前态、剩余值等）**不混入契约**，留在序列化层。

### 2. 模块与类设计

- **单一职责**：按职责域拆分，一个类负责一个职责；不建「万能类」。
- **组合优于继承**：类间通过构造函数注入组合，依赖方向**单向**（`A ← B ← C`），禁止循环依赖。
- 模块底部装配单例，职责类经单例协作。
- **新增逻辑先判归属**：按职责域落位；归属不明说明职责域划分需调整，而非塞进现有类或新建杂项类。

### 3. 文件组织

| 文件角色 | 职责 |
|---------|------|
| 契约文件 | 数据契约（dataclass + 枚举），纯数据零 I/O |
| 逻辑文件 | 按职责域拆分的类 + 单例装配 |
| 兼容层（转发壳） | 同名函数转发到对应单例，保证既有调用方零改动；调用方收敛后移除 |

- 写库仍走逻辑类方法（由 `api.py` 白名单转调）；状态机写原语落在职责类内，禁止散落。

## 本 App 契约（特例 + 真相源）

- **对外接口统一查阅**：`apps/device_pool/urls.py`（HTTP 端点）+ `apps/device_pool/api.py`（跨模块白名单）。
- **修改接口以 `urls.py` 为准**：路径、端点、视图对应关系均以 urls.py 为真相源，改动须与 views.py / api.py 同步。
- **特殊约定**：
  - 响应走全局标准信封，无 legacy 平铺特例。
  - 设备列表已内嵌当前设备字段，device-inspector 从列表读取即可，无需单独请求 current。
  - 其他 App 取设备 / 占设备统一走 `api.py` 的 `__all__` 白名单。
- **预留**：独立 current 端点前端暂未消费，保留路由；前端启用时同步本文。
