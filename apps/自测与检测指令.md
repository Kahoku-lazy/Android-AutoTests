## 1. Django 框架自检（system check）

| 指令 | 作用 |
|------|------|
| `python manage.py check` | 全项目系统检查（配置/模型/URL/模板等） |
| `python manage.py check <app_label>` | 只查某个 app，如 `case_manager` |
| `python manage.py check --deploy` | 部署项（SECRET_KEY、DEBUG、HTTPS 等）；本地可参考，CI 不阻断 |
| `python manage.py check --tag models` | 按标签只跑一类 |
| `python manage.py check --tag urls` | URL 相关 |
| `python manage.py check --tag security` | 安全相关 |
| `python manage.py check --list-tags` | 列出可用标签 |
| `python manage.py check --fail-level WARNING` | 警告也当失败 |

常见标签：`admin` `caches` `commands` `compatibility` `database` `files` `models` `security` `staticfiles` `templates` `translation` `urls`

扩展点（自定义检查）：`django.core.checks` + `@register()`，在 `AppConfig.ready()` 中加载。

## 2. 迁移自检（Django）

| 指令 | 作用 |
|------|------|
| `python manage.py makemigrations --check` | 模型有变更却未写 migration → 非 0 退出（不写文件） |
| `python manage.py makemigrations --dry-run` | 只预览会生成什么 |
| `python manage.py showmigrations` | 查看迁移应用状态 |
| `python manage.py makemigrations <app>` | 为指定 app 生成迁移 |
| `python manage.py migrate` | 应用迁移 |

## 3. 单元测试 / 集成测试

### 3.1 本仓库推荐：pytest（`pytest.ini`）

```bash
pytest                              # tests/ 下全部
pytest -m unit                      # 单元：纯逻辑，零 I/O
pytest -m integration               # 集成：ORM / 多模块
pytest -m api                       # 接口：HTTP + 鉴权
pytest -m "unit or integration"     # 日常后端自测
pytest -m e2e                       # 端到端（慢）
pytest -m ui                        # 真实浏览器（慢）
pytest -m case_manager              # 按业务模块
pytest tests/auth/ -v
pytest tests/case_manager/test_api_crud.py -k test_create
```

层级 marker：`unit` | `integration` | `api` | `ui` | `e2e` | `slow`  
业务 marker：`auth` `dashboard` `device_pool` `element_locator` `case_manager` `test_runner` `report_generator` `ai_assistant` `workflow` `evaluator` …

设置模块：`DJANGO_SETTINGS_MODULE = config.test_settings`

### 3.2 Django 原生（unittest）

```bash
python manage.py test
python manage.py test apps.case_manager
python manage.py test apps.case_manager.tests --keepdb
python manage.py test --failfast
python manage.py test --parallel
```

层级靠基类，**没有**官方 `--unit` / `--integration` 开关：

| 基类 | 更接近 |
|------|--------|
| `SimpleTestCase` | 单元（不碰 DB） |
| `TestCase` | 集成（DB，事务回滚） |
| `TransactionTestCase` | 更重集成 |
| `LiveServerTestCase` | 接近 E2E |
| `Client` / `APIClient` | 视图 / DRF 接口集成 |

本仓库日常以后端 **pytest** 为准。

## 4. 代码风格与规范检测（ruff，对齐 python-code.md）

配置：仓库根目录 `ruff.toml`（line-length=100，py313）。

```bash
# 检查（与 CI 路径一致）
ruff check apps/ agentscope_service/ config/ gateway/ shared/ models/
ruff format --check apps/ agentscope_service/ config/ gateway/ shared/ models/

# 自动修复
ruff check --fix apps/ agentscope_service/ config/ gateway/ shared/ models/
ruff format apps/ agentscope_service/ config/ gateway/ shared/ models/
```

| 规则族 | 含义（规范出处） |
|--------|------------------|
| `I` | Import 顺序：stdlib → 第三方 → 项目（§3） |
| `F401` | 禁止未使用 import（§3） |
| `F403` / `F405` | 禁止 `from x import *`（§3） |
| `E722` | 禁止裸 `except:`（§8） |
| `T201` | 禁止 `print()`，用 logging（§11；management/commands、tools、tests 豁免） |
| `Q` | 双引号（§11） |

排除：`**/migrations/*`、`**/__pycache__/*` 等。

## 6. 本仓库 Django 相关规范 / 架构检测

```bash
# 架构文档是否落后代码
python tools/gen_arch_stats.py --check-md

# 跨模块 ORM 写 / 防火墙边界（apps 间）
python tools/gen_arch_stats.py --check-boundaries

# 前端相关架构检查
python tools/gen_arch_stats.py --check-frontend

# 知识库检索自检（防幻觉）
python manage.py kb_self_test
python manage.py kb_self_test --detail
```

模块防火墙要点（详见 `.claude/rules/api-conventions.md`）：

- 允许：跨 App 读 Model；跨 App 调对方 `api.py`
- 禁止：跨 App 写 ORM；跨 App import service/runner/consumer/state_machine

## 7. 分层对照（改代码时选哪层）

| 层 | 指令 | 查什么 |
|----|------|--------|
| 框架 | `manage.py check` (+ `--deploy`) | Django 配置/模型/URL/安全 |
| 迁移 | `makemigrations --check` | 漏 migration |
| 风格 | `ruff check` / `ruff format --check` | 写法与格式规范 |
| 类型 | `mypy` / `basedpyright` | 类型与 Django stubs |
| 单元 | `pytest -m unit` | 纯逻辑 |
| 集成 | `pytest -m integration` / `api` | ORM、HTTP、模块协作 |
| 边界 | `gen_arch_stats.py --check-boundaries` | apps 防火墙 |
| E2E | `pytest -m e2e` / `ui` | 真链路（不全量日常跑） |
