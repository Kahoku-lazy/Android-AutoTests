🔍 第二部分：实际架构 vs 理想架构

⚠️ 发现 5 个架构差距，其中 2 个高优先级（dashboard 错位 + WebSocket 无认证）
差距主要集中在 L3 业务层模块边界和 L2 网关安全

差距对照表

#层级差距理想状态实际状态严重度修复方案
1L3 Dashboard 职责错位 独立的 apps/dashboard/ 负责聚合统计 散落在 ai_assistant/dashboard_views.py，导致 ai_assistant 横跨 6 个 App 的 Model 🔴 高 新建 apps/dashboard/ → 迁移 views + urls → 更新 config
2L2 WebSocket 无认证 connect() 验证 JWT，拒绝未授权连接 ws/screenshot 和 ws/test-run 直接 accept()，任何人都可连接 🔴 高 在 consumers.py 的 connect() 中从 query_string 提取 token 并验证
3L1 element-manager 模块重叠 element-locator 模块内的一个子视图 独立的前端模块 /element-mgr，操作同一批 element_locator 数据 🟠 中 合并到 element-locator → Tab 切换"设备发现 / 元素管理"
4L3 encrypt_key 重复实现 仅 api.py 一份，views.py import 使用 ai_assistant/views.py 和 api.py 各自实现一份加密函数 🟠 中 views.py 删除重复代码 → from .api import encrypt_key, decrypt_key
5L1 WS URL 端口硬编码 ws-url.js 统一构建，消除魔法数字 test-runner/index.vue 硬编码 :8765 端口 🟡 低 使用 shared/ws-url.js 替代硬编码字符串

🛠️ 实施路线

  • P0
    提取 Dashboard 为独立 App
    新建 apps/dashboard/（views.py + urls.py + apps.py），从 apps/ai_assistant/dashboard_views.py 迁移 4 个统计视图。 更新 config/urls.py 和 config/settings.py。 影响: 仪表盘 API 路径不变，前端无感。
  • P0
    WebSocket 添加 JWT 认证
    在 ScreenshotConsumer.connect() 和 TestRunConsumer.connect() 中从 query_string 提取 token， 调用 verify_token() 验证，拒绝无效连接。 前端 WS URL 改为 ws-url.js 统一构建，附加 token 参数。
  • P1
    合并 element-manager → element-locator
    element-locator/routes.js 新增 /element-mgr 子路由， 将 element-manager/index.vue 迁移为 element-locator/components/ElementManager.vue。 删除 frontend/src/modules/element-manager/ 目录。 更新 router.js 移除 element-manager 独立路由注册。
  • P1
    ai_assistant 去重 + 分离 CRUD
    删除 views.py 中重复的 encrypt/decrypt/mask 实现，改为 from .api import。 将 views.py 中的纯 CRUD 函数（list_agents, create_agent 等）迁移到 api.py， views.py 只保留 HTTP 入口（解析 request → 调用 api → 返回 JsonResponse）。
  • P2
    前端 .vue 迁移到 api.js 调用
    将 case-manager/CaseEditor.vue、test-runner/index.vue、 report-generator/index.vue 中直接 import client 的调用替换为 import { xxx } from './api.js'。api.js 文件已在上一轮创建，只需切换引用。
  • P2
    状态值 Enum 全局替换
    models/constants.py 已定义 14 个 Enum，逐步替换各 app models.py 中硬编码的 "ONLINE"/"BUSY" 等字符串为 DeviceStatus.ONLINE 等常量引用。 在 model 定义中添加 choices= 参数，增强 Django Admin 和 API 校验。
