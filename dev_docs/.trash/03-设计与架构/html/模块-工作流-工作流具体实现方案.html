VUE 3 + VITE + PINIA + SVG · COMFYUI PAGE FLOW · SCRATCH TEST CASE · BRIDGE

本文档描述工作流可视化 Demo 的实现方案演进。 当前实现位于 tests/workflow-demo（Vue 3 + Vite，非单文件 HTML）。 涵盖两个核心场景：① 页面跳转工作流（ComfyUI 风格 Page Flow Graph）、② Scratch 风格测试用例编辑（含图→用例数据桥）。

SVG 渲染引擎设计

所有可视化元素通过 document.createElementNS('http://www.w3.org/2000/svg', ...) 动态创建。 核心思路：一个 <svg> 根元素 + 一个 <g transform="translate(px,py) scale(s)"> 变换层实现平移和缩放。

节点渲染函数
function renderNode(node) { const NODE_W = 160, NODE_H = 72, RX = 12; const g = document.createElementNS(SVG_NS, 'g'); g.setAttribute('transform', `translate(${node.x},${node.y})`); g.classList.add('wf-node'); g.dataset.nodeId = node.id; // 阴影滤镜 const shadow = document.createElementNS(SVG_NS, 'filter'); // ... feDropShadow 配置 ... // 主体矩形 const rect = document.createElementNS(SVG_NS, 'rect'); rect.setAttribute('width', NODE_W); rect.setAttribute('height', NODE_H); rect.setAttribute('rx', RX); rect.setAttribute('fill', COLOR_MAP[node.color].bg); rect.setAttribute('stroke', COLOR_MAP[node.color].border); rect.setAttribute('stroke-width', node._selected ? '3' : '2'); g.appendChild(rect); // 图标文字 const icon = document.createElementNS(SVG_NS, 'text'); icon.setAttribute('x', 16); icon.setAttribute('y', 30); icon.textContent = node.icon; g.appendChild(icon); // 标题 const title = document.createElementNS(SVG_NS, 'text'); title.setAttribute('x', 44); title.setAttribute('y', 26); title.setAttribute('font-weight', '700'); title.textContent = node.label; g.appendChild(title); // 副标题 const sub = document.createElementNS(SVG_NS, 'text'); sub.setAttribute('x', 44); sub.setAttribute('y', 46); sub.setAttribute('fill', '#8a7b66'); sub.setAttribute('font-size', '11'); sub.textContent = node.subtitle || ''; g.appendChild(sub); // 状态圆点（执行轨迹模式） if (node.status) { const dot = document.createElementNS(SVG_NS, 'circle'); dot.setAttribute('cx', NODE_W - 14); dot.setAttribute('cy', 16); dot.setAttribute('r', 6); dot.setAttribute('fill', STATUS_COLORS[node.status]); dot.classList.add('status-dot'); g.appendChild(dot); } return g; }
连线渲染函数
function renderEdge(edge, fromNode, toNode) { const g = document.createElementNS(SVG_NS, 'g'); // 计算起点/终点（节点边缘） const NODE_W = 160, NODE_H = 72; const x1 = fromNode.x + NODE_W; // 右边缘中点 const y1 = fromNode.y + NODE_H / 2; const x2 = toNode.x; // 左边缘中点 const y2 = toNode.y + NODE_H / 2; // 贝塞尔曲线控制点 const cx = (x1 + x2) / 2; // 路径 const path = document.createElementNS(SVG_NS, 'path'); const d = `M${x1},${y1} C${cx},${y1} ${cx},${y2} ${x2},${y2}`; path.setAttribute('d', d); path.setAttribute('fill', 'none'); path.setAttribute('stroke', edge.hasPopup ? '#e05a5a' : COLOR_MAP[edge.color].border); path.setAttribute('stroke-width', '2'); path.setAttribute('stroke-dasharray', edge.hasPopup ? '6,3' : 'none'); // 箭头标记 path.setAttribute('marker-end', 'url(#arrowhead)'); g.appendChild(path); // 标签（路径中点） const label = document.createElementNS(SVG_NS, 'text'); const mx = (x1 + x2) / 2, my = (y1 + y2) / 2 - 8; label.setAttribute('x', mx); label.setAttribute('y', my); label.setAttribute('text-anchor', 'middle'); label.setAttribute('font-size', '9'); label.setAttribute('fill', '#8a7b66'); label.textContent = edge.label; g.appendChild(label); // 弹窗 badge if (edge.hasPopup) { const badge = document.createElementNS(SVG_NS, 'rect'); badge.setAttribute('x', mx - 16); badge.setAttribute('y', my + 2); badge.setAttribute('width', 32); badge.setAttribute('height', 14); badge.setAttribute('rx', 3); badge.setAttribute('fill', '#e05a5a'); g.appendChild(badge); const btxt = document.createElementNS(SVG_NS, 'text'); btxt.setAttribute('x', mx); btxt.setAttribute('y', my + 12); btxt.setAttribute('text-anchor', 'middle'); btxt.setAttribute('font-size', '8'); btxt.setAttribute('fill', '#fff'); btxt.setAttribute('font-weight', '700'); btxt.textContent = '⚠弹窗'; g.appendChild(btxt); } return g; }
交互系统设计

拖拽节点

事件：mousedown/mousemove/mouseup
命中检测：检查鼠标是否在节点 rect 范围内
坐标转换：screenX → SVG 坐标 = (screenX - panX) / scale
状态：拖拽中提升 z-index + 添加阴影

缩放

事件：wheel (passive: false, preventDefault)
范围：0.25x ~ 3x
以鼠标为中心：
newPan = mouse - (mouse - oldPan) * (newScale / oldScale)
变换层：更新 transform group 的 scale

平移画布

触发：mousedown 在空白区域 → mousemove → mouseup
变换：更新 transform group 的 translate
光标：grab → grabbing
排除：点击节点时不触发平移

Hover Tooltip

事件：mouseenter/mouseleave 在节点和连线上
渲染：独立的 tooltip div（HTML 层，非 SVG），跟随鼠标移动
内容：节点 → 显示完整 label + subtitle + 弹窗类型；连线 → 显示触发元素详情
延迟：200ms 后显示，避免快速划过闪烁

点击选中

效果：选中节点边框加粗至 3px + 高亮色；连线变粗 + 高亮
上下游高亮：选中节点时，其所有出/入连线变为高亮色，关联节点边框变亮
取消选中：点击空白区域 → 恢复默认样式
信息面板：选中后右侧弹出详情卡片（绝对定位的 HTML div）

坐标系统
// 三层坐标模型 // 屏幕坐标 (screenX, screenY) — 鼠标事件原生坐标 // ↓ screenToSVG() // SVG 坐标 (svgX, svgY) — 应用 pan/scale 逆变换后 // ↓ 直接比较 // 节点坐标 (node.x, node.y) — 存储在数据模型中 function screenToSVG(sx, sy) { return { x: (sx - panX) / scale, y: (sy - panY) / scale }; } function hitTestNode(svgX, svgY, node) { return svgX >= node.x && svgX <= node.x + NODE_W && svgY >= node.y && svgY <= node.y + NODE_H; }
布局算法

页面流：层级布局

思路：拓扑排序 → 分层 → 每层水平排列
步骤：
1. BFS 从根节点（无入边的节点）开始
2. 按距离分配层级 layer
3. 同层节点水平等距排列：x = layer * 260, y = index * 120 + offset
4. 特殊处理：弹窗目标节点加红色虚线边框
间距：层间距 260px，节点间距 120px

执行轨迹：水平流水线

思路：所有节点单行水平排列
步骤：
1. 按 step.index 排序
2. x = index * 200 + 40, y = 200
3. 超过 5 个节点自动换行
4. 节点间自动生成直线连线
间距：节点间距 200px，带箭头直线

动画系统
动画触发时机实现方式

端口锚点系统（Port Anchor System）

设计思路

每个节点有输入端口（Input Port）和输出端口（Output Port）。 连线从具体的端口锚点出发/到达，而非节点边界。
· Input Port：左侧蓝色圆点，接收上游连线
· Output Port：右侧紫色圆点 + 元素名称标签，发送下游连线
· 每个 PageNode 至少 1 个 Input Port（默认"入口"），可增加
· Output Port 从元素池选取创建

坐标计算

const HEADER_H = 40, PORT_ROW_H = 28; function getPortPos(node, port, side) { const idx = side === "left" ? node.inputPorts.indexOf(port) : node.outputPorts.indexOf(port); return { x: side === "left" ? node.x : node.x + node.w, y: node.y + HEADER_H + (idx + 0.5) * PORT_ROW_H }; }

V3 核心设计：端口类型系统

这是最重要的架构升级。ComfyUI 用类型系统校验连线合法性（IMAGE 不能直接连到 MODEL），我们用来区分页面跳转 vs 弹窗触发 vs 普通导航。

// 端口类型枚举 — 语义化区分不同业务场景 const PORT_TYPE = { // 输入端口类型 ENTRY: 'entry', // 页面入口 — 接收上游导航连线 POPUP_TRIGGER: 'popup_trigger', // 弹窗触发入口 — 仅接收 popup_fixed 连线 // 输出端口类型（对应元素行为） NAVIGATION: 'navigation', // 普通页面跳转 — 点击后跳转到另一个页面 POPUP_FIXED: 'popup_fixed', // 固定触发弹窗 — 点击后必定弹出（连线到 PopupNode） POPUP_RANDOM: 'popup_random', // 随机弹窗 — 页面自动随机弹出（暂搁置） POPUP_CLOSE: 'popup_close', // 关闭弹窗 — 从 PopupNode 返回原页面 }; // 连线类型校验规则 const LINK_RULES = { 'navigation': ['entry'], // 导航连接到页面入口 'popup_fixed': ['popup_trigger'], // 固定弹窗连接到弹窗触发入口 'popup_close': ['entry'], // 关闭弹窗连接到页面入口 'popup_random': ['popup_trigger'], // 随机弹窗连接到弹窗触发入口（搁置） };
V3 核心设计：连线格式（ComfyUI 风格）

旧格式 (v2) — 字符串 portId

{ id:"e1", fromNodeId:"page_1", fromPortId:"out_1", toNodeId:"page_2", toPortId:"in_1" }

新格式 (v3) — slot_index + type

{ id: 165, origin_id: "page_1", // 源节点 origin_slot: 0, // 源输出端口索引 target_id: "page_2", // 目标节点 target_slot: 0, // 目标输入端口索引 type: "navigation" // 传输类型 }

为什么改用 slot_index？ComfyUI 的做法证明整数索引比字符串 ID 更简洁、更稳定。 端口在数组中的位置天然唯一，不需要额外的 ID。type 字段让每条连线携带语义信息——知道这条线代表"导航"还是"弹窗"。

核心设计哲学：ComfyUI 教会我们——好的工作流系统 = 强类型端口 + 槽位索引 + 双格式分离 + 注册表扩展。 但我们的业务场景不同：ComfyUI 连接 AI 模型节点，我们连接 App 页面节点。弹窗节点、元素池、节点上限、搜索过滤 是我们针对 UI 自动化测试场景的独特创新。

为什么用 SVG 而非 Canvas？节点数量有限（最多 10 个页面 + 弹窗），SVG 的性能完全够用， 且 SVG 支持 CSS 动画、hover 伪类、响应式缩放，开发效率远超 Canvas。ComfyUI 用 Canvas 是因为需要处理 上百个节点和复杂 WebGL 渲染，我们的场景不需要。

COMPONENT REGISTRY · RULE ENGINE · DUAL ELEMENT POOLS · PLUGGABLE ARCHITECTURE

组件注册表（COMPONENT_REGISTRY）

所有组件类型集中注册，每种组件定义自己的端口默认值、最大实例数、元素池来源、业务规则。 新增组件类型只需在注册表中添加一项，无需修改渲染引擎。

const COMPONENTS = { PageComponent: { name: "页面组件", icon: "📱", color: "teal", maxInstances: 10, defaultInputs: [{ name: "入口", type: "entry" }], defaultOutputs: [], // 用户从元素池手动创建 elementPool: "page_elements", // 使用页面元素池 rules: { // 页面可以随时创建输出节点 canCreateOutput: (node, ctx) => true, // 没有输出节点的页面只能被连线，不能连出 canBeSource: (node, ctx) => node.outputs.length > 0, // 页面始终可以接收连线 canBeTarget: (node, ctx) => true, }, }, PopupComponent: { name: "弹窗组件", icon: "⚠️", color: "red", maxInstances: Infinity, defaultInputs: [{ name: "触发", type: "popup_trigger" }], defaultOutputs: [], // 必须先有输入才能创建 elementPool: "popup_elements", // 使用弹窗元素池 rules: { // 弹窗必须先收到输入连线，才能创建输出节点 canCreateOutput: (node, ctx) => ctx.links.some(l => l.target_id === node.id), canBeSource: (node, ctx) => node.outputs.length > 0, canBeTarget: (node, ctx) => true, }, }, };

业务规则引擎

每个组件实例在渲染和交互时，通过 rules 动态评估当前状态：

规则触发时机效果
canBeSource渲染输出端口、mousedown 端口false → 不渲染输出端口，无法拖线
canBeTarget渲染输入端口false → 不渲染输入端口（当前所有组件都为 true）
canCreateOutput渲染 + 添加元素按钮、右键菜单false → 隐藏添加按钮，显示提示文字
