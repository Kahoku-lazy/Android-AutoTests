# 管理智能体


## 管理智能体 — 灵感来源

## 来源清单

| 来源 | 启发点 |
|------|--------|
| PM-Project Stage-Gate | Agent 按生命周期分工，Gate 做 Go/No-Go |
| AgentScope 2.0 | Tool / Team / SSE，业务能力可工具化 |
| `.claude/` 双轨实践 | 日常开发 Agent 与项目管理 Agent 并存 |
| Cursor Skills / Subagents | Skill 可发现、可组合；角色可路由 |

## 核心问题

如何让智能体「可编排、可审计、可替换」，而不是一次性对话黑盒？

## 管理智能体 — 设计文档

## 管理目标

- **路由清晰**：什么问题找哪个 Agent / Skill
- **权限收敛**：写操作走 API/契约，禁止绕过防火墙
- **可观测**：对话、工具调用、任务状态可追溯
- **可降级**：Redis / 设备不可用时有明确降级路径

## 设计要点

1. `.claude/` = 日常开发轨；`.agents/` = PM 全生命周期轨（移植中）
2. 角色拆分见 `04-任务拆分/{角色}/`（设定 / Skill / MCP / 计划）
3. AgentScope Tool 清单与注册工厂作为「能力目录」
4. Memory 写入规范：`project` / `feedback` / `user`，并更新索引

## 管理智能体 — 实践结果

## 已落地

## 待加强

- `.agents/` PM Agent 移植尚未完成
- 智能体运行指标（成功率、返工率）未系统采集
- 管理员侧「一键验收 AI 输出」流程未产品化

## 管理智能体 — 总结与归纳

1. **先定角色再挂 Skill**：没有角色边界，Skill 会变成工具堆。
2. **双轨并存优于强行合并**：开发轨与 PM 轨场景不同，路由比合并更重要。
3. **Memory 是管理资产**：纠正与教训不入库，等于每次从零教。
4. **降级策略是管理要求**：无设备 / 无 Redis 时必须可解释、可验收。

## 推荐产出物模型

```
智能体管理包/
├── 角色卡（职责 / 边界 / 协作）

├── 路由表（用户意图 → Agent）
├── Memory 索引

```
