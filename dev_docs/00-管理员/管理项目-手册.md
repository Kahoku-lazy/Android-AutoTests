# 管理项目


## 管理项目 — 灵感来源

## 来源清单

| 来源 | 启发点 |
|------|--------|
| Stage-Gate | 阶段门禁，未过 Gate 不进入下游 |
| 文档索引 v3 | 侧边栏 + 仪表盘，文档按生命周期可见 |

## 核心问题

如何让项目「文档即状态机」：打开索引就知道卡在哪一阶段、缺什么产出？

## 管理项目 — 设计文档

## 管理目标

- Stage-Gate 六阶段文档齐全、可导航
- Gate 1/2/3 结论可追溯
- 角色任务计划与验收结果可对照
- 复盘行动项有 Owner 与状态

## 目录约定（PROJECT_ROOT）

```
立项验证/ → PRD需求/ → 设计与架构/ → 任务拆分/ → 开发与测试/ → 发布与复盘/
00-管理员/   ← 本栏：管理员方法论与成果模型
```

## 管理员日常动作

1. 看仪表盘完备度与空白阶段  
2. 抽查角色「详细任务计划 / 验收评审结果」  
3. 签发 Gate / 确认行动项  
4. 要求 AI 把结论写回对应栏目（禁止只口头汇报）

## 管理项目 — 总结与归纳

1. **文档结构 = 管理仪表盘**：栏目空就是风险信号。  
2. **复盘与执行分离**：评估报告进复盘，方法论进管理员。  
3. **管理员签发，不代写执行细节**：拆分侧管理员目录留空是刻意设计。  
4. **先 Gate 后开发**：跳过门禁的「快」会变成复盘里的「返工」。

## 管理项目 — 成果模型

## 推荐产出物模型

```
项目管理包/
├── Stage-Gate 索引（可点击）
├── 各阶段完备度快照
├── Gate 1/2/3 结论卡
├── 角色任务看板（计划 vs 验收）
├── 复盘行动项看板
└── workflow-manifest（跨阶段契约）
```

## 验收标准（管理员）

- [ ] 六阶段均可打开且无死链  
- [ ] 空白阶段有占位与责任角色  
- [ ] 复盘行动项有状态  
- [ ] 重大变更先改 PRD/架构再改代码
