# 验收AI输出


## 验收 AI 输出 — 灵感来源

## 来源清单

| 来源 | 启发点 |
|------|--------|
| Gate Review | 正式 Go/No-Go，而不是「看起来不错」 |
| 知行合一 / 三省吾身 | 不确定就停，禁止假装理解 |
| 功能测试五维 | 功能/接口/安全/数据/性能 |
| 复盘短板「验收上线 40 分」 | 验收是当前最大管理缺口 |

## 核心问题

如何把「AI 说做完了」变成「管理员可签字的验收包」？

## 验收 AI 输出 — 设计文档

## 验收对象

| 类型 | 验收关注点 |
|------|------------|
| 文档（PRD/架构/复盘） | 结构完整、可导航、无死链、结论可执行 |
| 代码变更 | 行为正确、边界不破、有证据 |
| Agent/Skill 配置 | 路由正确、权限不过度、可降级 |
| 测试报告 | 覆盖承诺范围、失败有归因 |

## 建议验收流程

```
AI 提交产出 → 对照栏目模板检查齐全性
    → 抽检关键路径（浏览器/用例）
    → 记录验收结论到角色「验收评审结果」或复盘行动项
    → 通过则归档；不通过则退回并写 Memory
```

## 管理员否决权

以下情况直接 No-Go：无 PRD 改功能、无浏览器验证、静默吞错、硬编码密钥、跨模块违规写。

## 验收 AI 输出 — 实践结果

## 已落地

| 实践 | 结果 |
|------|------|
| 文档索引与分类 | 产出物有固定落点，便于对照验收 |
| 角色验收评审结果模板 | 各角色可记 Gate/批次结论 |
| 复盘评估报告 | 质量/闭环/工程已有基线分数 |
| 验证铁律写入规则 | 降低「伪完成」概率 |

## 待加强

- 缺少统一「验收清单」勾选页（可后续做成 HTML）  
- Gate 结果未结构化（JSON/manifest）  
- AI 输出与管理员签字的双向追溯仍弱

## 验收 AI 输出 — 总结与归纳

1. **验收标准要先于生成**：先定栏目五点/Gate，再让 AI 填。  
2. **证据重于叙述**：截图、用例、链接比长篇「已完成」有用。  
3. **退回必须沉淀**：同一错误第二次出现，说明验收没形成记忆。  
4. **管理员验收是产品能力**：不是附加礼貌流程。

## 验收 AI 输出 — 成果模型

## 推荐产出物模型（验收包）

```
验收包/
├── 产出清单（路径 + 类型）
├── 对照标准（栏目五点 / Gate 条款）
├── 证据（截图、日志、测试结果）
├── 风险与遗留
├── 结论：Go / Conditional Go / No-Go
└── 后续行动项（Owner / 截止日期）
```
