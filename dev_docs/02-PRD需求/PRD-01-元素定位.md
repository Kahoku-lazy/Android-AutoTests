## 2. 功能需求与验收标准

### 2.1 Tab1 — 设备发现页

#### F-01-01 设备选择

**需求**：下拉框列出所有在线设备，显示设备型号、分辨率、连接方式图标（USB/WiFi）。

**验收**：
- [ ] 有在线设备时，下拉框展示所有 ONLINE 和 BUSY 设备
- [ ] 每项显示：📱型号 · 分辨率(如1080×2400) · 🔌USB 或 📶WiFi 图标
- [ ] 无在线设备时，下拉框为空，显示「暂无在线设备，请先连接」
- [ ] 选择设备后，30 秒内自动刷新设备在线状态
- [ ] 当前选中设备离线时，下拉框旁出现 ⚠️ 警告标记 + 「设备已离线」文字

**测试方案**：
```
场景1: 正常选择
  前置：设备管理页已连接 2 台设备(USB/WiFi 各一)
  操作：打开元素定位页 → 点击设备下拉框
  期望：显示 2 台设备，带型号/分辨率/连接图标，USB 和 WiFi 图标不同

场景2: 无设备
  前置：没有连接任何设备
  操作：打开元素定位页
  期望：下拉框为空，显示占位提示

场景3: 设备离线
  前置：已选中设备A
  操作：断开设备A的USB连接 → 等待 ≤30 秒
  期望：出现 ⚠️ 警告标记 + 「设备已离线」
```

---

#### F-01-02 Dump UI 层级

**需求**：点击「Dump UI」按钮，几秒内返回当前页面的完整 UI 层级树，每个可交互元素自动生成最多 8 种 XPath 候选。

**验收**：
- [ ] 点击按钮后，按钮显示 loading 状态（不可重复点击）
- [ ] 正常情况 2-5 秒内返回结果，元素列表和截图覆盖层同时刷新
- [ ] 每个含 resource-id 或 text 的元素至少有 1 种 XPath
- [ ] XPath 候选按匹配数（count）升序排列，count=1 排最前
- [ ] Dump 超时 30 秒，提示「抓取超时，请检查设备状态后重试」
- [ ] XML 截断时容错处理，仍展示可解析部分的元素

**测试方案**：
```
场景1: 正常 Dump
  前置：设备已连接，停留在 App 某个页面
  操作：点击「Dump UI」
  期望：按钮变灰+loading → 2-5秒后返回元素列表 → 截图出现蓝色边界框

场景2: 连续点击
  前置：同上
  操作：快速双击「Dump UI」
  期望：第一次点击后按钮变灰，第二次点击无效（不触发重复请求）

场景3: 超时
  前置：设备响应极慢或卡死
  操作：点击「Dump UI」→ 等待 30 秒
  期望：30 秒后显示「抓取超时，请检查设备状态后重试」

场景4: 复杂页面
  前置：打开一个包含 50+ 可交互元素的页面
  操作：点击「Dump UI」
  期望：所有 XPath 候选按 count 升序排列，count=1 的排在第一位
```

#### F-01-03 实时截图流

**需求**：设备画面以 2fps 实时推送到页面，Canvas 叠加层绘制元素边界框（蓝色=普通，橙色=悬停，红色=选中）。

**验收**：
- [ ] 首次加载时，REST 首帧在 WebSocket 建立前先展示（不白屏）
- [ ] WebSocket 连接成功后，截图每秒刷新约 2 次
- [ ] 截图正确缩放到手机外框内，不拉伸变形
- [ ] Canvas 覆盖层与截图位置完全对齐
- [ ] 三种颜色边界框正确区分：蓝色(普通元素) · 橙色(悬停) · 红色(选中)
- [ ] 断连后 3 秒内显示「截图流已断开」+ 倒计时，自动重连
- [ ] 重连失败后显示「重试」按钮，手动点击可重连

**测试方案**：
```
场景1: 正常截图流
  前置：设备已连接，App 在登录页
  操作：观察截图区域 5 秒
  期望：画面流畅更新(约 10 帧/5秒)，不卡顿，不白屏

场景2: 首帧加载
  前置：清空缓存，设备已连接
  操作：刷新页面 → 观察加载过程
  期望：先出现静态截图(REST首帧) → WebSocket连上后变为实时流，无白屏间隙

场景3: 断连重连
  前置：截图流正常运行中
  操作：断开设备 ADB 连接
  期望：≤3 秒出现「截图流已断开」+ 倒计时 → 自动尝试重连

场景4: 重连失败
  前置：截图流断开，设备已物理移除
  操作：等待自动重连失败
  期望：显示「重试」按钮，点击后再次尝试连接

场景5: 边界框对齐
  前置：Dump 已完成，截图上有元素边界框
  操作：鼠标悬停在某个蓝色边界框上 → 点击
  期望：悬停变橙色，点击变红色；边界框位置与下方元素视觉位置一致
```

#### F-01-04 点击截图选取元素

**需求**：在截图上直接点击元素边界框，右侧面板展示该元素的 XPath 候选列表和属性详情。

**验收**：
- [ ] 点击边界框内区域 → 该元素被选中，边界框变红色
- [ ] 右侧 XPath 候选面板展示该元素的所有 XPath（策略名 + 表达式 + 匹配数）
- [ ] 右侧元素详情面板展示 6 个核心属性（class_name, text, resource_id, content_desc, bounds, clickable）
- [ ] 点击无元素区域（边界框外的空白处）→ 无反应，保持当前选中状态
- [ ] 再次点击另一个元素的边界框 → 切换选中，上一个元素恢复蓝色

**测试方案**：
```
场景1: 点击选取
  前置：Dump 已完成，截图上有元素边界框
  操作：点击"登录"按钮的蓝色边界框
  期望：边界框变红；右侧显示 XPath 候选列表(至少1条)；右侧显示元素属性(class=Button, text=登录...)

场景2: 切换选中
  前置：已选中元素A(红色)
  操作：点击元素B的边界框
  期望：元素A变蓝，元素B变红；右侧面板内容切换为元素B

场景3: 点击空白
  前置：已选中元素A
  操作：点击截图上没有边界框的区域
  期望：元素A 保持红色选中状态，右侧面板不变
```

#### F-01-05 XPath 候选操作

**需求**：XPath 列表中每条候选提供复制和「添加到用例」操作。

**验收**：
- [ ] 每条 XPath 旁有 📋 复制按钮，点击后 XPath 复制到剪贴板
- [ ] 复制成功提示「已复制到剪贴板」
- [ ] 复制失败（浏览器不支持）降级为选中文本，用户手动 Ctrl+C
- [ ] 每条 XPath 旁有 ➕ 按钮，点击后通过 EventBus 发送到当前编辑的用例
- [ ] 发送成功提示「已添加到用例」
- [ ] 无正在编辑的用例时，提示「请先在用例管理中打开一个用例」

**测试方案**：
```
场景1: 复制 XPath
  前置：已选中元素，XPath 面板展示候选列表
  操作：点击第一条 XPath 的 📋 按钮
  期望：剪贴板包含该 XPath 文本；出现「已复制到剪贴板」提示

场景2: 添加到用例
  前置：用例管理页正在编辑一个用例（StepEditor 打开）
  操作：在元素定位页点击某 XPath 的 ➕ 按钮
  期望：用例编辑器新增一个 click 步骤，XPath 已填入；出现「已添加到用例」提示

场景3: 无编辑中的用例
  前置：用例管理页未打开任何编辑器
  操作：点击 ➕ 按钮
  期望：提示「请先在用例管理中打开一个用例」
```

### 2.2 Tab2 — 元素管理页

#### F-02-01 页面列表管理

**需求**：左侧页面树（最多 5 层嵌套），支持新建、重命名、删除页面。

**验收**：
- [ ] 页面以树形结构展示，支持展开/折叠
- [ ] 右键页面节点 → 菜单：新建子页面 / 重命名 / 删除 / 移动到...
- [ ] 新建页面：输入 label（必填且全局唯一），可选 package、activity
- [ ] label 重复时提示「该页面名称已存在，请使用其他名称」
- [ ] 重命名：行内编辑，回车保存，Esc 取消
- [ ] 删除页面：二次确认「删除后将同时删除该页面下的所有元素，确定？」确认后级联删除
- [ ] 嵌套超过 5 层时提示「目录层级不能超过 5 层」
- [ ] 「全部清空」按钮：二次确认后 CASCADE 删除所有页面和元素

**测试方案**：
```
场景1: 新建页面
  前置：页面列表为空
  操作：右键根节点 → 新建页面 → 输入 label="登录页"→ 回车
  期望：树中出现"登录页"节点，右侧元素表格为空

场景2: 重名检测
  前置：已有页面"登录页"
  操作：新建页面，label="登录页"→ 回车
  期望：输入框标红，提示「该页面名称已存在，请使用其他名称」

场景3: 级联删除
  前置：页面"登录页"下有 5 个元素
  操作：右键"登录页"→ 删除 → 确认弹窗点「确定」
  期望：页面和 5 个元素全部删除；前往数据库确认无残留

场景4: 深度限制
  前置：已有 5 层嵌套页面 a→b→c→d→e
  操作：右键 e → 新建子页面
  期望：提示「目录层级不能超过 5 层」
```

#### F-02-02 元素表格管理

**需求**：右侧元素表格展示当前选中页面的所有元素，支持筛选、编辑别名、切换测试点。

**验收**：
- [ ] 表格列：别名(可编辑) · XPath(首候选) · Class · Text · Resource ID · 可点击(标签) · 测试点(Switch)
- [ ] 4 个筛选 Tab：全部 / 可点击 / 已命名 / 测试点，切换后表格数据即时过滤
- [ ] 别名列支持行内编辑：双击进入编辑 → 回车保存 → Esc 取消
- [ ] 测试点 Switch 切换即时生效，不需要额外保存
- [ ] 「添加元素」按钮：弹窗填 class_name/text/resource_id/bounds → 手动添加
- [ ] 右上角显示「共 N 个元素」
- [ ] 无元素时显示空态「暂无元素，请先 Dump 或手动添加」

**测试方案**：
```
场景1: 筛选
  前置：页面下有 20 个元素，其中 8 个可点击
  操作：点击「可点击」Tab
  期望：表格显示 8 个元素；右上角显示「共 8 个元素」

场景2: 别名编辑
  前置：元素"Button_01"无别名
  操作：双击别名列 → 输入"登录按钮"→ 回车
  期望：别名列显示"登录按钮"；切换到「已命名」Tab 可看到该元素

场景3: 测试点切换
  前置：元素别名="登录按钮"，测试点=关
  操作：点击该行的测试点 Switch
  期望：Switch 变为开；切换到「测试点」Tab 可看到该元素
```

### 2.3 跨模块交互

#### F-03-01 EventBus 跨模块发送

**需求**：元素定位页可将 XPath 通过 EventBus 发送到用例管理模块的步骤编辑器。

**验收**：
- [ ] XPath 候选面板点击 ➕ → EventBus 发送 `add-step-to-case` 事件
- [ ] 事件包含：xpath、element_alias、step_type(默认 click)
- [ ] 用例编辑器的 StepEditor 接收事件 → 自动新增步骤
- [ ] 无编辑器打开时，提示用户先打开用例

**测试方案**：
```
场景1: 正常跨模块发送
  前置：用例管理页正在编辑用例A
  操作：元素定位页选中元素 → 点击某 XPath 的 ➕ 
  期望：切换到用例管理页 → 用例A 步骤列表末尾新增一个 click 步骤 → XPath 已填入

场景2: 无接收方
  前置：用例管理页在列表态（未打开任何编辑器）
  操作：点击 ➕ 
  期望：提示「请先在用例管理中打开一个用例」
```
