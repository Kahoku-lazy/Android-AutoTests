## 1. 功能定位

设备检查器是平台的**快照式页面元素获取工具**：用户从设备管理拉取设备，选择获取方法（Dump UI / OCR，可同时），一键抓取手机当前页面并解析为结构化 JSON（元素层级与 XPath、OCR 文本与坐标），快照连同页面截图落库保存，可回看、可筛减后一键导入元素定位模块；同时作为**页面快照查看器**，可打开元素定位已保存的页面（左边截图、右边表格，元素边界框叠加与选取保留）。

**核心模块功能**：

| 模块 | 功能编号 | 核心职责 |
|------|----------|----------|
| ① 获取表单 | F-01-01 / F-01-02 | 设备选择（拉取设备管理） / 方法选择与一键获取（dump / OCR / both） |
| ② 快照展示 | F-02-01 ~ F-02-03 | 截图展示与边界框选取 / 元素与 OCR 合并表格（按坐标合并展示） |
| ③ 快照管理 | F-03-01 / F-03-02 | 快照列表与 JSON 回看 / 快照删除 |
| ④ 导入元素定位 | F-04-01 | 筛减表单数据 → 决策存入元素定位（自定义目录与页面名） |
| ⑤ 页面回看 | F-05-01 | 打开元素定位已保存页面（只读查看） |

设备检查器是**快照持久化服务（自有数据表）**：区别于 v1.6 的瞬态会话，每次获取的 dump/OCR 解析结果、页面截图与缩略图均落库保存；元素资产归属仍由元素定位模块（PRD-04）承担，检查器快照与元素定位页面互为独立数据，用户决策后才导入。

## 2. 功能详细规格

> 本章按五个功能模块分层。每模块依次说明：**设计目的 → 功能需求 → 组件与边界 → 验收方式**。
> 模块 ↔ 功能编号映射见 §1（F-xx-xx 用于 §5 API、§8 非目标交叉引用）。

### 2.1 模块一：获取表单

**设计目的**

获取表单是检查器的**唯一入口**：从设备管理拉取可选设备，选择获取方法（Dump UI / OCR，可同时），一键抓取手机当前页面并生成快照。

**F-01-01 设备选择**

**功能实现逻辑**：用户从表单下拉框选择设备（用户动作）。系统从设备管理模块（PRD-02）拉取已注册且可用的设备列表供选择（功能响应）。

**详细功能点**：

- **设备可选范围**：展示设备管理模块中已注册且可用的设备（状态 `ONLINE` / `BUSY`）；执行引擎占用中的设备不展示（与 PRD-02 口径一致），避免干扰执行任务。
- **数据交互**：设备列表与元信息**从设备管理模块读取**（`GET /api/devices/`，契约见 PRD-02）；本模块不注册、不扫描、不锁定、不释放设备。
- **职责与边界**：只做设备选择；设备生命周期管理由设备管理模块承担。

**边界状态**：无可用设备 → 下拉框为空，提示「暂无可用设备，请先在设备管理中连接设备」。

**验收方式**：

- 下拉框仅展示已注册且可用的设备（执行引擎占用中的不出现）
- 选中设备后展示品牌 / 型号 / 分辨率 / 连接类型

**F-01-02 方法选择与一键获取**

**功能实现逻辑**：用户选择获取方法并点击「获取」（用户动作）。系统按所选方法抓取设备当前页面——Dump UI 层级、OCR 屏幕文字（可同时）——解析为结构化 JSON，连同页面截图落库为一条**快照**，并展示到快照展示区（功能响应）。

**详细功能点**：

- **方法选择**：三选一——仅 Dump / 仅 OCR / 两者同时（默认两者同时）。
- **抓取口径**：Dump 走完整 UI 树解析（元素属性 + XPath 候选，可交互元素判定 `clickable` / `text` / `resource_id` / `content_desc` 任一非空）；OCR 走 cnocr 识别（文字 + 坐标 + 置信度）。
- **快照落库**：抓取成功后写入 `di_snapshots`——dump 解析 JSON、OCR 解析 JSON、页面截图路径、package / activity、数量统计、设备、方法、创建人；元素缩略图按 bounds 从截图裁剪落盘、OCR 缩略图落盘，JSON 中仅存路径（见 §4.3）。
- **无占用**：获取是快照式操作，**不改变设备 ONLINE / BUSY 状态**；设备正被执行引擎占用时拒绝（见 §4.1）。
- **结果展示**：成功后快照展示区渲染截图 + 元素/OCR 合并表格（F-02），快照列表新增一条记录（F-03-01）。

**边界状态**：

| 场景 | 行为 |
|------|------|
| 未选择设备 | 提示「请先选择设备」，不发送请求 |
| 设备不可用（未注册 / 执行引擎占用） | 409 + 对应 message（见 §4.1），不落库 |
| Dump 失败 / OCR 失败 | 方法级失败：仅选 Dump 时整体失败；两者同时时，Dump 失败仅 OCR 数据入库，反之亦然（快照 method 记录实际成功的方法）；全部失败则提示「获取失败」不落库 |
| OCR 模型未就绪 | 提示「OCR 识别失败，请稍后重试」 |

**验收方式**：

- 选择「两者同时」确认后，合并表格 dump 列组与 OCR 列组均有数据，快照列表新增一条
- 仅选 Dump 时快照 `method=dump` 且 OCR 区显示「未获取」
- 执行引擎占用中的设备获取 → 409 且无快照落库
- 获取后设备在设备管理中的状态不变（仍 ONLINE / BUSY）

### 2.2 模块二：快照展示

**设计目的**

快照展示区是检查器的**展示中枢**：左侧展示快照页面截图（非实时画面），右侧以**单一合并表格**展示解析数据——dump 元素与 OCR 文本按坐标匹配合并。图片上的元素边界框叠加与选取交互保留。

**F-02-01 截图展示与边界框选取**

**功能实现逻辑**：获取成功（或回看快照/已保存页面）后，左侧展示该快照的页面截图（用户动作）。系统在截图上叠加可交互元素的边界框；悬停命中高亮、点击选取后在元素表格中定位对应行（功能响应）。

**详细功能点**：

- **截图来源**：当前快照的页面截图文件；展示为静态图片，**不实时刷新**（v1.7 起无实时流）。
- **边界框叠加与选取**：可交互元素叠加边界框（默认蓝 / hover 橙 / 选中红三色，见 §3.3）；悬停命中元素高亮，点击命中后在元素表格中定位对应行；图片与表格双向联动保留。
- **职责与边界**：只做图片展示与选取；元素数据由快照 JSON 提供。

**验收方式**：

- 获取成功 2s 内渲染截图与边界框；边界框随 hover / 选中变色（蓝 / 橙 / 红）
- 点击画面命中元素后，元素表格定位到对应行

**F-02-02 元素 / OCR 合并表格**

**功能实现逻辑**：用户查看快照解析出的元素与 OCR 文本（用户动作）。系统以**单一合并表格**展示：dump 元素为基准行，OCR 文本按坐标（x/y/width/height 全等）合并进匹配元素行，未匹配的 OCR 独立成行（功能响应）。

**详细功能点**：

- **合并口径**：按坐标（x/y/width/height 全等）把 OCR 文本合并进 dump 元素行，匹配行附 `ocr_text`/`ocr_confidence`/`ocr_thumbnail_path`；未匹配 OCR 独立成行（`_kind='ocr'`，`store.ts:64-94` mergedRows）。
- **列组**：dump 列组（缩略图 / text / resource-id / XPath / 坐标）+ OCR 列组（缩略图 / 文字 / 坐标 / 置信度）。
- **唯一定位**：每个元素生成一条唯一定位 xpath，按 ID（resource-id）→ Text 顺序，优先取匹配数 = 1 的候选。
- **筛选**：全部 / 可点击 / 有文本 / 有 Resource ID / 可点击+文本 / 可点击无文本 / 输入框 / 可滚动（作用于 dump 行；非 all 时隐藏纯 OCR 行）。
- **搜索**：匹配 text / resource_id / content_desc / class_name / ocr_text。
- **勾选**：行前复选框，支持全选 / 反选，用于 F-04-01 筛减。

**职责与边界**：元素/OCR 数据来自快照 JSON；元素资产 CRUD 由元素定位模块（PRD-04）承担。

**验收方式**：

- 合并表格 dump 行数与快照 `element_count` 一致；OCR 按坐标匹配合并 + 未匹配独立成行，合计与 `ocr_count` 口径一致
- 筛选作用于 dump 行、搜索两类都生效；匹配行同时展示 dump 列组与 OCR 列组（附 OCR 文字/置信度）

**F-02-03 OCR 文本合并展示**

**功能实现逻辑**：用户查看快照解析出的 OCR 文本（用户动作）。OCR 文本**并入合并表格**（与元素同一表格，按坐标匹配合并，未匹配独立成行）展示：文字 / 置信度 / 坐标 / 缩略图（功能响应）。

**详细功能点**：

- **列表字段**：text / confidence / x / y / width / height / 缩略图（列于 OCR 列组）。
- **合并展示**：OCR 与元素**同一合并表格**（不 Tab 分表），按坐标全等匹配合并进元素行，未匹配 OCR 独立成行（`_kind='ocr'`）；仅 Dump 的快照 OCR 列组显示「未获取」。
- **勾选**：行前复选框，供 F-04-01 决策是否连同保存（保存口径见 PRD-04）。

**职责与边界**：OCR 数据来自快照 JSON，只读展示。

**验收方式**：

- OCR 文本经坐标匹配合并进元素行或独立成行，行数与 `ocr_count` 口径一致
- 仅 Dump 的快照 OCR 列组显示「未获取」空态

### 2.3 模块三：快照管理

**设计目的**

每次获取的快照持久化保存，用户可随时回看历史快照（选 JSON 解析展示），也可删除不再需要的快照。

**F-03-01 快照列表与回看**

**功能实现逻辑**：用户打开快照列表并选择一条记录（用户动作）。系统列出全部快照（设备 / 方法 / 时间 / 数量统计），选中后读取该快照 JSON 并在快照展示区渲染（功能响应）。

**详细功能点**：

- **列表字段**：设备 serial / 方法（dump·OCR 标签）/ 获取时间 / 元素数 / OCR 数 / 前台包名。
- **回看**：选中后加载快照 JSON → 截图 + 元素/OCR 合并表格（F-02）。
- **分页**：按获取时间倒序，分页展示。

**验收方式**：

- 获取成功后快照列表新增一条且数据与本次结果一致
- 回看历史快照渲染出截图与元素/OCR 合并表格

**F-03-02 快照删除**

**功能实现逻辑**：用户删除快照（用户动作）。系统删除快照记录及其页面截图、元素/OCR 缩略图文件（功能响应）；已被导入元素定位的快照删除时仅提示关联关系，不影响元素定位已有数据（元素定位数据独立，见 PRD-04）。

**边界状态**：删除中快照不存在 → 404「快照不存在」；删除后当前展示区若正展示该快照 → 回到空态。

**验收方式**：

- 删除后列表移除、图片文件清理；已导入元素定位的页面数据不受影响
- 删除成功 Toast「快照已删除」

### 2.4 模块四：导入元素定位

**设计目的**

快照数据是否进入元素资产库由用户决策：用户筛减表格数据后，一键保存到元素定位模块，并自定义目录与页面名称。

**F-04-01 筛减与保存**

**功能实现逻辑**：用户勾选元素（可含 OCR 文本）并点击「保存到元素定位」（用户动作）。系统弹出表单：选择目标目录（或新建目录）+ 填写页面名称，确认后按勾选结果写入元素定位模块（经其 api，契约见 PRD-04），返回 saved / updated / skipped 计数（功能响应）。

**详细功能点**：

- **筛减**：只保存勾选的元素行（F-02-02 勾选）；OCR 文本可勾选是否连同保存（页面级 OCR JSON，见 PRD-04）。
- **保存目标**：支持「已有页面」（指定 `page_id`，写入该页面）与「新建页面」（目录 + 页面名）两种模式（`SaveToElementsDialog.vue` 单选切换）。
- **目录与命名**：目标目录经级联树逐层选择（`SaveToElementsDialog.vue:94-104` el-cascader，不选 = 根目录；不存在时自动创建，见 PRD-04）；新建页面名称必填，同级重名按 PRD-04 冲突规则处理（409）。
- **数据落库**：元素字段、XPath 候选、坐标、缩略图路径、页面截图随页面写入元素定位（完整字段见 PRD-04 §5）。
- **结果反馈**：返回 saved / updated / skipped 计数；保存成功后快照列表该项标记「已导入」角标 ⚠️ 未实施（见 §4.6 偏差登记）。
- **职责与边界**：本功能只发起写入；元素资产 CRUD 由元素定位模块（PRD-04）承担。

**边界状态**：未勾选任何元素 → 提示「请先勾选要保存的元素」；页面名称为空 → 400；目录层级超限 / 同级重名 → 按 PRD-04 错误码透传。

**验收方式**：

- 仅勾选的元素被写入元素定位对应页面；返回 saved / updated / skipped 计数
- 保存后元素定位模块出现新目录/页面与元素，页面含截图与 OCR JSON
- 快照列表该项出现「已导入」角标 ⚠️ 未实施（见 §4.6 偏差登记）

### 2.5 模块五：页面回看

**设计目的**

检查器作为页面快照查看器，可打开元素定位已保存的页面，以「左图右表」方式只读查看。

**F-05-01 打开元素定位已保存页面**

**功能实现逻辑**：用户从「已保存页面」入口选择元素定位中的一个页面（用户动作）。系统读取该页面元信息、截图、元素与页面级 OCR JSON（经元素定位 api，契约见 PRD-04），在快照展示区渲染（功能响应）。

**详细功能点**：

- **页面选择**：列表/搜索选择元素定位已保存页面（目录下的页面叶子）。
- **展示**：左侧页面截图 + 元素边界框叠加与选取，右侧元素/OCR 合并表格；有 OCR JSON 时在合并表格 OCR 列组展示。
- **只读**：本入口不做任何修改；编辑仍回元素定位模块。
- **职责与边界**：只读查看；页面/元素 CRUD 由元素定位模块（PRD-04）承担。

**边界状态**：页面不存在或已删除 → 404「页面不存在」；页面无截图 → 截图区占位「该页面无截图」。

**验收方式**：

- 打开已保存页面后渲染截图 + 元素表格，边界框叠加与选取可用
- 存在 OCR JSON 的页面在合并表格 OCR 列组展示；本入口无任何编辑入口

## 4. 后端功能逻辑

### 4.1 设备可用性（对齐 PRD-02）

设备状态以 PRD-02 为准：仅 `ONLINE` / `BUSY`；设备离线或断开后**删除记录**，不存在 `OFFLINE` / `DISCONNECTED` 墓碑。

**设备初始化归设备管理**：设备连接（adb/u2）与信息采集由 device-pool 在连接/注册时完成；本模块**不二次初始化**，仅在 capture 前做可用性检查。

capture 前统一校验：


| 检查项                    | 不通过 → 错误码 | 消息                       |
| ---------------------- | --------- | ------------------------ |
| serial 为空              | 409       | 未选择设备，请先连接设备             |
| Device 不存在（含离线已删）      | 409       | 设备未注册                    |
| status == BUSY 且执行引擎占用 | 409       | 设备正被执行引擎占用（{进程}），请等待执行完毕 |


> 执行引擎占用前缀：`runner-` / `ai_agent` / `task-` / `run-`。
>
> capture 为**快照式操作**：不 observe、不改变设备 ONLINE / BUSY 状态（v1.7 起无持续占用）。

### 4.2 快照落库口径

- capture 按 `method`（dump / ocr / both）抓取；**方法级成败**：both 时 dump 失败仅 OCR 数据入库（method 记 `ocr`），反之亦然；全部失败不落库。
- 落库字段：设备、serial（冗余）、method、dump 解析 JSON、OCR 解析 JSON、页面截图路径、package / activity、`screen_w` / `screen_h`、`element_count` / `actionable_count` / `ocr_count`、创建人、创建时间。
- Dump 解析 JSON 结构 = 原 dump 响应体（elements 全量 + actionable 含 XPath 候选）；OCR 解析 JSON = texts[]（text / confidence / x / y / width / height / 缩略图路径）。
- 缩略图不存 base64：元素缩略图按 bounds 从页面截图裁剪、OCR 缩略图按文本区域裁剪，**文件落盘，JSON 仅存路径**（见 §4.3）。
- 页面截图不再「保留最近 3 张」滚动清理，改为**随快照持久化**；快照删除时一并清理（见 §4.4）。

### 4.3 缩略图与文件存储

| 文件类型 | 存储位置 | 说明 |
|----------|----------|------|
| 页面截图 | 媒体目录（inspector 截图区） | 每快照 1 张，持久化 |
| 元素缩略图 | 媒体目录（inspector 缩略图区，按快照分目录） | 按 bounds 裁剪，宽度 > 0 才生成 |
| OCR 缩略图 | 同上 | 按文本区域裁剪 |

- JSON 中对应字段为相对路径；前端经媒体静态路由渲染。
- 裁剪失败（元素无坐标等）时该元素缩略图路径为空，前端显示占位图标。

### 4.4 快照删除清理

删除快照时：删除记录 + 页面截图 + 该快照缩略图目录；已被导入元素定位的快照**只提示关联、不阻止删除**，元素定位数据独立不受影响（主权 PRD-04）。

### 4.5 AI 复用链路（需 PRD-08 配合）

AI 助手的 `capture_page` / `save_page_to_elements` 工具复用本模块同一 capture 与快照写入链路（经本模块 api，**AI 直连设备由 Tool 调用本模块 api 完成**）：AI 拉取时快照同样落库，AI 保存到元素定位时基于已存快照数据写入（目录与页面名由 AI 指定）。AI 工具注册与启用开关见 PRD-08；本模块只提供 api 与端点，不感知调用方。

### 4.6 已知偏差登记

| 偏差 | 说明 |
|------|------|
| ⚠️ 已导入角标 / imported 整条未实施 | 后端 `api.py:250-261` snapshot_meta_dict 无 `imported` 字段；前端 `SnapshotListDrawer.vue` 无「已导入」角标（含删除/回看时「已导入 N 次」关联提示）。§5.3 `imported`、§2.4 F-04-01 角标验收、§3.4/§3.5 组件规格均已标 ⚠️ 未实施 |
| 元素/OCR 合并表（原分表设计未落地） | PRD 原设计为「元素表格 + OCR 文本表格」两表 Tab，实现为单组件 `PageElementsPanel.vue` 按坐标（x/y/width/height 全等）合并展示（`store.ts:64-94` mergedRows），OCR 列组内嵌；§2.2/§3.1/§3.5/§10 已按代码真相改 |

## 5. API 接口功能

鉴权：全部 HTTP 端点需 JWT Bearer。JSON 字段 snake_case。

> v1.7 起本模块端点**全量重定义**（旧 dump / ocr / screenshot / WS 移除），新端点统一平台信封 `{status, data}` / `{status, message}`（DRF 渲染），不再沿用旧平铺信封。

### 5.1 端点总览


| #   | 方法   | 端点                                    | 功能                          | 前端消费 | AI 工具 |
| --- | ---- | ------------------------------------- | --------------------------- | ---- | ---- |
| 1   | POST | `/api/inspector/capture`              | 一键获取（dump/OCR/both）→ 快照落库（F-01-02） | ✅    | ✅ capture_page |
| 2   | GET  | `/api/inspector/snapshots`            | 快照列表（F-03-01）                 | ✅    | — |
| 3   | GET  | `/api/inspector/snapshots/{id}`       | 快照详情 JSON（F-03-01）             | ✅    | ✅ |
| 4   | DELETE | `/api/inspector/snapshots/{id}/delete` | 删除快照（F-03-02）                 | ✅    | — |
| 5   | POST | `/api/inspector/snapshots/{id}/save-elements` | 筛减保存到元素定位（F-04-01）  | ✅    | ✅ save_page_to_elements |
| 6   | GET  | `/api/inspector/pages/{page_id}`      | 打开元素定位已保存页面（F-05-01）          | ✅    | — |


> 另消费 device-pool（契约见 PRD-02）：`GET /api/devices/`（设备下拉列表）；不再调用 observe / activate / disconnect-observe。

### 5.2 端点 1 — 一键获取（capture）

**接口地址**：`POST /api/inspector/capture`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `serial` | string | ✅ | 目标设备序列号（来自设备管理列表） |
| `method` | string | ✅ | `dump` \| `ocr` \| `both` |

**响应字段**（信封 `data` 内）：


| 字段                 | 类型      | 说明                |
| ------------------ | ------- | ----------------- |
| `snapshot_id`      | number  | 快照 ID             |
| `serial`           | string  | 设备 serial         |
| `method`           | string  | 实际成功的方法（dump/ocr/both） |
| `package` / `activity` | string | 前台包名 / Activity（dump 时） |
| `screen_w` / `screen_h` | number | 分辨率 |
| `element_count` / `actionable_count` | number | 节点总数 / 可交互元素数（dump 时，否则 0） |
| `elements` / `actionable` | array | 元素节点 / 可交互元素（含 `xpaths`；仅 dump 时非空） |
| `ocr_count`         | number  | OCR 文本条数（OCR 时，否则 0） |
| `texts`             | array   | OCR 文本（见下） |
| `screenshot_path`   | string  | 页面截图相对路径 |
| `created_at`        | string  | 快照创建时间（ISO，`api.py:283`） |

**节点字段**：`class_name` / `resource_id` / `text` / `content_desc` / `index` / `clickable` / `scrollable` / `bounds` / `x` / `y` / `width` / `height` / `thumbnail_path`；actionable 另含 `xpaths[]`（`type` / `xpath` / `count`）。

**texts[] 字段**：`text` / `confidence`（0~1）/ `x` / `y` / `width` / `height` / `thumbnail_path`（不再返回 base64）。

**错误**：serial 空 / 设备未注册 / 执行引擎占用 → 409（见 §4.1）；method 非法 → 400；dump 与 OCR 全部失败 → 500「获取失败」；仅 OCR 失败（both 时）→ 200 且 method=dump、texts 为空。

### 5.3 端点 2 — 快照列表

**接口地址**：`GET /api/inspector/snapshots?offset=&limit=`

**响应字段**：`total` + `items[]`（`id` / `serial` / `method` / `package` / `element_count` / `ocr_count` / `created_by` / `created_at` / `imported`（是否已导入元素定位）⚠️ 未实施（`api.py:250-261` 无此字段，见 §4.6 偏差登记）），按 `created_at` 倒序，分页（limit 上限 100）。

### 5.4 端点 3 — 快照详情

**接口地址**：`GET /api/inspector/snapshots/{id}`

**响应字段**：同 capture 响应（含 elements / actionable / texts / screenshot_path）。

**错误**：快照不存在 → 404「快照不存在」。

### 5.5 端点 4 — 删除快照

**接口地址**：`DELETE /api/inspector/snapshots/{id}/delete`

**行为**：删除记录 + 页面截图 + 缩略图文件（§4.4）。已被导入元素定位的快照同样可删（不影响元素定位数据）。

**错误**：快照不存在 → 404「快照不存在」。

### 5.6 端点 5 — 保存到元素定位

**接口地址**：`POST /api/inspector/snapshots/{id}/save-elements`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `page_id` | number | — | 目标已有页面 ID（「保存到已有页面」模式；与 `page_label`/`folder_path` 二选一，`api.py:172,181-182,205`） |
| `page_label` | string | ✅（无 page_id 时） | 目标页面名称 |
| `folder_path` | string | — | 目标目录路径（如「登录模块/账号页」，不存在时自动创建，规则见 PRD-04） |
| `element_ids` | array | — | 勾选的元素标识（按快照 JSON 中的元素索引/键）；空 = 全部 |
| `include_ocr` | boolean | — | 是否连同保存页面级 OCR JSON，默认 true（有 OCR 数据时） |

**响应字段**：`saved` / `updated` / `skipped` 计数 + `page_id`。

**错误**：快照不存在 404；`page_label` 空 400；目录层级超限 / 同级重名 → 按 PRD-04 错误码透传（409）；快照无 dump 数据且仅保存元素 → 400「该快照无元素数据」。

### 5.7 端点 6 — 打开已保存页面

**接口地址**：`GET /api/inspector/pages/{page_id}`

**响应字段**：页面元信息（`label` / `package` / `activity` / `screenshot_path` / `element_count`）+ `elements[]`（元素定位存储的完整字段，见 PRD-04 §5）+ `ocr_json`（页面级 OCR，无则为 null）。

**错误**：页面不存在 → 404「页面不存在」。

### 5.8 错误码汇总


| 状态码 | 场景 |
|:--:|------|
| 400 | method 非法 / page_label 空 / 快照无对应数据 |
| 404 | 快照不存在 / 页面不存在 |
| 409 | 设备未注册 / 执行引擎占用 / 目录重名等元素定位冲突（透传 PRD-04） |
| 500 | dump 与 OCR 全部失败 / OCR 识别异常 |

## 附录A：功能边界规则


| 边界     | 规则                                                                       |
| ------ | ------------------------------------------------------------------------ |
| 我能做什么  | 从设备管理拉取设备、一键 dump/OCR 获取并落库快照、快照回看与删除、筛减后导入元素定位、只读回看元素定位已保存页面 |
| 我不能做什么 | 扫描/锁定/释放/删除设备（PRD-02）、元素资产 CRUD（PRD-04）、编排/执行用例（PRD-05/06）、设备动作、实时截图流 |
| 如需越界   | 设备经 device_pool；元素保存经 element-locator api（页面级 OCR JSON 随页面写入）    |
| 数据可见性  | 快照按创建人可见（本人创建的快照），不跨用户共享；元素定位数据可见性见 PRD-04                                               |
