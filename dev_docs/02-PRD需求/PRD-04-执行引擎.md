# PRD-04 — 执行引擎 (Test Runner)

> 关联需求大纲：[`需求大纲.md`](./需求大纲.md) §5.4
> 版本：v7.1 · 日期：2026-07-27

---

## 1. 功能定位

执行引擎是任务调度与执行中枢。用户创建任务卡片、选择设备和用例、一键执行，通过 WebSocket 实时监控进度。

模块包含 **两个页面**：

| 页面 | 路由 | 组件 | 说明 |
|------|------|------|------|
| **执行引擎主页面** | `/runner` | `index.vue` | 统计概览 + 任务列表 + 新建任务 |
| **任务详情页面** | `/runner/task/:taskId` | `TaskDetail.vue` | 实时进度、步骤详情、缺陷记录、日志 |

## 3. 页面一：执行引擎主页面

> 路由 `/runner` · 组件 `index.vue`（808 行）

页面由两个区域自上而下排列：统计概览 → 任务列表。

### 3.1 统计概览（KpiCard × 4）

页面顶部 4 张拍立得风格卡片，展示任务状态分布。每张卡片包含：彩色几何图形 → 标签（加粗）→ 数字。微旋转排列，hover 归正放大。

| 卡片 | 颜色 | 图形 | 含义 |
|------|:--:|:--:|------|
| 执行中 | `var(--c-ai)` 柔粉 | ◆ 菱形 | `deriveTaskStatus === 'running'` |
| 等待中 | `var(--c-dashboard)` 柠黄 | ▲ 三角 | `isTaskQueued` 为 true |
| 已完成 | `var(--c-device)` 薄荷绿 | ■ 方块 | `taskBucket === 'completed'` |
| 失败/未完成 | `var(--c-runner)` 桃粉 | ● 圆 | `taskBucket === 'incomplete' \|\| status === 'idle'` |

**组件**：`shared/components/KpiCard.vue`

### 3.2 任务列表

筛选 + 操作工具栏 + 表格/卡片双视图。

#### 3.2.1 工具栏

| 元素 | 位置 | 功能 |
|------|------|------|
| 搜索框 | 左侧 | 按任务名称/ID/设备搜索 |
| FilterTabs（6 Tab） | 右侧 | 全部/⚡执行中/⏳等待中/✅已完成/⏹未完成/📝未执行 |
| 视图切换（📋表格/📷卡片） | 右侧 | 表格视图 vs 分组卡片视图 |
| 任务计数 | 右侧 | "N 任务" 实时数量 |
| ＋ 新建任务 | 右侧 | 打开 NewTaskDialog |

**组件**：`shared/components/FilterTabs.vue`

#### 3.2.2 表格视图

8 列数据表格，通过 `shared/components/AppTable.vue` 渲染：

| 列 | 渲染 | 说明 |
|------|------|------|
| 任务ID | 等宽字体 | `record.id`（如 ID-1） |
| 名称 | 加粗 | `record.name \|\| record.id` |
| 设备 | 📱 + 序列号 | `record.deviceSerial \|\| '—'` |
| 用例 | 数字 | `record.caseIds?.length` |
| 进度 | 迷你进度条 + 百分比 | 排队中显示"排队" |
| 状态 | 彩色标签 | 执行中/等待/完成/失败 各有对应颜色 |
| 时间 | 格式化 | `formatTime(record.createdAt)` |
| 操作 | 2×2 网格按钮 | 执行/重跑/报告/删除（非运行态）/ 停止（运行态）/ 取消排队（排队态） |

操作列按钮为 2×2 grid 布局，4 按钮时上下两行对齐；单按钮（停止/取消排队）占满整行。表格行 hover 淡桃粉底色（模块色 8% 透明）。

**交互**：点击任务行 → `openTaskDetail` → 跳转 `/runner/task/{id}` 详情页。

#### 3.2.3 卡片视图

按状态分 4 组展示（🟣 执行中 / 🟡 等待中 / 🟢 已完成 / 🔴 失败/未完成）。筛选为「全部」时四组同时显示。每张卡片包含：ID + 状态标签 → 名称 → 元数据行（设备/用例数/轮数）→ 进度条 → 统计行（完成数/总数/百分比/时间）→ 操作按钮。hover 上浮 2px + 阴影加深。

### 3.3 新建任务弹窗

表单弹窗，包含：任务名称 → 任务类型（UI/API/Web 三选一）→ 设备选择（仅 UI 类型）→ 用例多选（按类型过滤）→ 循环次数（1-10000）→ 轮间间隔（5-300 秒）→ 执行方式（立即/定时）。表单校验：名称必填、UI 类型必选设备、至少一个用例、间隔 ≥5 秒。

**组件**：`NewTaskDialog.vue`（已从 index.vue 拆出，143 行）

### 4.2 ① 信息卡片

页面顶部卡片，展示任务元信息 + 进度 + 操作按钮。

**信息网格（8 项）**：

| 字段 | 图标 | 内容 | 说明 |
|------|:--:|------|------|
| 任务名称 | 🏷️ | `task.name \|\| task.id` | 右侧附带类型彩色标签（UI自动化/API测试/Web自动化） |
| 设备/端点 | 📱/🌐/🌍 | `task.deviceSerial` | UI 任务显示序列号，API/Web 显示端点标识 |
| 用例数 | 📋 | `caseIds.length` 个 | — |
| 循环次数 | 🔁 | `loopCount` 轮 | — |
| 轮间间隔 | ⏱ | `intervalSeconds` 秒 | 默认 5 |
| 创建时间 | 🕐 | `formatTime(createdAt)` | 格式化显示 |
| 创建人 | 👤 | `creator` | 标签样式 |
| 状态 | 📊 | 中英文状态标签 | 彩色标签，颜色由 `taskStatusInfo()` 计算 |

**执行中额外显示**：
- 当前执行用例名称 + 当前轮次（占满行）
- 总进度文字：`已完成 / 总次数` 次

**进度条**：`el-progress` 组件，有 `caseItems` 时显示，颜色与当前状态标签一致，10px 粗。

**操作按钮栏**（根据任务状态动态切换）：

| 任务状态 | 显示的按钮 |
|----------|-----------|
| 未执行 + 无结果 | `[← 返回列表] [▶ 执行] [🗑 删除]` |
| 未执行 + 有结果 | `[← 返回列表] [↻ 重新执行] [🗑 删除]` |
| 执行中 | `[← 返回列表] [⏹ 停止]（ConfirmButton 二次确认）` |
| 等待中 | `[← 返回列表] [⏸ 取消排队]（ConfirmButton 二次确认）` |
| 已完成（终态） | `[← 返回列表] [↻ 重新执行] [📊 查看报告] [🗑 删除]` |

> 停止和取消排队使用 `ConfirmButton` 组件，需二次确认。删除也需 `ConfirmButton` 确认。

### 4.3 ② 用例执行列表

以可展开卡片展示每个用例的实时执行状态。卡片使用 `useExpandCollapse` composable 管理展开/折叠。

**卡片头部**（点击展开/折叠）：

| 元素 | 内容 | 样式 |
|------|------|------|
| 展开图标 | `▶`（展开后旋转 90°） | — |
| 用例 ID 标签 | `TC-001` | 绿色底；当前执行中用紫色底 |
| 用例标题 | `ci.title` | 加粗 |
| 状态文字 | "执行中"/"已完成"/"待执行" | 带颜色背景的标签 |
| 迭代统计 | `🔁 总数 ✅ 通过 ❌ 失败` | 右对齐 |

**展开内容**：

1. **迭代横幅**（执行中时显示）：当前轮次 + 已完成步骤数，紫色边框横幅

2. **步骤卡片列表**：每个步骤一张小卡片
   - 左侧色条（通过=绿色、失败=红色、执行中=蓝色、待执行=灰色）
   - 步骤序号 + 步骤类型标签（中文名）+ 状态标签
   - 步骤描述文字
   - XPath 选择器（灰色小字，如有）

3. **性能测量区块**（如有性能数据）：
   - 标题：`⏱️ 性能测量 — 等待元素出现耗时`
   - 统计行：次数 / 平均 / 最快 / 最慢 / 中位
   - 明细表：每轮迭代的描述 + 耗时

4. **空步骤提示**：`暂无可展示的步骤`

### 4.4 ③ 自动化执行步骤详情

使用共享组件 `StepScreenshotPanel`，展示每个已执行步骤的截图和元信息。

**数据来源**：`task.step_details` 数组，由 WebSocket 在执行过程中实时推送。

**展示内容**：

| 信息 | 说明 |
|------|------|
| 步骤截图 | Web 自动化每步自动截图，PIL 标注操作目标（红框=点击、蓝框=输入、绿框=断言） |
| 步骤序号 + 类型 | 步骤在用例中的位置和操作类型（中文名） |
| 执行结果 | PASS / FAIL，失败时附带错误原因 |
| 迭代切换 | 可切换查看不同迭代轮次的截图 |

> Web 自动化截图标注详情 → [PRD-04-执行引擎-业务功能.md §4.3](./PRD-04-执行引擎-业务功能.md)

### 4.5 ④ 缺陷记录（BUG 单）

自动汇总执行中失败的步骤，按「用例 + 迭代 + 失败步骤序号」去重后生成 BUG 编号。

**数据来源**：`task.failedSteps` 数组，由 WebSocket `step_result` 事件中失败步骤自动追加。

**每条 BUG 记录展示**：

| 区块 | 内容 |
|------|------|
| **卡片头部** | BUG 编号（`BUG-001` 红色标签）+ 用例标题 + 失败轮次和步骤 + 🔴 执行失败 标签 |
| **BUG 元信息** | BUG 编号、关联用例、失败轮次、失败步骤 |
| **完整步骤清单** | 该用例全部步骤，失败步骤高亮红色 + 显示失败原因 |

**展开/折叠**：使用 `useExpandCollapse` 管理，默认折叠。

### 4.6 ⑤ 执行日志

深色主题实时日志面板，WebSocket 推送驱动。

| 特性 | 说明 |
|------|------|
| **标题栏** | "执行日志 Logs" + 日志条数 + [清空] 按钮 |
| **日志条目** | 时间戳 + 日志文本，按级别着色（info=默认、error=红色、warn=橙色） |
| **可视高度** | 随日志行数变化：最少 25 行、最多 50 行；超出 50 行时面板内滚动 |
| **自动滚屏** | `ref="logPanel"` + `nextTick` 自动滚动到底部 |
| **容量控制** | 上限 1000 条，超出裁剪到 500 条 |
| **空状态** | "日志将在此显示" |

### 4.7 空状态 / 错误状态

**任务未找到**：当 URL 中的 `taskId` 在任务列表中不存在时，显示居中的 "任务未找到" 提示 + `[← 返回任务列表]` 按钮。

**加载态**：进入页面时通过 `loadTask()` 异步加载，期间 `task` 为 `null`，`v-if="task"` 控制内容区不渲染（防止访问 null 属性报错）。

**WebSocket 断连**：`useTaskWebSocket` composable 管理连接状态，断连后自动重连（指数退避 1s→2s→4s→8s→16s，最多 5 次）。

## 5. 数据流

### 5.1 主页面数据流

```
本地状态 (ref)
  ├── tasks[]            任务列表（含本地创建的 ID-1/ID-2 等）
  ├── cases[]            用例定义（来自 API）
  └── devices[]          设备列表（来自 API）

composables
  ├── taskUtils           纯函数工具（状态判定/进度计算/ID 生成）
  ├── useDebouncedSave    变更防抖 → POST /runner/tasks/save
  ├── useQueuePoller      setInterval 轮询 /runner/active → 排队→执行
  └── useTaskWebSocket    WS 连接 /ws/test-run/{taskId} → 实时进度推送

index.vue
  ├── kpiStats (computed)   ──→ KpiCard × 4
  ├── filteredTasks          ──→ FilterTabs + searchQuery
  ├── groupedTasks           ──→ 卡片视图分组
  └── pagedDevices           ──→ AppTable（表格视图）
```

### 5.2 任务详情页数据流

```
路由参数
  └── route.params.taskId ──→ loadTask() ──→ task (ref)

task 对象（来自 API：listTasks → find by id）
  ├── 基本信息：name, deviceSerial, caseIds, loopCount, ...
  ├── caseItems[]   ──→ 用例执行列表渲染
  ├── stepStates[]  ──→ 步骤状态实时更新
  ├── step_details[]──→ StepScreenshotPanel 截图面板
  ├── failedSteps[] ──→ bugEntries computed → BUG 记录区
  └── logs[]        ──→ 执行日志面板

composables
  ├── useTaskWebSocket     WS 连接 /ws/test-run/{taskId}
  │     └── applyWsMessage(task, msg) → 更新 caseItems/stepStates/logs/failedSteps
  ├── useExpandCollapse    管理用例卡片和 BUG 卡片的展开/折叠
  └── taskUtils            状态判定、进度计算、步骤类型标签
```
