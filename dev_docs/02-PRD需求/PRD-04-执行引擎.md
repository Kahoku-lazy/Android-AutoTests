# PRD-04 — 执行引擎 (Test Runner)

> 关联需求大纲：[`需求大纲.md`](./需求大纲.md) §5.4
> 版本：v6.0 · 日期：2026-07-16

---

## 1. 功能定位

执行引擎是任务调度与执行中枢。用户创建任务卡片、选择设备和用例、一键执行。

---

## 2. 功能需求与验收标准

### 2.1 任务卡片管理

#### F-01-01 创建任务

**需求**：创建任务卡片，选择设备、勾选用例、设置循环次数。

**验收**：
- [ ] 点击「创建任务」→ 弹出对话框
- [ ] 设备下拉仅显示 ONLINE 和 BUSY 设备，标注当前状态
- [ ] 用例多选列表按目录树展示，支持搜索和全选
- [ ] 循环次数默认 1，最小 1，最大 100
- [ ] 无在线设备时设备下拉为空，提示「暂无在线设备，请先连接设备」
- [ ] 无已启用用例时用例列表为空，提示「暂无可选用例」
- [ ] 创建成功 → 任务卡片出现在列表，状态为「未执行」

**测试方案**：
```
场景1: 正常创建
  前置：设备A 在线，已启用用例 3 条
  操作：创建任务 → 选设备A → 勾选 2 条用例 → 循环 3 次 → 确定
  期望：出现新任务卡片，名称含用例标题，状态=未执行

场景2: 无设备
  前置：没有在线设备
  操作：点击「创建任务」
  期望：设备下拉为空，显示「暂无在线设备」
```

---

#### F-01-02 任务列表与 Tab 筛选

**需求**：6 个 Tab 筛选任务状态，卡片展示进度。

**验收**：
- [ ] 6 个 Tab：全部 / 执行中 / 等待中 / 已完成 / 未完成 / 未执行
- [ ] 切换 Tab 即时过滤，显示对应状态的任务数
- [ ] 执行中卡片：绿色脉冲动画 + 进度条 + 「当前：XX」+ 停止按钮
- [ ] 等待中卡片：黄色边框 + 排队序号 + 取消排队按钮
- [ ] 已完成卡片：绿色标签 + 通过率（如「通过 12/15」）+ 查看报告按钮
- [ ] 未完成卡片：橙色/红色标签 + 失败原因摘要 + 重新执行按钮
- [ ] 卡片进度条显示「已执行 X/Y 次」

**测试方案**：
```
场景1: 状态切换
  前置：有执行中和已完成任务各 1 个
  操作：点击「执行中」Tab
  期望：只显示执行中的任务卡片，其他不显示
```

---

### 2.2 执行调度

#### F-02-01 一键执行

**需求**：点击「执行」，系统自动判断设备空闲/忙碌，决定立即执行还是排队。

**验收**：
- [ ] 设备空闲 → 立即开始执行，卡片状态变「执行中」
- [ ] 设备忙碌 → 自动加入排队，卡片状态变「等待中」
- [ ] 排队时提示「设备正忙，任务已加入队列，当前位置 #N」
- [ ] 设备释放后，排队任务 FIFO 自动开始执行
- [ ] 执行引擎重启后，未完成的任务卡片恢复为 idle 状态

**测试方案**：
```
场景1: 立即执行
  前置：设备A 空闲，任务卡片已创建
  操作：点击任务卡片上的「执行」
  期望：卡片状态立即变「执行中」；进度条开始更新

场景2: 排队执行
  前置：设备A 正在执行任务X
  操作：创建任务Y（选设备A）→ 点击「执行」
  期望：任务Y 状态变「等待中」；显示排队序号；任务X 完成后任务Y 自动开始

场景3: FIFO 调度
  前置：任务X 执行中，任务Y(#1)、任务Z(#2) 排队
  操作：任务X 完成
  期望：任务Y 开始执行(#1 先出队)；任务Z 变为 #1
```

---

#### F-02-02 实时进度

**需求**：WebSocket 实时推送每步执行结果、日志、迭代进度。

**验收**：
- [ ] 执行中卡片显示实时进度条和「当前用例名」
- [ ] 点击「查看详情」→ 详情页展示实时日志（自动滚动）
- [ ] 每步结果显示：步骤类型 · XPath · 结果(✅/❌) · 耗时
- [ ] 每轮迭代完成时更新进度条
- [ ] WebSocket 断开时日志区域显示「连接断开，正在重连...」并自动重连

**测试方案**：
```
场景1: 实时日志
  前置：任务正在执行，包含 3 个步骤
  操作：打开任务详情页 → 观察日志区域
  期望：日志逐条出现；步骤结果逐条更新；完成时显示总结
```

---

### 2.3 执行控制

#### F-03-01 停止执行

**需求**：中途停止正在执行的任务。

**验收**：
- [ ] 执行中卡片 → 点击「停止」
- [ ] 确认弹窗「确定停止当前执行？」
- [ ] 确认后当前步骤完成后停止，状态变为「未完成」+ outcome=stopped
- [ ] 停止后设备释放，下一个排队任务自动开始
- [ ] 取消 → 继续执行

**测试方案**：
```
场景1: 正常停止
  前置：任务正在执行，当前在第 5/10 轮
  操作：点击「停止」→ 确认
  期望：任务停止，状态变为「未完成」；设备释放
```

---

#### F-03-02 重新执行

**需求**：创建新卡片重新执行，保留旧卡片历史。

**验收**：
- [ ] 点击「重新执行」→ 创建新任务卡片
- [ ] 新卡片：新 ID + 名称后缀「第N轮」
- [ ] 新卡片复制原任务配置（设备、用例、循环次数）
- [ ] 旧卡片保留不变
- [ ] 未执行任务直接点击「执行」即可（不需要重新执行）

**测试方案**：
```
场景1: 重新执行已完成任务
  前置：任务X 已执行完成(3轮)
  操作：点击「重新执行」
  期望：出现新任务卡片，名称含「第2轮」；任务X 保持不变
```

---

#### F-03-03 取消排队

**需求**：取消排队中的任务。

**验收**：
- [ ] 排队中卡片 → 点击「取消排队」
- [ ] 确认弹窗「确定取消排队？」
- [ ] 确认后任务回到「未执行」，配置保留，可稍后重新执行
- [ ] 取消后队列中后面用户位置前移

**测试方案**：
```
场景1: 取消排队
  前置：任务X 排队 #2
  操作：点击「取消排队」→ 确认
  期望：任务X 状态变为「未执行」；原 #3 变为 #2
```
