# PRD-05 — 测试报告 (Report Generator)

> 关联需求大纲：[`需求大纲.md`](./需求大纲.md) §5.5
> 版本：v5.0 · 日期：2026-07-16

---

## 1. 功能定位

测试报告是执行结果收口。用户查看报告、分析失败原因、下载文件归档。

---

## 2. 功能需求与验收标准

### 2.1 报告列表

#### F-01-01 报告列表页

**需求**：所有执行记录以表格展示，支持筛选和下载。

**验收**：
- [ ] 表格列：Run ID · 设备 · 用例数 · 通过 · 失败 · 通过率(进度条) · 状态 · 耗时
- [ ] 按状态筛选：全部 / 已完成 / 未完成
- [ ] 点击 Run ID → 跳转报告详情页
- [ ] 每行提供 CSV 下载和 LOG 下载按钮
- [ ] 无执行记录时显示「暂无执行记录」
- [ ] 通过率颜色：≥90% 绿色、60-90% 黄色、<60% 红色

**测试方案**：
```
场景1: 正常列表
  前置：有 5 条执行记录，通过率各不相同
  操作：打开报告列表页
  期望：5 条记录按时间倒序排列；通过率颜色正确

场景2: 空列表
  前置：没有任何执行记录
  操作：打开报告列表页
  期望：显示「暂无执行记录」空态
```

---

### 2.2 报告详情

#### F-02-01 用例执行明细

**需求**：Tab1 展示每个用例的迭代结果。

**验收**：
- [ ] 顶部 KPI 卡片：总用例 · 通过 · 失败 · 通过率 · 总耗时
- [ ] 表格：用例名 · 迭代 · 结果 · XPath · 耗时
- [ ] 每行可展开查看步骤级详情
- [ ] 通过标记 ✅ 绿色，失败标记 ❌ 红色

**测试方案**：
```
场景1: 查看详情
  前置：某次执行包含 3 条用例
  操作：点击 Run ID → 查看 Tab1
  期望：KPI 卡片显示 3 条用例/2 通过/1 失败；失败行标红
```

---

#### F-02-02 失败分析

**需求**：Tab2 自动聚合失败用例，辅助定位问题。

**验收**：
- [ ] 仅展示失败用例（通过用例不显示在此 Tab）
- [ ] 每个失败卡片：失败步骤 · XPath · 期望 vs 实际 · 错误信息
- [ ] 全部通过时显示「🎉 所有用例通过，无失败记录」

**测试方案**：
```
场景1: 有失败
  前置：执行结果有 2 条失败
  操作：切换到 Tab2「失败分析」
  期望：展示 2 个失败卡片，含失败步骤和错误信息

场景2: 全部通过
  前置：执行结果全部通过
  操作：切换到 Tab2
  期望：显示「所有用例通过」
```

---

#### F-02-03 趋势图表

**需求**：Tab3 展示通过率趋势折线图。

**验收**：
- [ ] 通过率趋势：近 12 次执行的通过率折线
- [ ] 数据不足 2 次时显示「需要至少 2 次执行记录才能展示趋势」
- [ ] 图表下方附历史执行记录简表

**测试方案**：
```
场景1: 趋势展示
  前置：有 10 次执行记录
  操作：切换到 Tab3
  期望：折线图展示 10 个数据点；下方表格列出对应记录
```

---

### 2.3 文件下载

#### F-03-01 文件下载

**需求**：提供 CSV 和 LOG 文件下载。

**验收**：
- [ ] CSV 下载：包含每步执行结果（用例名/迭代/步骤类型/XPath/结果/耗时）
- [ ] LOG 下载：完整执行日志
- [ ] 文件不存在时提示「文件不存在或已被清理」
- [ ] 下载按钮在报告列表页和详情页均可使用

**测试方案**：
```
场景1: 正常下载
  前置：某次执行已完成
  操作：点击 CSV 下载按钮
  期望：浏览器开始下载；文件内容包含执行数据

场景2: 文件缺失
  前置：报告记录存在但文件已被删除
  操作：点击下载
  期望：提示「文件不存在或已被清理」
```
