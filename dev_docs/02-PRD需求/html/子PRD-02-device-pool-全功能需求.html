🎯 第一部分：业务视角

1 功能定位

设备管理是平台设备资产中枢：ADB 发现、状态、锁定/释放、排队、USB/WIFI 连接，供元素定位与执行引擎独占使用。

一句话：看清哪台空闲、锁住再测、测完释放；支持 USB 与局域网 adb connect。

5 功能详细规格

F-01 设备发现与注册 P0

adb devices → update_or_create；BUSY 保护不降 ONLINE；采集 model/brand/分辨率/android_version/connection_type。

F-02 连接与激活 P0

POST /api/devices/{serial} u2.connect；activate 切当前；可跳转 /elements。

F-03 锁定 / 释放 P0

lock_type: user/process；timeout 默认 300s；release_reason: manual/timeout/disconnect/force。表 dp_device_locks。

F-04 强制断开 P1

disconnect / disconnect-observe；清缓存与锁。

F-05 排队 P1

join/leave queue；状态 waiting/assigned/cancelled/timeout。表 dp_device_queue。

F-06 心跳 P1

GET /api/devices/heartbeat + 列表内状态同步。

F-07 局域网连接 P0

现网已交付：弹窗 IP+端口(默认5555) → POST /scan {"target":"ip:port"} → adb connect → WIFI 入库。动态无线调试端口须本机先 adb pair（平台外前提）。

F-08 跨模块 api.py P0

acquire_device / release_device / get_online_devices / ensure_device — runner、AI Tool、element-locator 共用。

6 模块边界

device-pool
  ├─ 唯一写入口：本模块 views + api.acquire/release
  ├─ 他模块禁止 Device.objects.update(status=...)
  └─ 被 element-locator / test-runner / agentscope 消费
  • 仅 Android/ADB（UI 若写 iOS 属文案错误）
  • 跨模块锁设备必须 api.acquire_device
  • api→views 内部依赖需逐步收敛，对外仍只暴露 api

10 数据链（入库 / 出库）

方向规则
入库scan/connect update_or_create；lock INSERT
出库列表 API；get_online_devices 给 AI/runner
状态ONLINE↔BUSY↔OFFLINE；UI 仍可能见 DISCONNECTED

11 状态机

(new) --scan--> ONLINE --lock--> BUSY --release/timeout--> ONLINE ONLINE --scan miss--> OFFLINE --scan--> ONLINE * --disconnect--> DISCONNECTED(或清缓存) --scan--> ONLINE
状态含义
ONLINE在线可连
BUSY锁定/占用中
OFFLINEadb 不可见
DISCONNECTED主动断开（前端仍处理）
