🎯 第一部分：业务视角

1 功能定位

用例管理是测试资产中枢：两级目录、用例定义、步骤编排、YAML 导出、编辑器内单步调试。

一句话：把元素 XPath 编成可执行步骤，按目录管起来，导出 YAML，交给执行引擎跑。

2 用户故事

US-01 · 目录

5 功能详细规格

F-01 用例定义 CRUD P0

表 cm_test_definitions。字段含 priority/design_method/precondition/expected_result/metrics。update_or_create；Dirty Tracking 离开拦截。

F-02 步骤编排 P0

现网：前端 STEP_TYPES 17 种；models/step_types.StepType 枚举 14 种；executor 已支持 long_click/swipe/drag/wait_any（及 wait_either）。双名 wait_any/wait_either 并存。以 executor 可跑为准。

组类型
点击click, long_click, click_indexed, retry_click
手势swipe, drag
等待wait, wait_disappear, wait_any/wait_either, wait_toast, sleep
断言verify_text, poll_text
应用start_app, kill_app, restart_app, log

F-03 两级目录 P0

cm_case_directories；未分配用例根级显示；长按拖拽+批量移动 batch-move。

F-04 步骤只读查看 P1

右侧三态：列表 A/B / 详情；面包屑可点回全部。

F-05 YAML 导出 P0

POST export/yaml（测试点+flows）→ exports/ 文件；GAP cm_test_cases 缓存表已删除(migration 0004)，勿再写 TestCaseCache。

F-06 批量移动 P0

POST /directories/batch-move；两级/重名/循环校验。

F-07 单步调试 P1

编辑器调 POST /api/runner/run-step；需设备连接。

F-08 批量导入 P1

POST /definitions/batch · overwrite · directory_id。
