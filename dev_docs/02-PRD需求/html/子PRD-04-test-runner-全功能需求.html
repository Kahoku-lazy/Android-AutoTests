🎯 第一部分：业务视角

1 功能定位

执行引擎是任务调度与用例执行中枢：任务卡片、设备 FIFO 排队、步骤执行、WebSocket 实时进度、执行快照。

一句话：选设备选用例点执行，忙则排队，进度实时推，停得下、结果可审计。

2 用户故事

US-01 · 一键执行
空闲立即跑，忙则排队。
验收：POST /run + active 轮询。
US-02 · 实时看
步骤/日志 WS 推送。
验收：ws/test-run/{id}。
US-03 · 停止
停止后释放设备并出队下一任务。
验收：POST stop。
US-04 · 跨设备同步
任务在 DB 不在 localStorage。
验收：tasks API。
US-05 · 重跑
新卡片第 N 轮，旧卡保留。
验收：新 task_id。

3 解决的痛点

没有本模块之前

  • 不知设备忙闲硬撞
  • 进度靠刷日志
  • 历史不可审计

有了本模块之后

  • 自动排队
  • WS 步骤流
  • selected_cases 快照

5 功能详细规格

F-01 任务卡片 P0

tr_task_cards：mode immediate/scheduled；case_ids/loop_count；case_items/step_states/logs；DB 持久化。

F-02 设备调度排队 P0

内存队列 FIFO；busy 检测；cancel queue；finally 出队下一任务。

F-03 用例执行 P0

加载 TestDefinition → StepExecutor → DeviceAdapter(u2)；写 TestRunRecord + TestResult；调 ReportGenerator。

F-04 WS 进度 P0

消息：log, run_started, case_started, step_started/result, iteration_result, case_finished, run_finished, device_error, heartbeat。

F-05 停止 / 取消排队 P0

POST run/{id}/stop；POST queue/cancel。

F-06 进度与 outcome P0

status: idle/queued/running/done；outcome: completed/stopped/interrupted/error。running 派生自 status。

F-07 重新执行新卡 P1

新 ID +「第N轮」后缀，复制配置。

F-08 单步 + TREP P1

POST run-step（用例编辑器用）。GET monitor/{run_id}、run/{id}/snapshot（TREP Phase0，前端未接）。

6 模块边界

test-runner
  ├─ 调 device_pool.api acquire/release
  ├─ 读 case_manager.TestDefinition
  ├─ 调 report_generator ReportGenerator
  ├─ 禁止他模块 import runner._active_runs
  └─ 对外 api：get_run_results / stop_run / list_active_runs…
  • 状态机是任务真相；禁止双写 running 与 status 冲突
  • 跨模块查活跃运行走公开 API
  • 执行快照 selected_cases 必写

11 状态机

idle --执行--> (设备空闲? running : queued) queued --轮到--> running running --完成--> done(outcome=completed) running --停止--> done(stopped) running --崩溃--> done(error) queued --取消--> idle 服务器恢复孤儿 --> done(interrupted)

14 Agent 专属提示词（编码时粘贴）
