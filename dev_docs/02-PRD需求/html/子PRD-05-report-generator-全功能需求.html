🎯 第一部分：业务视角

1 功能定位

测试报告是结果收口：列表来自执行记录聚合，详情含用例/迭代/失败分析/趋势；执行结束自动生成 CSV/MD/LOG 等文件。

一句话：跑完就能在平台里点开看通过率与失败原因，也能下载文件归档。

2 用户故事

US-01 · 列表
看到历史 run 与通过率。
验收：GET /api/reports/ 聚合 tr_test_runs。

有了本模块之后

5 功能详细规格

F-01 多格式自动生成 P0

runner 结束调 ReportGenerator：CSV、失败 MD、LOG、JSON；可写 rg_reports 文件路径。

F-02 报告列表 P0

主数据源是 tr_test_runs + tr_test_results 聚合，不是只扫 rg_reports。列含 rate/duration/status。

F-03 在线详情 P0

用例聚合 + iterations；失败分析；recent_runs。

F-04 趋势图 P1

详情内 Chart.js 通过率折线 + 耗时柱（以现网 ReportDetail 为准）。

F-05 文件 content/download P1

GET .../content 与 GET .../{filename}。

6 模块边界

report-generator
  ├─ 读 test_runner runs/results（只读 ORM）
  ├─ 写 rg_reports 经 api.save_report / ReportGenerator
  └─ ReportTemplate 仅 Model/Admin，无 REST CRUD
  • 列表口径与 runner 状态枚举兼容大小写
  • 生成失败不得拖垮 runner 主流程
  • 前端禁止硬编码假报告

7 数据流全景

TestRunner.finally → ReportGenerator.save_*
Vue /reports → GET /api/reports/ → 聚合 runs
详情 → GET /api/reports/run/{id} → JOIN results

11 状态机

UI 状态标签映射: COMPLETED/completed → 通过 FAILED/failed → 失败 RUNNING/running → 运行中 STOPPED/stopped → 已停止 PENDING → 排队中 iteration: pass|fail|stopped

14 Agent 专属提示词（编码时粘贴）

你在改「测试报告」。
红线：列表主源是 tr_test_runs；兼容 status 大小写；生成失败不影响 runner。
验证：跑一轮 → /reports 有记录 → 点进详情看失败与趋势。
