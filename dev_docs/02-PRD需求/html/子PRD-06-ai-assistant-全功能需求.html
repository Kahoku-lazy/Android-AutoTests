🎯 第一部分：业务视角

1 功能定位

AI 助手是智能入口：配置智能体、SSE 流式对话、HITL 确认工具调用、通过 Tool 编排五大业务模块；动森主题与业务模块视觉隔离。

一句话：用自然语言驱动搜元素、写用例、锁设备、跑测试、出报告；Redis 挂了还能降级 Django。

5 功能详细规格

F-01 智能体配置 P0

ai_agents 20+ 字段；头像上传；模型 detect；register-scope；test 连接；api_key 脱敏 sk-***。

F-02 多会话 P0

conversations CRUD；messages 列表；rename/delete。

F-03 SSE 流式 P0

前端优先 AgentScope /agentscope/chat + sessions stream；降级 Django send/stream_chat。

F-04 HITL 确认 P0

POST confirm-result；工具调用同意/拒绝。

F-05 平台 Tools P0

现网 factory 注册约 24 个业务 Tool + 4 个 Plan 内置（非文档旧称 14）。含元素/用例/设备/执行/报告/RAG/PRD 设计导入/SOP/任务卡等。

F-06 知识库 RAG P1

search_knowledge_base · ChromaDB。

F-07 JWT 认证 P0

/api/ai/auth/* 五端点；与平台 LoginView 共用体系。

F-08 动森主题 P1

animal-island-vue；禁止把业务 EP 风格污染进 AI 页，反之亦然。

6 模块边界

ai-assistant
  ├─ Tool → 各模块 api/ORM（同进程，不走 HTTP）
  ├─ 禁止残留双源 dashboard 统计（dashboard_views DEPRECATED）
  └─ api_key 响应必须脱敏
  • 写业务数据走对方 api，不破坏防火墙
  • SSE 与 Django 双通道行为要对用户可感知降级
  • ai_tasks 表与 runner TaskCard 关系勿混淆

7 数据流全景

ChatView → AgentScope SSE (Redis)
  → ReAct → Tools → Django ORM/api
  → save_message → ai_messages
Fallback: POST /api/ai/conversations/{id}/send

CRUD/api/ai/conversations*会话/消息/stream/confirm
POST/api/ai/upload-*头像/文件
SSE/agentscope/chat|sessions/.../stream流式

9 数据模型

表说明

10 数据链（入库 / 出库）

方向规则
入库agents/conversations/messages；Tool 写各业务表
出库列表详情；SSE 事件；任务跳转 runner
安全encrypt_key/mask_key；reveal 需鉴权

11 状态机

Agent: active|inactive Conversation: active|archived Message reason: normal|exceed_max_iters|stopped|error SSE: connecting → streaming → done | error → (可选) Django fallback HITL: tool_pending → confirmed|rejected
