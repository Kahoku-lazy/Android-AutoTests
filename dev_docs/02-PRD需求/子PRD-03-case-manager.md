## 1. 模块功能目标

用例工程模块是测试平台的测试资产管理中枢，承担以下核心职责：

1. **用例目录层级管理**：支持两级目录结构（一级目录 + 二级子目录），未分配目录的用例（`directory_id=NULL`）显示在目录树根级与一级目录平级，通过左侧目录树组织所有用例，支持右键菜单创建/重命名/删除目录
2. **测试用例定义管理**：创建、编辑、删除、启用/禁用可重用的测试用例定义，包含 17 种步骤类型的结构化编排。**用例 ID 全局唯一**作为主键，跨模块调用时附带 `directory_id`/`directory_name`；**同目录下用例名称唯一**（DB 约束 + 应用层校验），不同目录允许同名
3. **测试步骤编排**：通过拖拽排序组合 click / wait / verify_text / sleep 等 17 种原子操作，构建完整的业务流程测试步骤
4. **测试点接入**：从元素定位模块（element-locator）提取标记为 test_point 的元素及其 XPath，作为步骤的定位表达式
5. **YAML 导入导出**：支持将测试用例导出为 YAML 文件、从 YAML 文件导入，实现跨环境迁移和版本管理
6. **用例步骤查看**：在目录树中点击用例节点或点击卡片/表格行，右侧面板内联展示用例步骤详情（不跳转编辑页）

### 1.2 右侧面板三态模型

右侧面板内容由两个变量控制——**是否选中了目录**（`activeDirectoryId`）和**是否选中了用例**（`selectedCase`）——形成三种互斥的显示状态：

```
         selectedCase
         null     │  非 null
         ─────────┼──────────
active    null    │  列表态    │  详情态
Directory ────────┼───────────
         非 null  │  列表态    │  详情态
```

| 状态 | 条件 | 右侧面板显示 |
|------|------|-------------|
| **列表态** | `selectedCase === null` | 用例卡片或表格（取决于 viewMode） |
| **详情态** | `selectedCase !== null` | 单个用例的步骤详情 |

`activeDirectoryId` 只影响**列表态中显示哪些用例**（全部 vs 过滤），不改变面板状态。

---

#### 列表态（selectedCase = null）

右侧面板显示用例卡片网格或表格。根据是否有选中目录，分为两个子场景：

**场景 A：未选中目录（activeDirectoryId = null）**

这是用户第一次进入页面时的默认状态。

```

│ 面包屑: 📋 全部用例                       [📋] [🃏] [+ 新建用例] │
│                        12 个用例                          │
├─────────────────────────────────────────────────────────┤
│  ┌──────────┐ ┌──────────┐ ┌──────────┐               │
│  │ TC-001   │ │ TC-002   │ │ TC-003   │               │
│  │ 登录测试  │ │ 注册测试  │ │ 支付测试  │               │
│  │ smoke     │ │ smoke     │ │ critical  │               │
│  │ 📂 开关功能│ │ 📂 场景功能│ │ 📂 开关功能│               │
│  │ 3 步骤    │ │ 5 步骤    │ │ 8 步骤    │               │
│  │[编辑][删]│ │[编辑][删]│ │[编辑][删]│               │
│  └──────────┘ └──────────┘ └──────────┘               │
└─────────────────────────────────────────────────────────┘
```

- 面包屑只有一级：**📋 全部用例**
- 右侧显示**所有目录**下的全部用例（不按目录过滤）
- 左侧目录树**无高亮选中节点**
- 工具栏显示用例总数（如「12 个用例」）
- 视图切换按钮可用（卡片/列表）
- 「新建用例」按钮可用，点击跳转 `/cases/new`（不带 directory_id 参数）

**场景 B：选中了目录（activeDirectoryId = 目录 ID）**

用户点击了左侧目录树中的目录节点（一级或二级目录）。

```

│ 面包屑: 📋 全部用例 › 📁 H6601用例 › 📂 开关功能          │

│  └──────────┘ └──────────┘                             │
└─────────────────────────────────────────────────────────┘
```

- 面包屑变多级：**📋 全部用例 › 📁 父目录 › 📂 当前目录**
- 右侧**仅显示该目录及其子目录下的用例**（含二级目录的用例）
- 左侧目录树**该节点高亮**
- 工具栏显示过滤后的用例数（如「5 个用例」）
- 「新建用例」按钮点击跳转 `/cases/new?directory_id=X`（携带当前目录 ID）


- 面包屑正常显示目录路径
- 右侧显示空状态引导，提示「此目录下暂无用例」
- 「创建第一个用例」按钮点击跳转 `/cases/new?directory_id=X`

#### 设计原则

1. **渐进式复杂度** — 零数据时先引导建目录，再引导建用例，不在一开始暴露所有功能
2. **状态保持** — 用户在目录树中导航后，返回时不丢失目录过滤状态和视图模式
3. **视图偏好记忆** — 卡片/列表选择持久化 localStorage，跨会话保持
4. **只读优先** — 点击用例默认展示步骤详情（只读），编辑需主动点击按钮，防止误操作
5. **面包屑即状态** — 面包屑不仅展示路径，也是交互控件：点击「全部用例」可快速重置过滤

## 3. 功能详细规格

---

### 3.1 F-01：用例定义 CRUD

#### 3.1.1 需求定义

提供测试用例定义的完整生命周期管理：创建、编辑、删除、启用/禁用、列表查看、目录过滤、双视图切换（卡片/表格）。

#### 3.1.2 需求目标

| 目标 | 衡量方式 | 目标值 |
|------|----------|:--:|
| 用例创建数 | 数据库 test_definitions 记录数 | ≥500 |
| 操作响应 | CRUD 操作响应 ≤500ms | 100% |
| 数据一致性 | 删除用例定义不影响已执行的历史结果 | 100% |

#### 3.1.3 触发条件

- 用户进入 case-manager 页面 → 自动加载目录树 + 用例列表
- 用户点击「新建用例」→ 跳转新建编辑页（/cases/new）
- 用户点击卡片 → 右侧面板展示步骤详情
- 用户点击卡片/表格「编辑」→ 跳转编辑页（/cases/{id}/edit）
- 用户点击「删除」→ 二次确认后物理删除
- 用户点击目录树中二级目录右键 →「新建用例」→ 跳转新建页并预填目录
- 用户点击目录树中用例节点右键 →「编辑用例」/「删除用例」

#### 3.1.4 业务规则

**用例定义完整字段**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| `id` | VARCHAR(200) PK | ✅ | 自动生成 | 格式 `TC-YYYYMMDD-HHMMSS-XXXX`，新建时可编辑/重新生成 |
| `title` | VARCHAR(500) | ✅ | — | 用例标题，前端校验非空 |
| `category` | VARCHAR(200) | — | `""` | 分组分类，如 "smoke"、"regression" |
| `description` | TEXT | — | `""` | 详细描述 |
| `steps` | TEXT | — | `""` | 步骤文本摘要（保存时自动从 steps_data 生成） |
| `steps_json` | TEXT | — | `"[]"` | **结构化步骤 JSON**，执行引擎直接使用 |
| `enabled` | BOOLEAN | — | `true` | 是否启用，禁用后执行引擎不加载该用例 |
| `package_name` | VARCHAR(200) | ✅ | `""` | 目标 App 包名，前端校验非空 |
| `directory_id` | FK → cm_case_directories | — | `NULL` | 所属目录（SET_NULL on delete） |
| `priority` | VARCHAR(4) | — | `"P1"` | P0/P1/P2，始终可在编辑页修改 |
| `design_method` | VARCHAR(100) | — | `""` | 设计方法（五法之一），PRD 导入时自动填充 |
| `precondition` | TEXT | — | `""` | 前置条件，PRD 导入时自动填充 |
| `expected_result` | TEXT | — | `""` | 预期结果，PRD 导入时自动填充 |
| `metrics` | TEXT | — | `""` | 量化指标，PRD 导入时自动填充 |
| `created_at` | DATETIME | — | auto | 创建时间 |
| `updated_at` | DATETIME | — | auto | 更新时间 |

**Case ID 生成规则**：前端 `generateId()` 生成格式 `TC-{YYYYMMDD}-{HHMMSS}-{XXXX}`，后端兜底同样规则。用户可在新建时手动修改或点击「重新生成」。

**保存策略**：`update_or_create` 全量覆盖 —— 即使前端只改了标题，所有 16 个字段全部重新写入。

**未保存拦截（Dirty Tracking）**：编辑页通过 `JSON.stringify` 深比较检测修改。离开页面时（退出按钮 + 浏览器后退 + 侧边栏跳转）如有未保存修改，弹窗确认：「当前用例有未保存的修改，离开后数据将会丢失。是否继续？」

**删除约束**：物理删除，二次确认弹窗「确定删除用例「{title}」？」。步骤编排器内删除步骤支持「本次不再提示」。

**冲突处理**：同一 `id` 的用例，保存时执行 `update_or_create`（幂等）。

**并发编辑策略**：当两个用户同时编辑同一用例时，后保存者覆盖先保存者（Last Write Wins）。短期不做编辑锁。如果后保存者打开编辑页后用例已被他人修改，保存成功但前端不提示（v3 考虑增加"用例刚刚被修改过"的提示）。

**Dirty Tracking 检测粒度**：比较 16 个字段的值（不含 `created_at` / `updated_at`），仅字段值变化触发拦截。JSON key 顺序变化不触发拦截（`steps_data` 内 key 顺序不同视为无修改）。用户改了标题又改回去 → 视为无修改，不拦截（符合用户预期）。

**异常场景**：

| 异常类型 | 触发条件 | 系统行为 | 用户看到的提示 |
|------|------|------|------|
| 网络断连 | 保存/删除/查询时网络不可用 | 前端 axios 拦截器统一处理，操作失败不写入 DB | Toast：「网络异常，请检查网络连接后重试」+ 5 秒后自动重试（读操作），或显示「重试」按钮（写操作） |
| 数据为空 | 目录树下无目录、列表无用例 | 展示空状态引导页，区分两种场景 | 无目录时：「暂无目录，点击上方 + 按钮创建第一个目录」；有目录无用例时：「此目录下暂无用例」+「创建第一个用例」按钮 |
| 权限不足 | JWT 过期或未登录时操作 | 前端 axios 拦截器捕获 401，自动刷新 token，失败则跳转登录页 | 跳转 `/login`，登录后回到之前页面（redirect query 参数） |
| 重复提交 | 用户快速双击保存按钮 | 前端按钮进入 loading 态 + disabled，防重复点击；后端 update_or_create 幂等 | 保存中按钮显示 spinner + 「保存中...」文案，重复点击无效 |
| 输入非法 | title 为空 / package_name 为空 / 字段超长 | 前端实时校验 + 后端兜底校验，保存按钮在校验通过前 disabled | title 为空：「请输入用例标题」；package_name 为空：「请输入目标应用包名」；后端校验失败返回 400 + 具体错误字段 |
| 超时 | 保存操作超过 10 秒未响应 | 前端 axios 超时 10s，超时后终止请求 | Toast：「保存超时，请检查网络后重试」，编辑内容保留不丢失 |
| 并发编辑 | 用户 A 保存后用户 B 也保存同一用例 | 后保存者覆盖（Last Write Wins），用户 A 的修改静默丢失 | v2：无提示（权衡：编辑冲突概率低，过度提示影响体验）；v3：保存前检测 `updated_at` 变化，如被他人修改则弹窗确认 |

#### 3.1.5 前端交互要求

### 3.2 F-02：17 种步骤编排

#### 3.2.1 需求定义

测试用例的核心是步骤序列。用户通过拖拽排序组合步骤类型，构建完整的测试流程。每条步骤包含类型（type）、XPath（xpath/xpath2）、超时（timeout）、预期文本（expected_text）、索引（index）、描述（description）、方向（direction）、距离（distance）参数。

**当前阶段（2026-07-10 现网对齐）**: 前端步骤编辑器提供 **17** 种类型；`models/step_types.StepType` 枚举 **14** 种；执行引擎 `executor` **已支持** `long_click` / `swipe` / `drag` / `wait_any`（及后端 `wait_either` 双名）。改步骤类型须三端一起改。详见 `html/子PRD-03-case-manager-全功能需求.html`。

#### 3.2.2 需求目标

| 目标 | 衡量方式 | 目标值 |
|------|----------|:--:|
| 支持的步骤类型（已实现） | 步骤类型枚举数（v2 已实现） | 14 种 |
| 支持的步骤类型（规划中） | v3 新增步骤类型数 | 3 种（long_click / swipe / drag） |
| 步骤编排效率 | 非技术人员 10 分钟内创建 5 步骤用例 | — |
| 步骤数据完整性 | 保存的步骤可被执行引擎正确解析（14 种已实现步骤） | 100% |

#### 3.2.3 触发条件

- 用户在 element-locator 页面点击 XPath 的「加入步骤」（通过 EventBus 通信）
- 用户在 case-manager 用例编辑页手动添加步骤
- 用户拖拽步骤调整顺序
- 用户在目录树中点击用例节点查看步骤（只读 StepViewer）

#### 3.2.4 业务规则

**17 种步骤类型**（14 种已实现 + 3 种 v3 规划）：

| # | 步骤类型 | 值 | 参数 | 典型场景 | 状态 |
|---|----------|-----|------|----------|:--:|
| 1 | 点击元素 | `click` | xpath, description | 点击按钮/链接 | ✅ v2 |
| 2 | 长按元素 | `long_click` | xpath, timeout, description | 长按触发上下文菜单 | 🔮 v3 |
| 3 | 点击第N个 | `click_indexed` | xpath, index, description | 列表项点击 | ✅ v2 |
| 4 | 滑动屏幕 | `swipe` | direction, distance, description | 上下滑动列表 | 🔮 v3 |
| 5 | 拖动元素 | `drag` | xpath, direction, distance, description | 拖拽控件 | 🔮 v3 |
| 6 | 等待元素出现 | `wait` | xpath, timeout, description | 等待页面加载完成 | ✅ v2 |
| 7 | 等待元素消失 | `wait_disappear` | xpath, timeout, description | 等待加载遮罩消失 | ✅ v2 |
| 8 | 等待二选一 | `wait_any` | xpath, xpath2, timeout, description | 等待成功/失败二态 | ✅ v2 |
| 9 | 等待 Toast | `wait_toast` | expected_text, timeout, description | 验证 Toast 提示 | ✅ v2 |
| 10 | 暂停几秒 | `sleep` | timeout, description | 固定等待 | ✅ v2 |
| 11 | 校验文字 | `verify_text` | xpath, expected_text, description | 断言页面内容 | ✅ v2 |
| 12 | 等待文字出现 | `poll_text` | xpath, expected_text, timeout, description | 轮询文本变化 | ✅ v2 |
| 13 | 打开应用 | `start_app` | xpath (包名), description | 冷启动测试 | ✅ v2 |
| 14 | 关闭应用 | `kill_app` | xpath (包名), description | 清理应用状态 | ✅ v2 |
| 15 | 重启应用 | `restart_app` | xpath (包名), description | 重启流程测试 | ✅ v2 |
| 16 | 点击后等待结果 | `retry_click` | xpath, index (重试次数), description | 网络波动重试 | ✅ v2 |
| 17 | 记录信息 | `log` | description | 标记测试阶段 | ✅ v2 |

> **v3 规划的 3 种步骤**（`long_click` / `swipe` / `drag`）：前端步骤编辑器已预留类型选项和参数面板，但下游 test-runner 执行引擎（`adapter.py`）尚未实现对应的 uiautomator2 操作映射。用例保存时这三种步骤正常入库，执行时 test-runner 会跳过并记录 `WARNING: step type not implemented` 日志。v3 里程碑包含这三种步骤的执行引擎实现。

**Step 数据结构**：
```json
{
  "type": "click",
  "xpath": "//*[@resource-id='com.example:id/btn_login']",
  "xpath2": "",
  "timeout": 10,
  "expected_text": "",
  "index": 0,
  "description": "点击登录按钮",
  "direction": "",
  "distance": 0
}
```

**步骤校验**（执行引擎加载时校验）：
- `type` 必须是 17 种之一
- `click` / `long_click` / `click_indexed` / `wait` / `wait_disappear` / `verify_text` / `poll_text` / `retry_click` 必须有 `xpath`
- `swipe` / `drag` 必须有 `direction` + `distance`
- `wait_any` 必须有 `xpath` + `xpath2`
- `sleep` 必须有 `timeout`
- `wait_toast` 必须有 `expected_text`
- `log` 必须有 `description`

**步骤类型按组分类**：

| 组 | 步骤（v2 已实现） | v3 规划 |
|------|------|------|
| 元素操作 | click, click_indexed | long_click |
| 滑动操作 | — | swipe, drag |
| 等待操作 | wait, wait_disappear, wait_any, wait_toast, sleep | — |
| 检查操作 | verify_text, poll_text | — |
| 应用操作 | start_app, kill_app, restart_app, retry_click, log | — |

**v3 步骤执行降级策略**：用户保存含 `long_click` / `swipe` / `drag` 的用例时，前端不阻止。执行时 test-runner 遇到这三种类型会跳过并记录 `WARNING: step type 'swipe' not implemented in adapter`，后续步骤继续执行，不影响整体结果判定。

**异常场景**：

| 异常类型 | 触发条件 | 系统行为 | 用户看到的提示 |
|------|------|------|------|
| 网络断连 | 步骤编排中保存用例失败 | 前端保存按钮 loading 结束后显示错误，编辑内容保留在本地 | Toast：「保存失败，请检查网络」+「重试」按钮 |
| 数据为空 | 元素库中无可用元素 | 元素选取器展示空状态引导 | 「暂无可选元素，请先在元素定位模块抓取页面」+「前往元素定位」链接 |
| 输入非法 | 步骤必填参数缺失（如 click 无 xpath） | 前端即时校验：步骤卡片边框标红 + 保存按钮 disabled + 后端保存时二次校验 | 步骤卡片下方红字：「请选择目标元素（XPath 不能为空）」 |
| 超时 | 单步调试超过 30 秒未返回 | 前端终止等待，步骤卡片显示超时标记 | 步骤卡片显示 ⏱ 超时标记 + Toast：「步骤执行超时（30s）」 |
| v3 步骤执行 | 用例中含 v3 规划步骤（long_click/swipe/drag） | 保存正常入库，执行时 test-runner 跳过并记 warning 日志 | 执行报告中该步骤显示为「⏭ 跳过（未实现）」 |
| XPath 失效 | 调试时元素在设备上未找到 | 返回 NOT_FOUND 结果，不中断后续步骤 | 步骤卡片显示 ❌ NOT_FOUND + 元素未找到提示 |

#### 3.2.5 前端交互要求

| 变动项 | 描述 |
|--------|------|
| 步骤列表 | 用例编辑页核心区域：可折叠步骤卡片，每行显示 步骤序号 / 类型图标+名称 / XPath 摘要 / 参数摘要 |

### 3.3 F-03：测试点接入与 YAML 导出

#### 3.3.1 需求定义

从 element-locator 中提取所有标记为 `is_test_point=True` 的元素，结合页面流程（PageFlow）自动生成 YAML 格式的测试用例文件。支持从 `exports/` 目录导入已有 YAML 文件。

#### 3.3.2 需求目标

| 目标 | 衡量方式 | 目标值 |

| 导出 YAML 可执行 | 导出的 YAML 可被 test-runner 正确解析和执行 | 100% |

#### 3.3.3 触发条件

- 用户在 case-manager 页面点击「导出 YAML」

#### 3.3.4 业务规则

**YAML 导出流程**：
1. 查询所有 `Element.objects.filter(is_test_point=True)`

3. 读取 PageFlow 确定页面跳转顺序

5. 输出 YAML 文件到 `exports/`
6. 前端可下载 `exports/` 目录下任意文件（不再写入已删除的 TestCaseCache 表）

**导入支持**（批量导入）：
- `POST /api/cases/definitions/batch` 接收用例数组，支持 `overwrite` + `directory_id` 统一分配
- `GET /api/cases/exports` 列出所有已导出文件
- `GET /api/cases/exports/{filename}` 下载指定文件

#### 3.3.5 前端交互要求

| 变动项 | 描述 |
|--------|------|
| 导出按钮 | 页面顶部「导出 YAML」按钮，点击后 loading → toast 成功 |
| 导出列表 | el-table 列出 exports/ 下 YAML 文件：文件名 / 时间 / 下载按钮 |
| 下载 | 直接 GET `/api/cases/exports/{filename}` 触发浏览器下载 |

#### 3.3.6 后端接口要求

| 接口 | 核心行为 |
|------|---------|
| `POST /api/cases/export/yaml` | 查询 is_test_point 元素 + PageFlow → 生成 YAML → 写入 exports/ |

| `GET /api/cases/exports/{filename}` | 下载指定文件 |

**异常场景**：

| 异常类型 | 触发条件 | 系统行为 | 用户看到的提示 |
|------|------|------|------|
| 网络断连 | 导出/下载过程中网络不可用 | 导出失败，按钮恢复可用 | Toast：「导出失败，请检查网络后重试」 |

### 3.4 F-04：用例目录层级（新增）

#### 3.4.1 需求定义

支持两级目录结构组织测试用例。用户可创建一级目录（根目录）和二级子目录，将用例归入目录管理。目录树中直接显示用例子节点，右键菜单支持从目录直接创建用例。

#### 3.4.2 需求目标

#### 3.4.3 触发条件

- 点击目录树顶部 `+` 按钮 → 创建一级目录
- 右键一级目录节点 →「新建子目录」
- 右键目录节点 →「重命名」/「删除」
- 右键二级目录节点 →「新建用例」→ 跳转新建页并预填目录
- 右键用例子节点 →「编辑用例」/「删除用例」

#### 3.4.4 业务规则

**两级目录结构**：
- `parent_id IS NULL` → 一级目录（根目录）
- `parent_id IS NOT NULL` → 二级目录（子目录）
- 应用层强制不超过两级（`api.py` 校验），UI 层面：只有一级目录的右键菜单才显示「新建子目录」

**目录重名约束**：数据库层 `UNIQUE (parent_id, name)` + 应用层校验

**目录删除约束**：有子目录或用例时拒绝删除，提示「请先清空后再删除」

**用例归属**：FK `on_delete=SET_NULL` —— 删除目录时用例保留（`directory_id=NULL`）

**目录树响应**：`GET /api/cases/directories` 返回完整树，包含目录节点 + 用例子节点（`node_type: "case"`），case_count 递归聚合

**用例子节点**：每个用例在树中渲染为 `📋` 图标 + 标题（斜体）+ 优先级标签（P0🔴/P1🟡/P2⚪），停用用例显示灰色 + 删除线

**异常场景**：

| 异常类型 | 触发条件 | 系统行为 | 用户看到的提示 |
|------|------|------|------|
| 网络断连 | 创建/重命名/删除目录时网络不可用 | 操作失败，弹窗保持打开或目录树回滚 | Toast：「操作失败，请检查网络」；新建/重命名弹窗保持打开不关闭，避免用户输入丢失 |
| 数据为空 | 首次进入页面无目录 | 展示空状态引导 | 「暂无目录，点击上方 + 按钮创建第一个目录」 |
| 输入非法 | 目录名为空 / 超长（>200字符）/ 纯空格 | 前端实时校验 + 后端 400 | 空名：「目录名称不能为空」；超长：「目录名称不能超过 200 个字符」 |
| 重名冲突 | 同级目录下已存在同名目录 | 后端返回 400 + 409 状态码 | 弹窗内红字提示：「该层级下已存在同名目录: {name}」，弹窗保持打开 |
| 权限不足 | 删除非空目录（有子目录或用例） | 后端拒绝删除，返回 409 | Toast：「目录下存在子目录或用例，请先清空后再删除」 |
| 超时 | 目录树加载超过 5 秒 | 前端显示 loading 骨架屏，超时后展示错误态 | 「加载目录超时」+「重新加载」按钮 |

#### 3.4.5 前端交互要求

| 变动项 | 描述 |

#### 3.4.6 后端接口要求

| 接口 | 核心行为 |
|------|---------|
| `GET /api/cases/directories` | 返回完整树（目录 + 用例子节点），含 case_count、node_type |

#### 3.4.7 未分配目录用例的根级显示（v3.6 新增）

当用例的 `directory_id` 为 `NULL`（即未分配到任何目录）时，该用例在目录树中显示为根级节点，与一级目录平级。这确保用户不会因为不知道某个用例未归类而遗漏它。

**视觉表现**：
- 根级用例节点与目录内用例节点样式一致：📋 图标 + 标题（斜体）+ 优先级标签（P0🔴/P1🟡/P2⚪）
- 停用用例显示灰色 + 删除线
- 根级用例节点按标题字母序排列，排在所有一级目录节点之后

**交互规格**：

| 操作 | 行为 |
|------|------|
| 点击根级用例节点 | 与目录内用例节点一致：右侧面板切换到步骤详情态，面包屑追加 📄 用例标题 |
| 右键根级用例节点 | 显示用例菜单：📝 编辑用例 / 🗑️ 删除用例（不显示目录菜单） |
| 长按拖拽根级用例 | 可拖入任意目录；拖到根级（before/after 同级节点）时提示「不能移动到根级，请选择一个目录」 |
| 批量选择根级用例 | 与目录内用例一致：可选择 + 可批量移动到目录 |
| 删除根级用例 | 物理删除，二次确认后刷新树 |

**后端实现**：`get_directory_tree()` 构建完目录树后，追加 `directory__isnull=True` 的用例为根级虚拟节点：

```json
{
  "id": "case:TC-20260707-000000-0001",
  "name": "未归类的登录测试",
  "node_type": "case",
  "case_id": "TC-20260707-000000-0001",
  "enabled": true,
  "priority": "P0",
  "category": "smoke",
  "step_count": 5,
  "children": []
}
```

> **注意**：根级用例节点 `id` 使用 `"case:{case_id}"` 前缀格式，与目录内用例节点保持一致。`parent_id` 字段不存在（不是 null，是 key 不存在），前端通过 `node_type === "case"` 优先判断，不依赖 `parent_id`。

**边界约束**：
- 根级用例节点的右键菜单只显示「编辑用例」和「删除用例」，不显示「新建子目录」「新建用例」「重命名」（这些是目录节点专属操作）
- 拖拽根级用例到根级位置（另一个根级节点之前/之后）时，由于 `targetDirId` 为 `null`，系统提示「不能移动到根级」

## 5. 数据模型

### 5.1 cm_case_directories（目录表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INT PK | AUTO_INCREMENT | 自增主键 |
| `name` | VARCHAR(200) | NOT NULL | 目录名称 |
| `parent_id` | FK → self | NULLABLE, CASCADE | 父目录（NULL=一级） |
| `sort_order` | INT | DEFAULT 0 | 排序权重 |
| `created_at` | DATETIME | AUTO_NOW_ADD | 创建时间 |
| `updated_at` | DATETIME | AUTO_NOW | 更新时间 |

**索引/约束**: `UNIQUE (parent_id, name)` — 同级目录名唯一

**层级设计**: 两级上限由应用层强制，数据库层不限制。

**case_count 递归聚合规则**：目录树 API 返回的 `case_count` 为**递归聚合值** = 本目录直接用例数 + 所有子目录的 `case_count` 之和。如果一级目录 A 下有 5 个用例，其子目录 B 下有 3 个用例，则 A 的 `case_count=8`，B 的 `case_count=3`。用例子节点的 `case_count` 始终为 0。

**错误响应示例**：

```json
// 400 — 参数校验失败
{"ok": false, "error": "目录名称不能为空"}

// 404 — 资源不存在
{"ok": false, "error": "not found"}

// 409 — 状态冲突（删除非空目录/重名）
{"ok": false, "error": "目录下存在子目录或用例，请先清空后再删除"}

// 500 — 服务器内部错误
{"ok": false, "error": "服务器内部错误"}
```

## 9. 关键约束速查

| 约束 | 实施位置 | 说明 |
|------|:--:|------|
| 目录最大两级 | `api.py` | 应用层校验 |
| 同级目录名唯一 | `models.py` + `api.py` | UNIQUE 约束 + 应用层校验 |
| **同目录用例名唯一** | `models.py` + `api.py` | UNIQUE(directory, title) 约束 + 应用层校验。不同目录允许同名 |
| **用例 ID 全局唯一** | `models.py` (PK) | `id` VARCHAR PRIMARY KEY，`update_or_create` 保证不重复 |
| 删除非空目录禁止 | `api.py` | 有子目录或用例时拒绝 |
| 用例 title 必填 | `CaseEditor.vue` | 前端校验 |
| 用例 package_name 必填 | `CaseEditor.vue` | 前端校验 |
| 删除目录不影响用例 | `models.py` | FK `on_delete=SET_NULL` |
| 未保存离开拦截 | `CaseEditor.vue` | `onBeforeRouteLeave` + Dirty Tracking |
| 用例保存幂等 | `views.py` | `update_or_create` |
| el-cascader 必须 `emitPath: false` | `CaseEditor.vue` | 防止 v-model 类型不匹配 |
| 写操作 catch 必须报错 | `DirectoryTree.vue` | `formatApiError(e)` |
| **边界值** | | |
| 用例 title 最大长度 | `models.py` + 前端校验 | 500 字符（DB VARCHAR(500)），超长截断提示 |
| 目录名最大长度 | `models.py` + 前端校验 | 200 字符（DB VARCHAR(200)），超长截断提示 |
| 单用例最大步骤数 | 前端校验 | 100 步（超限提示「单用例最多 100 个步骤」） |
| 步骤 JSON 最大体积 | 后端校验 | 1MB（超限返回 400） |
| 批量导入最大条数 | `views.py` | 500 条/次（超限返回 400） |
| 目录树最大节点数 | `api.py` | 10000（含目录+用例节点，超限提示缩小范围） |
| **并发** | | |
| 用例保存冲突 | `views.py` | Last Write Wins（后保存覆盖先保存） |
