## 一、状态机 · 生命周期管理

> 对应 PRD §1.1-1.4：任务卡片从新建到终结的完整状态流转。

### 1.1 状态转移规则验证

> 验证状态机只允许合法状态跳转——新建任务后只能先排队再执行，执行完毕后不可回退。

| 测试项 | 测试场景说明 | 测试步骤 | 预期 | 状态 |
|------|------|------|------|:--:|
| **idle→queued** | 用户点击「执行」后，任务从"未执行"进入"等待中" | Mock `status="idle"` 的卡片，调用 `_validate(card, "queued", "")` | 不抛异常 | ✅ |
| **queued→running** | 设备释放后，排队任务自动出队进入"执行中" | Mock `status="queued"` 的卡片，调用 `_validate(card, "running", "")` | 不抛异常 | ✅ |
| **queued→idle（取消）** | 用户点击「取消排队」，任务回到未执行 | Mock `status="queued"` 的卡片，调用 `_validate(card, "idle", "")` | 不抛异常 | ✅ |
| **running→done/completed** | 全部用例执行完毕，正常终态 | `_validate(card, "done", "completed")` | 不抛异常 | ✅ |
| **running→done/stopped** | 用户点击「停止」，手动终止执行 | `_validate(card, "done", "stopped")` | 不抛异常 | ✅ |
| **running→done/interrupted** | 服务器重启/进程崩溃导致中断 | `_validate(card, "done", "interrupted")` | 不抛异常 | ✅ |
| **running→done/error** | 设备断连或前置检查失败导致的致命错误 | `_validate(card, "done", "error")` | 不抛异常 | ✅ |

### 1.2 幂等性验证

> 验证同一状态转移重复执行不会报错——比如已排队的任务再次排队，状态不变。

| 测试项 | 测试场景说明 | 测试步骤 | 预期 | 状态 |
|------|------|------|------|:--:|
| idle 重复 enqueue | 新建任务连续两次点「执行」 | `_validate(card, "queued", "")` → 再调一次 | 不抛异常 | ✅ |
| queued 重复转移 | 排队中的任务再次排队 | `_validate(card, "queued", "")` | 不抛异常 | ✅ |
| running 重复转移 | 执行中的任务再次标记执行中 | `_validate(card, "running", "")` | 不抛异常 | ✅ |
| done/completed 重复 | 已完成的任务再次标记完成 | `_validate(card, "done", "completed")` | 不抛异常 | ✅ |
| done/stopped 重复 | 已停止的任务再次标记停止 | `_validate(card, "done", "stopped")` | 不抛异常 | ✅ |
| done/interrupted 重复 | 已中断的任务再次标记中断 | `_validate(card, "done", "interrupted")` | 不抛异常 | ✅ |
| done/error 重复 | 已错误的任务再次标记错误 | `_validate(card, "done", "error")` | 不抛异常 | ✅ |

### 1.3 非法转移拒绝

> 验证状态机正确拦截不应发生的跳转——比如已完成的任务不能重新执行，未执行的任务不能直接跳到执行中。

| 测试项 | 测试场景说明 | 测试步骤 | 预期 | 状态 |
|------|------|------|------|:--:|
| **done 不能再转移** | 已完成的任务被误操作重新执行/回退 | done/completed → queued/idle/running 等 | 抛 `InvalidTransition` | ✅ |
| **idle 不能直接到 running** | 绕过排队逻辑直接执行（缺少设备锁定步骤） | idle → running | 抛 `InvalidTransition` | ✅ |
| **idle 不能直接到 done** | 未执行的任务被直接标记完成 | idle → done/completed | 抛 `InvalidTransition` | ✅ |
| **queued 不能直接到 done** | 排队中的任务跳过执行直接标记完成 | queued → done/completed | 抛 `InvalidTransition` | ✅ |
| **running 不能回退到 idle** | 执行中的任务被回退到未执行（绕过 done 终态） | running → idle | 抛 `InvalidTransition` | ✅ |
| **running 不能回退到 queued** | 执行中的任务被回退到排队 | running → queued | 抛 `InvalidTransition` | ✅ |
| **非法 outcome** | 传入不存在的终态子类型（如 timeout） | running → done/timeout | 抛 `InvalidTransition` | ✅ |

### 1.4 DB 持久化生命周期

> 验证状态变更不仅校验通过，还能正确写入数据库——状态机的 enqueue/dequeue/complete/fail 全链路。

| 测试项 | 测试场景说明 | 测试步骤 | 预期 | 状态 |
|------|------|------|------|:--:|
| **enqueue 写入 DB** | 用户提交执行→任务从 idle 变成 queued | 创建 idle TaskCard → `sm.enqueue()` → `refresh_from_db()` | `status == "queued"` | ✅ |
| **enqueue 幂等** | 已排队的任务被重复提交（防抖场景） | 已 queued 的卡片再次 enqueue | 不报错，status 不变 | ✅ |
| **cancel 回退到 idle** | 用户取消排队→任务回到未执行 | queued 卡片 → `sm.cancel()` → `refresh_from_db()` | `status == "idle"` | ✅ |
| **dequeue 创建 TestRunRecord** | 调度器出队→创建审计快照 | queued 卡片 → `sm.dequeue()` | status="running" 且 TestRunRecord 已创建 | ✅ |
| **dequeue 冻结用例快照** | 执行前冻结步骤定义，后续编辑不影响本次审计 | dequeue 传 `selected_cases=[]` | `record.selected_cases == []` | ✅ |
| **complete 完成生命周期** | 用例全部执行成功→正常终结 | 完整 idle→queued→running→done | TaskCard done/completed + RunRecord COMPLETED | ✅ |
| **fail(error)** | 执行阶段发生致命错误（设备断连等） | `sm.fail(outcome="error")` | TaskCard outcome="error" | ✅ |
| **fail(stopped)** | 用户手动点击停止 | `sm.fail(outcome="stopped")` | TaskCard stopped + RunRecord STOPPED | ✅ |
| **fail(interrupted)** | 服务器崩溃导致中断 | `sm.fail(outcome="interrupted")` | TaskCard outcome="interrupted" | ✅ |
| **record_iteration** | 每次迭代结果写入 TestResult 表 | dequeue → `sm.record_iteration()` | DB 中 case_id/iteration/result 正确 | ✅ |

### 1.5 孤儿恢复

> 验证服务器重启后自动修复异常中断的任务——模拟进程崩溃后，状态机将残留的 running 任务标记为 interrupted。

| 测试项 | 测试场景说明 | 测试步骤 | 预期 | 状态 |
|------|------|------|------|:--:|
| **修复孤儿 running 任务** | 服务重启后发现 status=running 但无活跃进程 | 手动设置 `status=running,running=True` → `recover_orphans()` | `outcome == "interrupted"` | ✅ |
| **修复僵尸 TestRunRecord** | 运行记录为 RUNNING 但关联的任务已丢失 | 创建无关联 TaskCard 的 RUNNING 记录 → `recover_orphans()` | `status == "FAILED"` | ✅ |
| **idle 卡片不受影响** | 未执行的任务不会被误修复 | idle 卡片 → `recover_orphans()` | status 保持 idle | ✅ |
