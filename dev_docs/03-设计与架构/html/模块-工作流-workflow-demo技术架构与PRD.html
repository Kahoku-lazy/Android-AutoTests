1. 产品定位与概述

🏝️
产品代号：工作流工作台
2
双视图 Tab：页面流 + 测试用例

1.1 解决什么问题

在 Android-AutoTests 主平台中，页面关系建模和测试用例编排是两件独立的事，用户需要在 element-locator 和 case-manager 之间来回切换，缺乏可视化联动。workflow-demo 尝试用 ComfyUI 风格节点图 + Scratch 风格积木块 两种可视化范式，将页面跳转关系和测试步骤编排统一到一个工作台中。

1.2 核心价值主张

  • 可视化页面关系：用带类型的端口（entry / navigation / popup_trigger）连接页面节点，连线规则内置校验
  • Scratch 积木式用例编写：14 种测试步骤 + 条件分支 + 循环，拖拽拼接，所见即所得
  • 元素桥接：页面流的输出端口（绑定 UI 元素 + XPath）一键灌入测试用例积木的定位字段
  • 离线可运行：内置 Mock 演示数据（5 页淘宝结构 + 8 步示例用例），不依赖后端即可体验完整流程
  • 动森主题：与主平台 AI 助手模块一致的暖木色、大圆角视觉风格

3. 核心类型系统

3.1 端口类型体系 types/workflow.ts

这是整个画布连线校验的基石——5 种端口类型 + 连线规则表，实现了强类型连线（类似 ComfyUI 的节点端口类型约束）：

端口类型常量颜色允许连入语义
entry蓝色—navigation / popup_close页面入口，支持多连入
navigation紫色entry—页面跳转
popup_trigger红色popup_fixed—弹窗触发入口（单连入）
popup_fixed红色—popup_trigger弹窗固定触发元素
popup_close灰色entry—弹窗关闭 → 返回页面入口

连线规则表

export const LINK_RULES: Record<string, string[]> = {
  navigation:   ['entry'],           // 页面跳转 → 目标页面入口
  popup_fixed:  ['popup_trigger'],  // 弹窗触发元素 → 弹窗入口
  popup_close:  ['entry'],           // 弹窗关闭 → 返回页面入口
}

// entry 端口允许多条线同时连入（MULTI_IN_PORT_TYPES）

节点类型颜色入口输出最大实例特殊行为

5.2 Vue Flow 集成细节 PageFlowVueFlow

  • Loose 连接模式：允许从任意 Handle 拖出，通过 normalizeConnection() 自动翻转源/目标
  • 连接校验链：isValidConnection → explainConnection → LINK_RULES 查表
  • 连接应用链：onConnect → explainConnection → applyVueFlowConnect → store.addLink
  • 节点拖拽同步：onNodeDragStop → syncNodePositionFromVueFlow
  • 删除连线同步：onEdgesChange (remove) → store.removeLink
  • 元素选择器：Teleport 到 body 的浮层，从元素池搜索/选择，去重检查
  • MiniMap + Controls：右下角小地图 + 左下角缩放控件

5.3 Blockly 集成细节 TestCaseBlockly

  • 自定义主题：基于 Zelos 渲染器，动森配色（暖木色背景 / Nunito 字体 / 青绿光标）
  • 自定义积木箱：用 Vue 组件 ScratchPalette.vue 替代 Blockly 原生 Toolbox（通过 toolbox: undefined 禁用原生，隐藏 flyout）
  • 双向序列化：workspaceToBlocks (Blockly→Store) / loadBlocksIntoWorkspace (Store→Blockly)
  • 自动同步：workspace.addChangeListener 监听非 UI 事件 → 自动 pushToStore
  • 尺寸自适应：ResizeObserver + Blockly.svgResize，处理 v-show 切换导致的 0 尺寸问题
  • 拖放接收：监听 dragover/drop 事件，从 dataTransfer 读取 application/x-blockly-type
  • 积木放置位置：计算 viewport 相对坐标，叠放在已有积木下方

5.4 桥接面板（元素绑定）

TestCaseBlockly 顶部可展开的 桥接面板，列出 workflowStore 中所有 bridgedElements：

  1. 用户在页面流 Tab 为节点输出端口挂载元素（如「搜索图标」+ XPath）
  2. bridgedElements getter 自动收集所有带 el 的输出端口
  3. 切换到测试用例 Tab → 展开桥接面板 → 看到所有已挂元素
  4. 点击某个桥接元素 → 调用 applyXpathToSelected，写入当前选中积木的 XPATH + LABEL 字段
  5. 同时标记 element_id / element_label 到 StepBlock 数据中

5.5 handleAddToCase（一键添加步骤）

页面流节点端口上的 👆 / ⏳ 按钮可直接将元素生成为测试步骤：

// App.vue
function handleAddToCase({ nodeId, slotIndex, stepType }) {
  const node = store.findNode(nodeId)
  const port = node?.outputs[slotIndex]
  if (!port?.el) return  // 端口没有挂元素

  const block = tcStore.addStepAfter(tcStore.selectedId, stepType)
  tcStore.updateStepData(block.id, {
    label: port.name,
    xpath: port.el.xpath || '',
    element_id: port.el.id,
    element_label: port.name,
    timeout: stepType === 'wait' ? 10 : 5,
  })
  activeTab.value = 'test-case'  // 自动切换到用例 Tab
}
