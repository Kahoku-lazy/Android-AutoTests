第 2 层：L2 执行编排层 — adapter → executor → runner 三级流水线

DeviceAdapter — u2 API 的薄封装 (242 行)

设计特点说明
适配器模式包装原始 u2 device 实例，对外暴露统一的设备操作接口。StepExecutor 只依赖 DeviceAdapter，不直接 touch u2。
可中断 sleepsleep() 每 100ms 检查 should_stop() 标志。传统 time.sleep() 无法中断，这个实现允许用户随时停止测试。
日志缓冲_log_buffer 收集所有日志，通过 _emit_log 回调实时推送 + 通过 get_log_buffer() 支持批量取回。
kill 多重保障kill_app() 执行 am force-stop → am kill → pkill 三级回退，确保 App 彻底终止而非后台挂起。
等待类方法的容错wait_for_toast() 双重检测（XPath 文本 + d.toast.get_message(0)），任一命中即返回。Timeout 后明确返回 False。

StepExecutor — 步骤类型 → 操作的分发器 (232 行)

设计特点说明
Handler 字典映射17 种步骤类型 → 17 个 _do_xxx() 方法。O(1) 查找，新增步骤类型只需加一个 key-value。
步骤回调每步执行后调用 _step_callback(i, total, type, desc, result)，供上层 runner 统计和推送。
early-exit任一步骤失败立即返回，后续步骤不执行。符合"失败即停"的测试执行语义。
17 种类型 vs 14 种枚举step_types.py 定义 14 种 StepType，但 executor 的 handler 字典映射了 17 种——多了 long_click / swipe / drag / wait_any。枚举和实现不同步。

TestRunner — 异步编排器 (310 行)

设计特点说明
线程池安全_safe_run_in_executor() 多层 try/except — RuntimeError(quit) / BrokenPipeError / OSError → 统一包装为 ConnectionError。这是生产环境的防御性代码。
设备隔离测试执行创建独立 u2 连接，不走 DevicePool 单例。设计意图：长时间测试不应持有全局锁，且设备池仍可为其他用户服务。
7 种回调on_log / on_case_started / on_iteration_result / on_case_finished / on_run_finished / on_step_result / on_device_error
_RunState 内存态_active_runs: dict 追踪所有活跃运行。但被 dashboard 直接引用（防火墙违规）。

🔄 执行数据流 — 从步骤定义到设备操作

  1. 用户保存用例 → CaseEditor → POST /api/cases/definitions → cm_test_definitions.steps_json
  2. 用户启动执行 → 前端 POST /api/runner/run → views.py → asyncio.create_task(run_test())
  3. runner.run_test() → 创建独立 u2 连接 → DeviceAdapter(device, ...) → StepExecutor(adapter)
  4. 遍历用例 → executor.execute_all(steps) → handler 字典查找步骤类型 → 调用 adapter 对应方法
  5. adapter 操作设备 → d.xpath(xp).click() → uiautomator2 → ADB → Android 真机
  6. 结果回传 → 每步回调 → TestRunnerCallback → consumers.py → WebSocket → 前端实时更新
  7. 持久化 → 执行完毕 → tr_test_results 写入结果 → ReportGenerator 生成 CSV/HTML 报告
