## 二、需求对齐任务（每次代码变更后）

### 与后端代码对齐

| 检查项 | 验证方式 | 频率 |
|--------|---------|:--:|
| API 端点数量是否匹配 PRD | `grep -c "path(" apps/*/urls.py` vs PRD 描述 | 每次新增端点 |
| 数据表是否匹配 | `python manage.py dbshell ".tables"` vs PRD 数据模型 | 每次新增表 |
| 字段是否一致 | `grep "class.*Model" apps/*/models.py` vs PRD 字段描述 | 新增字段时 |

### 与前端代码对齐

| 检查项 | 验证方式 | 频率 |
|--------|---------|:--:|
| 模块路由是否齐全 | `frontend/src/router.js` 中 import 数量 vs 7 模块 | 新增模块时 |
| 组件是否匹配 PRD 功能列表 | 逐一打开页面验证 | 新增功能时 |
| 数据是否来自 API | `grep -rn 'ref(\[{.*id:' frontend/src/modules/` | 每次改前端 |

## 三、8 维矛盾分析清单

| # | 维度 | P0 标准 |
|:--:|------|------|
| 1 | 架构一致性 | PRD 架构风格 ↔ 架构方案一致 |
| 2 | 模块一致性 | 7 子 PRD 齐全，编号 01-07 与代码一致 |
| 3 | 技术栈一致性 | 版本号与 `requirements.txt` / `package.json` 一致 |
| 4 | 版本路线 | 里程碑归属正确，工作量误差 ≤20% |
| 5 | 数据库一致性 | 表前缀/表名/表数量 18±2 |
| 6 | API 一致性 | 端点数量、路径前缀 `/api/{domain}/*` |
| 7 | 规则一致性 | Agent 约束、代码 Review 条款互相覆盖 |
| 8 | 跨文档引用 | 链接目标存在、编号一致、版本号不超前 |
