二、重构方案评估

模块化重构方案方向正确，但实施顺序和部分技术细节需调整。

✅ 合理之处
  • Django views 按子域拆 6 文件 — 职责清晰
  • ChatView 拆 8 组件 + 4 composables — SSE/UI 解耦
  • Tool 工厂按 agent ai_tools 过滤 — 与表设计一致
  • Provider 映射抽取 provider_registry.py
  • 分阶段实施降低一次性大改风险
⚠️ 需调整
  • 阶段顺序：原 Phase 1 只做 permissions，安全漏洞未优先
  • permissions 接入：当前是占位逻辑，需配合 owner FK
  • Tool user_id 注入：tool._user_id = 改单例 — 并发不安全
  • ChatView 拆分：应先抽 SSE composable，边拆边修 XSS
  • JWT 统一：需覆盖 jti + Redis 黑名单

四、Phase 1 — 横切能力接入（2–3 天）

新增 decorators.py

def require_auth(view):
    def wrapper(request, *args, **kwargs):
        if not getattr(request, 'user_id', None):
            return JsonResponse({'ok': False, 'error': 'Unauthorized'}, status=401)
        return view(request, *args, **kwargs)
    return wrapper

# 写操作统一模式
@require_auth
def update_agent(request, agent_id):

def build_business_tools(user_id, agent_id, session_id):
    enabled = set(
        AITool.objects.filter(agent_id=agent_id, enabled=True)
        .values_list('name', flat=True)
    )
    tools = []
    for cls in _TOOL_REGISTRY:
        if cls.name in enabled:
            tool = cls()  # 新实例，非单例
            tool._ctx = ToolContext(user_id=user_id, agent_id=agent_id, session_id=session_id)
            tools.append(tool)
    return _PLAN_TOOLS + tools
