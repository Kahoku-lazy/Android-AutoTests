## 一、测试设计方法论

### 六维覆盖模型

```
┌─────────────────────────────────────────────────────────┐
│                    接口测试六维模型                        │
├───────────┬───────────┬───────────┬─────────────────────┤
│ ① 单接口  │ ② 业务流  │ ③ 数据    │ ④ 状态机            │
│ 维度      │ 维度      │ 维度      │ 维度                │
├───────────┼───────────┼───────────┼─────────────────────┤
│ ⑤ 安全    │ ⑥ 非功能  │           │                     │
│ 维度      │ 维度      │           │                     │
└───────────┴───────────┴───────────┴─────────────────────┘
```

### ① 单接口维度 — 每个端点必须覆盖 5 类场景

| 类别 | 编号前缀 | 说明 | 最少条数 |
|------|:--:|------|:--:|
| **正常** | `_OK_` | 合法参数，期望 200 | 1 |
| **参数校验** | `_ARG_` | 缺必填、超长、类型错误、非法枚举值 | 3~5 |
| **权限校验** | `_AUTH_` | 无 Token、过期 Token、非授权用户 | 2~3 |
| **异常** | `_ERR_` | 资源不存在、冲突、重复操作 | 2~3 |
| **幂等** | `_IDEM_` | 重复相同请求，期望一致 | 1 |

### ② 业务流维度 — 完整用户场景串联

| 类别 | 说明 |
|------|------|
| 正向全流程 | 所有步骤成功，验证参数传递 |
| 中断流程 | 在第 N 步失败，验证回滚/错误处理 |
| 并发流程 | 两个用户同时操作，验证冲突解决 |
| 权限边界流 | 角色切换，验证权限检查点 |

### ③ 数据维度 — 参数生命周期

| 检查点 | 示例 |
|------|------|
| 参数溯源 | `dir_id` 从 `GET /directories` 响应获取 |
| 默认值 | 不传 `priority` → 应默认 `P1` |
| 自动生成 | `id` 格式、`created_at` 非空 |
| 边界值 | `title` 传 500 字符、传空字符串、传特殊字符 |
| 类型转换 | 传 `"true"` 字符串给 bool 字段 |

### ④ 状态机维度 — TestDefinition 状态转换

```
空闲 ──lock──→ 编辑中 ──unlock──→ 空闲
  │               │
  │               └── force unlock ──→ 空闲
  │
  └── case-lock ──→ 已锁定 ── case-unlock ──→ 空闲
```

**必须覆盖的转换**：正常转换 ✅ · 非法转换拒绝 · 超时自动转换

### ⑤ 安全维度

| 检查点 | 说明 |
|------|------|
| 认证 | 无 Token → 401 |
| 授权 | 非创建者改权限 → 403 |
| 数据隔离 | hidden 用例对他人不可见 |
| 信息泄露 | 404 不暴露用例是否存在 |

### ⑥ 非功能维度

| 检查点 | 说明 |
|------|------|
| Content-Type | 响应头正确 |
| 空请求体 | POST 无 body → 400 |
| JSON 格式错误 | 缺少引号/括号 → 400 |
| 超大请求体 | steps_data 超大数组 |

## 三、遗漏清单

### 遗漏 1：单接口用例缺失（8 条）

| 编号 | 端点 | 类别 | 测试内容 |
|------|------|:--:|------|
| CM-ARG-01 | `POST /directories/create` | 参数 | `name` 传 201 字符 → 500 |
| CM-ARG-02 | `POST /directories/create` | 参数 | `name` 为空字符串 |
| CM-ARG-03 | `POST /directories/create` | 参数 | `name` 含特殊字符 `<script>alert(1)</script>` |
| CM-ARG-04 | `POST /directories/{id}/permission` | 参数 | 不传 `allow_create` 字段 → 应使用默认值 true |
| CM-ARG-05 | `POST /definitions` | 参数 | `title` 传 501 字符 → 500 |
| CM-ARG-06 | `POST /definitions` | 参数 | `priority` 传 `"P99"` → 应静默降级为 P1 |
| CM-ARG-07 | `POST /definitions/{id}/visibility` | 参数 | `visibility` 传 `"deleted"` → 静默降级 |
| CM-ARG-08 | `GET /definitions/{id}` | 异常 | `case_id` 不存在 → `404` |

### 遗漏 2：单接口完整覆盖（6 条）

| 编号 | 端点 | 测试内容 |
|------|------|------|
| CM-END-01 | `POST /directories/batch-move` | 正常移动 + items 为空 + 目标不存在 |
| CM-END-02 | `POST /definitions/batch` | overwrite=true 覆盖 + overwrite=false 跳过 + cases>500 拒绝 |
| CM-END-03 | `POST /export/yaml` | 正常导出 + test_case_name 为空默认值 + 无测试点元素 |
| CM-END-04 | `GET /exports` | 空列表（无导出文件时）+ 有文件时 |
| CM-END-05 | `GET /exports/{filename}` | 正常下载 + 文件不存在 404 |
| CM-END-06 | `DELETE /definitions/{id}` | 删除不存在用例 → `200`（幂等） |

### 遗漏 3：幂等性验证（3 条）

| 编号 | 测试内容 |
|------|------|
| CM-IDEM-01 | 重复 `case-lock` 已锁定用例 → `200`（幂等，不报错） |
| CM-IDEM-02 | 重复 `DELETE /definitions/{id}` 已删除用例 → `200` |
| CM-IDEM-03 | 重复 `POST /directories/{id}/permission` 相同参数 → `200` |

### 遗漏 4：业务中断流（3 条）

| 编号 | 场景 | 步骤 |
|------|------|------|
| CM-FLOW-08 | 创建→锁定→编辑冲突 | admin lock → tester lock 被 423 拒绝 → admin unlock → tester lock 成功 |
| CM-FLOW-09 | 权限变更中断 | admin 设为 readonly → tester lock 被 423 → admin 改回 edit → tester lock 成功 |
| CM-FLOW-10 | 可见性中途变更 | tester 正在查看列表 → admin 将该用例 hidden → tester 刷新后消失 |

### 遗漏 5：并发冲突（2 条）

| 编号 | 测试内容 |
|------|------|
| CM-CONC-01 | 两个用户同时创建同目录同名用例 → 一个 200、一个 409 |
| CM-CONC-02 | 两个用户同时 lock 同一用例 → 一个 200、一个 423 |

### 遗漏 6：非功能（3 条）

| 编号 | 测试内容 |
|------|------|
| CM-NF-01 | POST 无 Content-Type header → 400 |
| CM-NF-02 | POST 空 body `{}` 给 `/definitions` → title 为空导致失败 |
| CM-NF-03 | 响应 Content-Type 为 `application/json` |
