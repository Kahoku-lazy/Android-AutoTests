# 报告页内容被截断、无法滚动

> 状态：✅ 已修复 · 日期：2026-07-13 · 模块：前端 · 影响页面：报告列表页、报告详情页

---

## 问题原因

### 1. App.vue 选择器过宽

```css
/* ❌ 原写法 — 选择器范围过大 */
.main-content :deep(> *) {
  flex: 1;
  height: 100%;
}
```

`main-content :deep(> *)` 匹配了 `.main-content` 下的**所有**直接子元素，包括底部的装饰图 `guide-line`。`guide-line` 被意外设为 `flex: 1; height: 100%`，挤占了路由页面的垂直空间。

### 2. 全局 doc-body 的 min-height: 0

```css
/* ❌ 原写法 */
.doc-body {
  min-height: 0;  /* 内容区无法按实际高度撑开 */
}
```

`min-height: 0` 导致 `.doc-body` 无法根据子内容自然撑高。超出首屏的部分被裁剪，且无法触发页面级滚动。

**叠加效果**：`guide-line` 抢空间 + `doc-body` 不撑高 = 下半截内容不可见、不可滚动。

---

## 修复内容

### App.vue

```css
/* ✅ 改为只作用于 .doc-page，让报告页占满主内容区 */
.main-content :deep(.doc-page) {
  flex: 1;
  height: 100%;
}
```

### 报告列表页 index.vue

| 元素 | 修复 |
|------|------|
| `.doc-page` | 作为滚动容器：`height: 100%` + `overflow-y: auto` |
| `.doc-body` | `flex: 0 0 auto; min-height: auto` — 内容可自然撑高 |
| `.doc-hero` | 页头固定不压缩（`flex-shrink: 0`） |

### 报告详情页 ReportDetail.vue

同步应用相同的滚动策略。

---

## 现在的效果

- 首屏正常显示 KPI、图表、标签栏等顶部内容
- 选择 50 / 100 行时，表格区域向下扩展
- 整页可上下滑动查看全部内容，表格内部无滚动条
- 底部装饰图 `guide-line` 不再挤占路由页面空间

---

## 关键教训

1. `:deep(> *)` 选择器杀伤力太大——必须限定到具体 class，不能匹配通配符
2. `min-height: 0` 在 flex 布局中是「允许收缩到零」的信号，不是「允许撑开」
3. 页面区域空白/不可见 → 先打开浏览器 DevTools 检查 computed styles，不要反复改模板
