# 工作流 — 页面流数据被清空 / 多端不同步

> 状态：已修复（2026-07-22）  
> 模块：`apps/workflow` + `frontend/src/modules/workflow`  
> 关联：PRD-08 F-03-01

## 现象

- 「APP页面跳转工作流」等页面流绘制后，再次打开经常变成空画布
- 多标签 / 多端打开同一文档时，内容不一致，后保存方可能覆盖对方

## 根因

1. **`renameNode` 把 `configCache` 一并 PUT**  
   创建时缓存为 `{ nodes: [], links: [] }`；用户只在内存里画图、改标题失焦触发重命名 → 空缓存写回 `config_json`，洗库。
2. **`fetchDocumentConfig` 命中内存缓存即返回**  
   打开文档不重新 GET，多端无法看到对方最新保存。

数据库侧：`wf_documents.config_json` 存 JSON 正常；实查目标文档曾被写成合法但空的 `nodes/links`，属写入问题而非解析失败。

## 修复

| 改动 | 文件 |
|------|------|
| 重命名只更新 title，禁止附带 config | `libraryStore.ts` `renameNode` |
| 打开页面流/用例强制 `GET`（`force: true`） | `libraryStore.ts` `loadPageFlowPayload` / `loadCaseDraft` |
| 保存后以服务端回写刷新缓存 | `savePageFlowPayload` / `saveCaseDraft` |

## 验证

- [ ] 库中 `config_json` 的 `nodes` 长度与画布一致
- [ ] 另一浏览器打开同一 `doc_id` 能看到最新图（打开时走 GET）

## 复现补充（2026-07-22 二次清空）

修复 rename 后，库内曾短暂有 1 个节点，约 1 分钟后再次变成空图（`updated_at=11:59:40`）。

**根因 3**：刷新页面时 `localStorage` 恢复 `wf_lib_active` 为页面流 id，但 **未调用 `openFile` 加载 config**，右侧以空 `workflowStore` 进入编辑；随后「保存 / 切文件 / 回看板」的 `persistActive` 把空快照写回库。

## 二次修复

| 改动 | 说明 |
|------|------|
| `index.vue` onMounted | 始终 `setActive(null)`，禁止带着空 store 自动进编辑 |
| `hydratedFlowId` | 仅 `openFile` 加载完成后才允许 persist 页面流 |
| `savePageFlowPayload` | 空画布覆盖服务器非空图时弹确认，默认拒绝误覆盖 |

## 三次修复（刷新仍丢 — 2026-07-22）

自测：`python tools/test_workflow_pageflow_persist.py` → **ALL PASSED**（后端读写正常）。

前端仍会导致「刷新后没有」：

- **根因 4**：`openFile` 先 `setActive` 再异步 load → VueFlow 挂载时空画布
- **根因 5**：无自动保存，刷新时若未点保存或保存未完成 → 丢内存数据

| 改动 | 说明 |
|------|------|
| `openFile` | 先 load+applySnapshot，再 setActive |
| 500ms 防抖自动保存 | 画布变更后自动 PUT |
| visibilitychange/pagehide | 切走/刷新前尽量落盘 |
| skipEmptyOverwrite | 自动保存拒绝空覆盖 |
