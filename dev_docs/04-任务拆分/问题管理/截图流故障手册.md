# 元素定位截图流故障手册

> **复发问题**：元素定位页左侧手机画面不显示，长期停在「正在连接截图流…」或「No device signal」。  
> 本文记录历次根因、诊断步骤与已落地修复，避免重复踩坑。  
> 版本：v1.0 · 日期：2026-07-02

---

## 一、典型症状

| 用户可见表现 | 说明 |
|-------------|------|
| `正在连接截图流…` | WebSocket 未成功建立，或连接后一直收不到 `screenshot` 消息 |
| `No device signal` / `等待设备画面…` | WS 已连上但无截图帧（旧文案，现已改为中文提示） |
| 页面布局正常，仅左侧手机框空白 | 工具栏、XPath 面板正常，问题集中在 `ScreenshotView.vue` |
| 加载极慢（>10s 才有画面） | 多为首帧 u2 截图慢 + 无 REST 兜底 |

**相关前端组件**

- `frontend/src/modules/element-locator/components/ScreenshotView.vue`
- WebSocket：`/ws/screenshot`（经 Vite 代理到 Django `:8765`）
- REST 兜底：`GET /api/elements/screenshot`（2026-07-02 新增）

---

## 二、根因清单（按出现频率排序）

### 2.1 🔴 Channels Redis + msgpack 序列化器不兼容（HTTP 500）

**最高频、最隐蔽**：HTTP API 正常，唯独 WebSocket 握手失败。

**后端日志特征**（`logs/backend.log`）：

```
Exception inside application: Can't instantiate abstract class MsgPackSerializer
without an implementation for abstract methods 'as_bytes', 'from_bytes'
```

**原因**：

- `config/settings.py` 中 `CHANNEL_LAYERS` 使用 `channels_redis.core.RedisChannelLayer`
- 默认 `serializer_format="msgpack"`
- 在部分 Python 环境（如 **Python 3.13** + 特定 `msgpack`/`channels-redis` 组合）下，MsgPack 序列化器实例化失败
- `AsyncWebsocketConsumer` 在握手阶段就会初始化 Channel Layer → **整段 WS 返回 HTTP 500**

**影响范围**：

- `/ws/screenshot`（元素定位实时截图）
- `/ws/test-run/{id}`（执行引擎实时日志）

**已落地修复**（`config/settings.py`）：

```python
'CONFIG': {
    'hosts': [REDIS_URL],
    'serializer_format': 'json',  # 勿改回 msgpack，除非验证环境兼容
},
```

并增加初始化失败时回退 `InMemoryChannelLayer`。

**截图 Consumer 额外加固**（`apps/element_locator/consumers.py`）：

```python
class ScreenshotConsumer(AsyncWebsocketConsumer):
    channel_layer_alias = None  # 截图广播走 stream.py 内存客户端，不依赖 Channel 组
```

### 2.2 🟡 WebSocket 地址未走 Vite 代理

**错误写法**（直连后端端口）：

```javascript
const url = `${proto}//${location.hostname}:8765/ws/screenshot`
```

**正确写法**（同源 + Vite proxy）：

```javascript
// frontend/src/shared/ws-url.js
export function wsUrl(path) {
  const proto = location.protocol === 'https:' ? 'wss:' : 'ws:'
  return `${proto}//${location.host}${path.startsWith('/') ? path : '/' + path}`
}
// → ws://localhost:5173/ws/screenshot  由 vite.config.js 转发到 :8765
```

**何时会出问题**：

- 前端用局域网 IP 访问（如 `http://192.168.x.x:5173`），但 `:8765` 未对外开放
- HTTPS 页面尝试 `ws://host:8765` 混合内容被拦截

---

### 2.3 🟡 未激活当前设备（`device.current_serial` 为空）

**症状**：WS 能连上，收到 `no_device` 或一直无 `screenshot`。

**原因**：`apps/element_locator/stream.py` 在 `current_serial` 为空时跳过截图循环。

**已落地修复**：

- `apps/device_pool/views.py` `list_devices`：无 current 时自动激活第一台 ONLINE 设备
- `frontend/.../element-locator/store.js`：`fetchDevices` 后若无 current 则静默 `activateDevice`
- 后端推送 `{"type":"no_device","message":"..."}` 供前端展示中文提示

---

### 2.4 🟢 截图阻塞 ASGI 事件循环（加载慢）

**原因**：`device.screenshot_b64()` 为同步 u2 调用，直接在 `async def _broadcast_loop` 里执行会卡住整个 WS 栈。

**已落地修复**：`stream.py` 使用 `loop.run_in_executor(None, ...)` 在线程池执行截图。

---

### 2.5 🟢 首帧慢、无静态兜底

**已落地修复**：

- 新增 `GET /api/elements/screenshot` 返回单帧 JPEG base64
- `ScreenshotView.vue` 在 `onMounted` 与 `onopen` 时调用 `fetchSnapshot()`，WS 连上前先显示一帧

## 三、5 分钟诊断流程

```
1. 服务是否在线？
   python run.py status
   → Django :8765 必须为 ONLINE

2. WebSocket 能否握手？（最关键）
   python -c "import asyncio,websockets; asyncio.run(websockets.connect('ws://127.0.0.1:8765/ws/screenshot').__aenter__())"
   或查看 logs/backend.log 是否有 MsgPackSerializer 报错

3. ADB 是否有设备？
   adb devices
   → 至少一台 status=device

4. 当前设备是否激活？
   curl http://localhost:8765/api/devices
   → data.current 非空

5. REST 截图是否可用？
   curl http://localhost:8765/api/elements/screenshot
   → {"ok":true,"image":"..."}

6. 浏览器 Network → WS
   → 应看到 /ws/screenshot 状态 101，持续收到 screenshot 帧
```

## 四、标准修复步骤

| 步骤 | 操作 |
|------|------|
| 1 | 确认 `config/settings.py` 中 `serializer_format: 'json'` 未被改回 |
| 2 | `python run.py restart`（修改 settings / consumers 后必须重启 Django） |
| 3 | 设备管理页扫描设备，确认 ONLINE |
| 4 | 元素定位页选择设备，或依赖自动激活 |
| 5 | 硬刷新页面 Ctrl+F5 |

**一键验证脚本**（项目根目录临时执行）：

```python
# 保存为 _verify_screenshot.py 后执行: python _verify_screenshot.py
import asyncio, json, websockets

async def main():
    async with websockets.connect("ws://127.0.0.1:8765/ws/screenshot") as ws:
        for _ in range(3):
            msg = json.loads(await asyncio.wait_for(ws.recv(), timeout=15))
            print(msg["type"], len(msg.get("image", "")) if msg["type"] == "screenshot" else msg)

asyncio.run(main())
```

期望输出包含 `device_changed` 与 `screenshot len=xxxxx`。

## 六、预防与 Code Review 检查项

开发或升级依赖后，**必须**确认：

- [ ] `pip show channels channels-redis msgpack` 版本变更后重测 WS 握手
- [ ] 未将 `CHANNEL_LAYERS.CONFIG.serializer_format` 改回 `msgpack` 除非全环境验证通过
- [ ] 前端 WS 统一使用 `wsUrl()`，禁止硬编码 `:8765`
- [ ] 新增 WS Consumer 若不用 Channel 组，设置 `channel_layer_alias = None`
- [ ] 阻塞型 u2/ADB 调用不得放在 async 协程主线程，使用 `run_in_executor`
- [ ] 合并后执行 `python run.py restart` 并跑 §三 诊断流程

**依赖建议**（`requirements.txt` 已声明，升级时注意）：

```
channels>=4.0
channels-redis>=4.0
```

若未来 msgpack 路径必须启用，需在目标 Python 版本上实测 `RedisChannelLayer(serializer_format='msgpack')` 实例化成功后再改配置。
