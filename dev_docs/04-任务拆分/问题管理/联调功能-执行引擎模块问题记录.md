## 🔴 P0：竞态条件（会导致数据丢失或状态错误）

### 1. 队列任务丢失
**位置**：`views.py:731-734` — `_start_next_queued()`

`is_device_busy()` 与 `mark_device_busy()` 非原子操作。两协程可同时通过 busy 检查，同时 `_dequeue()`，第二个拿到的任务被丢弃。

**修复方向**：加 `asyncio.Lock` 保护 dequeue 操作。

### 2. TaskCard 状态并发覆盖
**位置**：`state_machine.py:89` — `_save_transition()`

`task_card.save()` 无乐观锁。并发 `sm.complete()` 与 `sm.fail()` 后写者覆盖先写者，执行结果丢失。

**修复方向**：`select_for_update()` 或 `F()` 条件更新。

### 3. `_run_client_task` 并发删读
**位置**：`views.py:565 vs 972`

`finalize()` 读 `_run_client_task` 时，`list_active` 可能同时删除同一 key，导致 TaskCard 卡在 running 状态。

**修复方向**：`copy()` 快照读取，或加锁。

### 4. `_preflight_runs` 注册晚于协程启动
**位置**：`views.py:436`（在 `423` spawn 之后）

`stop_test_run` 信号在注册前到达会被静默忽略。

**修复方向**：先注册再 spawn。

### 5. `_bg_sync` 闭包变量捕获
**位置**：`views.py:233,333`

`effective_pkg` 等变量在 `await` 后可能被下一轮循环覆盖。

**修复方向**：默认参数捕获。

### 6. 并发恢复无互斥
**位置**：`recovery_helpers.py:28`

`recover_stale_running_taskcards` 可被两个 HTTP 端点同时调用。

**修复方向**：加互斥锁或改为启动时一次性执行。

## 🟠 P1：资源泄漏（设备锁/连接不释放）

### 7. 用例加载失败不释放 DB 设备锁
**位置**：`views.py:788-791`

`test_cases` 为空时 `mark_device_idle()` 被调用但 `dp_release_device()` 未调用。

**修复方向**：在 return 前补 `await sync_to_async(dp_release_device)(serial, reason="error")`。

### 8. `check_and_connect_async` 无超时包装
**位置**：`views.py:384`

USB 断连时可能无限挂起，阻塞设备和队列。

**修复方向**：`asyncio.wait_for(check_and_connect_async(...), timeout=30)`。

### 9. `persist()` DB 写入失败后不调度队列
**位置**：`views.py:543 vs 717`

执行成功但 DB 写入失败时，`_schedule_next_queued` 不被调用，排队任务饥饿。

**修复方向**：finally 中无条件调度。

## 🟡 P2：错误处理缺陷

### 10. 静默吞异常（5 处）
**位置**：`views.py:160,183,357,369,654`

`except Exception: pass` 或 `print()`，故障完全不可见。

**修复方向**：统一用 `logging.getLogger("test_runner.bg").exception()`。

### 11. 适配器错误处理不一致
**位置**：`adapter.py:90-126`

`click()` 正确重抛异常供恢复机制处理；`click_indexed()`/`long_click()`/`swipe()`/`drag()` 吞错或无限流，u2 崩溃无法被检测。

**修复方向**：统一重抛模式。

### 12. `_do_wait` / `_do_poll_text` 绕过适配器
**位置**：`executor.py:108,164`

直接调用 `self.exe.d.xpath()` 而非 `adapter.exists()`，不继承适配器错误处理。

**修复方向**：改为调用适配器方法。

### 13. `run_model.finished_at` 异常时不设置
**位置**：`runner.py:226`

崩溃的 run 无结束时间戳，审计链断裂。

**修复方向**：在异常处理中补 `datetime.now().isoformat()`。

### 14. WebSocket 鉴权失败无 close code
**位置**：`consumers.py:20,25,28`

客户端收到裸 TCP 断开，无法区分原因。

**修复方向**：`self.close(code=4001)` 并附 reason。

## 🟢 P3：设计缺陷

### 15. DB 写入在设备释放之后
**位置**：`views.py:543`

吞吐优先于持久性——设备已释放、下一个任务已开始，但当前任务的结果可能尚未写入 DB。

### 16. `status` / `running` 双源字段
**位置**：`models.py:114`

两个字段独立管理会漂移，恢复逻辑需同时检查两者。

### 17. `TestRunRecord.started_at` / `finished_at` 是 CharField
**位置**：`models.py:49-50`

非 DateTimeField，无法在 DB 级别做日期过滤排序。

### 18. 状态机缺少 `running→queued` 和 `done→idle` 转换
**位置**：`state_machine.py:29-46`

设备故障后无法退回排队；已完成任务无法通过状态机重新执行。

### 19. 恢复不重建 `_active_runs` 内存状态
**位置**：`state_machine.py:221-295`

重启后 `list_active` 返回空但 DB 可能有运行中任务。

### 20. `_device_queue` 恢复无去重
**位置**：`apps.py:47-53`

`AppConfig.ready()` 反复调用可能重复入队。

### 21. `TestResult` 表 0 行数据
**位置**：`views.py:546-560` — `persist()`

`TestResult.objects.bulk_create(results)` 从未成功写入。根因待定位：`run_model.case_results` 空 或 `bulk_create` 静默失败。

### 22. `AllowedHostsOriginValidator` 导入未使用
**位置**：`asgi.py:10-17`

WebSocket 连接无来源校验。

### 23. `case_items` 聚合计算后被丢弃（无 TaskCard 时）
**位置**：`views.py:655-660`

### 24. `api.py:persist_results` 死代码且有 FK 类型错误
**位置**：`api.py:15-22`

`run_id` 传字符串而非整数 PK，如其被调用会直接失败。

### 25. 跨线程无同步访问 `state.is_running` / `log_lines`
**位置**：`runner.py:173,448`

依赖 CPython GIL 实现细节，PyPy/无 GIL Python 下不安全。
