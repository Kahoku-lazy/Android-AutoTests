策略选择:
  ├── 单文件小改（≤50 行）→ Edit 工具精确替换
  │     ├── 第 1 次 Edit 失败 → Read 原文件 10 行上下文

Dashboard 特定编码规则

前端 数据获取
✅ 正确
const stats = ref({...})
onMounted(async () => {
  const { data } = await fetchDashboardStats()
  if (data.ok) stats.value = mapStatsResponse(data.data)
})
❌ 错误
// 硬编码假数据
const stats = ref({
  devices: { online: 3, total: 5 }
})
前端 组件导入规范
✅ 正确
import { Card, Button } from 'animal-island-vue'
import { IconDevice } from '@/shared/icons'
import StatsCard from './components/StatsCard.vue'
❌ 错误
import { ElMessage } from 'element-plus'
// Dashboard 是纯动森模块
import client from '@/shared/api-client.js'
// 组件不直接 import client
后端 views.py 编写规范
✅ 正确
from models.constants import DeviceStatus
@csrf_exempt
def dashboard_stats(request):
    online = Device.objects.filter(
        status=DeviceStatus.ONLINE
    ).count()
    return JsonResponse({"ok": True, "data": {...}})
❌ 错误
// 硬编码状态字符串
Device.objects.filter(status="ONLINE")
// 违反防火墙 #1
from apps.test_runner.runner import _active_runs
// 缺少 ok 字段
return JsonResponse({"error": "..."})

4 代码 Review（自动触发）

Step 1：确认范围 git diff --name-only

列出所有变更文件，确认无遗漏、无多余

Step 2：判定规模

1 文件 ≤50 行 → 小改动 终端输出  |  2+ 文件 → 大改动 HTML 报告

Step 3：五维检查 FUNC · API · SEC · DATA · PERF

维度Dashboard 重点检查项
🔧 功能 FUNCstats 映射正确？新组件正确导入？图表数据格式匹配 props？
🔌 接口 API/api/dashboard/stats/ 响应不变？新参数不影响旧调用？
🔒 安全 SEC无硬编码密码/Key？api_key 不泄露到响应？聚合数据不暴露隐私？
📊 数据 DATA后端无假数据？前端无 ref([{...}])？异常时 loading 正确重置？
⚡ 性能 PERF无循环内 ORM 查询？dashboard_stats 响应 < 500ms？

cd frontend && npx vite build # → 0 errors

📋 实例演示

需求："仪表盘加一个最近执行用例列表，显示最近 5 条"

① 需求分析

"最近执行用例"→ 数据来源 tr_test_results 表。"最近 5 条"→ 限 5 条。需要新组件还是复用 TaskResultPanel？需要新 API 还是复用已有？

② 改动评估

已有 GET /api/dashboard/stats/ 含 recent_tasks。先读 views.py 的 _recent_tasks() 看是否满足。满足 → 纯前端改（1 文件，小改动）。不满足 → 前后端都改（3+ 文件，大改动，需 HTML 报告）。

③ 代码修改

后端 → 修改 _recent_tasks()。前端 → 在 index.vue 新增 section + 复用 TaskResultPanel 或新建组件。写完 → ruff format + prettier。

④ 代码 Review

编译：vite build + manage.py check。接口：curl 验证 recent_tasks 字段。功能：浏览器打开 /dashboard 确认显示。输出：小改动→终端；大改动→HTML 报告。
