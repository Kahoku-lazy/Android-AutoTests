继承平台 开发-平台级-代码Review规则.md，下列为 Dashboard 专属裁剪清单。改动本模块后强制过一遍。

标签含义处理

🟡 SHOULD强烈建议修复或书面记录理由

1.2 Dashboard 专属检查清单

A. 模块边界（防火墙）

#检查项通过标准等级
D1改动范围仅 apps/dashboard/ + frontend/src/modules/dashboard/（及必要的 config/urls.py include）🔴
D2禁止穿透私有态无 from apps.test_runner.runner import _active_runs；活跃运行走 test_runner.api🔴
D3跨 App 只读允许 from apps.X.models import Y + SELECT；禁止跨 App INSERT/UPDATE/DELETE🔴
D4禁止写库Dashboard 是只读聚合层，views 内无 create/update/delete🔴
D5无 DEPRECATED 双源不新增对 ai_assistant/dashboard_views.py 的依赖；改动只落新 App🟡

B. API 契约

#检查项通过标准等级
D6响应格式{"ok":true,"data":...} / {"ok":false,"error":"..."}🔴
D7四端点字段稳定不擅自改 /dashboard/stats|activities、/devices/stats、/cases/stats 的字段名🔴
D8URL 注册config/urls.py 使用 include('apps.dashboard.urls')，禁止散装 import 视图🔴
D9设备口径online/total 与设备列表一致：排除 OFFLINE/DISCONNECTED🔴

C. 前端边界

#检查项通过标准等级
D10经 api.js组件禁止直连 @/shared/api-client🔴
D11无硬编码统计KPI/趋势/任务数字只来自 API；禁止 ref([{假数据}])🔴
D12纯动森 UI禁止 Element Plus；用 animal-island-vue🔴
D13错误可见禁止空 catch {}；须复位 loading 并提示用户🔴
D14trend 语义若展示 %，后端必须给百分比；绝对值不得硬套 %🟡
D15无死代码新增不提交未挂载组件；清理未用 import🟡

D. 判定规则

无 🔴 且无 🟡 → ✅ APPROVED 无 🔴 但有 🟡 → 🔄 NEEDS_REVISION（或 APPROVED + 记录理由） 有 🔴 → 🔄 NEEDS_REVISION 方案根本错误 → ❌ REJECTED

② 代码质量分析流程与步骤

对齐 module-design 四阶段。产出物：开发-仪表盘-代码质量分析.html

2.1 总流程

① Inventory 梳理 → ② Partition 边界 → ③ Standardize 规范 → ④ Cleanup 行动 → 📄 HTML 报告

2.2 分步操作手册

Step 1 · Inventory（梳理）

  • 统计文件行数：wc -l apps/dashboard/* frontend/src/modules/dashboard/**/*
  • 列组件挂载表：index.vue import 了哪些；哪些未引用（死代码）
  • 扫跨模块依赖：rg "from apps\\." apps/dashboard/ · 标出 models vs service/runner
  • 确认 urls：是否 include('apps.dashboard.urls')
  • 对照 DEPRECATED：ai_assistant/dashboard_views.py 是否仍被引用

Step 2 · Partition（边界）

  • 画依赖图：Dashboard → 六业务 Model（只读）是否单向
  • 检查破口：是否 import runner._active_runs / 其他 App service
  • 检查路径归属：/api/devices/stats、/api/cases/stats 是否错位
  • 确认无自有表、无写操作

Step 3 · Standardize（规范）

  • 对照 §1 Review 清单 D1–D15 逐项打 ✅/🔴/🟡
  • 前端：api.js 封装、无 Element Plus、无硬编码 KPI、catch 有提示
  • 后端：{ok,data}、设备口径、无假曲线 [1]*12、trend 语义
  • 复杂度：标出 >80 行函数、N+1 循环查询、index.vue 职责过重

Step 4 · Cleanup（行动计划）

  • 按 P0→P1→P2 排序修复项，写进报告「行动计划」时间线
  • 与上一版报告做「仍在 / 已修 / 新增」对比表
  • 输出 HTML 覆盖 开发-仪表盘-代码质量分析.html（禁止只 copy 旧文件）

报告必含章节

章节内容
概览 KPI组件数、views 行数、P0/P1/P2、合规数
四阶段正文Inventory / Partition / Standardize / Cleanup
问题清单每条：标题、位置、证据、修复建议
复杂度表文件/函数、行数、风险
对比表相对上次扫描的变化

③ 仪表盘报错诊断手册

平台通用项见 开发-平台级-报错诊断手册.md。以下为 Dashboard 高频症状速查。

3.1 诊断流程

Step 0 用关键词匹配下方速查表 → 命中则按「原因/排查/修复」执行 Step 1 未命中 → 看浏览器 Network：/api/dashboard/stats|activities 状态码与 body Step 2 看 Console：Vue 报错 / CORS / 401 Step 3 看 Django 日志：logs/backend*.log 堆栈 Step 4 对照防火墙：是否 _active_runs 静默 except 导致「无运行中任务」 Step 5 修复后归档到本手册（新增条目）

3.2 症状速查

KPI 全 0 / 页面空白数字

可能原因：未登录 401；API 500；前端 catch 静默；Vite proxy 未指向 :8765

  • Network 看 GET /api/dashboard/stats/ 是否 200 且 ok:true
  • 无 Token → 先登录；401 → 刷新 token
  • 500 → 读后端堆栈（常见：ORM 表不存在 / 迁移未跑）

有设备但「在线设备」为 0

可能原因：设备全是 OFFLINE/DISCONNECTED（被口径排除）；ADB 未连

  • 打开设备管理页对比可见列表
  • adb devices 确认 ONLINE
  • 核对 _device_dashboard_stats 过滤逻辑

运行中任务不显示 / KPI 无红点

可能原因：_active_runs import 失败被 except: pass 吞掉；或 selected_cases 格式不一致导致 TypeError

  • 后端临时打日志确认 _recent_tasks 活跃分支是否进入
  • 长期修复：改走 test_runner.api 公开快照，去掉静默 except

趋势图空白 / 页面报错

可能原因：charts.execution 缺字段；空数组未兜底

  • 确认响应含 labels/success/failed/new_cases
  • 前端应对空 chart 不抛错（AC-06）

趋势旁「xx%」数字离谱

可能原因：后端 trend 是绝对计数，StatsCard 硬编码 %

  • 属已知语义 Bug（质量分析 P1）
  • 修：统一单位或增加 trendUnit

刷新无反应 / 一直转圈

可能原因：refreshing 未在 finally 复位；请求挂起

  • 检查 refreshData 的 try/finally
  • Network 看请求是否 pending

401 / 跳登录

可能原因：JWT 过期；中间件拦截

  • 重新登录；确认 api-client 刷新逻辑
  • 平台级手册 §三 API 错误

stats 接口极慢（>2s）

可能原因：日循环 N+1（估 80+ 查询）

  • 用 Django Debug Toolbar / 日志数查询
  • 改为 TruncDate 一次聚合；_recent_tasks 用 in_bulk

④ 模块功能验收流程与标准

对齐子 PRD-07 AC + functional-testing 五维模型。命令：python tests/functional/dashboard/run_tests.py

4.1 验收流程

1. 对照 PRD → 2. Code Review → 3. 编译检查 → 4. 五维测试 → 5. 浏览器验收 → 6. 出报告
步骤动作通过门禁
1读 子PRD-07-dashboard.md + 全功能 HTML 规格改动在 F-01～F-05 范围内
2执行本章 §1 Review 清单无 🔴
3python manage.py check · 前端 npx vite build无错误
4run_tests.py（FUNC/API/SEC/DATA/PERF）相关用例 PASS
5浏览器打开 /dashboard 走 AC-01～07人工勾选全部 ✅
6更新 测试-仪表盘-测试报告.html结论可提交 / 列遗留

4.2 验收标准（AC）

ID场景期望维度
AC-01已登录访问 / 或 /dashboard进入仪表盘；KPI 有真实数据或合法空态FUNC
AC-02断网 / API 失败有错误提示；页面结构仍在FUNC · API
AC-03仅 OFFLINE 设备设备 total 与设备页可见口径一致FUNC · DATA
AC-04点击快捷操作五条路由跳转正确FUNC
AC-05依赖检查无跨 App import service / _active_runsSEC · 架构
AC-06趋势空库柱状图不抛错；任务/活动空态文案可见FUNC · DATA
AC-07有运行中任务KPI 红点 + 列表含 runningFUNC

功能点对照（F-01～F-05）

功能验收要点
F-01 KPI四卡来自 API；skeleton→数字；刷新按钮可用
F-02 趋势近 12 日三色柱；labels 对齐
F-03 任务摘要筹码 + ≤8 条；空态文案
F-04 活动activities 列表或空态
F-05 导航快捷 5 按钮 + 模块 Bento 可点

4.3 五维最低覆盖

变更类型最少维度建议用例数
改 stats APIFUNC + API + SEC + DATA≥4
改前端展示FUNC + PERF≥3
修防火墙 / 活跃任务FUNC + SEC + API≥3（含回归）
Bug 修复FUNC + 复现用例≥2

性能参考：stats 平均 <500ms、最大 <1000ms（现网 N+1 可能不达标，记为已知债）。

4.4 浏览器人工勾选单

  • 登录后默认进入仪表盘
  • 四张 KPI 有数字（或全 0 空态不崩）
  • 趋势图可见三色柱或空态
  • 任务面板摘要 + 列表 / 空态文案
  • 快捷操作五条跳转正确
  • 模块导航可进入各业务页
  • 活动时间线有数据或空态
  • Footer 显示更新时间与系统状态
  • 断网或停后端时有错误提示（AC-02）
  • 点刷新后数字更新且按钮复位
