> 格式：`case_info/steps/test_data/validation`（多接口多步骤）
> 端点文档：`dev_docs/02-PRD需求/API-00-认证.md`
> 执行器：`apps/test_runner/executors/api/executor_v2.py` → `_execute_row()`

---

## 用例信息

| 字段 | 值 |
|------|-----|
| ID | `API-AUTH-FLOW-001` |
| 标题 | 认证全流程 — 注册→查Me→刷新Token→登出 |
| 描述 | 验证完整用户认证生命周期：注册获取 token → 携带 token 查当前用户 → 用 refresh_token 刷新 → 登出作废 token |
| 前置条件 | 平台 API 已启动；该用户名此前未被注册 |

---

## 步骤定义 (4 步)

```
Step 1: POST /api/ai/auth/register   → 注册新用户，获取 access_token + refresh_token
  │ extract: $.access_token → {{token}}
  │ extract: $.refresh_token → {{refresh}}
  ▼
Step 2: GET /api/ai/auth/me          → 携带 {{token}} 查当前用户身份
  │ Authorization: Bearer {{token}}
  │ assert: user.username 正确
  ▼
Step 3: POST /api/ai/auth/refresh    → 用 {{refresh}} 换新 access_token
  │ body: { refresh_token: "{{refresh}}" }
  │ extract: $.access_token → {{new_token}}
  ▼
Step 4: POST /api/ai/auth/logout     → 携带 {{new_token}} 登出作废
  │ Authorization: Bearer {{new_token}}
  │ assert: 200 OK
```

---

## 变量流转表

| 变量名 | 来源 | 提取路径 | 消费步骤 |
|--------|------|----------|----------|
| `{{token}}` | Step 1 响应 | `$.access_token` | Step 2 (header) |
| `{{refresh}}` | Step 1 响应 | `$.refresh_token` | Step 3 (body) |
| `{{new_token}}` | Step 3 响应 | `$.access_token` | Step 4 (header) |

```

  ├── 检测 config_json 有 "case_info" + "steps" → 多步骤格式
  ├── test_data 有 2 行 → 数据驱动模式
  │

  │   ├── Step 1: POST /register  → 200 ✓ → extract token, refresh
  │   ├── Step 2: GET /me          → 200 ✓ (Authorization: Bearer {{token}})
  │   ├── Step 3: POST /refresh    → 200 ✓ → extract new_token
  │   └── Step 4: POST /logout     → 200 ✓ (Authorization: Bearer {{new_token}})
  │
  ├── Row 2: {username: "bob_test", password: "bob456", email: "bob@test.com"}
  │   └── (同上 4 步)
  │
  └── 2/2 rows pass → 返回 "pass"
```

## 断言覆盖

| 步骤 | 状态码 | body_schema |
|------|:--:|------|
| 注册 | 200 | `status=true`, `access_token`/`refresh_token` 为 string, `user` 含 id+username+email |
| 查Me | 200 | `status=true`, `user` 含 id+username |
| 刷新 | 200 | `status=true`, `access_token` 为 string |
| 登出 | 200 | `status=true` |

---

## 注意事项

1. **幂等性**：注册步骤创建真实用户（写入 DB），重复执行会因用户名已存在而返回 409。执行前需确认用户名未被占用，或每次执行后手动清理。
2. **Redis 依赖**：登出步骤依赖 Redis 存储 token 黑名单。若 Redis 不可用，Step 4 返回 503 而非 200。
3. **变量优先级**：`test_data[].input` 中的值优先于 extract 变量。本例中变量名无冲突（`token`/`refresh`/`new_token` vs `username`/`password`/`email`），不会覆盖。
4. **Step 4 必失败场景**：若 Step 3 返回的 `new_token` 不是有效的 access_token，Step 4 返回 401。执行器会在 Step 4 停止并标记该行 fail。
