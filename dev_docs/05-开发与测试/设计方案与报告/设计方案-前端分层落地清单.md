> 依据：`frontend/AGENTS.md` §1.1 分层与模块边界
> 状态：待执行（按优先级从设备管理模块开始逐一解决）

## 一、背景与判定标准

前端总原则（`frontend/AGENTS.md` 顶部）：**前端只显示状态，读写数据，不执行逻辑。**

分层纪律（§1.1）：

| 层 | 允许 | 违规信号 |
|----|------|---------|
| `.vue` 展示层 | 渲染 / v-model / emit / testid | 直接 import + 调用 api、组件内写业务 computed / 状态分类 |
| `*.logic.ts` 编排 | 组合 composable、提交前校验、清表单 | 直连 HTTP |
| 流程 composable | API → 副作用 → 跳转 | 表单校验、弹校验 toast |
| 校验 composable | `errors` / `canSubmit` | 发请求 |
| 模块 api | 唯一 HTTP 出口 | 组件绕开它直连 |

**全局硬约束已验证 ✅**

- 全前端无裸 `fetch()`、无 `client.get/post`（`.vue` 内 0 处）；
- `axios` 只在 `shared/api-client.ts` 出现；
- 无 `adb` / `uiautomator2` / `airtest` 直连（唯一命中为注释）。

## 三、分模块违规点与改造动作

### P0 — test-runner（最严重，优先改造）

**违规点**

1. `test-runner/index.vue`（**900 行**）与 `components/TaskDetail.vue`（**830 行**）是巨石组件。
2. `index.vue:38` 直接 `import { startRun, stopRun, getActiveRuns, listTasks, ... } from "./api"`，并在组件内直接发请求：
   - `await listTasks()`（:76）
   - `await startRun(body)`（:363）
   - `await getActiveRuns()`（:531）
   - `await listDefinitions()`（:613）
3. 组件内写业务分类逻辑：`kpiStats` / `groupedTasks` / `filteredTasks` 三个 computed（:51-53）直接调 `deriveTaskStatus` / `taskBucket` / `isTaskQueued` 做状态分类；模板里（:710、:742）也直接调 `deriveTaskStatus`。
4. 文档不一致：`frontend/AGENTS.md` 写「`deriveTaskStatus` 已删」，但 `composables/taskUtils.ts:35` 仍有兼容壳，且被大量调用。

**改造动作**

- 拆 `index.vue`：抽 `TestRunnerView.logic.ts`（编排）+ `useTestRunnerState.ts`（数据读写）+ `useTaskFilter.ts`（筛选/分组），组件只留模板渲染与 emit。
- 把状态分类从组件收敛进 composable，消费后端权威 `state` / `outcome` 字段（`taskUtils.ts` 已具备字段读取，只做「下沉调用位置」而非「新增推导」）。
- 删 `deriveTaskStatus` 兼容壳，调用点统一改 `resolveTaskState`（或直接 `task.state`），同步更新 `frontend/AGENTS.md` 与 `test-runner/AGENTS.md` 口径。

- `components/ui/UiCaseList.vue`、`components/storage/StorageCaseList.vue` / `StorageCaseEditor.vue`

- `components/CaseCard.vue`（`caseLock/caseUnlock`）、`components/StepEditor.vue`（`fetchStepTypes`）、`components/WatcherPanel.vue`（`listPages/getPageElements`）

**改造动作**

- 每个编辑器/列表抽 `useXxx` 流程 composable（或复用现有 `composables/`），组件经 composable 读数据、经 emit 触发动作。
- 保留 `api.ts` facade 不动，改动只在「调用点从组件上移到 composable」。

## 五、验收口径（每模块改造后）

- 组件零 api import / 零 HTTP 调用；数据读写在 composable，编排在 logic.ts。
- 组件内无业务状态推导；状态/结局消费后端权威字段（`state` / `status` / `outcome`）。
- 跨模块读取走本模块 `api.ts` 封装，无 `@/modules/xxx/api` 直接 import。
- `diff` 每行可追溯到本清单对应违规点；真实页面验证通过。
