# 报告页趋势图横向滚动失效（Chart.js + CSS Grid）

> 状态：✅ 已修复 · 日期：2026-07-13 · 模块：前端 · 页面：测试报告 `report-generator/index.vue`

---

## 现象

- 图表范围选「一月」（30 天）后，**无法左右滑动**查看上周/更早数据
- DevTools 中 `#overviewPassRateCanvas` 的 `style.width` 与滚动容器 `#chartScrollPass` 的 `clientWidth` 相同（约 539px），`scrollWidth === clientWidth`
- 修复第一轮后，卡片 `.chart-card` 被撑到 **3285px** 宽，整页横向溢出，仍不符合「固定显示 5 天、滑动浏览全量」的需求

---

## 预期行为

| 项 | 说明 |
|----|------|
| 可视窗口 | 卡片宽度 ≈ 半屏，一次只显示 **5 天** |
| 全量数据 | 一月 30 天、一季 90 天的 canvas 在 **内部** 横向展开 |
| 默认位置 | 加载后滚到**最右侧**（最近 5 天） |
| 查看历史 | 在图表区域**向左滑**（或拖动横向滚动条）查看更早日期 |

## 问题原因

### 1. Chart.js `responsive: true` 把 canvas 缩回视口（主因 · 无法滚动）

```js
// ❌ 原写法
options: { responsive: true, maintainAspectRatio: false }
```

即使 JS 给 `#chartInnerPass` 设置了 `width: 30 * dayWidth`，Chart.js 仍按**父容器可见宽度**重算 canvas 尺寸，导致 `scrollWidth === clientWidth`，横向滚动条不出现。

### 2. CSS `canvas { width: 100% !important }` 二次压扁

`.chart-wrap canvas` 强制 100% 宽度，与显式像素宽冲突。

### 3. CSS Grid `min-width: auto` 撑破卡片（主因 · 卡片过长）

Grid 子项默认 `min-width: auto`，会按**内容最小宽度**（30 天 canvas ≈ 3285px）撑开 `.chart-card`，而不是把溢出交给 `.chart-scroll` 滚动。

```css
/* ❌ 原写法 */
.chart-row { grid-template-columns: 1fr 1fr; }
.chart-card :deep(.animal-card__content) { overflow: visible; }
```

## 修复内容

### JS：固定 canvas 总宽 + 关闭 Chart.js 响应式

```js
const CHART_VISIBLE_DAYS = 5

function getChartDayWidth(scrollEl) {
  return scrollEl.clientWidth / CHART_VISIBLE_DAYS
}

function getChartMetrics() {
  const n = trend.value.labels.length
  const dayW = getChartDayWidth(document.getElementById('chartScrollPass'))
  return { n, dayW, totalW: Math.round(n * dayW), height: 200 }
}

function prepareChartCanvas(canvas, metrics) {
  const dpr = window.devicePixelRatio || 1
  canvas.style.width = `${metrics.totalW}px`
  canvas.style.height = `${metrics.height}px`
  canvas.width = Math.round(metrics.totalW * dpr)
  canvas.height = Math.round(metrics.height * dpr)
  canvas.getContext('2d')?.setTransform(dpr, 0, 0, dpr, 0, 0)
}

// Chart options
{ responsive: false, maintainAspectRatio: false }
```

`applyChartInnerWidths()` 同步设置 `#chartInnerPass` / `#chartInnerDaily` 及内部 `.chart-wrap` 的显式像素宽；双 `requestAnimationFrame` 后再测量 `clientWidth`，避免布局未稳定时算错 `dayWidth`。

### CSS：卡片限宽 + 仅内部滚动

```css
.chart-row {
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);
  min-width: 0;
}
.chart-card {
  min-width: 0;
  max-width: 100%;
  overflow: hidden;
}
.chart-card :deep(.animal-card__content) {
  overflow: hidden;
  min-width: 0;
}
.chart-scroll {
  width: 100%;
  max-width: 100%;
  min-width: 0;
  overflow-x: auto;
}
.chart-inner { flex-shrink: 0; }
/* 移除 canvas { width: 100% !important } */
```

## 排查 SOP

1. 选「一月」后检查 `#chartScrollPass`：`scrollWidth` 应 **>** `clientWidth`（约 6 倍）
2. 若 `scrollWidth === clientWidth` → 查 Chart.js 是否 `responsive: true` 或 canvas 被 CSS 压成 100%
3. 若 `.chart-card` 宽度等于 30 天总宽 → 查 Grid 子项是否缺 `min-width: 0` / `minmax(0, 1fr)`
4. 默认在最右侧是预期；要看上周需**向左滑**，不是向右
