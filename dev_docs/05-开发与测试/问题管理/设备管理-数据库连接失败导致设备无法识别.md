# 设备管理模块 — 数据库连接失败导致设备无法识别

> 状态：🟢 已修复 · 日期：2026-07-17 · 模块：device_pool · 范围：run.py / settings.py / device_views.py

---

## 问题现象

设备管理模块（前端 http://localhost:5173）无法识别 ADB 已连接的设备，界面显示空白。

---

## 根因分析

### 🔴 根因 1：`run.py` BASE_ENV 硬编码 `DB_USER=root` 覆盖 `.env` 配置

**文件**：`run.py:40`

```python
BASE_ENV = {
    ...
    "DB_USER": "root",  # ← 硬编码，覆盖 .env 的 DB_USER=autotests
    ...
}
```

**链路**：
```
run.py start → make_env() → env.setdefault("DB_USER", "root")
    → 子进程 os.environ 已有 DB_USER=root
    → settings.py _load_dotenv() 检查 DB_USER 已在 os.environ → 跳过 .env 的 DB_USER=autotests
    → .env 的 DB_PASSWORD=autotests2026 正常加载（BASE_ENV 未包含）
    → Django 连接: root / autotests2026 → MySQL Access Denied (1045)
    → 所有 API 返回 HTTP 500 + HTML 错误页
    → 前端收到 HTML 而非 JSON → 表现"没反应"
```

**修复**：从 `BASE_ENV` 移除 `DB_USER`，让 `.env` 全权控制数据库凭据。

### 🟡 根因 2：`device_views.py` 缺少 import

数据库连接恢复后暴露了代码 bug：`device_views.py` 使用了 `_check_timeout_queue()`、`_adb_device_serials()`、`device_pool`、`DeviceQueue`、`datetime` 但未导入。

**修复**：补充缺失的 import：
```python
from .helpers import ..., _check_timeout_queue, _adb_device_serials
from ..models import Device, DeviceQueue
from ..pool import device as device_pool
from datetime import datetime
```

## 教训

1. **`run.py` BASE_ENV 不应包含凭据类环境变量**（DB_USER / DB_PASSWORD）。这些属于 `.env` 管理范畴，硬编码在启动脚本中会导致 `.env` 配置被静默覆盖。
2. **`_load_dotenv()` 的 `key not in os.environ` 守卫语义**：子进程继承父进程环境变量时，`.env` 配置可能被跳过。应确保 `BASE_ENV` 与 `.env` 不冲突。
3. **数据库连接失败时 Django 返回 HTML 错误页**，前端静默失败无提示。应考虑在 API 层添加全局异常处理，将数据库错误转为 JSON 响应。
