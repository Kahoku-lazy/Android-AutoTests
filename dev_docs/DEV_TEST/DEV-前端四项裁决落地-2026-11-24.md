## 二、逐单改动

### 1）BUG 错误内容标签加粗（skip_specs）

- `BugDetailDrawer.vue`：`<pre>` → `<div class="bug-detail__body">` + 逐行 `<p class="bug-detail__line">`，行首标签包 `<strong class="bug-detail__line-key">`；`errorLines` 由 `computed` 调 `splitErrorDetail` 得出（组件内不写解析，符合规格）。
- 新增 `tests/bug-manager/p0/bug-detail-error-lines.spec.ts`（4 条）：行拆分与加粗单元、无标签行整行正文、缩进保留前导空白、空文本占位。
- **只改「无失败快照 → 退回原文」这一支**；有快照时仍显示四问，不渲染该段。
- 容器类名未变，故底色 / 描边 / 4px 硬影 / `max-height` 全部沿用原声明。

### 2）SplitHandle 口径（skip_specs，零代码）

- `page-layout.md`：「由用例管理工作台确立」→「一套**可选**分栏版式，当前无页面采用（用例管理工作台现为用例表 `ProjectSheet`）」。
- 「左栏可拖动」行：`MUST 有 SplitHandle` → **若采用可拖动分栏，MUST 使用**；若左栏固定宽不拖动，则 MUST NOT 渲染手柄。交互细则（夹取范围、键盘步进、双击复位、按模块记忆、窄屏不渲染、不得另画分隔线）逐字保留。
- `SplitHandle.vue` **未改动**，仍零引用；`standalone-html.md` 的「照抄 SplitHandle.vue」指引保留（它是交互规格来源）。
- 组件保留的理由已写进 design D3：判死需要「零引用 + 无规格/技能点名」同时成立；改为条件式后它仍是「采用分栏时的唯一实现」，属零件库存。

### 3）退已任务详情页（**spec delta**）

- `openspec/specs/ai-task-list` 的「Task list card content and actions」改为：任务卡 **MUST NOT** 提供详情入口、**MUST NOT** 跳 `/tasks/:id`，与 `dashboard-agent-tasks` 的「已下线」口径对齐。3 个场景名全部保留。
- 删除 `helpers/task-detail.ts`（362 行）、3 个 `STEP_LOG_CHECK_*` 常量、2 个用例文件、`shared/helpers/mediaUrl.ts` 及其用例。
- 新增 `helpers/task-card.ts`，承接仍在用的 `formatTaskCost` / `formatTaskDuration`（逻辑一字未改）；`TaskBoard.vue` 改 import。
- 同步 `.agents/docs/frontend/task_list/task_list_redlines_and_verify.md` 的真相源路径（`task-detail.ts` → `task-card.ts`）。
- **刻意保留**：`shared/types/ai.ts` 的 `TaskDetail*` / `TaskRun*`（既有接口 DTO，渲染层不消费不等于接口下线）。

### 4）退役 DoodleNote（**spec delta**）

- `openspec/specs/frontend-l4-data-surface` 的零件枚举收为 `AppCard` / `KpiCard` / `SketchCard`；两个场景逐字保留。
- 删除 `DoodleNote.vue` 与其用例；`DoodleBtn` 未动（仍 34 处引用）。
- 同步 `doodle-craft` 12 处提及（`SKILL.md` 4 处、`cards.md` 3 处含整节删除与小节重编号、`decorative.md`、`known-gaps.md`、`tokens.md`、`standalone-html.md`、`assistant-marker-card.md`）。技能内 `DoodleNote` 残留 **0**。
