## 二、根因

pytest 的 conftest 只对**自身目录及子目录**生效。目录重组（`3d39e44d test(layout): 补齐按模块重组后的测试，修复搬迁遗留`）把用例铺到
`tests/<模块>/api|e2e/` 之后，`tests/api/conftest.py`、`tests/e2e/conftest.py` 留在原地，而这两个目录里**已经没有任何用例**：

```
tests/api/conftest.py   → api_session / unique_username / admin_login / auth_session
tests/e2e/conftest.py   → frontend_url / e2e_services / e2e_account / login_page / steps / …
tests/auth/api/*        → 看不到，fixture not found（38 条）
tests/device/api/*      → 看不到（9 条）
tests/auth/e2e/*        → 看不到（15 条）
```

连带失效：`tests/e2e/conftest.py` 的两个 hook（失败截图、步骤报告）也只在空目录生效，
**模块 e2e 用例的留痕能力等于零，而且不报错**。CI 只跑 `pytest-collect`，所以一直没被拦住。

## 三、改法

| 动作 | 文件 |
|---|---|
| 4 个 api 夹具 + 8 个 e2e 夹具上提 | `tests/conftest.py`（+约 90 行） |
| 2 个 hook 上提（失败截图 / 步骤报告） | 同上 |
| 删除原目录级 conftest | `tests/api/conftest.py`、`tests/e2e/conftest.py`（保留 `tests/e2e/{selectors,step_report}.py`） |
| 同步守卫样本路径 | `tests/arch/unit/test_api_path_callers.py`：`tests/api/conftest.py` → `tests/conftest.py`（断言逻辑与扫描器未改） |

hook 上提后对全仓生效，但两者都自带守卫，非 e2e 用例等价无操作：

- `pytest_runtest_makereport`：`item.funcargs.get("steps")` / `get("page")` 为空时直接 return
- `pytest_sessionfinish`：`report.cases` 为空时直接 return

模块级 conftest（`tests/device/integration/`、`tests/ops_console/api/`）保持不动——它们只在各自子树用，
且两处都定义了 `admin_user`，上提会撞名。

## 四、唯一一条「转正」的失败

```
tests/auth/api/test_auth_tokens.py::test_auth_tokens_authenticated[TC-ME-001 me-success]
jsonschema: Additional properties are not allowed ('is_assistant_author', 'is_operator' were unexpected)
```

`/api/auth/me/` 现在返回 `is_operator` / `is_assistant_author`，而 `tests/api_kit` 的响应 schema 仍只允许
`id / username / is_superuser`。这是 `grant-operator-role`、`assistant-author` 两笔已归档变更带来的接口演进，
**schema 没跟上**——与夹具无关，未在本单修。

## 五、环境备注（下次会踩）

- 本机 `%LOCALAPPDATA%\ms-playwright` 只有 1228/1234，而 Python playwright 要 `chromium_headless_shell-1255`，
  且该目录 ACL 拒绝写入（`EPERM mkdir __dirlock`）。
