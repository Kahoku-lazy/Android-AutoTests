# H6810 卡片页：卡片样式切换与状态判定逻辑

> 适用范围：设备列表页（卡片页）上「长按卡片 → 切换卡片样式（经典 / 灵动）」这一段交互。
> 用途：① 统一**测试点编写**口径；② 作为**规划输入上下文**（第 6 节，可直接喂给规划模型）；③ 作为**验收标准**（第 5 节）。
> 证据来源：`screen.png`、`screen-01.png`（长按后的样式选择模式）、`screen-02.png`、`screen-03.png`（保存后的列表页）。

## 1. 三种界面状态

整段交互只涉及**同一页**（设备列表页）的三种状态，**不发生页面跳转**。

| | S0 列表页（普通态） | S1 样式选择模式（长按卡片后） | S2 保存后（回到列表页） |
| --- | --- | --- | --- |
| 页头第一行 | 标题「设备」＋右侧功能图标 | **左 ✕（取消）· 中「灵动 \| 经典」分段 · 右 ✓（保存）** | 恢复为标题「设备」＋右侧功能图标 |
| 附加行 | 无 | **「卡片大小同步应用到同类设备」＋复选圈** | 无 |
| 卡片区 | 按当前样式展示的卡片网格 | 卡片网格仍在 | 卡片已按所选样式展示 |
| 标签/搜索行 | 「全部 / AI 设备」＋搜索＋更多 | 同左（不变） | 同左（不变） |

**要点**：S1 是"**同一页顶部换了一条栏**"，不是弹窗、不是新页面、也没有遮罩。

## 2. 核心判定逻辑：保存没有反馈，靠结构特征判断

保存（点右上角 ✓）后**没有可依赖的保存结果反馈**，因此判定一律走结构特征，禁止写成"提示保存成功"之类的断言。

**判定「已保存、已回到列表页」= 同时满足两条结构特征：**

1. **顶部样式栏消失**：✕ / 「灵动 \| 经典」分段 / ✓ 这一行不再存在，页头恢复为标题「设备」＋右侧功能图标；「卡片大小同步应用到同类设备」行同时消失；
2. **卡片样式已变化**：目标卡片呈现目标样式的特征布局（见第 3 节）。

只看第 1 条分不清"还在 S1"与"保存了但样式没生效"，所以两条必须一起判。

> 说明：截图中曾出现过「保存成功」toast，但该反馈**不作为判定依据**（是否出现、出现时机都不稳定）。

## 3. 两种卡片样式的可判定特征

| 特征 | 经典样式 | 灵动样式 |
| --- | --- | --- |
| 名称位置 | 卡片中部，**在设备图右侧同一行** | **卡片左上角**，独占一行 |
| 设备图位置 | 中部偏左 | **名称下方**（卡片下半部） |
| 开关控件 | **「ON ｜ OFF」文字分段控件**（卡片下半部，左右两个半边） | **右下角圆形电源按钮**（无文字） |
| 开关状态怎么读 | **不用页面表现判定**：开关是否成功一律由设备日志断言（见第 5 节） | 同左 |
| 未连接时的表现 | 右上角**红色 WiFi 斜杠图标** | 名称下方**「设备离线」**文字 |

## 4. 连接状态与 WiFi / 蓝牙图标

| 场景 | 表现 |
| --- | --- |
| 已连接（在线） | 卡片**右上角**同时出现**蓝色蓝牙图标 + 蓝色 WiFi 图标** |
| 未连接（经典样式） | 右上角出现**红色 WiFi 斜杠图标** |
| 未连接（灵动样式） | 名称下方显示**「设备离线」** |

**关键前提与顺序**：图标**只在设备 WiFi 与蓝牙连接成功之后**才出现；因此任何依赖图标的检查，前面**必须有一个"等待连接成功"的步骤**，且测试前置为"设备已配网且在线"。

## 5. 验收标准：正确步骤与断言

判定口径分两类：**可机械判**（关键词/结构可自动核对）与**需人判／需视觉确认**（要看截图表现，无法只靠文字判）。全部 **可机械判**项通过 = 通过；需人判项作为复核项列出，不作为自动判定依据。

### 5.1 经典页面功能测试

| # | 动作（要求） | 断言（要求） | 判定方式 |
| --- | --- | --- | --- |
| 1 | 启动 govee 应用 | 前台为 govee，进入 APP 主页 | 可机械判：动作含「启动」+「govee」；断言含「主页」 |
| 2 | 在 APP 主页点「设备主页入口」 | 进入设备列表页，可见 H6810 卡片 | 可机械判：动作含「设备主页入口」；断言含「设备」 |
| 3 | 长按 H6810 卡片 | 页头第一行变为 ✕ / 「灵动 \| 经典」/ ✓，并出现「卡片大小同步应用到同类设备」行 | 可机械判：动作含「长按」+「H6810」；断言同时含「灵动」与「经典」 |
| 4 | 点分段控件「经典」（右半） | 「经典」呈选中态 | 可机械判：动作含「经典」；断言含「选中」 |
| 5 | 点右上角 ✓ | **样式栏消失、页头恢复标题「设备」**；且卡片变为经典布局（名称在图片右侧同行、出现 ON ｜ OFF 分段） | 可机械判：动作含「✓/勾/右上角」；断言含「经典」**且**含「消失/恢复」（二者之一） |
| 6 | 等待连接成功 | 卡片右上角出现蓝色蓝牙与 WiFi 图标 | 可机械判：动作为等待/连接类；断言含「蓝牙」+「WiFi/WIFI」 |
| 7 | 点 ON ｜ OFF 的 ON 半边 | **设备日志返回开关成功（开灯事件）** | 可机械判：`log_check=true` 必判；断言须含日志语义，且**不得**含页面状态语义（选中态 / 颜色） |
| 8 | 点 ON ｜ OFF 的 OFF 半边 | **设备日志返回开关成功（关灯事件）** | 同上 |

### 5.2 灵动页面功能测试

| # | 动作（要求） | 断言（要求） | 判定方式 |
| --- | --- | --- | --- |
| 1 | 启动 govee 应用 | 前台为 govee，进入 APP 主页 | 可机械判：动作含「启动」+「govee」；断言含「主页」 |
| 2 | 在 APP 主页点「设备主页入口」 | 进入设备列表页，可见 H6810 卡片 | 可机械判：动作含「设备主页入口」；断言含「设备」 |
| 3 | 长按 H6810 卡片 | 页头第一行变为 ✕ / 「灵动 \| 经典」/ ✓，并出现同步行 | 可机械判：动作含「长按」+「H6810」；断言同时含「灵动」与「经典」 |
| 4 | 点分段控件「灵动」（左半） | 「灵动」呈选中态 | 可机械判：动作含「灵动」；断言含「选中」 |
| 5 | 点右上角 ✓ | **样式栏消失、页头恢复标题「设备」**；且卡片变为灵动布局（名称在左上、图在下方、右下角圆形电源按钮） | 可机械判：动作含「✓/勾/右上角」；断言含「灵动」**且**含「消失/恢复」（二者之一） |
| 6 | 等待连接成功 | 卡片右上角出现蓝色蓝牙与 WiFi 图标 | 可机械判：动作为等待/连接类；断言含「蓝牙」+「WiFi/WIFI」 |
| 7 | 点右下角圆形电源按钮 | **设备日志返回开关成功（开灯事件）** | 可机械判：动作含「电源 / 圆形 / 右下角」；`log_check=true` 必判；断言不得含页面状态语义 |
| 8 | 再点该按钮 | **设备日志返回开关成功（关灯事件）** | 同上 |

**两条用例都必须满足的通用约束**：

- 不得出现"弹窗 / 菜单 / 保存按钮 / 提示保存成功"这类与真实界面不符的表述；
- **开关结果只允许用设备日志断言**：断言必须写成"日志返回开关成功／开灯 / 关灯事件"，**不得**用页面表现（ON/OFF 半边选中态、按钮颜色由灰变蓝等）作为断言依据；页面表现只能用于**找到并点击**控件；
- 检查蓝牙与 WiFi 图标的步骤**必须在其前面出现"等待连接成功"**；
- 经典与灵动**不得混用开关措辞**（经典＝ON ｜ OFF 文字分段；灵动＝圆形电源按钮 + 颜色）。

## 6. 页面状态上下文（可直接作为规划输入）

> 本节与用例输入中的上下文保持一致（规范文本以用例输入为准）。规划时把本节与测试点**一并**作为需求上下文提供。

```
【界面状态说明 · 设备列表页（卡片页）】

一、整段交互发生在同一页，不会跳转页面
- 普通态（S0）：页头第一行是标题「设备」＋右侧功能图标；其下是「全部 / AI 设备」标签行与设备卡片网格。
- 样式选择模式（S1）：长按任意设备卡片后，**同一页顶部换了一条栏**（不是弹窗、不是新页面、没有遮罩）：
  第一行变为「左 ✕ 取消 · 中间「灵动 | 经典」分段切换 · 右 ✓ 保存」，
  下方多出一行「卡片大小同步应用到同类设备」＋复选圈，卡片网格仍在。
- 保存后（S2）：**没有任何保存结果提示**。判断"已保存、已回到普通态"的唯一依据是：
  ① 顶部那一行恢复为标题「设备」＋右侧功能图标（✕ / 分段 / ✓ 与同步行全部消失）；
  ② 目标卡片已变成所选样式的布局。

二、经典样式的卡片（经典页面）状态
- 布局：设备图靠左，设备名称在图的右侧同一行；卡片下半部是「ON ｜ OFF」文字分段开关。
- 开关：点「ON」半边＝开，点「OFF」半边＝关；**开关是否成功只允许由设备日志断言判定**，不得用页面表现（选中态、颜色）判断。
- 连接：设备 WiFi 与蓝牙连接成功后，卡片**右上角**出现蓝色蓝牙图标＋蓝色 WiFi 图标；
  未连接时，卡片右上角显示**红色 WiFi 斜杠图标**。
- 注意：「ON ｜ OFF」是**文字分段控件**，必须点名点击哪一半。

三、灵动样式的卡片（灵动页面）状态
- 布局：设备名称在卡片左上角，设备图在名称下方；卡片**右下角**是**圆形电源按钮**（按钮上没有文字）。
- 开关：点右下角圆形电源按钮即切换开关；**开关是否成功只允许由设备日志断言判定**
  （按钮颜色等页面表现不得作为断言依据；颜色信息仅用于找到并点击该按钮）。
- 连接：设备 WiFi 与蓝牙连接成功后，卡片**右上角**出现蓝色蓝牙图标＋蓝色 WiFi 图标；
  未连接时，名称下方显示**「设备离线」**文字。
- 注意：灵动卡片上**没有** ON / OFF 文字控件，不要按文字开关描述。

四、规划时必须遵守
1. 长按后的界面写成"同页顶部出现样式栏"，不要写成弹窗 / 菜单 / 新页面。
2. 保存动作写成"点击右上角 ✓"，不存在文字「保存」按钮，也不存在保存成功提示。
3. 任何检查蓝牙 / WiFi 图标的步骤，前面必须先有一步"等待设备 WiFi 与蓝牙连接成功"；
   图标位置在卡片**右上角**。
4. 经典与灵动的开关控件形态不同，不要混用措辞。
5. 开关类步骤的结果一律由**设备日志断言**（写成“日志返回开关成功 / 开灯 / 关灯事件”）；
   禁止用页面表现（ON/OFF 半边选中态、按钮颜色由灰变蓝等）作为断言依据——页面表现只用来找到并点击控件。
```

## 7. 与现行测试点文档的差异（建议修订）

| 现行写法 | 问题 | 建议 |
| --- | --- | --- |
| 灵动："点击灵动卡片页上的**开关 OFF/ON**" | 灵动页**没有** OFF/ON 文字控件（照抄了经典的写法） | 改为"点击卡片**右下角圆形电源按钮**"；断言只写**设备日志返回开关成功**（不用按钮颜色判断） |
| 两条都未写"等待连接" | 图标只有连接成功后才出现；保存后立即检查必失败 | 检查图标前**补一步"等待连接成功"**，并写明前置：设备已配网且在线 |
| 经典："点击经典卡片页上的开关 OFF/ON" | 未指明点**哪半边** | 明确写"点 ON 半边 / 点 OFF 半边"；并补"当前开关状态如何判定"（第 8 节） |
| 两条步骤顺序不一致（经典：保存→开关→图标；灵动：保存→图标→开关） | 图标与开关**都依赖连接成功** | 统一为：**保存 → 等待连接 → 检查图标 → 开关** |
| 长按后的界面描述 | 实际是"同页顶部出现样式栏" | 统一为"同页顶部出现样式栏（✕ / 灵动\|经典 / ✓）" |

## 8. 待确认项

1. ~~经典样式的开关状态如何判定~~ —— **已定口径：不通过页面判断**。开关是否成功一律由设备日志断言（点 OFF 后看日志是否返回开关成功），页面表现（选中态、颜色）不作为断言依据。因此 5.1 / 5.2 的第 7、8 步不再需要视觉验收。
2. **是否需要反向断言**：未连接时显示红色 WiFi 斜杠（经典）/「设备离线」（灵动）是否纳入这两条用例。
3. **「卡片大小同步应用到同类设备」是否纳入测试范围**。
4. **前置条件是否写进测试点**：设备需已配网并在线。

## 9. 附：规划模型当前的偏差（已核实）

**资产缺口**：页面流文档（17 节点 / 16 连线）里**没有「长按卡片 → 样式选择模式」这段交互**，从"设备主页页面"出去的唯一边是点击式入口（`—[H6810]→ H6810设备详情页`）。规划模型对这段界面**没有事实来源**，只能照抄测试点词汇并补出通用控件名。

**实测偏差（两条用例 × 各两次运行，上下文尚未提供时）**：

| 计划里的写法 | 真实界面 | 性质 |
| --- | --- | --- |
| "弹出卡片设置菜单／弹窗" | 同页顶部出现样式栏 | 控件形态猜错 |
| "找到「保存」按钮并点击" | 右上角 ✓ 图标 | 控件名不存在 |
| "页面提示保存成功" | 无保存反馈，需靠结构特征判定 | 断言不可依赖 |
| 灵动："找到开关并点击（OFF 切为 ON）" | 右下角圆形电源按钮（颜色表状态） | 控件名不存在 |
| 检查 WIFI / 蓝牙图标（未写位置、未等待） | 卡片右上角，**连接成功后**才出现 | 缺前置等待 + 描述不完整 |
| 第二次运行："点击卡片 → 进详情页 → 在详情页长按" | 应在列表页直接长按 | 路径偏离（恰好是跟着页面流走的结果） |

**建议的资产补录**：把 S1（样式选择模式）作为一个状态/节点纳入页面流，至少包含：长按触发口、✕ 取消、灵动/经典 分段、✓ 保存、"保存后样式栏消失"这一退出特征，以及两种卡片样式的开关控件形态与连接状态图标位置。在此之前，可先以**第 6 节的上下文**作为规划输入补足（见验收结论）。
