## 一、总结论

**已提交的前端代码本身是健康的，但存在一批明确的"退役残留"和一处规格漂移。**

1. **质量闸门全绿（HEAD 快照实测）**：`vue-tsc` ✅、`vite build` ✅、ESLint 0 error（7 warning）、Vitest 89 文件 / 558 用例全绿、样式门禁 / 虚线白名单 / Prettier 全过。无超 500 行 `.vue`（最大 461 行），无注释掉的代码块，无 TODO/FIXME 积压，无跳过的测试。
2. **废弃代码确认存在**：5 个孤儿文件（约 226 行 + 115 行陪葬测试）、`ai.ts` 约 193 行死类型簇、45 个自绘图标中 31 个零使用、6 个未使用依赖、1 个死静态资源、1 条死代理配置。
3. **一处规格漂移（最值得优先处理）**：`bug-error-label-bold` 变更已归档并写入主规格 MUST 条款，但渲染接线从未入库——纯函数 + P0 测试空转，抽屉仍用 `<pre>` 直出。
4. **工具债**：dependency-cruiser 的"HTTP 唯一出口"红线没有接入 CI / 本地门禁，只靠手动跑。
5. **当前工作区红灯来自未提交 WIP**（knowledge-search / ops-console），不是仓库债：`RetrievalSettingsCard.vue` 引用不存在的 `@/shared/utils/api-error`，导致工作区 typecheck 5 错、build 失败。HEAD 快照验证两者均通过。

#### A2. token-refresh"主动续期 + WS 4401"：半套功能未接线

- 连带死配置：`vite.config.js:66-69` 的 `/ws` 代理。
- 定性：主动续期是"实现了 + 测了 + 没接"的预留能力；WS 相关描述与代理是退役残留。
