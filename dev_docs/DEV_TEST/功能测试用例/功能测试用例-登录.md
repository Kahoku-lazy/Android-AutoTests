## 一、业务流（先定流程，再拆用例）

| 编号 | 业务流 | 入口 | 关键步骤 | 成功出口 | 失败 / 分支出口 |
|------|--------|------|----------|----------|------------------|
| BF-01 | 登录成功 | `/login` | 输入账号 → 输入密码 → 点「登录」 | 跳 `/dashboard`，会话写入本地（单账号） | — |
| BF-02 | 登录失败与重试 | `/login` | 输入错误密码 → 点「登录」 | — | 错误覆盖层显示原因 → 关闭 → 输入保留 → 改后重试 |
| BF-03 | 输入不合格拦截 | `/login` | 只填一个字段 / 填空白 / 超长 | — | 按钮灰置不可点 + 字段下方文案 |
| BF-04 | 记住账号 | `/login` | 勾「记住账号」→ 登录成功 → 登出后重开登录页 | 账号自动预填、开关为开 | 取消勾选后再登录 → 本地记录被清除 |
| BF-05 | 模式切换 | `/login` | 点「注册 →」/「去登录」 | 容器标题与表单同步切换 | 切到注册清空四个注册字段；切回登录保留账号、清空密码 |
| BF-06 | 注册即登录 | `/login` → 注册态 | 填四个字段 → 点「完成注册」 | 直接进工作台（不再登一次） | 账号被占用 → 提示「用户名已存在」，其余字段保留 |
| BF-07 | 会话退出 | 侧栏账号区 | 点「登出」 | 清空本地会话 → 回 `/login` | 后端 503 + `retry` → 提示后**保留**登录态 |
| BF-08 | 令牌失效后的处理 | 任意受保护页面 | 令牌过期时发起业务请求 | 自动续期后原请求重试成功（用户无感） | 续期失败 → 清令牌 → 回 `/login` |

### BF-01 登录成功主流程（展开）

1. 打开 `/login`：左栏品牌文案 + 右栏手绘便签卡（标题「登录」），焦点不在任何输入框
2. 在「账号」输入框输入用户名（本例 `admin`）
3. 在「密码」输入框输入密码（本例 `admin123`；输入以圆点遮蔽，右侧有「显示密码」切换）
4. 两个字段都合格时，「登录」按钮**由灰变亮**
5. 点击「登录」→ 按钮转圈（loading），期间不可重复点击
6. 后端校验通过 → 提示「登录成功，正在跳转...」→ 跳转 `/dashboard`，会话写入本地（单账号）
7. 若勾了「记住账号」，账号被记住，下次打开登录页自动预填

### BF-02 登录失败与重试流程（展开）

1. 输入正确账号 + 错误密码 → 点「登录」
2. 弹出一层**覆盖整个视口**的错误提示，正文为后端给的原因（本例「用户名或密码错误」）
3. 关闭方式三种：点「知道了」/ 按 ESC / 点遮罩任意处
4. 关闭后**卡片上已填内容保留**，改完可以直接再点 —— 不需要重新输入全部

## 二、输入组合用例（等价类 + 边界值）

### 2.1 输入域划分

| 字段 | 有效等价类 | 无效等价类 | 边界点 |
|------|------------|------------|--------|
| 账号（登录） | 已存在的账号名；长度 1–150 的非空白串 | 空；纯空白；长度 >150；前后带空格（登录侧**不 trim**，按原样核对） | 0 / 1 / 150 / 151 字符；纯空白；前后空格 |
| 密码（登录） | 与账号匹配的非空串；前后带空格（后端**会 trim**，等价于无空格） | 空；不匹配的密码 | 0 / 1 / 超长（如 200 字符）；前后空格 |
| 账号（注册） | trim 后长度 3–20 | trim 后为空 / 长度 2 / 长度 21 / 前后空格（会 strip） | 2 / 3 / 4 / 20 / 21；纯空白 |
| 邮箱（注册） | trim 后含 `@` | 空；不含 `@`；前后空格（会 strip） | 空 / 无 `@` / 前后空格 |
| 密码（注册） | trim 后长度 ≥6 | trim 后为空 / 长度 5 / 两次不一致 | 0 / 5 / 6 / 7；前后空格 |

> 前后端口径差异（实测记录）：**账号**不 trim（`trim_whitespace=False`），**密码**在登录与注册两侧都 trim/strip —— 见接口文档 TC-LOGIN-015 / 016 与 TC-REG-021 / 022。

**仍留人工 / 专项**：TC-BF-UI-016（停后端）、019（多标签页）、021（限速）需环境编排；TC-SESSION-008~010（503 登出、令牌续期与失效）属会话切片，尚未落地。**TC-SESSION-003~006（多账号切换、`?add` 加账号）已随 `remove-multi-account-pool` 作废。**

## 五、待决项与已知缺口

1. **回车不提交（✅实测）** —— 表单里没有原生提交按钮（「登录」是 `el-button` + click，非 `type=submit`），所以在输入框按 Enter 不会提交。这是可用性缺口：需要产品决策「是否支持回车提交」，决定后要么改成原生提交按钮、要么加键盘处理。
2. **提交中切换模式的行为未定义** —— 提交后立刻点「注册 →」会切到注册态并清空注册字段，而登录请求仍在飞行；登录成功时是否要跳转、是否要提示，目前没有约定。
3. **端到端层已落地 15 条**（2026-09-20，Playwright；映射见第四节）—— 原先「默认静默跳过」的问题同时被解掉：端到端层不再需要 `TEST_ADMIN_PASSWORD`，夹具自建 `e2e_probe` 账号后复用。未落地部分只剩需要环境编排的 TC-BF-UI-016/019/021 与会话切片的 TC-SESSION-008~010（TC-SESSION-003~006 已随 `remove-multi-account-pool` 作废）。
4. **前后端 trim 口径差异** —— 账号不 trim、密码在登录与注册两侧都 trim；已作为接口用例（TC-LOGIN-015/016、TC-REG-021/022）固化，但产品上是否要让账号也 trim 值得再确认。
5. **本文只展开了登录与登录页上的注册入口** —— 刷新令牌、登出、身份读取与会话章的完整业务流（多标签页、令牌轮换、路由守卫）建议套用同一模板另开文档，或并入集成 / E2E 层。
