# 任务清单任务失败原因排查（TASK-177）

> 日期：2026-11-03　范围：`engines/agents`（middleware/budget、workflow、agent loop）+ `task_events` 数据
> 性质：只读排查，未改动任何代码

## 0. 结论

1. **任务清单当前只有 1 条任务**：`task_tasks.id=177`「定时任务测试-01」，`status=failed`；失败**不是**设备、串口、网络或接口异常，而是执行者**没有交卷**被 `sop` 判负。
2. **直接原因**：第 4 步（睡眠定时）两次尝试都触发 `ExceedMaxItersEvent`（60 轮 ReAct + 5 轮结构化宽限 = 65 次模型调用），判决为 `passed=False by=sop｜Your turn ended without a structured output` → 用例「H6810 定时功能测试」未完成 → 任务 failed。
3. **根本原因（三重叠加，缺一不成立）**：
   - **单步 token 预算把工具禁掉了**：`AGENT_REPLY_TOKEN_BUDGET` 默认 600,000 加权 token。执行者每轮都带截图，单轮 `input_tokens` 45k–90k，**跑到第 12–26 轮就撞线**；撞线后 `ReplyBudgetControlMiddleware` 把 `tool_choice` 强制成 `none` 并追加「不要再调用任何工具」。
   - **框架同时要求「必须调 GenerateStructuredOutput 交卷」**：只要该步存在结构化输出契约且未满足，ReAct 循环就会（max_iters 之后用 `tool_choice` 强制）要求交卷；而中间件的 `none` **覆盖**了框架的强制，交卷工具永远调不出来。
   - **模型于是把工具调用写进正文**：DeepSeek 侧输出 `<｜｜DSML｜｜ calls>…` 标记，框架按纯文本处理（没有 DSML 解析），结构化输出始终为空 → 循环空转到 65 轮 → `ExceedMaxIters`。
4. **量化浪费**：整任务 923 秒、255 次模型调用、约 **1,097 万加权 token**、成本 **¥3.31**；其中 **约 801 万（73%）发生在预算撞线之后的空转轮次**（3 次超限各空转 52 轮、共 156 次无效调用）。

## 3. 根因定位（代码）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `engines/agents/middleware/budget.py:37,48-51` | 默认预算 600,000；提示语固定为「不要再调用任何工具」 |
| 2 | `agentscope/middleware/_budget.py::on_reasoning` | 超预算后 `input_kwargs["tool_choice"] = ToolChoice(mode="none")`，**每轮**生效；提示还被重复追加进上下文 |
| 3 | `agentscope/agent/_agent.py:3580-3653` | `required and not satisfied` 时要求调用 `GenerateStructuredOutput`，`cur_iter>=max_iters` 时用 `tool_choice` 强制 —— 但被 #2 覆盖成 `none`，交卷工具不可用 |
| 4 | `agentscope/agent/_agent.py:3589-3622` | 宽限 `structured_output_grace_iters=5` 用完才抛 `ExceedMaxIters`；这 5 轮全部空转 |
| 5 | `engines/agents/config/data/agent_config.yaml:25-28` | `max_iters: 60` 与 600k 预算**严重不匹配**：按单轮 45k–90k 估算，实际可用行动轮次只有 7–13 轮，其余 47–53 轮必然空转 |
| 6 | `engines/agents/workflow/handover_guard.py:35-55` + `UI_EXECUTOR_PROMPT.md:18`（规则 13） | 提示词禁止 handover 出现「未完成/尚未/未点击」，守卫又按同一批词把交卷退回继续执行 → 预算耗尽时形成**「不能操作、也不能如实交卷」死锁**（日志里模型多次自述指令冲突） |

补充：本次失败**不是**业务操作能力问题。step3 attempt2 用同样手段（点「完成」→ 重进「唤醒」→ 改 7:50）成功通过；step4 attempt2 在被截断前已经打开「关闭倒计时」弹窗并点中目标数值，只差「完成 + 保存」两步。

## 4. 附带发现（非本次失败主因）

1. 每轮都刷 `Skill directory ...\engines\agents\skills\executor does not exist` 告警——skills 目录配置与磁盘不一致，属噪声但会掩盖真实告警。
2. 任务清单页请求 `/api/tasks/NaN/report/` 返回 404——前端在拿不到 id 时没有兜底（`logs/backend.log` 11:31:05）。
3. 两次上下文压缩请求返回 `400 Bad Request`（随后降级成功）；压缩发生在空转轮次里，纯属浪费（`backend.log` 11:25:20 / 11:30:16）。
4. 全局预算（`SOP_MAX_MODEL_CALLS=600` / `SOP_MAX_RUN_SECONDS=7200`）没有兜住这次失控：255 次调用、923 秒都远低于阈值，说明**单步预算才是唯一闸门，而它只禁工具、不终止循环**。
5. `dev_docs/DEV_TEST/SOP事件流与轮次治理方案-20261026.md` 明确写过「轮次上限不用调小，要加兜底」——那次的兜底只解决了任务级总量，没覆盖 2026-10-28 新增的**单步 token 预算与强制交卷的冲突**。

## 5. 待决策

1. **预算耗尽后的收场策略**（三选一，建议 A+B）
   - A：放行一次「无工具的结构化交卷」——撞线后把 `tool_choice` 从 `none` 改成 `GenerateStructuredOutput`，允许模型只交结论；
   - B：撞线即终止该步并判 fail，不再跑完 60+5 轮（本次可省 ~800 万 token / 约 2.4 元 / 约 700 秒）；
   - C：只调大预算、不动逻辑（不推荐，等于把空转成本放大）。
2. **`max_iters` 与预算对齐**：按「预算 ÷ 单轮实测 token」反推上限（当前实测约 13），或按步骤粒度拆分，避免 60 轮名义值误导。
3. **「如实交卷未达成」是否合法**：调整提示词规则 13 与 `IncompleteHandoverGuard` 的冲突（例如允许「未达成 + 阻塞点」的中性表述；守卫只在预算未耗尽时退回）。
4. **是否按 OpenSpec 流程落修复变更**（`/opsx:propose`）：① 预算与强制交卷的优先级；② DSML 正文兜底解析；③ 撞线即快速失败。
