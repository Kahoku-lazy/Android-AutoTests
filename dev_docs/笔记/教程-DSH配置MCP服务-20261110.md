# 教程：给 DSH 接入 MCP 服务

> 适用对象：在本机用 DeepSeek Harness（DSH）做开发，希望把外部 MCP 服务（文档检索、内部工具、第三方 SaaS）变成模型可直接调用的原生工具的同学。
> 成文依据：本机 `@deepseek-ai/dsh-mcp-client@0.1.5-rc.2` 的插件 README 与配置 schema，以及在 `agentscope-docs` 上的实测。
> 最后更新：2026-11-10

---

## 结论先行

三步，改一个 YAML 文件，**不用重启**：

1. 打开当前 profile 的补丁层：`~/.dsh/profiles/<profile>/cordis.patch.yml`（本机是 `desktop`）；
2. 在顶层数组里加一个 `- insert:` 条目，`name` 固定写 `@deepseek-ai/dsh-mcp-client`，`config` 里给服务器起个短名、选传输方式；
3. 保存即生效——插件会**原位重连**该条目；模型侧立刻能看到 `mcp__<serverName>__<tool>` 形态的工具。

本项目已按此法接入了 AgentScope 官方文档站，见文末「已落地实例」。

---

## 一、配置文件在哪

DSH 的配置是分层叠加的：

```
bundle 层（安装包自带）
   └─► profile 补丁层：~/.dsh/profiles/<profile>/cordis.patch.yml   ← 我们只改这里
          └─► 会话运行时
```

- 文件是一个**顶层 YAML 数组**，每个元素是按 `id` 定位的加载器补丁；
- `- insert:` 表示「追加实例」，`- id: xxx` + `config:` 表示「覆盖已有实例的配置」；
- 补丁层在每次启动时应用在 bundle 层之上，所以**升级 DSH 不会丢配置**。

当前 profile 名可以在 GUI 的设置里看到；本机是 `desktop`。

## 二、最小可跑示例

### 2.1 远程服务（Streamable HTTP）

```yaml
- insert:
    - id: agentscope-docs-mcp
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: agentscope-docs
        transport: streamable-http
        url: https://docs.agentscope.io/mcp
        toolCallTimeoutMs: 60000
        failOnStartupError: false
```

### 2.2 本地进程（stdio）

```yaml
- insert:
    - id: filesystem-mcp
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: fs
        transport: stdio
        command: npx
        args: ["-y", "@modelcontextprotocol/server-filesystem", "D:/work"]
        toolCallTimeoutMs: 60000
        failOnStartupError: false
```

> `id` 只是补丁条目自己的标识，随便起但要唯一；**真正决定工具名的是 `serverName`**。

## 三、字段说明

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `transport` | ✅ | — | `stdio` 或 `streamable-http` |
| `serverName` | ✅ | — | 工具命名空间，`[A-Za-z0-9_-]{1,32}`，同一作用域内唯一 |
| `url` | HTTP 必填 | — | MCP 端点，必须是 Streamable HTTP |
| `headers` | ❌ | `{}` | 附加请求头，鉴权 token 放这里 |
| `command` | stdio 必填 | — | 可执行程序 |
| `args` | ❌ | `[]` | 命令行参数 |
| `env` | ❌ | `{}` | 额外环境变量（父进程凭据类变量会被剥离） |
| `cwd` | ❌ | `""` | 子进程工作目录 |
| `toolCallTimeoutMs` | ❌ | `60000` | 单次 `tools/call` 超时 |
| `failOnStartupError` | ❌ | `false` | 初始连接失败时是否让插件激活直接失败 |
| `reconnect.enabled` | ❌ | `true` | 断线自动重连 |
| `reconnect.initialDelayMs` | ❌ | `500` | 首次重连延迟，之后逐次翻倍 |
| `reconnect.maxDelayMs` | ❌ | `30000` | 退避上限；连接稳定超过该时长会重置失败计数 |
| `reconnect.maxAttempts` | ❌ | `10` | 连续失败多少次后放弃并摘除工具 |

**`failOnStartupError` 怎么选**：

- 文档检索、搜索这类**锦上添花**的服务 → `false`，连不上就少几个工具，不影响干活；
- 内部关键服务、缺了就没法工作 → `true`，让问题在启动时暴露，而不是等模型调用时才报错。

## 四、生效与验证

### 4.1 工具长什么样

```
mcp__<serverName>__<rawName>
例：mcp__agentscope-docs__search_agent_scope
```

- 这是**稳定契约**：只要 `serverName` 和远端工具名不变，名字就不变，历史会话与权限规则都能对上；
- 名字里出现非法字符或被截断时，会追加 12 位 SHA-256 短哈希，保证不同工具不会撞名；
- 两个服务器都有 `search` 也不冲突：`mcp__github__search` 与 `mcp__web__search` 并存。

### 4.2 怎么确认接上了

1. **看配置解析**：保存后不该有 YAML 报错（DSH 会在加载时报出语法问题）；
2. **看工具列表**：新开会话或直接让模型「列出你有哪些 mcp 工具」，应能看到 `mcp__<serverName>__*`；
3. **调一次**：让模型调用一个只读工具（如搜索），比看列表更能证明链路通；
4. **看日志**：连接失败会打错误日志，重连过程也有记录。

### 4.3 为什么不用重启

插件对「配置条目被编辑」做了**原位重连**：同一个 `id` 重新求值后，旧的连接代际被关闭、新的建立，工具集合随之替换。所以改完保存，下一次模型调用就能用。

> 例外：把整段删掉后若工具仍残留，或 `reconnect.maxAttempts` 用尽导致工具被摘除，需要重载配置或重启 DSH。

## 五、已落地实例（本项目）

AgentScope 官方文档站提供 MCP 服务（`https://docs.agentscope.io/mcp`），我们把它接成了 `agentscope-docs`：

- 位置：`~/.dsh/profiles/desktop/cordis.patch.yml` 的 `- insert:` 段；
- 用途：查框架 API / SOP / 中间件 / MCP 教程时，让模型直接检索官方站点，而不是凭记忆；
- 暴露的工具：
  - `search_agent_scope`：语义检索，支持版本与语言过滤
  - `query_docs_filesystem_agent_scope`：在文档虚拟文件系统上跑只读 shell（`rg`/`tree`/`cat`），**这是读页面的唯一方式**（没有 `get_page`）
  - `submit_feedback`：给文档站报错
- 配套技能：[`agentscope-docs`](../../.agents/skills/agentscope-docs/SKILL.md)（不在 DSH 配置里的环境，用它的脚本走同一套接口）。

> 本机还配了一个 `modao`（墨刀 AI）服务，token 放在 `headers` 里。**本文不抄录任何真实凭证**；照着写的时候，密钥只进环境变量或本地补丁文件，不要进仓库。

## 六、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 直接 GET 端点返回 `405` + JSON-RPC 错误 | 那是 MCP 服务，只接受 POST JSON-RPC | 不用手测，交给 DSH |
| `curl` / `Invoke-WebRequest` 连不上 | Windows schannel 取不到客户端凭据 | 用 Python `urllib`/`httpx`，或直接让 DSH 连 |
| 启动后看不到工具 | 连接失败但 `failOnStartupError=false` | 看日志；先单独验证 URL 可达 |
| 工具名带一串哈希 | 原始名超出 `[A-Za-z0-9_-]{1,64}` 或被截断 | 正常现象，名字仍稳定 |
| 改了配置没反应 | 改的是别的 profile，或 `id` 与已有条目冲突 | 确认 profile 目录；`id` 必须唯一 |
| 断线后工具还在但调用失败 | 处于重连窗口，旧工具保留 | 等重连；或用尽后重载配置 |
| `serverName` 报不合法 | 超出 `[A-Za-z0-9_-]{1,32}` | 改短、只留字母数字下划线连字符 |

## 七、回滚 / 卸载

1. 删掉 `- insert:` 下对应条目（只删自己那一段，别动其他条目）；
2. 保存，插件卸载该连接、撤掉工具；
3. 若工具仍残留，重启 DSH。

建议改动前先备份：

```bash
copy "%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml" "%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml.bak"
```
