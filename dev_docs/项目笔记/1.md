## 2. 模板 / 样式 / 布局（每次改 UI 必做）

1. **布局裁剪（P0）**：真实页面缩小窗口可滚；侧栏展开不挤爆；表格区 `flex: 1 1 0; min-height: 0; overflow-y: auto`；外层禁止乱加 `overflow:hidden`。
2. **Dialog/Drawer**：长内容可滚，底部按钮可达。
3. **字段显示完整性**：有数据来源与空值占位；列表列 / Card / detail 关键字段不漏。
4. **表格长文本列**：`show-overflow-tooltip` 或等价。
5. **视图模式切换**（卡片↔表格等）后布局仍可用。
6. 字号/颜色走 token；静态样式进 class。
7. 三态 + **saving**；错误文案对用户友好，不暴露技术术语。
8. **多视图互斥**；**composable 入参**约定一致。
9. **保存**：信封解包；strip UI-only；校验≥Schema。
10. **展示组件**：薄组件；危险操作确认；编辑锁只读禁用；子面板只改自己 v-model 块。
11. 纯展示子组件：不为「配套重构」而改；只改契约/图标/bug/a11y。
12. 点阵纸纹背景（radial-gradient + `--paper`），无纯色背景；卡片网格微旋转错落（3n+1/3n+2/3n+3），无全 0° 排排坐。
13. 表单标签左对齐（80/100/120px），弹窗内单列；内容区不设全局 max-width 居中；表格放主内容区/Tab 面板，不嵌卡片。

**风格约束（Doodle Craft 主题）**——规则在此；**具体值一律读** `src/shared/styles/tokens.css`（先看头部「现行 / @deprecated / 待收敛」声明再取值，本文不重复贴值）：


| 项       | 规则                                                                                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 字号      | 只用 `--app-size-*` 6 档（最小 12px）；禁硬编码 `font-size`                                                                                                                                  |
| 颜色      | 组件 scoped 内禁硬编码色值；模块色 `--c-*` 仅作左边框/图标/图表系列/浅色背景，禁大面积正文；状态色禁正文；正文 `--ink`、辅助 `--app-text-secondary`                                                                              |
| 圆角      | 几何不对称（`--app-radius-*`）；禁对称大圆角 `50px`/`16px`/`20px`                                                                                                                              |
| 阴影      | 扁平零模糊（`--app-shadow-*`）；禁模糊阴影/大扩散                                                                                                                                                |
| 间距      | 只用 `--app-space-*` 刻度；禁 `15px`/`20px` 随意值                                                                                                                                        |
| 动效      | 只用 `--app-duration-*` + `--app-ease`/`--app-spring`                                                                                                                              |
| 禁项      | 玻璃态（`backdrop-filter` 全局清零）、旧色值 `#4a4e69`/`#9a8c98`、新模块引入玻璃态样式                                                                                                                   |
| CSS 块注释 | `/* ... */` 内禁止写字面量 `*/`（`--app-duration-*/--app-ease` 会在第一处结束注释，后续 `:root` 令牌全部丢掉）。列举 token 用顿号或 `、`，不要用 `/` 拼接。翻车：2026-08-21 `tokens.css` 头部提前闭合 → `--ink` 全空 → 登录页无渐变/白纸卡/手写体 |
| JS 画布例外 | ECharts/Canvas/动态 SVG 不解析 CSS 变量，色值/字体用字面量；改 tokens 后同步 JS 渲染配置                                                                                                                  |
| 组件做法    | 基础/业务组件实现与页面级验收口径 → `doodle-craft` skill + `vue-frontend-check` skill                                                                                                            |

## 3. 协议要点

**HTTP / DRF**：组件 emit → composable → 模块 `api` → `djangoClient`（统一客户端）→ `/api/...` **DRF**。  

- 逻辑层接口须与后端协议一致（路径、方法、字段、信封）；对照后端 `urls.py`、Serializer、`dev_docs/03-设计与架构/工具-VUE_API_CONTRACT.md`。  
- 禁止组件/composable 旁路直连后端端口或另起非约定 HTTP 客户端。  
**WS**：`wsUrl('/ws/...')` 经 Vite 代理，禁止直连后端端口。test-runner 事件 type 不可漏（现 9 种：`log` / `heartbeat` / `case_started` / `step_started` / `step_result` / `iteration_result` / `case_finished` / `run_finished` / `device_error`，见 `useTaskWebSocket.ts`）；后端另发 `run_started`，前端暂不消费。模块落点：`src/modules/test-runner/AGENTS.md`；编辑锁见 `src/modules/case-manager/AGENTS.md`。  
**报告下载**：FileResponse 用 `fetch().text()`，不用 JSON `api()`。  
**SSE（AI）**：单请求流式对话；事件经 `SSEMessageBuilder` 归一化 phase 后按类型渲染（模块落点：`src/modules/ai-assistant/AGENTS.md`）。


| 事件                               | 前端渲染                              |
| -------------------------------- | --------------------------------- |
| `REPLY_START`                    | 消息气泡出现，开始新回复                      |
| `TEXT_BLOCK_DELTA`               | 追加文本到消息气泡（逐字打字效果）                 |
| `THINKING_BLOCK_START/DELTA/END` | ThinkingBlock 可折叠推理过程             |
| `TOOL_CALL_START/DELTA`          | ToolCallCard（loading 态 + 参数 JSON） |
| `TOOL_RESULT_START/DELTA/END`    | 更新 ToolCallCard 结果摘要              |
| `HINT_BLOCK`                     | SOP 状态卡片 / 任务卡片                   |
| `REQUIRE_USER_CONFIRM`           | HITL 确认弹窗                         |
| `REPLY_END`                      | 消息完成 → `save-message` 持久化         |
| `error`                          | 错误提示，允许重试                         |


- **停止生成**：关闭 SSE → 保留已生成内容；旧流回调经 stale 检查失效。
- **断线重连**：自动重试最多 3 次，间隔递增（1s/2s/4s）；AI 不可用降级阻塞模式 `POST /api/ai/chat/sync`。
- **折叠规则**：`ThinkingBlock` 默认折叠手动展开；`ToolCallCard` 默认展开。
- **终端事件**：`reply_end` 与 `exceed_max_iters` 均触发完成；未到终端断流须报错。

## 1. 准备怎么做（动作清单）

对 5 个重灾区文件（`EvaluatorTab`/`WebElementManager`/`ApiEndpointManager`/`CaseFileSheet`/`ProjectTree`），只做三类机械替换，**不拆文件、不动逻辑、不动 API**：

| 动作 | 对象 | 目标 |
|------|------|------|
| ① 内联布局收口 | template 里的 `style="display:flex;gap:8px..."` | 迁到 `<style scoped>` 的语义 class |
| ② 裸值 token 化 | scoped CSS 里的硬编码色/字号/间距/圆角 | 换成 `var(--app-*)` |
| ③ 硬编码字号合规 | `11px`/`10px` | 抬到 `--app-size-xs`(12px) 起步 |

**不做的**：`width`/`height` 这类布局尺寸（属骨架，非皮肤）、JS 画布字面量（ECharts/Canvas 合法例外）、任何逻辑与数据流。

## 3. 结构与外观的边界（核心契约）

```
结构（template）          外观（<style scoped>）
─────────────────   class   ─────────────────
语义标签 + 指令  ───────────▶  选择器命中
"有什么/有没有/有几个"        "长什么样/多大/多少间距"
只写 class、v-if/v-for      只写 var(--token) + 布局值
```

**唯一契约 = class 名**。结构通过 `class` 引用外观，外观通过选择器锚定结构，两者互不感知对方内部。

**三层判定的分界线**：

| 层 | 属于 | 值怎么给 |
|----|------|---------|
| 颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效 | **皮肤** → 必须 token | `var(--app-*)` |
| `display` / `flex` / `width` / `height` / `grid` 列 / `overflow` | **骨架** → 进 class | 值可 px（结构尺寸），但**必须写在 CSS，不内联** |
| 数据 / 条件 / 循环 | 结构语义 | 指令表达，与外观无关 |

> 关键澄清：`el-select style="width:240px"` 的 `240px` 是**骨架尺寸不是皮肤**，方案 A 不强制 token 化，但要迁出内联、进 class。真正违规的是 `gap:8px`/`margin:20px`/`border-radius:8px`/`color:#8a7b66` 这些**皮肤值**。

## 4. 结构如何设计

原则：**模板只表达语义与状态，不表达"数值"**。

- **语义标签 + 语义 class**（项目 kebab-case / 动物岛 BEM 双下划线），如 `.tab-toolbar`、`.tag-row`、`.desc-box`
- **状态用 `:class` 切换**，不用内联 style：
  ```html
  <!-- ❌ 状态写进 style -->
  <div :style="active ? 'color:red' : ''">
  <!-- ✅ 状态用 class -->
  <div :class="{ 'mode-btn--active': active }">
  ```
- **`v-if`/`v-for` 只做"有无/个数"**，与外观零耦合
- **布局角色语义化**：`display:flex` 容器用 `.xxx-toolbar` 命名，让"这是一排工具按钮"从 class 名即可读，值留在 CSS

## 5. 外观如何设计

原则：**值全部来自 tokens.css，档位见下表**（真相源已核对）。

| 皮肤维度 | 可用 token | 关键约束 |
|---------|-----------|---------|
| 字号 | `--app-size-xs`(12)→`sm`(14)→`md`(16)→`lg`(20)→`xl`(24)→`2xl`(32) | 6 档，最小 12px |
| 间距 | `--app-space-xs`(4)/`sm`(8)/`md`(16)/`lg`(24)/`xl`(32)/`2xl`(48) | 禁 15px/20px 随意值 |

### 2.2 业务模块（模块划分与代码设计）

**模块边界**：一个模块 = 一个后端 App 的投影面；增删模块同步改 4 处（`config/urls.py` + `router.ts` + `AppSidebar.vue` + 目录）。
- ❌ 随意建模块目录、业务组件塞 `shared/`、跨模块 import 内部实现或 Pinia store。
- 💡 模块是架构级单位，边界清晰才能安全增删。

**分层数据流**：`index.vue（渲染/emit/v-model）→ Xxx.logic.ts（编排）→ composables/（流程/校验）→ api.ts → api-client → /api DRF`。
- ❌ 组件直接 HTTP、编排直连 api-client、下层反向依赖上层、跨层直达。
- 💡 单向依赖才能分层验证，每层职责单一可独立测试。

**代码设计**：数据流 `fetch → 解包 {status,data} → 赋值 → 渲染`；四态齐备（loading/error/empty/data）；消费后端权威 `state`。
- ❌ 前端推导业务状态、静默吞错（写操作必须 `ElMessage.error`）、`error.value` 放 `try` 第一行（retry 闪白）。
- 💡 单一事实源在后端；四态齐备杜绝白屏/假数据。

### 2.3 代码规范（注释/命名/风格）

- ✅ 事件 `handleXxx`；内部包装函数 `baseXxx`/`rawXxx`；`@retry="fetchData"` 命名函数；`error.value=''` 放 `data.status` 内（成功后清除）；`finally { loading=false }`；提前 `return` 压平嵌套；提交 Conventional Commits。
- ❌ 内联箭头 `@retry="() => {...}"`；魔法字符串/硬编码正则；只在 `try` 关 loading（catch 永远转圈）；深层 `if-else`；.vue 超 500 行不拆（先拆样式层再拆逻辑层）。
- ✅ 注释：复杂函数 JSDoc；CSS 注释列举 token 用顿号「、」；显式忽略错误的 `catch (_)` 注释原因。
- ❌ CSS 块注释嵌 `*/`（用 `/` 拼接 token）；无注释的静默 catch。
- 💡 语义清晰、风格一致，降低认知负担。

### 2.4 Vue 框架规范（组合式 API）

- ✅ 统一 `<script setup lang="ts">`；`defineProps` 解构带默认值；`defineEmits` 类型化；双向绑定 `defineModel<T>()`；插槽简写 `<template #header>`。
- ❌ Options API；手写 `modelValue` + `update:modelValue`（用 defineModel）；`v-slot:header` 老式写法；`watch` 传解构 prop（丢响应式，须 `() => count`）。

- ✅ 响应式：状态 `ref()` 优先；派生 `computed`（纯函数、无副作用、不 mutate 源）；副作用 `watch`；DOM 更新 `nextTick()`；对象解构 `toRefs()`。
- ❌ `reactive()` 解构丢响应式；`computed` 里做副作用；`computed` 值 mutate；method 替代 computed（失去缓存）。

- ✅ 组件通信：props 下行、emits 上行；多值双向 `v-model:xxx`；同名简写 `:count`；模板 kebab-case / 脚本 camelCase。
- ❌ 子组件 mutate 父 props；跨多层 props 透传（深了抽 provide/inject 或 store）。

- ✅ Composable：`use` 前缀、文件=函数名；只在顶层调用（不在事件/条件/循环里）；内部状态 `readonly()` 导出；`onUnmounted`/`onWatcherCleanup` 清理；接受 options 对象；能用 VueUse 不自造。
- ❌ 事件处理器里调 composable；导出可被外部 mutate 的内部 ref；异步 composable（丢生命周期上下文）。
- 💡 组合式 + 类型化是 Vue 3.5 正统写法，响应式行为可预测。

## 4. 协议要点

- **HTTP / DRF**：组件 emit → composable → 模块 `api` → `djangoClient` → `/api/...` DRF（唯一出口；禁止旁路直连后端端口或另起非约定 HTTP 客户端）。
