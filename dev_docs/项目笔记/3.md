1. 优美胜于丑陋，可读性至关重要
架构规范：采用 src/ 布局与清晰的目录划分
隔离源码：推荐使用 src/ 布局（如 src/my_project/），将核心业务代码与测试、配置文件、文档隔离开来。这能让项目结构一目了然，避免根目录杂乱无章。
按业务域划分：在大型项目中，摒弃单纯按技术类型（如 models, views）划分的方式，转而按业务功能（如 src/payments/, src/orders/）组织代码。这符合“可读性至关重要”的原则，让开发者在处理特定功能时，90%的代码都在同一个目录下。
扁平化结构：包层级尽量控制在3层以内，避免过度嵌套带来的“丑陋”与阅读困难。
2. 简单胜于复杂，扁平胜于嵌套
架构规范：分层架构与单一职责
职责分层：在 src/ 内部，遵循分层架构（如接口层 interfaces/、应用层 application/、领域层 domain/、基础设施层 infrastructure/）。让每一层只做自己该做的事，避免业务逻辑、数据库操作和接口参数校验混杂在一起（避免“错综复杂”）。
单一文件控制：遵循单一职责原则，按功能拆分文件，避免单文件代码超过 300-500 行。如果一个函数或类承担了太多工作，就将其拆分，保持结构的“扁平”。
3. 明确胜于隐晦，拒绝猜测的诱惑
架构规范：显式的接口与依赖管理
显式依赖：使用 pyproject.toml 集中管理项目元数据和依赖，明确项目的构建系统和工具配置，取代隐晦的环境依赖。
明确的接口契约：模块之间遵循“接口+实现”分层。定义清晰的抽象接口（如 PaymentService），具体实现通过依赖注入调用。使用类型提示（Type Hints）明确参数与返回值类型，让代码意图“明确”而非“隐晦”。
禁止魔法：禁止使用通配符导入（from module import *），避免魔法数字（将其定义为常量），避免隐式的全局状态。
4. 命名空间是个绝妙的主意
架构规范：模块化与包管理
包隔离：充分利用 Python 的包机制，通过 __init__.py 明确控制模块的对外导出接口（使用 __all__ 控制导出）。
绝对导入优先：在包内和跨包调用时，优先使用绝对导入，避免循环依赖，确保依赖方向单向流动。
5. 实用胜过纯粹，现在做总比从不做好
架构规范：务实的工程化基建
测试镜像结构：建立 tests/ 目录，其内部结构应严格镜像 src/ 目录（例如 src/payments/gateway.py 对应 tests/payments/test_gateway.py）。这既保证了代码的纯粹性，又兼顾了测试的实用性。
自动化规范：将代码规范（如 Black, isort, flake8, mypy）的配置统一收敛到 pyproject.toml 中，并集成到 CI/CD 流程（如 Makefile 或 GitLab CI）中。用工具代替人工审查，这是最“实用”的落地方式。
