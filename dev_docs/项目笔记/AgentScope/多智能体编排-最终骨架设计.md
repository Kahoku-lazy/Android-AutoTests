# AI 助手多智能体编排 — 最终骨架设计

> 日期：2026-08-28 · 状态：已实现（规划→执行两模型流水线）· 框架：AgentScope 2.0.7.post1
> 用途：复盘设计 + 实现依据。**意图识别/分类/路由已移除**，流水线收敛为「规划 → 执行」两模型：
> ① `planner`（规划模型）把用户输入优化为标准自动化执行步骤；② `vision`（执行模型）执行步骤。
> 智能体共 4 套 Harness（planner / vision / reasoning / strong）。

---

## 一、设计目标

1. **分工**：AI 要执行「控制设备、编写用例、梳理 UI 页面元素」等繁杂任务，单智能体无法有条理完成 → 拆成**多套专用 Harness 各司其职**。
2. **治理**：智能体是平台级资产，**管理员统一管理**（配模型），**用户只使用**（一个对话入口）。

核心抽象：**Agent = model + Harness**
- model：大脑，固定池子里选（规划 / 视觉 / 推理 / 强模型）
- Harness：任务外壳（system_prompt + 工具子集 + 循环/上下文配置 + 绑模型）

---

## 二、职责边界

- **Django 外层**：只调用 `agent_scope/` + 保存对话记录，不写智能体逻辑。
- **`agent_scope/`**：负责智能体配置、智能体工具配置、智能体逻辑。

## 四、四套 Harness

| name | model | 作用 |
|---|---|---|
| `planner` | `model_name` | **规划**：把用户输入优化为标准自动化执行步骤（纯文本步骤，无工具，无分类） |
| `vision` | `vision_model_name` 或 `model_name` | **执行**：看图 / 控设备，执行规划步骤（12 工具） |
| `reasoning` | `model_name` | 写用例 / 文本任务（23 工具），保留待用 |
| `strong` | `strong_model_name` 或 `vision_model_name` | 手动开关，短路执行，工具 = vision + reasoning（35 工具） |

```python
@dataclass
class Harness:
    name: str                # "planner" / "vision" / "reasoning" / "strong"
    provider: str = "deepseek"
    model_name: str = ""
    system_prompt: str = ""
    tools: list[str] = field(default_factory=list)
    parameters: dict = field(default_factory=dict)      # thinking_enable / reasoning_effort
    context_config: dict = field(default_factory=dict)  # max_image_num 等
    react_config: dict = field(default_factory=dict)    # max_iters 等
    enabled: bool = True     # 开关（strong 默认 False）
```

## 五、数据流（规划 → 执行）

```
用户消息（原话）
  → ① 规划模型 plan(manager, dialog)：planner 依 PLANNER_PROMPT 优化为标准步骤（纯文本「1. 2. 3.」）
  → ② 执行模型 build_agent(manager, "vision") + agent.reply_stream(steps)
     vision 依 VISION_PROMPT 的设备操作 SOP 在 ReAct 循环内：
       截图看图 → 定位 → 动作 → 截图校验（逐步执行规划步骤）
  → 终端事件 → 持久化 assistant 消息
```

Django 薄壳调用：

```python
manager = AgentManager(config, credentials)          # 读配置建 4 套 Harness
steps = await plan(manager, user_message)            # ① 规划：输入 → 标准步骤
agent = build_agent(manager, "vision")               # ② 执行：装配 vision agent
async for event in agent.reply_stream(steps):        #    流式执行步骤
    yield to_sse(event)
save_message(...)                                     # 存对话记录
```

## 六、UI 自动化流水线（自建，不用 GoalPipeline）

两段：**规划模型产出步骤 → 视觉 agent 执行步骤**。
执行阶段视觉 agent 依 `VISION_PROMPT` 的 SOP 在 ReAct 循环内「截图 → 定位 → 动作 → 校验」，
最后以结构化输出 `AssertionResult{result, message}` 给出断言。
关 thinking（结构化输出与 DeepSeek thinking 冲突）+ 限 `max_iters=8`（防「找不到元素」无限循环）。

## 七、关键设计决策汇总

| # | 决策 | 理由 |
|---|---|---|
| 1 | Agent = model + Harness | 模型固定、任务外壳可变，解耦 |
| 2 | 4 套 Harness（planner/vision/reasoning/strong） | 规划与执行分离，各司其职 |
| 3 | 流水线 = 规划 → 执行 两模型 | 规划模型优化步骤，执行模型落地动作，不再做意图分类 |
| 4 | 规划输出纯文本步骤 | 免 JSON 解析，直接喂执行模型 |
| 5 | reasoning 保留待用 | 写用例/文本任务；其 23 工具由 strong 模式复用 |
| 6 | 模型按 provider 用专用类 | `DeepSeekChatModel` + `DeepSeekCredential`；视觉/强模型走 OpenAI 兼容（支持图片） |
| 7 | 工具用 `FunctionTool` | 框架自带，自动推导 schema，不重复造轮子 |
| 8 | 图片返回 `ToolChunk(DataBlock(Base64Source))` | 截图给视觉模型 |
| 9 | 权限用 `PlatformFunctionTool` 子类 | 只读自动放行，写操作 ASK（设备动作为内部锁自动放行） |
| 10 | 图片数量控制用 `ContextConfig.max_image_num` | AgentScope 内置，不手写裁剪 |
| 11 | 去掉知识库（rag_service）与 skill（skill_registry） | 本次不涉及，简化 |
