## 一、复杂度分级速查

| 级别 | 特征 | 策略 | 最少方法数 |
|:--:|------|------|:--:|
| **L1** | 单一功能，用户操作驱动，秒级反馈，无物理依赖 | 直接套场景流法 | 2 |
| **L2** | 单一功能+物理依赖，或 2-3 子模块，部分与已有重叠 | 拆分后逐子模块评估 | 3 |
| **L3** | 多模块合集，多种驱动方式混合，大量物理依赖 | 必须拆分，按子模块分别选方法 | 4 |
| **L4** | 跨系统/跨协议/跨硬件，全生命周期 | 架构级分析，分阶段交付 | 全8种按需 |

### 分析六维度

| 维度 | 适合场景流 | 不适合场景流 |
|------|:--:|:--:|
| 模块数量 | 单一功能 | 多模块合集 |
| 驱动方式 | 用户可感知交互 | 硬件内部保护/后台任务 |
| 时间粒度 | 秒~分钟级 | ms级(硬件)/天月级(数据) |
| 物理依赖 | 纯软件/可模拟 | 需台架/温控箱/示波器 |
| 可观测性 | LED/蜂鸣/APP提示 | 内部寄存器/电流变化 |
| 已有覆盖 | 新领域 | >50% 重叠 |

## 二、八种测试方法详解

### 1. 场景流法
- **适用**: 用户操作 → 系统反馈 → 状态变化的闭环
- **不适用**: 硬件内部保护、纯数据功能、后台任务
- **典型场景**: 按键交互、指示灯、缺水/满冰
- **输出**: 状态转换图 + 每路径一条用例

### 2. 判定表法
- **适用**: 多条件组合、状态×事件交叉
- **不适用**: 线性流程
- **典型场景**: 按键×状态冲突、LED×状态并发
- **输出**: 条件组合表 → 每行一条用例

### 3. 边界值+等价类
- **适用**: 数值输入、定时器阈值
- **不适用**: 业务流程
- **典型场景**: 长按阈值(≥3s)，超时精度(30s/60s/19min50s)
- **输出**: 等价类划分 → 每个等价类 + 2边界值

### 4. 正交排列法
- **适用**: ≥4 个独立因子，全组合≥20 种
- **不适用**: 因子<3 或全组合<10
- **典型场景**: 多状态×多事件×多模式 → 全组合48种 → 正交剪枝到8种
- **输出**: 正交表 → 每行一条核心用例

### 5. 错误推测法
- **适用**: 异步操作/竞态/边界
- **不适用**: 纯同步确定性系统
- **典型场景**: 断电瞬间恰好到预约点、快速连击按键、缺水+满冰并发
- **输出**: 异常场景列表 → 每条一条用例

### 6. 硬件注入法
- **适用**: 传感器触发/硬件保护
- **不适用**: 纯 UI/协议
- **典型场景**: NTC 开路短路模拟、压缩机过载 180V/15A、温度探头 125°C
- **输出**: 硬件注入方案 + 可观测指标验证用例

### 7. 协议测试法
- **适用**: 蓝牙/WiFi/OTA/网关/分布式
- **不适用**: 本地按键/传感器
- **典型场景**: 配网超时/密码错误/A+B手机抢配/断网重连60s周期
- **输出**: 协议状态机 → 每个状态转换一条用例

### 8. CRUD 数据法
- **适用**: 日志记录/图表/持久化
- **不适用**: 实时控制
- **典型场景**: 轮次累计规则、日志离线10条上限、图表30天+12月颗粒度
- **输出**: 数据生命周期 → 创建/查询/更新/边界/异常

## 三、优先级校准规则

### P0 — 必测，阻塞发版
- 设备安全：缺水保护、满冰停止、压缩机过载保护、NTC 异常处理
- 数据安全：WiFi 密码加密存储、配网安全验证
- 不可逆损坏：传感器异常不停止运行
- 出厂默认配置

### P1 — 应测，发版前尽量完成
- 正向功能流程
- 主要异常处理（超时/断网/缺水恢复）
- 状态冲突矩阵
- 跨模块交互

### P2 — 可测，时间允许
- 数值边界（2.9s vs 3.0s）
- 性能指标（亮度衰减、连续运行）
- 罕见场景
- UI 体验细节

## 四、四层校验详解

### 层级 1：单条执行时校验
执行每条用例时逐项检查视觉类/时序类/功能类/传感器类/协议类的具体指标。
详见 SKILL.md §阶段5 → 层级1。

### 层级 2：批量回归校验
每次固件/APP/硬件变更后跑全量 P0+P1。对比上次结果，新出现的 FAIL 即为回归缺陷。
触发条件：固件变更 | APP变更 | 硬件改版 | 每周例行。

### 层级 3：需求追溯校验（发版门禁）
确认每个需求原子都有 PASS 的用例覆盖。
- P0 必须 100% PASS
- P1 ≥ 90% PASS
- P2 ≥ 70% PASS

### 层级 4：缺陷→用例反哺
Bug → 搜索用例库 → 有覆盖？→ 检查为什么没拦住 / 无覆盖？→ 补充用例 → 纳入下次回归。

## 五、用例编号规范

```
TC-{项目代号}-{模块缩写}-V{版本号}-{序号}

项目代号: 产品型号（如 H717D）
模块缩写: 3-4个字母（BTN=按键, IND=指示灯, ICE=制冰, NET=联网, SCH=预约, 
          WTR=缺水满冰, FAC=出厂状态, LMP=冰篮灯, MEM=记忆时钟, RCD=制冰轮次）
版本号: V1, V2, V3...（大版本变更时递增）
序号: 001-999

示例: TC-H717D-BTN-V3-042 = H717D 按键模块 V3 版本第 42 条用例
```
