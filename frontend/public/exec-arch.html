已知风险与缓解
@_bg_sync 线程池耗尽

每个 @_bg_sync 调用 = 新线程 = 新 MySQL 连接。3 种执行器并发时，每任务 4-8 次 DB 操作。多任务排队时线程池可能耗尽，新连接被拒绝。

缓解: 使用连接池 (django-db-connection-pool)；限制并发任务数

MySQL 间歇断连 → 任务挂起

Daphne worker 线程池独立建连。MySQL 重启或网络波动时，@_bg_sync 线程阻塞 TCP 超时 30 秒。不抛异常，任务挂起无结果。

缓解: MySQL 连接重试 + 健康检查；connect_timeout=5

case_ids 跨表查询

API-xxx ID 只能查 ApiTestCase。前端选错 task_type 或 URL 路径错误时，load_definitions 返回空数组，任务立即失败。

缓解: 前端 watcher 按 task_type 调不同 API；后端加校验

recover_orphans 误伤

服务重启时，state_machine.recover_orphans() 将所有 RUNNING 任务标记 FAILED。API 虚拟任务也被误杀。

缓解: 重启前等待任务完成；区分虚拟/物理设备任务
