## ADDED Requirements

### Requirement: 运行中任务详情页按 3 秒轮询

打开处于 `running` 或 `pending` 状态的任务详情页后，页面 SHALL 每 3 秒通过 HTTP 轮询 `GET /api/tasks/{id}/report/` 同步进度，MUST NOT 为此新增 WebSocket 或 SSE 通道。任务进入终态后 MUST 停止轮询。请求 MUST 强制重验证，MUST NOT 复用浏览器缓存中的旧响应。页面隐藏时 MUST 暂停轮询，重新可见时 MUST 立即补拉一次。

#### Scenario: 执行中任务自动出现新轮次

- **WHEN** 用户打开一个状态为 `running` 的执行类任务详情页并保持页面可见
- **THEN** 页面每 3 秒拉一次报告，新轮次与新事件无需手动刷新即出现在「用例执行详情」下
- **AND** 页头「任务状态」始终与接口返回的 `task.status` 一致

#### Scenario: 任务结束后自动停止

- **WHEN** 轮询拿到状态为 `completed`（或 `failed` / `interrupted` / `cancelled`）的报告
- **THEN** 不再发起新的报告请求
- **AND** 摘要区给出最终执行耗时、起止时间、费用与测试结果

#### Scenario: 标签页隐藏暂停并回来自补

- **WHEN** 页面切到后台 2 分钟后切回前台
- **THEN** 后台期间没有任何报告请求
- **AND** 切回后立即发起一次请求，无需再等一个 3 秒周期

#### Scenario: 刷新不复用旧缓存

- **WHEN** 上一次响应带 `Cache-Control: private, max-age=60`，且服务端在此期间已有新事件
- **THEN** 下一次轮询仍拿到本次新增内容，而不是浏览器缓存中的旧响应

### Requirement: 刷新静默且失败退避

自动刷新 MUST 静默完成：MUST NOT 显示首屏骨架、MUST NOT 清空已展示内容、MUST NOT 弹出错误提示。失败时 MUST 保留上一次成功的数据，并按 3 秒 → 6 秒 → 12 秒 → 30 秒退避重试，30 秒封顶。连续失败超过 5 次 MUST 停止自动刷新，并给出可手动重试的提示。

#### Scenario: 请求失败不清空页面

- **WHEN** 某次轮询请求超时或返回失败
- **THEN** 页面仍展示上一次成功的内容，且不出现错误提示或首屏骨架

#### Scenario: 连续失败停止自动刷新

- **WHEN** 报告请求连续失败 6 次
- **THEN** 页面停止自动刷新并显示可手动重试的提示
- **AND** 重试成功后恢复 3 秒间隔

### Requirement: 自动刷新不打断已读位置

自动刷新 MUST NOT 重置用户当前的阅读状态：已展开的用例 MUST 保持展开，用户主动折叠的用例 MUST 保持折叠，当前页码 MUST 保持不变，已展开的事件明细 MUST 保持展开，滚动位置 MUST NOT 因整体重绘跳回顶部。刷新 MUST NOT 改变既有条目的顺序，新轮次 MUST 追加在该用例末尾。只有响应中出现此前不存在的用例时，页面 MAY 回到默认展开态。

#### Scenario: 展开用例后刷新仍保持展开

- **WHEN** 用户展开第 2 个用例，随后发生 10 次自动刷新且用例集合未变
- **THEN** 第 2 个用例仍为展开态，第 1 个用例的展开态与刷新前一致

#### Scenario: 翻页后刷新不跳回第一页

- **WHEN** 用户把一个含 60 轮的用例翻到第 2 页，随后发生自动刷新
- **THEN** 页面仍停在第 2 页，显示「第 2 / 3 页」

#### Scenario: 展开事件明细不被刷新收起

- **WHEN** 用户点开某条事件的「展开全文」，随后发生自动刷新
- **THEN** 该条事件仍为展开状态

#### Scenario: 追加新轮次不改变既有顺序

- **WHEN** 轮询返回的 `rounds` 比上一份多了新轮次
- **THEN** 新轮次追加在该用例末尾，既有轮次的位置与内容不变

#### Scenario: 出现新用例才回到默认展开

- **WHEN** 刷新结果中出现了一个此前不存在的用例
- **THEN** 页面回到默认展开态：只展开第一个用例

### Requirement: 运行中给出可见的刷新信号

任务运行期间，页面 MUST 在「用例执行详情」标题旁显示自动刷新标识，并在摘要区显示最后一次成功刷新的时刻。任务进入终态后该标识 MUST 消失。

#### Scenario: 运行中标识随状态消失

- **WHEN** 报告显示任务运行中，随后变为 `completed`
- **THEN** 运行中先出现「运行中 · 自动刷新」与最后更新时间
- **AND** 变为终态后该标识消失
