## Purpose

按时间展示一次可见任务的智能体事件：每轮回复分成开始、推理、执行、结束，连续增量合并计数，时间写到秒并给出整次执行耗时。

## ADDED Requirements

### Requirement: 可见任务的事件流程

系统 SHALL 通过 `GET /api/reports/task/{id}` 返回当前用户可见任务的事件流程，信封为平铺 `{status, task, rounds}`。任务不存在、编号无效或当前用户不可见时 MUST 返回 404。该接口 MUST 只读，MUST NOT 写业务表。

#### Scenario: 返回已完成任务的流程

- **WHEN** 当前用户打开自己可见的任务 115 的流程
- **THEN** 响应 `status` 为真，`task` 含标题、状态、设备、用例、助手、起止时间与费用，`rounds` 按时间排列

#### Scenario: 他人任务不可见

- **WHEN** 另一个普通用户请求同一任务编号
- **THEN** 响应为 404

### Requirement: 按回复分轮并按阶段分块

系统 SHALL 以每条 `ReplyStartEvent` 开始一轮。一轮内 MUST 按事件顺序排列；阶段相对上一块发生变化时才新开一块。块标题 MUST 为「开始」「推理阶段」「执行阶段」「结束」。连续且同类型、同一步骤与尝试次数的增量 MUST 并成一条，并用 `count` 给出次数。

#### Scenario: 增量合并后阶段交替

- **WHEN** 一轮中依次出现回复开始、三条工具参数增量、工具参数完成、工具结果完成、回复结束
- **THEN** 该轮的块依次为开始、推理阶段、执行阶段、结束，推理阶段的增量条 `count` 为 3，其后仍保留参数完成

### Requirement: 报告页时间到秒并给出执行耗时

事件流程页的任务起止时间与每条事件时间 MUST 显示为 `YYYY-MM-DD HH:mm:ss`。起止都存在时 MUST 同时给出整次任务的执行耗时。没有事件时 MUST 说明这次任务还没有事件记录。

#### Scenario: 同一分钟内的起止可以区分

- **WHEN** 任务于 `2026-10-20 16:51:01` 开始、`2026-10-20 16:51:35` 结束
- **THEN** 页头显示这两个时刻，并显示执行 34 秒

### Requirement: 页头下方展示验收结论

系统 SHALL 在报告页头信息下方展示验收结论。结论 MUST 来自验收角色提交的结构化输出中的是否通过与说明，MUST NOT 从文本日志截取。最后一次判决为通过且任务状态为完成时，结论 MUST 为 PASS；最后一次判决为不通过，或任务状态为失败、取消、停止时，MUST 为 FAIL。每次判决的说明 MUST 全文展示。存在执行交付时 MUST 一并展示。

#### Scenario: 通过的判决出现在页头下方

- **WHEN** 任务已完成，且验收输出为通过、说明为「截图显示用户已登录」
- **THEN** 页头下方的结论为 PASS，并展示该说明全文
