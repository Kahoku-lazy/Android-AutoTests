## Context

动机与映射表见 `proposal.md` - Why。这项债的成因是「技能体系被删掉，但引用它的地方没有跟着改」，且被引用文件里还有更早一批（2026-09-01 / 2026-09-12）就已删除的。

## Goals / Non-Goals

**Goals:**

- 让每个指针都指向**当前存在**的文件；不允许再出现指向不存在路径的引用
- 映射依据可复核：每条都注明是「同名继任者」还是「主题归属」

**Non-Goals:**

- 不恢复被删除的技能与其文件（那是并行工作的决定）
- 不修改被指向文档的内容
- 不顺手统一 `frontend/README.md` 的其它过期描述（只改指针）

## Decisions

### 1. 只改指针，不搬家内容

- **选择**：把悬空路径替换为现址路径，并在少数位置补一句「真相源」标签
- **理由**：本变更的目标是消除悬空引用；内容重组是另一件事

### 2. 无同名继任者时按「主题归属」改

- **选择**：`troubleshooting.md` → `vue-frontend-check/references/checklist.md` 的「常见断裂点」；`database.md` → `apps/AGENTS.md` §1.2 + `ARCH-00` 附录 A.2；`security.md` → `apps/AGENTS.md` §1.2/§1.3 + `config/env.py` / `settings.py` + `frontend/AGENTS.md`
- **理由**：这三类内容没有一对一的继任文件，但主题在现存的权威文档里有落点；映射表里逐条登记，便于复核与调整

### 3. 同批修掉同源悬空 `工具-VUE_API_CONTRACT.md`

- **选择**：`apps/AGENTS.md` 两处契约对照改指 `dev_docs/05-开发与测试/接口文档/API-*.md`（11 份分端点契约）
- **理由**：该文件与本批同源（都被本轮 dev_docs 重组删除），留着会让「契约对照真相源」指向空

### 4. 范围在执行中扩大：把同批发现的其它悬空指针一并收口

- **发现**：清理过程中又暴露三类同源悬空 —— `工具-VUE_API_CONTRACT.md`（dev_docs 重组删除）· `DEVELOPMENT_CHECKLIST.md`（同上）· `.claude/rules/python-code.md`（`ruff.toml` 注释）
- **选择**：一并修掉，因为它们与本变更的目标完全同类（指向不存在的路径）
- **理由**：留下半数悬空等于没修；且这些指针都在同一批「重组后未跟改」的文档里

### 5. 有意保留的两类「看似悬空」

- **`plans/*.md`（gitignored，2 处）**：本地历史计划文档，不在版本控制内，改它价值低且属用户私有计划；在 proposal 的「有意保留」中登记
- **`frontend/README.md` 变更记录中的历史提及**：记录「当时补强了哪些文件」，是历史而非活指针

### 6. 验证口径：新路径必须存在

- **选择**：逐条 `Test-Path` 校验替换后的每个目标路径；再全仓检索旧路径关键字，确认只剩已归档变更文档
- **理由**：这次债的本质就是「引用了不存在的路径」，所以验证必须直接断言「目标存在」而不是只看文本变了

## 模块防火墙自检

- 纯文档与 1 行注释：不涉及跨 App import、写库、引擎边界、通信通道

## Risks / Trade-offs

- [改了指向但目标文档其实不含该主题] → 每个目标都读过其标题/章节名后才采用（见映射表括号内的章节）
- [并行工作又在改这些文档] → 编辑前逐个重新读取；被删技能的目录已不在磁盘，不会再变

## Migration Plan

1. 逐文件读取并替换指针（21 个文件）
2. `Test-Path` 校验所有新目标；全仓检索旧路径
3. 跑 `pytest tests/arch/test_channels.py` 与 `ruff check` 覆盖被改的测试/配置注释
4. 归档；回滚 = `git checkout` 版本控制内的 20 个文件（1 份报告为 gitignored，需手工回退）
