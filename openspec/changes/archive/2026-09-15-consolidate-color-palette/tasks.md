### 实施中修正的问题（如实记录）

1. **锚点值被质心平均污染**：首版实现让锚点吸收近邻后其声明值取**簇质心均值**，导致 `--color-white` 从 `#ffffff` 变成 `#f4f8fb`、纸面 `--paper` 也不再是暖白。已按设计 D2「锚点保留自身取值」修正 **21 行**：`--color-white=#ffffff` · `--color-lime-94=#fffef5`（纸面）· `--color-indigo-13=#1e1e24`（墨色）。
2. **因此产生的预算溢出（需你确认）**：锚点值不再取均值后，少数被吸收成员的色差超出 ΔE≤8——最大 `--color-orange-85` → 纸面 `#fffef5` 的 **ΔE 10.38**，`--color-yellow-70-s25` → `--color-orange-76` 的 **ΔE 9.42**。若不可接受，需把这 1~2 个成员拆回独立色阶（原子数 98 → 99/100）。
3. **命名瑕疵**：ink 锚点所在的簇被命名为 `--color-indigo-13`（中性色却挂 indigo 名）。改名会牵动消费点，本轮未改，留作观察项。
4. **首版 apply 的命名冲突**：两对基色曾撞成同名（`--color-teal-38` / `--color-teal-29` 各 2 条），导致 2 条声明重复、2 个原子被静默覆盖。已按权威声明清单重写原子块：**98 行 / 98 唯一 / 重复 0**，并复核 `解析不到声明 = 0`。
5. **`verify-colors` 的 `hex_bare` 由 0 → 3**：这 3 处是消费位置的 `#fff` 类字面量，此前因 tokens.css 里恰好存在 `#fff` 被判为「已登记」而漏报；调色板现在只有 `#ffffff`，于是被报出。属**报告口径变化**，不是新增缺陷——它们本就在门禁「消费位置裸色字面量 33 处」清单里。
6. 拓扑不变式保持：门禁批 3「非样式表载体 306 处：悬空 0 · 跨边界 0 · 模块声明持字面量 0」通过。
