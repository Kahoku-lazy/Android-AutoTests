## Context

L0 令牌体系已存在且被 8 个模块消费（字体 84 处全部走令牌、字号只有 2 处字面量），说明**方向是对的**；问题集中在「模块自定义色值没有登记处」：`tokens.css` 的 `:root` 只登记了 `--c-*` 模块色、`--app-status-*` 状态色与模块私有家族（`--ai-*` 35 个、`--case-*` 2 个），模块遇到「一个还没被登记的颜色」时就近写了字面量。

## Goals / Non-Goals

**Goals:**

- 让「判罚量规」覆盖本轮实测出来的四类新偏差，使同一份代码两次评审得到同一定级
- 收敛 5 条量规已覆盖的 🟠（低于 12px 的字号、交互/状态色字面量、EP 默认色当模块色、令牌值的字面量副本）
- 把 case-manager 的分类色板从「散落魔法值」变为「集中声明一次」的具名变量，保留其分类语义
- 把复盘与实测数据落进既有 L0–L5 骨架层级图文档，供接手者按层定位

**Non-Goals:**

- 不改 `tokens.css` 的令牌定义与取值（本轮只做消费侧收敛）
- 不把 case-manager 的 7 色测试类型标签压成状态色：那是数据编码色板，不是状态语义（把「照明」标成 danger 是错的）
- 不处理 `:root` 模块私有变量、`--doodle-*` 家族、146 处圆角、94 处废弃别名、41 处自建空态——登记为观察项，另案收敛
- 不动布局、骨架、组件结构与任何 API
- 不追求「全仓字面量归零」

## Decisions

**D1 · 先回写量规，再动代码**

校准 §9 明写「发现 §2 无对应类别 → 暂停定级，先补一行」。本轮有四类偏差（平行色板 / 分类色板散落 / 圆角字面量 / `:root` 模块变量）在 §2 无对应类目，上一轮报告只能标「待定级」。先补量规，本变更的 5 条 🟠 才有可复算的依据。

**D2 · 分类色板登记为例外，而非压成状态色**

`sheet-tag--app/web/api/func/appliance/lighting/biz-app` 是**测试类型**的编码色（7 类各一色），与「成功/失败/危险」的状态语义正交。若强行映射到 `--app-status-*`：一是会复用语义（`lighting` 落进 danger 色），二是分类会撞色、可辨识度下降。故取「保留色相 + 消除散落魔法值」：在该文件内用具名局部自定义属性声明一次，规则里不再出现裸字面量。这与既有 ECharts 例外（图表系列色允许字面量）同一思路，只是把「散落」也一并收敛。

**D3 · 白/中性/危险等语义字面量一律改用既有令牌**

`#fff`→`--app-bg-card` / `--app-text-inverse`、`#e85d5d`→`--app-status-danger-text`、`#ffe8e8`→`--app-status-danger-bg`、`#c0bbb0`→`--app-text-muted`、`#a03030`→`--app-status-danger-text`。这些都是**已有令牌的等价或近似值**，替换后视觉几乎不变（个别略有偏移，已登记浏览器复核项）。

**D4 · `#409eff` 用模块色而不是再造一个蓝**

`device-inspector` 的缩略图徽标 dump/OCR 需要两个可区分底色。dump 改用该模块自己的 `--c-device`，OCR 用 `--c-element`（与原值 `#a78bfa` **完全等价**，纯替换）。不新增令牌，也不把 EP 默认蓝带进主题。

**D5 · 复盘落进既有 L0–L5 文档，不新建报告文件**

该文档已是可交互的骨架层级图（含层勾选与三套页面变体），复盘所需的「层 → 类名 → 职责」对照已在其归属表里。在其后增补实测章节，比另起一份「报告-」文件更省接手者的来回跳转成本，也避免两份文档对同一骨架各写一套。

## Risks / Trade-offs

- [颜色替换会带来轻微视觉偏移（`#409eff`→`--c-device` 蓝转绿、`#f3fffd` 等 tint 改为 `color-mix` 派生）] → 本变更只改色值不改布局；已在 tasks 登记「浏览器复核颜色观感」，静态扫描可保证无遗漏、无语法错
- [分类色板改为局部变量后，两处文件各声明一次，存在重复] → 接受：跨文件共享需要新建模块级样式文件（当前 case-manager 无），收益不抵新增一层；两处声明各自带注释登记色板用途
- [量规 §2 增补后，历史报告按新量规复算会多出一批 🟡/🟠] → 正是目的：量规的价值在于让存量债务可被排序，而不是让它隐形
- [只收敛 5 条 🟠，读者可能误以为「已全仓对齐」] → 报告章节显式列出未收敛的登记观察项与计数，避免过度承诺

## Migration Plan

- 无数据迁移、无接口变更；回滚为 revert 本变更
- 顺序：量规回写 → 令牌替换 → 复盘落盘 → 静态复核 → 归档

## 模块防火墙自检

- 跨 App import：不涉及（只改 `frontend/src/modules` 与文档）
- 禁止跨 App import service / runner / consumer / state_machine：不涉及
- 所有 INSERT / UPDATE / DELETE 收敛到各 App 的 api.py：不涉及，无后端与写操作
- 前端不直连数据库；仪表盘不做写操作：不涉及，不改 `api.ts` / HTTP / store
- 新增跨模块依赖：无（改动方向是**减少**字面量、不改依赖图）
