## Purpose

定义智能体线路连通探测与看板徽标的对外行为：密钥可达与模型可推理分开判定，卡片只呈现三种业务状态，进入看板即完成探测。

## ADDED Requirements

### Requirement: 线路连通探测区分密钥可达与模型可用

系统 SHALL 对线路内每个已配置角色（规划 / 执行 / 校验）做两段探测：第一段验证密钥能访问供应商（模型列表或等价鉴权成功）；第二段对该角色配置的模型名发起极短推理请求。仅当第二段成功时，该角色视为可用于执行任务。系统 MUST NOT 仅凭模型列表 HTTP 2xx 将角色标为可用于执行。系统 MUST NOT 仅因模型名未出现在供应商目录中就跳过推理探测；目录缺失可作为辅助错误信息，最终可用性以推理请求结果为准。

#### Scenario: 目录未列出但推理成功

- **WHEN** 某角色密钥访问模型列表成功，返回的模型 id 列表不含配置的模型名，但对该模型的极短推理请求成功
- **THEN** 该角色视为可用于执行

#### Scenario: 密钥有效但推理余额不足

- **WHEN** 某角色密钥访问模型列表成功，且对该模型的推理请求返回余额不足（如 HTTP 402 Insufficient Balance）
- **THEN** 该角色不得视为可用于执行；线路不得进入「已连通，可执行任务」

#### Scenario: 密钥与推理均成功

- **WHEN** 某角色密钥访问模型列表成功，且对该模型的极短推理请求成功（HTTP 2xx）
- **THEN** 该角色视为可用于执行

#### Scenario: 密钥无法访问供应商

- **WHEN** 某角色缺少密钥、供应商地址不可达、或鉴权失败（如 HTTP 401）
- **THEN** 该角色既不视为密钥可达，也不视为可用于执行

### Requirement: 线路卡片只呈现三种业务状态

系统 SHALL 将一条线路聚合为且仅以下三种业务状态之一，并在看板线路卡片徽标展示对应文案（不得再展示「未检测」「已连通」「已断开」作为业务态）：

1. `unusable`：秘钥已连接，但无法使用 — 至少一个角色密钥可达，且并非全部执行所需角色（规划、执行、校验）推理成功
2. `ready`：已连通，可执行任务 — 规划、执行、校验三个角色均推理成功
3. `offline`：连接失败，小助手断线 — 没有任何角色密钥可达（含全部未配置、全部鉴权失败或网络失败）

系统 SHALL 在 `POST /api/ai/agents/{id}/test`（带 route）与 `GET /api/ai/agents/health` 的线路 health 中返回该三态（字段 `status`），`is_connected` / `connected` MUST 仅在 `ready` 时为 true。

#### Scenario: 进页后徽标必为三态之一

- **WHEN** 用户打开智能体看板且线路 health 无有效三态缓存
- **THEN** 系统对该线路执行探测，完成后卡片徽标只显示上述三种文案之一

#### Scenario: 密钥通但任务不可跑

- **WHEN** 三个角色密钥均可达，但任一角色推理失败（含余额不足、推理 HTTP 非 2xx）
- **THEN** 线路 `status` 为 `unusable`，徽标文案为「秘钥已连接，但无法使用」，`is_connected` 为 false

#### Scenario: 三角色均可推理

- **WHEN** 规划、执行、校验三个角色的极短推理均成功
- **THEN** 线路 `status` 为 `ready`，徽标文案为「已连通，可执行任务」，`is_connected` 为 true

#### Scenario: 无法建立密钥连接

- **WHEN** 线路三个角色均未配置密钥或均鉴权/网络失败
- **THEN** 线路 `status` 为 `offline`，徽标文案为「连接失败，小助手断线」，`is_connected` 为 false

#### Scenario: 探测进行中不是第四业务态

- **WHEN** 用户点击「校验」或看板正在等待探测响应
- **THEN** 界面可显示过程文案「校验中…」，MUST NOT 把「未检测」作为业务状态写入 health 或徽标
