## Context

动机与证据见 `proposal.md`。方案需要的当前状态：

- 守护模块 `tests/graybox/unit/test_frontend_api_paths.py` 的扫描是**逐行**的：
  `CALL_RX` 在一行内匹配"调用 + 字面量"。实测因此漏掉 **2 处前端**（`toolbox.ts:219, 229`）
  与 **15 处测试**调用点（含 `tests/api/conftest.py:34`）。
- `tests/api/conftest.py:34` 的调用与字面量分处两行，是本次要修的违规点。
- 精确扫描（按调用形态、跨行）实测各面规模：
  | 面 | 规模 | 缺尾斜杠 |
  |---|---|---|
  | `frontend/src` | 136 | 0 |
  | `tests/**/*.py` 中的 `/api/` 调用 | 41 | 1（+1 故意负向） |
  | `tests/api/case/*.yaml` 的 `path:` | 45 | 0 |
  | `tools/seed_api_endpoints.py` | 183 | 0 |
- `tests/graybox/unit` 下没有非测试的辅助模块（只有 `__init__.py` 与 `test_*.py`），
  跨模块复用扫描器没有现成位置。
- 端点资产目录有 **52 个不同路径（61 处）已无法 resolve**，与尾斜杠约定无关。

## Goals / Non-Goals

**Goals:**

- 让守护**不再因源码换行而漏扫** —— 这是本次缺陷能溜过去的直接原因。
- 覆盖全部四个调用面，且覆盖面本身可审计（面清单与规模下限都写在测试里）。
- 让负向用例的例外**可见、带理由、进 diff**。
- 让 `tests/api` 的 `auth_session` fixture 恢复可用。

**Non-Goals:**

- 不修端点资产目录的 52 条路由漂移（独立缺口）。
- 不为守护引入 YAML 解析库或前端测试基建。
- 不改变既有断言的强度：合并后尾斜杠、resolve、认证链路命中断言一条都不能少。

## Decisions

### D1 按"调用形态"扫整份文件文本，而不是按行

把源文件整体读入后用支持跨行的正则匹配 `.get(/.post(...(` 直到第一个引号字面量，行号由匹配起点反推。
这是漏扫根因的直接修法。

- 备选 (a)：保留逐行扫描，额外拼接"以 `(` 结尾的行 + 下一行" → 只能覆盖一种换行形态
  （参数前有换行、多个参数各占一行等仍会漏），治标不治本。
- 备选 (b)：用 AST / TS 解析器 → Python 侧没有 TS 解析器；Python 侧用 AST 可行但前端仍要另写一套，
  收益不抵复杂度。当前调用形态高度统一，正则足够。

### D2 合并为单一守护模块，而不是每个面一个文件

跨面共享同一个"调用点识别 + 字面量提取"实现。`tests/graybox/unit` 下没有辅助模块的先例，
与其为共享扫描器新造一个 `_xxx.py` 约定，不如把四个面放进同一个测试模块：
它们断言的是**同一条需求**（调用方遵循唯一写法），本就该在一起。

- 备选 (a)：每个面一个文件 + 复制扫描逻辑 → 重复实现，且四面会各自漂移。
- 备选 (b)：把扫描器放到 `tools/` 下让测试 import → 让测试依赖工具脚本，且 `tools/` 的定位是
  数据/资产脚本，不是测试基建。
- 代价：删除既有模块 `test_frontend_api_paths.py`。其 5 条前端断言与认证链路断言必须全部迁移，
  不得减少（列入 tasks 的验证项）。

### D3 例外用 (文件, 字面量, 理由) 三元组登记在测试内

不用行号（会漂移），不用整文件白名单（等于关掉该文件）。清单本身是测试常量，
新增例外必然进 diff、被 review。

### D4 端点资产目录只断言尾斜杠，不做 resolve

目录里 52 个路径已失效。若对它做 resolve 断言，只能二选一：修 52 条（远超本单）或加 52 条白名单（等于关掉断言）。
因此本单对它只断言写法，并在测试 docstring 里**写明"目录与路由表的一致性当前不成立"**，
把它作为独立缺口留给后续变更 —— 而不是让守护沉默。

### D5 面清单与规模下限一起登记

MIN_COUNTS 按面记录实测规模。识别规则退化（正则写坏、路径改名）会让计数骤降，
测试随即失败并提示"检查识别规则"，而不是给出虚假的"全部一致"。

### D6 YAML 用行级取 `path:`，不引入 YAML 解析

`tests/api/case/*.yaml` 中 `path:` 是单行标量，无跨行风险；用正则可避免引入解析库
与"注释/引号风格"的格式耦合。若将来出现跨行 `path:`，D5 的下限自检会先失败。

## 模块防火墙自检

- **跨 App import**：无新增。改动集中在 `tests/`（不属于任何 App）与一处测试夹具路径字符串。
- **禁止跨 App import service/runner/consumer/state_machine**：无。
- **写库收敛**：不触碰任何 INSERT/UPDATE/DELETE，无 Model 改动，无迁移。
- **前端不直连数据库**：不改前端产品代码。
- **结论**：不触碰任何红线。

## Risks / Trade-offs

- **[跨行正则可能吞掉过多内容]**（例如括号内嵌套字符串）→ 只取调用括号后的**第一个**引号字面量；
  无法判定时显式失败并列出该处，不跳过。
- **[合并模块让 diff 变大、可能顺手丢断言]** → tasks 里把"原 5 条前端断言 + 7 条鉴权姿态断言不得减少"
  写成可验证项（对照删除前后 `pytest` 的通过条数与测试名）。
- **[例外清单腐化]** → 每条强制带理由；清单规模体现在测试常量里，扩充即进 diff。
- **[目录漂移被误读为已解决]** → 在守护 docstring、proposal「新发现的缺口」两处写明"一致性不成立"。
- **[修改主规格既有需求时弱化它]** → MODIFIED 块从主规格整段复制，只改两处（场景替换、面枚举）；
  未删除任何既有约束，且新增了"负向用例必须显式登记"这一条。

## Migration Plan

1. 新增合并后的守护模块（跨行感知 + 四面 + 例外清单 + 下限自检）—— 预期**红**，且只报出 `conftest` 那一条。
2. 删除旧的前端守护模块，确认断言数量与强度未降。
3. 修 `tests/api/conftest.py` 的登录路径 —— 守护转绿。
4. 更新 `tests/AGENTS.md`。
5. 跑门禁并确认 `tests/api` 的 16 个 error 消失。

**回滚**：改动为测试文件与一处夹具路径字符串，`git revert` 即可；无数据、迁移、配置或依赖影响。
