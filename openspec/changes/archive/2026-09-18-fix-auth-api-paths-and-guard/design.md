## Context

动机与缺陷证据见 `proposal.md`。方案需要以下当前状态与约束：

- **后端侧已是正确基线**：`APPEND_SLASH=False`，路由表内不存在无尾斜杠的 `/api/` 路由，缺失尾斜杠是确定的 404。
  本变更**不改后端任何文件**。
- **前端没有测试运行器**：实测 `frontend/src` 下 0 个 `*.spec.ts` / `*.test.ts`，无 vitest/jest 配置。
  因此"在前端加一条单测"这条路当前不存在。
- **`tests/` 目前不读前端源码**：实测全仓 `tests/` 对 `frontend/` 的引用为 0 处 —— 本变更会引入一个新范式。
- **已有的端到端覆盖是可选件**：`tests/e2e/test_example_e2e.py::test_login_and_enter_dashboard` 覆盖的正是这条链路，
  但它需要 `TEST_ADMIN_PASSWORD` 且前后端必须在跑，`conftest.py` 在不满足时 `pytest.skip`。
  这就是缺陷能合入的直接原因：唯一的守卫默认不执行。
- **默认门禁是** `python -m pytest tests/graybox/unit`（见 `tests/AGENTS.md`），守护必须落在这里才有意义。

## Goals / Non-Goals

**Goals:**

- 让"前端路径字面量 ↔ 后端路由表"的不一致在**默认单测套件**里失败，且失败信息直接指出文件、行号与原文。
- 守护检查零外部依赖：不启服务、不需凭据、不联网，秒级完成。
- 认证端点的鉴权姿态成为被断言的不变量，而不是靠人记住的隐性知识。

**Non-Goals:**

- 不引入前端测试基建（不在本变更里加 vitest / 前端运行器 / package.json 改动）。
- 不做通用的"前后端契约对拍框架"：本次只覆盖 HTTP 路径这一条，其余（字段、文案、鉴权）各自独立评估。
- 不用静态守护替代 E2E：静态检查回答"路径对不对"，E2E 回答"接线通不通"（代理、方法、载荷）。
- 不修改 `tests/e2e` 的 skip 行为（凭据与 CI 方案是独立议题，见 Open Questions）。

## Decisions

### D1 守护放在 Python 侧，而不是前端侧

断言的核心是"这条路径在后端能不能 resolve" —— 那只有后端能回答。前端侧哪怕建了运行器，也只能验格式（"以 / 结尾"），
验不了"后端到底有没有这条路由"，而后者才是真正被违反的契约。

- 备选 (a)：引入 vitest + 前端断言字面量格式 → 只能验格式，且要新建基建。
- 备选 (b)：只靠已有的 E2E 登录用例 → 默认 skip，等于没有守卫（这正是缺陷成因）。
- 备选 (c)：写进 `tools/` 或独立 CI 脚本 → 不在默认测试套件里，仍会被忽略。
- 取舍：测试需要读 TS 源码做跨语言静态扫描，扫描器的脆弱度是主要风险（见 Risks）。

### D2 识别规则最小化，且例外必须显式

只把**作为 `.get` / `.post` / `.put` / `.patch` / `.delete(` 或 `fetch(` 首个参数出现的 `/` 开头字面量**纳入断言；
模板字面量取其静态前缀。例外白名单只含前端自身路由（`/login`、`/dashboard`），**写死在测试内** ——
新增例外必须改测试、进 diff、被 review，不允许静默跳过。

- 备选 (a)：扫描所有 `/` 开头字符串 → 大量误报（前端路由、CSS 路径、图标标识）。
- 备选 (b)：维护一份"应存在的端点清单" → 那就不是守护而是复制，清单本身会漂移，等于把问题挪个地方。
- 一致性要求：识别正则与 `temps/login-stack-map/collect_stack_facts.py` 中的采集器保持同源，
  避免"图里统计 134 条、测试却看到别的数字"这类自相矛盾。

### D3 逐条 resolve，而不只检查尾斜杠

尾斜杠只是本次的成因。真正的契约是"这条路径在后端存在"。只查格式会漏掉
"两端都改了、但改得不一样"这一类。代价是测试与路由表绑定：后端删改路由时该测试会失败 ——
这是**期望行为**，契约变更本就要求调用方同步。

### D4 鉴权姿态用等价关系断言，而不是逐条列举

断言 `permission_classes` 含 `AllowAny` **当且仅当** `authentication_classes` 为空。
这条不变量对 `apps/accounts` 下**任意** APIView 成立或失败，因此未来新增端点时天然被覆盖；
逐条列举今天这 5 个端点则不会。

### D5 修字面量，而不是恢复容错

容错中间件已被上一变更删除，恢复它等于推翻 `api-path-convention` 的取舍。
也不引入运行期补斜杠的 `apiPath()` 拼接函数 —— 那会重新制造"两种写法都对"的幻觉。

### D6 视图类经 URL conf 解析取得，不直接 import

鉴权姿态断言需要拿到视图类。通过 `django.urls.resolve(path).func.view_class` 取得，
而不是 `from apps.accounts.views import ...`。两个好处：不引入任何跨 App import；
断言的是**实际挂载**的视图，而非源码里定义但可能未被挂载的类。

### D7 守护测试先跑红，再修字面量

实施顺序是"先加守护、看到它精确报出 5 处失败，再修字面量让它转绿"。
若先修后加，就无法证明这条守护真的能发现本缺陷 —— 而"守护本身有效"正是本变更的主要交付物。

## 模块防火墙自检

- **跨 App import**：无新增。唯一新增的 Python 文件位于 `tests/`（不属于任何 App），
  经 URL conf 与 `get_resolver()` 读路由表，属测试对实现的只读引用，与既有
  `tests/arch/test_view_write_convergence.py`、`tests/graybox/unit/test_api_path_convention.py` 同性质，
  不构成 App 之间的 import 依赖。
- **禁止跨 App import service/runner/consumer/state_machine**：无。
- **写库收敛**：本变更不触碰任何 INSERT/UPDATE/DELETE，无 Model 改动，无迁移。
- **前端不直连数据库**：前端改动只是两个文件里的字符串字面量；HTTP 出口仍是 `shared/api-client` 唯一出口，
  未新增任何调用通道。
- **结论**：不触碰任何红线。

## Risks / Trade-offs

- **[静态扫描器对 TS 语法过敏]**（新增写法如泛型嵌套、跨行调用可能漏扫或误扫）
  → 只依赖最小语法假设（调用形态 + 引号包裹的字面量），不做 TS 解析；扫描器与已实测过的产物采集器同源；
  失败输出带 文件:行 + 原文，误报可人工一眼判定。
- **[例外白名单变成后门]** → 白名单写死在测试文件内且仅含前端路由；任何新增例外都会出现在 diff 里被 review。
- **[`tests/` 读前端源码是新范式，可能被认为越界耦合]** → 在 `tests/AGENTS.md` 明确记录该范式的边界
  （只读、只做路径一致性断言、不反向影响前端产物），并在测试 docstring 说明理由。
- **[后端改路由名会让该测试失败，被误判为"测试太脆"]** → 这是设计意图：契约变更必须双边同步。
  失败信息直接指出"哪个前端文件哪一行、拼出的路径是什么、后端有没有"，使同步成本可见。
- **[带动态段的路径字面量（模板字面量）只能取静态前缀]** → 动态段替换为占位值后再 resolve；
  若某条路径因动态段无法判定，测试必须**显式失败并列出该条**，而不是跳过（拒绝静默忽略）。
- **[与 E2E 职责重叠的误解]** → 两者互补且都保留；本变更不替代也不修改 E2E。
- **[未来若前端改为从 OpenAPI schema 生成路径]** → 该守护会自然失去意义，届时删除即可；现在不预设抽象（YAGNI）。

## Migration Plan

1. 新增守护测试并运行 —— 预期**红**，且失败项精确列出认证链路的 5 处。
2. 修正 5 处字面量（`shared/api/auth.ts` ×4、`shared/api-client.ts` ×1）—— 守护转绿。
3. `tests/AGENTS.md` 追加范式说明。
4. 端到端确认：登录 / 注册 / 续期 / 登出 / 身份五个入口恢复可用。

**回滚**：改动仅为两个前端文件中的字符串字面量与一个新增测试文件，`git revert` 即可；
无数据、迁移、配置或依赖影响。
