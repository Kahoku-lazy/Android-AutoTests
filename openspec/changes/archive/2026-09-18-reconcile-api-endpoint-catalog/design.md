## Context

动机与实测见 `proposal.md`。方案需要的当前状态：

- 目录文件 `tools/seed_api_endpoints.py`：187 个 `create_endpoint` 条目，**大量调用是跨行书写**
  （`create_endpoint(\n  g, "GET", "名", "url", "desc"\n)`）。用单行正则只能解析到 **41 条**，
  这是本次对账必须先解决的问题。
- 61 条失效条目的分类见 proposal 的表。
- 守护 `tests/graybox/unit/test_api_path_callers.py` 目前对目录面**只断言尾斜杠**，
  并在 docstring 里显式说明原因（避免用 61 条白名单把 resolve 断言绕过去）。

## Goals / Non-Goals

**Goals:**

- 目录与路由表一致，且由默认门禁持续保证。
- 对账的每一步都可复核：改了几条、删了几条、复核结果是多少。

**Non-Goals:**

- 不改后端路由、不给目录加 `is_implemented` 之类的字段。
- 不补齐新端点的条目（那是"目录覆盖率"问题，与"漂移"不同）。
- 不把目录改成从路由表自动导出（独立评估）。

## Decisions

### D1 删除，而不是标记

文件 docstring 明确其定位是 "the platform's own API catalog" —— 镜像语义。
指向不存在端点的资产在接口测试里不可执行，保留只会让目录失去可信度。

### D2 只对"可确认"的条目改名

仅 `/api/ai/auth/*` 这 5 条改名到 `/api/auth/*`，依据是网关 `RETIRED_AUTH_PATHS` 恰恰列出了这 5 条
（说明它们是**被替换掉**的旧路径），且目录中不存在 `/api/auth/*` 条目（不会产生重复）。
其余一概删除 —— 靠"末段相同"之类的模糊匹配去猜改名，会制造新的谎言。

### D3 空分组/目录一并删除

删完条目后，`create_group` / `create_folder` 若不再被任何语句引用，其声明一并删除（固定点迭代）。
空壳分组在接口测试界面上是噪音，也会掩盖"这块能力已经没了"。

### D4 用括号配对解析，不用正则

本文件七成以上的调用跨行。对账脚本与守护都必须按"调用形态"解析（与 `test_api_path_callers.py`
的跨行修法同源），否则会像上次那样只看到 41/187。

### D5 目录纳入 resolve 断言，并按实测调整规模下限

对账后四个面全部参与 resolve；目录面的规模下限从 175 调整为 120（实测 127）。
下限仍起"解析规则退化即失败"的作用，防止目录被解析成空集却显示"全部一致"。

## 模块防火墙自检

- **跨 App import**：无新增。对账脚本读 `tools/seed_api_endpoints.py`（文本）与 Django 路由表；
  守护只读源码文本。
- **禁止跨 App import service/runner/consumer/state_machine**：无。
- **写库收敛**：本变更**不执行** seed 脚本、不写数据库；只改其源码文本。运行时由使用者自行执行。
- **前端不直连数据库**：不涉及前端。
- **结论**：不触碰任何红线。

## Risks / Trade-offs

- **[删多了：把仍在用的条目删掉]** → 对账以 `resolve()` 为唯一判据，删完复核"失效 0、条目 131"；
  且改动全部是删行与 5 处 URL 字符串，`git diff` 可逐行审阅。
- **[改名改错]** → 只改 5 条且有网关 `RETIRED_AUTH_PATHS` 作证；目录中无同名冲突。
- **[空分组误删]** → 固定点只在"变量不再被引用"时才删；被其他语句引用的分组/目录（如 `parent=f_runner`）
  会因仍被引用而保留。
- **[规模下限调低掩盖解析失效]** → 下限取实测的 ~94%，且另有"四个面都非空"的提取自检。
- **[该文件未被执行验证]** → 本变更不运行 seed（会写库）；语法与解析由 `ruff check` 与守护覆盖，
  端到端使用由需要该资产库的人执行。

## Migration Plan

1. 运行对账脚本（改 5、删 56、清理 11 个空分组）。
2. 复核：解析结果为 131 条目、失效 0。
3. 守护升级为四面 resolve；注入一个假路径证明它会失败，再还原。
4. 更新 `tests/AGENTS.md`；跑门禁。

**回滚**：`git revert` 即可恢复全部条目；无数据、迁移、依赖影响。
