## Context

见 proposal.md — Why。现状与约束（均实测）：

1. `page.screenshot()` 默认截**视口**（pytest-playwright 默认 1280×720），与 `locator.bounding_box()` 的坐标系一致 —— 这是标注能对齐的前提。
2. 单张 1280×720 PNG 约 219KB；若每步一张原图，15 条用例约 150 步 → 33MB，报告不可接受，必须压缩。
3. Pillow 12.1.1 已装；系统中文字体 `C:\Windows\Fonts\msyh.ttc`、`simhei.ttf` 存在（PIL 自带位图字体渲染不了中文）。
4. 报告设计须遵循 `.agents/skills/html-report`（animal-island-ui）：暖木色/羊皮纸配色、圆角 ≥12px、body 字重 500、卡片无阴影 hover 上浮 2px、禁止冷蓝聚焦环。

## Goals / Non-Goals

**Goals**：每步一张「看得懂」的截图（标注动作位置与内容）+ 一个自包含 HTML 报告（步骤 + 缩放截图 + 点击看大图）。

**Non-Goals**：不改被测页面（不注入高亮 DOM）、不做视频、不做像素级视觉回归、不接管断言逻辑（断言仍是 Playwright 的 `expect`）。

## Decisions

### D1 标注画在图片上（Pillow），不注入页面 DOM

**替代方案**：往页面里插一个高亮 div 再截图。**否决理由**：注入的元素会出现在截图里、可能影响布局与被测行为（比如遮住按钮导致点击失败），而且「测试污染被测对象」是更严重的边界问题。

**代价**：需要在截图后做一次图像处理（~30ms/张），并自己处理中文字体。

### D2 每步先动作后截图，标注用「动作前」测得的坐标

点击/输入的坐标来自动作**之前**的 `bounding_box()`，而截图在动作**之后**。对登录页这类动作不引起布局位移的场景是准确的；若某步会引发跳转/重排，标注框可能落在旧位置 —— 这类步骤（如跳转后）我们用无标注的 `shot()`，不硬套坐标。

### D3 断言用元素局部放大截图（`inspect`），不重复整屏

整屏截图在「按钮点亮 / 文案出现」这类断言上与上一步几乎无差别，既占体积又没信息量。局部截图裁到元素外扩 24px，能看清按钮态与提示文案，体积也只有整屏的几分之一。

### D4 图片统一压成宽 1100px 的 JPEG（q=82）

**替代方案**：保留全分辨率 PNG + 只在小图里缩放。**否决理由**：报告体积才是矛盾的主要方面（33MB → 约 8MB），且 1100px 宽足够读清界面文字；需要极致清晰时有 Playwright 的 trace/原图路径可查。

### D5 报告是自包含目录（HTML + shots/），不是单文件 base64 内联

**替代理由**：内联 base64 会让单个 HTML 膨胀到十几 MB，浏览器打开卡顿，也无法单独保存某张图。目录形式下 HTML 只有几十 KB，图片懒加载（`loading="lazy"`）。

### D6 报告层失败不静默吞掉

记录器里不做 `try/except` 兜底：截图或标注失败就抛出，让用例红掉。理由是「报告缺失」本身就是要修的问题，静默吞掉会得到一份看着完整、实则缺步的报告。唯一例外是 `pytest_runtest_makereport` 里已有的失败截图钩子（它已经存在，且失败时不能让二次异常掩盖原始失败）。

## Risks / Trade-offs

- [中文字体缺失（非 Windows 机器）] → 字体候选列表逐个探测，全失败则退回 PIL 默认位图字体（中文会显示为方块），同时报告仍生成 —— 这是可观测的降级，不是静默错误。
- [用例运行变慢] → 每步多一次截图 + 压缩，实测基线 40s，预计增至 ~90s；相对可观测性收益可接受。
- [报告目录被 gitignore] → 与 `tests/reports/api.html` 同一约定，属可随时重新生成的产物。
- [坐标标注不适用于引发跳转的步骤] → 见 D2，这类步骤不套坐标。
