## Context

- 现状（上一单落地后）：`fix-dangling-snapshot-media` 在**删除侧**判定引用并保留文件，止住了继续丢；但元素定位记录仍指向 `inspector/**`（`Page.screenshot_path` / `Element.thumbnail_path` 由导入原样写入），两个模块的资产依旧共命，且检查器必须读对方的数据表才能安全删除。
- 导入流程（读码）：`apps/element_locator/api_snapshot.py` 的 `import_snapshot_page` —— 新建页面时 `Page.objects.create(..., screenshot_path=screenshot_path)`（`:132-144`）；已有页面时仅在 `screenshot_path` 为空才补（`:110-112`）；元素按 `(page, resource_id, bounds)` upsert 并写入 `thumbnail_path`（`:170,173-185`）。页面 ID 只有在 create/fetch 之后才可知。
- 媒体根：`MEDIA_ROOT=D:\Govee\data\uploads`（仓库外，dev）；生产同样由部署提供，因此复制必须走相对路径 + `settings.MEDIA_ROOT` 拼接。
- 已在本设计中被否决的一个实现细节（值得留档）：若按「元素序号」命名副本（`el_<i>.png`），当同一页面第二次导入的元素集合或顺序变化时，`el_0.png` 会被第二次导入的另一个元素覆盖，而只存在于第一次导入的元素行**仍指向 `el_0.png`** → 串图。upsert 键是 `(page, resource_id, bounds)`，副本命名必须与之一致。

## Goals / Non-Goals

**Goals:**

- 新导入的元素定位记录不再引用检查器媒体路径
- 删快照后已保存页面仍可正常显示（不依赖删除侧的判定）
- 副本命名与元素行 1:1，重复导入不串图

**Non-Goals:**

- 不做成批存量回填（不写迁移、不改历史行）；同一页面**再次导入**时会就地自愈（复制并改指副本）
- 不恢复已丢失的媒体（源文件不存在无从复制）
- 不做孤儿副本回收（登记为后续项）
- 不改 `get_page_full` / 端点契约 / 前端回看链路

## Decisions

**D1 副本路径：`locator/pages/<page_id>/screen.png` + `el_<安全前缀>_<键哈希8>.png`**
缩略图文件名由 upsert 键 `(resource_id, bounds)` 派生（`sha1("rid|bounds")[:8]`），前面保留一段可读的资源 ID 安全前缀（非 `[A-Za-z0-9_.-]` 替成 `_`，截断 32 字符）。这样同一元素每次导入稳定命中同一文件，且不同元素不会互相覆盖。
备选：按序号 `el_<i>.png` → **否决**（Context 里记的串图缺陷）；备选：按导入时间戳建子目录 → 可行但会持续堆积且无法从路径看出「当前是哪一份」，可读性差；备选：按内容哈希命名（同一图只存一份）→ 记为可选优化，本轮不引入（缩略图很小，收益是磁盘，代价是路径不可读）。

**D2 复制时机：页面 ID 已知之后，元素写入之前**
新建页面先落库（此时 `screenshot_path` 仍是原值）→ 复制截图 → 回写副本路径；元素在循环内先复制、再把副本路径写进 `fields`。不存在「先复制后建行」的做法，因为目录名依赖 `page_id`。

**D3 源文件缺失 → 保留原路径 + 告警**
不写空路径：空路径会把「曾经有但已丢失」伪装成「从未有过」，与前端「失效媒体降级」的语义冲突。
备选：写入指向不存在副本的路径 → 否决（伪造路径）。

**D4 复制 IO 失败 → 告警并保留原路径，导入继续**
元素数据是导入的主产物；媒体复制失败不该让整次导入失败，但必须有痕迹（`logger.warning` + `exc_info`）。与既有 `_crop_thumbnail` 的 best-effort 风格一致。
备选：抛错让导入失败 → 否决（会丢掉用户已经勾选保存的元素数据）。

**D5 已有页面的截图也参与自愈，但不覆盖内容语义**
只要页面当前的 `screenshot_path` 不是元素定位自有路径且源文件存在，就复制并改指副本（重复导入同一页面即完成自愈）；若源文件不存在则保持原样。这不改变「已有内容不覆盖」的规则实质（图还是那张图，只是归属变了）。

## 模块防火墙自检

- 跨 App import：零新增（改动全在 `element_locator` 内部；检查器侧不动）
- 写库收敛：改的是 `element_locator` 自己的 api 层（`api_snapshot.py` 属 api 层，写库收敛点）
- 新增文件系统写入：`locator/pages/**` 由本模块拥有，属于「本 App 资产自己落盘」，不是跨模块写
- 前端不直连数据库：不涉及
- HTTP 出口 / 端点契约 / 信封：不变
- 迁移：零

## Risks / Trade-offs

- [磁盘增长：每次导入多一份截图 + 每元素一份缩略图] → 缩略图 ~48px 级别，单页 100 元素量级可接受；孤儿回收登记为后续项
- [回滚后行为] → `git revert` 只回滚代码；已经复制并写进 DB 的历史路径不会复原，但功能不受影响（副本仍可访问）。需在回滚说明里写明「已导入记录保留副本路径」
- [副本路径写入 DB 后，若媒体目录被清盘仍会失效] → 语义已从「被别的模块删」变为「自有资产被清」，前端降级文案仍适用
- [测试需要 tmp MEDIA_ROOT + 真实文件] → 集成测试用 `tmp_path` + `override_settings(MEDIA_ROOT=...)`，不碰真实媒体目录
- [重复导入的元素集合变化造成孤儿文件] → 明确登记为后续项（与孤儿回收一起做），不影响正确性

## Migration Plan

1. `api_snapshot.py` 加复制工具函数与两处调用（页面截图 / 元素缩略图）
2. 扩展集成测试 4 例：路径改指 / 删源快照后副本可用 / 源缺失保留原路径 / 重复导入不串图
3. 真机端到端：抓快照 → 保存为新页面 → 核对库里路径在 `locator/pages/<id>/` 且媒体 200 → **删除该快照** → 页面回看截图与缩略图仍正常
4. 门禁：`manage.py check` + `ruff` + `pytest`（新老用例）+ `lint:styles` + `vite build`
5. 回滚：`git revert`；已导入记录的副本路径保留（功能不受影响）
