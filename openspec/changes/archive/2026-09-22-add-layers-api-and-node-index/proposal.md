## Why

前端要按新分组展示「解析出的全量元素」，但今日快照只落**展示裁剪后**的集合（实测一页 95/140），被裁掉的 45 个元素在库里根本不存在——前端无从显示，圈选图上也不会有「被裁」标记。同时后端目前既没有分层结构，也没有筛减能力：分层只存在于工具脚本，筛减全靠前端本地算。

本变更把「全量节点索引」与「分层查询 + 筛减」补进平台，作为前端改版的数据底座。

前置变更：`add-element-layering-core`（引擎原始 XML 取数 + 算法层分层与主定位规则）；本单在其之上提供端点。

## What Changes

- **快照落库口径扩展**：新增「全量节点索引」字段，保存**未经展示裁剪**的节点几何与属性（类名、资源标识、文本、内容描述、坐标、层级、序号、七项交互标志、是否被展示裁剪保留）。**BREAKING（数据形态）**：`di_snapshots` 新增字段并配套迁移。
- **不含定位候选**：索引只存节点本身，XPath 候选由算法层按需即时生成（实测：全量节点 58.5 KB，含全部候选则为 134.6 KB，差 2.3 倍）。
- **新增分层查询端点**：`GET /api/inspector/snapshots/{id}/layers/`，返回两级分组摘要与元素条目，并支持筛减参数（一级分组 / 二级分组 / 交互标志 / 关键词 / 是否被保留 / 主定位是否稳定 / 分页）。
- **分层即时计算、不落库**：分组是可从节点索引重算的派生数据（示例页重算 <1ms），不新增分层表，避免两处真相源。
- **历史快照降级而非报错**：已有快照没有全量索引，端点 MUST 按保留集回退并在响应中如实标注数据来源。
- **保留既有 6 层分区端点**：本页不再使用，但端点与实现不动（冻结而非移除）。
