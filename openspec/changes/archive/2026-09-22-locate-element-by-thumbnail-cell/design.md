## Context

- `ScreenshotView.vue` 的绘制：底层缓存画「当前分组全部框」（实线 / 虚线），可见层只画 hover（橙色）与 `props.selected`（`rgba(231,76,60,0.4)` 填充 + `#e74c3c` 3px 描边）；`watch(() => props.selected)` 会重绘并在元素位于视区外时 `scrollToRow` 平滑滚动过去。**本变更不动这一层。**
- `StructureAnalysisPanel.vue`：行的紫色填充来自 `isRowSelected(row)`（`props.selected._idx === row._idx`）；写入选中只有两处 —— 表格双击数据格 `emit('select', row)`、以及 `index.vue` 把 `ScreenshotView` 的 `click-element` 也接到同一个 `store.selectElement`。因此**只要表格也 emit select，画面高亮自动生效**（同一状态，天然对称）。
- `ROW_DBLCLICK_SKIP` 已含 `'thumbnail'`，故双击缩略图不会经行级双击再改一次选中。
- 列宽与冻结列口径登记在 `constants.ts`；缩略图格现在是 `<div class="sap-thumb-wrap">`（仅有图时渲染）+ `<span class="sap-thumb-empty">—</span>`。
- 设备检查器当前不放缩略图数据（用户确认），故「有图」分支目前只在其他形态下可达。

## Goals / Non-Goals

**Goals:**

- 一次单击（左键、缩略图列、整格可点）即在画面上高亮该行元素对应的矩形框，并让该行呈选中态。
- 不改动画面的绘制逻辑、不改其它单元格的单击语义、不动后端。

**Non-Goals:**

- 不新增独立的「定位」视觉（用户选择复用现有选中高亮）。
- 不把单击选中扩大到整行或其它列（规格明确其余单元格单击不得改高亮）。
- 不复活缩略图数据（该列在检查器里不放截图数据）。
- 不为「零宽高元素」补视觉（规格既有条款：不画框）。

## Decisions

**D1 复用 `selected` 这一个状态，而不是新增「定位中」状态。** 截图 → 表格（单击矩形给行紫色填充）已经在用 `selected`；表格 → 截图走同一个状态才能天然对称，也不必维护两套高亮与「谁覆盖谁」的规则。备选：新增独立定位状态 → 否决（要处理两套状态的清除与叠加，收益为零）。

**D2 点击目标是整格，不是图片。** 该列当前没有缩略图数据、渲染的是占位 `—`；如果只把事件绑在 `<img>` 上，用户实际要点的是空白与占位文本。故用一个铺满单元格的定位层承载点击（与「元素名称」格的既有做法同形）。

**D3 放大预览移到双击。** 单击已被定位占用；预览必须有图才有意义，绑双击后「一次点击只有一个含义」，且不删除既有能力。备选：单击同时预览 + 高亮 → 否决（一次点击两种反馈，且当前无图时预览无意义）；备选：删掉预览 → 否决（超出用户请求，且规格里仍有「放大预览失效仍有占位」条款）。

**D4 事件加 `.stop`，不依赖行级事件。** 行级 `row-dblclick` 对缩略图列本来就被跳过；`.stop` 保证单击不会冒泡到表格的其它监听（也与名称格的既有写法一致）。

**D5 用例挂 AppTable 替身并渲染 `cell-thumbnail` 插槽。** 既有面板用例的替身只渲染行、不渲染单元格插槽，测不到本变更；新用例让替身把 `cell-thumbnail` 插槽渲染出来，从而点击真实单元格标记。

## 模块防火墙自检

- **前端 HTTP 出口**：无新增调用。
- **共享件**：不改 `AppTable` / `usePagination` / `useTableDragScroll`。
- **截图绘制**：零改动。
- **后端**：零改动。

## Risks / Trade-offs

- [单击缩略图列从此不再打开放大预览] → 已与用户确认：该列在检查器里不放缩略图数据；预览改挂双击保留能力。
- [零宽高元素被点击时画面无红框（按规格不画）] → 该行仍会出现紫色填充，用户至少知道点到了哪一行；不为它破例画框。
- [用户可能期望「单击整行就能定位」] → 本次按需求只开放缩略图列；扩大到整行需要改规格里「单击其余单元格不得改高亮」的条款，另议。
