## Context

动机与范围见 proposal.md。方案需要的现状约束：

- 规划模型的入参不是独立字段，而是运行时由 `AITask` 行派生的一条四键 JSON 文本（本 App `api.py` 的规划输入构造函数），引擎装配（`engine_adapter.build_request`）调用它并塞进 `TaskRequest.goal`。也就是说**这条文本随时可从任务行重算**。
- 任务四字段（标题/目标/附件/设备）在创建后**没有任何写入口**：本 App 只有创建、删除、重新执行（克隆新建），没有更新任务内容的端点。因此「重算值」与「当时入模值」在现有系统里恒等。
- 附件解析正文已落库在任务行的文本字段里，但**没有任何接口下发过它**；详情接口目前只下发附件文件名，且前端从未渲染该字段。
- 详情接口已经内联下发完整的执行过程日志（含各角色思考与工具轨迹），载荷本来就偏大；列表接口最多 100 行。

## Goals / Non-Goals

**Goals:**

- 让「送给规划模型的原文」与「附件解析正文」在任务详情里直接可读，不需要翻服务端日志。
- 让列表卡片一眼看出该任务是否带附件。
- 零迁移、零写入、零行为变更：只增读侧字段与展示。

**Non-Goals:**

- 不做入模内容快照落库（见 Decisions D1 的取舍与触发条件）。
- 不改任何提示词、四键契约、调度与执行链路。
- 不引入附件正文长度保护/截断（报告 G4）、设备型号名入模（G3）、扫描版 PDF 兜底文案（G5）。
- 不提供附件原文件下载。

## Decisions

### D1 规划输入用「同源派生」，不新增落库快照

详情接口返回的规划输入 MUST 由引擎装配所用的**同一个函数**就地计算（本 App `api.py` 的 `build_planner_user_input(task)`），不新增字段、不写库、不加迁移。

- 理由：任务内容创建后不可变，派生值与真实入模值恒等；单一函数保证「展示的就是发出去的」，且历史任务无需回填即可查看。
- 备选一（否决）：在工作流启动时把 `req.goal` 快照写进任务结果 JSON。更「铁证」，但引入一次额外写库、与结果结构耦合，且对已跑完的历史任务无补。
- 备选二（否决）：把入参持久化为独立列。收益与 D1 相同，代价是迁移 + 冗余数据。
- **触发条件**：一旦将来出现「编辑任务标题/目标/附件/设备」的能力，或规划输入构造函数被拆成多份，本决策立即失效，必须改为启动时快照。

### D2 附件正文随详情接口内联下发，不截断

详情载荷新增附件正文全文（未上传附件时为空串）。展示层的折叠与定高滚动由前端负责。

- 理由：与既有「详情内联执行日志」的形态一致，前端一次请求拿全；截断会让「看到的」不等于「发出去的」，违背本变更的目的。
- 备选（否决）：新开附件正文端点。多一个端点与一次往返，收益仅是延迟加载，而详情页本来就不是高频大流量页面。

### D3 列表只下发附件名，不下发正文

列表行新增附件文件名字段，正文一律不下发；卡片按「有则显示文件名、无则 —」渲染。

- 理由：列表一次最多 100 行，正文会把响应体积放大两个数量级。

### D4 详情页版式：新增两个折叠区块，放在 KPI 与步骤分栏之间

「送给规划模型的输入」（预格式展示四键 JSON）与「任务附件」（文件名 + 正文全文）各为一个默认收起的折叠区块；正文区块展开后定高滚动。卡片 meta 列表在既有字段后追加「附件」一行，顺序不变。

- 理由：折叠默认收起，既不干扰现有「步骤清单 → 步骤详情」主视觉，又让需要核对入参的人一键展开；不引入新的版式层级。

## 模块防火墙自检

- 跨 App import：无。改动全部落在 `apps/ai_assistant` 本 App 内（`api.py` 两个序列化函数），无新增跨模块依赖。
- 跨 App import service/runner：无。
- 写库收敛：本变更**不含任何写操作**，不新增 INSERT/UPDATE/DELETE；详情与列表均为只读序列化。
- 前端边界：前端只经本模块 `api/tasks.ts` 走既有 `/api` 出口，不直连数据库、不新增 HTTP 出口。
- 信封与命名：两个接口沿用既有响应形态，新增字段一律 snake_case；前端 camelCase 转换仍在共享 api-client 侧完成。

## Risks / Trade-offs

- [派生值与真实入模值漂移] → 展示与装配共用同一函数，并加单测断言「详情返回值 == 装配取用的规划输入」；同时把「出现任务编辑能力即须改为快照」写成 D1 的触发条件。
- [超大附件正文导致详情载荷与渲染变大] → 详情区块默认收起 + 定高滚动；本条不引入截断，长度保护按报告 G4 另行立项。
- [旧任务无附件] → 新字段全部按可选读取，界面回落为「—」/空态，不做数据回填。
- [卡片 meta 变长影响便签卡片版式] → 附件名在卡片内单行省略号截断，不换行撑高。

## Migration Plan

无数据迁移、无模型变更。上线顺序：后端先发（纯增量字段，旧前端忽略），前端后发。回滚：仅需回滚前端展示；后端多出的字段对旧前端无副作用，可保留。
