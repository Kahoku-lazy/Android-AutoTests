## Why

四字段确实进了规划模型，但**除了任务目标以外，界面上没有任何地方能看到「到底送了什么」**：规划模型的入参不落库、附件解析后的正文不进任何接口、列表卡片与详情页都不显示附件。任务一旦跑歪，只能由开发去翻服务端日志才能确认入参，用户与测试无法自助核对。

## What Changes

- 任务详情接口在既有字段基础上增补两项只读展示数据：**规划输入原文**（引擎实际收到的那条四键 JSON 文本）与**附件解析正文**（落库的 Markdown 全文）。
- 任务详情页新增可折叠区块：「送给规划模型的输入」展示四键 JSON 原文（预格式、定高滚动）；「任务附件」展示文件名与解析后的 Markdown 全文（默认收起、展开后定高滚动）。
- 任务列表行增补附件文件名，任务卡片新增一项「附件」（无附件时为 —），保持卡片既有字段顺序不变。
- 规划输入**按引擎装配所用的同一个函数派生**，不新增落库字段、不产生迁移；展示值与实际入模值同源同函数。
- **BREAKING**：无。四键契约、入模内容、调度与执行链路一律不动；详情接口只新增字段，既有字段名与语义不变。
- **非目标**：不改规划/执行/验收的任何提示词与入参；不补设备型号名入模、附件正文长度保护、扫描版 PDF 兜底文案（核查报告中的 G3/G4/G5，留待后续单独立项）；不新增任务编辑能力；不提供附件下载。
