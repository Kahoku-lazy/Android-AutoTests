## ADDED Requirements

### Requirement: 任务详情可查看规划输入原文

系统 SHALL 在任务详情数据中提供「规划输入原文」，即引擎装配时实际交给规划模型的那条四键 JSON 文本。该文本 MUST 与引擎装配走同一处派生逻辑（同一函数、同一字段集），MUST NOT 另存一份副本以免与实际入模内容漂移。系统 MUST NOT 因此新增或修改数据表字段。

#### Scenario: 详情可见四键原文

- **WHEN** 用户打开一条任务的详情
- **THEN** 系统返回的规划输入可解析为含「任务标题」「任务目标」「附件文本内容」「设备ID」四个键的 JSON 文本，其值与任务的标题、目标、附件文本、设备 serial 一致

#### Scenario: 无附件时附件键为空串

- **WHEN** 用户查看一条未上传附件的任务详情
- **THEN** 规划输入原文中「附件文本内容」的值为空字符串，其余三键仍为其真实值

#### Scenario: 规划输入与实际入模同源

- **WHEN** 同一条任务既被引擎装配取用规划输入、又被详情接口取用规划输入
- **THEN** 两次取到的文本完全一致（同一派生函数，不引入第二份实现）

### Requirement: 任务详情可查看附件解析正文

系统 SHALL 在任务详情数据中提供附件解析后的 Markdown 正文全文与附件文件名。未上传附件时，附件正文 MUST 为空字符串、附件文件名 MUST 为空字符串。系统 MUST NOT 因正文较长而截断或改写其内容，展示层的折叠与滚动由前端负责。

#### Scenario: 有附件时详情返回解析正文

- **WHEN** 用户打开一条带 Word 或 PDF 附件的任务详情
- **THEN** 系统返回附件文件名与解析得到的 Markdown 正文，且正文与规划输入中「附件文本内容」一致

#### Scenario: 无附件时正文与文件名均为空

- **WHEN** 用户打开一条未上传附件的任务详情
- **THEN** 系统返回的附件正文与附件文件名均为空字符串

#### Scenario: 详情页可读附件全文

- **WHEN** 用户在任务详情页展开「任务附件」区块
- **THEN** 页面按预格式展示附件正文全文，并在正文超出可视高度时于区块内部滚动，不撑破页面布局

### Requirement: 任务卡片展示附件名

系统 SHALL 在任务列表数据中提供附件文件名。任务卡片在任务带附件时 MUST 展示该文件名，未带附件时 MUST 展示占位符（—），且 MUST NOT 展示附件正文。

#### Scenario: 带附件的卡片显示文件名

- **WHEN** 用户查看一条带附件的任务卡片
- **THEN** 卡片展示该项附件文件名

#### Scenario: 无附件的卡片显示占位

- **WHEN** 用户查看一条未上传附件的任务卡片
- **THEN** 卡片的附件一项显示「—」，且列表接口响应中不包含附件正文
