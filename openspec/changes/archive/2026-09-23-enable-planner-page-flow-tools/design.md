## Context

- planner 的系统提示词不是代码而是 **DB 数据**：`ai_agents.prompt_planner`，种子在迁移 `0038` 的 `_SNAPSHOT_PLANNER`，管理员可在 AI 工具箱「设备提示词」页编辑。
- 实测：种子与库内现值**逐字节相同**（均 1123 字），且都不含 `list_page_flows`；「步骤要求」第 7 条原文存在，可作为条件锚点。
- 本变更 §1 已把 `list_page_flows` / `get_page_flow` 装配给 planner，但提示词里**零处**提到页面流 → 只装配不足以让模型去用。
- 先例：`0039`/`0040` 已建立「短语级条件替换 + 可逆」的迁移写法，本单沿用并推广为「条件插入」。
- 动机见 proposal.md - Why；条款见 specs/ai-device-planner-tools。

## Goals / Non-Goals

**Goals:**

- planner 的**默认**提示词含页面流阅读指引（先列出、再按需读摘要）。
- 存量库同步该指引；**用户已改写的提示词不被覆盖**；写入可逆。

**Non-Goals:**

- 不改 executor / verifier 提示词。
- 不改提示词的读写接口（`ai-device-prompts` 能力的接口面）。
- 不做「规划必须先读页面流」的硬约束（提示词是软引导；见 Open Questions）。

## Decisions

**D1 以「追加一条编号项」注入，而不是改写既有语句。** 指引作为「步骤要求」第 8 条追加，与既有 1~7 条风格一致；改动最小，反向操作就是删掉该行。

**D2 条件插入的判据：含锚点且不含特征名。** 仅当字段含第 7 条原文锚点、且不含 `list_page_flows` 时才插入。这样：用户整体改写过的（锚点没了）不动；用户已自行加过指引的（已含特征名）不重复插入。

**D3 种子与数据迁移同单交付。** 编辑已应用的 `0038` 只影响新装，故必须配 `0041` 覆盖存量；两者同单避免新装与存量分叉（与 `0039`/`0040` 同一处理方式）。

**D4 指引措辞只用已注册的工具名与真实参数。** 现工具面：`list_page_flows(query="")` 返回全部文档（每条含 `directory_path`/`directory_depth`），`get_page_flow(doc_id)` 取语义摘要。指引 MUST NOT 描述不存在的参数（如已移除的 `directory_id`/`limit`）。

## 模块防火墙自检

- **写操作收敛**：迁移只更新 `ai_assistant` 自有表 `ai_agents`，不跨 App 写库。
- **跨 App import**：无新增；前端与引擎接口不变。
- **数据库**：无 schema 变更，只有一次可逆数据写入。

## Risks / Trade-offs

- [覆盖用户编辑] → 双重条件（锚点在 + 特征名不在）；另提供 reverse。
- [锚点漂移导致存量库漏更新] → 锚点取第 7 条**完整原文**；缺失即跳过（宁可不改，也不猜位置）。
- [提示词变长挤占 token] → 仅追加一句（约 60 字），planner 提示词当前 1123 字。
- [模型仍不调用] → 提示词是软引导；本单不强制，是否需要更强约束留作 Open Question。
- [新装与存量分叉] → 种子与迁移同单交付并各有断言（种子含指引 / 迁移条件插入正确）。

## Migration Plan

- `0041` forward：条件插入；reverse：删除追加行。无 schema 变更。
- 回滚：`migrate ai_assistant 0040` + 代码回退。
