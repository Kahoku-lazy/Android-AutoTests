## Context

当前状态（上一轮结束后）：`.md-split` 为 `minmax(0, 2fr) minmax(0, 1fr)`（对话栏 1/3），`.md-chat-body` 固定 `132vh`。前者源自对「太宽了，缩小一倍」的横向误读，后者源自更早一轮「纵向扩大一倍」的实现。需求方本轮澄清：要缩的是高度。

## Goals / Non-Goals

**Goals:**

- 高度砍半：`132vh` → `66vh`，对话区不再长于一屏。
- 宽度退回上一轮误改前的 2/3。

**Non-Goals:**

- 不改窄屏断点、工具折叠、消息区内部结构、接口与交互。
- 不再回到 420px 固定宽度写法（继续保持栅格比例）。

## Decisions

**D1：两个维度各改一处声明，互不耦合。** 高度只动 `.md-chat-body` 的 `height`，宽度只动 `.md-split` 的 `grid-template-columns`。把尺寸回退做成"改回上上版"最省事的方式是直接改这两个值，而不是回滚提交——中间已有「工具分组折叠」「高度固定为占位」等需要保留的成果。

**D2：高度仍保留"固定"语义。** `66vh` 是固定高度（无消息时同样占位），不是 `max-height`；这样左右两栏高度关系稳定，且与上一版只有数值差异，行为契约不变。

## 模块防火墙自检

- 跨 App import：无（只动一个前端模块内的样式与测试文件）。
- 引擎边界 / 通信通道：不涉及；不新增或修改任何 HTTP、WebSocket、SSE 调用。
- 前端不直连数据库、不新增写操作。

## Risks / Trade-offs

- [66vh 比"一屏可读"少] → 恢复到此前的观感，且高度翻倍带来的「左右等高」收益仍在（固定高度、无消息也占位）。
- [用户实际想保留上一轮的窄宽度] → 该取舍已在提案里写明；若需要，反向调整同为一行声明。

## Migration Plan

纯前端样式调整，无数据迁移。回滚：还原 `ModelDebugPage.style.css` 的两行声明。
