## ADDED Requirements

### Requirement: 调试消息区高度固定为屏幕三分之二

调试对话栏的消息区 MUST 采用固定高度而非随消息数量伸缩：其高度 MUST 为屏幕高度的约三分之二（`66vh`，即上一版 `132vh` 的一半），使对话区不再占掉一屏以上。消息超出该高度时 MUST 仍在消息区内独立滚动，MUST NOT 把整页撑长。消息为空时该区域 MUST 保持同一高度，MUST NOT 因无消息而塌缩。输入框与清空 / 发送按钮 MUST 仍留在对话栏内、位于消息区之下。

#### Scenario: 高度为三分之二屏且不随消息数量变化

- **WHEN** 超管打开任一角色调试子页（有对话或无对话）
- **THEN** 消息区高度为屏幕高度的约三分之二（约 66vh）
- **AND** 消息条数增减不改变该高度

#### Scenario: 超出部分只在该区内滚动

- **WHEN** 对话内容超过消息区的固定高度
- **THEN** 滚动只发生在消息区内，页面不因消息增多而变长

#### Scenario: 无消息时同样占位

- **WHEN** 超管首次进入某角色调试子页（尚无任何消息）
- **THEN** 消息区仍占据约三分之二屏高，空态提示与示例问法显示在该区域顶部

### Requirement: 调试对话栏占正文宽度三分之二

调试子页的调试对话栏 MUST 保持独立成栏并与配置内容并排常驻，且其横向占比 MUST 为正文宽度的三分之二（配置区占三分之一）。当正文可视宽度不足以让两侧同时保持可读时，页面 MUST 改为上下单列堆叠，对话栏此时 MUST 占满正文宽度。该占比约束 MUST NOT 改变对话栏内部结构与高度契约：消息区固定高度与内部滚动、输入框与清空 / 发送常驻、思考过程与工具轨迹分区展示 MUST 与既有实现一致。

#### Scenario: 宽屏下对话栏占三分之二

- **WHEN** 超管在宽屏（正文可视宽度 ≥ 1200px）打开任一角色调试子页
- **THEN** 配置区与对话栏并排可见
- **AND** 对话栏与配置区的宽度之比为 2 : 1（即对话栏占正文宽度的三分之二）

#### Scenario: 窄屏下改为上下单列

- **WHEN** 正文可视宽度小于 1200px
- **THEN** 配置区与对话栏改为上下单列堆叠
- **AND** 对话栏占满正文宽度，不出现两侧同时被挤压到不可读的并排布局

#### Scenario: 三个角色占比一致

- **WHEN** 超管分别打开规划 / 执行 / 验收三个角色的调试子页
- **THEN** 三页的对话栏与配置区占比完全相同（2 : 1）

## REMOVED Requirements

### Requirement: 调试消息区高度固定为原上限的两倍

**Reason**: 需求方反馈「太高了」并澄清要缩小的是高度：1.3 屏的对话区把整页拉得比一屏还长，输入框被顶到折线以下。

**Migration**: 由「调试消息区高度固定为屏幕三分之二」取代：`.md-chat-body` 的固定高度由 `132vh` 改为 `66vh`，滚动归属与空态占位规则不变。

### Requirement: 调试对话栏占正文宽度三分之一

**Reason**: 上一轮把「缩小一倍」误读为横向收窄而引入；需求方的诉求在高度，横向比例应保持其确认过的 2/3。

**Migration**: 由「调试对话栏占正文宽度三分之二」取代：`.md-split` 分栏恢复为 `minmax(0, 1fr) minmax(0, 2fr)`。
