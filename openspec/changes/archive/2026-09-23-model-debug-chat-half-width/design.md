## Context

模型调试页正文为两栏栅格 `.md-split`，当前为 `minmax(0, 1fr) minmax(0, 2fr)`（配置区 1/3、对话栏 2/3），窄屏 1200px 以下退化为单列。对话栏高度已由上一变更固定为 `132vh`（见已归档变更 `2026-09-23-model-debug-chat-height-and-tool-collapse`）。本次只调横向比例，动机见 proposal.md - Why。

## Goals / Non-Goals

**Goals:**

- 对话栏宽度收为正文的 1/3（上一版的一半），配置区回到 2/3。

**Non-Goals:**

- 不改对话栏高度（`132vh`）、内部滚动、折叠、工具分组、断点与任何接口。
- 不回到上一版的 420px 固定上限写法（栅格比例保留，随正文自适应）。

## Decisions

**D1：交换栅格两轨的权重，而不是给对话栏写死宽度。** `.md-split` 改为 `minmax(0, 2fr) minmax(0, 1fr)`（配置区在前、对话栏在后）。备选：`width: 33%` 固定值——与栅格第一轨争抢宽度，且窄屏回退要多写一套覆盖；比例轨在任何正文宽度下都自洽，弃用。

**D2：断点与高度都不动。** 1200px 单列回退在 1:2 分栏下更宽松（正文 1200px 时对话栏约 390px），无需调整；对话栏高度契约与本次诉求无关，保持 `132vh`，避免把两个维度耦合进同一次改动。

## 模块防火墙自检

- 跨 App import：无（只动一个前端模块内的样式与测试文件）。
- 引擎边界 / 通信通道：不涉及；不新增或修改任何 HTTP、WebSocket、SSE 调用。
- 前端不直连数据库、不新增写操作。

## Risks / Trade-offs

- [对话栏回到 1/3 后，长回复折行变多] → 高度已翻倍（1.3 屏），折行带来的滚动成本由纵向余量吸收；这是需求方在「太宽」与「折行」之间的明确取舍。
- [用户实际想要的是「回到最初的 420px」而非「1/3」] → 1/3 在常见正文宽度（约 1200–1700px）下折合 400–570px，与新老观感都接近；若仍不满意，再按具体像素值微调一次即可，改动面同为一处声明。

纯前端样式调整，无数据迁移。回滚：还原 `ModelDebugPage.style.css` 的 `.md-split` 一行。
