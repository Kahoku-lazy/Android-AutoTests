## ADDED Requirements

### Requirement: 调试对话栏占正文宽度三分之一

调试子页的调试对话栏 MUST 保持独立成栏并与配置内容并排常驻，且其横向占比 MUST 为正文宽度的三分之一（配置区占三分之二）。当正文可视宽度不足以让两侧同时保持可读时，页面 MUST 改为上下单列堆叠，对话栏此时 MUST 占满正文宽度。该占比约束 MUST NOT 改变对话栏内部结构：消息区固定高度与内部滚动、输入框与清空 / 发送常驻、思考过程与工具轨迹分区展示 MUST 与既有实现一致；对话栏高度 MUST 不受占比调整影响。

#### Scenario: 宽屏下对话栏占三分之一

- **WHEN** 超管在宽屏（正文可视宽度 ≥ 1200px）打开任一角色调试子页
- **THEN** 配置区与对话栏并排可见
- **AND** 对话栏与配置区的宽度之比为 1 : 2（即对话栏占正文宽度的三分之一）

#### Scenario: 窄屏下改为上下单列

- **WHEN** 正文可视宽度小于 1200px
- **THEN** 配置区与对话栏改为上下单列堆叠
- **AND** 对话栏占满正文宽度，不出现两侧同时被挤压到不可读的并排布局

#### Scenario: 三个角色占比一致

- **WHEN** 超管分别打开规划 / 执行 / 验收三个角色的调试子页
- **THEN** 三页的对话栏与配置区占比完全相同（1 : 2）

#### Scenario: 宽度收窄不影响高度与内部结构

- **WHEN** 超管打开任一角色调试子页
- **THEN** 消息区高度仍为屏幕高度的约 1.3 倍且内部独立滚动
- **AND** 输入框与清空 / 发送按钮仍常驻可见，助手消息仍分别渲染「回复 / 调用失败」与「思考过程」两个区块

## REMOVED Requirements

### Requirement: 调试对话栏占正文宽度三分之二

**Reason**: 需求方观感 2/3 过宽：对话栏把配置区挤到 1/3，左栏工具分组与提示词阅读局促；对话内容在 2/3 宽下也超出所需。

**Migration**: 由「调试对话栏占正文宽度三分之一」取代：`ModelDebugPage.style.css` 的 `.md-split` 分栏比例改为 `minmax(0, 2fr) minmax(0, 1fr)`（配置区在前）。对话栏高度契约「调试消息区高度固定为原上限的两倍」不受影响。
