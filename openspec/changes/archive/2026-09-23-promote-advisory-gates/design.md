## Context

动机见 proposal.md。现状与约束：

- 本地门禁 `tools/check_gates.py` 已有阻塞/告警两级（`Gate.blocking`），退出码只由阻塞项决定；6 项待转的门禁当前均为 `blocking=False`。
- CI 侧这 5 项（静默吞异常此前未接入 CI）位于独立 job `advisory-checks`，步骤形式为 `命令 || { echo "::warning::…"; exit 0; }`——即"执行并输出告警，但不影响结论"。
- 静默吞异常检查是 AST 实现，**无法用一行 shell 表达**；CI 要覆盖它，必须能单独调用该门禁。
- 约束一：`AGENTS.md` 测试范围收敛条款——禁止主动跑全量回归，因此不能用"跑一次全量看是否全绿"作为验收手段。
- 约束二：Vue 文件体积（6 个文件超 500 行）是既有拦截型门禁且尚未清零，本变更**无法**让整仓门禁变全绿；转拦截只针对已清零的 6 项。

## Goals / Non-Goals

**Goals:**

- 6 项已清零的检查转为拦截，使违规立即失败。
- 本地与 CI 的判定强度一致（同一批检查、同一级别）。
- 让 CI 能覆盖非内联的 AST 检查。

**Non-Goals:**

- 不清算 Vue 文件体积存量（超长文件拆分单独排期）。
- 不改动其余门禁的判定口径与作用域。
- 不为 CI 单独重写一份静默吞异常逻辑。

## Decisions

### 决策 1：转拦截只针对"存量已清零"的 6 项，不触碰仍红的体积门禁

- 理由：转拦截的前提是该检查当前为绿；把仍红的门禁"转拦截"没有意义（它本来就是拦截型且已在失败）。
- 备选：等体积也清完再一起转。被否——会把 6 项已就绪的收紧无限期拖延，且体积清算的工作量与风险面完全不同（拆组件 vs 改配置）。

### 决策 2：给 `check_gates.py` 增加 `--only`，而不是在 CI 内联重写 AST 逻辑

- 理由：静默吞异常检查约 50 行 AST 代码；在 workflow 里再写一份必然与本地实现分叉，"本地 = CI"的前提被破坏。
- 备选一：CI 步骤里 `python -c "import ...; ..."`。被否——同样是第二处实现。
- 备选二：CI 直接跑 `python tools/check_gates.py`（全部 21 项）。被否——会重复执行该 job 已完成的检查，且把前端全量检查耦合进 Python 步骤。
- 边界：`--only` 只做过滤与校验（未知名称报错并返回退出码 2），不改变任何判定口径。

### 决策 3：CI 的 `advisory-checks` job 更名为 `static-checks`，步骤去掉告警包裹

- 理由：job 名与步骤名是运行记录里唯一的可读标签，继续叫 advisory 会与实际强度矛盾（本次刚发生过"名字说仅警告、实际已拦截"的语义漂移风险）。
- 备选：保留 job 名只改步骤。被否——job 名出现在 GitHub 的 checks 列表与 PR 状态里，是主要可读面。

### 决策 4：`AGENTS.md` 的「已知盲区登记」升级为「门禁清单」

- 理由：原小节的全部内容（四道仅警告的检查）在本变更后已不成立，若不改写会直接误导后续读者。
- 同时显式保留"Vue 文件体积仍红"这一项事实，避免"门禁清单=全绿"的误读。

## 模块防火墙自检

本变更只改本地检查脚本、CI workflow 与文档：

- 跨 App import：不涉及。
- 跨 App import service / runner / consumer / state_machine：不涉及。
- INSERT / UPDATE / DELETE 收敛到 api.py：不涉及（无写库行为）。
- 前端不直连数据库、仪表盘不做写操作：不涉及。

无新增跨模块依赖。

## Risks / Trade-offs

- [转拦截后，开发者在存量未清干净的分支上会踩红] → 6 项存量已清零；体积项本就红，无新增意外。
- [CI 未实际执行过（账号付款问题），转拦截在 CI 侧无法当场验证] → 本地门禁与 CI 使用同一脚本同一判定；CI 侧验证待账号恢复后由运行记录补齐（属运维动作）。
- [`--only` 被误用为"绕过检查"] → 它只支持"少跑"，不支持"放宽判定"；未知名称直接报错。
- [无法用一次全量确认整体状态] → 各项单独验证已记录；整体结论属推断（体积项仍红），已在 proposal 中标注为推断而非实测。

## Migration Plan

- 生效方式：合并后本地门禁立即收紧；CI 侧待其能执行时同样收紧。
- 验证：`--only` 过滤与退出码（含未知名称 → 2）；`ruff check/format`；workflow YAML 解析；`AGENTS.md` 文案与事实一致。
- 回滚：把 6 处 `blocking=True` 改回 `False` 并还原 CI 步骤包裹即可。
