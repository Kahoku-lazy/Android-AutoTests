## Context

现状（ModelDebugPage.vue 第一版）：六个区块全是同一层级的 panel —— 角色概览（:62）、系统提示词（:89）、工具（:94）、Skill（:111）、知识库（:122）、对话（:131）；提示词整篇铺开、对话在最底、工具平铺无分组。

已确认方案：temps/relayout-model-debug-page-proto.html（变体 C 分栏台 · 左配置 / 右对话），本次只落其 P0/P1。

约束：只改本模块前端两个文件；页面当前约 260 行，重排后若超 500 行必须按前端硬规范拆分。

## Goals / Non-Goals

**Goals:** 三层语义可辨；对话常驻右栏；工具有分组与计数；提示词默认折叠；归属标注升级为组头徽标。

**Non-Goals:** 不动接口 / 字段 / 权限 / 5 分钟超时 / 不落库 / 不挂工具；不动路由与装配台；不新增共享件；不引入新视觉令牌。

## Decisions

**D1 版式 = 变体 C 分栏台，复用同族写法。**
左侧内容（角色带 → 生效装配 → 参考数据 + 提示词），右侧对话；窄屏（<=960px）由既有媒体查询回落单栏。理由：与设备检查器 / 平台工具调试同族，审阅者已熟悉；不必发明新骨架。

**D2 三层用语义分区，不加新面板壳。**
顶层分区用现有 section + 分区标题（项目规范：顶层分区不用卡片壳），组头复用纸面样式；不新增共享组件。理由：把六块等权面板改成三层分组是信息架构问题，不是加壳问题。

**D3 工具按分类分组，组默认展开。**
按后端已回的 tool.category 分组（保序 Map），组头显示启用数与总数。只有提示词默认折叠 —— 工具是这一页的主要核对对象，藏两层折叠反而增加点击成本。理由：与既有前端 spec 的可见性断言一致（工具名仍在首屏 DOM）。

**D4 角色切换 = 页内分段入口 + 同页路由参数。**
点击分段项 router.push(modelDebugRoute(role))，复用既有 watch(role) 重新取数并清空消息；不引入第三层页面，因此页头返回与面包屑不变（规格场景：不出现返回上一角色式回退）。

**D5 提示词折叠状态是组件本地 ref（默认收起）。**
折叠头显示 prompt.length 字数与库中当前值标识；展开才 v-html 渲染 Markdown（仍走 renderSkillMarkdown 的 DOMPurify 清洗）。理由：默认收起能立刻看到三层结构与对话。

**D6 归属标注升级为组头徽标，文案仍取自 constants。**
Skill 组头带三模型共用徽标、知识库组头带执行链路未挂载 RAG 徽标；文案常量仍是唯一真相源（spec 以文本包含断言）。

**D7 超过 500 行就拆子组件。**
若 ModelDebugPage.vue 超 500 行，把对话栏抽成 components/ModelDebugChat.vue（消息区 + 输入 + 空态，纯展示 + emits，不碰网），页面只保留取数与编排。

## 模块防火墙自检

- 只改 frontend/src/modules/ai-assistant 下的 ModelDebugPage.vue 与其 .style.css（必要时 +1 个私有子组件）；HTTP 仍只经 api/toolbox.ts → shared/api-client。
- 零后端改动：不碰 apps/、engines/、路由与 urls。
- 无新增共享件、无新依赖。

## Risks / Trade-offs

- [窄屏分栏挤压] → 既有媒体查询已把分栏落成单栏；浏览器缩窗复查。
- [折叠隐藏关键信息] → 只有提示词默认折叠；工具与标注始终可见（spec 场景守护）。
- [页面超 500 行] → D7 拆子组件。
- [原型色值被误当规范] → 实现一律引用令牌（--c-ai / --space-* / --app-size-*），原型仅示意。
- [角色 Tab 与路由历史混淆] → push 到同页不同参数，页头返回仍指工具箱；不做返回上一角色。

## Migration Plan

无数据迁移、无接口变更。发布即前端资源更新；回滚 = 还原 ModelDebugPage.vue 与 style.css（必要时删掉新增子组件）。
