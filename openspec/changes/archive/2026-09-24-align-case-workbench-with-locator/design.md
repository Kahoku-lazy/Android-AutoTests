## Context

元素定位工作台的树皮肤（变更 `relayout-locator-workspace` 确立）与用例工作台的树（`ProjectTree.vue`，早期 explorer 风格）现在是两套：前者行式列表、后者每行一个墨框盒子。两页其余部分（左右分栏、右栏只读预览 + 分页 + 单一入口、页头内容概况）已同源。

`ProjectTree.vue` 现状关键值：行 `display:grid` + `grid-template-columns: 28px minmax(72px,1fr) minmax(0,max-content) 14px`、`border: 2px solid var(--ink)`、`border-radius: var(--app-radius-lg)`、`min-height: 44px`、`padding: var(--app-space-sm) 12px`；隐藏 el-tree 原生展开箭头；无层级引导线；工具栏有常驻「项目根 / 全部」静态面包屑与浅色底。

## Goals / Non-Goals

**Goals:**

- 用例工作台的树与工具栏与元素定位同源（行皮肤 / 层级表达 / 进入指示 / 目录计数 / 按钮皮肤 / 工具栏构成）
- 一次改动只落在 `ProjectTree.vue`，不动判定逻辑与数据

**Non-Goals:**

- 不统一模块色（两模块本就不同色）
- 不统一右栏列集（元素 3 列 / 用例 5 列，均为需求方指定）
- 不删批量的「全选」能力，不动拖拽 / 右键 / 批量判定与端点
- 不动分隔线令牌（`--case-border-subtle` 是模块色分隔线，属登记的模块差异）

## Decisions

**D1 行由 grid 改为 flex，逐属性对齐 `.locator-row`**
grid 的固定列模板在 280px 窄栏里必然溢出（已实测 396 vs 246）；flex + `margin-left:auto` 的尾随信息更贴合「名称可压缩、尾随信息靠右」的语义，也与元素定位逐属性一致（`border: 2px solid transparent`、悬停底色、选中 `border-color + --app-shadow-sm`）。

**D2 恢复 el-tree 原生展开箭头，删掉行尾自绘 `▾` / `→`**
元素定位没有隐藏原生箭头，目录的可展开性由箭头表达；用例此前隐藏箭头并用行尾符号代替，是两套语言。恢复原生后行尾符号失去职责，一并删除；文件行改为名称右侧的「进入 ›」。

**D3 目录计数与元素定位同口径（0 → 「空」）**
元素定位的目录行尾是纯数字、0 显示「空」；用例原为「N 项」。统一为纯数量 + 「空」，避免同一位置两种文案。

**D4 文件行的更新时间保留**
元素定位的文件行尾没有数据，用例有更新时间。这是**数据差异**而非皮肤差异（用例是文档、时效性有意义），保留在同一个「尾随弱化信息」槽位里，并已在 proposal 的「保留的业务差异」中登记；若要彻底对齐可后续单独决策。

**D5 工具栏去掉常驻静态面包屑**
「项目根 / 全部」是固定字符串（不随选中变化），不承载信息却占一行高度；批量模式下的「已选 N 个文件」是动态的，保留。

## 模块防火墙自检

- 跨 App import / 写库 / ORM：无（纯前端模板与样式）
- 前端 HTTP 出口：不变
- 引擎边界 / 通信通道：不涉及

## Risks / Trade-offs

- [行去掉常驻描边后，树的整体"盒子感"消失，用户可能一时不习惯] → 与元素定位一致；悬停与选中仍给出明确反馈
- [删掉行尾 `→` 后进入暗示变弱] → 名称右侧的「进入 ›」与元素定位一致，比行尾符号离视线更近
- [工具栏去掉面包屑后，"当前在哪一层"信息减少] → 该行本就是固定文案；层级由缩进与引导线表达
