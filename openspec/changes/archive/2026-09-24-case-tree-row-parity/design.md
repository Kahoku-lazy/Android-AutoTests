## Context

上一单（`align-case-workbench-with-locator`，已归档）把用例树的**皮肤与结构**对齐到元素定位，同时把「文件行尾带更新时间」登记为可保留的数据差异。归档后目视两页截图发现：在 280px 左栏里，文件行的宽度预算被名称 + 「进入 ›」+ 时间三份瓜分，名称只剩约 4 个字（截图显示为「临时… 进入 › 09-24 11:11」）；元素定位的文件行只放名称 + 「进入 ›」，名称约 9 个字。差异不在于皮肤而在于**行承载的职责**。

## Goals / Non-Goals

**Goals:**

- 树行的职责与元素定位一致：只表达结构与名称
- 名称拿回被时间占用的宽度

**Non-Goals:**

- 不删任何数据：更新时间仍在右栏预览与详情页
- 不改目录行的子项数表达（上一单已对齐）
- 不改行皮肤与交互

## Decisions

**D1 删掉文件行的尾随时间，而不是缩短它或换行**
缩短（省年份）已在上一单做过，仍不够；换行会让行高与元素定位不一致。树是导航结构，时间属于数据列——数据列统一放右栏预览与详情页，职责边界更清楚。

**D2 同时删除失去消费方的时间格式化函数**
`formatTime` / `formatFullTime` 在 `ProjectTree.vue` 内只服务这一个行尾元素；保留会成为无消费方代码（与仓库清死代码口径冲突）。右栏预览有自己的时间列渲染，不受影响。

## 模块防火墙自检

- 跨 App import / 写库 / ORM：无（纯前端模板与函数删除）
- 前端 HTTP 出口：不变
- 引擎边界 / 通信通道：不涉及

## Risks / Trade-offs

- [树里看不到时间，判断"最近改过哪个文件"需先点开看右栏] → 右栏预览就在同一屏，选中即见；且该列本就是需求方指定的预览列
- [与上一单登记的「数据差异」条目冲突] → 本条取代该登记，同步更新技能手册
