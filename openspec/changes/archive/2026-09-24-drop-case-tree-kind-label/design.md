## Context

`ProjectTree.vue` 的行模板渲染 `.explorer-row__ico`（图标）→ `.explorer-row__name` → `.explorer-row__kind`（「目录」/「文件」文字标签）→ `.explorer-row__meta`（目录「N 项」/ 文件更新时间）→ `.explorer-row__hint`（「展开 / 收起」/「进入表格 →」）。其中 `.explorer-row__kind` 与图标、meta、hint 三处信息重复。全仓对该类的引用只有模板一处与样式三条（无测试、无其它模块消费）。

## Goals / Non-Goals

**Goals:**

- 去掉重复的类型文字标签，行内信息不重复
- 保证去掉后目录与文件仍一眼可辨

**Non-Goals:**

- 不动行内其它信息与交互（拖拽 / 右键 / 批量勾选 / 进入提示）
- 不对齐元素定位目录树的皮肤（那边本就没有类型标签）

## Decisions

**D1 只删标签与它的三条样式规则，不补替代文案**
图标（📁 / 📄）+ 目录的「N 项」+ 文件的更新时间 + 尾部提示（「展开 / 收起」/「进入表格 →」）已经三处区分类型，再加替代文案只会换个说法重复。
**D2 类名不保留空壳**
`.explorer-row__kind*` 一并删除，避免留下无消费方的样式（与仓库「清理死代码」口径一致）。

## 模块防火墙自检

- 跨 App import / 写库 / ORM：无（纯前端模板与样式）
- 前端 HTTP 出口：不变
- 引擎边界 / 通信通道：不涉及

## Risks / Trade-offs

- [去掉文字标签后，仅凭图标可能对色弱 / 高分屏用户不够] → 尾部信息（N 项 vs 时间）与提示文案（展开 / 进入表格）仍在，且目录行有可展开箭头；信息冗余度仍高于单图标
