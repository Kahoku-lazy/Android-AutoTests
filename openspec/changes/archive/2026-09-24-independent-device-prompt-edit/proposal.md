## Why

「设备提示词」区当前只有整块一个「编辑」入口：点下去规划 / 执行 / 验收三份提示词同时变成输入框，角色卡片头上的「保存」也是三份一起提交。三份提示词分属三个不同模型，是彼此独立的资产；管理员只想改其中一份时，无法避免另外两份被拖进编辑态，也无法只保存这一份——交互粒度与业务粒度不匹配。

## What Changes

- 三个角色（规划 / 执行 / 验收）各自拥有独立的「编辑」入口与编辑态：点某一份的「编辑」MUST 只让该份进入可输入状态，其余两份保持只读 Markdown 渲染。
- 允许同时编辑多份：三份编辑态相互独立、互不干扰，编辑其中一份 MUST NOT 改变其余份的编辑态或草稿。
- 每份拥有独立的「保存」与「取消」：保存只把该份新正文写入；其余两份按「当前已保存值」随请求一并提交（接口约束：三份必须同时提交且均非空），因此写库内容 MUST NOT 携带另一份尚未保存的草稿。取消只丢弃该份草稿并退出该份编辑态。
- 「查看历史记录」入口从三个角色下拉头收敛到面板页头唯一一处；存档是规划 + 执行 + 验收三份一组的整组快照，与单个模型无对应关系。
- 进入某一份编辑时只自动展开该份折叠面板，MUST NOT 强制展开全部三份。
- 退出编辑的自动保存按份生效：离开「设备提示词」来源或离开页面时，只把仍处于编辑态且有改动的那几份与其余「已保存值」合并写库一次并留一份自动档；无改动 MUST NOT 写库。
- 非目标（一律不改）：后端接口与存档结构、三份必须同时提交的接口约束、「覆盖备份」确认文案、Markdown 渲染方式、非超管只读。
