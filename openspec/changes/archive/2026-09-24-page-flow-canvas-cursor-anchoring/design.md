## Context

- 画布组件持有两个浮层状态：节点右键菜单（`ctxMenu`，含 menu / link 两种模式）与元素选择器（`picker`），另有独立的连线右键菜单（`edgeMenu`）。三者都是 `position: fixed` + `left/top = 点击点` 的 Teleport 浮层；节点菜单宽 288px、最大高 420px（列表区 260px），连线菜单宽 248px。
- 画布的多处浮层目前没有做视口收敛：靠近右/下边缘右键时菜单会被视口裁掉。仓库内没有可复用的贴边工具（工作流模块内 `getBoundingClientRect` / `innerWidth` 命中 0 次），`frontend-l5-overlay` 也只约束阻塞型覆盖层。
- 新建页面节点的落点写死为 `180 + 页面数 * 40, 160 + 页面数 * 20`，与鼠标无关。
- `useVueFlow()`（@vue-flow/core 1.48.2）提供 `screenToFlowCoordinate`，可把屏幕坐标换算成画布坐标并自动考虑当前缩放与平移；store 里旧的 `screenToCanvas` / `updateViewport` 没有消费者（store 的 scale/pan 从未被写回），因此不复用它们。
- 画布容器的可视矩形可由 `.vf-canvas` 元素的 `getBoundingClientRect()` 取得。

## Goals / Non-Goals

**Goals:**

- 新建页面节点落在鼠标所指的画布位置，且缩放/平移后仍然算得对。
- 画布内所有光标锚定浮层在任意窗口尺寸下都完整可见，且不改变其非模态菜单形态。
- 落点与贴边逻辑都能在没有浏览器的单测里验证（纯函数 + 可注入的尺寸/视口）。

**Non-Goals:**

- 不改元素定位、设备检查器等其它模块的右键菜单（本变更只覆盖页面流画布内浮层）。
- 不做浮层的「翻转到光标另一侧」策略（见 Decisions 3）。
- 不改节点/连线的增删、元素关联、菜单项文案与顺序，也不动自动保存与节点上限。
- 不做画布自动滚动到新节点、节点自动布局、网格吸附策略调整（`snap-to-grid` 保持现状）。

## Decisions

1. **落点用 VueFlow 的 `screenToFlowCoordinate`，不用 store 里的 `screenToCanvas`。** 理由：前者由 VueFlow 维护视口变换，缩放/平移后天然正确；后者的 `scale/panX/panY` 从无人写回，等于永远按 1:1 算，缩放后会落错位置。备选：改造成由 `onViewportChange` 持续写回 store（改动面更大，且与 VueFlow 内部职责重复，否决）。

2. **记录鼠标位置用画布容器上的 `mousemove`，坐标按节点中心对齐。** 在 `.vf-canvas` 上挂一个 `mousemove` 监听记录最近一次的客户端坐标；新建时换算成画布坐标后减去节点尺寸的一半，使节点中心落在鼠标处。节点尺寸取注册表声明值 `[180, 0]` 与 store 的高度计算（`computeNodeHeight`），避免读 DOM 造成首帧跳动。备选：只在 `onPaneMouseMove` 上记录（鼠标停在节点上时不更新，用户从节点上直接点新建会落到旧位置，否决）。

3. **贴边用「平移回屏内」，不做翻转。** 位置由纯函数 `containOverlayPosition(anchor, size, viewport, margin = 8)` 计算：`x = clamp(anchor.x, margin, viewport.w - size.w - margin)`，纵向同理；浮层比视口还大时收敛到 `margin` 并由 CSS 的 `max-height` 接管内部滚动。翻转（空间不足时把浮层放到光标左侧/上方）观感更"聪明"，但会让同一菜单在不同位置从不同方向出现，且需要额外的尺寸测量与二次渲染判断。备选：翻转优先 + 兜底平移（多一倍分支与测试面，本单不做）。

4. **尺寸先用常量估计、测量后再精修。** 首次渲染用各自的最大尺寸常量（节点菜单 288×420、连线菜单 248×约 160、选择器 340×420）算好位置，保证第一帧就在屏内；浮层挂载后按 `getBoundingClientRect()` 实测尺寸重算一次，只会让位置更贴边，不会跳回屏外。尺寸测不到（如 jsdom 下为 0）时回落到常量，使单测不依赖布局引擎。

5. **CSS 兜底一层 `max-height: min(<自然高度>, calc(100dvh - 16px))`。** 即使脚本未执行（首帧、异常），浮层也不会超出视口高度；内部列表区已有滚动，收敛后仍可滚动查看全部条目。

6. **同一位置连续新建做最小错位。** 目标点与既有节点中心的距离小于一个步长（24×16）时按步长递推，最多 8 步；这样不动鼠标连点两次不会得到一个被完全压住、看不见也点不到的节点。备选：严格重合（诚实但观感像"没建出来"）、把新节点选中以便用户察觉（改变选中语义，否决）。错位比较的是**节点中心**而不是左上角，否则尺寸不同的两个节点会误判为重合。

7. **落点自己换算，不走 VueFlow 的 `screenToFlowCoordinate`。** 画布开着 `snap-to-grid`（16×16），VueFlow 的换算函数内部会做网格吸附（实测：1px 屏幕位移换算结果为 0），用它落位会把节点中心推离鼠标最多 16 画布像素、也让"按尺寸修正"完全失效。改为本模块纯函数做同一套换算（平移 + 缩放，不吸附）；拖拽仍是吸附语义，两者互不影响。

8. **节点尺寸取 VueFlow 的实测 `dimensions`，不取注册表 `size`。** 注册表尺寸（180×82）是端口布局模型，与节点 CSS 实际尺寸（min-width 228 + 动态高度，实测约 274×158）不同，用它会整体偏移（实测偏差 60~100 屏幕像素）。做法：首帧若画布上已有同类节点，用它的实测尺寸落位；渲染后按**新节点自身**的实测尺寸定稿。两者同源，节点不会来回跳。DOM 测量与缩放换算只在早期方案里用过，迭代修正会被节点位移过渡期测到中间态而震荡（实测 dx −120 → −15 → +25 不收敛），已弃用。

9. **关联页面列表加载完成后重新收敛一次。** 该浮层从"菜单"切到"列表"后高度从 126px 涨到 420px，只在打开瞬间收敛会把它顶出视口下缘（实测 bottom=1251 > 视口 1000）。因此 `openLink` 在 `loadPages()` 完成后再次落位。CSS 的 `max-height` 兜底只能限制自身高度，不能解决锚点位置，故必须重算位置。

## 模块防火墙自检

- 只改前端工作流模块内部（画布组件、两个右键菜单组件、一个新的纯函数 helper），不新增任何跨 App import。
- 后端零改动：不新增/修改 `api.py`、Model、Serializer、URL、Consumer；无写库路径变化。
- 不新增 HTTP 调用，前端仍只经 `shared/api-client` 与后端通信。
- 不引入新的共享件、不改 `shared/`：浮层定位函数放在工作流模块自己的 `helpers/`，因为当前只有本模块消费（升级为共享件的时机是第二个模块也需要贴边时）。

## Risks / Trade-offs

- [鼠标位置换算在极端缩放下有 1px 级误差] → 用与 VueFlow 同源的换算（只是不做吸附）；浏览器实测在 zoom 1.65 与 1.98 下节点中心与鼠标**完全一致**（误差 0px），验收按 ±2px 断言。
- [浮层尺寸常量与真实尺寸不一致（字体、换行导致菜单更高）] → 常量按当前 CSS 的最大值取，挂载后按实测尺寸重算；CSS `max-height` 再兜一层；内容驱动变高（关联页面列表）后单独重算一次。
- [小窗口下浮层收敛后条目更拥挤] → 内部列表区本就可滚动，收敛只影响外层高度，不改变条目本身。
- [记录鼠标位置带来每次移动一个写操作] → 只写一个 `ref` 的普通对象，且画布内 `mousemove` 不涉及渲染依赖（仅新建时读取），无额外渲染开销。
- [改动画布浮层可能影响已有的右键删除等操作] → 菜单项与事件不变，只改外层定位；既有 13 条工作流用例保持全绿作为回归保护。
- [落点不吸附网格，与拖拽的吸附语义不一致] → 有意为之：吸附会把中心推离鼠标（最多 16 画布像素），与"跟着鼠标"的要求直接冲突；拖拽是用户手动微调，保持吸附更稳。
- [新建后异步定稿会带来一帧位移] → 首帧已用同类节点实测尺寸落位（偏差仅十几像素），定稿只做最后几像素的收敛；同一帧内完成，肉眼不可见。
