## Context

现状（代码事实，动机见 proposal.md）：

- 知识库是一条**未接线**的能力：设备执行装配不读 `enable_knowledge_base` / `knowledge_sources`；`api.search_knowledge`（唯一检索入口）全仓无调用者；落盘目录 `data/rag_datas` 与向量库 `data/rag_vector` **当前均不存在**（从未导入过文档）。
- 它同时有 5 个端点（状态 / 列表 / 预览 / 重建索引 / 上传）**零权限校验**，其中上传与重建索引都是写操作，重建索引还是同步重活。
- 索引面与展示面不一致：上传/列表支持 `.md/.markdown/.txt/.docx/.pdf`，索引只扫 `*.md`。
- `kb_files.py` 被两类功能共用：知识库（列表 / 上传 / 预览）与**任务附件解析**（`parse_task_attachment_bytes`，任务发布链路在用）。
- 已确认（用户裁决）：该能力不再需要、后续不迭代，**整体下线**；数据库两个字段**删列**；`chromadb` 依赖**一并清除**。

## Goals / Non-Goals

**Goals:**

- 产品面、HTTP 面、数据面、依赖面四处全清：无入口、无端点、无字段、无实现、无依赖。
- 任务附件能力行为零变更。
- 让「知识库」这个词不再出现在活代码与活规格里（历史归档与 `dev_docs` 框架笔记除外）。

**Non-Goals:**

- 不修复与本能力无关的既有问题（例如 `ai-model-debug` 里「调试对话是否挂工具」的规格自相矛盾），只在 proposal 登记。
- 不做「保留端点返回空」的兼容层（无外部调用方）。
- 不重构任务附件解析逻辑，只改它所在模块与异常类的名字。

## Decisions

**D1 整面删除，不留死开关。**
不采用「只改文案/只关入口」的保守做法：既然不再迭代，留下字段、端点或页面只会持续误导（现状已经证明：页面承诺"自动检索"、状态数字是假的）。删除比隐藏更省维护成本。

**D2 删列而不是留列。**
两个字段只承载配置值（布尔 + 文档 id 映射），落盘目录与向量库都不存在 → 无内容可失。删列后表结构与代码一致，避免"字段在、功能没了"的长期困惑。

**D3 `kb_files.py` 重命名为 `attachments.py`，异常类 `KbFileError` → `AttachmentError`。**
删除知识库专用函数后，该模块只剩任务附件解析；保留 `kb_` 前缀会让后来者以为知识库还在。行为零变更，只改模块名 / 类名与引用点。

**D4 端点直接消失（404），不做兼容返回。**
前端是唯一消费方且同步删除；`search_knowledge` 等包装函数在仓库内无调用者，没有兼容需求。旧路径请求落到 404 是期望行为。

**D5 规格处置：新增 `knowledge-base-retirement` 承载"已下线"契约。**
沿用本仓既有做法（`evaluator-retirement` 就是同一形态的能力规格），把"必须不存在"写成可验收的场景；同时改动四个被波及的既有规格（模型调试归属、入口页页头、侧栏子项、子页导航模版），不新增第四种导航模版。

## 模块防火墙自检

- 本次是**跨前后端的删除**，但不引入任何新依赖方向：后端删除模块与函数，前端删除页面与调用，未新增跨 App import，未新增 HTTP 出口。
- 写库路径不变：仅新增一条删列迁移（`ai_assistant` 自身表），仍由 Django 迁移承载。
- 任务附件解析保持在同 App 内，且只改模块名与异常类名，未改变其调用链（视图 → `api` 层不涉及，视图直接调用解析函数，与删除前一致）。
- 未触碰 `engines/`、`gateway/`、共享件与全局主题。

## Risks / Trade-offs

- [删列不可逆] → 已确认两列只有配置值、知识库目录与向量库不存在，无内容损失；用户已确认。
- [任务附件与知识库共用解析代码，误删会连带打断任务发布] → 只改模块名与异常类名；以 `tests/graybox/unit/test_ai_task_title_attach_dispatch.py` 与任务提交路径守护，实施后必跑。
- [`tests/graybox/unit/test_api_path_callers.py` 会读前端 API 层与后端路由做一致性对拍，并有扫描量下限] → 后端路由与前端调用同时删除，两侧仍一致；删除 5 条调用后需确认该用例仍通过（下限按实测约 95% 设置，量级影响可忽略）。
- [文档/规格里仍有"知识库"字样会长期误导] → 本变更同步更新四个既有规格与模块 `AGENTS.md`；`dev_docs` 的 AgentScope 框架笔记属外部资料，保留。
- [本体例曾把「knowledge」写进平台配置与遗留工具网关] → 两处一并清理，避免"字段没了但网关还在读"的半吊子状态。

## 迁移与回滚

- 迁移：一条删列迁移（`ai_agents` 去掉两列）。无数据迁移、无数据回填。
- 回滚：还原代码与迁移文件即可恢复功能；两列的历史值不可恢复（内容为空，实测无损失）。
- 部署注意：前端与后端需同批发布（后端端点消失后，旧前端页面的知识库请求会 404）。
