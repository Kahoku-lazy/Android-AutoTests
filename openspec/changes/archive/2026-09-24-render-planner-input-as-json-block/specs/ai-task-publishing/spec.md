## ADDED Requirements

### Requirement: 规划输入以缩进 JSON 代码块呈现

任务详情页「送给规划模型的输入」区块 SHALL 以缩进 JSON 代码块呈现规划输入：对象与数组 MUST 每键（每项）一行、MUST 以 2 空格缩进、MUST 保持后端下发文本中的键顺序。字符串值内部由 `\n`、`\r\n`、`\r` 表示的换行 MUST 渲染为真实换行，且续行 MUST 缩进对齐到该值所在层级。展示形态的派生 MUST 只发生在前端渲染期，后端下发的 `planner_input` 文本 MUST NOT 被改写、重新序列化或落库。

#### Scenario: 四键按行展开

- **WHEN** 用户打开一条任务详情并展开「送给规划模型的输入」
- **THEN** 四个键各占一行、按后端下发顺序排列、整体缩进 2 空格，不再是一行横向长条

#### Scenario: 字符串内换行按真实换行显示

- **WHEN** 规划输入中某个字符串值（如「任务目标」或「附件文本内容」）本身含 `\n` 换行
- **THEN** 该值在区块内按多行呈现，不出现 `\n` 字面量，且续行与首行起始列对齐

#### Scenario: 展示派生不改变入模原文

- **WHEN** 同一条任务既被引擎装配取用规划输入、又被详情接口取用规划输入
- **THEN** 接口返回的 `planner_input` 仍与引擎入模文本逐字一致；格式化只作用于页面渲染结果

#### Scenario: 脏数据回退原文

- **WHEN** 某条任务的规划输入不是合法 JSON 文本
- **THEN** 区块按原样整段展示该文本，不报错、不显示空白区块、不丢内容

#### Scenario: 空输入沿用空态

- **WHEN** 某条任务没有规划输入记录
- **THEN** 区块显示既有空态文案，不产生空代码块
