## Context

`LocatorPagePreview.vue`（上一单新增，已归档 `2026-09-24-preview-only-locator-pane`）当前照搬详情页的七列。右栏是概览位，宽度只有 872px 左右，七列必然横向滚动；而概览位要回答的是「这一页有哪些元素」，不是核对定位表达式。

## Goals / Non-Goals

**Goals:**

- 右栏预览只保留缩略图 / 元素名称 / 序号三列，一屏可读，不横向滚动
- 其余四列与全部编辑能力留在文件详情页

**Non-Goals:**

- 不改详情页的七列与编辑行为
- 不改预览条数（仍为首屏 6 条 + 总数标注）
- 不改后端

## Decisions

**D1 只改预览组件的列定义与单元格模板**
`LocatorPagePreview.vue` 的 `PREVIEW_COLUMNS` 收窄为三列，并删除文本 / 主定位 / 交互标注 / 测试点四个 `#cell-*` 插槽与 `interactionLabels` 导入（该函数改由详情页独占使用）。不再需要任何新组件或共享件。

**D2 元素名称列吃掉剩余宽度**
缩略图与序号为固定宽度，元素名称保持 `minWidth` 且不设 `width`，由表纸自身把剩余宽度分给该列，避免右侧留一大片空白。

**D3 保留横向滚动场景**
三列在正常并置宽度下不会溢出；该场景保留为极窄并置下的守卫（压缩不可读同样违规），不删除，以免规范出现能力真空。

## 模块防火墙自检

- 跨 App import：无
- 写库 / ORM：无；右栏仍零写请求
- 前端 HTTP 出口：不变（只读 `pages/{id}/items/`）
- 引擎边界 / 通信通道：不涉及

## Risks / Trade-offs

- [预览只给名称与序号，可能不足以判断元素是否就是目标] → 缩略图承担识别职责（本页元素缩略图为真实裁剪图），其余信息一键进详情页
- [三列下元素名称过长] → 单行省略 + `title` 悬浮显示全称
