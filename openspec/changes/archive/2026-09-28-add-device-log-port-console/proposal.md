## Why

平台已经会收设备日志，但收来的东西只活在内存里（约 10 分钟就被淘汰），而且「听不听」由程序自己决定——第一次跑设备任务时自动开监听、之后一直占着端口。用户既看不到平台此刻在听哪些端口，也无法主动开关；想事后翻查设备日志只能靠临时脚本。

## What Changes

- AI 工具箱新增「无线端口」区块，内含一张端口表（5 列）：**端口 / SKU名称 / 波特率 / 监听开关 / 日志查看**。
- 前三列为只读展示，取值来自平台配置登记的日志来源（现场一条：`7005 / H6810 / 921600`）。其中**波特率是无线串口盒串口侧的参数，仅作展示，不参与采集**（采集走 TCP 监听）。
- **监听开关**（仅超级管理员可改）：打开＝平台持续监听该端口并把日志落成本地文件；关闭＝立即停止监听并释放端口。开关状态持久化，平台启动后按上次状态自动恢复，**不需要有人打开页面**。
- **日志落文件**：写入根目录 `logs/` 下的 `{SKU}_{端口}.log`（如 `H6810_7005.log`），一行一条＝北京时间毫秒时间戳 + 来源 + 设备原文，得到一行即刷盘。单文件上限 50MB，写满即改名存档为 `{SKU}_{端口}_{YYYYMMDD}.log`，新文件继续沿用原名；同一天多次轮转追加 `_2`/`_3`，**绝不覆盖**。
- **日志查看**：窗口**只读当前** `{SKU}_{端口}.log` 的尾部（默认 2000 行），支持手动刷新与自动刷新；渲染口径与既有 AI 日志查询一致——**同一毫秒的日志合并为一条、最新的时间排在最上面**。存档文件只留在目录里，不读取、不删除。
- **开关即总开关**：关闭后 AI 做设备任务时也没有该端口的日志证据（验收自动降级为只看页面截图），日志相关调用返回可读结论「端口已关闭监听」，**不报错**（沿用既有「未配置端口不报错」口径）。
- 采集不再由「第一次设备任务」隐式启动，改由端口开关显式控制（开关未打开时，只读查询也不得擅自开启监听）。
- 范围外：不做端口 / SKU / 波特率三列的页面编辑（增删改端口来源）；**不启用串口直连通道**（现场不需要，保持现状不动）。

## 关联文档

关联需求编号 **PRD-08（AI 助手 · 设备操控 · 工具箱）**；该子 PRD 尚未产出（与上一次设备日志变更情况相同）。本次需求来源为需求方在评审上一次设备日志变更时提出的补充要求：AI 工具箱需要一个无线端口管理模块（五列表格 + 监听开关 + 日志查看 + 本地日志文件按 50MB 轮转）。

## Capabilities

### New Capabilities

- `device-log-file-archive`: 设备日志落本地文件与轮转——文件命名 `{SKU}_{端口}.log`、单文件 50MB 上限、写满改名存档且不覆盖、查看只读当前文件、日志内容不入库、目录可配置
- `device-log-port-console`: AI 工具箱「无线端口」管理区块——五列表格与只读列取值、监听开关（权限、持久化、启动恢复、关闭即释放端口）、日志查看窗口（尾部行数、手动/自动刷新、合并与倒序排版）、三个 HTTP 端点契约

### Modified Capabilities

- `device-log-capture`: 采集启停改由端口开关显式控制（不再由首次设备任务隐式启动）；开关关闭即停止监听并释放端口；平台启动按持久化状态恢复启用端口
- `device-log-read-tool`: 端口处于关闭状态时返回可读结论「端口已关闭监听」而非报错，且只读查询本身不得启动或恢复采集

## Impact

- **代码**
  - `engines/device/logbus.py`：采集改为**按端口启停**（每个端口独立采集线程与释放），日志落到文件挂钩
  - `engines/device/logfiles.py`（新增）：日志文件命名、追加写入、50MB 轮转、尾部读取（引擎层，零 Django 依赖）
  - `apps/ai_assistant/`：新增日志端口来源模型 + `api.py` 读写 + DRF 视图 + `urls.py` 三个端点；`log_evidence.py` 装配时尊重开关状态
  - `apps/ai_assistant/tools.py`：`read_device_log` 增加「端口已关闭监听」结论
  - `config/settings.py`：日志来源登记扩展为「端口 + SKU + 波特率」、日志目录、单文件上限
  - `frontend/src/modules/ai-assistant/`：装配台新增「无线端口」来源、新面板组件（表格 + 开关 + 日志窗口）、`api/` 层新增三个调用
- **数据**：新增一张「日志端口来源」表（端口 / SKU / 波特率 / 开关状态 / 更新时间）+ 一份迁移；**日志内容不入库**

- **接口**：新增「端口列表」「切换监听开关」「读取日志行」三个端点；既有日志查询工具只新增一个结论取值
- **测试范围**：`tests/graybox/unit`（落文件与轮转、按端口启停与恢复、关闭态只读结论）、`tests/api`（三个端点契约与权限）、`frontend/tests/ai-assistant`（来源登记与面板标签）
