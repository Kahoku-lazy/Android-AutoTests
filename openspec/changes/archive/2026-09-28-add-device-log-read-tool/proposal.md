## Why

上一次变更把设备日志做成了「验收阶段的内部证据」：采集常驻、由编排层自动注入给验收模型。但它对用户与 AI 都不可见——平台工具箱里没有任何日志相关工具，任务详情页也不展示证据。用户在工具箱里找不到这个能力，测试时想「看一眼这台设备那一刻到底打了什么日志」只能靠临时脚本。需要一个只读业务工具，让 AI（以及工具箱的调试入口）能按「指定时间点 + 指定端口」查设备日志。

## What Changes

- 新增一个**只读业务工具** `read_device_log`：按**指定时间点**与**指定端口**返回日志信息
  - `at`：指定时间点（北京时间，支持只写 `HH:MM:SS.mmm`，日期默认今天）→ 返回该时刻**前后各半个跨度**的日志
  - 不传 `at`：返回**最近一段时间**的日志
  - `port`：指定端口（默认取平台配置的日志端口）；传入未配置的端口时**不报错**，返回可读结论「端口 X 未配置为日志来源」，**不临时开新连接**
  - `keyword`（可选）：只看含关键词的行，并还原命中的功能模块 / 功能点
  - `serial`（可选）：按设备通道取；不传则用平台默认通道
- 新增工具箱分类**「设备日志」**（可整类启停、标记只读），该工具登记进平台工具表
- 该工具装配进**执行模型**的工具子集，使 AI 在执行/排查时能主动查日志
- 日志行记录**来源端口**，使「按端口查询」可落地
- **同一时刻的日志合并为一条**（时间戳 + 来源相同即合并，`text` 内保留换行）：设备一次事件常在同一毫秒打出一串日志，逐行摊开既长又难读；工具输出与验收证据两处都按此口径展示，并同时给出合并前的原始行数
- 工具返回**结构化 JSON**（时间范围、来源、行数、行列表、命中列表），只读、不落库、不改设备状态

## 关联文档

关联需求编号 **PRD-08（AI 助手 · 设备操控）**。该子 PRD 文档尚未产出；本次变更来源为需求方在评审上一次变更（`archive/2026-09-28-add-device-log-evidence`）时提出的补充要求：「加一个只读业务工具，AI 能调用指定时间点、指定端口的日志信息」，以及在实施评审中追加的两条口径：未配置端口不报错（只回「端口 X 未配置为日志来源」）、同一时间点的日志合并并保留换行。

## Capabilities

### New Capabilities

- `device-log-read-tool`: 设备日志只读查询工具——按时间点 / 端口 / 关键词读日志，含工具箱分类、只读约束、未配置端口的返回口径、同一时刻日志合并、装配进执行模型

### Modified Capabilities

- `device-log-evidence`: 新增一条需求——交给验收模型的窗口日志同样按「时间戳 + 来源」合并为按事件阅读的一条，原始行数单独给出（既有「窗口内原始日志一并交付」「未命中仍给原始日志」等需求不变）

## Impact

- **代码**
  - `engines/device/logbus.py`：日志行记录来源端口；提供「按时间窗/端口读取」的只读查询（复用既有缓冲）
  - `apps/ai_assistant/tools.py`：新增 `read_device_log` 只读工具并登记（`TOOLS` / `TOOL_META` / `TOOL_CATEGORIES`）
  - `engines/ai/agentscope/config.py`：把工具名加入执行模型工具子集
  - `config/settings.py`：如需，补充日志来源端口与通道的映射配置（多端口预留）
- **数据**：不新增表、不写库；查询只读内存缓冲
- **测试范围**：`tests/graybox/unit` 相关单测（工具入参口径、时间点解析、未配置端口、关键词过滤、只读性）
