## Context

动机见 `proposal.md - Why`。方案需要的现状约束（已核实）：

- 执行模型的输出契约由引擎侧 `engines/ai/agentscope/workflow.py` 的 `ExecutionOutput` 建模，工作流用 `_coerce` 解析模型文本；解析失败时走固定兜底对象。
- 执行模型的输出形状由**库中系统提示词**决定（`ai_agents.prompt_executor`），种子在 `0038_aiagent_device_prompts`，后续变更一律以「短语级、可逆、按锚点条件替换」的迁移同步（`0039` / `0040` / `0046` 是既有先例）。
- 工具侧已经在**真正调设备之前**把动作发出时刻（北京时间毫秒）并进工具结果 JSON；`screenshot_page` 默认 `keep_local=True`，返回里带落盘相对路径。即模型在工具返回里**能读到**这两个值。
- 平台另有**独立**的点击证据块（`executor_log_check` / 调试台 `log_check`）：由平台按工具轨迹装配，与模型自报字段无关，本次不动。
- 前端任务详情页把过程记录里的 `executor` 段渲染成 `TaskStepAttempt.executorResult` / `executorMessage` 两件，存量任务库里已有大量旧形状记录。

## Goals / Non-Goals

**Goals:**

- 执行模型输出固定为 `result` / `click_timer` / `screenshot` 三字段，任务链路与执行模型调试对话共用同一契约。
- 下游（任务过程记录、任务详情页、验收模型输入）按新契约同步，且新旧记录的呈现都成立。

**Non-Goals:**

- 不改平台装配的点击证据块与 5 秒日志证据口径（继续由平台产出，不依赖模型自觉）。
- 不由平台改写模型回复、不在平台侧替模型补 `click_timer` / `screenshot`（否则「模型自报」这一契约失去意义，也无法暴露模型漏抄）。
- 不改验收模型自己的输出契约（仍为 `action/assert/actual/result`）。
- 不改工具侧打点与截图落盘行为。

## Decisions

**决策 1：契约改在既有 `ExecutionOutput` 上，不新加一层。**

- 做法：把 `ExecutionOutput` 的三个字段换成 `result: Literal["PASS","FAIL"]`、`click_timer: str`、`screenshot: str`；解析路径与兜底逻辑不变（解析失败 → `FAIL` + 两个空串）。
- 备选：保留旧模型、另建「新执行结果」模型并在工作流里做形状嗅探。放弃原因：两条契约并存会让过程记录与前端出现四种形状，兼容成本高于收益；旧形状只需在**读取侧**（前端呈现）兼容即可。

**决策 2：`click_timer` / `screenshot` 由模型照抄工具返回，平台只做校验性的「照抄不拦」。**

- 做法：提示词明确写出取值来源（点击工具的 `action_time`、`screenshot_page(keep_local=true)` 的 `screenshot_path`）；平台对模型给出的值**原样落库**，不比对、不修正。
- 理由：需求方选定「模型自报该三字段」。平台不修正，才能如实反映模型是否抄对；真正的权威证据仍由平台装配块提供，两者互不替代。
- 备选：平台在落库时用工具轨迹覆盖模型的值。放弃原因：会掩盖模型漏抄，且与「模型自报」的诉求矛盾。

**决策 3：操作后截图口径改为强制回传落盘路径。**

- 做法：提示词里操作后确认这一步由 `screenshot_page(serial)` 改为 `screenshot_page(serial, keep_local=true)`，并说明返回里的路径供最终 JSON 使用；操作前定位那次截图不要求路径。
- 理由：不落盘就没有路径可抄；`keep_local` 默认已为真，改提示词是为让模型知道路径从哪来。

**决策 4：验收模型的输入由平台按新契约拼装。**

- 做法：`VerifierRole.run` 的第二个证据参数由「执行模型的说明文字」改为「点击前时间戳 + 点击后截图路径」的平台拼装文本（无点击 / 未截图时如实标注）；DB 里验收模型提示词的「输入（重点关注）」段同步改写。执行侧截图图片照旧随输入附上。
- 理由：验收不再可能拿到 `message`，若什么都不给，验收侧会丢掉「点了没有、几时点的」这条线索；且该线索本就在平台手里，不需要依赖模型自述。
- 备选：验收输入只留 `result`。放弃原因：会让验收退化到只看截图，削弱既有的时刻对齐能力。

**决策 5：提示词同步走一份可逆迁移，锚点取 0038 快照原文。**

- 做法：新增迁移，对 `prompt_executor` 做四处短语级条件替换（输出字段块、输出格式约束末句、案例 JSON、操作后截图命令行），对 `prompt_verifier` 做一处（输入说明行）；每处「不含锚点则跳过」，reverse 按新文精确回退旧文。
- 理由：与 `0039` / `0040` / `0046` 一致；提示词允许用户编辑，锚点条件替换保证已改写的行不被覆盖。
- 备选：直接改 `0038` 快照常量。放弃原因：迁移已应用，改历史迁移对存量库无效，且破坏迁移可追溯性。

**决策 6：前端按「新字段优先、旧字段兜底」呈现。**

- 做法：`TaskRunExecutorOut` 增 `click_timer` / `screenshot`（旧 `action` / `message` 保留为可选），attempt 派生同时给出新旧两套；卡片执行结果段：有 `click_timer` / `screenshot` 时新增「点击前时间」「点击后截图」两行（路径文本 + 有图可点开），有旧 `message` 时继续按原样显示为说明文字。
- 理由：存量任务记录不可回填，页面必须两种形状都能如实渲染；用「有则显示」而不是按任务新旧分流，避免额外状态判定。

## 模块防火墙自检

- 本次改动集中在 `engines/ai/`（引擎内部契约与角色装配）、`apps/ai_assistant/`（迁移与调试装配）与 `frontend/src/shared` + `ai-assistant` 模块。
- 不新增跨 App import：迁移只操作本 App 的 `AIAgent` 字段；`apps/ai_assistant` 对 `engines/ai` 的依赖是既有方向（apps → engines），未新增反向依赖。
- 不新增写库路径：迁移是唯一写库点（Django 迁移属框架层，不经过业务 api）；引擎不触碰 ORM。
- 前端不新增 HTTP 出口：任务详情与执行模型调试均复用既有接口，只改 DTO 与呈现。

## Risks / Trade-offs

- [模型漏抄或抄错时间戳/路径，且平台不修正] → 平台装配的点击证据块（点击前时间点 + 点击后截图，按工具轨迹配对）保持不动，排查与断言仍可依赖它；提示词把取值来源写到字段级，降低抄错概率。
- [丢掉 `message` 后，任务详情页少了「模型自己怎么说的」] → 执行侧思考与工具轨迹（`executor_trace`）照旧保留，说明性信息仍在；执行结果段改为结构化三件，可读性更稳定。
- [旧记录与新记录形状不同，前端分支出错] → 前端按「字段有则显示」渲染，并为存量旧形状补一条用例。
- [同一步多次点击时，单值 `click_timer` / `screenshot` 只能表达一次] → 该限制为需求方已确认的取舍；多次点击的完整证据由平台装配块（逐次成条）负责。
- [提示词迁移在用户已改写提示词的库上不生效] → 与既有迁移同口径：跳过并保持原样，在迁移说明与验收记录里写明实际是否写入。
