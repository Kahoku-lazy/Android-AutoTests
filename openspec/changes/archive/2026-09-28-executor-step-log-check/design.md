## Context

见 `proposal.md - Why`。与本设计相关的现状约束（均为代码事实）：

- 步骤结构 `Step {action, assertion}`（`engines/ai/agentscope/workflow.py`），planner 输出经 pydantic 解析；规划 / 执行 / 验收提示词是 **DB 数据**（`ai_agents.prompt_planner/executor/verifier`，种子来自迁移 0038，用户可改写），增量指引必须走迁移，且既有迁移（0039 / 0044）已确立「锚点 + 标记 + 可逆 + 不覆盖用户改写」的做法。
- 动作工具在真正调设备**之前**打点，并把 `action_time`（北京时间毫秒）写进返回 JSON（`apps/ai_assistant/tools.py` 的 `_with_action_time`）；只读工具不打点。
- 截图工具返回 `screenshot_path`（MEDIA 相对路径）；过程记录的 trace 行也已带 `screenshot_path`。
- 每步已有 5 秒取证窗：`_open_log_window` → 执行 → `_read_log_window` → 证据块 `log_evidence` 随截图一起进验收输入；`_step_action_times(result, seen_results)` 负责「只取本步新增的工具返回」（executor 上下文整个任务累积，不切片会把上一步动作算进本步——真机验证时踩到过）。
- 任务详情的过程记录以 `log` 数组原样下发，前端 `TaskAttemptCard` 按尝试卡片渲染执行结果 / 验收 / 验证截图 / 「设备日志证据」区块。

## Goals / Non-Goals

**Goals:**

- 执行模型那一步的记录里出现「日志检查」块：点击前时间点 + 点击后截图路径（成对、按发生顺序）；步骤被标记为需日志核对时，另含同一份 5 秒窗口证据（原始日志 + 命中标注）。
- 模块由平台装配，零额外模型调用、零额外 token；执行模型漏报也不影响该块完整性。
- 未标记步骤的展示与既有页面完全不变。

**Non-Goals:**

- 不改验收模型的输入、5 秒阈值、证据等级与合并排序口径（沿用 `device-log-evidence`）。
- 不改执行模型提示词与工具子集（不要求模型自觉调用日志工具、不要求模型抄写路径）。
- 不改平台任务（`ai-platform-task`）的 GoalPlan 链路、不改模型调试台的产出（调试台没有「步骤 / 断言」上下文）。
- 不在前端重算窗口、不新增接口、不改任务详情接口契约（只多一个过程记录键）。

## Decisions

**决策 1：标记落在 `Step` 上，字段名 `log_check`，缺省 `False`。**

- 做法：`Step` 增 `log_check: bool = Field(default=False, description=...)`；planner 提示词要求对每步判断并输出该键。
- 理由：判定口径与「断言」同源，交给规划模型最准（需求方已拍板）；带缺省值使存量 / 异常输出自然退化为「不需日志」，不会因缺字段解析失败。另加一个 `mode="before"` 的宽松校验：非布尔取值归一为布尔（可读为真即真，其余为假）——该标记只决定是否附带日志，MUST NOT 因为它把整步建模拖垮（`_coerce` 一旦校验失败会让整个规划作废）。
- 备选：① 平台按断言文案关键词猜——会误判，且规则要单独维护；② 按窗口内是否真有日志决定——最省事，但「断言要日志而设备没打」这一最需要看的情形会看不到结论。均不取。

**决策 2：点击证据由平台从**本步新增的**工具返回组装，用未截断的 `tool_usage` 切片。**

- 做法：新增纯函数 `_build_executor_log_check(result, skip_results, log_evidence, need_log)`：取 `result.tool_usage[skip_results:]`，按行序扫；
  - 每一次出现 `action_time` 的 `result` 行（沿用既有 `_extract_action_time`：JSON 优先 + 正则兜底）记一次点击；
  - 每次点击配对**其后第一张**带 `screenshot_path` 的行；已配对的截图不再分配给后续点击（一次截图不能同时证明两次点击）；其后没有截图则 `screenshot_path: ""`；
  - `need_log` 为真时把同一份 `log_evidence` 附在 `log` 键上。
- 理由：`skip_results` 与「动作发出时刻」基准用的是同一处切片，两者天然对齐，避免重演「把上一步的动作算进本步」。用未截断的 `tool_usage` 而非截断后的 trace（`_TRACE_TOOL_N=80`、`_OUTPUT_MAX=800`）：证据是事实记录，不应被展示用的截断规则影响。
- 备选：从 `_role_trace()` 的结果里取——会被 80 行上限与 800 字截断波及，且它与 `skip_results` 语义不同（取的是前 80 行）。不取。

**决策 3：过程记录新增一个键 `executor_log_check`，形状固定。**

- 形状：`{"clicks": [{"action_time": str, "screenshot_path": str}], "log": <证据块> | null}`。
- 理由：`clicks` 与 `log` 分开，使「未标记步骤只显示时间点与截图」只需 `log === null` 一个判据；前端不必解析 agent 文本。
- 备选：复用既有 `log_evidence` 键并在前端按标记隐藏——会让「验收侧证据」与「执行侧检查」两件事在数据上不可区分，违背「并存、互不替代」。不取。

**决策 4：前端新增一个展示组件，执行模型段渲染；日志部分复用既有渲染口径。**

- 做法：`StepLogCheck.vue`：逐条渲染「点击前时间点 + 截图路径文本」，路径有图时以缩略图呈现（点开看原图）；`log` 非空时内嵌既有 `StepLogEvidence`（同一份渲染口径，避免两处各写一套等级 / 合并文案）。`clicks` 为空且 `log` 为空时不渲染（不出现空壳区块）。
- 理由：与既有「设备日志证据」区块的呈现口径必须一致（`ai-task-publishing` 已有该口径的既有要求），复用组件是唯一不产生第二套口径的做法。
- 备选：把日志再渲染一遍（复制等级标签逻辑）——会产生两处文案漂移。不取。

**决策 5：规划提示词指引走可逆迁移，锚点取 0038 planner 快照里的输出字段行。**

- 做法：新迁移 forward：若 `prompt_planner` 含锚点 `- assert：该操作的断言，即操作后屏幕上可观察到的期望结果（供验证模型比对）。` 且不含标记 `log_check`，则在锚点行之后插入指引块（含判定口径与输出字段说明）；reverse：按插入块的精确文本删除。
- 理由：与 0044（verifier 日志证据指引）同一形态，测试与评审都已成型；含锚点才写 → 管理员改写过的提示词不动。
- 备选：直接覆写 `prompt_planner` 为最新全文——会清掉用户的改写，绝对不可取。

## 模块防火墙自检

- 跨 App import：无。改动集中在 `engines/ai/agentscope/**`（引擎内部）、`apps/ai_assistant/migrations/**`、前端模块内部。
- 写库收敛：迁移直接操作 `ai_agents.prompt_planner` 列，属于 Django 迁移的既有例外形态（与 0039 / 0044 一致）；运行期不新增任何写库路径，不触碰 `api.py` 的既有契约。
- 引擎边界：引擎不 import `apps.*` / `engines.device.*`（证据块仍以只含标准库类型的协议对象注入），不新增引擎依赖；前端不直连数据库。
- 通信通道：无新端点、无新 WS 事件、不改前端 HTTP 出口（过程记录随任务详情接口原样下发）。

## Risks / Trade-offs

- [把上一步的工具返回算进本步，导致点击证据张冠李戴] → 复用 `_executor_results_seen()` 的同一次快照做切片，并加用例：`skip_results` 大于本步新增数时 `clicks` 为空。
- [一步内多次点击只截一张图，配对后第二次点击显示「未截图」，被误读为缺陷] → 用例覆盖该情形并断言如实标注；文案明确「该次点击后未截图」。
- [规划模型把 `log_check` 一律标真，导致每步都带日志、页面变长] → 提示词写明判定口径与「不得一律标真」；spec 有对应场景；再有偏差可后续收紧。
- [新增过程记录键使任务详情响应体变大] → `log` 只在该步标记为真时出现，且与验收侧已下发的是同一份证据（不翻倍）；`clicks` 是短字符串列表。
- [既有任务（存量 `result`）没有该键] → 前端按「无该键即不渲染」处理，与既有任务兼容，不回填历史数据。
- [迁移锚点被平台后续改动改掉，导致指引不再下发] → 迁移测试固定锚点字符串；若将来 prompt 快照变更，锚点需同步，这是既有迁移模式的已知代价。
