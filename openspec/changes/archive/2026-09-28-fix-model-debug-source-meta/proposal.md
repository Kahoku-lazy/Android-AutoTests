## Why

AI 工具箱左侧「工具来源」列表中，「模型调试」一行显示「0/5 生效」——这是装配台计数逻辑漏改留下的假数据：模型调试与「无线端口」一样没有「交给助手」总闸、也不是可装配的开关型来源，但只有 port 被单独写了说明文案，debug 掉进通用分支，于是把「自定义 Skill 目录里的 Skill 个数」当成了自己的分母，分子则恒为 0（`buildLiveChips` 永不产出 `source === 'debug'` 的芯片）。用户看到「0/5 生效」会误以为模型调试有 5 项能力未能生效，实际这一行根本不存在「生效 / 不生效」这回事。

## What Changes

- 工具箱来源列表「模型调试」行的副标题不再展示「分子/分母 生效」计数，改为说明性文案，与该行真实语义一致：`规划 / 执行 / 验收 · 仅调试不交给助手`。
- 「模型调试」行的其余行为不变：仍无「交给助手」总闸、不参与「未装配」提示、不进入左上角「助手此刻可用」的生效芯片与统计条、点击仍进入三角色入口。
- 消除根因：让「无总闸来源」（设备提示词 / 无线端口 / 模型调试）在来源定义处各自声明自己的副标题文案，装配台的「n/m 生效」计数逻辑只服务真正参与装配的来源（平台业务 / 自定义 Skill），杜绝「无总闸来源借用其它来源数量当分母」的隐式兜底。
- **BREAKING**：无。

## 关联文档

- PRD-08（AI 助手 · 设备操控 · 工具箱）。该子 PRD 与上次「无线端口」变更情况相同，尚未产出；本次需求来源为需求方在评审工具箱页面时提出的疑问（「模型调试下的 0/5 生效是什么意思」），已确认为显示缺陷并要求按 A 方案修正。
