## Context

- 参数 schema 的唯一产地是 `apps/ai_assistant/tools.py::get_tool_debug_schema()`：它对工具函数做 `inspect.signature`，产出 `name` / `type` / `required`（+ `default`、`options_source`）。**没有中文名与说明**。
- 前端 `ToolDebugPage.vue` 的参数块当前渲染：`{{ p.name }}` + 「必填/可选」`<em>` + 类型 `<span>`；参数说明无处可取。
- 工具 docstring 里已有中文说明（`Args:` 段），是现成可用的说明来源；同文件已存在按「工具 + 参数」登记的元数据先例（`DEBUG_PARAM_OPTIONS`）。
- 前端约束（`frontend/AGENTS.md`）：组件只做渲染、禁止魔法字符串、字号只取 `tokens.css`；`frontend/src/modules/ai-assistant/AGENTS.md` 记录调试页行为，改口径要同步。
- 已有 Python 侧读前端源码做契约对拍的先例（`tests/graybox/unit/test_*_frontend_contract.py`）。

## Goals / Non-Goals

**Goals:**

- 参数以「中文名（english_name）」呈现，保留英文名可见，附「必填 / 可选」
- 中文名与说明**一处维护、多工具复用**，加工具/参数不需要改前端
- 说明以悬浮提示呈现，不铺开表单
- 现有候选下拉、本地校验、写工具二次确认等行为完全不变

**Non-Goals:**

- 不给参数做多语言（i18n）切换，只做中文
- 不改工具函数的签名、默认值、执行语义
- 不做「按参数类型自动选控件」等表单增强
- 不改模型调试页（那一页展示的是工具清单，不是参数表单）

## Decisions

### D1 中文名放后端集中表，前端零硬编码

新增 `PARAM_LABELS: dict[str, str]`（参数名 → 中文短名）+ `TOOL_PARAM_LABELS: dict[tuple[str, str], str]`（工具级覆盖），`get_tool_debug_schema` 下发 `label`。

- 理由：参数语义是数据，集中一处；前端只渲染，符合「组件不做业务逻辑/禁止魔法字符串」；新增工具或参数不改前端。
- 备选：前端维护映射表 → 每加一个工具都要改前端，且同名参数（`serial`、`name`）在不同工具下语义可能不同，容易漂移。
- 备选：从 docstring `Args:` 自动抽短名 → docstring 是给模型看的长句，抽短名不稳定，会出现「时间点（北京时间）。可写 `2026-...`」这种半句标签。

### D2 说明（hint）从 docstring 的 Args 段解析

按参数名在 docstring 的 `Args:` 段取该参数首行说明（续行并入），作为 `hint`；取不到给空串。

- 理由：说明文本已经写好且随工具演进，无需二次维护；只作提示，缺失不影响使用。
- 备选：另建说明表 → 与 docstring 双份维护，必然漂移。

### D3 标签口径：中文名（english_name）+ 必填/可选

主标签 `中文名（english_name）`，其后「必填」或「可选」，再跟类型；`hint` 走 `title`/悬浮提示。

- 理由（需求方口径）：中文便于使用，英文便于对接口与排查；两者都要在，缺一不可。
- 备选：只显示中文 → 排查时要回代码里找参数名，且与 HTTP 网关入参对不上。

### D4 前端只加渲染，不加判断

组件里只做「有这个字段就显示」的渲染，不做中文/英文拼接以外的逻辑；拼接放在模板表达式或模块内的纯函数里。

- 理由：遵守组件只渲染的硬性约束；拼接是纯展示，不需要额外状态。
- 备选：把标签拼好由后端下发 `display_label` → 前端更薄，但把展示口径塞进接口，后续换样式要改后端；保留 `label` + `name` 两个字段更灵活。

### D5 字号与样式走既有令牌

新增标签与提示样式使用 `tokens.css` 的字号令牌，不硬编码 `font-size`；沿用调试页现有样式文件。

- 理由：`frontend/AGENTS.md` 硬性要求；且本页已有样式层文件，无需新造风格。

## 模块防火墙自检

- **跨 App import**：只改 `apps/ai_assistant/tools.py` 内的 schema 产出，不新增跨 App 依赖。
- **写库收敛**：本变更零写库、零新表。
- **引擎边界**：不触碰引擎层；工具签名与执行路径不变。
- **通信通道**：不新增接口、不新增 WS；复用既有 `GET /api/ai/platform-tools/{name}` schema 端点，只在响应里加字段。
- **前端边界**：参数中文名不落在前端常量里；前端仍只经 `api/toolbox.ts` 这一个出口取 schema。

## Risks / Trade-offs

- [参数标签表漏登记新参数，回退成英文名] → 回退是安全行为（不显示空标签），并在契约测试里断言常用参数有中文名；漏登记只影响观感，不影响调用
- [docstring 解析规则脆弱（缩进/续行变化）] → 解析失败只导致 `hint` 为空，不影响 `label` 与调用；解析规则集中在一处并有单测
- [中文名与英文名拼接后标签变长，窄栏可能换行] → 沿用既有 `td-field-label` 的排版（允许换行），必要时只压缩类型标签，不改信息量
- [接口加字段可能与旧前端不兼容] → 纯新增字段，旧前端不读即忽略，无需版本协商

## Migration Plan

- 无数据迁移；后端先上线（新增字段可选消费），前端随后使用；回滚只需回退前端模板，接口多出的字段被忽略
