## Context

- 证据的**生产**已经完成（变更 `archive/2026-09-28-add-device-log-evidence` / `add-device-log-port-console`）：编排层在每步动作前开窗、验收前读窗，把证据块写进该步的过程记录。
- 证据块的字段：`channel / window_id / window_opened_at / action_time / action_times / threshold_seconds / baseline_seconds / window_line_count / conclusion / hits[] / before_action[] / out_of_window[] / lines[]`；`hits[]` 每项含 `keyword / grade / count / timestamps[] / occurrences[] / features[] / baseline_occurrences[]`。
- 等级取值：`strong`（强证据）/ `periodic`（疑似周期，不能单独作为通过依据）/ `before_action`（动作前）/ `out_of_window`（超窗）；结论取值：`hit` / `no_hit` / `no_log` / `out_of_window`。
- 详情接口 `serialize_agent_task_detail` 用 `parse_task_result(task.result)` 原样下发整个结果对象，因此 `run.log[i].log_evidence` **已经到达前端**（现场任务 id=101 的 5 条过程记录都带该字段），后端与数据表无需改动。
- 前端现状：`helpers/task-detail.ts` 把过程记录聚合成「步骤 → 尝试」；`TaskAttemptCard.vue` 展示执行结果（执行/验收/截图）并把 Agent 过程折叠；`frontend/src/shared/types/ai.ts` 的 `TaskRunLogEntry` 尚无 `log_evidence` 字段。
- 既有页面口径（必须沿用）：同毫秒合并、最新在上、合并条内部不倒序；证据链只在「日志查询」与「验收输入」里出现过，页面尚未呈现。

## Goals / Non-Goals

**Goals:**

- 在任务详情页**每步的尝试卡片内**展示该步的验收日志证据：摘要常显、详情折叠，让「验收 pass/fail 的依据」可见。
- 摘要一眼看清：等级（强证据 / 疑似周期 / …）、命中条数、关键词、功能点。
- 详情可查：命中（含时间戳与那一刻原文）、动作前基线、超窗（含延迟秒数）、窗口原始日志。
- 无证据时如实降级为一行说明（老任务、端口未监听/已关闭都走这条路）。
- 展示口径与 AI 日志查询一致，且前端不做二次排序/合并。

**Non-Goals:**

- 不改引擎的证据算法、等级判定与阈值配置。
- 不改后端序列化、不新增接口字段、不动数据表（数据已下发）。
- 不做证据的检索、导出、下载、跨步骤汇总统计。
- 不接管「未展示的其它遗留项」（端口三列可编辑、存档文件页面入口）。

## Decisions

### D1 挂在「尝试」卡片内，而不是详情页底部汇总

一条过程记录 = 一次尝试，证据就挂在这条记录上，天然与「这次尝试的验收结论」同屏。放底部汇总需要在页面上重新归属步骤与尝试，还会让用户来回滚动对照。选择：在 `TaskAttemptCard.vue` 的执行结果区（验证截图之后）插入证据区块。

### D2 摘要常显 + 详情折叠

验收依据是判断任务成败的关键信息，默认藏起来等于没做；但完整证据（原始日志可能几十行）又不该铺满详情页。选择：摘要恒显一行（等级标签 + 条数 + 关键词 + 功能点），详情用折叠（沿用页面既有的 `el-collapse` 皮肤）；无可折叠内容时不渲染折叠区。

- 备选「全部默认收起」（与 Agent 过程一致）：用户仍看不到判定依据，否。
- 备选「全部展开」：原始日志把页面撑长、噪声大，否。

### D3 等级与结论的中文口径集中在 helper

`strong/periodic/before_action/out_of_window` 与 `hit/no_hit/no_log/out_of_window` 一律由新增的 `helpers/log-evidence.ts` 映射为中文标签与配色类，组件只渲染。理由：同一口径将来在别处（如任务列表、报告）复用时不必抄第二份；同时便于单测覆盖。

摘要文案口径：有命中 → `强证据 N 条 · keyword · 功能点A / 功能点B`；命中多条时全部列出（沿用「多条命中全给」的既有口径）；无命中但有日志 → `未命中（窗口内 N 行）`；窗口无日志 → `窗口内无日志`；无证据对象 → `本次未采集到设备日志证据`。

### D4 详情四段，顺序固定

1. **命中**：每条命中一行头部（等级标签 + 关键词 + 条数 + 功能点），下面列各次时间戳与那一刻的原文（`occurrences[].text`，保留换行）。
2. **动作前**：基线内同名日志（时间 + 原文），用于解释「疑似周期」。
3. **超窗**：晚于「动作 + 阈值」的日志，附 `delta_seconds`。
4. **窗口原始日志**：`lines[]` 原样呈现（同毫秒合并条内部换行、最新在上），前端不排序。

空段不渲染，避免「动作前（0）」这类噪声行。

### D5 类型补在共享 DTO，供前后端契约对读

`frontend/src/shared/types/ai.ts` 增加 `TaskLogEvidence` 及子结构（hit / line / feature / occurrence），并在 `TaskRunLogEntry` 上加 `log_evidence?`。所有字段可选：老任务没有该字段、新任务里个别字段也可能缺省，展示层必须容错（MUST NOT 因缺字段白屏）。

### D6 组件拆分与文件体积

新增 `components/StepLogEvidence.vue`（渲染）+ `StepLogEvidence.style.css`（样式），`TaskAttemptCard.vue` 只加一行挂载与一个 prop。理由：`TaskDetailPage.vue` 已 525 行、`TaskAttemptCard.vue` 已 260 行，500 行门禁在即，新逻辑不再往既有文件里塞。

## 模块防火墙自检

- **跨 App import**：无（纯前端改动）。
- **跨 App service/runner import**：无。
- **写库路径**：无写操作；本变更不触碰后端与数据库。
- **引擎边界**：不 import 引擎、不触碰设备句柄（证据已是后端下发的只读 JSON）。
- **前端出口**：不新增 HTTP 调用，不新增裸 `fetch`/`axios`（数据随既有任务详情接口到达）。
- **通道收敛**：不新增生产点，不改 WS/SSE。

## Risks / Trade-offs

- [证据体量大导致详情页变长/变慢] → 摘要常显、详情折叠；原始日志只在展开时渲染；不做图片与大表格。
- [老任务无 `log_evidence` 字段] → 所有字段可选 + 缺失时渲染一行灰字说明（有专门用例）。
- [等级被误读为「通过依据」] → 「疑似周期」在摘要里显式标出并给出提示语气（它不能单独作为通过依据）；等级配色沿用既有状态色，不新造颜色。
- [与 AI 口径漂移（前端排序/合并）] → 前端只消费服务端顺序，纯函数只做映射不做排序，并有「不重排」用例守住。
- [存量任务的窗口日志顺序与新口径不同] → 现场 4 条历史任务（id 98–101，产生于「最新在上」口径上线前）的 `lines[]` 是时间正序；页面如实呈现存储顺序，MUST NOT 改写历史数据。已用真机页面与服务端原文逐行对拍（32/32 行、顺序完全一致、无重排）。若需求方希望老任务也统一按最新在上显示，需要单独决策（属于「展示期改写历史」）。
- [现场窗口里暂时没有同毫秒合并条] → 合并条的换行渲染由前端用例与「无线端口」日志窗口（同一份合并实现、真实设备数据）覆盖；任务详情页一旦出现合并条即按 `text` 内部换行渲染。
- [500 行门禁] → 拆成独立组件与独立样式文件；既有文件只各加一行。

## Migration Plan

1. 纯前端发布：随前端构建生效，无迁移、无配置项、无后端发布顺序要求。
2. 回滚：还原前端文件即可；历史任务的 `log_evidence` 仍在库里，不受影响。
3. 存量数据：老任务无证据字段 → 页面显示「本次未采集到设备日志证据」，不视为缺陷。
