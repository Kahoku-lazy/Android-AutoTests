## Why

AI 做设备任务时，验收阶段其实已经拿到「设备日志证据」（哪一刻命中了哪个关键词、属于哪个功能点、证据等级是强证据还是疑似周期），但这些内容只落在任务记录的 JSON 里——用户在任务详情页只能看到「验证截图 + 验收 pass」，看不到判定依据。上一次变更留下的遗留项就是这个：证据链做进了引擎，却没做到页面上。

## What Changes

- 任务详情页的**每一步「尝试」卡片**内新增「设备日志证据」区块：**摘要常显 + 详情折叠**，位置紧接「执行结果」（验证截图之后）。
- 摘要常显一行：命中等级与条数、关键词、命中的功能点；疑似周期必须被显式标出（它不能单独作为通过依据）。典型形态：`强证据 1 条 · switch_off · 关闭设备成功（#1 设备开关）`。
- 折叠详情分四段：**命中**（关键词 / 等级 / 功能点 / 各次时间戳 / 那一刻的原文）、**动作前**（基线内的同名日志，作为「疑似周期」的依据）、**超窗**（晚于「动作 + 阈值」的日志，附延迟秒数）、**窗口原始日志**（同毫秒合并条，内部保留换行，最新在上）。
- 证据缺失时如实降级：该步没有日志证据（端口未监听 / 已关闭 / 老任务无此字段）时，只显示一行灰字说明，MUST NOT 报错、MUST NOT 空着不提。
- 展示口径与既有 AI 日志查询完全一致（同毫秒合并、最新在上、合并条内部不倒序），**前端只消费后端顺序、不再排序**；本区块只读，MUST NOT 提供任何写操作。
- 范围外：不改引擎证据算法与证据等级判定；不改后端接口与数据表（`log_evidence` 已随任务详情接口下发）；不做日志证据的检索/导出/下载。
