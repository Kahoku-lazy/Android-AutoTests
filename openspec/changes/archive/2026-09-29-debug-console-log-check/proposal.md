## Why

上一份变更（`executor-step-log-check`）把「点击前时间点 + 点击后截图 + 5 秒日志」补进了**任务详情**，但当时把**模型调试台**列为非目标。实测下来，调试台恰恰是排查「这个模型这一步到底点没点成、设备有没有响应」的第一现场：那里只回模型的回复与工具调用轨迹 —— 点击前时间点藏在工具返回 JSON 里（且调试台只展示每次返回的前 160 个字符，时间点位于该 JSON 的最后一段，稍长就被截掉看不见），5 秒日志则完全没有，用户只能靠模型自己在 message 里抄一遍（模型漏抄就没有）。

## What Changes

- 模型调试台的调试对话（挂设备工具的角色，如执行模型）响应新增「日志检查」块：本轮**每一次**产生副作用的点击给出**点击前时间点**与**点击后截图路径**（同一配对规则：点击之后第一张截图，已配对的不重复分配，无则如实标注未截图）；并附该时间点后 **5 秒**窗口内的日志——原始日志（同毫秒已合并、最新在上）+ 命中关键词与功能点标注（含证据等级），与任务步骤证据**同源**（同一份证据数据、同一阈值、同一合并与等级口径）。
- 采集时机与生产链路同口径：平台在把内容交给该角色**之前**对目标设备开一次日志证据窗，对话结束后读窗；端口处于关闭监听 / 总线未启动时，**如实不给日志**，MUST NOT 因此打开端口、MUST NOT 伪造日志。
- 本轮没有任何副作用点击时 MUST NOT 产出该块（前端不渲染空壳）。
- 该块 MUST 由平台装配，MUST NOT 要求模型在自己的回复里抄写时间点 / 路径 / 日志。
- 点击↔截图的配对与切片实现收敛到**一处共享**：任务步骤链路与调试台调用同一份纯函数，避免两套规则漂移。
- 前端在助手消息内呈现该块，复用任务详情已有的展示组件与文案口径。
- **BREAKING**：无（响应新增一个键；无点击的对话与既有一致）。

## Impact

- 后端：`apps/ai_assistant/model_debug.py`（开窗 / 读窗 / 组装响应）、`apps/ai_assistant/views_model_debug_drf.py`（无契约变化，响应多一个键）。
- 引擎：`engines/ai/agentscope/`（配对与切片纯函数收敛到共享模块，任务链路与调试台共用；调用方向仍为 apps → engines）。
- 前端：`api/toolbox.ts`（调试回复 DTO）、`composables/useModelDebug.ts`（消息 DTO 透传）、`ModelDebugPage.vue`（助手消息内渲染既有 `StepLogCheck`）。
- 测试：`tests/graybox/unit/`（调试对话产出该块、无点击不产出、无端口监听如实不给日志）、`frontend/tests/ai-assistant/p0/`。
- 不改动：任务步骤链路的既有行为、验收模型输入、5 秒阈值与等级口径、无线端口面板的监听开关语义（平台不会替用户打开端口）。
- 副作用代价：读窗会等到「最后一次点击 + 5 秒」，因此调试对话的返回比现在晚约 5 秒（前端本就不设等待上限）。
