## Context

- **等待上限**：`frontend/src/shared/api-client.ts` 的 axios 实例写死 `timeout: 120000`；调试对话 `chatWithModelDebug` 只传 `{text, serial}`，因此实际受 2 分钟约束。既有前端用例以「只传两个实参 = 不设上限」为断言，该假设不成立（实例默认值仍生效）。
- **费用**：后端 `run_role_chat` 的响应已带 `cost` 与 `usage`，前端 `useModelDebug` 已把它收进消息对象，但页面没有任何渲染点——钱花了不显示。
- **设备池**：执行模型调试挂的是 `ExecutorRole.spec.tool_names`（即引擎侧 `VISION_TOOLS`），其中含 `acquire_device` / `release_device`；生产链路确实会用到它们（技能手册写明"必要时 acquire_device 锁定"），所以不能从角色规格里删。但 `ai-model-debug` 要求「调试对话不得改变设备池占用状态」——设计当初只做到「候选过滤 + 不 acquire」（`2026-09-23-mount-real-tools-in-model-debug` 的 D6），模型仍可自行调用这两个工具。
- **不变约束**：调试能力仅超管；调试对话不落库；设备选定与二次确认口径不变；`RoleSpec` 仍是生产工具子集的唯一真相源，页面展示与实际装配同源。

## Goals / Non-Goals

**Goals:**

- 调试对话不再受前端固定等待上限约束，且页面如实描述当前行为。
- 调试对话展示本轮费用与会话累计费用。
- 执行模型调试不再改变设备池占用状态，与验收标准一致。

**Non-Goals:**

- 不做「停止」按钮（需求方已拍板）——跑飞的调试只能刷新页面。
- 不做服务端硬超时（要真能掐断需把调试对话改成后台任务 + 轮询，另立一单）。
- 不做调试留痕落库 / 审计（另一议题，未纳入本单）。
- 不动其它接口的等待上限、任务链路与生产装配、执行与验收角色的其余工具、点击证据与 5 秒日志检查、设备选定与二次确认口径。

## Decisions

**D1 取消上限用「显式声明不设上限」，而不是不传超时参数。**
理由：共享实例的默认上限不因缺参而消失，不显式取消等于没改。
备选：改共享实例的默认值——会连带放开所有接口，否决；备选：给调试对话设一个更长的固定值——仍与「不设固定上限」的验收标准相抵，否决。

**D2 费用只展示，不落库、不新增接口。**
理由：本轮费用与用量已在调试响应里，前端只是没渲染；新增用量接口属过度设计。
备选：后端按智能体聚合调试花费——需要状态与写库，与「对话不落库」相抵，否决。

**D3 会话累计在前端口径内计算并随会话生命周期归零。**
口径：累计 = 本次会话里各轮返回的费用之和；清空对话或切换角色后归零；某轮未返回费用时该轮不显示、也不计入累计（不以 0 冒充）。
备选：后端记账——同上否决。

**D4 设备池记账工具按名字在调试角色构造处排除，不动角色规格。**
理由：生产链路的执行模型确实需要 `acquire_device` / `release_device`（技能手册的生产步骤里会用到），改 `RoleSpec` 会削掉生产能力；排除只发生在调试台现场构造的那个调试角色上。
代价：调试时无法验证这两步——如实说明，需要单独验证时走平台工具调试页（该页支持对写工具单独调用并二次确认）。
备选：改引擎规格——影响生产，否决；备选：改验收标准承认调试可占用——需求方已拍板选「改代码不装配」，否决。

**D5 「取消上限」必须与「不提供中止」一起如实写在页面上。**
理由：只说"不设上限"会让操作者以为等不下去可以停；实际只能刷新页面，且刷新不会中止后端本轮执行。文案与验收标准里的"如实描述"一致。

## 模块防火墙自检

- 跨 App import：无新增。工具名排除只发生在 `apps/ai_assistant/model_debug.py`，读的是本 App 的 `TOOLS` 表与引擎角色规格（上层 → 引擎方向不变）。
- 写库路径：本单无任何写库；调试对话仍不落库，费用只在内存展示。
- 前端不直连数据库；费用展示为只读，不引入写操作。
- 引擎边界：不改 `engines/ai/agents/config.py` 的角色工具常量与生产装配；排除仅作用于调试台构造的调试角色。

## Risks / Trade-offs

- [取消上限且无停止按钮：一次跑飞的调试只能刷新页面，后端仍把本轮跑完] → 页面如实标注；「停止」与服务端硬超时登记为后续单独立项。
- [排除记账工具后，调试时无法验证 acquire / release 两步] → 如实说明并指向平台工具调试页（可对单个写工具发起调用 + 二次确认）。
- [长跑调用会占住后端工作线程（无服务端超时）] → 已知取舍，与本单"不做服务端硬超时"同源；风险登记在案。
- [工具名以名单方式排除，引擎日后新增同类记账工具会漏] → 排除集合集中在一处常量，并加用例守护；引擎新增记账工具时用例与清单须同步。
- [会话累计与任务卡片的计价展示口径被误认为同一回事] → 累计取的是调试响应里的 `cost`（引擎计价），不前端估算；文案写清"本次会话累计"。
