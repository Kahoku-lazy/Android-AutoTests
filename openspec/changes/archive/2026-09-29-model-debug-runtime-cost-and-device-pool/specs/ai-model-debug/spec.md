# ai-model-debug — 调试对话的运行时长、费用与设备池记账口径

## MODIFIED Requirements

### Requirement: 调试对话按该角色真实装配运行

调试对话 MUST 挂载该角色在实际装配中的工具子集（与角色规格 `RoleSpec.tool_names` 同源），MUST NOT 以空工具集运行；**例外：设备池记账工具（`acquire_device` / `release_device`）MUST NOT 装配进调试对话**——它们改变设备池占用，与「需要设备的角色须先选定设备并获得一次性授权」中「调试对话不得改变设备池占用状态」相抵，故由「不装配」兑现，其余工具不受影响。对话结果 MUST 返回并展示本轮的**工具调用轨迹**：每次调用 MUST 至少含工具名与结果状态，MUST 标明该工具为只读或写。Skill 的挂载行为 MUST 与既有实现保持一致（仍不挂载），MUST NOT 因本变更改变。

#### Scenario: 执行模型调试对话能真正调用工具

- **WHEN** 超管在执行模型调试页选定设备并发送一条会触发设备操作的内容
- **THEN** 模型可以调用执行模型工具子集内的工具
- **AND** 助手消息内可见工具调用轨迹（工具名与结果状态）

#### Scenario: 各角色只挂自己的子集

- **WHEN** 超管分别打开规划 / 执行 / 验收模型调试页
- **THEN** 规划页的工具名属于页面流工具（list_page_flows / get_page_flow）
- **AND** 执行页含设备控制与截图工具，验收页为截图工具

#### Scenario: 设备池记账工具不进调试对话

- **WHEN** 超管对执行模型发起调试对话并查看本轮工具子集
- **THEN** 子集内不含 `acquire_device` 与 `release_device`
- **AND** 本轮结束后设备池的占用状态与本轮开始前一致

### Requirement: 需要设备的角色须先选定设备并获得一次性授权

当该角色的工具子集中存在声明 `serial` 参数的工具时，调试对话请求 MUST 携带 `serial`，且服务端 MUST 校验该 `serial` 对请求者可见、状态在线且当前未被占用；不满足时 MUST 返回可读 4xx，且 MUST NOT 触发任何模型调用。前端 MUST 在发送前取得一次性授权（二次确认），确认内容 MUST 包含目标设备标识与本次将挂载的写工具数量；用户取消时 MUST NOT 发出请求。`serial` MUST 以与生产装配同口径的形式进入模型输入。调试对话 MUST NOT 改变设备池的占用状态——该约束由「不装配设备池记账工具」（见「调试对话按该角色真实装配运行」）兑现，MUST NOT 依赖模型自觉不调用。写工具数量 MUST 按实际挂载的子集计数（因此不含被排除的记账工具）。

#### Scenario: 未选设备时被拒

- **WHEN** 超管对执行模型发起调试对话但未提供 serial
- **THEN** 返回可读 4xx，且不产生任何模型调用

#### Scenario: 设备不可用时被拒

- **WHEN** 提供的 serial 对请求者不可见、不在线或已被占用
- **THEN** 返回可读 4xx，且不产生任何模型调用

#### Scenario: 取消授权则不发起调用

- **WHEN** 超管在确认框中选择取消
- **THEN** 不发出调试对话请求

#### Scenario: 规划模型不需要设备

- **WHEN** 超管对规划模型发起调试对话
- **THEN** 无需提供 serial 也能调用（其工具子集不含设备操作工具）

### Requirement: 调试对话不设前端等待上限且如实描述行为

前端 MUST NOT 对调试对话施加固定的等待上限，MUST NOT 在等待文案或页面提示中声明「单次最长 5 分钟」这类限制。该请求 MUST **显式**声明不设等待上限——MUST NOT 依赖「不传超时参数」：共享 HTTP 客户端自带默认上限，不显式取消即等于仍受其约束。取消上限 MUST 只作用于调试对话，其余接口的默认上限 MUST 保持不变。页面 MUST 如实描述当前行为：挂载该角色真实工具、会真实操作所选设备、不提供中止（跑飞的调试只能刷新页面，且刷新不会中止后端本轮执行）。

#### Scenario: 长跑不被前端掐断

- **WHEN** 一次调试对话因多轮工具调用耗时超过 5 分钟
- **THEN** 前端不因固定超时中断该请求

#### Scenario: 请求显式取消默认上限

- **WHEN** 检查调试对话请求的发送参数
- **THEN** 该请求显式声明不设等待上限，不沿用共享客户端的默认上限
- **AND** 其它接口的请求仍沿用各自既有上限

#### Scenario: 页面不再声明旧限制

- **WHEN** 超管打开任一角色调试页
- **THEN** 页面不出现「不挂工具 / 不碰真机 / 单次最长 5 分钟」这类与当前行为不符的描述

## ADDED Requirements

### Requirement: 调试对话展示本轮与会话累计费用

调试子页 SHALL 在每条助手回复内展示该轮的**费用**，并 SHALL 在调试对话栏展示本次会话的**累计费用**（自进入该角色调试页或上次清空以来）。费用 MUST 取自本轮调用实际返回的用量与计价，MUST NOT 由前端另行估算。调用未返回费用时 MUST 如实不显示该数字，MUST NOT 以 0 或占位数字冒充。费用展示 MUST 为只读，MUST NOT 因此新增服务端接口、MUST NOT 落库；切换角色或清空对话后累计 MUST 归零。

#### Scenario: 单轮回复显示本轮费用

- **WHEN** 超管完成一次返回了费用的调试对话
- **THEN** 该条助手消息内可见本轮费用

#### Scenario: 会话累计随轮次累加

- **WHEN** 超管在同一角色调试页连续完成两次各返回费用的对话
- **THEN** 对话栏显示的累计费用等于两轮费用之和

#### Scenario: 清空对话后累计归零

- **WHEN** 超管点击清空对话
- **THEN** 累计费用归零，且不显示任何残留数字

#### Scenario: 无费用返回时如实不显示

- **WHEN** 某轮调用未返回费用
- **THEN** 该条消息不显示费用数字
- **AND** 累计费用不因该轮变化
