## Context

- demo 已证明可行：登录模块 160 节点 / 262 条边，21 条 Requirement，人工声明只用了 30 行；工作台页面在 `file://` 下双击可用（载入 JSON、缩放平移、拖动并保存位置、详情、按功能模块筛选）。
- 当前生成器与模板在 `temps/arch_graph/`，该目录被 `.gitignore:199` 忽略；`tools/` 才是仓内工具的正式位置（既有 `gen_arch_stats.py`、`generate_report.py` 等）。
- 工具是纯 Python 扫描器：只读文件系统 + 正则/AST，不 import Django、不连库、不起服务。页面是自包含单文件 HTML。

## Goals / Non-Goals

**Goals:**

- 一条命令重建「关系图 JSON + 工作台页面 + 文档页」，产物路径稳定、可重复。
- 人工声明外置成仓库内文件，能评审、能版本化、能按模块增量补。
- 保持 `temps/` 只承担临时自检脚本的角色，正式产物不再依赖它。

**Non-Goals:**

- 不做断锚门禁：不新增 `--check`、不改 `tools/check_gates.py`、不接 CI、不动退出码契约。
- 不覆盖登录之外的模块（声明量会涨一个量级，另立变更）。
- 不做平台内页面（要立单、写规格、动前后端）。
- 不入库、不建表、不加 `doc_type`。

## Decisions

**1. 入口形状照 `tools/gen_arch_stats.py`：单文件 CLI + 同级数据目录。**
理由：仓内工具已统一这个形状，读者不用学第二套。备选（做成 `tools/arch_graph/` 包）会让入口变成 `python -m tools.arch_graph`，与既有习惯不一致，收益为零。

**2. 声明用 JSON，不用 YAML。**
理由：`tools/` 里既有数据文件（`boundary-whitelist.json`、`frontend-whitelist.json`）都是 JSON，且不需要新增解析依赖。备选 YAML 更省括号，但要引依赖或写解析器。

**3. 页面模板内嵌 JSON，而不是运行时 fetch。**
理由：工作台要能双击打开（`file://`），此时 fetch 兄弟文件会被 CORS 拦掉。代价是页面 ~168KB，换来零依赖、零部署、可当附件发给别人。

**4. 同一份 JSON 注入两个模板，两个页面同源产出。**
理由：文档页已经交付过，若只转正工作台模板，文档页就变成没人能重建的孤儿产物。两个模板共用注入逻辑，成本约 10 行。默认全出，`--only` 可只出其中一个。

**5. 工具内部保留结构自检，但不提供检查语义。**
生成后断言「每条边的两端都在节点表里」「健康度计数与节点表一致」，不自洽就以非 0 退出 —— 这是"工具必须产出合法数据"，不是需求-代码规则检查，因此不违反本轮"不做检查"的范围。

## 模块防火墙自检

- 不 import `apps.*` / `gateway.*` / `shared.*`：工具只在 `tools/` 内运行，跨模块依赖为零。
- 不写库、不连 Redis、不新增端点、不改 Serializer 与 `api.py`。
- 前端零改动：页面是独立的静态 HTML，不进 `frontend/` 构建。

## Risks / Trade-offs

- [声明与代码漂移：改了代码不更新声明，图会出现「孤儿需求」] → 这正是图要暴露的信号，本轮明确不拦；等报告稳定后再决定是否升级为门禁。
- [产物写进 `dev_docs/`，与"临时产物进 temps"的约定看似冲突] → 产物是**交付物**（给人看的报告与页面），不是临时文件；`dev_docs/DEV_TEST/设计方案与报告/` 正是这类文档的既定位置。
- [页面体积随图变大而涨] → 登录模块 168KB；全仓量级预计 1MB 上下，仍可接受。若后续过大，再改为"外部 JSON + 本地静态服务"。

## Migration Plan

1. 新增 `tools/gen_arch_graph.py` 与 `tools/arch_graph/`（声明 + 模板）。
2. 实跑生成三份产物，与 demo 期的输出逐项对齐（节点数 / 边数 / 健康度）。
3. 更新 `temps/arch_graph/` 的两个自检脚本指向新路径，跑通。
4. 删除 `temps/arch_graph/` 里已被转正的生成器与模板，避免两份真相源。
5. 回滚：删除新增文件即可；产物为生成物，可随时重建。
