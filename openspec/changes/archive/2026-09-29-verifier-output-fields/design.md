## Context

动机见 `proposal.md - Why`。方案需要的现状约束（已核实）：

- 验收模型的输出契约由引擎侧 `VerificationOutput` 建模，工作流用 `_coerce` 解析；解析失败走固定兜底。通过判定目前是 `verdict.result is True`（两处），失败原因回灌是 `retry_hint = verdict.actual`。
- 验收模型的**工具子集只有截图工具**（规格已定，本次不改），因此它拿不到点击时刻、也读不了日志 —— 这两条坐标只能从平台**下发给它的输入**里取：执行侧证据文本里已有「点击前时间戳=…」（上一变更加的），日志证据文本里已有命中关键词与每条日志的时间戳。
- 验收模型的输出形状由库中系统提示词决定（`ai_agents.prompt_verifier`）。该提示词已被 0044（日志证据解读指引，含「判 true/false」措辞）与 0047（执行侧输入说明）改过，因此锚点必须取**当前库中原文**；本次仍走「短语级、可逆、按锚点条件替换」的迁移。
- 前端任务详情页只消费 `verifier.result` 与 `verifier.actual`；存量任务库里已有大量旧形状（布尔 `result` + `action/assert/actual`）记录。

## Goals / Non-Goals

**Goals:**

- 验收模型输出固定五字段，任务链路与验收模型调试对话共用同一契约。
- 保留失败原因回灌（`actual`），且新坐标（点击前时间戳 / 日志关键词时间戳 / 验证截图路径）在页面上可核对。

**Non-Goals:**

- 不给验收模型加日志查询或点击工具（工具子集不变，坐标从输入取）。
- 不改平台装配的点击证据块与 5 秒日志证据口径。
- 不由平台改写模型回复、不替模型补坐标（取不到就如实为空）。
- 不改执行模型的输出契约（上一变更已定）。

## Decisions

**决策 1：契约改在既有 `VerificationOutput` 上，五个字段；`result` 由布尔改 `PASS`/`FAIL`。**

- 做法：`result: Literal["PASS","FAIL"]`、`click_timer`、`log_assertion_timer`（别名为契约要求的 `logAssertionTimer`，序列化按别名下发）、`screenshot`、`actual`；解析路径与兜底不变（解析失败 → `FAIL` + 三个空串 + 可读 `actual`）。
- 理由：与执行模型那次的处理一致，避免新旧两套契约并存导致过程记录出现更多形状；前端 `normalizeResult` 已同时支持布尔与 `pass/fail` 字符串，改动可控。
- 备选：保留布尔 `result` 并另加 `verdict` 字段。放弃原因：需求方明确要 `PASS/FAIL`。

**决策 2：字段名 `logAssertionTimer` 按需求方给的原样落库（camelCase），不是 snake_case。**

- 做法：Python 字段名用 `log_assertion_timer` + alias `logAssertionTimer`，下发与落库均按别名。
- 理由：该键是需求方指定的契约字段名（与 `click_timer` 混用大小写是需求方口径）；用别名可同时满足「契约键名不变」与「Python 侧命名规范」。
- 备选：统一改成 `log_assertion_timer`。放弃原因：与需求方给的字段名不一致。

**决策 3：两条坐标从平台下发的输入里取，模型照抄。**

- 做法：`click_timer` 抄执行侧证据文本里的「点击前时间戳=…」（无点击时为「本步无点击」→ 留空）；`logAssertionTimer` 抄日志证据里命中关键词那一次的时间戳（多次命中取最早一次）。
- 理由：验收模型的工具子集只有截图，这是唯一能让它拿到坐标的来源；也保持「模型自报、平台不修正」的一致口径。
- 备选：平台在读结果时用工具轨迹覆盖这两个值。放弃原因：会掩盖模型漏抄，且与「模型自报」的诉求矛盾。

**决策 4：保留 `actual`，失败原因继续回灌。**

- 做法：`actual` 留在契约里；`retry_hint = verdict.actual` 与失败步骤记录的 `actual` 均不变；`actual` 为空时如实留空。
- 理由：这是需求方在「严格四字段」与「四字段 + 实际结果」之间选定的方案：任务详情要看得到为什么没过，重试也要有原因可回灌。
- 备选：用日志关键词顶替原因说明。放弃原因：纯看页面的失败没有日志可依据，反而更说不清。

**决策 5：提示词同步走一份可逆迁移，锚点取当前库中原文。**

- 做法：新增迁移（依赖 0047），对 `prompt_verifier` 做六处短语级条件替换：照抄路径那条、日志证据段的 `判 true/false` 措辞、验收段的 `actual/result/偏离` 三条、输出字段块、输出格式约束、案例 JSON；每处不含锚点则跳过，reverse 按新文精确回退。
- 理由：与 0039 / 0040 / 0044 / 0046 / 0047 一致；提示词允许用户编辑，锚点条件替换保证已改写的行不被覆盖。按迁移逆序回滚时，本次的 reverse 先还原 0044 插入块的原文，因此 0044 自身的 reverse 仍能精确匹配。
- 备选：直接改 0038 / 0044 的历史迁移。放弃原因：已应用，对存量库无效且破坏迁移可追溯性。

**决策 6：前端「有则显示」，验收段不重复点击前时间。**

- 做法：`TaskRunVerifierOut` 增三个新键（旧键保留可选）；attempt 派生带出 `verifierLogTimer` / `verifierScreenshotPath`；卡片验收段在 `logAssertionTimer` 非空时显示「日志断言时间」，验证截图块把模型回报的路径作为文本显示（图片仍取平台落盘的验收截图）；旧记录仍按 `actual` + 布尔结果呈现。
- 理由：同一处点击的「点击前时间」执行结果段已经给出，验收段再堆一行同名信息只会让人分不清是两次点击；`click_timer` 仍按契约由模型返回并落记录。

## 模块防火墙自检

- 改动集中在 `engines/ai/`（契约与工作流判定）、`apps/ai_assistant/migrations/`（提示词同步）、`frontend/src/shared` + `ai-assistant` 模块。
- 不新增跨 App import：迁移只操作本 App 的 `AIAgent` 字段；apps → engines 的既有方向不变。
- 不新增写库路径：迁移是唯一写库点；引擎不触碰 ORM。
- 前端不新增 HTTP 出口：任务详情与模型调试复用既有接口，只改 DTO 与呈现。

## Risks / Trade-offs

- [`result` 由布尔改字符串，遗漏某处布尔判定会静默把通过判成不通过] → 工作流两处判定显式改为字符串比较，并补单测覆盖 `PASS` 通过 / `FAIL` 不通过 / 输出无效三条；前端 `normalizeResult` 已兼容两种形态，补一条 `PASS` 用例。
- [模型漏抄 `logAssertionTimer`（日志证据里命中时间戳不显眼）] → 提示词把该字段的取值位置写死到「日志证据里命中关键词那一次的时间戳」，并允许留空；平台侧日志证据块本身照旧可核对，不依赖模型。
- [camelCase 键与仓库 snake_case 约定不一致] → 契约键按需求方口径固定，只在 Python 侧用别名声明的常规命名；文档与前端类型同键名，避免第三套写法。
- [存量旧记录与新记录形状不同] → 前端按「字段有则显示」，并为旧形状补一条用例；后端不做数据回填。
