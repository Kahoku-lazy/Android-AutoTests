# 设计：提示词收回引擎（含调试页现场收口）

## Context

- 三角色系统提示词由引擎常量提供（动机见 proposal.md「为什么」）；本单同时删掉库表三列与存档表，属数据面删除，迁移不可逆。
- 调试页（`/ai-assistant/toolbox/models/:role`）在删掉「系统提示词」折叠块后留下现场：参考数据区为空壳；前端 DTO 仍声明 `prompt`；区内一句「调试对话不挂载这些工具……不触碰真机」与真实行为相反；页面区块编号与规格三层口径不一致。
- 主规格 `ai-model-debug` 同时存在两条互斥要求：「单角色调试对话」要求不得挂载工具、不得触发真机；「调试对话按该角色真实装配运行」要求必须挂真实工具子集。前者从未随后者删除，页面那句文案正是照抄了它。
- 约束：平台是严格三角色结构（模型配置、健康探测、用量拆分、任务装配、前端线路表单均按规划 / 执行 / 验收固定）。本单不新增角色、不改工具子集、不改提示词内容。

## Goals / Non-Goals

**Goals:**

- 提示词唯一真相源回到引擎常量；库表与 HTTP 端点面下线（含不可逆迁移）。
- `ai-model-debug` 规格去重：删掉被取代、且与代码事实相反的旧条款，归档后同一能力内不再自相矛盾。
- 调试页与规格一致：文案如实、参考数据区按规格落地、编号口径对齐、前端无死字段。

**Non-Goals:**

- 不改三份提示词内容；不改工具子集与设备池口径（执行模型调试仍可调用设备池工具，属已知取舍）。
- 不补服务端硬超时、不加「停止」按钮、不做费用显示与调试留痕审计——均为独立新增能力，另行立项。
- 不动前端请求的固定等待上限（现为共享客户端 2 分钟），归上述独立立项。
- 不改引擎注册名；目录改名已由本单 tasks §7 登记。

## Decisions

**D1 旧条款用 REMOVED + ADDED，而不是 MODIFIED 改写。**

`openspec validate` 拒绝 MODIFIED 丢场景（原文：a MODIFIED requirement replaces the whole block, so archive refuses to drop them）：场景「对话不触碰真机」无法在 MODIFIED 块里删除。故把「单角色调试对话」整条 **REMOVED**（含 Reason / Migration），其中仍然有效的约束（引擎侧系统提示词、不落库、回复展示与可读错误）以新条「单角色调试对话的输入与留痕约束」**ADDED** 承接。理由：归档时 REMOVED 会把失真旧条从主规格移除，新条承接有效约束，同一能力内不再自相矛盾。
备选：MODIFIED 保留全部场景 —— 必须保留「对话不触碰真机」这个与事实相反的场景名，等于把假话写回规格，否决；备选：MODIFIED 改名场景 —— 校验器仍视为丢场景，同样被拒。

**D2 以代码事实为准删旧规格文，而不是让代码回退。**

代码现状：调试对话挂该角色真实工具子集、会真机操作、没有服务端 5 分钟超时。故删的是失真的规格旧文。
备选：按旧规格让调试对话不挂工具 —— 会把调试台打回「测不出真实装配」的状态，与 `2026-09-23-mount-real-tools-in-model-debug` 的决策相反，否决。

**D3 参考数据区填「设备 + Skill 目录」，生效装配区不动。**

生效装配区保留工具清单与 Skill 现状（规格亦要求该区含工具与 Skill）；参考数据区补该角色的设备信息（需要设备的角色给可用设备候选，不需要的如实说明）与 Skill 目录路径。理由：满足既有三层规格，且不需要搬动已有内容。
备选：砍掉该区、规格改成两层 —— 要改一条已验收的规格且页面信息量下降，否决。

**D4 `prompt` 死字段直接删。**

后端 `build_role_debug_configs` 已不下发该字段，前端全模块零读取（改前已 grep 确认：前端源码仅 DTO 声明一处）。保留会让契约看起来仍下发提示词正文，与本单「不展示提示词」的意图相反。

**D5 服务端 5 分钟超时条款随旧文一并删除，不在本单补实现。**

该条款从未实现（视图层无超时），且与既有「调试对话不设前端等待上限」冲突。真正的超时 / 停止能力（含前端固定上限问题）另行立项，本单只删掉这条失真的约束。

## 模块防火墙自检

- 跨 App import：无新增。本单删除的是 `apps/ai_assistant` 内部实现与引擎侧注入通道，不引入新的跨模块依赖。
- 写库路径：实现面只做删除（迁移删列删表），不新增任何 ORM 写；无跨 App 写。
- 前端不直连数据库；前端改动为删字段、改文案、填只读展示区，无写操作。
- 引擎边界：提示词常量留在 `engines/ai/agents/config.py`，由角色类自持；上层仍只经 `build_device_models` 使用，不反向 import 内部实现。

## Risks / Trade-offs

- [归档后主规格仍自相矛盾] → 归档前复核 `openspec/specs/ai-model-debug/spec.md` 全文，确认「不得挂载任何工具」「不触发真机操作」零命中；并以 `openspec validate` 把关 delta 结构。
- [删 `prompt` 字段影响未察觉的读者] → 改前 grep 前端源码确认仅 DTO 声明一处；改后以 `vue-tsc` 与相关用例把关。
- [删列删表不可逆] → 收回前已落 `dev_docs/DEV_TEST/设计方案与报告/AI设备提示词收回存档.json`；迁移单独待用户确认后执行，执行前先确认存档文件存在且三份正文完整。
- [三处现场只改一半] → tasks §8 逐条对应规格 / 字段 / 文案 / 区块 / 编号 / 用例，关单以 grep 与页面肉眼双验。
- [页面编号对齐引起既有前端用例失效] → 编号与文案属展示层，同步更新用例（tasks 8.6），不作为行为变更。

## Migration Plan

1. 代码与规划件先落地（本单 tasks §1~§5、§8），全程不触碰库。
2. 关单前跑 §6 各项校验（`manage.py check`、`makemigrations --check`、引号整理、边界检查、前端类型与用例）。
3. 最后执行 6.6：`python manage.py migrate ai_assistant`（删三列 + 删存档表，不可逆）。执行前确认存档文件可用。
4. 回滚策略：迁移本身不可回滚；如需回退，从存档文件重建列与表内容（历史迁移 0038~0050 按规矩不重跑、不改写）。
