# ai-model-debug — 不再展示系统提示词

## MODIFIED Requirements

### Requirement: 调试页展示该角色实际生效的配置
调试子页 MUST 展示该角色的模型连接（provider、model_name、是否视觉）、以及该角色的工具子集（每个工具名 + 只读/写标记 + 是否被平台停用）。调试接口 MUST NOT 下发系统提示词正文，调试子页 MUST NOT 展示提示词正文（提示词随引擎走，见 `ai-engine-protocol`）。工具清单 MUST 与该角色实际装配一致：规划模型为页面流工具、执行模型为视觉/设备操作工具集、验收模型为截图工具与只读日志检查工具。MUST NOT 展示 api_key、base_url 明文等敏感字段。

#### Scenario: 三个角色的工具清单各不相同
- **WHEN** 分别打开规划 / 执行 / 验收三个调试子页
- **THEN** 三页的工具清单按各自子集展示（规划为页面流工具、执行为视觉工具集、验收为截图工具与只读日志检查工具）
- **AND** 执行模型页标注该角色使用视觉模型
- **AND** 任何一页都不出现系统提示词区块或正文

#### Scenario: 不泄漏密钥
- **WHEN** 打开任一角色调试子页
- **THEN** 页面与接口响应都不出现 api_key 明文

### Requirement: 调试页按三层组织并分组展示
调试子页 MUST 按三层语义组织内容：① 角色带（当前角色 + 模型名 + provider + 模态 + 连接态 + 工具 / Skill 计数）② 生效装配（该角色工具与 Skill）③ 参考数据（设备：该角色是否需要设备、需要时为可用设备候选；Skill 目录路径）。调试对话 MUST 独立成栏并与内容并排常驻。该角色的工具 MUST 按分类分组展示，每组头部 MUST 显示该分类启用数与总数；每个工具 MUST 保留只读/写与已启用/已停用标记。参考数据区 MUST NOT 出现系统提示词区块（含折叠头与字数标识）——提示词随引擎走且不在前端展示；参考数据区 MUST 展示该角色的设备信息（需要设备的角色给出可用设备候选，不需要设备的角色如实说明该角色不需要设备）与 Skill 目录路径，MUST NOT 呈现为空区块。Skill 区块 MUST 以组头徽标标注「三模型共用」。角色切换 MUST 采用页内分段入口，且 MUST NOT 因此新增浏览历史层级（返回与面包屑行为不变）。

#### Scenario: 三层结构在一屏内可辨
- **WHEN** 超管打开某角色调试页
- **THEN** 可见角色带（角色名 / 模型名 / 模态 / 工具·Skill 计数）
- **AND** 可见「生效装配」与「参考数据」两个分组区，且两区都不出现系统提示词正文

#### Scenario: 工具按分类分组且组头带计数
- **WHEN** 超管打开执行模型调试页
- **THEN** 工具按分类分组（如设备控制 / 设备信息 / 设备检查器 / 视觉识别）
- **AND** 每组头部显示该分类的启用数与总数
- **AND** 每个工具仍带只读/写与已启用/已停用标记

#### Scenario: 参考数据区不含提示词
- **WHEN** 超管首次打开调试页
- **THEN** 参考数据区没有任何提示词区块、折叠头与字数标识
- **AND** 页面任何位置都不渲染提示词正文

#### Scenario: 参考数据区展示设备与 Skill 目录
- **WHEN** 超管打开任一角色调试子页
- **THEN** 参考数据区可见该角色的设备信息（需要设备的角色给出可用设备候选，不需要设备的角色如实说明该角色不需要设备）
- **AND** 可见 Skill 目录路径清单，且该区不呈现为空区块

#### Scenario: 对话常驻右栏
- **WHEN** 超管打开调试页（未滚动）
- **THEN** 对话消息区与输入框与配置内容并排可见

#### Scenario: 归属标注可见
- **WHEN** 超管打开任一角色调试页
- **THEN** Skill 组头可见「三模型共用」
- **AND** 页面不出现知识库区块

#### Scenario: 角色切换不新增历史层级
- **WHEN** 超管从规划模型切到执行模型
- **THEN** 页面在同一子页内切换角色（路由 role 参数变化），页头返回与面包屑仍指向工具箱
- **AND** 不出现"返回上一角色"这类新增层级的回退

## REMOVED Requirements

### Requirement: 单角色调试对话
**Reason**: 该条的三处条款已被后续变更取代，且与当前实现相反——调试对话现已挂载该角色**真实工具子集**（见「调试对话按该角色真实装配运行」，该条要求 MUST NOT 以空工具集运行），需要设备的角色必须先选定设备并二次确认（见「需要设备的角色须先选定设备并获得一次性授权」），平台也不对调试对话施加固定等待上限（见「调试对话不设前端等待上限且如实描述行为」）。保留该条会让同一能力内并存互斥要求，并使调试页照抄它写出与真实行为相反的说明。
**Migration**: 挂载工具的行为改看「调试对话按该角色真实装配运行」；设备选定与一次性授权改看「需要设备的角色须先选定设备并获得一次性授权」；等待上限改看「调试对话不设前端等待上限且如实描述行为」。该条中仍然有效的约束——使用引擎侧系统提示词、对话不落库、回复展示与可读错误——由本变更新增的「单角色调试对话的输入与留痕约束」承接。

## ADDED Requirements

### Requirement: 单角色调试对话的输入与留痕约束
系统 SHALL 允许超级管理员对单个角色发起一次调试对话，该对话 MUST 使用该角色**引擎侧**的系统提示词与模型连接（与任务链路同一份）。对话 MUST NOT 落库到会话 / 消息表。回复 MUST 展示给用户，失败时 MUST 给出可读错误。该对话挂载工具的行为见「调试对话按该角色真实装配运行」；需要设备的角色须先选定设备，见「需要设备的角色须先选定设备并获得一次性授权」。

#### Scenario: 对话使用该角色的引擎侧系统提示词
- **WHEN** 超管对某角色发起调试对话
- **THEN** 该对话使用引擎侧该角色的系统提示词（与任务链路同一份），回复体现其要求
- **AND** 前端不因该对话而展示提示词正文

#### Scenario: 对话不产生会话记录
- **WHEN** 超管在任一角色调试页完成一次对话
- **THEN** 会话表与消息表不新增记录
