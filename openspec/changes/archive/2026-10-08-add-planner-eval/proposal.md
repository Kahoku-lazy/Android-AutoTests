# 新增：规划模型能力评测入口（不走前端、直接代码测）

## Why

要评估**规划模型**（planner 角色）的能力——它把用户需求拆成"一步一动作 + 断言 + 是否需日志核对"的步骤计划。现在唯一的代码入口是 `python manage.py model_test planner "<需求>"`，它是"**单次、看输出**"的口子，测不了能力：

- **不能批量**：一次一条需求，无法覆盖"单步 / 多步 / 指定设备名 / 带附件 / 模糊需求 / 需日志核对"等不同难度；
- **没有校验**：契约能否解析、步骤是否一步一动作、断言是否可观察、`log_check` 标注有没有区分度、有没有按提示词先读页面流——全靠人眼看，结论不可复现；
- **没有重复**：测不出同一需求的稳定性；
- **没有对比**：换模型（DeepSeek 两档 / 阿里百炼）跑同一批，看不出差异；
- **不算成本**：不知道一次评测花了多少 token 与费用。

目标：建一个**可复用的评测入口**，让"规划能力"变成一组可复现、可对比、带成本的客观指标；不改任何生产行为。

## What Changes

- 新增管理命令 `planner_eval`：读用例集 → 逐条（可重复 N 次）调用**生产同源的规划角色** → 机械校验 → 控制台结果表 + 落一份报告。
- 新增**用例集**（入库、可版本化），每条需求登记机械可判的期望：必须出现的关键词、步骤数区间、是否应调用页面流工具、`log_check` 是否应混合取值等。
- **机械校验**（全部客观、可复现）：输出契约、一步一动作、断言可观察性、`log_check` 区分度、页面流工具使用、需求关键词覆盖、稳定性、token 与费用。
- **模型对比**：同一批用例换模型跑，报告并列呈现（用于选型与回归）。
- **不碰生产**：只做"装配 + 调模型"，不写库、不建任务、不改任务链路、不动前端。

## 关联文档

- 关联能力：无（评测工具属工程侧工具链，不改变平台对外行为；见下方 Capabilities 说明）。
- 相关既有规格：`ai-device-planner-tools`（规划提示词须指引先读页面流）——本工具把该要求变成可执行的检查项之一。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本变更新增的是**评测工具**（命令行 + 用例集 + 报告），不改变平台对外的任何行为契约：规划提示词、工具子集、任务链路、接口与前端均不动。按 schema 约定在 `.openspec.yaml` 设 `skip_specs: true`。

## Impact

- 新增：`apps/ai_assistant/management/commands/planner_eval.py`（命令与机械校验）、`tests/ai_planner/cases/*.yaml`（用例集，6~8 条）。
- 复用（不改）：`apps/ai_assistant/model_debug.py` 的 `build_device_models_for_agent`（与 `model_test`、模型调试台同源的装配）、`apps/ai_assistant/api.py` 的四键 JSON 输入构造、`engines/ai/messaging` 的 `RoleResult`（输出/工具轨迹/用量/费用）。
- 产出：报告落 `tests/reports/planner_eval/<标签>-<时间戳>.md`（仓库既有约定：测试报告统一到 `reports/`）。
- 后端接口 / 前端 / 数据库 / 通道：零改动。
- **成本**：每次评测都是真实模型调用（用例数 × 重复次数），按平台既有计价体现；**不需要设备**。
- **不改生产**：无迁移、无新端点、不影响在跑任务。
