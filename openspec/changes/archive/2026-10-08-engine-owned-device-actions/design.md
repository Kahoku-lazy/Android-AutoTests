## Context

动机见 `proposal.md` - Why。方案需要的事实（已核对代码）：

- 设备动作的实现今天住在平台侧工具模块，引擎靠 `TaskRequest.tools` 注入拿到它——引擎离开平台就无法驱动设备。
- 设备引擎本身在引擎层：`engines/device/android/u2.py` 是 uiautomator2 单栈实现（已满足 `engines/device/base.py` 的能力协议），但方法按「连接生命周期 / 感知 / 操作原语 / XPath」松散分布，没有信息查询与控制的明确分界，也没有「按系统选择」的概念。
- 约束：引擎 MUST NOT import `apps.*` / Django；平台上层 MUST NOT 直触具体设备实现；操作手机只能经引擎层。

## Goals / Non-Goals

**Goals:**

- 设备能力在引擎内按「连接 / 信息查询 / 控制」三类归口。
- 设备动作经一层「按目标系统选择」的中转执行，为 iOS 与 PC 留出选择位。
- 引擎自带设备工具与登记清单；装配时使用自带工具。
- 平台侧与前端零改动。

**Non-Goals:**

- 不改 `apps/` 任何文件（平台那份设备工具保持现状）。
- 不动设备日志、设备信息类平台工具、OCR、设备池台账、页面流工具、模型接入层、任务分发与记录链路。
- 不实现 iOS / PC 的真实动作（只留选择位与可读结论）。
- 本单不写测试代码（登记为后继项）。

## Decisions

**D1 `u2.py` 更名为 `android_device.py`，文件内三个类分别承担三类能力。**

| 类 | 承担 | 方法要点 |
|---|---|---|
| `AndroidConnection` | 设备连接 | 连接 / 断开 / 存活探测 / 重连；无线连接前的 adb connect；分辨率与型号验证 |
| `AndroidInfo` | 设备信息查询 | 屏幕尺寸、包名（已安装列表）、当前已连接设备列表、当前前台应用、层级原始 XML、shell 取数 |
| `AndroidControl` | 设备控制 | 点击（坐标 / 元素 / 图片）、长按（三种）、滑动（方向 / 坐标）、拖动、输入、按键、截图（字节 / base64 / 落盘）、应用启停，以及 XPath 与 Toast 辅助 |

三个类分别继承 `action.py` 的三份方法名契约。包入口 `engines/device/android/__init__.py` 另留一个**只做转发、不含设备逻辑**的门面（实现既有 `UiEngine` 协议），因为平台侧（设备池、检查器、引擎注册表）消费的是那份协议且一行不改；注册表指向门面，历史类名 `U2Engine` 作为别名保留。

**D2 新增单模块 `engines/device/action.py`：系统声明 + 三份方法名契约 + 动作类。**

- `System`：声明 `android` / `ios` / `windows`，按系统解析三类实现类；未实现的系统抛可读异常（由工具层转成给模型看的结论）。
- **方法名契约**（`DeviceConnection` / `DeviceInfo` / `DeviceControl`，均为抽象基类）：三端实现 MUST 使用同一套方法名（图片点击一律 `click_img`，别名不合法）；继承契约后缺方法无法实例化，命名漂移在运行期就暴露。
- **动作类**：`Click` / `LongClick` / `Swipe` / `Drag` / `InputText` / `PressKey` / `Screenshot` / `AppControl`，一个动作一个类，只依赖控制契约因而天然兼容三端；每种方式一个独立函数。
- 模块级 `open_device(system, serial, addr)` 一次返回（连接, 信息, 控制）三件套，三端同一套用法。
- 本模块不 import 任何具体设备实现；Android 实现由 `System` 按路径懒加载。

**D3 动作类与方式（Android 落地）。**

| 动作类 | 方式（各自独立函数） | Android 实现 |
|---|---|---|
| `Click` | `by_coord` / `by_element(by=xpath\|id\|text)` / `by_img` | 像素点击 / 元素定位点击 / 归一化坐标点击 |
| `LongClick` | `by_coord` / `by_element` / `by_img` | 像素长按 / 元素长按 / 归一化长按 |
| `Swipe` | `by_direction` / `by_coord` | 方向滑动（起终点在实现内换算）/ 像素起终点滑动 |
| `Drag` | `by_ratio` | 归一化起终点拖动 |
| `InputText` | `by_text` | 清空后输入（失败回退 shell） |
| `PressKey` | `by_key` / `back` | 系统按键 |
| `Screenshot` | `full`（字节）/ `save`（落盘，返回相对路径） | 截图并落盘到 `inspector/shots/capture_<ts>.png` |
| `AppControl` | `start` / `stop` | 应用启停 |

元素未命中时返回 `clicked=False`，由工具层转成可读结论（MUST NOT 静默误点别处）。

**D4 新增 `engines/ai/tools/tool_device.py`：引擎侧设备工具。**

工具函数即模型可见的实现：说明书（描述 + 参数表）与今天平台侧逐字段一致，**含 `serial` 必填**，因此模型可见契约与行为零变化；只有「截图落盘目录」这类平台侧隐含上下文由装配期闭包注入（`build_device_tools(output_root=...)`），不进参数表。工具内部只调 D2 的中转层，不直接 import 具体设备实现；失败返回带可读说明的 JSON（`error` 字段），不抛异常给模型。

工具函数的 docstring 由登记清单注入（说明书的唯一真相源在 `tool_device_catalog.py`），实现文件不另写一份描述。

**D5 新增 `engines/ai/tools/tool_device_catalog.py`：设备动作登记清单。**

每项 = 名字 + 说明书 + 实现引用 + 元数据（只读 / 串行 / 是否设备动作）。该模块为纯数据、零框架依赖；框架翻译发生在既有包装层，换框架不影响清单。

**D6 装配改为引擎自带设备工具优先。**

装配时先放引擎自带设备工具，再从注入清单里补充数据类工具；注入清单里与设备动作同名的条目被跳过（并记一条日志）。这是「平台一行不改也能生效」的关键：过滤发生在引擎侧，不依赖平台配合。

**D7 两份实现并存，登记为后继项。**

平台那份设备动作实现保持现状（继续服务外部工具通道与工具箱调试页），引擎自带一份供模型使用。两份并存的漂移风险在风险段列出，统一方案（平台实现改为转调引擎）登记为后继项，不在本单。

**D8 测试本单不写，登记为后继项。**

本单以真机手测作为验证手段（每个动作各跑一次、观察返回与截图落盘）；桩实现与契约测试、登记清单与平台工具的说明书对拍，一起登记为后继项。

## 模块防火墙自检

- **跨 App 调用**：本变更不触碰 `apps/`，无新增跨 App import，无写库路径变化。
- **引擎依赖方向**：`engines/ai` MUST NOT import `apps.*` / Django（`ai-engine-protocol` 既有要求）；新增的 `engines/ai` → `engines/device` 属同层内部依赖（ARCH-00 §1.1 L1c 允许）。
- **具体设备实现的接触面**：只有 `engines/device/android/android_device.py` 的三个类接触 uiautomator2；`engines/ai` 只经 `engines/device/action.py` 的动作类，不直接接触具体实现。
- **前端**：零改动。
- **新跨模块依赖声明**：`engines/ai` → `engines/device`（同层，无需走 `api.py`）；无新增 App 间写路径。

## Risks / Trade-offs

- [平台与引擎两份设备动作实现漂移，出现「调试页调的是平台版、模型用的是引擎版」] → 本单明确平台侧不改、引擎侧为模型可见来源；统一方案登记为后继项。
- [引擎直连绕过设备池占用校验] → 平台任务链路继续做只读校验、serial 由分发决定；引擎不建占用账，独立运行时占用由运行者负责。
- [按文本定位命中多个同名元素] → 点第一个并回传命中数量；未命中返回可读结论，MUST NOT 静默点到别处。
- [`u2.py` 方法归位影响既有调用方] → 只做分组与注释归位，不删方法、不改签名；新增能力仅「当前已连接的设备列表」一项。
- [未实现的系统或方式被模型误用] → 返回含可用取值的可读结论，模型可据此自我纠正。
- [本单无自动化测试] → 以每个动作的真机冒烟作为验收证据，并在后继项里补齐桩与契约测试。
- [平台两处调用（模型调试台 / 命令行 `model_test`）没有把媒体目录传进引擎，截图落到引擎默认目录（`ENGINE_DEVICE_SHOT_DIR` 或 `<cwd>/temps/engine_shots`）] → 平台任务链路不受影响（`TaskRequest.media_root` 已传）；这两处的差异登记为后继项，本单不改 `apps/`。

## 后继项（不在本单）

| 后继项 | 收益 / 原因 |
|---|---|
| 平台那份设备动作实现改为转调引擎 | 消除两份实现漂移（调试页用平台版、模型用引擎版） |
| 桩设备实现 + 契约测试 + 登记清单与平台工具说明书对拍 | 本单按约定不写测试代码；补齐后单测不连真机 |
| 平台两处调用把媒体目录传进引擎 | 让调试台/命令行的截图落回平台媒体目录（现状落引擎默认目录） |
| 引擎层与 `apps/device_pool` 的主机侧设备枚举统一 | 目前引擎新增的「当前已连接设备列表」与平台 detector 各有一份 |
| `serial` 改为可省（缺省用当前设备） | 消掉实测中「漏传必填参数」的失败；属模型可见契约变化，需评测对拍 |
| 参数改硬枚举（方向 / 模式） | 让校验层拦住乱传取值，而非等函数报错 |
| iOS / Windows 的实际实现 | 本单只留选择位与可读结论（`System` 已声明三个系统） |

## 迁移与回滚

- 无数据库迁移、无接口契约变更、无前端变更、`apps/` 零改动。
- 切换顺序：`u2.py` 更名为 `android_device.py` 并拆成三个类（包入口留只做转发的门面）→ 新增 `engines/device/action.py`（系统声明 + 三份方法名契约 + 动作类）→ `tool_device.py` 改走动作类、`tool_device_catalog.py` 对齐动作与方式名 → 装配切换为引擎自带工具优先 → 真机逐动作冒烟。
- 改名影响面：`u2.py` 旧文件已删除；注册表路径与两处既有测试的 import 同步更新，其余调用方零感知（门面提供既有协议方法名）。
- 回滚：把装配改回「注入工具优先」即可；改名与拆分属结构性调整，回滚需同时恢复 `u2.py` 与注册表路径。
