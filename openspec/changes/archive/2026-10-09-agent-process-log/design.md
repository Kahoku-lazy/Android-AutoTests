## Context

- 角色执行当前走 `await agent.reply(msg)`：跑完之后再从 `agent.state.context` 里把思考与工具调用/返回翻出来（`engines/ai/messaging`），因此**不存在**"边跑边看到"的可能。
- AgentScope 2.0.7.post1 提供 `Agent.reply_stream(...)`：异步生成器，逐条产出 `ReplyStart / ModelCallStart / ModelCallEnd / ThinkingBlock{Start,Delta,End} / ToolCall{Start,Delta,End} / ToolResult{Start,TextDelta,DataDelta,End} / TextBlock* / DataBlock* / ReplyEnd` 等事件（已在本机实测这些导出存在）。框架本版本**没有** hook 模块（`agentscope.hook` 不存在）。
- 过程数据的现状链路：角色结果对象 → 工作流 `_role_trace` 裁剪（思考 24 段 / 每段 2000 字、工具 80 条、入参与返回各 800 字）→ 写入任务 `result` 的 `log[].executor_trace / verifier_trace` → 前端每 3 秒轮询整包任务 → 步骤卡片折叠区渲染。
- 引擎边界要求零平台依赖（`ai-engine-protocol`）；已有注入先例：`TaskRequest` 携带 `user_id / task_id / media_root / models / max_loops / on_progress`。
- 截图落点两套：任务链路注入 MEDIA 根目录（前端可按 `/media/` 渲染），命令行与已退役的调试台不注入 → 落到引擎默认目录。

## Goals / Non-Goals

**Goals:**

- 三角色的思考、工具调用、工具返回在产生的当下追加写入一份人类可读的过程日志，行内固定带时间戳、角色名、模型名、事件类型。
- 日志落点由调用方注入，未注入时落到 `<当前工作目录>/logs/agents.log`，不存在则自动创建。
- 三个角色的系统提示词要求思考与回复使用中文，输出契约不变。
- 平台任务过程记录与任务详情页去掉思考与工具明细；判定与证据数据完整保留。
- 退役工具箱「模型调试」来源、模型调试子页、其后端调试接口，并作废在办改版单。

**Non-Goals:**

- 不做平台侧实时推送（SSE/Log 流）：实时性由日志文件承担。
- 不改三角色的输出契约、判定口径、日志取证窗与验收证据链。
- 不做日志轮转、压缩与保留期策略（本单只保证"自动创建 + 追加写"）。
- 不动设备动作工具与元素锚定（元素长按缺陷另单处理）。

## Decisions

**D1 以 `reply_stream` 事件流取代"事后翻上下文"。**
理由：这是唯一能在内容产生的当下落盘的机制，且框架原生；`engines/ai/messaging` 的模块注释里已把"消费事件流"预留为本模块的替换面。备选一：继续轮询 `state.context`（做不到实时，且需要解析整段上下文）；备选二：自建 hook（本版本无 hook 模块，实测不存在）。

**D2 解析与写入分离：事件→记录映射留在 `engines/ai/messaging`（叶子包），日志写入器新建独立模块。**
理由：保持"消息与事件的解析归属"单一；写入器可被单测直接驱动，不依赖模型。

**D3 落点由调用方注入。**
`TaskRequest` 增加日志落点字段；平台注入 `<BASE_DIR>/logs/agents.log`；未注入时引擎用 `<当前工作目录>/logs/agents.log`。理由：引擎零平台依赖，同时让命令行与跑测工具开箱可用。备选一：引擎内写死路径（测试与多环境下无法重定向）；备选二：走 Python logging（用户要求固定文件与固定列格式，且每行必须绑定角色与模型名，直接追加写文件更可控，也避免与既有 `logs/*.log` 的格式冲突）。

**D4 行格式为可读文本，固定列 + 自由内容。**

```
2026-10-09 10:22:44.123 | executor | deepseek-flash | 任务 12 · 步骤 3/8 | 思考 | <正文>
2026-10-09 10:22:45.010 | executor | deepseek-flash | 任务 12 · 步骤 3/8 | 工具调用 | screenshot_page({"serial": "…", "keep_local": true})
2026-10-09 10:22:45.663 | executor | deepseek-flash | 任务 12 · 步骤 3/8 | 工具返回 | success | {"screenshot_path": "inspector/shots/capture_….png"}
```

固定列共五个：时间戳 / 角色 / 模型 / 任务与步骤标识 / 事件类型，其后为内容（内容中允许出现 `|`）。规划角色写 `任务 12 · 规划`，验收角色写 `任务 12 · 步骤 3/8 验收`；无任务上下文时（命令行、跑测工具）写 `独立运行`。理由：用户要求"时间戳与模型名称"，并确认补一列任务/步骤标识以便并发跑动时区分；这份日志的主要消费者是人（`tail -f` / grep）。备选：JSON Lines（机器友好但人读差，且本次无机器消费者）。

**D5 中文约束落在三角色系统提示词，不改输出契约。**
理由：字段名是平台与验收的契约（英文键必须保持）。已知局限：推理型模型的思维链语言不完全可控，因此验收方式是"连续多轮抽样，思考与回复正文以中文为主"，而不是逐个字符断言。

**D6 三角色共写同一份日志，每条带角色名。**
理由：单文件便于按时间线看一次任务的完整过程；需要单角色视角时按第二列过滤。

**D7 过程日志不含图片二进制。**
截图事件只记相对路径 + 页面标识（包名 / Activity / 分辨率）；工具返回的超长文本按固定上限截断，并在截断处标注。理由：日志要能长期留存与直接打开，二进制会毁掉可读性。

**D8 退役模型调试页，保留角色装配函数。**
删除工具箱来源、子页、路由、前端常量/composable/helper、后端调试接口与调试对话；保留"按智能体配置装配三角色模型"的函数（命令行 `model_test` 与 `planner_eval` 依赖），把它从调试模块中拆出来单独成模块。备选：保留页面只去掉思考（用户已否决）。

## 模块防火墙自检

- 引擎新增模块只依赖标准库与 AgentScope，**不** import 平台模块；日志落点经 `TaskRequest` 注入，符合引擎零平台依赖。
- 平台侧本单以**删除**为主，不新增跨 App import；任务落库仍经 `apps/ai_assistant/api.py`。
- 前端只删除页面与来源，不新增 HTTP 调用；任务详情页的数据仍来自既有任务详情接口。
- 无新增跨模块依赖，无新的写库路径。

## Risks / Trade-offs

- [事件流改造可能影响三角色执行、用量累计与既有行为] → 保持角色结果对象的字段与语义完全不变，只替换"过程数据从哪来"；先跑引擎单测，再做一次真机三步冒烟。
- [思考语言不完全可控] → 提示词硬约束 + 抽样验收（多轮运行后抽取日志确认以中文为主），并在 tasks 里登记验证方式。
- [日志无轮转，长跑会变大] → 本单不做轮转，在日志文件头与文档中标注；轮转与保留期另立单。
- [退役调试页可能留下死引用（常量、路由、装配台来源、测试、文档）] → tasks 内列全清单，用"全仓 grep 断言 + 前端类型检查/lint + 后端 ruff"收口。
- [归档时 `ai-model-debug` 主规格需整体移除] → delta 已逐条 REMOVED（19 条）；归档后确认该能力目录不再存在。
- [存量任务的旧过程记录仍带 trace 字段] → 前端渲染不再读取这些字段，存量任务 MUST NOT 因此报错或空白。

## Migration Plan

1. 引擎：事件流消费 + 过程日志写入器（含单测，可在无设备、无平台条件下跑）。
2. 平台：注入日志落点；过程记录不再装配 trace；任务详情页与前端类型同步瘦身。
3. 退役：删除模型调试页与后端调试接口，保留并拆出装配函数。
4. 作废在办改版单 `2026-09-29-restyle-model-debug-role-band`。
5. 回归：引擎单测 + 平台单测 + 前端类型检查与 lint + 一次真机任务冒烟。

回滚策略：本单以行为收敛与删除为主，回滚即还原引擎的 `reply` 调用路径与前端区块；任务 `result` 的存量数据不受影响。

## Open Questions

- 日志轮转与保留期（多大切分、留多久）：不影响本单规格与任务拆分，另立单。
- 是否需要按任务分文件：本单固定单文件（便于看一次跑动的完整时间线），后续如确有多任务交织困扰再评估。
