## Context

- 现状：`engines/ai/process_log.py` 的 `AgentProcessLog` 每次写入都打开同一个文件（追加 + 立即 flush），落点由调用方经 `TaskRequest.log_path` 注入，未注入时用 `<当前工作目录>/logs/agents.log`。
- 该模块只依赖标准库，写入失败只记 warning，不打断模型执行；并发写用线程锁保证一条记录一行。
- 使用反馈：单文件持续增长，需要按天切分。

## Goals / Non-Goals

**Goals:**

- 按天切分（`agents-YYYYMMDD.log`），跨天在同一进程内自动切换。
- 保持既有语义：追加写、自动创建、落点由调用方注入基路径、并发不串行、写入失败不打断执行。

**Non-Goals:**

- 不做自动删除、压缩或保留期策略。
- 不改日志行格式（仍是六列）与事件类型。
- 不改落点注入契约（仍注入基路径，不引入"注入目录"这一新参数）。

## Decisions

**D1 由基路径派生当日文件名，而不是让调用方注入目录。**
理由：注入契约已经稳定（`TaskRequest.log_path`），派生规则留在引擎侧即可，平台零改动。备选：注入目录 + 固定前缀（要改平台与引擎两处，收益不明显）。

**D2 每次写入前按当前日期解析目标文件（跨天自动切换）。**
理由：一次任务可能跨零点；解析是纯字符串拼接，开销可忽略。备选：进程启动时定死文件名（跨天会继续写旧文件，不符合需求）。

**D3 不为"当日文件"缓存句柄，仍每次打开追加。**
理由：跨天切换、多进程并发与外部轮转都由"每次打开"天然兜住；既有并发测试与失败兜底逻辑不变。

**D4 不做清理。**
理由：保留期与磁盘占用是运营决策，本单只解决"按天切分"。

## 模块防火墙自检

- 只改引擎模块与测试，依赖标准库；落点仍由调用方注入，引擎 MUST NOT import 平台模块。
- 平台侧仅同步注释口径，不新增跨 App 依赖、不新增写库路径。
- 前端不涉及。

## Risks / Trade-offs

- [跨天切换后，`tail -f` 追的是旧文件，用户可能以为日志停了] → 在过程日志首次创建与切换时，向应用日志（python logging）记一条 info，说明当前文件路径；文档口径同步。
- [按天文件变多，`grep` 需要跨文件] → 属预期：按天文件小、可按日期精确定位；需要跨天检索时用通配符 `logs/agents-*.log`。
- [测试依赖"当前日期"，会变成与时间耦合的脆弱测试] → 把"当天日期"抽成一个可替换的函数（模块级 `_today_stamp()`），测试用 monkeypatch 固定日期。

## Migration Plan

1. 引擎：文件名派生 + 每次写入解析 + 跨天切换；当日文件与切换记 info 日志。
2. 测试：更新当日文件名断言，新增跨天切换与"历史文件不被删除"断言。
3. 回归：过程日志与工作流相关单测、门禁（ruff / 自检 / 架构边界）。
4. 不需要数据迁移：旧文件保留，新记录按天新建。

回滚：还原文件名派生即可，历史按天文件仍可读。
