## Context

- 验收角色的工具子集里 `screenshot_page` 会被一层包装替换，目的是"无论模型是否传 `keep_local`，一律保留落盘路径"（`engines/ai/agents/verifier.py`）。
- 包装函数签名声明了 `user_id`，而工具装配层按签名判断是否注入归属（`PlatformFunctionTool`）：声明了就注入。包装层拿到 `user_id` 后又**无条件**转发给被包装的实现。
- 设备动作工具自 2026-10-08 起由引擎自带：引擎的 `screenshot_page` 只接受 `serial` 与 `keep_local`，不接受 `user_id`。于是包装层把 `user_id` 转发过去 → `TypeError: unexpected keyword argument 'user_id'`。
- 实测证据：引擎级端到端跑测里验收侧两次截图调用均报此错，验收只能凭日志判定并给出 FAIL。

## Goals / Non-Goals

**Goals:**

- 验收截图工具在两种被包装实现下都能调用：引擎自带（无 `user_id`）与平台实现（有 `user_id`）。
- 用单测固定该行为，避免以后再被签名漂移打穿。

**Non-Goals:**

- 不改验收提示词与判定口径（另一件待决事项：验收对"页面类断言"仍会去找日志关键词，见 design 的记录）。
- 不改工具装配层的注入规则（它按签名注入是对的）。

## Decisions

**D1 由包装层按被包装实现的签名决定是否转发 `user_id`，而不是让包装层不再声明 `user_id`。**
理由：包装层若不再声明 `user_id`，平台实现（需要归属）在验收路径上就拿不到归属；保持"声明 + 按需转发"两边都安全。备选：让引擎自带实现也接受并忽略 `user_id`（把补丁打到实现上，等于让每个设备动作都挂一个无意义参数）。

**D2 用 `inspect.signature` 与既有 `PlatformFunctionTool` 同一判定口径。**
理由：一处口径、一个来源；不引入新约定。

## 模块防火墙自检

- 只改引擎内的角色文件与测试，依赖标准库；不 import 平台模块。
- 无跨 App 依赖、无写库路径变化、前端不涉及。

## Risks / Trade-offs

- [被包装实现用 `**kwargs` 兜住任意参数时，签名里看不到 `user_id`，会被判为"不接受"] → 这正是期望：设备动作实现不接受归属；若将来某个实现真需要归属，它必须显式声明，与工具装配层同一规则。
- [同类包装在别处也存在] → 本单只修验收截图这一处；实施时顺带全仓 grep 同类"包装后无条件转发 `user_id`"的写法，发现即记在遗留里。

## 遗留（本单不做，另议）

- 验收模型对**页面类断言**仍会去查设备日志关键词（引擎级跑测里对"启动应用"这类断言调用 `check_device_log`，拿不到命中就判 FAIL），在无日志采集或断言与日志无关时会误判。属提示词与判定口径问题，建议另立一单收紧（只在步骤被标记需日志核对时才要求日志条件）。

## Migration Plan

1. 改包装层的转发条件。
2. 新增单测（两种签名各一条）。
3. 回归：验收与工作流相关单测、引擎级端到端跑测复跑一次。
