## Context

- 其余 8 个设备动作工具共用一个执行辅助函数；截图因为要返回图片（不是 JSON 字符串）而单独写了一套连接与异常样板，于是同一文件里出现两份相同逻辑。
- 截图动作层已保证返回固定的四个键，工具层再写 `.get(..., 默认值)` 属于死代码，而且那个默认值（`image/jpeg`）与现在的无损 PNG 口径不符。

## Goals / Non-Goals

**Goals:** 去掉重复样板与死默认值，让截图工具一眼能读完。

**Non-Goals:** 不改工具入参、返回形状、编码档位与落盘口径；不动其余 8 个工具的实现。

## Decisions

**D1 新增"在设备上做一件事"的辅助函数，而不是把截图塞进既有 JSON 执行函数。**
理由：既有那个函数的契约是"返回 JSON 字符串 + 副作用动作附时间点"，截图要返回图片结构，硬塞会让两边的语义都变模糊；抽公共的设备连接/异常处理即可。

**D2 直接按键取值，不再给默认值。**
理由：键由动作层保证存在；默认值只会掩盖"动作层改了键名"这类错误，且这次那个默认值本身就是错的。

## 模块防火墙自检

- 只改引擎工具层，依赖标准库与既有动作层；不 import 平台模块、不改落点注入。
- 无跨 App 依赖、无写库路径、前端不涉及。

## Risks / Trade-offs

- [辅助函数把"连接失败"与"执行失败"的文案统一成同一形状] → 文案统一为「<标签>失败：<原因>」，比原来更一致；既有单测未断言这两句原文，行为不变。
- [未来某个工具需要 info 侧信息（如屏幕尺寸）] → 辅助函数仍把 info 交回给执行体，需要时可用。
