## Context

- 截图工具（`engines/ai/tools/tool_device.py` 的 `screenshot_page`）在截图之外还查了当前前台应用与屏幕尺寸，把 `serial / package / activity / screen_w / screen_h` 一起返回。
- 工具说明本身写的是「轻量：仅截图，不 dump/OCR/落库」——实现与说明不一致。
- 全仓确认：没有任何代码消费截图返回里的 `package / activity / screen_w / screen_h`；提示词只要求 `screenshot_path`；页面是否跳转的判据由**动作类工具**的返回提供（点击/滑动/输入/返回等副作用动作会带 `package / activity`）。

## Goals / Non-Goals

**Goals:**

- 截图工具只做截图：一次取帧、一次编码、一次落盘，返回模型图 + 本地路径。
- 少两次设备往返（查前台应用、查屏幕尺寸），截图更快。

**Non-Goals:**

- 不改动作类工具的返回（页面跳转判据仍在那里）。
- 不改截图编码档位、命名与落盘位置。
- 不新增"设备信息"工具（若日后模型确实需要分辨率，另立单讨论）。

## Decisions

**D1 直接删掉两项额外查询，而不是保留可选开关。**
理由：它们是过渡期为了"少调一次工具"临时拼进去的，没有消费方；保留开关等于把不一致长期留在代码里。

**D2 `serial` 也不再放回摘要。**
理由：设备号已由调用入参体现（过程日志里的"工具调用"行就有），摘要只回答"这次截图产出了什么"。

**D3 坐标口径不变：模型用归一化点击（`click_ratio`）。**
理由：屏幕分辨率不再随截图返回；`tap_screen` 的像素坐标只在步骤显式给出坐标时使用，模型不应自行估算分辨率。

## 模块防火墙自检

- 只改引擎工具层与测试；不 import 平台模块，不改落点注入方式。
- 无跨 App 依赖、无写库路径、前端不涉及。

## Risks / Trade-offs

- [模型少了"截完就知道前台是谁"的便利，可能多调一次动作类工具] → 动作返回本来就带 `package/activity`，且提示词要求先定位再操作；真机回归观察是否有步骤因此变慢或误判。
- [模型改用像素坐标点击时缺少分辨率] → 提示词口径是"优先视觉定位 → 归一化坐标"；`click_ratio` 不依赖分辨率。
- [有历史对话/日志里出现过旧字段] → 只影响读取方；已确认无消费方。

## Migration Plan

1. 工具层：删两次额外查询与四个字段。
2. 测试：新增"返回只含路径与文件名""不额外查询设备信息""不落盘分支仍给模型图"。
3. 真机验证一次并归档。
