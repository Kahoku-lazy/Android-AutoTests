## Purpose

让设备多步检查按固定里程碑逐个执行、逐个验收，并把整次运行的用量与费用汇总成一份可核对的结论。角色、提示词与运行状态都留在独立脚手架内。

## ADDED Requirements

### Requirement: 用已就绪的角色装配 SOP
系统 SHALL 支持把已就绪的执行角色与验收角色，按「步骤名 + 这一步必须达成的结果」列表装成标准作业流程；列表顺序即执行顺序，步骤可增删。装配 MUST 复用角色上已就绪的智能体实例，MUST NOT 另建智能体。角色尚未就绪时 MUST 报错，并在错误信息里指明是执行侧还是验收侧。

#### Scenario: 用默认步骤列表装配
- **WHEN** 两个角色都已就绪，且不显式给出步骤列表
- **THEN** 装配出的流程步骤等于默认列表，且每一步的执行者与验收者就是两个角色各自的智能体实例

#### Scenario: 自定义步骤覆盖默认列表
- **WHEN** 调用方给出「(步骤名, 必须达成的结果)」列表
- **THEN** 流程按该列表的顺序装配，步骤数与内容与入参一致

#### Scenario: 角色未就绪时报错
- **WHEN** 执行角色尚未就绪就要求装配
- **THEN** 装配失败，错误信息指明是执行侧未就绪，且不产出流程对象

### Requirement: SOP 专用交付与验收提示词
进入 SOP 的执行角色与验收角色 MUST 使用 SOP 专用系统提示词：执行者以「交接说明」交付本步成果，验收者以「是否通过 + 不通过时的具体原因」给出结论，两者 MUST 由结构化输出产出。SOP 提示词 MUST NOT 与既有的「只输出一个 JSON 字符串」输出契约混用。角色构造 MUST 支持覆盖系统提示词与角色名；不覆盖时 MUST 保持既有默认提示词与默认角色名。

#### Scenario: 装配时覆盖系统提示词
- **WHEN** 构造执行角色时传入 SOP 专用提示词
- **THEN** 该角色实际使用的系统提示词是 SOP 专用提示词，既有默认提示词不被修改

#### Scenario: 不覆盖时默认提示词生效
- **WHEN** 构造角色时不传系统提示词
- **THEN** 角色使用既有默认提示词，行为与本变更前一致

#### Scenario: 执行与验收在日志里可区分
- **WHEN** 执行角色与验收角色分别使用默认角色名
- **THEN** 两者角色名不同，过程日志与验收结论里能区分谁在做、谁在判

### Requirement: 运行时按角色实时写过程日志
SOP 运行时，执行者与验收者产生的思考、工具调用与工具返回 MUST 在产生的当下写入过程日志，MUST NOT 等整轮结束再写。每条记录 MUST 带角色名、模型名、阶段标识；阶段标识 MUST 包含当前步骤名与第几次尝试。日志开关与落点 MUST 沿用执行角色就绪时给出的开关与基路径；关闭时 MUST NOT 产生日志文件。

#### Scenario: 两个角色分别署名
- **WHEN** 一步的执行者与验收者各自产出思考
- **THEN** 过程日志里先出现执行角色名的记录，随后出现验收角色名的记录，两者可按角色名区分

#### Scenario: 阶段标识带步骤与尝试次数
- **WHEN** 流程推进到「启动应用」这一步的第 1 次尝试
- **THEN** 该步产生的每条记录都带「启动应用」与「第 1 次」

#### Scenario: 日志开关关闭时不落盘
- **WHEN** 执行角色就绪时未开启日志
- **THEN** 整个 SOP 运行结束后，对应日志文件不存在

### Requirement: 运行级用量与费用汇总
SOP 运行器 MUST 在每次模型调用结束时累计输入 token、输出 token 与缓存命中 token。费用 MUST 按该次调用自己的时刻与模型名分别计算后再求和，MUST NOT 先合并 token 再统一计费。MUST 提供整次运行的合计与按角色的分项，金额取位 MUST 与既有单轮计费口径一致。提供商不是 DeepSeek 时 MUST 只统计 token，费用 MUST 为 0。汇总 MUST NOT 写入平台用量统计。

#### Scenario: 逐次计费后求和
- **WHEN** 一次运行内的多次模型调用分别发生在高峰与空闲时段
- **THEN** 每笔费用按各自时刻的单价算出后再相加，结果与逐笔计费之和一致

#### Scenario: 按角色分项
- **WHEN** 一次运行里执行者发生 49 次调用、验收者发生 20 次调用
- **THEN** 汇总给出「执行者 49 次、验收者 20 次」的分项用量与费用，两者之和等于合计

#### Scenario: 非 DeepSeek 只记用量
- **WHEN** 角色使用的提供商不是 DeepSeek，且本轮用量不为零
- **THEN** 用量照常累计，三项费用均为 0

#### Scenario: 不并入平台用量统计
- **WHEN** 一次 SOP 运行结束
- **THEN** 平台用量统计的数据不发生任何新增

### Requirement: 用量与费用写进过程日志
每次流程推进结束时，运行器 MUST 把累计用量与费用写一条过程日志，内容 MUST 含模型调用次数、三项 token、三项费用与合计金额。

#### Scenario: 结束后留一条汇总
- **WHEN** 一次推进（启动运行或恢复挂起）结束
- **THEN** 过程日志末尾出现一条汇总记录，其累计值包含本次推进之前的所有调用

### Requirement: 运行状态可导出与续跑
系统 SHALL 支持导出运行状态，并 SHALL 支持用同一份流程定义与导出的状态重建运行、继续推进。状态里的步骤数与流程定义的步骤数不一致时 MUST 报错，MUST NOT 错位推进。导出的状态 MUST 只包含流程自身的阶段、输入、交付与历次结论，MUST NOT 包含用量与费用；续跑后的用量与费用从重建时刻重新累计。

#### Scenario: 导出后重建并续跑
- **WHEN** 用导出的状态重建运行并继续推进
- **THEN** 已完成的步骤被跳过，未完成的步骤继续执行

#### Scenario: 步骤数不匹配时报错
- **WHEN** 流程定义被增删过步骤，再拿旧状态重建
- **THEN** 重建失败并报出步骤数不一致，MUST NOT 把状态错配到别的步骤

#### Scenario: 续跑后的费用只覆盖新进程
- **WHEN** 重建后的运行继续发生模型调用
- **THEN** 汇总只统计重建之后的调用，MUST NOT 声称包含重建之前的用量

### Requirement: 不改变平台引擎的对外行为
本能力 MUST 只落在独立脚手架内，MUST NOT 修改平台引擎（平台侧引擎代码与其对外行为保持不变）。

#### Scenario: 平台侧零改动
- **WHEN** 本变更实施完成
- **THEN** 平台侧引擎目录下的文件没有改动，平台既有测试与接口行为与变更前一致
