## REMOVED Requirements

### Requirement: 任务附件为 Word 或 PDF 并解析为 Markdown
**Reason**: 附件改为「一份 YAML 配置 + 多份文档」，文档不再限于单份 Word/PDF，也不再送入规划模型。
**Migration**: 使用本 delta 新增的「任务附件分为配置与文档」。已存在的单附件任务保持原正文与文件名可读。

### Requirement: 任务详情可查看规划输入原文
**Reason**: 控制设备任务不再把四键 JSON 交给规划模型。
**Migration**: 详情改为展示配置加载结论、开场说明与文档 Markdown。历史任务若仍存有规划输入，详情按原样展示该文本，不再新写规划输入。

### Requirement: 规划输入以缩进 JSON 代码块呈现
**Reason**: 新任务不再产生规划输入。
**Migration**: 新建任务的详情不再出现「送给规划模型的输入」。历史任务仍有该文本时，沿用原代码块展示。

## ADDED Requirements

### Requirement: 新建任务选择平台小助手上的助手
系统 SHALL 在新建任务弹窗提供助手下拉。选项 MUST 与平台小助手卡片当前展示的助手一致，名称与卡片名称相同。当前展示 MUST 只有控制设备这一条。只有一个选项时 MUST 默认选中。未选择助手时 MUST 拒绝提交。提交 MUST 带上该助手对应的线路键，后端 MUST 只接受当前展示的线路。

#### Scenario: 只有一个助手时默认选中
- **WHEN** 平台小助手卡片只展示控制设备这一条，用户打开新建任务弹窗
- **THEN** 助手下拉只有这一条，并且已经选中

#### Scenario: 未选择助手时不能提交
- **WHEN** 用户提交新建任务时没有带上当前展示的助手线路
- **THEN** 系统拒绝创建任务，并说明需要选择助手

### Requirement: 任务附件分为配置与文档
系统 SHALL 在新建任务中提供两类附件，且每一类都可以添加多份。配置类 MUST 列出 csv、yaml、json；csv 与 json MUST 标明「暂不可用」且不能选择，只有 YAML 可以随任务提交。文档类 MUST 接受 markdown、Word（.docx）与 PDF。一次提交 MUST 至多一份 YAML，文档份数不限。系统 MUST 在后端检查扩展名与 YAML 格式，并在后端把文档解析为 Markdown 后写入任务记录。解析或格式检查失败时 MUST 拒绝创建任务并返回可读错误。未上传任何附件时 MUST 拒绝创建任务并说明需要一份 YAML。系统 MUST NOT 把 csv、json 或其它扩展名当作可执行配置。

#### Scenario: 一份 YAML 与两份文档可以提交
- **WHEN** 用户填写标题与目标，并附上一份合法 YAML、一份 .md 与一份 .pdf 后提交
- **THEN** 系统创建任务，YAML 正文与两份文档的 Markdown 都写入该任务

#### Scenario: csv 与 json 不能提交
- **WHEN** 用户选择配置类中的 csv 或 json
- **THEN** 该项不可选，界面标明「暂不可用」；若请求仍带上该文件，系统拒绝创建任务

#### Scenario: 文档解析失败时不创建任务
- **WHEN** 用户上传的 PDF 无法解析为文本
- **THEN** 系统拒绝创建任务并返回可读错误，不留下半成品任务

#### Scenario: 没有 YAML 时拒绝创建
- **WHEN** 用户只上传文档、不上传 YAML，且标题与目标已填写
- **THEN** 系统拒绝创建任务并说明需要一份 YAML 配置

### Requirement: 原始上传文件只保留七天
系统 SHALL 把任务原始上传文件放入既有上传目录，并在超过 7 天后删除这些文件。任务记录中的 YAML 正文与文档 Markdown MUST 保留。原件已删除时，再次启动 MUST 用任务记录中的正文重新落成临时文件交给智能体。

#### Scenario: 超过七天的原件被删除
- **WHEN** 某任务的原始上传文件在上传目录中的修改时间早于 7 天，且清理运行
- **THEN** 该原件被删除，任务记录中的 YAML 正文与文档 Markdown 仍在

#### Scenario: 原件已删除时仍能启动
- **WHEN** 一条待执行任务的原始 YAML 文件已被清理，且记录中仍有 YAML 正文
- **THEN** 系统用该正文落成临时文件再交给智能体，并按执行前检查显示加载结论

## MODIFIED Requirements

### Requirement: 线路分发执行

系统 SHALL 按任务所选线路分发执行：控制设备线路启动已登记的 SOP；平台任务线路本期返回占位状态。

#### Scenario: 控制设备线路启动 SOP

- **WHEN** 用户在控制设备线路提交一条通过格式检查的任务
- **THEN** 系统创建任务并按设备调度启动 SOP，不调用规划模型生成步骤

#### Scenario: 平台任务占位

- **WHEN** 用户选择「平台任务」线路提交任务
- **THEN** 系统创建任务并返回「线路开发中」占位状态，不执行 reasoning

### Requirement: 失败任务可克隆新建后重新执行

系统 SHALL 在失败任务卡片提供「重新执行」。点击后 MUST 读取该任务的标题、目标、全部附件（YAML 正文、文档 Markdown 与各自文件名）、设备 serial/label、所属智能体，创建一条**新**任务记录（新 id、pending），并进入与新建任务相同的设备调度。原任务 MUST 保持原 id、状态与结果不变。系统 MUST NOT 覆盖或重置原任务。cancelled 任务 MUST NOT 提供「重新执行」。

#### Scenario: 失败卡重新执行产生新任务

- **WHEN** 用户在状态为失败的任务卡片点击「重新执行」
- **THEN** 系统创建新任务（标题、目标、全部附件、设备与原任务相同），原失败任务仍在列表中且状态仍为失败

#### Scenario: 新任务出现在列表

- **WHEN** 重新执行成功
- **THEN** 任务列表包含新任务卡片，且该新任务进入待执行/执行中流程

#### Scenario: 非失败任务不提供重新执行

- **WHEN** 任务状态不是失败
- **THEN** 卡片不展示「重新执行」

### Requirement: 任务详情可查看附件解析正文

系统 SHALL 在任务详情数据中提供每份文档附件的文件名与 Markdown 正文全文，以及 YAML 的文件名、正文与配置加载结论。未上传文档时，文档列表 MUST 为空。系统 MUST NOT 因正文较长而截断或改写其内容，展示层的折叠与滚动由前端负责。配置加载结论 MUST 为「配置加载成功」或「加载失败」；任务尚未执行到加载检查时，结论 MUST 为空。

#### Scenario: 有附件时详情返回解析正文

- **WHEN** 用户打开一条带两份文档附件的任务详情
- **THEN** 系统按上传顺序返回两份文件名与各自的 Markdown 正文

#### Scenario: 无附件时正文与文件名均为空

- **WHEN** 用户打开一条没有文档附件、且没有历史单附件字段的任务详情
- **THEN** 系统返回的文档列表为空

#### Scenario: 详情展示配置加载结论

- **WHEN** 用户打开一条已经完成执行前检查的任务详情
- **THEN** 页面显示该 YAML 的文件名，以及「配置加载成功」或「加载失败」

#### Scenario: 详情页可读附件全文

- **WHEN** 用户在任务详情页展开某份文档附件
- **THEN** 页面按预格式展示该份 Markdown 全文，并在正文超出可视高度时于区块内部滚动，不撑破页面布局

### Requirement: 任务卡片展示附件名

系统 SHALL 在任务列表数据中提供全部附件文件名。任务卡片 MUST 展示 YAML 文件名；存在文档附件时 MUST 一并展示文档文件名。没有任何附件名时 MUST 展示占位符（—）。卡片 MUST NOT 展示附件正文。

#### Scenario: 带附件的卡片显示文件名

- **WHEN** 用户查看一条带 YAML 与一份 PDF 的任务卡片
- **THEN** 卡片展示该 YAML 文件名与该 PDF 文件名

#### Scenario: 无附件的卡片显示占位

- **WHEN** 用户查看一条没有附件文件名的历史任务卡片
- **THEN** 卡片的附件一项显示「—」，且列表接口响应中不包含附件正文

### Requirement: 任务过程记录不含模型思考与工具明细

任务过程记录 MUST NOT 包含模型思考过程与工具调用 / 返回明细（执行侧与验收侧皆然）；这些内容 SHALL 只出现在过程日志文件中。过程记录 SHALL 保留展示与判定所需的全部数据：YAML 中的步骤、执行结果三字段、验收结论五字段、验证截图路径、日志检查块与设备日志证据。

#### Scenario: 新任务的过程记录不含过程明细

- **WHEN** 查看一个新任务的某步过程记录
- **THEN** 该步记录中不含思考过程与工具调用 / 返回明细字段

#### Scenario: 判定所需数据仍完整

- **WHEN** 查看一个新任务的某步过程记录
- **THEN** 仍能读到该步的执行结果三字段、验收结论五字段、验证截图路径，以及需日志核对时的日志检查与设备日志证据

### Requirement: 任务详情页不展示模型思考与工具明细

任务详情页 MUST NOT 呈现模型思考过程与工具调用 / 返回明细（含任何折叠区块）。页面 SHALL 保留：已加载 YAML 中的步骤清单、每一步的执行结果、验证截图、日志检查块与设备日志证据；这些区块 MUST 为只读展示。页面 MUST NOT 再展示「送给规划模型的输入」。

#### Scenario: 步骤卡片不含思考与工具区块

- **WHEN** 用户打开一个任务的详情页
- **THEN** 每张步骤尝试卡片上都不出现思考过程或工具调用明细的区块

#### Scenario: 结果与证据仍可见

- **WHEN** 用户打开一个已完成任务的详情页
- **THEN** 仍能看到 YAML 中的步骤、每步执行结果、验证截图；被标记需日志核对时仍能看到日志检查与设备日志证据
