## 上下文

「AI 用量」第 4 张 KPI 卡当前读取统计接口的 `ai_usage.avg_tokens_per_task`，主数值为累计平均值（千 K），副标题为今日平均值。接口同时已在 `ai_usage.total_tokens` 中提供今日与累计的 token 合计，无需新增字段。仪表盘 KPI 卡统一走 `StatsCard`（`KpiCard` entry 变体的薄包装），其 `desc` 缺省时会回退为「核心指标实时更新」。

## 目标 / 非目标

- 目标：第 4 张卡改为「当天 Token 用量」，主数值为当天 token 合计，百万（M）单位、2 位小数，不取平均、不显示副标题。
- 非目标：不改后端聚合与接口契约，不删除 `avg_tokens_per_task` 字段，不改其余四张卡的今日/累计口径，不改智能体明细卡。

## 决策

- 复用 `ai_usage.total_tokens.today` 与既有 `toMillions()`，不新增接口字段。这样后端零改动，今日 token 口径与「累计 Token」卡的今日值完全一致。
- 主数值使用百万（M）单位、保留 2 位小数，与「累计 Token」卡同精度，便于直接对照。
- 副标题不显示：给 `StatsCard` 增加显式 `hideDesc` 开关，而不是传空字符串。原因是 `desc` 为空时会回退默认文案，传空无法表达「不要副标题」；新增开关可保持其余卡默认行为不变。
- 删除仅被旧卡使用的 `toK()`，避免留下无调用点的死代码。
- `avg_tokens_per_task` 继续保留在接口中，只是前端不再消费。删除字段会破坏接口契约与既有文档，收益不足。

## 风险 / 权衡

- 当天 token 小于 0.005M 时显示 `0.00M`，与「累计 Token」卡的小数口径一致，属于可接受的四舍五入观感。
- 去掉副标题后卡片文字更少，但卡片有固定最小高度，五卡仍保持等高网格。

## 迁移计划

- 仅前端展示层改动，无需数据迁移。回滚即还原 `index.vue`、`StatsCard.vue`、`DashboardView.logic.ts` 与对应单测。
