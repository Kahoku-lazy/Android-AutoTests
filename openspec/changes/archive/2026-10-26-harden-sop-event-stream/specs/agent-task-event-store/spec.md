# agent-task-event-store 变更

## MODIFIED Requirements

### Requirement: 平台任务写入结构化事件
有任务号的平台运行 MUST 把交给接收方的结构化记录写入该任务的事件表。同一任务内序号 MUST 从已有最大序号之后连续递增，且任务与序号的组合 MUST 唯一。每条记录 MUST 带上**当前正在执行的用例**标题：一个任务按序跑多条用例时，每进入一条用例 MUST 刷新该标题，MUST NOT 让整任务的所有行共用一个值；没有用例标题时 MUST 写空串。有当前步骤时 MUST 带上从 1 起的步骤序号和该步的尝试次数，没有当前步骤时这两项 MUST 为空。费用 MUST 保留小数点后 8 位。文本日志 MUST 仍然写出。任务号为 0 或未绑定运行上下文时 MUST NOT 写入事件、图片或小时用量。

#### Scenario: 三条记录按序落在同一任务下
- **WHEN** 一次任务依次交出回复结束、模型调用结束和工具返回结束
- **THEN** 事件表有序号 1、2、3 的三行，且都带该任务的用例标题

#### Scenario: 一个任务里两条用例各有自己的标题
- **WHEN** 同一任务先跑标题为「甲」的用例，再跑标题为「乙」的用例，两条用例各自交出记录
- **THEN** 「甲」产生的行用例标题为「甲」，「乙」产生的行用例标题为「乙」，后半段行的步骤序号从 1 重新开始

#### Scenario: 当前步骤被盖到记录上
- **WHEN** 交出记录时，流程正处于第 2 步的第 1 次尝试
- **THEN** 该行的步骤序号为 2，尝试次数为 1

#### Scenario: 没有任务号时不写库
- **WHEN** 任务号为 0 时交出一条模型调用结束
- **THEN** 事件表、图片表和小时用量表都没有新增行，文本日志仍可写出

### Requirement: 图片只存缩略图并按内容去重
带图片的记录 MUST 把原图压成长边不超过 720 的 JPEG 缩略图后再保存，MUST NOT 保存原图 base64。同一任务内内容相同的原图 MUST 只占一行图片，后续记录 MUST 指向这一行。系统 MUST NOT 按张数设置采集上限：任意数量的不同图片 MUST 都能新增图片行，对应事件 MUST 拿到该图片的引用。无法解码的图片 MUST 跳过图片保存，事件行本身 MUST 仍然写入，且该行的载荷 MUST 带上表示编码失败的标记，使「这一步没有截图」与「截图存不下来」在事后可区分；同时 MUST 留下可读警告日志，含任务号、序号与角色名。删除任务时，该任务的事件和图片 MUST 一并删除。

#### Scenario: 同一张图只存一行
- **WHEN** 同一任务的两条工具返回结束携带同一张原图
- **THEN** 图片表只有一行，两行事件指向同一张缩略图，且媒体类型为 JPEG

#### Scenario: 超过三百张后继续保存
- **WHEN** 某任务已经有 300 张不同图片，又出现第 301 张新的不同图片
- **THEN** 图片表新增一行，该事件的图片引用不为空

#### Scenario: 多用例任务全程都有图
- **WHEN** 一个任务的截图总数达到 785 张（跨 12 条用例）
- **THEN** 每张不同画面都占一行图片，任意一次截图事件都能拿到图片引用

#### Scenario: 坏图在行上留痕
- **WHEN** 一条记录携带的 base64 无法解码成图片
- **THEN** 该行照常写入、图片引用为空，载荷带编码失败标记，并留下含任务号与序号的警告日志

#### Scenario: 删除任务带走事件和图片
- **WHEN** 删除一个已有事件和图片的任务
- **THEN** 该任务的事件和图片都不再存在

## ADDED Requirements

### Requirement: 整批写入失败降级逐行
接收方按批写入事件时，整批失败 MUST NOT 使这一批行被反复重试到运行结束，也 MUST NOT 因为其中一行写不进去而丢掉同批其余行。整批失败 MUST 降级为逐行写入：写得进去的行 MUST 落库；写不进去的行 MUST 只记一条含任务号、序号与事件类型名的警告并被丢弃。一批的行 MUST 在写入尝试之前从缓冲中取出，MUST NOT 在失败后仍留在缓冲里等待重试。降级之后小时用量 MUST 只按真正落库的行累加。

#### Scenario: 整批失败后坏的丢好 的留下
- **WHEN** 一批三行，整批写入失败，改为逐行后第 2 行仍然失败
- **THEN** 第 1、3 行落库，第 2 行被丢弃并留下警告，缓冲清空，小时用量只增加第 1、3 行对应的部分

#### Scenario: 失败的那批不重复写入
- **WHEN** 一批写入失败并降级成功后，运行继续产生新行
- **THEN** 后续批次只包含新行，已写入的行不会再次写入

### Requirement: 单批按字节上限分片
接收方 MUST 按累计字节数提前结束一批，MUST NOT 只按行数分批。单批累计字节数达到上限时 MUST 立即写入，不等凑满行数。上限 MUST 显著小于数据库单次语句允许的最大包长，以免一条长载荷把整批顶穿。

#### Scenario: 长载荷触发提前写入
- **WHEN** 单批字节上限为 100，先收到一行短行，再收到一行带 200 字节载荷的行
- **THEN** 两行进同一批并立即写入，不等凑满常规行数

#### Scenario: 短行仍按行数分批
- **WHEN** 每行都很短，累计字节数远低于上限
- **THEN** 仍按常规行数上限分批写入
