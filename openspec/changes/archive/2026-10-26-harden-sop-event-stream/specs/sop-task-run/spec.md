# sop-task-run 变更

## ADDED Requirements

### Requirement: 运行预算超限时停止整轮

系统 SHALL 为一次控制设备任务维护两项运行预算：模型调用总次数与运行总时长。任一预算超限时，任务 MUST 结束当前用例并**停止整轮**，MUST NOT 继续启动后面的用例。停止时任务状态 SHALL 为失败，原因 MUST 可读并写明命中的上限与当前上限值。已被判定完成的用例 MUST 保留在完成清单里，MUST NOT 因为整轮停止而被改写为失败；已经写入的事件 MUST NOT 被回滚或删除。停止 MUST NOT 由用例自身的验收次数或交付检查触发，也 MUST NOT 占用步骤的尝试次数。未绑定运行上下文时的运行（本地调试）MUST NOT 受预算约束。

#### Scenario: 次数超限后不再启动下一条用例

- **WHEN** 一个任务的 YAML 有「甲」「乙」两条用例，模型调用次数上限在「甲」执行期间被用尽
- **THEN** 「甲」结束后任务停止，报告的失败原因含「运行预算超限」与上限值，「乙」不开始

#### Scenario: 已完成的用例不被改写

- **WHEN** 一个任务先跑完「甲」，随后在「乙」期间触发时长上限
- **THEN** 完成清单仍含「甲」，失败原因含「运行预算超限」，任务状态为失败

#### Scenario: 事件不被回滚

- **WHEN** 运行因预算超限停止
- **THEN** 停止前已写入的事件行仍在事件表里，报告仍能读到这些轮次

#### Scenario: 未绑定运行时不受约束

- **WHEN** 以本地调试方式直接执行一次运行，没有任务号
- **THEN** 不发生预算判定，运行按引擎自身的轮次上限收尾
