## Context

验收轮标题当前渲染三件东西：`✅` / `❌` 标记、角色徽章、PASS / FAIL 判决徽章。判决徽章的数据来自 `round.verdict.passed`，与标记同源，纯属重复；它原先挂在标题最左（上一轮之前），本轮改成跟到角色徽章之后，仍多占一格。

## Goals / Non-Goals

**Goals:**

- 单轮判决只出现一次：`✅` / `❌`。
- 少一个元素、少一种配色，标题更短。

**Non-Goals:**

- 不动执行轮的 `➡️`、序号、重试次数与角色徽章配色。
- 不动用例级结果徽章（`.flow-case__title` 与页头摘要仍用 `.badge-pass` / `.badge-fail`）。
- 不改接口字段。

## Decisions

**1. 直接删掉标题里的判决徽章，而不是把它换成文字。**

`✅` / `❌` 已表达判决，再写「PASS」是同一布尔第二次出现。删掉后 `roundOutcomeText()` 失去调用方，一并删除，避免留死代码；`.badge-pass` / `.badge-fail` 仍被用例标题与页头摘要使用，样式保留。

**2. 无判决时什么都不画。**

没有 `verdict` 时既无标记也无徽章，标题为「角色徽章 + ：动作」，与改动前的空态一致。

## 模块防火墙自检

- 只动 `task-list` 模块与其 `helpers/`、`tests/task-list/`，无跨模块引用。

## Risks / Trade-offs

- [判决的可访问性] → `✅` / `❌` 是字符而非纯色块，读屏可读；色觉障碍用户也能靠形状区分。
- [既有样式规则失效] → `.badge-role + .badge` 的间距规则随判决徽章一起删除，避免留下无人命中的选择器。
