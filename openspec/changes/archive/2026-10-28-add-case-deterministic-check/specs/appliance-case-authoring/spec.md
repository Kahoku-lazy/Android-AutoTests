## ADDED Requirements

### Requirement: 确定性校验

平台 MUST 在每轮 GoalPipeline 写完后，用代码解析模块文档并核对：七节是否齐全、原子/用例 ID 是否唯一、每条追溯 ID 是否存在于原子表、原子是否被覆盖、13 字段是否为空或占位符、执行状态是否合法、复杂度与最少方法数是否达标、P0 用例占比是否 ≤30%、E2E 是否 ≥3、预期结果是否含模糊词。

存在任一确定性问题时，该轮 MUST NOT 判定为通过。平台 MUST 追加一条 `[确定性问题]` 判决，把问题清单并入下一轮重写输入；没有剩余轮次时该模块判失败。

平台 MUST 用表格实际数据重写第六节「覆盖与门禁自检」，至少给出需求原子数、用例数、P0/P1/P2 用例数及占比、已判定覆盖率、已登记覆盖率、方法使用统计与 E2E 条数。重写结果 MUST 回写模块存储，验收角色读到的是修正后的统计。

#### Scenario: 统计与表格不一致

- **WHEN** 编写角色在第六节写「用例数 30」，但用例表实际只有 28 行
- **THEN** 平台把第六节重写为用例数 28
- **AND** 其余确定性问题（如有）作为 `[确定性问题]` 判决进入下一轮

#### Scenario: 追溯 ID 不在原子表

- **WHEN** 某条用例追溯 `REQ-999`，而原子表没有该 ID
- **THEN** 该轮标记确定性问题，MUST NOT 通过验收
- **AND** 下一轮输入包含「REQ-999 不在原子表」的明确要求

#### Scenario: 方法数不足

- **WHEN** 一条 L2 用例的方法列只有「场景流+判定表」两种
- **THEN** 该轮标记确定性问题，要求补足到三种或下调复杂度

#### Scenario: 确定性问题已修复

- **WHEN** 下一轮文档通过全部确定性校验且验收 `result=pass`
- **THEN** 该模块通过，最终文档使用代码重写后的第六节
