## MODIFIED Requirements

### Requirement: 平台任务写入结构化事件

有任务号的平台运行 MUST 把交给接收方的结构化记录写入该任务的事件表。同一任务内序号 MUST 从已有最大序号之后连续递增，且任务与序号的组合 MUST 唯一。连续且同类型、同步骤、同尝试次数的流式增量 MUST 合并写成一行，并用 `delta_count` 记录该段的增量条数；这一行的展示时刻 MUST 取该段第一条增量的时刻。每条记录 MUST 带上当前正在执行的用例标题：一个任务按序跑多条用例时，每进入一条用例 MUST 刷新该标题，MUST NOT 让整任务的所有行共用一个值；没有用例标题时 MUST 写空串。有当前步骤时 MUST 带上从 1 起的步骤序号和该步的尝试次数，没有当前步骤时这两项 MUST 为空。费用 MUST 保留小数点后 8 位。文本日志 MUST 仍然写出。任务号为 0 或未绑定运行上下文时 MUST NOT 写入事件、图片或小时用量。

#### Scenario: 三条记录按序落在同一任务下
- **WHEN** 一次任务依次交出回复结束、模型调用结束和工具返回结束
- **THEN** 事件表有序号 1、2、3 的三行，且都带该任务的用例标题

#### Scenario: 一个任务里两条用例各有自己的标题
- **WHEN** 同一任务先跑标题为「甲」的用例，再跑标题为「乙」的用例，两条用例各自交出记录
- **THEN** 「甲」产生的行用例标题为「甲」，「乙」产生的行用例标题为「乙」，后半段行的步骤序号从 1 重新开始

#### Scenario: 当前步骤被盖到记录上
- **WHEN** 交出记录时，流程正处于第 2 步的第 1 次尝试
- **THEN** 该行的步骤序号为 2，尝试次数为 1

#### Scenario: 没有任务号时不写库
- **WHEN** 任务号为 0 时交出一条模型调用结束
- **THEN** 事件表、图片表和小时用量表都没有新增行，文本日志仍可写出

#### Scenario: 连续增量合并成一行
- **WHEN** 同一类型、同一步骤、同一尝试次数连续交出 17,447 条工具参数增量
- **THEN** 事件表只为该段写一行，`delta_count` 为 17,447，序号在段结束时分配
