## MODIFIED Requirements

### Requirement: 图片只存缩略图并按内容去重

带图片的记录 MUST 把原图压成长边不超过 720 的 WebP（质量 75）后写入任务媒体目录下的本地文件，MUST NOT 保存原图，MUST NOT 把图片字节写进数据库。文件路径 MUST 为 `<任务媒体目录>/<task_id>/<sha256>.webp`。同一任务内内容相同的原图 MUST 只占一行图片与一个文件，后续记录 MUST 指向这一行。系统 MUST NOT 按张数设置采集上限：任意数量的不同图片 MUST 都能新增图片行和文件，对应事件 MUST 拿到该图片的引用。无法解码的图片 MUST 跳过图片保存，事件行本身 MUST 仍然写入，且该行的载荷 MUST 带上表示编码失败的标记，使「这一步没有截图」与「截图存不下来」在事后可区分；同时 MUST 留下可读警告日志，含任务号、序号与角色名。删除任务时，该任务的事件、图片行与图片文件 MUST 一并删除。

#### Scenario: 坏图在行上留痕

- **WHEN** 一条记录携带的 base64 无法解码成图片
- **THEN** 该行照常写入、图片引用为空，载荷带编码失败标记，并留下含任务号与序号的警告日志

#### Scenario: 同一张图只存一行

- **WHEN** 同一任务的两条工具返回结束携带同一张原图
- **THEN** 图片表只有一行、任务目录下只有一个 `.webp` 文件，两行事件指向同一张缩略图

#### Scenario: 数据库不存图片字节

- **WHEN** 写入一张新截图
- **THEN** `task_media` 行的 `thumb_b64` 为空，`storage_key` 指向存在的 WebP 文件

#### Scenario: 超过三百张后继续保存

- **WHEN** 某任务已经有 300 张不同图片，又出现第 301 张新的不同图片
- **THEN** 图片表新增一行、目录新增一个文件，该事件的图片引用不为空

#### Scenario: 多用例任务全程都有图

- **WHEN** 一个任务的截图总数达到 785 张（跨 12 条用例）
- **THEN** 每张不同画面都占一行图片和一个文件，任意一次截图事件都能拿到图片引用

#### Scenario: 删除任务带走事件和图片

- **WHEN** 删除一个已有事件和图片的任务
- **THEN** 该任务的事件行、图片行与图片目录都不再存在
