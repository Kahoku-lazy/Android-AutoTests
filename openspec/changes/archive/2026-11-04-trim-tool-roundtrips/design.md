## Context

现状见 proposal.md - Why。设计上要动的只有三处引擎工具与一处报告聚合，约束来自既有分层：

- 工具实现集中在 `engines/agents/tools/tool_*.py`，分配只经 `tools_config.py`；工具名与分组本次不变（常驻组仍是 `screenshot_page` / `mark_dot` / `press_key`），因此不动 `tools_config.py`。
- `mark_dot` 现在位于 `tool_img_b64.py`（图片标注），点击类工具位于 `tool_device.py`（设备动作）。两者要共享「刚核对过的那一帧」，只能靠一个不属于任一工具的短时缓存。
- 报告聚合在 `backend/apps/task_list/task_reports.py`，已有 `duration_ms`（步骤墙钟）与 `model_ms`（轮级模型耗时），本次在同一聚合里补两项。
- `engines` 不写业务库，帧缓存也不得落盘或进入事件载荷。

## Goals / Non-Goals

**Goals:**

- 同一次点击只截一屏：核对用的帧直接用于定位，点击工具回传点击后的图。
- 日志检查从「每次全量解析 8.5MB」变成「只解析新增行」，对外结果逐字一致。
- 详情页能读出「墙钟 = 模型 + 工具 + 空档」，三者可对照。

**Non-Goals:**

- 不新增工具、不改工具组、不改 `tools_config.py`。
- 不改日志 5 秒窗口、关键词来源规则与验收判决口径。
- 不做「一次调用完成标点+点击」的单趟合并（取消点击前否决权，当前重标率 45% 不具备条件）。
- 不改 `task_events` 表结构，不引入新事件类型。

## Decisions

**D1 帧缓存放进程内 LRU，键 `(serial, token)`，TTL 90s，每设备最多 2 帧。**

备选：落盘缓存（要清理、跨进程不一致）、写库（engines 禁止写业务库）、按任务目录存（SOP 跨进程恢复后失效更隐蔽）。进程内最简单且失效语义明确：进程重启即全部失效，模型会收到可读 error 并重新核对。每设备 2 帧足以覆盖「核对 → 点击」以及偶发的一次重标。

**D2 `token` 失效一律报错，不静默换帧。**

静默重截会让「你看到的那一屏」和「实际点击的位置」悄悄错开，正是本变更要消除的问题的镜像。错误文案要给出可执行动作：`标记帧已过期，请重新调用 mark_dot 核对坐标`。

**D3 点击工具默认回传点击后页面图，可用 `shot_after=False` 关闭。**

默认回图是为了让「手势后必须复核」这条既有纪律不再额外花一趟往返；`app_control` 这类不需要屏幕的动作不传该参数也不回图。回图走与 `screenshot_page` 相同的一次采集链路，不额外截第二屏。

**D4 日志增量解析按「已解析字节偏移 + 行数」缓存，失配就回退全量。**

键为日志绝对路径，值为 `(size, mtime_ns, parsed_bytes, rows)`。只解析 `parsed_bytes` 之后以换行结尾的完整行，半行留到下次；`size` 变小或 `mtime_ns` 早于记录时丢弃缓存并全量重解析。备选：只读尾部 N MB（会丢历史行，导致「窗口内命中」判定与全量解析不一致，违反 spec 的一致性要求）。

**D5 `idle_ms` 用减法并 clamp 到 0，不在聚合里跑区间并集。**

事件区间存在嵌套（模型调用内含流式事件），精确求并集要遍历全部事件区间，代价远大于价值；步骤墙钟、模型、工具三项本身都是可靠量，差额截断到 0 已足够回答「差在哪」。离线复核脚本（`temps/analyze_task184.py`）保留区间并集算法，用于人工核对。

**D6 前端沿用现有步骤行徽标位，三项都非零才同时出现，零值隐藏。**

避免给存量任务凭空加两个 `0s`；也避免改动折叠结构。格式化继续用既有 `formatDurationMs`。

## 模块防火墙自检

- 跨 App import：本次后端只改 `backend/apps/task_list/task_reports.py`，属本 App 内部聚合函数，不新增跨 App import。
- 写操作：本次无新增写库路径；`mark_dot` / 点击 / 日志检查仍为只读或设备副作用，不写业务库。
- engines 边界：帧缓存是引擎内进程内结构，不 import `apps.*` / `django.*`，不落盘、不入事件载荷。
- 前端：只消费既有 `GET /api/tasks/{id}/report/` 信封，不新增接口、不直连数据库。

## Risks / Trade-offs

- [帧在 90s 内被后续截图覆盖，模型拿旧 token 点错位置] → 每设备保留 2 帧 + TTL 90s，且 token 与设备绑定；单元测试覆盖「旧 token 失效」与「跨设备 token」。
- [模型看见 token 就跳过红点确认直接点] → 提示词保留「先看到红点、再用该 token 点击」；token 只在核对成功时签发。
- [日志在两次检查之间被截断重建，长度恰好没变小] → 同时比对 `mtime_ns`，倒退即回退全量；单测覆盖截断与轮转两个场景。
- [增量解析与全量解析出现细微差异（编码错误行）] → 解析函数与全量路径共用同一实现，只差起始偏移；单测对同一文件比对两条路径的输出。
- [`idle_ms` 被读成「框架浪费」] → 页面文案用「空档」，并在设计文档与 `dev_docs` 分析里写明它包含事件落库、图片编码与上下文装配。

## Migration Plan

无数据库迁移。存量任务的 `tool_ms` / `idle_ms` 为 0，前端自动隐藏；回滚只需还原三个工具文件与聚合函数、提示词与前端展示，帧缓存不持久化因而无残留状态。
