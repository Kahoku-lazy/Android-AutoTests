## MODIFIED Requirements

### Requirement: 执行提示词声明提交前自检

执行角色的系统提示词 MUST 声明以下约束：提交前逐条核对本步“必须达成的结果”；存在未达成条目时 MUST NOT 声称完成；被驳回后 MUST 先执行上一条驳回说明里的最小动作，再考虑其它方案；定位 MUST 先按页面上的确定文案走 xpath（含去空白、全角转半角的归一化匹配，最多 3 个候选一次给全），xpath 全部未命中或目标本身没有文案（开关、滑块、加号）时才用截图估算归一化坐标；取到的坐标 MUST 先经坐标核对（xpath 标记或红点标记）确认落在目标元素上，确认前 MUST NOT 执行点击；长按、拖动等手势完成后 MUST 核对工具回传的页面图。

坐标核对与点击之间 MUST NOT 再截一张图：核对返回帧标识后，MUST 用该标识直接调用点击类工具，MUST NOT 先截图再点击，MUST NOT 用截图重新估一遍坐标。点击类工具已返回点击后的页面图时，MUST 用这张图判断本步结果，MUST NOT 为同一个动作再调一次截图工具；同一动作的截图 MUST 只出现一次。

**硬规则**：提示词 MUST 声明「没有经过坐标核对确认的目标不得操作」——点击类工具缺帧标识会直接报错，提示词 MUST 要求模型先补一次核对再点，MUST NOT 绕过或把报错当成已完成。xpath 命中多个时，提示词 MUST 要求先看带序号的标记图，从中选出真正要点的那个序号，再把该帧标识与序号交给点击工具，MUST NOT 凭坐标大小猜。

handover MUST 只包含两块内容，且 MUST 按此顺序：① 本步做了什么——每次点击 / 长按 / 拖动的 `action_time`（点击类工具返回原文），按操作顺序逐条列出，有输入或开关改动的写明改成了什么；② 最终结果——以「达成」或「未达成」开头，再用一句话写清设备与页面的实际状态。handover MUST NOT 写过程分析、逐条证据、日志结论、阻塞说明或下一步建议。handover MUST NOT 出现“尚未”“未完成”“未点击”“请下一步”这类收尾表述；确实没做完时 MUST 继续操作，直到达成或确认无法达成，再按「未达成」写最终结果。

提示词还 MUST 区分两类加载：页面整体加载（空白、骨架屏、全屏 loading）超过 10 秒可按失败处理；长按或点击卡片后出现的小加载圈属于设备连接/同步过程，MUST 等待其消失（最长 60 秒），MUST NOT 据此判本步失败，也 MUST NOT 在等待期间重复长按。

#### Scenario: 提示词包含提交前自检条款

- **WHEN** 读取执行角色的系统提示词常量
- **THEN** 其中同时包含“逐条核对”“未达成不得声称完成”“先执行驳回指令”“坐标以工具返回为准”“手势后复核”“action_time 写进 handover”六项约束

#### Scenario: 定位顺序是先 xpath 再视觉

- **WHEN** 检查执行角色提示词里关于“怎么定位目标”的规则
- **THEN** 其中明确先按页面上确定文案走 xpath（含归一化匹配、最多 3 个候选），xpath 未命中或目标无文案时才用截图估算

#### Scenario: 多命中时按标记图挑序号

- **WHEN** 检查执行角色提示词里关于“命中多个怎么办”的规则
- **THEN** 其中要求先看带序号的标记图选出要点的那个序号，再带帧标识与序号点击，且明确不得凭坐标大小猜

#### Scenario: 未确认目标的操作被禁止

- **WHEN** 检查执行角色提示词里关于“能不能直接点”的规则
- **THEN** 其中明确没有经过坐标核对确认的目标不得操作，工具报缺帧标识时 MUST 先补核对，MUST NOT 绕过

#### Scenario: 提示词只要求两块交卷内容

- **WHEN** 检查执行角色提示词里 handover 的写法条款
- **THEN** 其中只要求“本步操作步骤（逐条带 `action_time`）”与“最终结果（达成 / 未达成 + 一句话实况）”两块，且明确不写过程分析、逐条证据、阻塞说明与下一步建议

#### Scenario: 提示词不再允许交半成品

- **WHEN** 检查执行角色提示词中关于“没做完”的表述
- **THEN** MUST 要求继续操作直到达成或确认无法达成，并按「未达成 + 一句话实况」如实交卷，MUST NOT 仅要求把未完成情况写出来就允许提交

#### Scenario: 未达成也按结果如实交卷

- **WHEN** 检查执行角色提示词里“确实做不到”时的交卷口径
- **THEN** 其中要求按「未达成」写最终结果并写清卡在哪里，MUST NOT 把未达成写成达成，也 MUST NOT 改用“尚未 / 未完成 / 请下一步”这类措辞

#### Scenario: 长按加载不当页面超时

- **WHEN** 检查执行角色提示词里关于加载圈的规则
- **THEN** 其中明确“长按/点击卡片后的加载圈是设备连接过程”，要求等待其消失而不是按页面加载超时判失败

#### Scenario: 未完成措辞视为未做完

- **WHEN** 检查执行角色提示词里关于 handover 的写法
- **THEN** 其中明确 handover 不得出现“尚未/未完成/请下一步”等表述，没做完必须继续操作

#### Scenario: 点击前必须先用红点核对坐标

- **WHEN** 检查执行角色提示词里关于“点击坐标”的规则
- **THEN** 其中要求估算坐标与 xpath 返回坐标都先经坐标核对确认（像素坐标传 normalized=False），红点不对必须重新确定并再次标记，确认前不得执行点击

#### Scenario: 核对与点击之间不再截图

- **WHEN** 检查执行角色提示词里关于“确认之后怎么点”的规则
- **THEN** 其中要求用核对返回的帧标识直接点击，且明确核对与点击之间不得再截图、不得用截图重新估算坐标

#### Scenario: 点击后不再单独截图核对

- **WHEN** 检查执行角色提示词里关于“手势完成后复核”的规则
- **THEN** 其中要求直接使用点击类工具回传的点击后页面图判断结果，同一个动作不得再调截图工具
