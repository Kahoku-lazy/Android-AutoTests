## Why

H6810 的用例以 YAML 形式躺在本地目录（`D:\Govee\data\H6810`，7 份共 56 条），平台这边是两套互不相通的形态：用例库只存「动作 + 断言」的文档形态，执行链只认上传的 YAML 文件。结果是同一批用例要在两处各维护一遍，每次执行都得手工挑文件上传；而结构化 YAML 里专门写的 `anchor`（页面锚点）与 `log`（日志证据）在入库后就丢了，从平台跑反而比本地跑更差。

## What Changes

- 用例步骤新增两个可选执行提示字段：`anchor`（页面锚点）与 `log`（日志证据），导入、保存、读回全程保真；动作与断言的校验规则不变。
- 新增「YAML ⇄ 用例库」互转能力：
  - 命令行按目录同步（每份 YAML 一张用例表，重复同步为幂等覆盖，可显式清理缺席行）；
  - 用例库网页上传导入（同一套解析与落库逻辑）；
  - 平台用例导出为可执行 YAML（供执行链直接消费）。
- 新建任务弹窗新增「用例来源」二选一：**平台用例**（项目 → 文件 → 选用例）或**本地 YAML**（沿用现有上传）。平台用例来源提交后由后端把选中用例物化为 YAML 附件，执行链与引擎零改动。
- 不是**BREAKING**：本地 YAML 上传路径、现有用例数据与执行流程全部保留。

## 关联文档

- 无独立 PRD 编号：依据 [PRD-平台总需求](../../dev_docs/ARCH_PRD/PRD-平台总需求.md) §四 子模块功能规格索引中「文档式用例……支持移动、批量删除、导入导出」与「AI 任务：按智能体下发、指定设备与用例」两条既有描述；本次把其中「导入导出」与「指定用例」从手工上传闭环为平台用例。

## Capabilities

### New Capabilities

- `case-manager-yaml-sync`: YAML 与用例库互转——目录同步、网页导入、导出可执行 YAML，导入过程保留页面锚点与日志证据等执行提示。

### Modified Capabilities

- `case-manager-case-form`: 步骤序列新增可选执行提示（anchor / log）及其保存、读回与校验语义。
- `task-card-sop-form`: 新建任务弹窗增加「用例来源」选择，提交载荷按来源区分；智能体参数组的描述随之调整。

## Impact

- **backend**：`case_manager`（模型 + 迁移、步骤序列化与校验、新增 `api_yaml`、导入接口、目录同步管理命令）、`task_list`（提交入参、按平台用例物化 YAML 附件）。
- **engines**：`agents/workflow/case_file.py` 增加公开的执行提示校验入口，供后端与自身解析共用；执行链与提示词不变。
- **前端**：`task-list` 新建任务弹窗（用例来源 + 平台用例选择器）、`case-manager` 用例库（导入 YAML 入口、步骤面板只读展示执行提示）。
- **测试**：新增后端单测（解析/映射/幂等/导出往返/接口/提交物化）与前端 vitest（来源切换与载荷、导入对话框状态）。
- **数据**：`cm_case_steps` 新增两列 JSON，旧行按空值处理，无需数据回填。
