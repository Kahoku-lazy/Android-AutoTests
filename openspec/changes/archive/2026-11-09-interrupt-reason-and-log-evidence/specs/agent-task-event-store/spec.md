## REMOVED Requirements

### Requirement: 整批写入失败降级逐行
**Reason**: 该口径要求「写不进去的行只记警告并丢弃、且不在缓冲里等待重试」，任务 201 因此整批丢失事件（含写着中断原因的 `StepInterruptedEvent`）。
**Migration**: 由 `写入失败保留待写行并重试` 取代。调用方无需改动：接收方按批写失败后自动保留待写行并在下次写入重试，收尾再试一次后才丢弃并告警。

## ADDED Requirements

### Requirement: 写入失败保留待写行并重试

接收方按批写入事件时，整批失败 MUST NOT 使这一批行被永久丢弃：待写行 MUST 留在缓冲里，并在下一次写入时重试；写得进去的行 MUST 落库，写不进去的行 MUST 继续保留。缓冲 MUST 有行数上限，超过上限时 MUST 只保留最新的行并留下含任务号与行数的告警，MUST NOT 无限增长。任务收尾时 MUST 再尝试一次；只有收尾仍写不进去的行才允许丢弃，且 MUST 留下含任务号、序号与事件类型名的警告。降级之后小时用量 MUST 只按真正落库的行累加，MUST NOT 重复累加。

事件写入 MUST 在同步上下文执行。调用方处在事件循环里（异步上下文）时，MUST 通过线程转交执行，MUST NOT 直接访问 ORM；因此产生的 `SynchronousOnlyOperation` MUST NOT 造成任何事件丢失。

#### Scenario: 整批失败后下次写入补齐

- **WHEN** 一批三行整批写入失败，随后连接恢复
- **THEN** 这三行在下次写入时被重试并落库，序号连续；小时用量只按真正落库的行累加一次

#### Scenario: 收尾仍失败才丢弃

- **WHEN** 某几行到任务收尾时仍写不进去
- **THEN** 丢弃这几行并写一条含任务号与序号的告警，其余事件照常保留

#### Scenario: 缓冲超过上限只留最新行

- **WHEN** 写入持续失败，待写行数超过上限
- **THEN** 只保留最新的若干行，并留下含任务号与行数的告警

#### Scenario: 异步上下文里不丢行

- **WHEN** 工作流在事件循环里记录一条事件，而写入需要访问 ORM
- **THEN** 写入经线程转交执行并成功落库，不出现 `SynchronousOnlyOperation`，也不因它丢事件

### Requirement: 成品记录直交接收方

已经是成品记录的条目（例如步骤中断事件）MUST 直接交给接收方，MUST NOT 送进按 AgentScope 事件类型分派的折叠：折叠对认不出的类型返回空结果，既不入库也不报错。

#### Scenario: 成品记录不被折叠吞掉

- **WHEN** 工作流写入一条已构造好的步骤中断记录
- **THEN** 接收方收到该记录并入库；MUST NOT 因它不属于事件流类型而被静默丢弃
