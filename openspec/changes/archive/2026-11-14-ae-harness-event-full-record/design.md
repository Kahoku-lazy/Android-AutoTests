## Context

全量转储实验（`temps/event_dump/20261114_184043`）给出 17 类事件、175 条的字段实况。三条事实决定了本方案：

| 事实 | 影响 |
| --- | --- |
| 每条事件都有 `created_at`（ISO 8601）、`id`、`metadata` | 绝对时间不必自己推 |
| `ReplyStart/End` 有 `session_id`；`HintBlockEvent` 有 `source` | 归属信息现成可得 |
| `ThinkingBlockDeltaEvent` 占 80%（140/175） | 全量不能等于「逐条落 delta」 |

现状：`record.py` 只落块级结果，思考截断 600、工具输出截断 4000，且丢掉上述公共字段。

## Goals / Non-Goals

**Goals:**

- 让产物自带绝对时间与事件标识，事后可精确排序、去重、与外部日志对齐。
- 让思考与工具输出在事后可完整复核（不再截断）。
- 默认开启，零调用方改动。

**Non-Goals:**

- 不逐条落 delta（体积与可读性都不划算）。
- 不改变用量记录、观测记录、`RunRecord` 的既有结构。
- 不替换自研的时间戳体系：`t_ms` 相对偏移仍保留（时间轴渲染依赖它）；`created_at` 是新增并列字段。

## Decisions

### D1. 开关放在记录器构造上，默认 `True`

`AgentEventRecorder(..., full=True)`。默认开、零调用方改动；需要小体积的场景显式传 `False`。

### D2. 「全量」= 字段全 + 不截断 + 仍折叠

用户明确要求「全量 JSON 按块级折叠」。因此全量模式不改变折叠策略（`_buf` 继续累积 delta），只做两件事：补字段、取消截断。这也是唯一能同时满足「信息全」与「产物可读」的组合。

### D3. 空值不写字段

`created_at` / `event_id` / `session_id` / `metadata` 取不到时**不写该字段**，而不是写空串。理由：产物里出现一堆 `""` 比缺字段更干扰判断；且替身事件的单测也不至于被空字段污染。

### D4. 截断上限保留但仅用于非全量模式

`_shrink` 的默认上限（4000）与思考上限（600）保留，作为 `full=False` 时的行为。全量模式下思考与工具输出传 `None` 上限表示不截断。文本块 `text` 只在全量模式写入。

### D5. 观测行不受开关影响

观测记录由中间件产生、由 `_drain_observations` 落盘，其字段集合与 `full` 无关，避免两个开关相互污染。

### D6. 关联键与开关无关，始终写入

`tool_call_id`（工具调用行与结果行）与 `block_id`（思考块行、文本块行）**不受 `full` 开关控制**，两种模式都写。

理由：它们是**身份**而不是补充信息。没有它们，产物里的「调用」与「结果」只能靠顺序配对，一次并发多工具就会错配；块也无法回溯到框架事件。既然要修「信息损失」，这两类键必须无条件存在。

代价：非全量模式的字段集合比改造前多两个键——这是有意的偏离，已在 spec 里单列一条需求说明。

## 模块防火墙自检

| 红线 | 是否触碰 | 说明 |
| --- | --- | --- |
| 跨 App / 写库 / 前端 | 否 | 只改 `engines/ae_harness/event/record.py` |
| `engines/` 零 `django.*` / `apps.*` | 否 | 只读事件属性 |
| 观测层零同包依赖 | 否 | 未新增导入 |
| 角色层 / 观测中间件边界 | 否 | 不涉及 |

## Risks / Trade-offs

- **默认开启会放大产物** → 这是需求方的明确选择；`full=False` 是回退开关，且已用实测规模（175 条、思考占 80%）说明放大来源。
- **思考/工具输出全文可能含敏感内容** → 工具输出来自设备（截图元信息、日志）；不新增外部读取，风险与改造前同源。
- **读取 `metadata` 可能是任意结构** → 落盘前做 JSON 化兜底（不能序列化的转 `repr` 截断），避免写盘时抛错。
- **`created_at` 与 `t_ms` 并存** → 两者语义不同（绝对 vs 相对），文档里写清，避免消费方混用。

## Migration Plan

1. 加开关与字段补齐，默认开；调用方零改动。
2. 单测覆盖「开／关」两组；关闭组断言旧结构不变。
3. 若产物过大，入口显式传 `full=False` 即可回退，无需改代码。
