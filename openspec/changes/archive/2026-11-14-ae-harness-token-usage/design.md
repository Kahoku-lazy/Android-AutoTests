## Context

`engines/ae_harness/` 是 `engines/` 下的独立原型链路：不接后端、无调用方、无测试资产。token 采集目前只发生在事件记录层——模型调用结束事件上的四类 token 被累加成四个整数写进汇总，逐次明细留在内存的事件行里，没有得到组织。

上一版设计把记账标签做成了五项身份（短名 / 厂商 / 密钥环境变量名 / 基址 / 正式模型名），代价是新增一个身份模块、一套结构协议，并让同一份配置被解析两遍。需求方指出记账只需要「哪把密钥」，本次设计据此收敛。

约束（来自 `engines/AGENTS.md`、`engines/ae_harness/*/AGENTS.md`、`.agents/rules/engines-code-style.md`）：

- token 采集只允许在 `engines/ae_harness/event/` 内实现。
- 事件层红线：不引用具体工具名、不修改智能体、不把图片 base64 写进 JSONL、不硬编码阶段标记、不写死路径。
- 角色层红线：不得绕过唯一创建出口、不得新增第二种创建入口、不得给角色加「第四样东西」。
- `engines/` 零 `apps.*`、零 `django.*`。
- 模块 docstring 必须满足 11 字段模板，`类型` 只能取四个枚举值。

## Goals / Non-Goals

**Goals:**

- 每次模型调用产出一条带密钥环境变量名的用量记录，可被同包之外的消费者直接读取。
- 记账标签在创建模型的瞬间就已经知道，必须顺带交出，不能再解析一遍配置。
- 采集与产出限定在事件记录层，该层只收一个字符串。
- 4 个既有命令行入口的参数、控制台输出与产物目录布局不变。

**Non-Goals:**

- 不记录 `provider`、`base_url`、配置短名、正式模型名；不实现「官方直连 vs 第三方网关」的通道审计。
- 不实现用量上报、不入库、不接 `model-usage-ledger` 的账本表；`engines/backend_bridge/token_usage/` 本期保持空目录。
- 不实现费用折算（金额、分时价、8 位小数）。
- 不改变报告 HTML 的版式与图表。
- 不改造 `engines/agents/`（正式链路）。

## Decisions

### D1. 密钥环境变量名由模型创建出口顺带返回

`create_model` 内部本来就要解析配置条目，`ChatModel.api_key` 就是环境变量名。让它把模型实例与这个名字一起返回，是零额外解析、零新增模块的做法。

返回值用两字段不可变数据类（`.model` + `.api_key_env`），不用裸元组：调用点读 `.api_key_env` 比读 `[1]` 可查，且以后加字段不破坏调用方。

考虑过的备选：

| 备选 | 为什么没选 |
| --- | --- |
| 另建身份模块，按短名再解析一次配置 | 同一份条目被 `ChatModel` 校验两遍，是实打实的冗余 |
| 调用方直接读 `models.yaml` 的 `api_key` 字段 | 绕过校验；字段名散落到创建层之外 |
| 返回裸元组 `(model, name)` | 位置语义不可读，加字段即破坏调用方 |

### D2. 只记密钥环境变量名，不记通道信息

`provider` 与 `base_url` 能区分「同一模型名走哪个网关」，但记账只回答「哪把密钥」。多记四项就多四处要维护、要测试、要落盘的字段，而当前配置表是一配置一密钥，环境变量名已经一对一标识了配置。

代价明确接受：将来看不到「官方直连 / 网关」，也看不到配置短名。要做通道审计时再加字段，那时是新增而不是返工。

### D3. 时间在用量记录内合成，不改事件行的写入逻辑

用量记录的开始与结束时刻由「本次运行的起始墙钟 + 相对偏移」合成。不给所有事件行补绝对时间戳：那会改变全部事件行的形状，连带影响 JSONL 体积与报告的事件视图列，属于本次需求之外的扩散。

### D4. 粒度为一次模型调用一条

一次运行实测可达上百次模型调用，合并成一条会丢失「哪一轮烧了多少」。任务级、密钥级的汇总作为纯函数另外提供。

### D5. 采集层零依赖，标签以字符串传入

事件记录层不导入配置读取模块、不导入创建层、不要求调用方传对象，只收一个 `str`（默认空）。这样需求方的「只在 event 内实现」与「不引入后端/配置依赖」同时成立；标签缺失时记录照常产出，只是归到空组。

### D6. 兼容性按「加默认值」处理

- 用量记录挂到运行记录上，新字段带默认值，既有构造点不受影响。
- 记录器的标签参数使用仅关键字参数且默认为空字符串。
- SOP 编排层的 `run_sop` 需要新增一个带默认值的标签参数，由命令行入口透传；这是唯一需要改签名的地方，因为编排层本来不知道用的是哪把密钥。

### D7. 缓存命中是输入的子集

汇总分别统计四项，任何两项之间不做相加。缓存命中已含在输入里，缓存写入单独一列。

## 模块防火墙自检

| 红线 | 本设计是否触碰 | 说明 |
| --- | --- | --- |
| 跨 App import（仅允只读 Model 与 `api.py`） | 否 | 不涉及 `backend/apps` |
| 跨 App import service/runner/consumer | 否 | 同上 |
| 写库收敛到各 App 的 `api.py` | 否 | 本期无任何写库 |
| 前端不直连数据库 | 否 | 不涉及前端 |
| `engines/` 零 `django.*` / `apps.*` | 否 | 采集层只用标准库；无网络调用 |
| 角色层「唯一创建出口」 | 是（返回值变更） | 不新增入口，只改既有出口的返回结构；已在 `agents/AGENTS.md` 登记 |
| 事件层五条红线 | 否 | 不引工具名、不改智能体、不写图片、不硬编码正则、不写死路径 |

新增的跨模块依赖只有一条：入口脚本 → 创建出口 → 事件记录层，方向单一，不产生反向依赖。

## Risks / Trade-offs

- **`create_model` 返回值变更** → 只有 `create_agent` 一个调用方，影响面被限制在一个函数内。
- **`create_agent` 返回值变更影响 4 个调用点** → 全仓无其它模块 import 本包；改完后用导入冒烟与命令行入口实跑验证。
- **丢失通道审计能力** → 明确记为 Non-Goal；将来要区分官方与网关时，需要同时加 `provider` / `base_url` 字段并重做汇总分组。
- **采集层依赖框架事件字段名** → 事件字段来自 AgentScope 的 `ModelCallEndEvent`，属外部契约；用「取不到给默认值」降级，并在测试里固定字段名。
- **首次为 ae_harness 建测试资产** → 新增测试目录需与既有 `tests/<模块>/<类型>/` 布局对齐。
- **时间锚点缺失时只有空时刻** → 记录里留空，不伪造；调用方按空串处理。

## Migration Plan

1. 先改模型与角色创建出口（返回两段），同步改 4 个入口解包。
2. 再在事件层落形状与采集，标签缺失时也能跑。
3. 历史产物（`logs/` 下两份旧记录）不迁移；新旧字段不同由消费方按「字段可缺省」处理。

回滚：把两处出口的返回值改回单实例，事件层新增字段带默认值，不阻塞回滚。
