## Purpose

让用户像新建助手一样登记一条 SOP：绑定两张助手名片，运行时读当前名片，并用里程碑 YAML 跑现有的执行加验收流程。

## ADDED Requirements

### Requirement: SOP 工作流只保存名称与两张名片引用

系统 SHALL 允许已登录用户创建一条 SOP 工作流。记录 MUST 保存非空名称、执行助手编号与验收助手编号。编号 MUST 是已存在的助手名片 `assistant_id`。系统 MUST NOT 把名片的显示名、系统提示词、模型连接参数或工具勾选复制进工作流记录。两张名片可以是同一张。任一编号不存在时，创建 MUST 拒绝并返回可读原因。

#### Scenario: 绑定两张已有名片

- **WHEN** 用户提交名称，以及两张已存在的助手名片编号
- **THEN** 系统创建工作流，记录只含名称与这两个编号

#### Scenario: 同一张名片同时担任两侧

- **WHEN** 用户把同一张助手名片同时选为执行助手与验收助手
- **THEN** 系统创建工作流

#### Scenario: 名片不存在时拒绝创建

- **WHEN** 执行助手或验收助手编号不对应任何名片
- **THEN** 系统拒绝创建，并说明哪一侧的名片不存在

### Requirement: 运行时现读当前名片

系统 SHALL 在每次启动该工作流时，按记录中的两个编号读取当时的助手名片及其引用的 Agent 配置。系统 MUST 使用当时的系统提示词、模型连接参数与工具勾选，MUST NOT 使用创建工作流时的副本。名片被改名、改提示词、改模型或改工具后，下一次运行 MUST 使用改后的内容。名片或其所引用的 Agent 配置不存在时，运行 MUST 失败，并且 MUST NOT 开始第一步。

#### Scenario: 改名片后下次运行使用新内容

- **WHEN** 工作流已绑定一张执行名片，用户随后修改该名片引用的系统提示词，再启动该工作流
- **THEN** 本次执行角色使用修改后的系统提示词

#### Scenario: 名片已删除时不开始步骤

- **WHEN** 工作流记录仍在，但执行名片或验收名片已被删除
- **THEN** 运行失败，详情说明缺失的一侧，且不产生步骤执行

#### Scenario: Agent 配置已删除时不开始步骤

- **WHEN** 名片仍在，但其引用的 Agent 配置已不存在
- **THEN** 运行失败，并且不开始第一步

### Requirement: 运行输入是里程碑 YAML

系统 SHALL 在启动该工作流时接收一份 YAML。顶层 MUST 含非空 `name` 与非空 `steps`。每一步 MUST 含非空 `subject` 与非空 `description`。`max_attempts` 缺省为 3，写出时 MUST 是正整数。`task` 与 `description` 可选。YAML MUST NOT 作为角色来源；其中出现的角色、模型或工具字段 MUST 被忽略，不得覆盖工作流绑定。用例格式（根节点为用例列表，或步骤使用 `action` 与 `assert`）MUST 被拒绝，并且 MUST NOT 进入执行。一次运行 MUST 只有一份该 YAML。

#### Scenario: 合法里程碑可以启动

- **WHEN** 用户提交一份含两个步骤的 YAML，每步都有非空 `subject` 与 `description`，且工作流绑定的两张名片都可解析
- **THEN** 系统按文件顺序执行这两步

#### Scenario: 用例格式被拒绝

- **WHEN** 用户提交的 YAML 用 `title`、`action`、`assert` 描述用例
- **THEN** 系统拒绝本次运行，并说明需要里程碑格式

#### Scenario: YAML 里的角色字段不生效

- **WHEN** 里程碑 YAML 另外写了执行者或验收者编号
- **THEN** 系统仍使用工作流表单绑定的两张名片

### Requirement: 整份流程只使用一对角色

一次运行 MUST 只装配一个执行角色实例与一个验收角色实例，并在全部步骤中复用这一对。系统 MUST NOT 为每一步新建角色，也 MUST NOT 让两侧共用同一个运行实例。执行角色 MUST 挂载执行名片当前勾选并经目录校验后的工具。验收角色 MUST 只挂载这些勾选与只读工具目录的交集。写操作工具即使出现在验收名片的勾选中，也 MUST NOT 挂到验收角色。未知工具名 MUST 使运行失败，并且 MUST NOT 开始第一步。

#### Scenario: 步骤之间复用同一对实例

- **WHEN** YAML 含两步，且第一步已经执行
- **THEN** 第二步仍由同一次运行里的那一个执行实例与那一个验收实例处理

#### Scenario: 验收侧丢掉写工具

- **WHEN** 验收名片勾选了只读工具和写操作工具
- **THEN** 验收角色只挂载其中的只读工具

#### Scenario: 未知工具名拒绝启动

- **WHEN** 执行名片的工具勾选含目录中不存在的名字
- **THEN** 运行失败，并且不开始第一步

### Requirement: 新入口不改变既有控制设备任务

本工作流 MUST 使用独立入口启动。既有控制设备任务 MUST 继续使用其现有步骤来源、角色装配与用例 YAML 校验。本变更 MUST NOT 要求控制设备任务改为里程碑 YAML，也 MUST NOT 把本工作流的名片绑定写入控制设备任务。

#### Scenario: 旧任务仍按原入口运行

- **WHEN** 用户按现有方式提交一条控制设备任务
- **THEN** 该任务不读取 SOP 工作流绑定，也不按里程碑 YAML 校验其配置附件

### Requirement: 设备不是本工作流的必填项

启动本工作流时，系统 MUST NOT 因设备序列号为空而拒绝运行。YAML MUST NOT 被要求携带设备序列号。

#### Scenario: 不选设备也可以启动

- **WHEN** 用户启动一条绑定合法、YAML 合法的工作流，且未提供设备序列号
- **THEN** 系统不因缺少设备而拒绝本次运行

### Requirement: 工作流可以由用户编辑与删除

系统 SHALL 允许用户编辑一条已有工作流。编辑 MUST 只改名称与两侧名片编号，并 MUST 沿用创建时的校验：名称非空、两侧名片都存在、两侧可以是同一张。校验失败时 MUST 拒绝并说明是哪一侧，且 MUST NOT 留下任何被改动的字段。系统 SHALL 允许删除一条工作流。删除 MUST 只删该工作流记录，MUST NOT 删除两张助手名片、它们引用的 Agent 配置，或任何历史任务。

#### Scenario: 改名后卡片同步

- **WHEN** 用户点某工作流卡片的「配置」，把名称改掉并保存
- **THEN** 同一张卡片显示新名称
- **AND** 记录里仍是原来的两个名片编号

#### Scenario: 换执行助手后按新名片运行

- **WHEN** 用户把执行助手换成另一张名片并保存，随后启动该工作流
- **THEN** 本次执行角色使用新名片的提示词、模型与工具勾选

#### Scenario: 编辑时名片不存在

- **WHEN** 用户提交的两侧名片中有一侧已在别处被删除
- **THEN** 保存被拒绝，并说明是哪一侧的名片不存在
- **AND** 工作流记录保持编辑前的名称与编号

#### Scenario: 删除工作流不动名片与任务

- **WHEN** 用户删除一条已经跑过任务的工作流
- **THEN** 该工作流记录消失
- **AND** 两张助手名片与历史任务仍然存在

### Requirement: 页面按助手在上、工作流在下分区呈现

助手入口页 SHALL 分成两个区块：助手区块 MUST 在上，工作流区块 MUST 在下。两个区块都 MUST 用卡片网格展示。工作流 MUST NOT 再以页内常驻表单呈现。两个区块之间 MUST 有一条分区虚线，并且两块之间的留白 MUST 大于同一区块内卡片之间的间距。工作流卡片 MUST 分三行显示工作流名称、执行者、验收者，其中工作流名称 MUST 是视觉上最重的一行。工作流卡片 MUST 采用便签卡形态：顶部一条半透明的该工作流笔色胶带、浅墨虚线外框；底部一排有三块同尺寸的元素——「配置」「任务」两枚动作 MUST 用不同底色区分，第三块 MUST 只是一块纯色占位，MUST NOT 承载交互或信息。工作流区块 MUST 提供「新建工作流」入口，新建 MUST 在弹窗内完成并保存到工作流记录。

#### Scenario: 打开页面先看到助手再看工作流

- **WHEN** 用户打开助手入口页
- **THEN** 助手卡片网格排在页面上方
- **AND** 工作流卡片网格排在其下方，两块之间有一条虚线
- **AND** 页面上没有常驻的工作流表单

#### Scenario: 工作流卡片是顶部带胶带的便签卡

- **WHEN** 用户查看工作流区块的卡片
- **THEN** 卡片顶部有一条半透明的笔色胶带，外框是浅墨虚线
- **AND** 卡片正文自上而下是工作流名称、`执行者：…`、`验收者：…` 三行

#### Scenario: 底部三块同尺寸、只有两枚可点

- **WHEN** 用户查看工作流卡片底部那一排
- **THEN** 「配置」「任务」与第三块占位块高度、宽度一致，前两块底色不同
- **AND** 第三块没有文字、不能点击、不进无障碍树

#### Scenario: 工作流为空时仍能新建

- **WHEN** 还没有任何工作流
- **THEN** 工作流区块显示空态与「新建工作流」入口
- **AND** 点该入口打开新建弹窗

#### Scenario: 没有助手时新建被拦住

- **WHEN** 平台上还没有任何助手名片，用户点「新建工作流」
- **THEN** 弹窗说明需要先新建助手
- **AND** 保存不可用

### Requirement: 工作流卡片只有配置与任务两个动作

每张工作流卡片 MUST 只有「配置」与「任务」两个动作，MUST NOT 提供第三个动作入口。点「配置」MUST 打开预填了该工作流字段的弹窗，MUST 支持改名、换两侧名片与删除。点「任务」MUST 打开本工作流的运行弹窗。两个动作 MUST NOT 混入卡片的信息字段，卡片 MUST NOT 显示工具清单、模型名或工作流编号。

#### Scenario: 卡片上只有两个按钮

- **WHEN** 用户查看任意一张工作流卡片
- **THEN** 卡片动作只有「配置」与「任务」

#### Scenario: 配置预填当前绑定

- **WHEN** 用户点某张卡片的「配置」
- **THEN** 弹窗里名称与两个助手下拉都是该工作流当前的值

#### Scenario: 任务由卡片带入工作流

- **WHEN** 用户点某张卡片的「任务」
- **THEN** 弹窗打开，并且不要求再选一次工作流

### Requirement: 运行弹窗只提交工作流编号、里程碑 YAML 与可选设备

运行弹窗 MUST 提供一份里程碑 YAML 与一台可为空的设备。未选择 YAML 时 MUST NOT 提交；未选设备 MUST NOT 阻止提交。设备 MUST 从设备管理的设备列表里下拉选择，MUST NOT 允许手填序列号，MUST NOT 在助手页另建一套设备数据。下拉取值口径 MUST 与新建任务一致：USB 设备取序列号，局域网设备取 `IP:端口`，只挂在无线调试别名上的记录 MUST NOT 出现在选项里。下拉 MUST 含一个「不指定设备」的空选项。设备列表取不到时 MUST 给出可读提示，并且 MUST 仍允许不选设备提交。提交 MUST 只带工作流编号、YAML 与（选了设备才带）设备地址，MUST NOT 带提示词、工具清单或角色编号。提交成功后弹窗 MUST 关闭，并 MUST 提示新任务编号。

#### Scenario: 没选 YAML 不能提交

- **WHEN** 用户打开任务弹窗但没有选择 YAML
- **THEN** 提交被拒绝并提示需要一份里程碑 YAML

#### Scenario: 设备从设备管理里选

- **WHEN** 用户打开任务弹窗
- **THEN** 设备字段是下拉框，选项来自设备管理当前列出的设备
- **AND** 没有可手填序列号的输入框

#### Scenario: 局域网设备提交 IP 与端口

- **WHEN** 用户在下拉里选中地址为 `192.168.35.57:39569` 的设备并提交
- **THEN** 请求体的设备字段为 `192.168.35.57:39569`

#### Scenario: 空设备可以提交

- **WHEN** 用户上传合法 YAML，设备保持「不指定设备」后点「开始运行」
- **THEN** 请求体只含工作流编号与 YAML
- **AND** 任务被创建

#### Scenario: 提交成功后关闭弹窗

- **WHEN** 任务提交成功
- **THEN** 弹窗关闭，页面提示新任务编号
