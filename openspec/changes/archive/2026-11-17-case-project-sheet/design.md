## Context

见 `proposal.md` 的 Why。现状：`CaseProject → CaseDirectory → CaseFile → TestDefinition + CaseStep`，功能与自动化只靠行上的 `case_type`。任务提交只接受里程碑 YAML，平台用例物化已随 `retire-engines-agents` 下线。工作流任务从助手页提交，任务清单不再提供新建入口。

## Goals / Non-Goals

**Goals:**

- 项目页只有一张表，分类靠个人视图。
- 两种库分表，旧目录、文件和用例行清空。
- 导入与 Agent 入库都是追加，并在同一事务里守住 999。
- 平台用例编译成里程碑后，仍走现有执行入口。

**Non-Goals:**

- 不恢复 `engines/agents` 的用例 YAML 模型。
- 不在任务清单页恢复新建按钮。
- 不做公式、泳道、甘特和多人同时编辑。
- 不改元素定位工作台。

## Decisions

### D1 项目锁类型，用例分两套表

`CaseProject` 增加不可改的 `library_kind`：`automation` 或 `functional`。自动化用例与步骤、功能用例与步骤各用自己的表。删除 `CaseDirectory`、`CaseFile`、`TestDefinition`、`CaseStep`。

备选：继续用一张用例表，只在项目上加类型。这不满足「两种用例的表分开」，也会让功能表读到执行提示字段。

### D2 旧数据只清空，不映射

迁移先删旧行，再删目录表和文件表。不保留旧编号，不做 `case_type` 拆分。回滚只能重建空表，不能找回已删行。

### D3 个人视图是一份服务端 JSON

每个用户每个项目一条视图：隐藏列、筛选、排序、分组。服务端只接受允许的字段名和枚举值，不执行任意查询。视图不影响其他用户，也不改变行的归属。

备选：只存浏览器本地。换浏览器会丢，与已确认口径不符。

### D4 导入整份成功或整份失败

导入认用例 YAML：顶层是用例列表或单条用例，每条要有非空标题和至少一步，每步要有动作与断言。可选字段缺省为 `P1`、`ANDROID`、家电。功能表遇到锚点或日志字段即整份拒绝。里程碑格式（顶层 `name` + `subject/description`）拒绝导入，并提示去任务里上传。

写入放在一个事务里，先锁项目再数行。现有行加新行超过 999 时整份回滚，并返回剩余条数。

### D5 编译留在用例模块，执行入口不分支

`task_list` 只通过 `case_manager.api` 读取并编译。编译结果必须能通过现有里程碑校验。顺序与所选行一致。每一步编译为一条里程碑步骤：`subject` 取「用例标题 · 第 N 步」，`description` 含动作与断言；自动化行的锚点和日志只写成可读提示，不新增里程碑字段。`max_attempts` 固定为 3。

备选：把编译放进 `engines/`。这是数据变换，不是 Agent 原语，放进去会让引擎反向了解用例表。

### D6 入口只改工作流任务弹窗

平台用例选择器加在当前工作流任务弹窗，不回到任务清单页头。选择器只有「自动化项目 → 用例」，没有文件层。上传里程碑仍不入库。

### D7 Agent 入库改为追加功能表

验收通过后，按用户取得或创建名为「AI 生成用例」的功能项目，把产物追加进去。不再创建用例文件。`case_import.path` 改为 `/cases/projects/{id}`，不再带 `file_id`。超过 999 时任务仍完成，导入状态为失败。

## 模块防火墙自检

- `task_list` 与 `dashboard` 只调用 `case_manager.api` 或只读 `CaseProject`。不引用 `case_manager` 的 views。
- 写库仍经各自 `api.py`。编译本身不写用例表。
- 前端不直连数据库。仪表盘只读统计，不在仪表盘写项目。
- 不新增 `engines` 对 `apps` 的依赖，不恢复 `engines/agents`。

## Risks / Trade-offs

- [清空不可恢复] → 迁移说明写明不回填；上线前由发布人确认当前库可丢。
- [编译后的里程碑比原步骤粗] → 动作和断言都进入 `description`，执行器仍只认里程碑字段；不在本变更里扩展 SOP 字段。
- [工作流弹窗与任务清单规格口径容易混] → 选择器只加在工作流弹窗，任务清单继续无新建入口。
- [999 并发追加] → 计数与写入放在同一事务，并锁项目行。

## Migration Plan

1. 新增库类型、两套用例表和视图表。
2. 删除旧用例、目录、文件数据及对应表。
3. 项目页改为单表；旧文件路由重定向到项目。
4. 工作流弹窗接入平台用例，后端编译后走原里程碑入口。
5. 回滚：反向迁移只重建空的旧表，不恢复已删数据。已导入的新行需单独导出后才能人工迁回。
