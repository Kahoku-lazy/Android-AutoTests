## Context

五个智能体接口已经接回 `backend/apps/ai_assistant/urls.py`：列表、详情、创建、更新、删除。写操作在 `views_drf.py` 里用 `is_superuser` 卡住。列表在 `api.filter_agents_for_user`：超管全量，其他人只看无主、超管拥有、自己拥有。

`create_agent` 会把创建者写成 `owner_id`。若只放宽写权限、不改可见性，运营建的智能体会挂在运营名下，普通用户的列表和任务发布都看不到。这和「统一管理、建完全员可见」相反。

入参 `AgentInputSerializer` 只有名称、头像、标签、描述。更新不改模型、任务类型、状态。

## Goals / Non-Goals

**Goals:**

- 运营和超管都能新建、修改、删除任意智能体。
- 任意登录用户看到同一份清单，并能用其中任意一条发任务。
- 运营栏有一个维护页，表单只有那四项。

**Non-Goals:**

- 不新建 `/api/ops/agents/`。
- 不开放模型、密钥、循环次数、任务类型。
- 不恢复已下线的 `/ai-assistant/agent/:id`。
- 不改导入工具箱、查看完整密钥的超管限制。
- 不按归属人做「只能改自己的」。

## Decisions

### D1 写权限改成 `is_operator`，路径不动

`create`、`update`、`delete` 三处 `is_superuser` 换成 `is_operator`。超管天然算运营，不必并列判断。

更新和删除仍先看记录在不在：不存在 404，存在但不是运营 403。不能先 403 再查库，否则不存在和没权限混在一起。

- 备选「运营栏再包一套 `/api/ops/agents/`」：任务清单已经调 `/api/ai/agents/`，两套写口会分叉，否。

### D2 列表与详情对登录用户全量返回

`filter_agents_for_user` 改为：有登录身份就返回原查询集，没有就空集。详情同一口径：记录在就 200，不在就 404，不再因为归属人返回 403。

这是可见性放宽，不是新接口。任务发布若仍通过这个列表取智能体，会自动看到运营新建的条目，不必再改发布弹窗的路径。

- 备选「创建时把 owner 写成某个超管」：能钻旧过滤规则，但智能体仍被当成某人的资产，下一次改归属又会漏，否。

### D3 创建时不写归属人

`create_agent` 的 `owner_id` 置空，不再用 `user_id`。`user_id` 参数可留着供日志，但不落库。这样即使有人暂时仍走旧过滤，新建记录也会被当成平台共享。

存量已有归属人的智能体靠 D2 变为全员可见，不写数据迁移去清空 `owner_id`。清空是展示字段清理，不是可见性所必需。

### D4 运营页只做这四项

侧栏「运营」下增加「智能体」，路由 `/ops/agents`，守卫与用户管理相同。页面是列表加抽屉：新建、编辑、删除。

删除走 `ElMessageBox`。确认文案写明级联删除该智能体下的任务。取消不发请求。

前端不拼第二套创建地址，HTTP 仍打 `/api/ai/agents/create|update|delete/`。

### D5 规格改写，不绕开

`admin-managed-shared-agent` 的「仅超管可写」和「按归属可见」在本变更的 delta 里改掉。实现与规格放在同一提交。

## 模块防火墙自检

| 检查项 | 结论 |
| --- | --- |
| 跨 App import | 运营页只经 HTTP 调 `/api/ai/agents/`，不 import `ai_assistant` 的 api 或 views |
| 写库收敛 | 创建、更新、删除仍只走 `ai_assistant.api` 的三个函数 |
| 依赖方向 | 不新增 `ops_console` → `ai_assistant` 的 Python 依赖 |
| 前端边界 | 智能体维护页的 HTTP 放在 `ops-console/api.ts`，不从页面里直接打 axios |
| engines | 零触碰 |

## Risks / Trade-offs

- [普通用户突然看到以前被归属过滤掉的智能体] → 这是本变更的目标，不是副作用。任务清单下拉会变多，不另做隐藏开关。
- [运营误删一条正在被任务使用的智能体] → 删除二次确认，文案写明级联删除任务。不做软删除。
- [存量 owner 仍有值，排障时误以为还按人隔离] → 列表响应不把 owner 当权限；文档写明可见性不再读 owner。本变更不清空旧 owner。
- [详情从 403 改成 404] → 仅对「记录不存在」成立。普通用户看已存在记录必须是 200，测试要覆盖这条，避免改过滤时把详情又收窄。

## 上线与回退

- 无迁移。上线即改三处权限、一处过滤、一处创建归属，加一个运营页。
- 回退：写权限改回 `is_superuser`，过滤改回按归属，创建恢复写 owner，撤掉运营栏入口。已创建且 owner 为空的智能体在回退后仍按「无主即共享」对登录用户可见，这是旧规则，不需要补数据。
