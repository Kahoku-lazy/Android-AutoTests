## Why

运营后台「新建模型」已按聊天 / 实时语音 / 语音合成三类建模，但厂商下拉仍固定列三家：切到实时语音或语音合成时还能选到只支持聊天的 deepseek、govee，保存后得到与该分类不匹配的配置；列表里也看不出每条配置属于哪一类。另外，实时语音与语音合成的模型是「一个模型一个音色」，名称却沿用了聊天的多行列表；语音合成不显示 API 地址，保存时又被地址校验拦住，实际存不进去。

## What Changes

- 建立「模型类型 → 支持的厂商」对应关系：聊天 = deepseek / dashscope / govee；实时语音 = dashscope；语音合成 = dashscope。
- 新建 / 编辑抽屉的厂商下拉只列当前分类支持的厂商；切换分类时若已选厂商不再受支持，自动切到该分类的默认厂商（聊天 → deepseek，实时语音 / 语音合成 → dashscope），并同步密钥环境变量。
- 若切换后已选厂商仍受支持，则保留用户当前选择，不强行重置。
- 打开历史配置时同样归一：模型类型与厂商不匹配的行，厂商落回该分类的默认厂商，不把不受支持的厂商回显到下拉里。
- 实时语音与语音合成只维护**一个模型名称**：不显示「+ 添加一行」与逐行「删除」；从聊天切到这两类时只保留第一行；保存时只提交一个模型名称。聊天仍保留多行与批量加载。
- 「音色」字段从「API 协议」下方移到「模型名称」下方。
- 语音合成不要求 API 地址：前端保存时跳过地址校验，服务端 `base_url` 允许空串（当前字段必填且不允许空，导致语音合成实际无法保存）。
- 模型配置表格在「模型名称」前新增「模型类型」列，显示聊天 / 实时语音 / 语音合成；旧数据缺该字段时按聊天显示。

**BREAKING**：无。

## 关联文档

无。`dev_docs/ARCH_PRD/PRD-平台总需求.md` 未覆盖运营模型配置页；本变更是该页表单默认值、单模型约束与列表展示的修正，不改变任务、用例、设备与计费链路。

## Capabilities

### New Capabilities

- `ops-model-config`: 运营模型配置页的三类模型与厂商支持关系、切换分类时的默认厂商与密钥同步、历史配置归一、单模型约束、音色位置、语音合成免地址与列表模型类型列。

### Modified Capabilities

（无。运营用户管理、智能体维护等既有能力不涉及模型配置页。）

## Impact

- 前端：`frontend/src/modules/ops-console/constants.ts`（厂商选项补支持分类、模型类型标签与列定义）、`model-configs.vue`（按分类过滤厂商、切换默认、单模型、音色位置、地址校验、列表列插槽）、`types.ts`（模型类型 DTO）；`frontend/tests/ops-console/` 增加映射、单模型与字段顺序用例。
- 后端：`backend/apps/ai_assistant/serializers.py` 的 `ModelConfigSerializer.base_url` 改为可空，并补语音合成创建 / 聊天空地址拒绝的接口用例。合法厂商集合、`model_kind` 取值与三类模型的实际调用链不变。
- 接口：仅放宽语音合成对 `base_url` 的要求；成功响应仍由全局 `EnvelopeJSONRenderer` 包成 `{status, data}`。
- 回退：恢复静态厂商列表、多行名称与旧字段顺序；`base_url` 的 `allow_blank` 可单独回退，已保存的语音合成配置不受影响。
