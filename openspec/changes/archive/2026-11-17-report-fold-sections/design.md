## Context

报告的渲染入口只有一个：`engines/ae_harness/event/render.py` 的 `HtmlReportRenderer`，输入是 `RunRecord`（由 `record.py` 从事件流攒出），输出一段自包含 HTML（内联 CSS/JS、base64 缩略图）。三个视图（报告 / 轨迹 / 事件）共用一套 `_CSS` 与一段 `_SCRIPT`。

现状（实测 2026-11-17 15:50 那份报告，`logs/agents/backend_bridge/20261117_155020/`）：

- 报告区结构是 `.phase` → `.phase-h`（`h3` + `N 次调用`）→ `.role-block`（`.role-label` 胶囊 + 卡片）→ `.card` → `.card-h`（序号 + 工具名 + 耗时）+ 正文。
- `.card-h` 已经有 `cursor: pointer`，`tip` 文案也写着「点卡片标题可收起」，但**没有任何脚本或 `onclick` 绑定**，纯装饰。
- 轨迹区的折叠是**两套状态源**：CSS 里 `.call-b { display: none }` / `.call.open .call-b { display: block }` 这两条规则没有任何元素用得上（标记里只有 `.trace-body`），全是死代码；真正显示的 `.trace-body` 没有作者样式，所以 103 条调用的详情**默认全部展开**；点击时 `toggleTrace()` 只切 `hidden` 属性，`aria-expanded` 恒定停在 `false`。表现就是「打开时已经全摊开、点一下反而收起、读屏器永远读到收起」。
- 报告本身约 12 MB，58 张截图缩略图全部内联，DOM 节点数固定。

## Goals / Non-Goals

**Goals:**

- 报告区三层（子目标 / 角色块 / 工具卡）各自折叠，默认全部收起，收起后标题行保留序号、工具名、耗时、调用次数等辨识信息。
- 折叠状态用 `aria-expanded` 表达，标题行鼠标与键盘（Enter / Space）都能切。
- 轨迹区调用行默认收起、点行展开 / 再点收起，`aria-expanded` 与视觉同步，并删掉死掉的 `.call-b` 规则。
- 只改视图层：`RunRecord` / `StepRecord`、JSONL 写入、用量与费用口径一律不动。

**Non-Goals:**

- 不做「全部展开 / 全部收起」批量按钮（需求方未提，先不加）。
- 不做折叠状态持久化（localStorage / URL 参数）——报告是静态快照，跨会话记忆会引入旧报告兼容问题。
- 不改缩略图体积、不改 `step_extras` 扩展点、不改三个视图的划分与页头。
- 不重写已经落盘的旧报告；要新样式就重新跑一轮。

## Decisions

**1. 标题行用真 `<button>`，状态用 class + `aria-expanded` 切换，不用原生 `<details>` / `<summary>`。**
标题行里要放 `h3`、序号方块、胶囊、耗时这类块级元素，`<summary>` 只允许短语内容，塞进去要么不合法要么被 UA 的 `::marker` 打乱；而且报告区外层卡片带微倾 `transform`，`<details>` 的展开盒在部分浏览器里会另起新格式化上下文，与现有 `rotate` + 硬阴影的层级冲突。
标题行拆成 `<button>` 而不是 `<div role="button">`：键盘 Enter / Space 由浏览器原生转成 click，不用自己写 `keydown`；子目标标题仍留在 `<h3>` 里（按钮只包标题文字），读屏器还能按标题跳转——若把 `role="button"` 直接压在 `h3` 上，标题语义会被吃掉。
备选：原生 `<details>`（无 JS 更稳）——否决，理由如上；且报告本来已经依赖脚本切视图。

**2. 三层默认收起，而不是默认展开到某一层。**
需求方的痛点是「内容太长不便于查看」，默认收起后首屏就是 5 条子目标 + 调用次数，正好是要看的结构。代价是最深一层要点三次；这个代价换来的是一屏能看完全局，值得。
备选：子目标收起、角色块与卡片展开——否决，展开一个分组仍是几十屏。

**3. 收起只切显示，不裁剪 DOM。**
截图、入参、结果始终在 HTML 里，收起只是不渲染可见盒子。这样同一份报告仍可被复制、搜索、打印，也不需要「展开后再异步生成」的新链路。
代价：体积没变小（12 MB 照旧）——这是已知取舍，见 Risks。

**4. 轨迹区与报告区共用一套「标题行 → 详情区」折叠写法，并删掉死规则。**
把 `.call-b` / `.call.open` 这两条没人用到的规则删掉，`.trace-body` 改成默认收起、由 `.call.is-open > .trace-body` 展开；`toggleTrace()` 这个只切 `hidden` 的旧函数一并删除，改成与报告区同一个 `toggleFold()`。根因不是少写一行 CSS，而是**两套状态源**（CSS 的死类 vs `hidden` 属性 + 从不更新的 `aria-expanded`）彼此不认；统一到单一状态源后不会再复发，默认状态也从「全摊开」变成「先收起」。
代价：轨迹页第一次要多点一下；换来的是 100 条调用不再是一面墙。

**5. 测试断言渲染出来的 HTML，而不是跑浏览器。**
仓库没有报告的前端 e2e，引入浏览器的成本远大于收益。渲染器是纯函数（`RunRecord` → `str`），用单元测试断言：三层挂点存在、默认 `aria-expanded="false"`、详情区初始带收起类、脚本里存在对应切换函数、轨迹行详情区不再被写死 `display:none`。这样能挡住「改样式顺手删掉挂点」这类回退，但挡不住样式本身好不好看——那部分靠人眼看重新生成的报告。

**5. 子目标序号用 SVG 描边笔画画，不用字体、不用位图。**
需求方给了手绘字母参考图（蜡笔质感 + 红蓝混色），字体字形太干净、位图又不能跟着主题色走。做法是：0-9 各一条单笔画路径（坐标系 20×30），用 `stroke` + 圆头圆角画出粗线，用 `feTurbulence` + `feDisplacementMap` 把边缘抖出毛边；颜色按需求方选定的方案**左位红、右位蓝**，用两份 `userSpaceOnUse` 线性渐变各自沿笔画从 `45%` 淡到 `30%`，类名直接挂在路径上（不靠 `nth-of-type` 定位），再叠一层更粗更淡的同路径当作蜡迹扩散。两位数字各歪 1.8°~2.6° 且方向相反，模拟手写不对齐。
渐变与滤镜只定义一次（放在 `#view-report` 顶部的一个 0×0 SVG 里），所以 100 个序号也只多 400 条 `path`，不重复 defs。
备选：字体渲染（干净、但偏离参考图）、每个序号一张小图（体积与时序都更差）、红→蓝整体渐变（蓝色在 15% 浓度下几乎看不见，已由需求方否决）——均不采用。

**6. 序号封顶在 99。**
需求方要求「最大值 99」。超过 99 个分组时按 `min(index, 99)` 显示，第 100 个起重复 `99`——序号的用途是「一眼定位第几个子目标」，三位数会把标题行撑歪，重复比溢出更可接受。

## 模块防火墙自检

- 不新增跨 App import，不碰 `apps.*` / `django.*`；改动只在 `engines/ae_harness/event/render.py`，仍满足 `engines/` 零反向依赖。
- 不涉及数据库读写，不新增接口，不改 `backend_bridge` 的落盘路径与用量上送。
- `event/` 的红线「禁止引用具体工具名」不受影响：折叠逻辑对工具名无感知，`step_extras` 扩展点保持原样。

## Risks / Trade-offs

- [报告体积仍是十几 MB，打开依旧慢] → 折叠只解决「看不清结构」，不解决体积；缩略图降质 / 外置图片是另一个变更，本次不碰。
- [默认全收起可能让只关心最后一张截图的读者多点两次] → 标题行保留序号 + 工具名 + 耗时，靠标题就能定位到目标卡片，再点一次即可看正文。
- [键盘事件与 `<div role="button">` 组合在部分读屏器上表现不一致] → 同时提供 `tabindex="0"` 与 Enter/Space 处理，并在视觉上给 `:focus-visible` 描边（复用既有规则）。
- [改 `_SCRIPT` 时容易和抽屉 `openDrawer` 的类名冲突] → 折叠只用 `is-open` 前缀类，与 `.open`（抽屉）区分开，避免互相影响。
