## Purpose

工作流运行弹窗的平台用例选择器：让用户在一个弹窗里看清每条用例属于用例管理里的哪个项目，并能按名称或编号快速找到、跨项目勾选，且随时看得回自己选了什么。

## ADDED Requirements

### Requirement: 运行弹窗分两栏呈现基本信息与用例选择

运行弹窗 SHALL 在宽度足够的屏幕（≥1024px）上分两栏：左栏 MUST 只放本次运行的基本信息（用例来源、设备、已选用例摘要），右栏 MUST 只放用例输入区（平台用例选择器或里程碑 YAML）。屏幕宽度不足 1024px 时 MUST 回退为单列，且回退后各字段仍 MUST 全部可见、无需在弹窗内滚动即可看到底部按钮。弹窗本体 MUST NOT 出现纵向滚动条；用例列表与项目栏各自 MUST 有固定视口并在其内部滚动。

#### Scenario: 宽屏两栏各司其职

- **WHEN** 用户在 1440px 宽窗口打开工作流任务弹窗
- **THEN** 左侧一列是用例来源、设备与已选摘要
- **AND** 右侧一列是用例选择器（项目栏 + 搜索 + 列表 + 计数）

#### Scenario: 窄屏回退单列且按钮可见

- **WHEN** 窗口宽度小于 1024px
- **THEN** 两栏自动变为单列
- **AND** 底部「取消」「开始运行」仍在弹窗可见范围内

#### Scenario: 弹窗本体不滚动

- **WHEN** 自动化项目与用例多到列表放不下
- **THEN** 只有用例列表与项目栏出现滚动
- **AND** 弹窗标题、设备字段与底部按钮不随列表滚动

### Requirement: 平台用例按项目分组并显示归属

平台用例来源下，选择器 MUST 展示项目维度：项目和「全部项目」入口 MUST 各自显示其用例条数；列表 MUST 按项目分组，每个分组 MUST 有段头写明项目名与条数，并 MUST 提供只选本组的「全选本项目」。每条用例 MUST 同时显示标题与用例编号。默认视图 MUST 是「全部项目」，即首屏就按项目分组列出全部自动化用例。

#### Scenario: 首屏按项目分组

- **WHEN** 用户打开弹窗，来源为平台用例且未做任何筛选
- **THEN** 列表按项目分段，每段段头写明项目名与条数
- **AND** 每条用例同时显示标题与编号

#### Scenario: 选中项目只留该项目的用例

- **WHEN** 用户在项目栏点某个项目
- **THEN** 列表只显示该项目下的用例
- **AND** 列表顶部写明当前项目名

#### Scenario: 分组全选与取消

- **WHEN** 用户点某个项目段头的「全选本项目」
- **THEN** 该项目当前列出的用例全部进入已选
- **AND** 再次点击同一按钮时该项目用例全部退出已选

#### Scenario: 空项目仍在项目栏

- **WHEN** 某个自动化项目下还没有用例
- **THEN** 项目栏仍列出该项目并标注 `0` 条
- **AND** 点它时列表显示该项目没有用例，而不是空白的列表

### Requirement: 按用例名或编号搜索

选择器 MUST 提供常驻搜索框，输入 MUST 同时匹配用例标题与用例编号，且匹配 MUST 忽略大小写与首尾空白。搜索在当前项目范围内生效；当其他项目也有命中时，MUST 给出含命中条数的提示，并 MUST 提供一键切到「全部项目」查看的动作。当前范围没有命中时 MUST 显示说明文案，并 MUST 提供清空搜索的动作，MUST NOT 只留一张空列表。

#### Scenario: 按编号搜索

- **WHEN** 用户输入 `H6810-02`
- **THEN** 列表只剩编号命中的用例
- **AND** 项目栏各项目的条数同步变成命中数

#### Scenario: 按名称片段搜索

- **WHEN** 用户输入 `h705`（小写）
- **THEN** 名称含该片段且忽略大小写的用例出现在列表中

#### Scenario: 命中在其他项目时给出提示

- **WHEN** 用户先选中项目 A，再搜索一个只在项目 B 命中的关键词
- **THEN** 提示写明「本项目没有命中，另有 N 条在 B 项目命中」
- **AND** 点提示里的动作后切到「全部项目」并显示这次搜索的结果

#### Scenario: 无命中时给出退路

- **WHEN** 搜索关键词在任何项目中都没有命中
- **THEN** 列表区显示「没有匹配」说明与清空搜索的入口
- **AND** 项目栏中命中为 0 的项目不可点

### Requirement: 已选跨项目保留并汇总

用户切换项目、或搜索后清空搜索时，已选 MUST 保留，MUST NOT 因切换项目而清空。面板头部 MUST 显示已选条数；左栏摘要 MUST 同时显示已选条数、覆盖的项目数与所选用例名（超出若干条时 MUST 给出「还有 N 条」）。选择器 MUST 提供清空全部已选的动作。切换用例来源时，MUST 按既有口径清空另一侧输入（平台用例与 YAML 互斥）。

#### Scenario: 切项目不清空已选

- **WHEN** 用户勾选项目 A 的 2 条用例，再切到项目 B 勾 1 条
- **THEN** 已选共 3 条
- **AND** 切回项目 A 时这 3 条仍处于选中态

#### Scenario: 摘要写明条数与项目数

- **WHEN** 用户勾选了来自 2 个项目的 3 条用例
- **THEN** 摘要显示「3 条 · 覆盖 2 个项目」
- **AND** 摘要列出这 3 条用例名

#### Scenario: 清空已选

- **WHEN** 用户点「清空」
- **THEN** 已选归零，面板头与摘要同步更新
- **AND** 提交按钮回到不可用并说明缺用例

#### Scenario: 切到 YAML 清空平台用例

- **WHEN** 用户已勾选若干平台用例，随后把来源切到本地 YAML
- **THEN** 平台用例已选被清空
- **AND** 摘要区不再显示平台用例条数

### Requirement: 缺项时提交不可用并写明缺哪一项

在平台用例来源下，「开始运行」MUST 在未勾选用例时不可用；在本地 YAML 来源下，MUST 在未选择 YAML 时不可用；两种来源下设备为空时 MUST 不可用。不可用时弹窗 MUST 以可见文字写明缺的是用例、YAML 还是设备，MUST NOT 只在点击后用报错告知。三项齐备时按钮 MUST 可用，并在同一位置写明已选条数。

#### Scenario: 未勾选用例时按钮不可用

- **WHEN** 用户打开弹窗且没有勾选任何用例
- **THEN** 「开始运行」不可用，并显示「还需勾选用例」

#### Scenario: 有勾选但没设备

- **WHEN** 用户勾选了 2 条用例、设备仍为空
- **THEN** 「开始运行」仍不可用，并显示「还需选择设备」

#### Scenario: 三项齐备后可提交

- **WHEN** 用户勾选了用例并选好设备
- **THEN** 「开始运行」可用，并在原位置显示「已选 N 条用例 · 可以开始」

#### Scenario: YAML 来源下的缺项提示

- **WHEN** 来源为本地 YAML 且尚未选择文件
- **THEN** 「开始运行」不可用，并显示「还需上传里程碑 YAML」

### Requirement: 选择器不改变提交内容

选择器新增的项目名、条数、已选摘要 MUST 只用于展示，MUST NOT 进入提交请求。提交 MUST 仍按既有口径发送工作流编号、设备地址与用例来源对应用例输入（平台来源发所选用例编号数组，YAML 来源发配置文件），MUST NOT 新增字段，MUST NOT 改变设备地址取值方式。

#### Scenario: 平台来源提交只带用例编号

- **WHEN** 用户勾选 2 条用例、选好设备后点「开始运行」
- **THEN** 请求里的用例字段只有这两条用例的编号
- **AND** 请求中没有项目名或条数字段

#### Scenario: YAML 来源不发送用例编号

- **WHEN** 用户以本地 YAML 来源提交
- **THEN** 请求里没有用例编号数组
- **AND** 设备地址仍按 USB 序列号或 `IP:端口` 发送
