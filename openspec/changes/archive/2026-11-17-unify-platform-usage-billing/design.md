## Context

见 proposal.md 的 Why。当前有两条计价路径：DeepSeek 名字走 `engines/backend_bridge/model_billing`，其它名字走 `usage_ledger/pricing.json`。任务收口在 `task_list/task_runner.py` 自行调用 `price_usage`，再用结束时刻整段计价。仪表盘读 `task_usage_hourly`。`record_run_usages`、`record_voice_event`、`add_usage_hourly` 都没有生产调用方。

约束：`engines/` 不写库、不依赖 Django。钱与配额口径的变更以本设计为准，实现时不得再引入第二套公式。

## Goals / Non-Goals

**Goals:**

- 一次调用一条账，仪表盘与任务清单只做汇总。
- 公式固定，基数可替换。
- 库存人民币 8 位；人民币 / 美元切换只改显示。

**Non-Goals:**

- 不删除 `task_usage_hourly`，不重算切换点之前的三套历史费用。
- 不把 Omni 的音频 token 与文本 token 拆开；试看阶段用一个可替换基数。
- 不改实验角色日志的 4 位 DeepSeek 展示。
- 不把 govee 网关的实际结算价自动发现出来；试看先用官方基数。

## Decisions

### 1. 账本是唯一写入点

平台任务、助手运行、语音与文字会话在模型调用结束时调用 `usage_ledger.api.record_usage`。幂等键保持「来源:执行 ID:轮次」。引擎只返回逐次用量字典，不计算平台费用。

备选：继续写小时表再由仪表盘聚合。否决，因为小时行没有单笔输入量，Grok 的 20 万门槛无法复算。

### 2. 公式与基数分离

公式只在 `usage_ledger` 实现一次：

```
未命中 = max(输入 - min(缓存命中, 输入), 0)
原币费用 = (未命中 × 输入价 + 缓存命中 × 缓存价 + 输出 × 输出价 + 字符 × 字符价) × 倍率
人民币 = 原币费用 × 该币种到人民币的汇率
```

基数表按模型名索引，至少含：原币种、输入价、缓存价、输出价、字符价、高峰倍率、长上下文门槛与高档三价、可选映射目标。选择器只做两件事：按调用起点判断是否高峰；按该笔输入 token 判断是否达到门槛。达到门槛时整笔使用高档价。

`deepseek-v4.1-flash` 的试看映射目标是 `deepseek-flash`。`grok-4.6` 与 `grok-4.7` 使用 xAI 官方美元价，门槛 200000。`qwen3.5-omni-plus-realtime` 试看使用北京音频价：输入 80 元 / 百万 token，输出 300 元 / 百万 token，无缓存折扣。替换这些数字不改公式。

备选：继续用厂商名分流。否决，因为 govee 网关下的 grok 会被收进 DeepSeek 分支并记成已计价 0 元。

### 3. 任务费用是账本缓存

任务收口删除 `_price_call_costs` 与 `_price_costs`。终态写入后，按 `execution_id` 对账本已计价行求和，回写任务费用列。未计价行不进和，并在任务结果里留下条数。清单接口继续返回数值，但语义改为该任务的平台费用，不再叫 DeepSeek 费用。

备选：清单继续读 `task.cost_total` 且由收口自行计价。否决，这是 0.91 元与按调用时刻重算不一致的来源。

### 4. 仪表盘只聚合账本

`ai_usage`、近 7 日曲线、今日逐小时全部改为按 `occurred_at` 聚合 `ai_usage_records`。费用合计排除 `unpriced`。副标题由「DeepSeek」改为「平台」。智能体用量卡不再作为账单组成部分。Voice 分类图继续只过滤 `source=voice`，但其 token 与费用也来自同一账本。

### 5. 币种切换在前端

接口始终返回人民币 8 位与一个展示汇率。前端按钮只做除法与单位替换，不发重算请求。快照保存原币种单价和入库汇率，便于事后核对，不用于二次折算。

展示汇率的试看值固定为 2026-11-17 中间价 6.7132，并在界面标明日期。后续更换展示汇率只影响显示，不影响库存。

### 6. 历史归档

切换上线时刻之前的 `task_usage_hourly` 与任务行费用不回填、不重算。仪表盘累计从账本全表读取，因此切换前已入账的 51.22 元仍在；小时表多出的约 109 元不并入。界面需能区分「账本累计」与「切换前小时表归档」，避免两数被当成同一笔账。

## 模块防火墙自检

- `dashboard` 只读 `usage_ledger` 的汇总函数与 `task_list` 的任务计数 Model，不写库。
- `task_list` 写任务费用仍走自己的 `api.py`；写账本只调用 `usage_ledger.api.record_usage`，不 import 其内部计价实现以外的写入。
- `usage_ledger` 不写任务表、不写小时表。
- `engines/backend_bridge` 不 import `backend.apps`，不新增 Django 依赖。
- 前端不直连数据库。币种切换不产生写请求。

## Risks / Trade-offs

- [Omni 试看价按音频，文本调用会被高估] → 快照标明「试看音频基数」；确认模态后再换基数，不改公式。
- [govee 官方价不等于网关扣款] → 界面标明「官方试看基数」；拿到网关价后只替换基数。
- [切换前账本缺行，累计小于真实历史] → 归档数单独展示，不自动补账。
- [入账失败会造成任务费用暂时为 0] → 收口不阻断；补写账本后按执行 ID 重新汇总。

## Migration Plan

1. 先让新调用入账并按新公式计价，仪表盘改读账本。
2. 任务收口改为汇总账本，停止自行计价。
3. 前端改副标题、未计价提示与币种按钮。
4. 回退时恢复仪表盘读取小时表、任务收口自行计价；已写入的新账本行保留，不删除。

## Open Questions

无。试看基数、展示汇率与「历史不回填」已在本设计定稿；后续只替换基数值。
