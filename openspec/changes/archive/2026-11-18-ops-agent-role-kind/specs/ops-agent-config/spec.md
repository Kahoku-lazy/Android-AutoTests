# ops-agent-config Delta

## ADDED Requirements

### Requirement: Agent 配置列表展示类型列

运营后台「Agent配置」列表 MUST 在「名称」列之后展示「类型」列，顺序为：名称 / 类型 / 模型配置 / 系统提示词 / 操作。

类型列 MUST 以标签（chip）呈现当前配置的类型中文名（执行者 / 验收者 / 规划者）；未分类的配置 MUST 显示「未分类」并以次要色文字呈现，MUST NOT 留空白单元格。类型列 MUST NOT 改变既有的分页口径（仍为本页前端每页 10 条切片），也 MUST NOT 改变提示词与模型参数的传递方式。

#### Scenario: 有类型时显示中文标签

- **WHEN** 列表里有一条类型为「验收者」的配置
- **THEN** 该行类型列显示「验收者」标签
- **AND** 该列位于名称列与模型配置列之间

#### Scenario: 未分类配置显示占位

- **WHEN** 列表里有一条没有类型的存量配置
- **THEN** 该行类型列显示「未分类」
- **AND** 该行其余列与分页行为不受影响

#### Scenario: 类型列不改变分页

- **WHEN** 接口返回 12 条配置且都带类型
- **THEN** 表格仍只显示 10 行，页码文案为「第 1 / 2 页 · 共 12 条」

### Requirement: 类型随配置保存与编辑

新建与编辑抽屉 MUST 提供类型单选（执行者 / 验收者 / 规划者），新建时 MUST 必选一项，未选时 MUST 阻止提交并给出可读提示。

保存时类型 MUST 与名称、模型配置、系统提示词一起提交给 `POST` / `PATCH /api/ai/roles/`；保存成功后列表 MUST 立即反映新类型，失败时 MUST 给出可读错误且 MUST NOT 把本地状态当成已保存。编辑存量未分类配置时，抽屉 MUST 预填为空并要求补齐。

#### Scenario: 新建选类型后列表回带

- **WHEN** 新建配置时选择「验收者」并保存
- **THEN** 保存请求带上该类型
- **AND** 列表该行类型列显示「验收者」

#### Scenario: 未选类型阻止提交

- **WHEN** 新建配置时未选择类型就点保存
- **THEN** 页面给出可读提示并且不发起保存请求

#### Scenario: 编辑可改类型

- **WHEN** 把一条「执行者」配置改为「规划者」并保存
- **THEN** 列表该行类型列变为「规划者」
- **AND** 名称、模型配置与系统提示词保持原值
