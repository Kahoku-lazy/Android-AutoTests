## REMOVED Requirements

### Requirement: 新建任务必须填写独立标题

**Reason**: 任务清单不再提供新建任务表单。工作流标题由工作流名称带入。
**Migration**: 从助手页工作流卡片提交任务。

### Requirement: 任务附件为 Word 或 PDF 并解析为 Markdown

**Reason**: 该附件规则只服务任务清单自己的新建入口。
**Migration**: 工作流任务提交一份里程碑 YAML；历史附件记录保持不变。

### Requirement: 新建任务设备下拉与设备管理列表同步

**Reason**: 任务清单新建弹窗退役后，不再需要弹窗内的设备轮询。
**Migration**: 设备选择改到助手页工作流运行弹窗，打开时读取设备管理列表。

## MODIFIED Requirements

### Requirement: 失败任务可克隆新建后重新执行

系统 SHALL 在任务清单中为失败或已中断的工作流记录提供「重新执行」。点击后 MUST 读取该任务的标题、目标、附件、设备地址与工作流绑定，创建一条新的工作流任务，并进入同一设备地址的排队调度。原任务 MUST 保持原编号、状态与结果不变。系统 MUST NOT 覆盖或重置原任务。

#### Scenario: 失败卡重新执行产生新任务

- **WHEN** 用户对一条失败的工作流记录点击「重新执行」
- **THEN** 系统创建新的工作流任务，设备地址与原任务相同
- **AND** 原失败记录仍在表格中且状态仍为失败

#### Scenario: 新任务出现在列表

- **WHEN** 重新执行成功，且该设备已有 running 任务
- **THEN** 新任务保持 pending
- **AND** 该设备没有 running 任务时，新任务可以变为 running

#### Scenario: 非失败任务不提供重新执行

- **WHEN** 记录状态不是失败或已中断
- **THEN** 行内不展示「重新执行」

### Requirement: 任务卡片展示当前助手名称并随改名同步

任务清单表格 MUST 展示工作流名称。工作流仍存在时 MUST 显示当前名称；工作流已删除时 MUST 显示该次运行记录中的执行者与验收者运行名。系统 MUST NOT 再把控制设备线路名称当作任务清单的助手列。

#### Scenario: 卡片显示线路助手名

- **WHEN** 用户查看一条仍关联现存工作流的记录
- **THEN** 工作流列显示该工作流的当前名称

#### Scenario: 改名后历史卡片同步

- **WHEN** 工作流记录已删除，但历史任务仍在
- **THEN** 工作流列显示该次运行保存的执行者与验收者运行名
