# Design: harness-adb-grid-ring-marker

## Context

现状与实测证据见 proposal「Why」。相关代码事实：`engines/ae_harness/tools/adb/tools.py` 里 `_grid_points` 生成候选点、`_annotate` 负责在缩放后的图上画标记、`_screenshot_with_points` 统一拼返回体；`_annotate` 目前有 25 点上限与固定的十字/圆圈分支。返回图长边固定压到 1024（1080×2340 → 473×1024），因此标记的像素尺寸只能按缩放后的画布计算。

## Goals / Non-Goals

**Goals**

- 让模型在一张 473×1024 的返回图上能指出「第几行第几列压中了目标」，并直接取到可点击的归一化坐标。
- 支持方形点阵：同一张图上横向与纵向的点间距可以不同。
- 默认参数下不改变任何既有行为与返回字段。

**Non-Goals**

- 不做局部放大、不做多轮自动收敛、不做 OCR/xpath 备选路径——那是调用方的决策，不是本工具职责。
- 不改截屏时机、分辨率与坐标换算口径；不引入像素坐标入参（红线 8）。
- 不新增工具，不调整 `build_adb_tools()` 的工具名单与只读分组。

## Decisions

### 1. 在既有 `adb_screenshot_grid` 上加参数，而不是新开一个工具

模型可见工具表越短越不容易选错；`adb_screenshot_grid` 与新增点阵工具语义高度重叠，并存会制造「两个近义工具选哪个」的新歧义。加参数且默认值等于旧行为，既向后兼容又能被同一条提示词覆盖。

*备选*：新增 `adb_screenshot_matrix`。否决理由：工具表从 16 涨到 17，`build_adb_readonly_tools()` 与目录文案都要跟着变，收益只是命名更直白。

### 2. 环点而非实心点

实测：实心点直径 6 px（画布）会盖住 7×11 px 的箭头笔画，无法确认是否命中；空心环（半径 3~4 px、描边 2 px）让目标从环心透出，判读从「猜」变成「看见」。

*备选*：半透明实心点。否决理由：110 alpha 在浅灰底上仍然糊住笔画，且不同底色上透明度表现不一致。

### 3. 环点阵用行列轴标注，不给每个点写序号

49 个点写 49 个序号必然叠字（实测 5×5 十字已经糊成一片）。轴标注只画 `2×N` 个数字，且全部落在点阵外沿，不占用候选区域。返回体带 `row` / `col`，模型读「第 4 行第 3 列」即可取到坐标，不必从图里数点。

*备选*：只标部分点（四角 + 中心）。否决理由：模型要插值推断中间点的编号，反而增加出错面。

### 4. `step_y = 0` 表示沿用 `step`

保持既有调用与默认渲染完全不变（`step_y` 缺省 0 → 取 `step`）。不用 `None`：`FunctionTool` 的 JSON schema 对可选数字以 0 表示「未设置」最稳，避免 `null` 在不同模型 provider 上被序列化成字符串。

*备选*：`step_y: float | None = None`。否决理由：schema 里 `anyOf` 会多一层，模型侧描述更难写清。

### 5. 圆环半径与字号由点间距推导

`radius = clamp(间距×0.3, 2, 9)`（画布像素），字号 `= clamp(横向间距×1.0, 8, 14)`。固定半径在 0.01 步长下会让相邻环相交，推导值能保证「环之间至少留一个描边的空隙」，同时保证环心可见。

### 6. `size` 由 `{3,5}` 放宽到 `{3,5,7}`

实测需要纵向跨一行以上搜索：7 行 × 0.01 步长 = 187 px 覆盖，5 行只有 94 px。放宽后仍保持奇数与小规模（≤49 点），不引入 9×9。

## Risks / Trade-offs

- [473 宽画布上轴标注字号约 9 px，压在深色底上会读不清] → 标注统一加白色描边（`stroke_width=1`），与既有十字序号同一手法。
- [7×7 环点在密集区域仍可能互相贴边] → 半径按间距收敛（×0.3），描边固定 2 px，保证不相交。
- [模型可能数错行列] → 返回体同时给 `row` / `col` 与 `nx` / `ny`，可交叉核对；且 `index` 仍在，三种索引互为校验。
- [放宽 `size` 到 7 会让旧的 5×5 提示词失效] → 旧提示词写的是 `size=3 或 5`，仍被接受，行为不变。
- [环点模式返回图信息量下降（没有逐点序号）] → 代价换可读性；调用方若需要逐点坐标，仍可从 `marks` 取。

## Migration Plan

无数据迁移。上线即生效；旧调用（不传 `marker` / `step_y`）走十字分支，渲染与返回字段不变。回滚：还原 `tools.py` 与模块文档两处，旧的提示词与调用方无需改动。
