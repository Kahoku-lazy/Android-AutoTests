## Context

报告当前由 `HtmlReportRenderer` 消费 `RunRecord`（`steps` / `events` / `spans` / `schemas`），而 `RunRecord` 是记录器在 `on_event` 里自研折叠的产物。日志侧已有对齐记录：`AlignedRun` 用官方 `Msg.append_event()` 把同一批事件折成 `replies[].msg`，助手对话与 UI 执行两条路径都已接上。

约束：
- 报告的视觉契约（三层折叠且默认收起、子目标手绘序号、字号三档、左栏默认三成可拖拽）在 `ae-harness-report-render` 里，不能因换数据源改动。
- 任务报告接口仍读记录器产出的 `.jsonl`，本变更不能让它断供。

## Goals / Non-Goals

**Goals:**

- 报告渲染改为消费对齐记录里每条回复的官方内容块，块顺序即渲染顺序。
- 五类内容块（思考 / 文本 / 工具调用 / 工具结果 / 提示）各有对应区块；未知块降级不丢弃。
- 用量与耗时取自记录本身，渲染期不再重算。
- 视觉契约与现有页面结构保持不变。

**Non-Goals:**

- 任务报告接口（`agent-task-flow-report`）的数据源切换。
- SOP / goal / team 三条路径接入对齐记录。
- 删除记录器、`.jsonl` 与旧渲染入口。
- 报告视觉改版（分区层级、配色、字号规则均不动）。

## Decisions

**D1：渲染入参改为对齐记录文档，而不是给 `RunRecord` 加字段。**
渲染只需要 `replies[].msg.content` 与 `summary`。若把 `msg` 塞进 `RunRecord`，等于让自研折叠继续当唯一入口，两套语义继续并行。备选「保留 `RunRecord` 但由它派生 `msg`」被否决：那样渲染仍然依赖自研折叠的正确性。

**D2：三层分区由现有视觉规则从块序列派生，不新增元信息。**
子目标分组取文本块里的阶段标记（`### 目标：…`），没有标记时退化为单组；角色块取该条回复的智能体名；工具卡由工具调用块与工具结果块配对而来。这样报告结构不变，只是数据来源从 `steps` 换成块序列。

**D3：工具卡配对用内容块的身份，不靠顺序。**
官方契约里工具结果块的 `id` 与工具调用块相同，配对以该 id 为准；并发多工具时不会错配。缺失结果块的调用单独成卡并标注「结果缺失」。

**D4：未知块类型降级为通用区块。**
标题取块类型名，正文放该块的 JSON 摘要（长字段截断）。不抛错、不丢块，避免一次框架新增块类型就整份报告失败。

**D5：用量取 `msg.usage`，耗时取运行汇总。**
两者缺失时页面显示「未知」，不在渲染期按步骤重算 token。这条同时挡住「报告数字与记录数字对不上」的老问题。

**D6：新增按对齐记录渲染的入口，旧入口保留一个版本。**
未接入对齐记录的路径（SOP / goal / team）继续走旧入口，行为不变；两条已接入的路径切到新入口。旧入口标记为过渡，由后续变更删除。备选「一次性切换全部路径」被否决：三条编排路径尚未产出对齐记录。

**D7：媒体按 URL 读取后内嵌 HTML，不在记录里内联 base64。**
记录里的图片是 `URLSource`（`file://` 或 `http`）。报告要保持单文件可分发的现状，因此在渲染时按 URL 读取并转 base64 内嵌，同时对单图设体积上限，超限时退化为「仅给路径」。

**D8：观测覆盖框架全部可观测位置，链路视图直接消费观测段，不从事件反推。**
框架提供 7 个中间件位置（`on_reply` / `on_reasoning` / `on_acting` / `on_model_call` / `on_compress_context` / `on_system_prompt`，包内另有 `on_check_permission`），观测中间件逐个接入，只读、原样透传。报告新增「链路」页签，按观测顺序渲染，而不是再用事件流拼一遍——事件流表达的是「产出」，观测表达的是「输入与判定」，两者不可互相替代。

**D9：状态快照放进推理观测，而不是单独开一条观测流。**
`agent.state` 的信息（上下文条数、计划任务、压缩摘要长度、权限模式）只在推理开始时采样一次，挂在 `reasoning` 观测的 `state` 字段里。这样链路顺序天然正确（快照就在那一轮），也避免额外的 5 秒级轮询或第二条时间线。

**D10：模型的输入能力以框架模型卡为准，不靠配置里手填。**
`create_model` 之前给 formatter 传的是默认 `input_types=["text/plain"]`，导致 `deepseek-flash`（模型卡声明支持 `image/jpeg|png|gif|webp`）的截图被格式化器静默丢弃——工具结果里的图片被换成一句「image file is returned and saved locally at: <本机路径>」，模型只看到文字路径，于是反复说“看不到图”。修法是：创建模型时用 `ChatModelBase.list_models()` 取同名模型卡的 `input_types` 传给 formatter，卡片没有声明时回落到 `text/plain`。备选「在角色配置里手填是否支持图片」被否决：那等于把框架已有的能力声明再抄一份，容易漂移。

**D11：对账放在观测侧，不改格式化器。**
只要通道丢图，观测就标注「框架 N 张 / 实际发送 M 张」，并用探测一次的 payload 摘要作证；不尝试修补第三方 formatter 的行为。这样第三方升级后行为变化也能被看见。

## 模块防火墙自检

- 改动只落在 `engines/ae_harness/event/`：不 import `backend.*` 或 `django.*`，不写库，不新增跨 App 依赖。
- 不新增自定义异常类；渲染失败按现有异常口径处理。
- 报告仍由引擎产出 HTML 文件，后端只按既有路径白名单读取，不新增接口。
- 未引入新的跨模块依赖，因此不涉及 `api.py` 收口问题。

## Risks / Trade-offs

- [新入口与旧入口并存，短期两套渲染] → 旧入口标注过渡，下一个变更删除；两套入口共用同一套区块组件，避免分叉。
- [阶段标记缺失导致分组退化] → 退化为单组并在标题标注「未分阶段」，不报错；SOP 场景后续用步骤元信息补齐。
- [工具结果块缺失导致配对失败] → 单独成卡并标注「结果缺失」，不隐藏这次调用。
- [对齐记录体积随事件数增长] → 渲染只读 `replies` / `observations` / `summary`，不读 `events`；记录侧可关闭事件段。
- [截图内嵌体积上限导致降级] → 超限时页面显示路径与尺寸，保留可追溯性。

## Migration Plan

1. 新增按对齐记录渲染的入口与块映射，旧入口保持不动。
2. 助手对话与 UI 执行两条路径切到新入口（它们已产出对齐记录）。
3. SOP / goal / team 继续用旧入口，产出与现在一致。
4. 回退：把两条路径切回旧入口即可，记录文件不受影响。
