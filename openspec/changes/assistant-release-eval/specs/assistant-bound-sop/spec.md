## MODIFIED Requirements

### Requirement: 运行时现读当前名片

系统 SHALL 在工作流任务开跑和重跑时读取该任务已记下的冻结版本，MUST NOT 读取两侧名片的当前内容。版本中的系统提示词、模型与工具勾选 MUST 作为本次两侧角色的运行内容。任务没有版本时 MUST 失败，且 MUST NOT 开始第一步。名片在任务记下版本后被修改、退回草稿或删除，MUST NOT 改变该任务的运行内容。

#### Scenario: 改名片后下次运行使用新内容

- **WHEN** 工作流发布后，作者修改执行名片的系统提示词并再次发布，用户随后提交一条新任务
- **THEN** 新任务使用新版本的系统提示词
- **AND** 发布前已记下旧版本的任务仍使用旧提示词

#### Scenario: 名片已删除时不开始步骤

- **WHEN** 任务已经记下版本，但其中一侧的运行内容在版本中缺失
- **THEN** 运行失败，详情说明缺失的一侧，且不产生步骤执行

#### Scenario: Agent 配置已删除时不开始步骤

- **WHEN** 任务所记版本无法解析出一侧的模型或提示词
- **THEN** 运行失败，并且不开始第一步

### Requirement: 页面按助手在上、工作流在下分区呈现

助手入口页 SHALL 分成两个区块：助手区块 MUST 在上，工作流区块 MUST 在下。两个区块都 MUST 用卡片网格展示。普通用户的两个区块 MUST 只展示已发布记录。作者与超级管理员 MUST 同时看见自己可见的草稿，并标明草稿。工作流 MUST NOT 再以页内常驻表单呈现。两个区块之间 MUST 有一条分区虚线。工作流卡片 MUST 显示名称，并按编排显示绑定：`sop` 与 `goal` 显示执行者与验收者，`team` 显示队长与成员数量。卡片 MUST 保持便签卡形态：顶部半透明笔色胶带、浅墨虚线外框，底部「配置」「任务」与一块不可交互的占位块。只有助手作者的工作流区块 MUST 提供「新建工作流」入口，新建时 MUST 先选择允许的编排与种类，并保存为草稿。

#### Scenario: 打开页面先看到助手再看工作流

- **WHEN** 用户打开助手入口页
- **THEN** 助手卡片网格排在页面上方
- **AND** 工作流卡片网格排在其下方，两块之间有一条虚线

#### Scenario: Team 卡片显示队长与成员数

- **WHEN** 用户查看一条含一名队长和三名成员的需求拆解工作流
- **THEN** 卡片显示队长名称与成员数量 3
- **AND** 不显示验收者

#### Scenario: 没有助手时新建被拦住

- **WHEN** 平台上还没有任何助手名片，助手作者点「新建工作流」
- **THEN** 弹窗说明需要先新建助手
- **AND** 保存不可用

#### Scenario: 普通用户看不到草稿

- **WHEN** 作者有一条草稿工作流，普通用户打开助手入口页
- **THEN** 该草稿不在工作流区块中
