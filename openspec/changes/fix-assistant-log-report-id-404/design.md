# Design: fix-assistant-log-report-id-404

## Context

`AssistantThreadLogFileView.get()` 的三步顺序是「线程存在 → 线程未在跑 → 换票」，而 `report_id` 的边界校验藏在第四步
`resolve_thread_report()` 里。非法 id 因此先撞 401，永不抵达边界校验；顺带把一次性 ticket 烧掉。

约束：只改顺序与复用点，不改错误码语义，不动 spec 文本。

## Goals / Non-Goals

**Goals**
- 非法 `report_id` → 404，且不消耗 ticket。
- 合法 id 的三种既有结果（401 无票 / 401 过期票 / 404 报告不存在）一字不改。
- 边界规则只有一处实现。

**Non-Goals**
- 不改 `assistant-log-ticket` 规格；不改换票接口本身；不引入新的错误码。

## Decisions

### D1 前移判定，而不是把换票改成可跳过
备选是「先换票失败也先解析路径」，那会让路径解析在未授权分支上跑，等于给未认证请求开一次文件系统访问。
前移纯字符串判定则零 I/O、零副作用，只在「这个 id 不可能是合法报告」时提前 404。选前移。

### D2 提取纯函数而不是在视图里复制一份规则
现有规则是两条（`Path(id).name == id`、非 `.`/`..`）。视图里再写一份就出现两个真相源，
后续任一处放宽都会留下绕过口。提取 `is_safe_report_id()` 供两处共用。

### D3 不改测试去迎合实现
把用例从 404 改成 401 是最省事的做法，但那等于放弃「非法编号必须 404」这条守卫，
并默认「非法请求可以烧票」这个副作用。拒绝。

## Risks / Trade-offs

- [404 与 401 的语义边界可能被误解为「不鉴权了」] → 只有**非法 id** 才提前 404；合法 id 无票依然是 401，用例 1.4 专门锁这条。
- [路径包含校验（`root not in folder.parents`）仍在后面] → 意图明确：前移的是**语法合法性**，不是**归属校验**；归属仍需要 thread 对象，无法在换票前完成。

## Migration Plan

纯代码顺序调整，无数据迁移。回退 = 还原两个文件。
