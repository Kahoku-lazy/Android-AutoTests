## ADDED Requirements

### Requirement: 异常收口也写逐次账与任务用量

运行内以失败结束的任务 MUST 与成功收口一样，把该次运行已经结束的模型调用写入逐次账（来源 `task`，执行 ID 为任务号），并按执行 ID 汇总回写任务的输入、输出、缓存命中 token 与逐项费用。回写 MUST 使用整次运行的累计值，MUST NOT 使用增量累加，重复收口 MUST NOT 让任务用量翻倍。逐次账写入失败 MUST NOT 阻止任务终态落库；此时任务用量与费用 MUST 保持可随后按执行 ID 补汇总。回写用量与费用 MUST NOT 改写任务状态、失败原因、失败步骤清单或已完成清单。进程退出导致的中断与用户主动取消不适用本条，按各自既有口径处理。

#### Scenario: 失败任务仍回写用量与费用

- **WHEN** 一次运行已完成 25 次模型调用，随后在交卷轮失败
- **THEN** 该任务的输入、输出与缓存命中 token 均大于 0
- **AND** 任务费用等于逐次账中该执行 ID 已计价行之和
- **AND** 逐次账中该执行 ID 的调用行数与实际调用次数一致

#### Scenario: 账本暂不可写不阻断失败收口

- **WHEN** 失败收口时逐次账暂时不可写
- **THEN** 任务仍以 `failed` 落库，失败原因与失败步骤清单保持不变
- **AND** 任务费用列保持可随后按执行 ID 补汇总

#### Scenario: 重复收口不重复计入

- **WHEN** 同一次失败运行的用量回写被触发两次
- **THEN** 逐次账中同一「执行 ID + 轮次」仍只有一行
- **AND** 任务费用仍等于逐次账之和，不翻倍
