## ADDED Requirements

### Requirement: 写库失败不丢待写行

事件写入失败时，待写行 MUST 保留并在下一次写入时重试，MUST NOT 在失败后直接丢弃整批。逐行降级仍然失败的行 MUST 保留到任务结束再尝试一次；只有任务收尾时仍写不进去的行才允许丢弃，并 MUST 留下可检索的告警。

事件写入 MUST 在同步上下文执行。调用方处在事件循环里（异步上下文）时，MUST 通过线程转交执行，MUST NOT 直接访问 ORM；因此产生的 `SynchronousOnlyOperation` MUST NOT 造成任何事件丢失。

#### Scenario: 批量写入失败后重试成功

- **WHEN** 某一批 50 条事件写入失败（连接抖动、上下文不合法等），随后恢复正常
- **THEN** 这批事件在下一次写入时被重试并最终入库，序号连续且不缺失

#### Scenario: 中断事件不因写库失败而消失

- **WHEN** 工作流在异步上下文里记录一条步骤中断事件
- **THEN** 该事件经线程转交写入成功，报告里能读到中断原因

#### Scenario: 收尾仍失败才丢弃

- **WHEN** 某几行到任务收尾时仍写不进去
- **THEN** 丢弃这几行并写一条告警，其余事件照常保留
