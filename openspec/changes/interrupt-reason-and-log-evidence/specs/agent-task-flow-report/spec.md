## ADDED Requirements

### Requirement: 步骤行标出中断类别与原因

报告 MUST 在步骤行给出中断标注，并区分**日志中断**（证据不可用：设备日志为空、未盖满 5 秒、采集断流等环境问题）与**异常中断**（执行层异常：工具或事件流抛出异常）两类。标注 MUST 带出具体原因（异常类型、原文、涉及的工具名；证据缺失时写明缺的是哪种证据），使用户在详情页即可判断「这一步为什么失败、该找谁」，无需翻后台日志。

被中断的步骤 MUST 显示为 `FAIL` 并同时带中断标注；MUST NOT 只显示一个无原因的 `FAIL`，也 MUST NOT 显示为「未完成」。用例级结论 MUST 为 `FAIL`，与步骤一致。

#### Scenario: 日志证据缺失的步骤

- **WHEN** 某步因日志窗口为空被中断
- **THEN** 该步显示 `FAIL` 与「日志中断」标注，悬停或展开可读到「证据不可用：日志为空」原文

#### Scenario: 工具异常导致的步骤

- **WHEN** 某步因工具抛出异常被中断
- **THEN** 该步显示 `FAIL` 与「异常中断」标注，原因里含异常类型与涉及的工具名

#### Scenario: 未中断的步骤不受影响

- **WHEN** 其他步骤正常给出判决
- **THEN** 这些步骤仍按 `PASS` / `FAIL` 显示，不出现中断标注
