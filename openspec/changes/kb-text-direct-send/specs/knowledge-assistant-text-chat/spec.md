## MODIFIED Requirements

### Requirement: 页面提供语音与文字两种会话方式

知识库助手页面 MUST 提供可见的「语音 / 文字」方式选择。语音方式 MUST 由用户点击启动按键后建立会话；文字方式 MUST 允许用户直接输入并发送，MUST NOT 要求先点击启动按键。文字方式首次发送时若尚未连接，前端 MUST 自动完成建连（含建连前的凭证续期），连接就绪后 MUST 立即把这条文本发出；连接建立前发出的文本 MUST 排队且不丢失。文字方式 MUST NOT 申请麦克风权限、MUST NOT 创建音频播放。一次会话只允许一种方式，切换方式 MUST 先结束当前会话再重新开始。文字方式下输入框 MUST 可发送（未连接时发送会自动建连），语音方式下 MUST 不可发送。

#### Scenario: 选择文字方式不申请麦克风

- **WHEN** 用户选择「文字」并发送第一条文本
- **THEN** 浏览器未弹出麦克风授权提示
- **AND** 未创建音频播放器，且连接携带 `mode=text`

#### Scenario: 文字方式直接发送无需先开始对话

- **WHEN** 用户选择「文字」后在输入框输入问题并回车（此时尚未建立连接）
- **THEN** 前端自动建立 `mode=text` 的连接，并在连接就绪后立即把这条文本发出
- **AND** 输入框 MUST NOT 因「未连接」而禁用

#### Scenario: 连接建立前的输入不丢失

- **WHEN** 用户在连接尚在建立时发送文本
- **THEN** 该文本在收到服务端 `ready` 后立即发出，不需要用户再次点击发送
- **AND** 同一条文本只发送一次

#### Scenario: 文字方式可发送、语音方式禁用输入

- **WHEN** 页面处于文字方式
- **THEN** 对话记录输入框可输入并发送
- **AND** 语音方式下同一输入框不可发送

#### Scenario: 切换方式需先结束会话

- **WHEN** 语音会话进行中用户选择「文字」
- **THEN** 页面提示先结束当前会话
- **AND** 已建立的连接方式不发生改变
