## Context

见 `proposal.md` 的 Why。当前工作流提交走独立的立即派发，不看设备地址；设备执行任务已经按可连接地址排队。任务清单页面仍以卡片和状态分组展示全部任务，并自带新建弹窗。

## Goals / Non-Goals

**Goals:**

- 工作流任务与设备执行任务共用同一设备槽。
- 任务清单只读展示工作流记录，并用设备管理同款表格承载筛选与操作。

**Non-Goals:**

- 不按 `workflow_id` 另建队列。
- 不合并同一手机的 USB 地址与 `IP:端口`。
- 不修改 SOP 步骤重试、失败汇总、仪表盘 `agent` 查询和重跑函数旧签名。
- 不改测试报告与 BUG 台账的数据范围。

## Decisions

1. **提交改入现有设备槽。** 工作流创建后调用 `dispatch_device(serial)`，删除 `dispatch_assistant_sop()`。备选是给工作流单独加锁；那会让同机的设备执行任务与工作流任务并行，违反目标。
2. **设备键沿用提交地址。** USB 用硬件序列号，局域网用 `IP:端口`，提交后不重新解析。备选是按硬件序列号合并；当前设备池没有稳定的双向映射，本次不引入。
3. **放行只留线程退出点。** 成功、失败、取消都等执行线程退出后调用 `dispatch_device()`。取消路径不提前放行，避免旧线程还在操作手机。
4. **删除后补派发。** `delete_task()` 删除带地址的 pending 或 running 记录后，再调用一次 `dispatch_device()`。清空仍是调试动作，不逐条补派发。
5. **排空只加日志。** `_DRAINING` 仍是进程内开关。派发被拒绝时记录任务编号和地址，不自动恢复，避免真正停机时放出新任务。
6. **列表接口增加筛选参数。** `GET /api/tasks/` 只返回 `assistant_sop`，接受 `workflow_id` 与 `status`。工作流名称由 `task_list` 经 `ai_assistant.api` 只读解析；工作流已删除时回退结果里的运行名。
7. **表格复用设备管理样式，不复制组件。** 使用共享 `AppTable`、`FilterTabs`、`usePagination` 与 `EmptyState`。任务清单作用域内把 `.sketch-sheet` 改成实线、无阴影，强调色用 `var(--c-ai)`。每页 5 行，表头带图标，行高 64px，外层横向拖拽。
8. **执行状态不进分类 tabs。** tabs 只放「全部」和现存工作流；状态下拉单独放在工具栏。暂停没有写入路径，不出现在筛选项。

## 模块防火墙自检

- `task_list` 只通过 `ai_assistant.api` 读取工作流名称，不 import 其 service 或 views。
- 任务创建、状态、删除和派发仍只写在 `task_list.api`。
- `backend_bridge` 不参与排队，不新增 Django 依赖。
- 前端只调用 `/api/tasks/*` 与现有工作流提交接口，不直连数据库。
- 仪表盘不新增写操作。

## Risks / Trade-offs

- [同一手机的 USB 与无线地址形成两条队列] → 接受。本次不新增设备身份合并。
- [停机被打断后进程继续服务，但排空开关仍为真] → 拒绝派发时写日志。不在本次自动复位。
- [重跑函数旧签名仍会在克隆时失败] → 明确排除。本次只改调度入口，不修该签名。
- [报告列表仍可能指向缺失的 `/tasks/:id`] → 本次去掉该跳转依赖；报告页的数据范围不改。

## Migration Plan

1. 先改后端调度与列表过滤，补同机、异机、空设备和删除补派发测试。
2. 再改助手页运行弹窗，去掉空设备。
3. 最后替换任务清单页面。回退时恢复旧页面入口，不需要数据迁移。
