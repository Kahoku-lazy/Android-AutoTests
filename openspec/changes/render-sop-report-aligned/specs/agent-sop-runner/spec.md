## MODIFIED Requirements

### Requirement: 运行时按角色实时写过程日志

SOP 运行时，执行者与验收者产生的思考、工具调用与工具返回 MUST 在产生的当下写入过程日志，MUST NOT 等整轮结束再写。每条记录 MUST 带角色名、模型名、阶段标识；阶段标识 MUST 包含当前步骤名与第几次尝试。日志开关与落点 MUST 沿用执行角色就绪时给出的开关与基路径；关闭时 MUST NOT 产生日志文件。

运行器 MUST 同时提供「逐事件」与「逐观测」两个可选出口，供调用方写对齐记录与原始事件流；出口接入与否 MUST NOT 改变运行结果与过程日志内容。

报告渲染 MUST 由调用方决定：运行器 MUST NOT 硬编码某一种渲染方式；调用方不接管时 MUST 保持既有四段式报告的产出，调用方接管时 MUST 不再重复产出该报告。

#### Scenario: 两个角色分别署名

- **WHEN** 一步的执行者与验收者各自产出思考
- **THEN** 过程日志里先出现执行角色名的记录，随后出现验收角色名的记录，两者可按角色名区分

#### Scenario: 阶段标识带步骤与尝试次数

- **WHEN** 流程推进到「启动应用」这一步的第 1 次尝试
- **THEN** 该步产生的每条记录都带「启动应用」与「第 1 次」

#### Scenario: 日志开关关闭时不落盘

- **WHEN** 执行角色就绪时未开启日志
- **THEN** 整个 SOP 运行结束后，对应日志文件不存在

#### Scenario: 事件与观测可被调用方接管

- **WHEN** 调用方接入逐事件与逐观测出口
- **THEN** 每个事件与每条观测都被投递一次
- **AND** 过程日志内容与未接入时一致

#### Scenario: 调用方接管报告渲染

- **WHEN** 调用方声明自己渲染报告
- **THEN** 运行器不再产出四段式报告
- **AND** 运行结果里的报告路径指向调用方渲染的文件
