## Context

- `DoodleNote.vue` 定义「胶带 / 便利贴」型条目卡：`variant`（`note` 等）、胶带装饰、虚线基类。全 `src` 零引用已由上一单三次核验（路径字符串匹配、模板标签、纯文本点名）。
- `frontend-l4-data-surface` 的 MUST 把它与 `AppCard` / `KpiCard` / `SketchCard` 并列为合法零件，这是它一直没被删的唯一理由。
- `doodle-craft` 技能反而把它当成现役组件：`SKILL.md` 的卡片清单、`cards.md` 的 §4 整节、`decorative.md` 的胶带行、`known-gaps.md` 的现役零件行、`tokens.md` 的 reduced-motion 降级清单、`assistant-marker-card.md` 的对比说明、`standalone-html.md` 的零件枚举都提到它，其中 `cards.md:7` 还把它的 `dashed` 列为「待迁移存量」。

## Goals / Non-Goals

**Goals:**

1. 规格不再列举一个零消费方的零件。
2. 组件与其唯一用例一并删除，不留「已备未用」的检索噪声。
3. `doodle-craft` 不再把已删组件写成现役零件（否则后来者按技能去 import 会失败）。

**Non-Goals:**

- 不删 `DoodleBtn`（按钮零件，与本组件无关，有 7 处使用）。
- 不重画 `AppCard` / `KpiCard` / `SketchCard`，也不改它们的 `dashed` 口径。
- 不做「用别的零件顶替被删组件的条目卡场景」——没有场景需要它，不做无对象的替代。

## Decisions

**D1：删组件，而不是保留为「设计系统备件」。**
上一单已论证：零引用 + 无规格点名 = 真死代码（D10）。本单把「规格点名」这个最后的挡箭牌按需求方裁决移除，判据即全部满足。备选：留作备件 → 否决，正是这类备件让「这个零件谁在用」永远要人工排除。

**D2：规格用 MODIFIED 只改枚举，不改需求主旨。**
需求的主旨是「可复用数据块必须走 shared 零件，不许自建私有卡壳」，它依然成立；删的只是列表里的一个已退役成员。两个场景都不提 `DoodleNote`，逐字保留。

**D3：`doodle-craft` 的同步采用「删除行」而非「标注已退役」。**
技能是给未来动作用的操作指引，不是变更日志；保留一行「已退役」只会让读者再去搜一个不存在的文件。历史留在本 change 与关单报告里即可。唯一例外是 `cards.md`：其 §4 是一整节，删除后需检查小节编号连续性（§4 → §5…）。

**D4：`cards.md:7` 的「待迁移存量」名单里删掉 `DoodleNote` 基类虚线这一项。**
该项描述的是「DoodleNote 基类虚线应下沉到 AgentRouteCard 自持」，组件删了自然失效；其余存量项不受影响。

## 模块防火墙自检

- **跨 App import**：不涉及。
- **禁跨层依赖**：本单只删文件与改文档，不新增任何 import。
- **写库收敛**：不涉及。
- **前端不直连数据库**：维持。
- **仪表盘只读**：不涉及。

## Risks / Trade-offs

- **[文档面变化大（7 处），漏改会让技能与代码再次分叉]** → tasks 第 3 组逐文件列出落点，关单时对 `DoodleNote` 做全仓文档复扫（`openspec/` 归档与历史审计除外）。
- **[删除用例后 shared 用例数下降被误读为覆盖率回归]** → 关单说明「删除的用例，其被测组件已删」。
- **[`cards.md` 小节编号断档]** → D3 要求删除后重排编号并检查目录/交叉引用。
