## REMOVED Requirements

### Requirement: 表格内容与当前生效的关键词表一致

**Reason**: 取值来源由「运行中的采集索引 / 配置文件」改为数据库关键词表，「文件更新时间」「文件缺失空态」等文件口径不再成立。
**Migration**: 由新需求「表格内容与数据库关键词表一致」承接；逐条列出、不遗漏不臆造、一词多功能点占多行、编号名称齐全、空态可读的口径保留，另新增范围字段要求。

### Requirement: 表格列与排序、搜索口径确定

**Reason**: 表格由恰三列改为四列（新增「范围」），并新增范围筛选；旧需求「恰为三列」与仅搜索的控件口径被取代。
**Migration**: 由新需求「表格列、范围筛选与搜索口径确定」承接；行序与登记一致、搜索忽略大小写包含匹配、计数恒报全量、无命中空态、清空回全量的口径原样保留。

## ADDED Requirements

### Requirement: 表格内容与数据库关键词表一致

表格 SHALL 逐个列出数据库关键词表里的关键词与其功能点，MUST NOT 遗漏、MUST NOT 臆造；同一个关键词对应多个功能点时 MUST 占多行（每行一个功能点），MUST NOT 被合并或漏掉；每个功能点 MUST 带编号与名称，并 MUST 带其范围。表格 MUST 同时给出取值来源（数据库）与表内最近一次写入时间，使「看到的就是当前登记的那张表」可核对。表为空或不可用时 MUST 给出可读的空态与原因，MUST NOT 空白、MUST NOT 报错中断。

#### Scenario: 一个关键词对应多个功能点占多行

- **WHEN** 某个关键词在关键词表里登记了多个功能点
- **THEN** 表格中该关键词出现多行，每行一个功能点，各自带模块名与功能点编号 / 名称

#### Scenario: 关键词一个不少

- **WHEN** 关键词表里登记了 N 个关键词
- **THEN** 表格上的关键词总数为 N，且逐行可查

#### Scenario: 取值来源如实标注

- **WHEN** 用户查看关键词表
- **THEN** 表格上方标注其取值来自数据库，并给出表内最近一次写入时间

#### Scenario: 表为空时给出可读空态

- **WHEN** 关键词表没有条目或不可用
- **THEN** 页面给出可读原因与空态，MUST NOT 呈现空白区域或错误页，也 MUST NOT 呈现空表格

### Requirement: 表格列、范围筛选与搜索口径确定

表格 MUST 恰为四列：**关键词 / 功能模块 / 功能点（编号 + 名称）/ 范围**。范围列 MUST 按口径渲染：通用范围显示「通用」，SKU 专用范围显示「<SKU>专用」（如「H6601专用」）。行序 MUST 与关键词表内登记顺序一致：关键词按登记先后、同一关键词的功能点按登记先后；前端 MUST NOT 重排或合并。搜索 SHALL 以忽略大小写的包含匹配同时作用于关键词、功能模块名与功能点名，命中即保留该行。表格 SHALL 提供范围筛选（全部 / 通用 / 各 SKU 专用），筛选 MUST 只保留所选范围的行；搜索与范围筛选 MUST 可叠加。搜索或筛选时 MUST NOT 改变表格列，也 MUST NOT 让计数缩水（计数恒报全量：关键词按原文去重、功能点按「模块 + 编号 + 名称」去重，范围不影响去重口径）；无命中时 MUST 给出可读空态；清空搜索与范围筛选后 MUST 回到全量。

#### Scenario: 四列固定

- **WHEN** 用户查看该表格
- **THEN** 表头恰为「关键词 / 功能模块 / 功能点 / 范围」四列

#### Scenario: 行序与登记顺序一致

- **WHEN** 关键词表里关键词与功能点的登记先后顺序固定
- **THEN** 表格行序与之逐行一致，前端不重排

#### Scenario: 按关键词搜索

- **WHEN** 用户输入某个关键词的一部分
- **THEN** 只保留命中该关键词的行，其余不显示

#### Scenario: 按功能点或模块搜索

- **WHEN** 用户输入某个功能点名称或模块名称的一部分
- **THEN** 命中该名称的行被保留

#### Scenario: 搜索时计数不缩水

- **WHEN** 用户输入任一搜索内容
- **THEN** 关键词数与功能点数仍为全量数值

#### Scenario: 无命中给空态

- **WHEN** 用户输入的内容在关键词表里没有任何匹配
- **THEN** 表格区展示可读的「没有匹配的关键词」空态，MUST NOT 呈现空白区域

#### Scenario: 清空搜索回到全量

- **WHEN** 用户清空搜索框
- **THEN** 表格恢复到全量并按既定行序排列

#### Scenario: 通用范围渲染

- **WHEN** 某行范围为通用
- **THEN** 范围列显示「通用」

#### Scenario: SKU 专用范围渲染

- **WHEN** 某行范围为 SKU H6601
- **THEN** 范围列显示「H6601专用」

#### Scenario: 按范围筛选

- **WHEN** 用户选择只看某一范围（如「H6601专用」或「通用」）
- **THEN** 只保留该范围的行，计数仍为全量数值
- **AND** 叠加搜索词时两个条件同时生效

#### Scenario: 清空范围筛选回到全量

- **WHEN** 用户把范围筛选恢复为「全部」
- **THEN** 表格恢复全量行，行序与配色不变

## MODIFIED Requirements

### Requirement: 表格只读且如实说明生效时机

该表格 MUST 为只读视图：MUST NOT 提供任何新增、编辑、删除、上传或保存关键词的操作，也 MUST NOT 提供任何写回接口；除「搜索」「范围筛选」与「刷新」外 MUST NOT 出现其它控件。条目取自数据库，页面刷新 MUST 取到表内最新条目，MUST NOT 要求重启平台才能看到新条目；页面 MUST 如实说明条目来源为数据库，MUST NOT 再呈现「改表后需重启平台才用于判定」的旧文案，也 MUST NOT 暗示页面可写回关键词表。

#### Scenario: 没有写操作

- **WHEN** 用户浏览该表格
- **THEN** 页面不出现新增 / 编辑 / 删除 / 上传 / 保存控件，也不发出任何写请求

#### Scenario: 如实说明生效时机

- **WHEN** 用户查看表格底部的来源说明
- **THEN** 说明标注取值来自数据库、刷新即取最新条目，不出现「改表后需重启平台」字样

#### Scenario: 刷新即见最新条目

- **WHEN** 关键词表新登记了条目，用户点击刷新
- **THEN** 表格展示最新条目，无需重启平台
