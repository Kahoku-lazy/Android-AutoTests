# admin-managed-shared-agent Specification

## Purpose
约定智能体由超级管理员统一配置并共享：创建、修改、删除、导入工具箱与查看完整密钥仅超级管理员可做，普通用户可以查看这些智能体并在其上继续自己的对话。

## Requirements

### Requirement: 超级管理员身份判定
平台 API MUST 能将 JWT 认证用户解析为平台真实用户，并 MUST 能判定其是否为超级管理员，供权限控制复用。

#### Scenario: 超级管理员访问 API
- **WHEN** 超级管理员携带有效 JWT 令牌访问受保护 API
- **THEN** 系统将其识别为超级管理员（`is_superuser` 为真）

#### Scenario: 普通用户访问 API
- **WHEN** 非超级管理员携带有效 JWT 令牌访问受保护 API
- **THEN** 系统将其识别为普通用户（`is_superuser` 为假）

### Requirement: 智能体配置仅超级管理员可写
系统 MUST 仅允许超级管理员创建、更新、删除智能体，以及导入工具箱项、查看完整 API Key。

#### Scenario: 普通用户创建智能体被拒
- **WHEN** 非超级管理员请求创建智能体
- **THEN** 系统返回 403 且不创建记录

#### Scenario: 普通用户修改智能体被拒
- **WHEN** 非超级管理员请求更新或删除智能体
- **THEN** 系统返回 403 且不修改记录

#### Scenario: 超级管理员配置智能体
- **WHEN** 超级管理员请求创建、更新或删除智能体
- **THEN** 系统允许执行该操作

### Requirement: 共享智能体对普通用户可见且可用
非超级管理员 SHALL 能查看超级管理员配置的智能体，并 MUST 能在其上创建和继续自己的对话。

#### Scenario: 普通用户查看共享智能体
- **WHEN** 非超级管理员请求智能体列表或详情
- **THEN** 系统返回超级管理员配置的共享智能体

#### Scenario: 普通用户在共享智能体上对话
- **WHEN** 非超级管理员在共享智能体上创建或继续对话
- **THEN** 系统允许该对话，且该对话归属于该用户

### Requirement: 共享智能体下数据隔离
在共享智能体对话中，工具调用 MUST 以发起对话的用户身份写库，SHALL NOT 以超级管理员身份跨用户写入。

#### Scenario: 普通用户经共享智能体写用例
- **WHEN** 非超级管理员在共享智能体对话中触发写操作（如保存用例）
- **THEN** 数据写入该用户名下，其他用户不可见该数据

### Requirement: 超级管理员对话审计
超级管理员 SHALL 能在 Django 后台查看所有用户的对话与消息记录，并 MUST 能按所属用户过滤或搜索。

#### Scenario: 超级管理员审计对话
- **WHEN** 超级管理员在 Django 后台打开对话或消息列表
- **THEN** 系统展示所有用户的记录，且可按所属用户过滤或搜索

### Requirement: 默认智能体随迁移种子化
平台 MUST 在数据库迁移执行时种下默认的**设备执行**智能体（`task_kind=device_control`），使任何全新环境在不依赖任何机器历史数据的前提下具备设备执行能力。种子 MUST 幂等：库中已存在任意设备执行智能体时 MUST NOT 新增记录。

#### Scenario: 全新数据库迁移后具备两类默认智能体
- **WHEN** 在一个空数据库上按顺序执行全部迁移
- **THEN** 库中同时存在设备执行与用例编写两个默认智能体
- **AND** 两者的 `task_kind` 分别为 `device_control` 与 `case_authoring`

#### Scenario: 已有设备执行智能体的库不重复种子
- **WHEN** 库中已存在任意 `task_kind=device_control` 的智能体
- **THEN** 迁移 MUST NOT 新增设备执行智能体
- **AND** 既有智能体的名称、归属与配置 MUST 保持不变

#### Scenario: 迁移重放不产生重复记录
- **WHEN** 种子迁移被重复执行
- **THEN** 设备执行智能体的数量保持不变

### Requirement: 无主智能体视为平台共享
`owner_id` 为空的智能体 MUST 对所有已登录用户可见并可用于提交任务，使种子结果不依赖「迁移执行时是否已存在超级管理员」。写权限 MUST 保持原状：仅超级管理员可创建、修改、删除智能体。

#### Scenario: 普通用户可见无主智能体
- **WHEN** 非超级管理员请求智能体列表
- **THEN** 响应 MUST 包含 `owner_id` 为空的智能体

#### Scenario: 普通用户可在无主智能体上提交任务
- **WHEN** 非超级管理员使用无主智能体提交任务
- **THEN** 系统 MUST 允许提交，不得判为不可见或返回 403

#### Scenario: 无主不放开写权限
- **WHEN** 非超级管理员请求修改该无主智能体
- **THEN** 系统 MUST 返回 403 且不修改记录

### Requirement: 历史无主智能体回填归属
迁移 MUST 把 `owner_id` 为空的智能体回填为「执行迁移时已存在的第一个超级管理员」，并 MUST NOT 修改名称、`task_kind`、`route_configs` 等其他字段；库中不存在超级管理员时 MUST 保持为空并交由「无主即共享」规则兜底。

#### Scenario: 存在超级管理员时回填归属
- **WHEN** 执行迁移时库中已有超级管理员且存在无主智能体
- **THEN** 这些智能体的 `owner_id` MUST 变为该超级管理员的 id
- **AND** 其他字段 MUST 保持不变

#### Scenario: 无超级管理员时不阻塞迁移
- **WHEN** 执行迁移时库中尚无任何超级管理员
- **THEN** 迁移 MUST 正常完成
- **AND** 无主智能体 MUST 仍对全部登录用户可见可用
