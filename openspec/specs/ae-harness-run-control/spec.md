# ae-harness-run-control Specification

## Purpose
给 `engines/ae_harness` 三个运行时保障：模型调用失败可重试、一次运行有预算上限、长任务可取消。三者都以中间件形式挂载，默认不启用，不影响现状。

## Requirements

### Requirement: 模型调用重试

模型调用失败时 MUST 按错误类型判断是否值得重试：限流、超时、连接中断与服务端 5xx MUST 重试；请求本身有问题的错误（参数非法、鉴权失败、模型不存在）MUST NOT 重试。

重试 MUST 使用带抖动的指数退避，且重试次数与退避参数 MUST 可配置、MUST 有安全上限。

流式响应在**已产出内容之后**失败 MUST NOT 重放，避免把已显示的文本重复一遍；首块之前的失败 MUST 重试。

#### Scenario: 一次性故障被重试

- **WHEN** 第一次模型调用超时、第二次成功
- **THEN** 调用方拿到成功结果
- **AND** 调用方看不到中间失败

#### Scenario: 不可重试的错误立即上抛

- **WHEN** 模型调用因参数非法失败
- **THEN** 立即抛出原异常，不重试

#### Scenario: 流式已产出不重放

- **WHEN** 流式响应已经产出若干片段后失败
- **THEN** 直接把异常抛给调用方
- **AND** 不重新开始整段响应

### Requirement: 运行预算

一次运行 MUST 支持设置两个上限：模型调用次数与墙钟秒数；任一超限 MUST 中止运行并抛出可识别的预算异常。

预算 MUST 在每次模型调用前检查，MUST NOT 等整轮跑完才判定。

未设置上限时 MUST NOT 施加任何限制。

#### Scenario: 超次数即停

- **WHEN** 预算设为 1 次调用，而流程需要多次
- **THEN** 第二次调用前抛出预算异常
- **AND** 已完成的调用与事件照常保留

#### Scenario: 不设预算不受限

- **WHEN** 不传预算
- **THEN** 运行不受次数与时长限制

### Requirement: 取消

一次运行 MUST 支持外部取消：调用方置位取消令牌后，运行 MUST 在下一次模型调用前中止并抛出可识别的取消异常。

取消 MUST NOT 与预算异常混为一谈：两者 MUST 是不同的异常类型，便于调用方区分「用户主动停」与「预算耗尽」。

#### Scenario: 置位后尽快停

- **WHEN** 运行中把取消令牌置位
- **THEN** 下一次模型调用前抛出取消异常

#### Scenario: 异常类型可区分

- **WHEN** 分别触发预算耗尽与取消
- **THEN** 抛出的异常类型不同

### Requirement: 中间件准入扩为三类

中间件准入 MUST 从「只有只读观测」扩为三类，且三类 MUST 各有明确准入条款：

| 类别 | 允许做什么 | 典型 |
| --- | --- | --- |
| 只读观测 | 只看不改，记录或采样 | 上下文压缩、最终提示词 |
| 可靠性 | 在失败时重试同一动作，不改变动作本身 | 模型调用重试 |
| 运行控制 | 按上限或外部信号**中止**运行 | 预算、取消 |

**能力型中间件仍然禁止**：不得借中间件给角色加工具、记忆、知识库或新技能。

#### Scenario: 可靠性中间件不改动作

- **WHEN** 启用重试中间件
- **THEN** 被调用的仍是同一个动作
- **AND** 只是失败时再试一次

#### Scenario: 运行控制只能中止不能扩展

- **WHEN** 启用预算或取消中间件
- **THEN** 它们只会让运行提前结束
- **AND** 不会改变角色能力

### Requirement: 默认不启用

三个中间件 MUST 由调用方显式启用；未启用时 MUST 与现状完全一致。

#### Scenario: 不传就不挂

- **WHEN** 调用方只传观测中间件
- **THEN** 智能体的中间件列表与改造前相同
