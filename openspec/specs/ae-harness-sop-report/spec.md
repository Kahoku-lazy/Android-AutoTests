# ae-harness-sop-report Specification

## Purpose
让一次执行者 + 验收者的 SOP 运行，也产出与单角色执行器同等信息量的报告与记录：五页签报告、按步骤切分的阶段视图、两个角色各自的提示词与逐轮上下文、可单文件复现的对齐记录与逐事件原始流。它是「SOP 报告口径唯一」的契约，替代此前只画步骤与工具调用的四段式报告。

## Requirements

### Requirement: SOP 报告与单角色报告共用一套页签与视觉契约

SOP 报告 MUST 由与单角色执行器相同的渲染入口产出，页签 MUST 为「报告 / 概览 / 阶段 / 事件流 / 原始记录」五个，MUST NOT 出现第二套 SOP 专用渲染器。

视觉契约 MUST 沿用现有规则：三层分区默认收起、子目标带手绘序号、字号只有三档、左栏默认占三成且可拖可键盘调整。

#### Scenario: SOP 报告与单角色报告页签一致

- **WHEN** 打开一次 SOP 运行产出的 HTML
- **THEN** 页签为报告、概览、阶段、事件流、原始记录五个
- **AND** 页签名称与单角色报告的完全相同

#### Scenario: 不存在第二套渲染器

- **WHEN** 审查 SOP 报告的产出代码路径
- **THEN** SOP 与单角色调用同一个渲染入口
- **AND** 旧的四段式渲染只服务 goal / team 路径

### Requirement: 阶段按 SOP 步骤切分

「阶段」页签 MUST 以 SOP 步骤为单位切分：一张准备卡（两个角色的提示词与工具清单）→ 每步一张步骤卡 → 一张收尾卡。

步骤卡 MUST 显示步骤名、该步尝试次数、该步验证结论；验证未通过时 MUST 同时显示失败说明与期望结果。步骤边界 MUST 取自运行期步骤事件，MUST NOT 从回复文本里猜。

#### Scenario: 每步一张卡且带验证结论

- **WHEN** 一次 4 步的 SOP 运行结束并渲染报告
- **THEN** 阶段页签出现 4 张步骤卡
- **AND** 每张卡带该步的尝试次数与通过与否

#### Scenario: 失败步骤可定位原因

- **WHEN** 某一步验证未通过
- **THEN** 该步卡片显示验收者给出的失败说明
- **AND** 同时显示该步的期望结果

#### Scenario: 步骤边界不靠文本推断

- **WHEN** 执行者的回复里不含任何阶段标记
- **THEN** 阶段仍按运行期步骤事件切分
- **AND** 不出现「未分阶段」的退化分组

### Requirement: 两个角色在报告里各自成块

同一步骤内执行者与验收者的回复 MUST 各自成块，块头 MUST 标出角色（执行者 / 验收者）、角色名与所用模型；MUST NOT 把两个角色的内容合并成一段。

验收者的只读约束 MUST 在报告里可见：其工具清单 MUST 只含只读工具。

#### Scenario: 一步之内两个角色可分辨

- **WHEN** 第 2 步执行者与验收者各回复一次
- **THEN** 该步卡片里出现两个角色块
- **AND** 两个块分别标执行者与验收者，且模型名可见

#### Scenario: 验收者工具清单只读

- **WHEN** 展开验收者的准备信息
- **THEN** 其工具清单里没有设备写操作工具

### Requirement: SOP 观测与单角色观测同口径可见

SOP 报告 MUST 能看到与单角色执行器同口径的观测：两个角色各自的系统提示全文、每轮模型真实收到的消息（含图片数量与是否被通道丢弃）、模型调用与返回、工具调用入参与输出、上下文压缩判定。

MUST NOT 以「SOP 有步骤视图」为由省略上述任一项。

#### Scenario: 系统提示与逐轮上下文都可查

- **WHEN** 展开某一步的某一轮
- **THEN** 该轮可见模型请求、返回与工具执行
- **AND** 报告里可查到执行者与验收者各自完整的系统提示

#### Scenario: 图片投喂可核对

- **WHEN** 某轮模型请求携带截图
- **THEN** 该轮显示框架图片数与实际发送数
- **AND** 通道不支持时标注图片被丢弃

### Requirement: 报告可单文件复现且原始事件可定位

对齐记录 MUST 是自包含单文件：仅凭它 MUST 能重渲染出同一份报告，MUST NOT 需要回读过程日志；媒体 MUST 以旁路文件加 URL 保存，MUST NOT 内联进记录。

原始事件流 MUST 逐事件实时写入，MUST 能让排查者从一条对齐记录定位到对应原始事件。

#### Scenario: 单文件重渲染

- **WHEN** 只给一份 SOP 对齐记录重新渲染
- **THEN** 产出结构相同的报告
- **AND** 不需要过程日志或原始事件流参与

#### Scenario: 原始事件逐条可查

- **WHEN** 运行中打开原始事件流文件
- **THEN** 已产生的事件已经落盘（不等整轮结束）
- **AND** 每条事件可对应到对齐记录里的事件序号

### Requirement: 无步骤段的记录不受本次口径影响

对齐记录缺少步骤段时（单角色运行、`goal` / `team` 记录），阶段 MUST 仍按轮切分，报告结构与本次变更前一致。

#### Scenario: 单角色记录保持原样

- **WHEN** 渲染一份不含步骤段的对齐记录
- **THEN** 阶段按轮切分
- **AND** 不出现空的步骤卡或报错
