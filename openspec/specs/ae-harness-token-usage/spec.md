# ae-harness-token-usage Specification

## Purpose
让 `engines/ae_harness/` 的每一次模型调用都留下一条可归组的 token 用量记录：带密钥环境变量名、绝对时间与四类 token，使「这次花的 token 是哪把密钥的」在事后可以回答，并保证缓存命中不被重复计入。

## Requirements

### Requirement: 创建模型时交出密钥环境变量名

模型创建出口在返回模型实例的同时 MUST 交出本次使用的密钥环境变量名，使调用方无需再读配置文件即可知道「用了哪把密钥」。

交出的 MUST 只是环境变量名；密钥明文 MUST NOT 出现在返回结构、日志、异常消息或记录文件里。

#### Scenario: 创建时直接拿到密钥环境变量名

- **WHEN** 调用方以短名 `govee_chat_flash` 创建模型
- **THEN** 返回值同时给出模型实例与 `GOVEE_API_KEY`
- **AND** 返回值里不存在密钥明文

#### Scenario: 另一条配置给出另一把密钥名

- **WHEN** 调用方以短名 `deepseek_chat_flash` 创建模型
- **THEN** 返回值给出的环境变量名为 `DEEPSEEK_API_KEY`

### Requirement: 角色创建出口透传密钥环境变量名

角色创建出口 MUST 在返回可运行智能体的同时交出本次使用的密钥环境变量名，且 MUST NOT 因此新增第二种创建入口，也 MUST NOT 改变三个既有入参的含义。

#### Scenario: 创建智能体后拿到密钥名

- **WHEN** 调用方创建 `govee_chat_flash` 的智能体
- **THEN** 返回值的智能体可运行
- **AND** 同一返回值的密钥环境变量名为 `GOVEE_API_KEY`

### Requirement: 一次模型调用产生一条用量记录

每次模型调用结束 MUST 产生且只产生一条用量记录。同一次运行内的多次调用 MUST 各自成条，MUST NOT 被合并或加总。

用量记录 MUST 包含：密钥环境变量名、该调用在本次运行中的轮次、开始时刻、结束时刻，以及输入 token、输出 token、缓存命中 token、缓存写入 token。

不是模型调用结束的事件 MUST NOT 产生用量记录。

#### Scenario: 单次调用成一条记录

- **WHEN** 一次运行只发生一次模型调用，输入 1000、输出 200、缓存命中 400
- **THEN** 产出且仅产出一条用量记录
- **AND** 该记录的四类 token 依次为 1000、200、400、0

#### Scenario: 同一运行两次调用各自成条

- **WHEN** 同一次运行先后发生两次模型调用，用量分别为输入 10 / 输出 1 与输入 20 / 输出 2
- **THEN** 产出两条用量记录，分别携带这两组数字
- **AND** MUST NOT 产出输入 30、输出 3 的单条记录

#### Scenario: 增量与工具事件不产生记录

- **WHEN** 事件流里只有文本增量、思考增量、工具调用或工具结果事件
- **THEN** 不产生任何用量记录

### Requirement: 用量按密钥环境变量名归组

汇总 MUST 按密钥环境变量名归组，给出每组的发生次数与四类 token 合计。同一把密钥的多次调用 MUST 落在同一组；没有标签的记录 MUST 归到一个可识别的空组，MUST NOT 被丢弃。

#### Scenario: 同一把密钥的调用归到一组

- **WHEN** 一次运行里三次调用都用 `GOVEE_API_KEY`
- **THEN** 汇总给出该组 3 次调用与四类 token 合计

#### Scenario: 没有标签的记录不丢弃

- **WHEN** 用量记录的密钥环境变量名为空串
- **THEN** 该记录仍参与计数与合计，只是归到空标签组

### Requirement: 用量记录携带可还原的绝对时间

用量记录的开始与结束时刻 MUST 能还原为该调用在墙上时钟中的绝对时刻，精度不低于毫秒。运行起点未知时 MUST 留空，MUST NOT 用当前时间冒充。

#### Scenario: 按记录还原绝对时刻

- **WHEN** 一次运行有起始墙钟，某条用量记录的开始时刻为 `2026-11-13_18-51-05.822`
- **THEN** 该时刻可按毫秒解析，且不晚于本次运行的结束时刻

#### Scenario: 无起点时不伪造

- **WHEN** 记录器未拿到运行起始墙钟
- **THEN** 用量记录的开始与结束时刻均留空
- **AND** token 与轮次照常产出

### Requirement: 运行汇总携带密钥环境变量名

一次运行结束落盘的汇总 MUST 携带本次运行的密钥环境变量名，使事后审计不依赖内存对象。

#### Scenario: 跑完后从产物判断用了哪把密钥

- **WHEN** 一次运行结束并产出记录文件
- **THEN** 汇总条目里能看到密钥环境变量名
- **AND** 不读内存对象也能判定本次用的是哪把密钥

### Requirement: 缓存命中不重复计入总量

缓存命中 token MUST 视为输入 token 的子集。用量汇总 MUST NOT 把缓存命中与输入相加作为输入总量；缓存写入 token MUST 单独统计，MUST NOT 混入输入、输出或缓存命中任一项。

#### Scenario: 输入含缓存命中时的汇总

- **WHEN** 一次调用的输入为 2,494,048、其中缓存命中 2,014,592、输出为 32,462
- **THEN** 输入总量仍为 2,494,048，MUST NOT 变成 4,508,640
- **AND** 缓存写入单独列出，不进入输入、输出或缓存命中

### Requirement: 采集不引入后端依赖

采集与产出 MUST 限定在 `engines/ae_harness/` 的事件记录层完成。该层 MUST NOT 引入 Django、后端应用或任何网络调用；MUST NOT 读取密钥明文。

采集层 MUST 保持对同包内其它模块的零依赖：标签由创建层产出后以字符串形式传入，MUST NOT 由采集层自行读取配置文件或解析模型对象。

#### Scenario: 无后端环境也能采集

- **WHEN** 在未安装 Django、无数据库的环境中跑一次 ae_harness 任务
- **THEN** 用量记录照常产出
- **AND** 不出现任何后端或网络相关导入

#### Scenario: 采集层不自读配置

- **WHEN** 审查采集层的导入
- **THEN** 采集层不导入配置读取模块，也不导入创建层
- **AND** 标签只能是调用方传入的字符串

### Requirement: 既有入口行为保持不变

改造后 4 个既有可运行入口（执行角色、验收角色、SOP 命令行、SOP 编排）MUST 保持原有的命令行参数、控制台输出结构与产物目录布局。

#### Scenario: 命令行行为不变

- **WHEN** 以原有参数运行任一入口
- **THEN** 任务照常执行，产物仍落在 `logs/<时间戳>/` 下
- **AND** 控制台输出的字段与改造前一致
