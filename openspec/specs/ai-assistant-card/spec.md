# ai-assistant-card Specification

## Purpose

让登录用户把一条运营 Agent 配置收成一张可展示、可入库的助手名片，卡片只露出用户名称、头像和 Agent 配置名称。

## Requirements

### Requirement: 助手编号在创建当日生成且之后不变

系统 SHALL 在创建助手时生成编号，格式为服务器当地日期 `YYYYMMDD`、一个下划线、以及 3 位由数字与大写字母组成的随机后缀。该编号 MUST 在全部助手中唯一，且创建后 MUST NOT 因改名、换头像、换引用或改工具勾选而变化。生成 MUST 查重；当日可用后缀耗尽时创建 MUST 失败并返回可读错误，MUST NOT 写入重复编号。

#### Scenario: 新建助手得到当日编号

- **WHEN** 已登录用户在 2026-11-16 创建助手
- **THEN** 返回的编号匹配 `^20261116_[0-9A-Z]{3}$`
- **AND** 数据库中不存在另一个相同编号

#### Scenario: 修改名片不改变编号

- **WHEN** 用户修改该助手的显示名或头像
- **THEN** 编号与创建时相同

### Requirement: 名片只保存引用与展示字段

助手记录 MUST 保存显示名、可选头像、笔色、所引用运营 Agent 配置的标识，以及工具勾选。系统 MUST NOT 把该配置的系统提示词或模型连接参数复制进助手记录。显示名 MUST NOT 为空。引用的配置不存在时，创建与更新 MUST 拒绝。删除运营配置 MUST NOT 级联删除助手。

#### Scenario: 创建时不复制提示词

- **WHEN** 用户引用一条已有运营 Agent 配置并创建助手
- **THEN** 助手记录只保存该配置的标识
- **AND** 记录中没有该配置的系统提示词正文与模型密钥

#### Scenario: 引用不存在时拒绝

- **WHEN** 用户提交一个不存在的运营 Agent 配置标识
- **THEN** 创建失败并返回可读错误
- **AND** 不写入助手记录

### Requirement: 头像压缩后以 base64 单独下发

上传的头像 MUST 由服务端压成最长边不超过 128 像素的 JPEG，再以 base64 保存，且保存后的文本 MUST NOT 超过 12KB。超过该上限或无法解码的图片 MUST 拒绝，不得原样入库。未上传时头像为空。助手列表 MUST NOT 返回头像正文，只返回是否有头像；头像正文 MUST 经按编号的单独接口返回。

#### Scenario: 大图被压缩后可在卡片显示

- **WHEN** 用户上传一张长边大于 128 像素的图片
- **THEN** 入库的是压缩后的 base64
- **AND** 其文本长度不超过 12KB

#### Scenario: 列表不带头像正文

- **WHEN** 客户端请求助手列表
- **THEN** 每条记录含编号、显示名、笔色、是否有头像、所引用配置的名称
- **AND** 响应不含头像 base64

### Requirement: 卡片只显示三样信息

助手列表页的每张卡片 MUST 只显示用户定义的名称、头像或笔色圆、以及所引用运营 Agent 配置的名称。卡片 MUST NOT 显示工具清单、模型名、系统提示词或编号以外的运行参数。有头像时中间显示头像；无头像时中间圆使用该助手笔色的深到浅，圆内 MUST NOT 显示文字。

#### Scenario: 无头像卡片显示笔色圆

- **WHEN** 用户打开助手列表，某助手没有头像
- **THEN** 卡片中间是该助手笔色的渐变圆
- **AND** 信息字段只有用户名称、该圆、以及 Agent 配置名称
- **AND** 笔色图钉与「配置 / 对话」按钮可以出现，但不是信息字段

#### Scenario: 有头像卡片不显示笔色圆

- **WHEN** 某助手已有头像
- **THEN** 卡片中间显示该头像
- **AND** 不同时显示笔色圆

### Requirement: 卡片动作在卡内以手绘小按钮呈现

每张颜料片 MUST 在卡内提供「配置」与「对话」两个动作；草稿卡 MUST 在**同一动作行**内另有第三个动作「发布」，MUST NOT 另起一排或用分隔线把发布与前两个动作隔开。工作流便签卡底部一排为「配置」「任务」与第三个同尺寸元素：草稿态该位置是「发布」，已发布态是笔色占位块。这些动作 MUST NOT 混入三样展示信息（名称、头像或笔色圆、Agent 配置名称）。动作按钮 MUST 是卡内小号按钮（高度不超过 32px），使用虚线描边与笔色浅底 hover，并 MUST 提供可见的键盘焦点环。已发布卡 MUST NOT 显示「发布」动作。

#### Scenario: 卡片仍只展示三样信息

- **WHEN** 用户打开助手列表
- **THEN** 卡片正文只有名称、头像或笔色圆、Agent 配置名称
- **AND** 「配置」「对话」在视觉上是按钮而不是信息字段

#### Scenario: 草稿卡的三个动作在同一行

- **WHEN** 作者看到一张草稿助手卡
- **THEN** 同一动作行内依次是「配置」「对话」「发布」
- **AND** 「发布」位于卡片边框之内，不与该卡硬阴影重叠

#### Scenario: 草稿工作流的发布占住第三块

- **WHEN** 作者看到一张草稿工作流卡
- **THEN** 底部一排三块依次是「配置」「任务」「发布」
- **AND** 已发布工作流卡该位置是笔色占位块，没有「发布」

#### Scenario: 已发布卡没有发布动作

- **WHEN** 作者看到一张已发布助手卡或工作流卡
- **THEN** 卡内动作仍是「配置」与「对话」（工作流卡为「配置」与「任务」）
- **AND** 卡内没有「发布」

#### Scenario: 键盘可达

- **WHEN** 用户用 Tab 键在卡片间移动
- **THEN** 获得焦点的动作按钮出现 2px 焦点环
- **AND** 回车可触发该动作

### Requirement: 配置打开即预填，保存回写同一张名片

点击卡片的「配置」MUST 打开预填了该名片字段的表单（显示名、所引用配置、工具勾选、已有头像）。保存 MUST 使用 `PATCH /api/ai/assistants/{assistant_id}/` 回写，MUST NOT 新建另一张名片。编号与笔色 MUST NOT 因编辑而改变。头像 MUST 支持三种状态：保留原图（不带头像字段）、替换（上传新文件）、移除（`clear_avatar`）。移除头像后，卡片中间圆 MUST 回到该助手原来的笔色。

#### Scenario: 改名字后卡片同步

- **WHEN** 用户点某卡片的「配置」，把名称改掉并保存
- **THEN** 列表里同一张卡片的名称变为新值
- **AND** 该卡片的编号与笔色不变

#### Scenario: 移除头像回到笔色圆

- **WHEN** 用户在编辑弹窗里点「移除头像」并保存
- **THEN** 该卡片中间重新显示笔色渐变圆
- **AND** 笔色与创建时一致

### Requirement: 卡片的视觉顺序固定

卡片 MUST 自上而下为：上边沿中心的笔色图钉、头像或笔色圆、显示名、Agent 配置名。图钉 MUST 用该助手的笔色、MUST 居中跨在卡片上边沿，且 MUST NOT 承载信息或响应点击。笔色圆 MUST 排在显示名之上。

#### Scenario: 卡片上边沿有笔色图钉

- **WHEN** 用户打开助手列表
- **THEN** 每张卡片上边沿中心有一枚与该卡片同色的圆点
- **AND** 圆点下方是头像或笔色圆，再往下才是显示名

### Requirement: 配置表单以头像为第一个字段

配置表单 MUST 以头像为第一个字段，其后依次为名称、Agent 配置、工具域，以及选了工具域后才出现的预设。头像 MUST 是圆形预览（未选图时用笔色渐变圆），并 MUST 提供「选择图片」与「移除」两个动作。新建与编辑两种模式 MUST 共用这一顺序。

#### Scenario: 打开新建弹窗先看到头像

- **WHEN** 用户点「新建助手」
- **THEN** 弹窗里第一个字段是头像，圆内是该笔色的深到浅
- **AND** 名称字段排在头像之后

### Requirement: 卡片动作键按语义使用 20%→5% 渐变底

助手颜料片与工作流便签卡的动作键 MUST 以其语义色做**纵向渐变**底：助手卡「配置」= 蓝色（`--c-workflow`）、「对话」= 绿色（`--c-device`）、草稿卡「发布」= 青绿（`--c-case`）；工作流卡「配置」= 蓝色（`--c-workflow`）、「任务」= 紫色（`--c-element`）、草稿卡「发布」= 青绿（`--c-case`）。渐变两端 MUST 分别为该语义色的约 **20%** 与约 **5%** 混纸色。描边线型（1.5px 虚线）、圆角与硬影几何 MUST 保持不变。悬停 MUST NOT 把底色换回单色填充——只允许位移与硬影变化。

#### Scenario: 四种动作键的底色两两不同

- **WHEN** 打开 `/ai-assistant`
- **THEN** 助手卡「配置」与「对话」、工作流卡「配置」与「任务」四枚键的背景两两不同
- **AND** 每枚键的 `background-image` 都含 `linear-gradient`

#### Scenario: 发布键有自己的语义色

- **WHEN** 打开 `/ai-assistant` 并看到一张草稿卡
- **THEN** 「发布」键的渐变取自青绿（`--c-case`）
- **AND** 它的底色与前两个动作键不同

#### Scenario: 渐变浓度在 20% 与 5% 之间

- **WHEN** 读取任一动作键的渐变两端颜色
- **THEN** 顶端约为该语义色 20% 与纸色的混合、底端约为 5%
- **AND** 键的描边仍为 1.5px 虚线、圆角仍为近直角

#### Scenario: 悬停不破坏渐变

- **WHEN** 指针悬停任一动作键
- **THEN** 底色仍是渐变（不退回单色），仅出现位移与硬影

### Requirement: 名片写操作只允许助手作者

创建助手、修改名片和删除名片 MUST 只允许助手作者。运营身份本身 MUST NOT 再作为这三项的准入。不是作者的请求 MUST 返回 403，且 MUST NOT 新建、修改或删除记录。查看已发布名片与发起对话 MUST NOT 要求作者能力。

#### Scenario: 运营不能新建名片

- **WHEN** 属于运营组但不是助手作者的账号打开新建助手并提交合法内容
- **THEN** 系统返回 403
- **AND** 不产生名片

#### Scenario: 作者可以保存同一张名片

- **WHEN** 助手作者修改自己可见名片的显示名并保存
- **THEN** 同一张名片显示新名称
- **AND** 不新建第二张名片

### Requirement: 普通用户只看见已发布名片

助手列表对普通用户 MUST 只返回已发布名片。作者 MUST 能在同一列表看见自己的草稿，并且草稿 MUST 有可见标识。超级管理员 MUST 能看见全部草稿。普通用户请求草稿详情 MUST 返回 404。

同一可见性口径 MUST 覆盖所有按编号访问的旁路接口：草稿名片及其头像、对话栏列表与新建、对话栏详情/改名/发送/取消/删除、对话栏日志列表，对非作者 MUST 返回 404，MUST NOT 返回 403，MUST NOT 泄露草稿内容。已发布名片 MUST 对所有登录用户开放头像与对话。

#### Scenario: 列表按身份过滤草稿

- **WHEN** 平台同时有一条草稿助手和一条已发布助手
- **THEN** 普通用户只看到已发布助手
- **AND** 该草稿的作者能看到两条，且草稿有标识

#### Scenario: 草稿头像不外泄

- **WHEN** 普通用户请求草稿助手的头像
- **THEN** 系统返回 404
- **AND** 响应不含头像内容

#### Scenario: 草稿不能开新对话

- **WHEN** 普通用户对草稿助手请求新建对话栏
- **THEN** 系统返回 404
- **AND** 不创建对话栏

#### Scenario: 草稿的对话与日志不可读

- **WHEN** 普通用户用草稿助手的对话栏编号请求消息、日志列表、改名、发送、取消或删除
- **THEN** 系统返回 404
- **AND** 对话栏与其消息保持不变

#### Scenario: 已发布名片对所有人可对话

- **WHEN** 非作者对已发布助手的头像与对话栏发起请求
- **THEN** 请求正常成功

### Requirement: 草稿标识是独立胶囊

草稿卡 MUST 在卡片右上角显示独立的「草稿」标识，且该标识 MUST NOT 写进名称文本或名称元素内部。已发布卡 MUST NOT 显示该标识。

#### Scenario: 草稿标识与名称分离

- **WHEN** 作者看到一张草稿助手卡
- **THEN** 名称元素内只有该助手的显示名
- **AND** 卡片右上角另有一个「草稿」标识

#### Scenario: 已发布卡没有草稿标识

- **WHEN** 作者看到一张已发布助手卡
- **THEN** 卡片上没有「草稿」标识

### Requirement: 发布失败只影响该卡

对草稿卡发起发布而失败时，系统 MUST 只在该卡显示失败原因并保持列表其余部分可交互，MUST NOT 用整页错误态替换整块卡片列表。

#### Scenario: 工作流两侧名片未发布时只提示该卡

- **WHEN** 作者对一条草稿工作流卡点「发布」，而其一侧名片仍是草稿
- **THEN** 该卡显示失败原因
- **AND** 列表其余卡片仍在原处且可继续操作
- **AND** 卡片状态仍是草稿

#### Scenario: 发布成功刷新该卡

- **WHEN** 作者对草稿卡点「发布」且请求成功
- **THEN** 该卡的「发布」动作消失、草稿标识消失
- **AND** 列表不整页重载

### Requirement: 发布要求引用的 Agent 配置仍然存在

发布助手或发布工作流时，系统 MUST 校验其引用的 Agent 配置仍然存在。引用缺失时 MUST 拒绝发布并返回可读原因，MUST NOT 冻结一份空提示词或空模型的版本。

#### Scenario: 配置被删后发布被拒

- **WHEN** 名片引用的 Agent 配置已被删除，作者点发布
- **THEN** 系统返回 400 并说明 Agent 配置不存在
- **AND** 不产生新的发布版本
