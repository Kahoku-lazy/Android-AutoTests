# ai-device-action-dispatch Specification

## Purpose

让设备动作按目标系统分派，并把设备能力按「连接 / 信息查询 / 控制」三类固定下来：三端实现共用同一套方法名，调用方只用系统无关的动作类，当前支持 Android，为 iOS 与 Windows 预留选择位。

## Requirements

### Requirement: 系统声明与分派

设备动作层 SHALL 声明可选系统，取值恰为 `android` / `ios` / `windows`；按系统分派到对应的连接、信息查询、控制三类实现。当前 SHALL 只实现 Android；指定未实现的系统时 MUST 返回可读结论（说明该系统尚未实现并列出已实现系统），MUST NOT 抛崩溃、MUST NOT 静默落到 Android。

#### Scenario: 指定 Android 分派成功

- **WHEN** 调用方以 android 取用三类实现
- **THEN** 返回 Android 的连接、信息查询与控制实现类

#### Scenario: 指定未实现的系统

- **WHEN** 调用方以 ios 或 windows 取用实现
- **THEN** 得到可读结论（该系统尚未实现 + 已实现系统清单），且不产生任何设备副作用

### Requirement: 三端方法名必须统一

设备动作层 SHALL 用三份方法名契约（设备连接 / 设备信息查询 / 设备控制）固定各端实现的方法名；同一能力在三端 MUST 使用同一名称（例如图片点击一律 `click_img`），MUST NOT 出现同义别名（如 `click_image`）。各端实现 SHALL 继承对应契约，缺少任一方法即无法实例化。

#### Scenario: 契约固定方法名

- **WHEN** 检查三份方法名契约
- **THEN** 连接类含连接 / 断开 / 存活探测 / 重连；信息类含屏幕尺寸 / 前台应用 / 包名 / 已连接设备 / 层级；控制类含点击、长按、滑动、拖动、输入、按键、截图、应用启停

#### Scenario: 同义别名不合法

- **WHEN** 检查任一已实现系统的控制类
- **THEN** 契约里的方法名存在，同义别名不存在

#### Scenario: 缺方法无法实例化

- **WHEN** 某系统实现缺少契约里的抽象方法
- **THEN** 该实现类无法被实例化（契约强制）

### Requirement: 一个动作一个类，每种方式一个独立函数

设备动作层 SHALL 为每个动作提供一个类（点击 / 长按 / 滑动 / 拖动 / 输入 / 按键 / 截图 / 应用启停），每个类 MUST 天然兼容三端（只依赖控制契约），并 SHALL 支持多种方式，**每种方式 MUST 是独立的函数**。

#### Scenario: 点击的多种方式

- **WHEN** 调用点击动作
- **THEN** 坐标点击、元素点击（xpath / id / text）、图片点击分别是独立函数，且同一套调用对三端通用

#### Scenario: 元素未命中给可读结论

- **WHEN** 以元素方式点击或长按而目标不存在
- **THEN** 返回未命中结论，不产生误点

#### Scenario: 长按与滑动支持多种方式

- **WHEN** 调用长按或滑动动作
- **THEN** 长按支持坐标 / 元素 / 图片三种方式，滑动支持方向 / 坐标两种方式，各自独立函数

### Requirement: 设备能力三类归口

设备动作层 SHALL 把设备能力归为三类：**设备连接**（含无线连接）、**设备信息查询**（屏幕尺寸、包名、当前已连接设备列表、当前前台应用、层级）、**设备控制**（点击、长按、滑动、拖动、输入、按键、截图、应用启停）。信息查询类 MUST NOT 产生设备副作用。

#### Scenario: 连接类可用

- **WHEN** 调用方发起连接（USB 或无线地址）
- **THEN** 连接成功后三类能力均可继续调用

#### Scenario: 信息查询不产生副作用

- **WHEN** 调用方查询屏幕尺寸、包名、已连接设备列表、前台应用或层级
- **THEN** 返回对应信息，设备状态不变

#### Scenario: 控制类可用

- **WHEN** 调用方执行点击、长按、滑动、拖动、输入、按键、截图或应用启停
- **THEN** 对应动作在目标设备上生效
