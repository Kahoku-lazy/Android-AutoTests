# ai-device-prompts Specification

## Purpose
让管理员在 AI 工具箱查看并编辑设备控制三角色的系统提示词，以 Markdown 持久化到平台唯一智能体数据表，供后续任务装配读取。

## Requirements

### Requirement: 工具箱展示三角色系统提示词
系统 SHALL 在 AI 工具箱「工具来源」中提供「设备提示词」入口。选中后，右侧 MUST 展示规划、执行、验收三份系统提示词，且 MUST 将库中 Markdown 源码渲染为可读文档。该入口 MUST NOT 使用与业务工具 / Skill 相同的「交给助手」总闸；提示词始终参与设备任务装配，不由总闸关闭。

#### Scenario: 选中设备提示词来源
- **WHEN** 用户在工具箱左侧点击「设备提示词」
- **THEN** 右侧展示规划 / 执行 / 验收三份提示词，并以 Markdown 渲染正文（标题、列表、代码块可见）

#### Scenario: 非管理员只读
- **WHEN** 非超级管理员打开「设备提示词」
- **THEN** 可见渲染后的三份提示词，不可保存修改

### Requirement: 超级管理员可保存提示词
系统 SHALL 仅允许超级管理员更新三份系统提示词。保存成功后 MUST 立即持久化到平台唯一智能体记录。任一份保存内容去空白后为空时 MUST 拒绝写入并返回可读错误，MUST NOT 部分更新其余角色。

#### Scenario: 管理员保存三份提示词
- **WHEN** 超级管理员提交非空的规划 / 执行 / 验收 Markdown 文本
- **THEN** 三份均写入平台智能体记录，再次读取得到相同正文

#### Scenario: 空提示词拒绝保存
- **WHEN** 超级管理员提交的三份中任一份去空白后为空
- **THEN** 系统拒绝保存，数据库保持原值

#### Scenario: 非管理员保存被拒
- **WHEN** 非超级管理员请求更新设备提示词
- **THEN** 系统返回 403 且不修改记录

### Requirement: 登录用户可读取当前提示词
系统 SHALL 允许已登录用户读取平台唯一智能体当前三份系统提示词（Markdown 源码）。平台智能体不存在时 MUST 返回 404。

#### Scenario: 读取当前提示词
- **WHEN** 已登录用户请求设备提示词
- **THEN** 响应包含 planner / executor / verifier 三份正文

#### Scenario: 无平台智能体
- **WHEN** 系统中不存在平台唯一智能体
- **THEN** 读取返回 404

### Requirement: 自动存档保留最近三份

系统 SHALL 在每次提示词写库时（手工保存或退出编辑自动保存）为平台唯一智能体留存一份自动存档，内容为该次写入后的规划 / 执行 / 验收三份正文。同一智能体的自动存档 MUST 只保留最新三份；超出时 MUST 删除最旧的一份。自动淘汰 MUST NOT 影响永久存档。

#### Scenario: 连续四次保存只留最新三份

- **WHEN** 超级管理员连续保存四次设备提示词，且每次正文都不同
- **THEN** 该智能体的自动存档恰好为三份，且对应最新的三次写入
- **AND** 最早那一次的内容已不在自动存档中

#### Scenario: 自动淘汰不触碰永久存档

- **WHEN** 已存在一份永久存档，之后又连续保存四次触发自动淘汰
- **THEN** 永久存档的内容、创建时间与数量都不变

### Requirement: 手工保留一份永久存档

手工保存（点击「保存」）SHALL 在写库后创建该智能体唯一的永久存档。已存在永久存档时 MUST 覆盖它，MUST NOT 新增第二份。永久存档 MUST NOT 参与自动淘汰，MUST 只在此后被手工覆盖或手工删除时变动。

#### Scenario: 首次保存创建永久存档

- **WHEN** 该智能体还没有永久存档，超管确认保存
- **THEN** 产生一份永久存档，正文等于刚写入的三份提示词

#### Scenario: 再次保存覆盖同一份永久存档

- **WHEN** 已有永久存档，超管修改正文并再次确认保存
- **THEN** 永久存档数量仍为一份，正文为最新内容，更新时间被刷新

### Requirement: 保存前确认覆盖

点击「保存」时前端 MUST 先弹出确认，提示文案 MUST 为「此次保存会覆盖之前的备份记录，请确认是否覆盖保存」。用户取消时 MUST NOT 写库、MUST NOT 新增或改动任何存档；确认后 MUST 完成写库并覆盖永久存档。

#### Scenario: 取消确认不产生任何改动

- **WHEN** 超管修改正文后点「保存」，在确认框中取消
- **THEN** 数据库中的三份提示词保持原值
- **AND** 自动存档与永久存档的数量与内容都不变

#### Scenario: 确认后写库并覆盖永久存档

- **WHEN** 超管在确认框中确认
- **THEN** 三份提示词写入库，再次读取得到新正文
- **AND** 永久存档的内容同步为新的三份正文

### Requirement: 退出编辑自动保存

退出编辑（取消编辑、切换工具来源、或离开编辑态）时，若编辑内容与库中当前值不同，系统 MUST 自动写库并生成一份自动存档；内容相同 MUST NOT 写库、MUST NOT 留下存档。自动保存 MUST NOT 覆盖永久存档。

#### Scenario: 有改动退出编辑

- **WHEN** 超管在编辑态修改正文后直接退出编辑（取消或切换来源）
- **THEN** 修改被自动写库，并新增一份自动存档

#### Scenario: 无改动退出编辑

- **WHEN** 超管进入编辑态但未修改任何内容就退出
- **THEN** 不写库，也不新增自动存档

### Requirement: 从历史存档覆盖当前提示词

超级管理员 SHALL 能从历史存档中选一份，把其三份正文覆盖到当前提示词。覆盖前系统 MUST 先把当前提示词存为一份自动存档；该自动存档写入失败时 MUST 中止覆盖，且 MUST NOT 改动当前提示词。覆盖成功后当前提示词 MUST 等于所选存档正文，且被选中的存档 MUST 保留（MUST NOT 因被使用而删除）。

#### Scenario: 用自动存档覆盖当前提示词

- **WHEN** 超管选一份自动存档执行覆盖
- **THEN** 当前三份提示词变为该存档正文
- **AND** 覆盖前的提示词出现在自动存档中，自动存档数量仍不超过三份

#### Scenario: 用永久存档覆盖后永久存档仍在

- **WHEN** 超管选永久存档执行覆盖
- **THEN** 当前提示词变为该永久存档正文
- **AND** 永久存档本身内容与数量不变

### Requirement: 存档仅超级管理员可用

历史存档的列出、读取、覆盖与删除 MUST 仅超级管理员可用；非超级管理员的这些请求 MUST 返回 403 且 MUST NOT 改动任何数据。提示词正文的读取仍对已登录用户开放（保持不变）。

#### Scenario: 非超管访问历史被拒

- **WHEN** 非超级管理员请求历史存档列表或执行覆盖
- **THEN** 返回 403，且存档与当前提示词均不变

#### Scenario: 超管可列出存档

- **WHEN** 超级管理员请求历史存档列表
- **THEN** 返回自动存档（最多三份）与永久存档（最多一份），每项含类型与时间

### Requirement: 下拉头入口与历史抽屉

设备提示词三个角色下拉头的右上角 MUST 各提供属于该角色自己的编辑入口：未进入编辑时显示「编辑」，该角色处于编辑态时显示「保存」与「取消」。「查看历史记录」MUST 只在面板页头出现一次，MUST NOT 在每个角色下拉头重复出现。历史抽屉 MUST 列出自动存档与永久存档，每项 MUST 能预览三份正文；永久存档 MUST 提供删除入口且删除前 MUST 二次确认；自动存档 MUST NOT 提供手动删除入口。

#### Scenario: 下拉头可见入口

- **WHEN** 超级管理员打开设备提示词来源
- **THEN** 三个角色下拉头右上角各能看到该角色自己的「编辑」
- **AND** 面板页头能看到唯一的「查看历史记录」

#### Scenario: 编辑态入口切换

- **WHEN** 超管点击某个角色的「编辑」
- **THEN** 该角色下拉头右上角变为「保存」与「取消」
- **AND** 另外两个角色下拉头仍为「编辑」

#### Scenario: 抽屉预览与删除

- **WHEN** 超管打开历史抽屉
- **THEN** 列出自动存档与永久存档并可预览正文
- **AND** 可对永久存档发起删除（删除前有确认），自动存档没有删除入口

### Requirement: 每份提示词独立编辑与独立保存

系统 SHALL 让规划 / 执行 / 验收三份提示词的编辑态与草稿彼此独立：进入某一份编辑 MUST NOT 改变其余两份的展示与编辑态，也 MUST NOT 强制展开其余两份折叠面板；多份编辑态 MUST 允许并存。每份的「保存」MUST 只把该份草稿写入库，同一请求中其余两份 MUST 取当前已保存值，MUST NOT 携带其余份尚未保存的草稿。每份的「取消」MUST 只退出该份编辑态，MUST NOT 影响其余份的草稿与编辑态。

#### Scenario: 点一份的编辑不牵动其余两份

- **WHEN** 超管在设备提示词来源点击「规划」的「编辑」
- **THEN** 只有规划变为可输入的编辑框并展开
- **AND** 执行与验收仍为只读 Markdown 渲染，且保持各自原有的展开 / 折叠状态

#### Scenario: 同时编辑多份互不干扰

- **WHEN** 超管先后点击「规划」与「执行」的「编辑」
- **THEN** 两份同时处于编辑态，各自草稿互不覆盖
- **AND** 验收仍未进入编辑态

#### Scenario: 保存一份不带入另一份草稿

- **WHEN** 规划与执行同时处于编辑态，超管只点「规划」的「保存」并在确认框中确认
- **THEN** 库中规划为该份草稿正文
- **AND** 库中执行仍为该次编辑前的已保存值，执行未保存的草稿 MUST NOT 被写入

#### Scenario: 取消一份不影响另一份

- **WHEN** 规划与执行同时处于编辑态，超管点「执行」的「取消」
- **THEN** 执行退出编辑态；其草稿有改动时按既有规则自动落库并留一份自动档，无改动时不写库
- **AND** 规划仍在编辑态，其草稿保持用户已输入的内容，且 MUST NOT 被该次写库覆盖

### Requirement: 自动保存只覆盖处于编辑态且有改动的份

系统 SHALL 在退出编辑时按触发点处理：某一份点「取消」时只处理该份（该份有改动才写库）；切换工具来源或离开页面时，把当前仍处于编辑态且有改动的若干份与其余「已保存值」合并提交一次写库。每次写库 MUST 按既有规则留下一份自动存档。未处于编辑态的份、以及未被本次处理的其他编辑中份的草稿，MUST NOT 被写入库。没有任何编辑中改动时 MUST NOT 写库、MUST NOT 新增存档。

#### Scenario: 取消一份只处理该份

- **WHEN** 规划与执行同时处于编辑态且都被改动，超管点「执行」的「取消」
- **THEN** 写库一次，内容为执行的新正文加规划 / 验收的已保存值
- **AND** 规划仍在编辑态且其草稿保持用户已输入的内容（MUST NOT 被写库、MUST NOT 被重置）

#### Scenario: 切换来源只保存有改动的编辑中份

- **WHEN** 规划与执行同时处于编辑态且都被改动，超管切换到其它工具来源
- **THEN** 一次写库提交规划与执行的新正文，验收取已保存值
- **AND** 只新增一份自动存档，永久存档不变

#### Scenario: 无改动退出不写库

- **WHEN** 超管进入某一份编辑态但未修改任何内容就点「取消」
- **THEN** 不写库，也不新增自动存档
