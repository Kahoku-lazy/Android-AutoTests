# assistant-release Specification

## Purpose
让助手和工作流先以草稿存在，只有发布时冻结下来的那一版才能被别人使用，避免测过之后又改内容。

## Requirements

### Requirement: 助手与工作流有草稿和已发布两种状态

新建的助手与工作流 MUST 以草稿保存。草稿 MUST NOT 出现在其他用户的列表、详情、下拉或任务提交中。其他用户直接访问草稿 MUST 得到 404，MUST NOT 得到 403。作者 MUST 能看见自己的草稿和全部已发布记录。超级管理员 MUST 能看见全部草稿与已发布记录。

#### Scenario: 其他人看不到草稿

- **WHEN** 作者保存一条尚未发布的工作流，另一个普通用户请求工作流列表
- **THEN** 该工作流不在列表中

#### Scenario: 直接访问草稿不暴露存在

- **WHEN** 普通用户用草稿的编号请求详情
- **THEN** 系统返回 404

#### Scenario: 作者能看见自己的草稿

- **WHEN** 作者请求自己的助手列表
- **THEN** 列表同时含该作者的草稿和已发布助手

### Requirement: 只有运行内容变化才退回草稿

已发布记录在修改系统提示词、模型、工具勾选、工作流两侧名片、编排或种类时，MUST 在同一次保存中退回草稿，并作废原来的发布通过记录。只修改显示名、头像或笔色 MUST 保持已发布。退回后，其他用户 MUST 只继续看到退回前的已发布版本，直到新版本再次发布。

#### Scenario: 改工具后其他人仍用旧版本

- **WHEN** 作者修改已发布助手的工具勾选并保存
- **THEN** 该助手对作者显示为草稿
- **AND** 其他用户继续看到修改前的已发布内容

#### Scenario: 改显示名不退回

- **WHEN** 作者只修改已发布助手的显示名
- **THEN** 该助手保持已发布
- **AND** 其他用户看到新的显示名

### Requirement: 发布冻结当前运行内容

发布 MUST 生成一个新的不可变版本，并复制当时的运行内容。助手版本 MUST 含系统提示词、模型标识、模型名、厂商和工具勾选。工作流版本 MUST 含编排、种类，以及两侧助手当时的运行内容（系统提示词、模型标识、模型名、厂商、工具勾选与服务地址）。工作流版本 MUST 同时含两侧的运行身份：助手标识与运行名。运行名 MUST 取发布时的名片显示名；两侧显示名相同时，验收侧的运行名 MUST 带上助手标识后缀，与实时解析口径一致。版本 MUST NOT 含密钥明文。发布后再修改草稿 MUST NOT 改变已生成的版本。

#### Scenario: 发布后的修改不影响旧版本

- **WHEN** 作者发布工作流后，再修改执行助手的系统提示词
- **THEN** 已发布版本中的系统提示词保持发布当时的正文

#### Scenario: 草稿名片不能发布工作流

- **WHEN** 作者发布一条工作流，但其一侧名片没有已发布版本
- **THEN** 系统拒绝发布
- **AND** 不生成新版本

#### Scenario: 工作流版本带两侧运行身份

- **WHEN** 作者发布一条执行与验收名片都已发布的工作流
- **THEN** 该版本的执行侧与验收侧都能读回 `assistant_id`、`run_name` 与服务地址
- **AND** `run_name` 等于发布当时的名片显示名

#### Scenario: 两侧同名时验收侧带后缀

- **WHEN** 两侧名片的显示名相同，作者发布该工作流
- **THEN** 验收侧的 `run_name` 是「显示名-助手标识」
- **AND** 执行侧保持原显示名

### Requirement: 使用方读取冻结版本

新的助手对话 MUST 使用当前已发布版本。已经打开并发送过的对话栏 MUST 继续使用该栏首次发送时的内容。新提交的工作流任务 MUST 记下版本。开跑与重跑 MUST 读取该版本，MUST NOT 再读取名片的当前内容。已发布记录退回草稿后，已写下版本号的任务 MUST 仍按该版本跑完。

#### Scenario: 旧任务不跟随新发布

- **WHEN** 一条任务已经记下版本，作者之后发布了新版本
- **THEN** 该任务开跑和重跑仍使用原来的版本

#### Scenario: 旧对话栏不跟随新版本

- **WHEN** 一个对话栏已经发送过，作者之后发布助手的新版本
- **THEN** 该栏继续使用首次发送时的内容
- **AND** 新建的另一个栏使用新版本

### Requirement: 删除不得切断已有任务

已发布记录仍被尚未开跑的任务引用时，删除 MUST 被拒绝，并说明仍有任务。已经跑完的历史任务 MUST NOT 阻挡删除。删除 MUST NOT 删除历史任务、对话或对方名片。

#### Scenario: 有排队任务时不能删除

- **WHEN** 作者删除一条仍有未开跑任务的已发布工作流
- **THEN** 系统拒绝删除
- **AND** 工作流与那些任务都还在

#### Scenario: 历史任务不阻挡删除

- **WHEN** 作者删除一条只有已结束任务的已发布工作流
- **THEN** 工作流记录删除
- **AND** 已结束任务保持原结果

### Requirement: 同时编辑不得互相覆盖

同一条草稿被两个作者先后保存时，系统 MUST 只接受先保存的那一次。后保存的请求 MUST 失败，并要求先刷新。系统 MUST NOT 静默覆盖先保存的内容。

#### Scenario: 后保存的人被拒绝

- **WHEN** 两个作者同时打开同一条草稿，一人先保存成功，另一人仍提交打开时的内容
- **THEN** 后一个请求失败
- **AND** 记录保持先保存的内容

### Requirement: 上线时现有记录视为已发布

首次启用草稿与版本时，系统 MUST 把当时已存在的助手和工作流记为已发布，并按当时内容生成第一个版本。尚未开跑的任务 MUST 补上该版本。已经跑完的任务 MUST NOT 改变结果。补齐 MUST 可以重复执行，且 MUST NOT 为同一旧记录重复生成版本。

#### Scenario: 旧工作流在上线后仍可提交

- **WHEN** 草稿能力首次启用前已经存在一条工作流
- **THEN** 启用后普通用户仍能看见并提交它

#### Scenario: 重复迁移不产生第二个初始版本

- **WHEN** 补齐过程被再次执行
- **THEN** 每条旧记录仍只有一个初始版本

### Requirement: 历史工作流版本补齐运行身份字段

升级 MUST 以一次性数据修复补齐库中已有工作流版本的运行身份字段（`assistant_id`、`run_name`、服务地址），取值来自该工作流当时绑定的名片与模型配置。补齐 MUST 只填空缺，MUST NOT 覆盖版本里已有的值；MUST NOT 改动系统提示词、模型名、厂商、工具勾选与编排。补齐 MUST 可重复执行，重复执行 MUST NOT 产生第二次写入。补齐后，引用旧版本的历史任务 MUST 能按原版本解析出可执行的角色绑定，MUST NOT 只需重发新版本才能跑。

#### Scenario: 旧版本补齐后能被开跑读取

- **WHEN** 库中存在一条发布时代码未写运行身份字段的工作流版本
- **THEN** 升级补齐后，按该版本解析能得到带 `assistant_id` 与 `run_name` 的两侧绑定
- **AND** 引用该版本的任务开跑不再因缺字段失败

#### Scenario: 补齐不覆盖已有值与运行内容

- **WHEN** 某条版本里已有 `run_name`，且提示词与工具勾选与当前名片不同
- **THEN** 补齐保留原有 `run_name`、提示词、模型与工具，只补缺失的身份字段

#### Scenario: 重复执行不重复写

- **WHEN** 补齐过程被执行两次
- **THEN** 第二次不产生新的字段变化，版本内容与第一次执行后一致
