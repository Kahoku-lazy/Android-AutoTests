# case-project-sheet Specification

## Purpose

把用例项目收成一张最多 999 行的表：创建时锁定自动化或功能，用个人视图代替目录和文件，并按字段追加导入 YAML。

## Requirements

### Requirement: 项目创建时锁定库类型

新建项目 MUST 选择且只能选择一种库类型：自动化或功能。创建成功后该类型 MUST NOT 可修改。项目列表 MUST 标出类型，并给出「已用条数 / 999」。系统 MUST NOT 提供新建目录、新建文件夹或新建用例文件的入口。

#### Scenario: 创建自动化项目

- **WHEN** 用户填写项目名称并选择自动化后创建
- **THEN** 新项目的库类型为自动化
- **AND** 项目页不出现目录树、文件夹或用例文件

#### Scenario: 创建后不能改类型

- **WHEN** 用户打开一个已创建的功能项目并尝试改为自动化
- **THEN** 系统拒绝修改
- **AND** 项目仍是功能库

### Requirement: 一个项目只有一张表且最多 999 行

每个项目 MUST 只有一张用例表，用例行 MUST 直接属于该项目。自动化项目与功能项目 MUST 使用各自的用例表，MUST NOT 把两种行放在同一张表。单个项目的用例行数 MUST NOT 超过 999。达到 999 后，新增行与导入 MUST 被拒绝，并说明已达上限。

#### Scenario: 第 1000 行被拒绝

- **WHEN** 一个项目已有 999 行，用户再新增一行
- **THEN** 系统拒绝保存并说明上限为 999
- **AND** 原有 999 行不变

#### Scenario: 两种库不混表

- **WHEN** 用户查看一个自动化项目的表
- **THEN** 表中只存在自动化用例
- **AND** 不存在功能用例行，也不存在可切换的类型列

### Requirement: 个人视图代替目录

项目表 MUST 提供隐藏列、筛选、排序和分组。这些设置构成该登录用户在该项目上的个人视图，MUST 保存在服务端。换浏览器后再次登录 MUST 读回同一视图。视图 MUST NOT 改变其他用户看到的行集合，也 MUST NOT 表现为可新建的目录或文件夹。

#### Scenario: 视图跟随用户

- **WHEN** 用户隐藏「模块」列并按优先级筛选后退出，再从另一浏览器登录打开同一项目
- **THEN** 「模块」列仍隐藏，优先级筛选仍生效
- **AND** 另一用户打开同一项目时不受该视图影响

#### Scenario: 分组不是文件夹

- **WHEN** 用户按模块分组查看表格
- **THEN** 行按模块折成组
- **AND** 页面不出现新建目录或新建文件夹

### Requirement: YAML 按字段追加导入

项目页 MUST 允许上传一份 YAML，并把其中的用例追加到当前项目。导入 MUST NOT 覆盖或删除已有行。字段缺失、枚举非法或步骤为空时，系统 MUST 拒绝整份导入，指出失败行号，且 MUST NOT 写入任何新行。追加后总数超过 999 时 MUST 拒绝整份导入，并说明剩余可追加条数。功能项目 MUST 拒绝带执行提示（页面锚点或日志证据）的步骤。

#### Scenario: 合法文件追加

- **WHEN** 功能项目已有 10 行，用户导入一份含 3 条合法用例的 YAML
- **THEN** 项目变为 13 行
- **AND** 原有 10 行的内容不变

#### Scenario: 超限整份拒绝

- **WHEN** 项目已有 990 行，用户导入 20 条合法用例
- **THEN** 系统拒绝整份导入并说明还可追加 9 条
- **AND** 项目仍是 990 行

#### Scenario: 功能表拒绝执行提示

- **WHEN** 用户向功能项目导入的某步带有页面锚点或日志证据
- **THEN** 系统拒绝整份导入并指出该行
- **AND** 不写入任何新行

### Requirement: 项目列表的分区虚线

用例项目列表页的「新建项目」操作带与下方内容（项目卡片网格或空态）之间 MUST 有一条**分区虚线**把两者分开。该虚线 MUST 由共享件 `SectionDivider` 提供（`1.5px dashed`、墨色 38%），MUST NOT 在页面里就地手写 `dashed`，也 MUST NOT 复用卡片自身的虚线边框充当分隔。虚线 MUST 只做分区，MUST NOT 承载文字或可点元素。

间距 MUST 不对称：操作带底部到虚线 MUST 小于虚线到内容的距离（当前 8px 对 16px），使分隔线读起来属于上方的操作带。虚线 MUST 与内容区同宽，MUST NOT 溢出内容区。空态与有卡片时 MUST 都插入该虚线，版式在两态之间保持一致。

#### Scenario: 有项目卡片时有分区线

- **WHEN** 打开 `/cases` 且存在至少一个项目
- **THEN** 「新建项目」与卡片网格之间出现一条浅墨虚线
- **AND** 该虚线宽度与内容区一致，且不可点击

#### Scenario: 空态时同样分隔

- **WHEN** 打开 `/cases` 且没有任何项目
- **THEN** 「新建项目」与空态之间同样有这条虚线

#### Scenario: 间距上紧下松

- **WHEN** 测量操作带底部到虚线的距离与虚线到内容的距离
- **THEN** 前者小于后者（约 24px 对 32px，含页面骨架的纵向 gap）

### Requirement: 项目表控制区只用共享件

项目表的控制区 MUST 只由共享件构成（`FilterTabs`、`.sketch-kit` 作用域内的表单控件、`DoodleBtn`、chip），MUST NOT 把浏览器原生的 `<select>` / `<input>` / `<button>` 当作可见控件。控制区 MUST 分两段：视图设置（分组 / 筛选 / 列显示）与写操作（新增 / 导入 / 保存）。「列显示」MUST 收成一个控件（按钮 + 复选清单），按钮上给出「可见列数 / 总列数」，MUST NOT 按列展开成一排同形按钮。

#### Scenario: 控制区结构与列显示

- **WHEN** 用户打开一个项目的用例表
- **THEN** 控制区出现分组切换、筛选下拉、列显示按钮，以及新增与导入操作
- **AND** 列显示按钮上给出「可见列数 / 总列数」
- **AND** 页面内不存在可见的原生下拉、原生输入框或原生按钮

#### Scenario: 隐藏列不丢组头

- **WHEN** 用户按优先级分组后，逐列隐藏直到只剩一列
- **THEN** 每个分组的组头条仍然显示组名与该组条数
- **AND** 隐藏的列不出现在表头与行内

### Requirement: 项目表单元格为读态

表格单元格 MUST 为读态：优先级、系统、业务类型与步骤 MUST 以标签（chip）呈现，编号 MUST 以等宽字体呈现，更新时间 MUST 以相对时间呈现并用 `title` 给出绝对时间；单元格内 MUST NOT 出现可聚焦的输入件。

#### Scenario: 单元格为读态

- **WHEN** 用户查看任意一行
- **THEN** 优先级、系统、业务类型与步骤显示为标签，编号为等宽文本，更新时间为相对时间
- **AND** 单元格内没有任何可聚焦的输入件

### Requirement: 用例行编辑经独立面板

用例行的字段编辑 MUST 经一个独立面板（抽屉或弹层）完成，该面板 MUST 承载标题、优先级、系统、业务类型、模块、前置条件与步骤序列；行内 MUST NOT 再出现「保存」「删除」按钮。面板内的修改 MUST 先落在草稿中，用户应用后该行 MUST 被标记为未保存；写入 MUST 由页面的「保存」逐行提交，全部成功后才清除标记。删除用例 MUST 经确认框。草稿构建或校验失败 MUST 给出可见提示，MUST NOT 表现为「点击后没有反应」。

面板内存在未应用的草稿改动时，关闭面板（✕、遮罩、Esc 或「取消」）MUST 先弹出确认，说明关闭后草稿会被丢弃；用户取消时面板 MUST 保持打开且草稿 MUST 逐字不变。面板内没有改动时关闭 MUST NOT 弹确认。

#### Scenario: 抽屉编辑只落草稿

- **WHEN** 用户在抽屉里把某行优先级从 `P1` 改为 `P0` 并点击应用
- **THEN** 该行显示 `P0` 且被标记为未保存
- **AND** 在用户点击页面「保存」之前不发出任何写请求

#### Scenario: 取消抽屉不改行

- **WHEN** 用户修改抽屉内字段后关闭抽屉而未应用
- **THEN** 系统先弹出丢弃草稿的确认
- **AND** 用户确认后该行内容与未保存标记都不变

#### Scenario: 放弃关闭留在抽屉

- **WHEN** 用户修改抽屉内字段后点 ✕，并在确认框里选择继续编辑
- **THEN** 抽屉保持打开
- **AND** 草稿里已填写的内容逐字保留

#### Scenario: 无改动关闭不打扰

- **WHEN** 用户打开抽屉但没有任何修改直接关闭
- **THEN** 直接关闭，不出现确认框

#### Scenario: 保存逐行提交

- **WHEN** 有 3 行被标记未保存，用户点击「保存」
- **THEN** 系统逐行提交这 3 行的可编辑字段
- **AND** 全部成功后清除未保存标记并重载表格

#### Scenario: 步骤面板校验与执行提示保留

- **WHEN** 用户在抽屉里清空第 2 步的断言并点击应用
- **THEN** 系统拒绝应用并指出第 2 步
- **AND** 整行内容保持应用前的状态
- **AND** 未被编辑的步骤其 `anchor` 与 `log` MUST 原样保留

#### Scenario: 空执行提示不阻断编辑

- **WHEN** 用户打开一个自动化项目的用例，其步骤的执行提示为空（服务端把空提示序列化为 `{}` 而非缺键）
- **THEN** 编辑面板 MUST 正常打开并显示全部字段与步骤
- **AND** 该步骤 MUST NOT 显示「带执行提示」的说明
- **AND** 保存时 MUST NOT 因为空提示被接口拒绝

#### Scenario: 抽屉构建失败必须可见

- **WHEN** 打开编辑面板时草稿构建出错
- **THEN** 系统 MUST 给出错误提示
- **AND** MUST NOT 表现为「点击后没有任何反应」

#### Scenario: 删除需确认

- **WHEN** 用户在抽屉底部点击「删除用例」
- **THEN** 先出现确认框，取消则不发出删除请求

### Requirement: 未保存改动离开前必须提示

页面上存在未写库的改动时（表格里被标记未保存的行、抽屉里尚未应用的草稿），用户尝试离开 MUST 先拦住并提示，MUST NOT 静默丢弃：

- 浏览器级离开（刷新、关闭标签或窗口）：MUST 触发浏览器原生离开确认；文案由浏览器决定。
- 站内路由离开（返回项目列表、面包屑、侧边栏跳转、退出登录）：MUST 弹应用内确认框，给出「留下 / 离开」两个动作；选择留下时 MUST 停留原页，未保存状态与草稿 MUST 逐字保留。

退出登录的确认 MUST 早于吊销会话与清除本地会话；选择留下时 MUST 保持登录且页面数据不变，跳转登录页 MUST NOT 再弹第二次确认。

页面上没有未保存改动时，两类离开 MUST 与现状一致，MUST NOT 多出任何确认；草稿与当前行等价 MUST NOT 计为未保存改动。

#### Scenario: 刷新时被拦住

- **WHEN** 表格里有一行被标记未保存，用户按 F5 或关闭标签
- **THEN** 浏览器弹出原生离开确认
- **AND** 用户取消后页面与未保存标记都还在

#### Scenario: 抽屉草稿也算未保存

- **WHEN** 用户在抽屉里改了步骤但还没点「应用改动」，此时刷新页面
- **THEN** 浏览器同样弹出原生离开确认
- **AND** 未应用的草稿未被计为「无改动」而放行

#### Scenario: 站内跳转先确认

- **WHEN** 有未保存改动，用户点「返回项目列表」或侧边栏其他模块
- **THEN** 先弹出应用内确认框，写明离开会丢失改动
- **AND** 选择留下时停留在当前项目页，未保存标记与抽屉草稿保持原样

#### Scenario: 退出登录先确认且取消后仍保持登录

- **WHEN** 有未保存改动，用户点侧边栏「退出」
- **THEN** 先弹出应用内确认框，不发出登出请求
- **AND** 选择留下时仍在项目页、仍保持登录，未保存标记与草稿都在
- **AND** 选择离开时才吊销会话并回到登录页

#### Scenario: 没有改动不打扰

- **WHEN** 页面没有任何未保存改动（含打开过抽屉但未修改）
- **THEN** 刷新与站内跳转都直接执行，不出现任何确认框
