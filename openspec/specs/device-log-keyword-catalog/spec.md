# device-log-keyword-catalog Specification

## Purpose
把「串口日志关键词 → 功能模块 / 功能点」这张对照表以**只读表格**的形式摆到 AI 工具箱里：让人一眼看到当前支持哪些关键词、每个关键词对应哪个功能点，从而判断「某个关键词受不受支持」「某个功能点靠什么关键字判定」，不必去翻数据文件或读源码。

## Requirements

### Requirement: 工具箱提供日志关键词只读入口

系统 SHALL 在 AI 工具箱「工具来源」提供**「日志关键词」**入口，且该入口 MUST NOT 绑定「交给助手」总闸：MUST NOT 进入「助手此刻可用的工具」清单与统计，MUST NOT 出现在「未装配」提示中，其来源行副标题 MUST 为说明性文案而非「n/m 生效」计数。选中后右侧 MUST 以**表格**展示关键词对照，并 MUST 显示关键词总数、功能点总数与表格行数。

#### Scenario: 选中日志关键词来源

- **WHEN** 用户点击工具箱左侧「日志关键词」
- **THEN** 右侧以表格列出关键词对照，并显示关键词数、功能点数与行数

#### Scenario: 该来源不参与装配

- **WHEN** 用户查看「助手此刻可用的工具」清单与统计
- **THEN** 该来源不出现在生效芯片、统计与「未装配」提示中
- **AND** 该来源行没有「交给助手」开关，副标题是一句说明性文案

### Requirement: 表格内容与当前生效的关键词表一致

表格 SHALL 逐个列出对照表里的关键词与其功能点，MUST NOT 遗漏、MUST NOT 臆造；同一个关键词对应多个功能点时 MUST 占多行（每行一个功能点），MUST NOT 被合并或漏掉；每个功能点 MUST 带编号与名称。表格 MUST 同时给出取值来源（运行中的采集索引 / 配置文件）与文件更新时间，使「看到的就是正在用于判定的那张表」可核对。表为空、文件缺失或不可读时 MUST 给出可读的空态与原因，MUST NOT 空白、MUST NOT 报错中断。

#### Scenario: 一个关键词对应多个功能点占多行

- **WHEN** 某个关键词在对照表里登记了多个功能点
- **THEN** 表格中该关键词出现多行，每行一个功能点，各自带模块名与功能点编号 / 名称

#### Scenario: 关键词一个不少

- **WHEN** 对照表里登记了 N 个关键词
- **THEN** 表格上的关键词总数为 N，且逐行可查

#### Scenario: 取值来源如实标注

- **WHEN** 采集正在运行
- **THEN** 表格上方标注其取值来自运行中的采集索引，并给出对照表文件与更新时间

#### Scenario: 文件缺失时给出可读空态

- **WHEN** 对照表文件缺失或无法解析
- **THEN** 页面给出可读原因与空态，MUST NOT 呈现空白区域或错误页，也 MUST NOT 呈现空表格

### Requirement: 表格列与排序、搜索口径确定

表格 MUST 恰为三列：**关键词 / 功能模块 / 功能点（编号 + 名称）**。行序 MUST 与对照表一致：关键词按其在对照表中的先后、同一关键词的功能点按其在表中的先后；前端 MUST NOT 重排或合并。搜索 SHALL 以忽略大小写的包含匹配同时作用于关键词、功能模块名与功能点名，命中即保留该行；搜索时 MUST NOT 改变表格列，也 MUST NOT 让计数缩水（计数恒报全量）；无命中时 MUST 给出可读空态；清空搜索后 MUST 回到全量。

#### Scenario: 三列固定

- **WHEN** 用户查看该表格
- **THEN** 表头恰为「关键词 / 功能模块 / 功能点」三列

#### Scenario: 行序与对照表一致

- **WHEN** 对照表里关键词与功能点的先后顺序固定
- **THEN** 表格行序与之逐行一致，前端不重排

#### Scenario: 按关键词搜索

- **WHEN** 用户输入某个关键词的一部分
- **THEN** 只保留命中该关键词的行，其余不显示

#### Scenario: 按功能点或模块搜索

- **WHEN** 用户输入某个功能点名称或模块名称的一部分
- **THEN** 命中该名称的行被保留

#### Scenario: 搜索时计数不缩水

- **WHEN** 用户输入任一搜索内容
- **THEN** 关键词数与功能点数仍为全量数值

#### Scenario: 无命中给空态

- **WHEN** 用户输入的内容在对照表里没有任何匹配
- **THEN** 表格区展示可读的「没有匹配的关键词」空态，MUST NOT 呈现空白区域

#### Scenario: 清空搜索回到全量

- **WHEN** 用户清空搜索框
- **THEN** 表格恢复到全量并按既定行序排列

### Requirement: 表格只读且如实说明生效时机

该表格 MUST 为只读视图：MUST NOT 提供任何新增、编辑、删除、上传或保存关键词的操作，也 MUST NOT 提供任何写回接口；除「搜索」与「刷新」外 MUST NOT 出现其它控件。由于判定使用的关键词表在平台启动时加载一次，页面 MUST 如实说明「改表后需重启平台才用于判定」，MUST NOT 暗示改表即时生效。

#### Scenario: 没有写操作

- **WHEN** 用户浏览该表格
- **THEN** 页面不出现新增 / 编辑 / 删除 / 上传 / 保存控件，也不发出任何写请求

#### Scenario: 如实说明生效时机

- **WHEN** 用户查看该表格
- **THEN** 页面明确说明关键词表的改动需重启平台后才用于判定
