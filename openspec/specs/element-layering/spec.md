# element-layering Specification

## Purpose
定义设备页面 UI 元素的两级分组规则与主定位选择口径，使页面层级在同一份数据上被报告、后端接口与前端页面一致地分组，并如实反映每个元素的定位可靠性。

## Requirements

### Requirement: 按控件类型划分一级分组

页面层级中的每个元素 MUST 被归入且仅归入一个一级分组：**布局容器**、**滚动·集合容器**、**内容控件**、**其它（不属于以上三类的）**。归组 MUST 仅依据控件类名所属集合，MUST NOT 依据元素位置、文本或交互标志推断。类名不在任何集合内的元素 MUST 归入「其它」，MUST NOT 被猜测归入前三个分组。布局容器集合成员包括 FrameLayout、LinearLayout、RelativeLayout、ViewGroup、ConstraintLayout 等；滚动·集合容器集合成员包括 RecyclerView、ScrollView、ViewPager、GridView、ListView 等。

#### Scenario: 布局容器类归入布局容器
- **WHEN** 元素类名属于布局容器集合（如 FrameLayout、LinearLayout、RelativeLayout、ViewGroup）
- **THEN** 该元素的一级分组为「布局容器」

#### Scenario: 滚动与集合类归入滚动·集合容器
- **WHEN** 元素类名属于滚动·集合容器集合（如 RecyclerView、ScrollView、ViewPager、GridView）
- **THEN** 该元素的一级分组为「滚动·集合容器」

#### Scenario: 未知类名归入其它且不被猜测
- **WHEN** 元素类名不属于任何集合
- **THEN** 该元素的一级分组为「其它（不属于以上三类的）」
- **AND** 它 MUST NOT 出现在前三个分组的任何一组中

### Requirement: 内容控件按承载物划分二级分组

一级分组为「内容控件」的元素 MUST 再被划入**文本**、**图标**、**其它**三个二级分组之一，且 MUST 同时记录一个细类。判据如下：文本类控件且文本非空且不含私用区字符（U+E000–F8FF 或 U+F0000–FFFFD）→ 文本（细类 text）；文本类控件但文本为空 → 文本（细类 text_empty）；文本类控件但文本为私用区字符 → 图标（细类 icon_font）；图形类控件且有内容描述 → 图标（细类 icon_semantic）；图形类控件且无内容描述 → 图标（细类 icon_bare）；裸视图 → 其它（可点击时细类 hotzone，否则 shape）。

#### Scenario: 文本类控件归入文本
- **WHEN** 元素是文本类控件且文本非空、不含私用区字符
- **THEN** 其二级分组为「文本」，细类为 text

#### Scenario: 空文本的文本类控件仍归入文本
- **WHEN** 元素是文本类控件但文本为空
- **THEN** 其二级分组仍为「文本」（占位件 MUST NOT 被归入图标）

#### Scenario: 图标字体的文本类控件归入图标
- **WHEN** 元素是文本类控件，但文本全部由私用区码点组成
- **THEN** 其二级分组为「图标」，细类为 icon_font

#### Scenario: 图形类控件按内容描述区分为有语义与无语义
- **WHEN** 元素是图形类控件
- **THEN** 有内容描述时细类为 icon_semantic，无内容描述时细类为 icon_bare，二级分组均为「图标」

#### Scenario: 裸视图归入其它
- **WHEN** 元素是既不承载文字也不承载图形的裸视图
- **THEN** 其二级分组为「其它」，可点击时细类为 hotzone，不可点击时细类为 shape

### Requirement: 主定位选择与唯一性判定

每个元素 MUST 给出一个主定位候选。选择口径 MUST 为：先筛出「匹配数为 1 且不是位置型（同类索引型）」的候选，再按 resource-id > content-desc > 组合条件 > text > 文本(不限类名) > class 的质量顺序取第一条。不存在这样的候选时，系统 MUST 标记该元素的主定位为不稳定，MUST NOT 用位置型候选冒充唯一。位置型候选 MUST 始终被标注为脆弱。

#### Scenario: 存在唯一资源标识时选它
- **WHEN** 元素存在匹配数为 1 的资源标识候选
- **THEN** 主定位取该资源标识候选，并标记为稳定

#### Scenario: 位置型候选不得冒充唯一
- **WHEN** 元素的资源标识候选匹配数为 2，而位置型候选的匹配数恒为 1
- **THEN** 主定位 MUST NOT 取该位置型候选，该元素 MUST 被标记为不稳定

#### Scenario: 唯一候选优先于类型质量
- **WHEN** 元素同时存在「匹配数为 3 的资源标识候选」与「匹配数为 1 的内容描述候选」
- **THEN** 主定位取匹配数为 1 的内容描述候选（唯一性优先于类型质量）

#### Scenario: 无可定位身份时主定位为空
- **WHEN** 元素没有资源标识、文本、内容描述且不可点击
- **THEN** 主定位为空且标记为不稳定

### Requirement: 元素条目携带坐标与状态

每个分组内的元素 MUST 按坐标顺序排列（顶边 y 升序，同 y 再 x 升序，同坐标再按层级深度升序）。每个元素条目 MUST 携带：屏幕像素坐标（左上角、宽、高、中心点、原始 bounds 文本）、控件类名、资源标识、文本、内容描述、交互标志（可点击/可长按/可滚动/可勾选/已勾选/启用/可聚焦）、是否被展示裁剪保留、主定位。被展示裁剪丢弃的元素 MUST 与保留元素一样参与分组与坐标排序，并以保留标记区分。候选定位列表 MUST NOT 作为元素条目的字段出现 —— 候选是可由节点集合重算的派生数据，需要时按元素单独查询。

#### Scenario: 分组内按坐标顺序排列
- **WHEN** 一个分组内存在多个元素
- **THEN** 它们按 (顶边 y, 左边 x, 层级深度) 升序排列

#### Scenario: 被展示裁剪的元素仍参与分组
- **WHEN** 元素被展示裁剪规则丢弃（纯布局容器或同 bounds 去重）
- **THEN** 它仍出现在所属分组中，且其保留标记为假

#### Scenario: 坐标与截图同空间
- **WHEN** 元素坐标被用于在截图上圈选
- **THEN** 坐标单位为设备像素，与整屏截图像素空间一致

#### Scenario: 条目不含候选定位列表
- **WHEN** 读取任一元素的条目
- **THEN** 条目含一条主定位（表达式、类型、匹配数、是否稳定）
- **AND** 条目 MUST NOT 含该元素的候选定位列表
