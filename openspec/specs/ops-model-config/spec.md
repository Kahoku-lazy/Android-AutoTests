# ops-model-config Specification

## Purpose
约束运营后台模型配置页里「模型类型」与「厂商」的对应关系：三类模型各自只提供真实支持的厂商，切换分类时给出正确的默认厂商与密钥，列表也能一眼看出每条配置属于哪一类，避免保存出类型与厂商不匹配的配置。

## Requirements

### Requirement: 模型类型与厂商的支持关系

系统 SHALL 按以下关系限定某个模型类型可选的厂商：聊天支持 deepseek、dashscope、openai；实时语音只支持 dashscope；语音合成只支持 dashscope。厂商下拉 MUST 只列出当前模型类型支持的厂商，MUST NOT 出现不受支持的厂商选项。

#### Scenario: 聊天分类显示三家厂商
- **WHEN** 用户把模型类型选为聊天
- **THEN** 厂商下拉恰好包含 deepseek、dashscope、openai

#### Scenario: 实时语音只显示 dashscope
- **WHEN** 用户把模型类型选为实时语音
- **THEN** 厂商下拉只有 dashscope，deepseek 与 openai 不出现

#### Scenario: 语音合成只显示 dashscope
- **WHEN** 用户把模型类型选为语音合成
- **THEN** 厂商下拉只有 dashscope，deepseek 与 openai 不出现

### Requirement: 切换模型类型时的默认厂商与密钥

切换模型类型时，若当前厂商仍受新类型支持，系统 MUST 保留该厂商；若不再受支持，MUST 自动切换到该类型的默认厂商：聊天为 deepseek，实时语音与语音合成均为 dashscope。厂商变化后，密钥环境变量 MUST 同步为该厂商对应的变量名，MUST NOT 留下厂商与密钥不匹配的组合。

#### Scenario: 从聊天切到实时语音
- **WHEN** 用户在厂商为 deepseek 的聊天配置上把模型类型改为实时语音
- **THEN** 厂商自动变为 dashscope，密钥环境变量同步为 DashScope 对应的变量名

#### Scenario: 已受支持的厂商不被重置
- **WHEN** 用户在厂商为 dashscope 的实时语音配置上把模型类型改为语音合成
- **THEN** 厂商仍为 dashscope，密钥环境变量不变

#### Scenario: 切回聊天保留仍受支持的厂商
- **WHEN** 用户在厂商为 dashscope 的语音合成配置上把模型类型改回聊天
- **THEN** 厂商仍为 dashscope，不被强行改回 deepseek

#### Scenario: 新建默认值
- **WHEN** 用户打开新建模型抽屉
- **THEN** 模型类型默认为聊天，厂商默认为 deepseek，密钥环境变量为 DeepSeek 对应的变量名

### Requirement: 编辑历史配置时归一厂商

打开一条既有配置编辑时，若其厂商不在该模型类型支持的集合内，系统 MUST 把厂商显示为该类型的默认厂商，MUST NOT 把不受支持的厂商回显到下拉里；模型类型及模型名称、地址等其它字段 MUST 保持原值。

#### Scenario: 历史脏组合被归一
- **WHEN** 用户编辑一条模型类型为语音合成、厂商为 openai 的历史配置
- **THEN** 厂商显示为 dashscope，模型类型仍为语音合成

### Requirement: 列表展示模型类型

模型配置列表 MUST 以「模型」为首列身份单元（模型名 + 「厂商 · 类型（· 音色）」副行），「模型类型」列 MUST 紧随该首列，取值为聊天、实时语音、语音合成，并以 chip 呈现（1.5px 墨边 + 类型色混底 + 14px 粗字）。记录缺少模型类型时 MUST 按聊天展示（副行与 chip 同时回退为聊天）。

#### Scenario: 三类配置并排展示
- **WHEN** 列表里同时存在聊天、实时语音、语音合成三条配置
- **THEN** 每条记录在模型首列的右侧显示与自身类型一致的类型 chip
- **AND** 首列副行同时给出厂商与类型

#### Scenario: 旧数据缺类型按聊天展示
- **WHEN** 某条历史记录没有模型类型字段
- **THEN** 类型 chip 显示聊天，副行也按聊天渲染

### Requirement: 实时语音与语音合成只维护一个模型名称

模型类型为实时语音或语音合成时，系统 SHALL 只允许维护一个模型名称：MUST NOT 显示「+ 添加一行」，MUST NOT 显示逐行「删除」。从聊天切到这两类时，已有多行 MUST 折叠为第一行；切回聊天后 MUST 可以继续添加行。保存这两类配置时 MUST 只提交一个模型名称。

#### Scenario: 实时语音只有一个名称输入
- **WHEN** 用户把模型类型选为实时语音
- **THEN** 模型名称只有一个输入框，且不出现「+ 添加一行」与「删除」

#### Scenario: 语音合成只有一个名称输入
- **WHEN** 用户把模型类型选为语音合成
- **THEN** 模型名称只有一个输入框，且不出现「+ 添加一行」与「删除」

#### Scenario: 从聊天切到实时语音折叠为第一行
- **WHEN** 聊天配置里填了三个模型名称，用户把模型类型改为实时语音
- **THEN** 模型名称只剩第一行，其余行被丢弃

#### Scenario: 切回聊天可以继续添加
- **WHEN** 用户在实时语音的单名称配置上把模型类型改回聊天
- **THEN** 模型名称显示一行，并重新出现「+ 添加一行」

#### Scenario: 保存只提交一个名称
- **WHEN** 用户保存一条实时语音或语音合成配置
- **THEN** 请求体只包含一个模型名称

### Requirement: 音色字段位于模型名称下方

模型类型为实时语音或语音合成时，音色字段 MUST 紧跟在模型名称字段之后；模型类型为聊天时 MUST NOT 显示音色字段。

#### Scenario: 音色排在模型名称之后
- **WHEN** 用户把模型类型选为语音合成或实时语音
- **THEN** 表单字段顺序中「音色」紧接在「模型名称」之后

### Requirement: 语音合成不要求 API 地址

模型类型为语音合成时，系统 MUST NOT 要求填写 API 地址，保存时 MUST NOT 因地址为空而失败；服务端 MUST 接受空 `base_url`。聊天与实时语音仍 MUST 校验地址，空地址 MUST 被拒绝。

#### Scenario: 语音合成空地址可保存
- **WHEN** 用户只填模型名称与音色就保存一条语音合成配置
- **THEN** 保存成功，落库的 `base_url` 为空串

#### Scenario: 聊天空地址仍被拒绝
- **WHEN** 用户提交一条聊天配置且 API 地址为空
- **THEN** 保存失败并提示 API 地址不能为空

#### Scenario: 历史语音合成配置可再次编辑保存
- **WHEN** 用户打开一条 `base_url` 为空的语音合成配置并保存
- **THEN** 保存成功，不要求补填地址

### Requirement: 模型配置列表的表格形态

模型配置列表的表纸 MUST 使用与设备管理、BUG 单一致的无影变体：保留共享描边与圆角，MUST NOT 绘制赭橙模块色位移硬影；同样 MUST NOT 被 `.doc-section` 外框再包一层，且 MUST NOT 传 `:border`。表格 MUST 使用 `table-layout="fixed"`，长地址由 tooltip 承担，MUST NOT 把表格撑出表纸而被裁切；固定布局下表格 MUST NOT 出现横向滚动条（原生横条须隐藏，按列宽压缩 + tooltip 兜底）。

字号 MUST 为表头 16px、正文 14px、次级 12px（首列副行）；类型 chip MUST 为 14px。

控制区 MUST 为两行：第一行是关键字搜索 + 「新建模型」（搜索在左、按键在右），第二行是页码文案 + 上一页 / 下一页。列表 MUST 按每页固定 **10 条**分页，页码文案 MUST 常驻显示「第 X / Y 页 · 共 N 条」，并 MUST 是页面上唯一显示总条数的位置；只有一页时两键 MUST 同时置灰但仍可见，MUST NOT 隐藏整条翻页栏。关键字变化时 MUST 回到第 1 页；删除使当前页越界时 MUST 自动夹回最后一页。

搜索 MUST 在页面前端过滤（模型名 / 厂商 / 类型 / 密钥环境变量 / 地址），MUST NOT 为它新增接口参数；过滤 MUST 先于分页，页码统计的是过滤后的条数。操作列 MUST 为「编辑」主操作胶囊 + `⋯` 菜单，删除 MUST 收进 `⋯`，且 MUST 保留二次确认。

#### Scenario: 无影表纸 + 固定布局

- **WHEN** 打开 `/ops/model-configs`
- **THEN** 表纸 `box-shadow` 为 `none`，页面里只有表纸一层框
- **AND** 超长 `wss://` 地址不会把表格撑出表纸，操作列完整可见
- **AND** 表格底部不出现横向滚动条

#### Scenario: 每页 10 条且翻页常驻

- **WHEN** 接口返回 12 条配置
- **THEN** 表格只显示 10 行，页码文案为「第 1 / 2 页 · 共 12 条」
- **AND** 「上一页」置灰、「下一页」可用；翻到第 2 页显示剩余 2 行、「下一页」置灰
- **AND** 只有一页时两键都置灰但仍可见

#### Scenario: 前端关键字过滤

- **WHEN** 在搜索框输入厂商名片段
- **THEN** 列表只保留命中项，页码文案的「共 N 条」随命中数变化
- **AND** 页码回到第 1 页，且不产生新的网络请求

#### Scenario: 操作列收敛

- **WHEN** 查看任一模型行的操作列
- **THEN** 只有「编辑」胶囊与 `⋯` 两颗
- **AND** 点 `⋯` 里的删除仍会弹出二次确认

### Requirement: 运营不能决定模型的使用人

运营保存模型配置 MUST NOT 改变任何用户的使用名单。新建配置保存成功后，系统 MUST 只允许超级管理员主动使用该模型，直到超级管理员另行授予。运营请求修改名单 MUST 返回 403。

#### Scenario: 保存新配置不开放给所有人

- **WHEN** 运营按现有规则保存一条合法的新模型配置
- **THEN** 配置被保存
- **AND** 普通用户的可主动使用名单不包含该模型

#### Scenario: 运营的名单请求被拒绝

- **WHEN** 运营请求把某模型加入某用户名单
- **THEN** 系统返回 403
- **AND** 名单不变
