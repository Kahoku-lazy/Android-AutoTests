一、背景与目标

平台小助手当前是「自由对话」形态。本次重构目标：

  • 改为 两条明确能力线路：控制设备（已实现）+ 平台任务（仅入口）。
  • 智能体配置从「配置一个模型」改为「配置一个智能体」（多线路模型配置）。
  • 前端新增「任务发布模块」：任务卡片 → 选定智能体 → 下发执行。
  • 移除主对话（SSE 接口 + 前端聊天窗口）。

三、候选方案（含推荐）

3.1 智能体配置存储

方案 A · 推荐

ai_agents 增 route_configs JSONField，扁平字段降级兼容。

改动小、增线路免迁移；JSON 无 DB 约束、api_key 需 Fernet 加密。

方案 B

拆表 ai_agent_routes + ai_route_models。

规范化可约束；3 表 + serializer 复杂 + 迁移量大。

3.2 任务模型与执行

方案 A · 推荐

扩展 ai_tasks，新增 goal/requirements/attachment/route/checklist/report_name/status。

复用已有表 + 历史端点；需一次字段迁移。

方案 B

新表 ai_task_submissions。

与旧任务解耦；多一张语义重叠的表。

3.3 主对话移除范围

方案 A · 推荐

删 SSE + 前端聊天 + 会话/消息 API/组件。

任务历史由 ai_tasks + ai_execution_logs 承载。

方案 B

保留 ai_conversations/ai_messages 表供审计。

仅删前端聊天 + SSE。

七、风险与边界

① 配置 JSON 迁移：旧扁平字段折叠进 route_configs，需数据迁移脚本 + 回滚预案。
② 删除对话面广：SSE 是全平台唯一流式通道，删除后 useSSE/SSEMessageBuilder 一并下线，需确认无其它模块复用。
③ 平台任务占位：本期只保留入口，不接线 reasoning，避免提前开发未评审能力。
④ 安全：route_configs 内 api_key 必须 Fernet 加密 + 脱敏 + 一次性 reveal。
