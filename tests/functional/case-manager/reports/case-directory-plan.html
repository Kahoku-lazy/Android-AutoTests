📋 背景与目标

当前问题

现有 case-manager 模块采用扁平结构管理用例 — 所有用例平铺在列表中，仅靠一个自由文本 category 字段做简单筛选。随着用例数量增长（H6601、Wi-Fi 稳定性、蓝牙性能等多条产品线），扁平列表已无法满足分类浏览和快速定位的需求。

目标产出

  • 三级层级：一级目录 → 二级目录 → 用例，支持嵌套浏览
  • 双视图切换：列表视图（Table）+ 卡片视图（Card Grid），一键切换，偏好记忆
  • 向后兼容：现有用例的 category 文本字段保留，directory 外键 nullable，不强制迁移
🗄️ 数据模型设计

新增表 cm_case_directories

字段 类型 说明
id int PK 自增 主键
name varchar(200) 目录名称（如 "H6601用例"、"开关功能"）
parent FK → self nullable 父级目录。一级目录为 null，二级目录指向一级
sort_order int 默认 0 排序序号，支持拖拽调整
created_at datetime auto_now_add 创建时间
updated_at datetime auto_now 更新时间

🔒 唯一约束：(parent, name) — 同一父级下目录名不可重复

TestDefinition 新增字段

字段 类型 说明
directory FK → CaseDirectory nullable 所属二级目录。为空时保持向后兼容，category 字段不变

💡 设计意图：directory 指向二级目录，一级目录通过 directory.parent 间接关联。现有用例 directory=null，category 自由文本保留，后续可通过脚本批量迁移。

数据关系示意

📁 H6601用例 (id=1, parent=null)
    ├── 📂 开关功能 (id=2, parent=1)
    │    ├── 📄 TC-001 打开Wi-Fi开关 (directory_id=2)
    │    └── 📄 TC-002 关闭Wi-Fi开关 (directory_id=2)
    └── 📂 场景功能 (id=3, parent=1)

🔌 API 设计

新增端点

方法 路径 说明
GET /api/cases/directories 获取完整目录树（嵌套 JSON，含每个节点的 case_count）
POST /api/cases/directories/create 创建目录（name + parent_id + sort_order）
POST /api/cases/directories/{id}/update 更新目录（名称、父级、排序）
POST /api/cases/directories/{id}/delete 删除目录（含子目录或用例时返回警告）

修改端点

端点 变更内容

⚠️ 风险评估
等级 风险 应对措施
🟠 中 现有用例 category 为自由文本，迁移到目录结构可能丢失数据 directory 字段设为 nullable，不强制迁移；后续提供 category → directory 批量映射脚本
🟢 低 el-tree 大量节点时性能问题 目录层级固定 2 层，节点总数有限（通常 <100），性能无虞
🟢 低 卡片视图渲染大量用例时性能下降 用例数量通常 <200，CSS Grid 布局无虚拟滚动需求
🟢 低 删除含子目录的目录时数据孤立 删除前检查子目录和关联用例数，弹窗确认；directory 使用 SET_NULL 而非 CASCADE
