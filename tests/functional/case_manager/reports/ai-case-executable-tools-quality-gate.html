P1 级发现（必须修复）

P1-1 · adb_loop_n 非数字 index 通过校验 → 执行期 TypeError 崩溃

位置：apps/case_manager/api_ai.py:47（"adb_loop_n": ("index",)）+ :101（空值判断不覆盖 0/负数/非数字）；apps/test_runner/executors/ui/executor.py:297（n = s.index if s.index > 0 else 1）

证据（探针实测）：index='abc' → ok=True 通过校验；TestStep.from_dict 原样保留 str → 'abc' > 0 抛 TypeError 崩溃执行；index=0 / -2 通过校验但执行时被静默改写为 1（语义漂移）

建议：adb_loop_n（及 adb_loop_elements 的 index 可选值）校验 index 为 int 且 ≥ 1，否则返回明确错误

P1-2 · 未知 case_type 静默落成 UI 用例，payload 回显与库中类型不一致

位置：apps/case_manager/api_ai.py:84-85（非 ui/web 一律返回 True 放行）+ :203-215（else 分支硬编码 case_type="ui_automation" 落库）+ :221（payload 回显原始 ct）

证据（探针实测）：validate_steps('bogus', ...) → ok=True；随后 save_ai_definition 走 UI 落库，返回 {"case_type": "bogus"} 但 DB 行为 ui_automation —— AI 拿到错误语义（schema 无 enum 约束，模型越界输入可触发）

建议：save_ai_definition 入口处对 case_type 不在 {ui_automation, web_automation, storage, api_testing} 的值直接返回 (False, "无效 case_type ...")

P2 级发现（建议随修）

P2-1 · whitespace-only 必填字段通过校验

api_ai.py:101 不 strip：探针 xpath=' ' → ok=True，执行期必然失败。建议判空前 str(val).strip()。

P2-2 · web_wait 无 selector 且无 timeout 通过校验 → 执行必 fail

web/executor.py:347 明确 "Wait FAIL: no selector/xpath and no timeout"；_REQUIRED_FIELDS 未列入 web_wait。建议要求 selector 或 timeout 至少其一。

P2-3 · 执行器支持的 log / click_indexed 被白名单拒绝（注册表存量缺口）

STEP_TYPE_META 缺 log 与 click_indexed（executor handlers 均存在），validate_steps 以 META 为唯一权威 → AI 无法写这两类步骤。建议 META 补登记（属存量注册表债，本次白名单继承了缺口）。

P2-4 · storage 分支 steps 静默降级为 legacy 文本 repr；schema 无 rows 参数

api_ai.py:170-184 传 steps=steps → api_storage.py:95 落 legacy steps TEXT 字段，列表被 str() 成 Python repr；rows 始终为空，digest 读回 steps=[] 假象；且 save_case schema 无 rows 参数，AI 无法创建有数据的 storage 用例。建议 storage 分支改接 rows 或拒绝 steps。

P2-5 · _format_result 4000 字符硬截断无标记

in_process_tool.py:74/97：大 digest（多步骤用例）被截成非法 JSON 且无 "…已截断" 提示，LLM 静默拿到损坏结构。建议截断边界追加标记或按条数裁剪 steps。

P2-6 · 单模型序列化噪音（debug_case）

in_process_tool.py:52-58：_model_to_dict 输出 steps_json 原文（JSON 字符串双转义）、watchers/permitted_users repr 串、datetime 走 str() 非 ISO。语义正确但 token 噪音大；debug_case 建议改走 get_case_digest。

P2-7 · 容器步骤 children 不递归校验

api_ai.py:89-103 只校验顶层；探针 {'type':'adb_loop_n','index':2,'children':[{'type':'click'}]} → ok=True，子步骤缺 xpath 执行期才暴露。建议递归校验 children。

P2-8 · handler 对 enabled 做 bool() 强转

tool_registry.py:717：字符串 "false" → bool("false") == True。schema 声明 boolean 降低概率，建议显式校验类型。
