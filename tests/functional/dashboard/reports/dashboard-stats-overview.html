1 功能定位

统计概览是仪表盘最顶部的 4 张指标卡片，用一瞥就能回答：平台现在状态如何？

4 张卡片对应平台的 4 个核心维度——设备有没有在线的、用例库有多大、AI Agent 有多少在干活、有没有任务正在跑。它是整个平台的心率监测器。

连接了多少台手机
📋

有多少条可执行的用例
🧠
活跃 Agent
有多少 AI 智能体在线
▶️
运行中任务
有多少测试正在执行

2 用户故事

👤 测试工程师 · 上班第一件事
"打开仪表盘，一眼确认设备都在线、昨天跑的任务没挂。"
统计概览在页面最顶部，不需要滚动。4 个数字 3 秒内扫完——在线设备 > 0、运行中任务 = 0（说明昨晚的任务跑完了）、用例数没变少。
👤 运维人员 · 设备故障排查
"我要快速知道现在有几台设备连不上，是否需要紧急处理。"
在线设备卡片显示"在线数 / 总数"，如果在线数远小于总数，说明有设备掉线——立即去设备管理页排查。趋势箭头向下也提示最近活动减少。
👤 团队 Leader · 了解团队产出
"这周新增了多少用例？Agent 有没有人在用？"
测试用例卡片显示总数 + 本周新增趋势，Agent 卡片显示活跃数。两个数字反映团队在建用例和用 AI方面的活跃度。

3 解决的痛点

❌ 没有统计概览之前

  • 不知道设备在线状态，要进设备管理页一个个看
  • 不知道有没有任务在跑，可能同时启动两个测试
  • 用例总数靠记忆——"大概两三百条吧"
  • Agent 状态不可见——创建了但不知道有没有启用
  • 每次想了解平台状态至少要点 3-4 个页面

✅ 有了统计概览之后

  • 一页知全局：4 个数字覆盖平台核心维度
  • 异常可见：设备离线、任务异常一眼发现
  • 趋势感知：每个卡片带趋势箭头，知道在变好还是变差
  • 零点击：打开仪表盘即看，不需要任何操作
  • 心跳动画：有任务在跑时显示红色脉冲点，视觉提醒

5 数据流全景 — 逐层展开

📖 7 层流水线 — 从数据库到 4 张卡片

统计概览的数据旅程比趋势数据更简单——不涉及复杂的循环查询，后端直接用 .count() 数一下各表有多少条符合条件的记录，返回给前端渲染成 4 张卡片。

🟡 第 1 层：数据库（4 张表）

表名通俗含义统计概览用它做什么
dp_devices设备花名册——记录每台连接过的手机，含在线/离线状态数在线设备数和总设备数
cm_test_definitions用例库目录——平台上所有测试用例的定义数总用例数和已启用数
ai_agentsAI 员工表——所有创建的智能体配置数总 Agent 数和活跃数
tr_test_runs测试任务工单——每次批量执行的任务记录数总执行次数和正在运行的任务
↓ Django ORM 逐表 .count() — 数据库内部计数，只返回数字 ↓

🟤 第 2 层：ORM 聚合查询 — 简单的 COUNT

查询操作通俗解释
Device.objects.count()"设备表里一共有多少行？" → 返回一个数字
Device.objects.filter(status="ONLINE").count()"其中状态是在线的有多少行？" → 先筛再数
统计概览的查询特点全是简单的 COUNT 查询，没有循环、没有 JOIN，性能很好（每条 < 1ms）
↓ 8 个数字 → 交给 dashboard_stats() 组装为 JSON ↓

🔵 第 3 层：后端函数 — dashboard_stats() 前 10 行

变量含义来自哪张表

6 前端实现 — StatsCard 组件

👁️ 从交互上你能感知到什么？

StatsCard 不是一个简单的 <div>数字</div>，它有三个细节： ① 首次进入视野时数字从 0 滚动到目标值（约 1.2 秒），② 鼠标悬停时卡片微微放大（弹性动画）， ③ 数据加载中显示骨架屏而非空白。这些细节让页面感觉"活"的。

7 后端实现 — 8 个数字的来源

🔄 后端数据流转 — 用大白话讲

统计概览的数据生产非常简单——dashboard_stats() 函数的前 10 行就是它。逐一去 4 张表里 COUNT 一下，每张表数两次数（总数 + 条件筛选数），得到 8 个数字，和其他统计一起打包成 JSON 返回。没有复杂计算，没有循环查询，是整个 dashboard_stats 中性能最好的部分。 

// apps/dashboard/views.py — dashboard_stats() 前 10 行
device_online = Device.objects.filter(status="ONLINE").count()   // 在线设备
device_total  = Device.objects.count()                        // 设备总数
case_total    = TestDefinition.objects.count()                 // 用例总数
case_enabled  = TestDefinition.objects.filter(enabled=True).count()
run_total     = TestRunRecord.objects.count()                  // 任务总数
run_active    = TestRunRecord.objects.filter(status="RUNNING").count()
agent_total   = AIAgent.objects.count()                       // Agent 总数
agent_active  = AIAgent.objects.filter(status="active").count()

// 打包为 JSON 返回给前端
return JsonResponse({"ok": True, "data": {
    "devices":  {"online": device_online, "total": device_total, "trend": ...},
    "cases":    {"total": case_total, "enabled": case_enabled, "trend": ...},
    "agents":   {"total": agent_total, "active": agent_active, "trend": ...},
    "runs":     {"total": run_total, "active": run_active, "trend": ...},
}})

14 统计概览专属 AI 提示词

【绝对红线】

规则要求
1. 数据来源统计数字必须来自 ORM COUNT 查询，禁止硬编码、禁止假数据
2. 响应格式devices/cases/agents/runs 四个字段的结构不可修改
3. 状态值必须用 DeviceStatus.ONLINE 等 Enum，禁止 "ONLINE" 字符串
4. 动画数字滚动用 countUpFormatted，禁止自己写动画逻辑
5. UI 库纯 animal-island-vue 的 Card，禁止引入 el-card 或其他库

【代码生成要求】

  • 新增统计指标时，在 dashboard_stats() 中加 COUNT 查询 + 在 JSON 响应中加字段 + 在 index.vue 中加 StatsCard 实例
  • 同步输出测试：后端验证新字段存在 + 前端验证新卡片渲染
  • 保持 4 卡片网格布局（响应式：900px 以下 2 列，480px 以下 1 列）
