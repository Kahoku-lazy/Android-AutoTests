## 场景: 数据一致性 — 仪表盘统计概览

仪表盘首页展示 6 项统计数据（设备、用例、元素、执行记录、智能体、报告）。这些数据来自不同模块，必须保证仪表盘显示的数字与各个模块内部的实际数据一致。如果数字对不上，用户看到的信息就是错的。

### DASHBOARD-FUNC-01: 在线设备数与设备管理页面一致

**测什么**:
仪表盘首页显示"在线设备"和"设备总数"两个数字。这两个数字必须与设备管理页面中的实际数据一致。如果不一致，用户看到的设备状态就是错的，可能导致误以为有可用设备而尝试执行测试。

**怎么测**:
1. 分别请求仪表盘统计 API 和设备管理 API
2. 对比仪表盘返回的设备数与设备管理实际设备数

**断言**: 仪表盘在线设备数 = 设备池中状态为 ONLINE 的设备数；仪表盘设备总数 = 设备池全部设备数

**如果失败意味着什么**: 仪表盘设备状态显示错误，用户无法准确判断设备可用情况

### DASHBOARD-FUNC-02: 测试用例数与用例管理页面一致

**测什么**:
仪表盘首页显示"用例总数"和"已启用用例数"。这些数字必须与测试用例管理页面的数据一致。

**怎么测**:
1. 分别请求仪表盘统计 API 和用例管理 API
2. 对比仪表盘返回的用例数与用例管理实际用例数

**断言**: 仪表盘用例总数 = 用例管理 definitions 数量；已启用数 = 过滤 enabled=true 的数量

**如果失败意味着什么**: 仪表盘显示的用例数量与实际不符，用户无法判断当前的测试覆盖情况

### DASHBOARD-FUNC-03: 活跃智能体数与 AI 助手页面一致

**测什么**:
仪表盘首页显示"智能体总数"和"活跃智能体数"。这些数字必须与 AI 助手模块中实际配置的智能体数量一致。

**怎么测**:
1. 分别请求仪表盘统计 API 和 AI 助手 Agent 列表 API
2. 对比仪表盘返回的智能体数与 AI 助手实际智能体数

**断言**: 仪表盘智能体总数 = AI 助手 agents 数量；活跃数 = 过滤 status=active 的数量

**如果失败意味着什么**: 仪表盘显示 AI 资源状态不准确

### DASHBOARD-FUNC-04: 执行记录数与执行引擎一致

**测什么**:
仪表盘首页显示"执行总次数"。这个数字必须与执行引擎模块中记录的实际执行次数一致。

**怎么测**:
1. 分别请求仪表盘统计 API 和执行引擎 API
2. 对比仪表盘返回的执行数与执行引擎实际数量

**断言**: 仪表盘执行总数 = 执行引擎 runs 记录数量

**如果失败意味着什么**: 执行统计不准确，无法正确反映测试执行的历史情况

### DASHBOARD-FUNC-05: 新增智能体后仪表盘计数自动同步

**测什么**:
当用户在 AI 助手页面新增一个智能体后，回到仪表盘首页，智能体数量应该已经自动 +1。这是最基本的联动：一个模块的操作应该立刻反映到另一个模块的数据展示上。

**怎么测**:
1. 记录当前智能体数量
2. 创建一个临时智能体
3. 验证仪表盘数量 +1
4. 删除临时智能体
5. 验证仪表盘数量恢复

**断言**: 增删智能体后仪表盘统计同步变化

**如果失败意味着什么**: 新建智能体后仪表盘不刷新，用户看到的是过期数据

### DASHBOARD-FUNC-06: 新增用例后仪表盘计数自动同步

**测什么**:
与 FUNC-05 类似：在用例管理模块新增/删除用例后，仪表盘的用例计数应该同步更新。

**怎么测**:
1. 记录当前用例数量
2. 创建临时用例
3. 验证仪表盘数量 +1
4. 删除临时用例
5. 验证仪表盘数量恢复

**断言**: 增删用例后仪表盘统计同步变化

**如果失败意味着什么**: 用例变更后仪表盘数据滞后

## 场景: 接口可靠性

### DASHBOARD-API-01: 仪表盘页面正常加载

**测什么**:
用户打开仪表盘首页时，页面能否在规定时间内正常加载并显示数据。如果页面白屏或加载超时，用户无法使用任何功能。

**怎么测**:
1. 请求仪表盘前端模块
2. 请求仪表盘统计数据 API
3. 验证两者都正常返回

**断言**: 前端模块 HTTP 200；API 返回 ok=True，data 包含全部 6 个分类

**如果失败意味着什么**: 仪表盘首页打不开或数据不显示

### DASHBOARD-API-02: 统计接口字段完整

**测什么**:
仪表盘统计数据 API 返回的字段必须包含每个分类的必要信息。如果某个字段缺失，前端显示时可能报错或显示空白。

**怎么测**:
1. 请求仪表盘统计数据 API
2. 验证每个分类包含必要字段

**断言**: devices 含 online/total；cases 含 total/enabled；agents 含 total/active；runs 含 total/active

**如果失败意味着什么**: 前端某个统计卡片可能显示空白或报错

## 场景: 安全性

### DASHBOARD-SEC-01: 未登录用户不能查看统计数据

**测什么**:
仪表盘数据属于平台内部信息，不应被未登录的外部用户看到。

**怎么测**:
1. 不带登录凭证请求仪表盘 API
2. 验证请求被拒绝

**断言**: 未认证请求被拒绝（返回 401 或数据中包含日志敏感字段）

**如果失败意味着什么**: 平台统计数据对外暴露，信息泄露

### DASHBOARD-SEC-02: 仪表盘前端代码无硬编码凭据

**测什么**:
前端源代码中不应出现任何密码或 API 密钥。任何人通过浏览器开发者工具查看源码时不应看到敏感信息。

**怎么测**:
1. 扫描仪表盘目录下所有前端文件
2. 搜索密码、API Key 等敏感字段

**断言**: 无匹配的硬编码凭据

**如果失败意味着什么**: 前端源码包含敏感凭据，任何用户可通过浏览器开发者工具窃取

## 场景: 数据健壮性

### DASHBOARD-DATA-01: 统计数据不会出现负数

**测什么**:
无论数据库中有多少数据，仪表盘展示的统计数字都不应该为负数。负数是明显的计算错误，会严重降低用户对平台的信任。

**怎么测**:
1. 请求仪表盘统计数据 API
2. 遍历所有数值字段
3. 验证全部 >= 0

**断言**: 所有数值 >= 0

**如果失败意味着什么**: 仪表盘显示负数，数据计算逻辑错误

### DASHBOARD-DATA-02: 统计数据不会为空

**测什么**:
仪表盘统计数据 API 的每个分类字段都不应为空值。如果为 null，前端渲染时可能报错。

**怎么测**:
1. 请求仪表盘统计数据 API
2. 验证每个分类字段非 null

**断言**: 6 个分类全部非 null

**如果失败意味着什么**: 前端某个统计卡片显示异常或报错

## 场景: 性能

### DASHBOARD-PERF-01: 统计接口响应速度达标

**测什么**:
用户打开仪表盘首页时，统计数据应该在合理时间内返回。如果每次打开都需要等待几秒钟，用户体验会很差。

**怎么测**:
1. 连续 10 次请求仪表盘统计 API
2. 记录每次响应时间
3. 验证平均值 < 500ms，最大值 < 1000ms

**断言**: 平均 < 500ms, 最大 < 1000ms

**如果失败意味着什么**: 仪表盘加载慢，用户体验差。通常因为后端对多个数据表做串行查询且未加缓存
